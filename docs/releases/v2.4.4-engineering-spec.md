# v2.4.4 Engineering Spec - Canvas Edges + ObjectRelation Seed

**Created**: 2026-05-23
**Updated**: 2026-05-23
**Status**: Implemented

---

## 1. Implementation Contract

v2.4.4 implements a local React/CSS/SVG edge layer over the existing `LearningCanvasSurface`.

No external canvas, relation editor, or graph library is added.

---

## 2. CanvasEdge Contract

`CanvasEdge` is a projection record. It stores how a connector appears and what it is attached to.

Required states:

```text
incomplete
visual_only
relation_suggested
relation_backed
stale_binding
broken_relation
```

Ports:

```text
top
right
bottom
left
```

Rules:

- `source_node_id` and `source_port` are required.
- `target_node_id` and `target_port` are nullable.
- `loose_target_x` and `loose_target_y` are used for `incomplete` edges.
- `object_relation_id` is nullable.
- `relation_layer_id` is nullable and should default to the visual layer when omitted.

---

## 3. ObjectRelation Contract

`ObjectRelation` is the semantic edge candidate.

Endpoint fields:

```text
source_type
source_id
target_type
target_id
```

The first resolver maps CanvasNode to:

- `note_block`
- `source_scope`
- `source_anchor`
- `source_board_node`
- `source_material`
- `material_segment`
- `evidence_set`
- `proposal`

If either CanvasNode cannot resolve to a domain object, relation binding fails cleanly.

---

## 4. RelationLayer Contract

`RelationLayer` is a minimal visibility/purpose layer.

Default layers are seeded per course and optionally canvas-scoped:

```text
visual
learning_logic
source_evidence
ai_suggested
ai_hidden
```

v2.4.4 UI can show/hide these layers, but does not support full layer management.

---

## 5. API Behavior

Canvas edge creation:

- complete edge payload creates `visual_only`;
- loose endpoint payload creates `incomplete`;
- invalid ports fail before mutation;
- node ownership and canvas ownership must match.

Relation binding:

- incomplete edge fails;
- complete edge creates one `object_relations` row;
- edge updates to `relation_backed`;
- relation type must be one of the v2.4.4 seed types.

Unbind:

- removes the edge's `object_relation_id`;
- changes state back to `visual_only`;
- marks the ObjectRelation as `detached`;
- does not delete the edge or target objects.

---

## 6. Frontend Behavior

Canvas UI:

- toolbar includes `Connect`;
- node ports appear while connect mode is active or a node is selected;
- drag from a port starts an edge draft;
- drop on another node port creates a complete edge;
- drop on empty canvas creates an incomplete edge;
- edges render in an SVG layer below nodes;
- selecting an edge opens an inspector.

Inspector:

- displays state, source node, target node or loose endpoint;
- lets the user choose relation type and layer;
- supports bind, unbind, archive;
- disables bind for incomplete edges.

---

## 7. Data Safety

Creating or editing CanvasEdges does not mutate:

- NoteBlocks;
- SourceSnapshots;
- SourceScopes;
- EvidenceSets;
- Proposals;
- SourceBoards.

Only relation binding creates semantic truth, and only after user action.

---

## 8. Graph-Native Notes

v2.4.4 should record these future v3.x lessons:

- `CanvasEdge` is projection and may degrade.
- `ObjectRelation` is a graph edge candidate.
- `RelationLayer` may become graph subgraph metadata, relationship property, or graph node.
- Incomplete visual edges are not graph truth.
- Broken bindings require recovery state rather than silent deletion.
