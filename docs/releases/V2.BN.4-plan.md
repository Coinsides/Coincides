# V2.BN.4 Plan - Page / Canvas / Export Boundary

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:executing-plans` to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Define Coincides as a page-first, canvas-backed note surface where formal page content, outside-page scratch work, export visibility, and AI visibility are clear to the user and stable in data.

**Architecture:** V2.BN.4 builds on V2.BN.3 BlockBox layout. NoteBlock remains content truth; BlockBox / placement remains layout truth; page/canvas/export state is projection and policy state around those objects. Export preview is a seed view, not a full PDF export engine.

**Tech Stack:** React, TypeScript, CSS modules, existing NoteDetail note-block APIs, existing `note_block_placements.display_overrides_json` layout payload where sufficient, browser smoke through the local client.

---

## Summary

V2.BN.4 answers a product question we kept circling around during V2.BN.3:

```text
What is the formal note page,
what is outside-page scratch/canvas space,
what exports,
and what can AI see?
```

The result should feel simple:

- page mode is the stable writing/export surface;
- open canvas mode gives extra working space;
- objects inside the formal page default to exportable;
- objects outside the formal page default to scratch / not exported;
- export visibility and AI visibility are related but separate.

This version does not attempt to finish the full edgeless canvas, PDF export engine, or page-number editor. It creates the first reliable product boundary.

## User Workflow

### Workflow 1: Understand What Exports

1. User opens a note.
2. User sees a formal page boundary.
3. User places content inside the formal page.
4. The content is treated as exportable by default.
5. User places a scratch note outside the formal page.
6. The scratch object remains saved and searchable, but is not exported by default.
7. User can inspect or toggle export intent for a selected object.

Expected result:

- The product can explain why a block is included or excluded from export.
- Page-outside content does not silently pollute the formal report.

### Workflow 2: Page Mode Versus Open Canvas Mode

1. User starts in locked page mode.
2. Formal page content stays stable and page-first.
3. User switches to open canvas mode.
4. The user gets more working space around the page.
5. The formal page boundary remains understandable.
6. User switches back to page mode without losing placements.

Expected result:

- Mode switch changes the work surface behavior.
- Mode switch does not rewrite NoteBlock content.
- Open canvas mode does not turn every scratch object into formal report content.

### Workflow 3: AI Visibility Is Not Export Visibility

1. User selects a page-outside scratch block.
2. User sees that it is excluded from export by default.
3. User can mark whether AI may read it.
4. User can keep a private scratch object hidden from export and hidden from AI.
5. User can keep another scratch object hidden from export but visible to AI as thinking context.

Expected result:

- Export visibility answers "will this appear in a shared/exported document?"
- AI visibility answers "can assistant workflows use this as context?"

### Workflow 4: Export Preview Seed

1. User opens an export preview or export boundary view.
2. Exportable objects are emphasized.
3. Excluded scratch objects are lightly marked or omitted from the preview.
4. Broken or ambiguous export states show warnings.

Expected result:

- This is a preview seed, not a full PDF engine.
- It helps users understand the boundary before the real export pipeline exists.

## Data / State Impact

Touched:

- `NoteBlock` content truth: unchanged by page/canvas/export mode changes.
- BlockBox / placement layout truth: may gain or persist export/AI visibility metadata in the existing layout payload if sufficient.
- Page / canvas projection state: mode, page boundary, outside workspace, export preview state.
- UI state: selected object, mode switch, export preview, AI visibility toggle, export role indicator.

Not touched unless the audit proves it is strictly required:

- full PDF export engine;
- source chain / provenance schema;
- ObjectRelation / relation runtime;
- TemplateDefinition field schema;
- Concept-lite;
- GraphRAG adapter;
- OCR/VLM source reconstruction;
- package import/export.

### Data Contract Questions To Answer Before Implementation

- Can `note_block_placements.display_overrides_json` safely store first-pass `export_role` and `ai_visibility` metadata?
- Do we need a lightweight page-surface payload distinct from each BlockBox payload?
- How do we classify an object as page-in or page-out: by its anchor point, bounding box center, or full box intersection?
- What is the default rule for a block crossing the page boundary?
- How does old V2.BN.3 layout data display if it has no export/AI visibility metadata?
- Can export/AI visibility be changed without changing NoteBlock content or semantic relation truth?

Important rule:

If a user workflow needs a small data repair to avoid fragile client-only state, do it in this version. Do not leave page/canvas/export truth as invisible cache just because V2.BN.6 is later.

## Key Product Rules

- Coincides is page-first and canvas-backed.
- Formal page area is the default export surface.
- Outside-page workspace is saved, useful, and searchable, but defaults to scratch / not exported.
- Scratch objects can still be NoteBlocks.
- Page-outside objects can still have source references and relations.
- Export visibility and AI visibility are separate object-level policies.
- Visual position does not create semantic relation.
- Page mode should feel calm and document-like.
- Open canvas mode should give workspace freedom without losing the formal page.
- Top bar / side tools / bottom tools are app chrome, not page content.

The audit must answer:

- where the formal page dimensions are defined;
- whether the current page shell can show outside-page workspace;
- where mode state should live first;
- whether export/AI visibility can be stored without migration;
- whether existing top chrome and Insert controls stay outside page content.

### 2. Page Mode / Open Canvas Mode Seed

Implement a first-pass mode control:

```text
Page:
  locked, formal writing/export surface.

Canvas:
  open workspace around the page.
```

The first version may be visually modest. It must still make the mode boundary understandable.

### 3. Formal Page And Scratch Workspace

Clarify page-in and page-out behavior:

- page-in objects default to exportable;
- page-out objects default to scratch / excluded from export;
- page-out objects are still saved;
- page-out objects can still be selected, moved, resized, sourced, and related.

### 4. Export Role Seed

Add object-level export intent:

```text
export_role:
  default
  included
  excluded
  scratch
```

First version can store this in placement/layout metadata if the audit confirms it is safe.

### 5. AI Visibility Seed

Add object-level AI visibility:

```text
ai_visibility:
  default
  visible
  hidden
```

This must not be confused with export visibility.

### 6. Export Preview Seed

Add a small preview/status surface that explains:

- included objects;
- excluded/scratch objects;
- ambiguous boundary objects;
- page-outside objects that remain AI-visible.

Do not build real PDF export in this version.

### 7. UI / Chrome Placement Review

Make sure app controls remain outside page content:

- top bar;
- mode switch;
- Insert tool;
- more menu;
- future inspector entry;
- future bottom/side dock.

No permanent engineering panel should live at the bottom of a long page.

## Out Of Scope

V2.BN.4 does not implement:

- full PDF export;
- full project backup;
- full continuous multi-page canvas;
- page number editor;
- full edgeless canvas with pan/zoom physics;
- relation mode;
- source library;
- GraphRAG adapter;
- OCR/VLM reconstruction;
- full Style Studio;
- AI note assembly.

## Test Plan

Automated / build checks:

- client build passes;
- server build only if server files are touched;
- `git diff --check`;
- changed-file secret scan.

Browser smoke:

```text
Open a note.
Verify formal page boundary is visible and balanced.
Create one block inside the page.
Move or create one block outside the page boundary.
Verify inside block defaults to export included.
Verify outside block defaults to scratch / excluded.
Toggle export role for a selected block.
Toggle AI visibility for a selected block.
Switch Page / Canvas mode.
Reload note and verify placements and visibility states remain.
Open export preview seed and verify included/excluded explanation is visible.
```

Experience review:

- Page mode should feel like a real document surface.
- Open canvas mode should not make the page title or toolbars feel like page content.
- Export boundary indicators should be light, not noisy.
- Scratch objects should be discoverable but not visually dominant.
- The user should not need to understand database terms to know what will export.
