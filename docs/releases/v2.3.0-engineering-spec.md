# v2.3.0 Engineering Spec - Source Snapshot Foundation

**Created**: 2026-05-22
**Updated**: 2026-05-22
**Status**: Draft

---

## 1. Implementation Boundary

v2.3.0 adds a text-first normalized Source Snapshot layer over existing parsed course documents.

It implements:

- additive source snapshot tables;
- idempotent snapshot generation from `documents` and `document_chunks`;
- snapshot list/detail/pages APIs;
- minimal Course Detail viewer.

It does not implement SourceAnchor, source range selection, PDF rendering, Source Board, annotation editing, Canvas, or external snapshot tools.

---

## 3. Generation Behavior

Snapshot generation uses existing course material state.

Input sources:

```text
documents
document_chunks
source_materials
```

Rules:

- Only `documents.parse_status = completed` with matching `source_materials` can generate ready snapshots.
- Chunks with `page_start/page_end` become page-like groups.
- If chunks have no page metadata, they become ordered synthetic pages.
- Re-running generation deletes/replaces pages for the same snapshot but preserves the snapshot identity.
- Failed, pending, or missing material rows return warnings.

---

## 4. API Behavior

Routes:

```text
GET /api/source-snapshots?course_id=...
POST /api/source-snapshots/generate
GET /api/source-snapshots/:id
GET /api/source-snapshots/:id/pages
```

Responses must be user-scoped.

`GET /api/source-snapshots/:id` returns:

```json
{
  "snapshot": {},
  "pages": [],
  "warnings": []
}
```

`GET /api/source-snapshots/:id/pages` returns:

```json
{
  "pages": [],
  "warnings": []
}
```

---

## 5. UI Behavior

Course Detail adds a Source Snapshots section near the existing Course Material / Proposal workspace.

Minimum UI:

- generate snapshots button;
- list existing snapshots;
- open selected snapshot;
- show source title, filename, status, page count, chunk count;
- render page-like text sections;
- show warnings;
- no highlight editing or range selection.
