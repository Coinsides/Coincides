# v2.4.3 Engineering Spec - Agent Canvas Layout Proposal UX

**Created**: 2026-05-23
**Updated**: 2026-05-23
**Status**: Draft / active implementation

---

## 1. Contract

v2.4.3 adds `canvas_layout` proposals. A layout proposal is a reviewable mutation over canvas projection records.

It may create or update:

- `canvas_nodes`
- `canvas_frames`
- `learning_canvases` projection sizing/metadata
- `operation_batches`
- `proposals.status`

It must not create or update:

- `note_blocks`
- `note_block_sources`
- `source_materials`
- `source_fragments`
- `material_segments`
- `evidence_sets`
- `canvas_edges`
- future `object_relations`

## 2. API

### `POST /api/proposals/canvas-layout`

Payload:

```json
{
  "course_id": "course-id",
  "canvas_id": "canvas-id",
  "source_board_id": "optional-board-id",
  "canvas_node_ids": ["optional-existing-node-id"],
  "source_scope_ids": ["optional-source-scope-id"],
  "note_block_ids": ["optional-note-block-id"],
  "layout_goal": "a4_reading"
}
```

Rules:

- `course_id` and `canvas_id` are required.
- `layout_goal` defaults to `a4_reading`.
- Source Board, Source Scopes, NoteBlocks, and CanvasNodes must belong to the same user/course.
- If no existing or selected object can be laid out, return `400`.
- Creating the proposal inserts only a pending proposal row.

### `POST /api/proposals/:id/apply`

For `canvas_layout`, apply:

- creates missing CanvasNodes for selected existing objects;
- updates layout for existing CanvasNodes;
- creates CanvasFrames from proposal frame entries;
- expands canvas height if the planned layout exceeds current height;
- creates an operation batch with `source_type = proposal`.

## 4. Deterministic Planner

The first planner is local and deterministic:

- A4/page-first layout.
- Two-column layout when there is enough canvas width.
- Stable order:
  - selected/existing CanvasNodes;
  - active Source Board nodes;
  - explicit SourceScopes;
  - explicit NoteBlocks.
- Deduplicate by `node_type + target_id`.
- Preserve existing node dimensions when updating.
- Use a single frame around the proposed group.
- Add warnings when the layout is broader than the first A4 page or when no Source Board / source scope input is present.

No real AI API call is made in v2.4.3.

---

## 5. Frontend Behavior

Course Detail / Canvas Document adds:

- `Plan layout` button;
- layout proposal creation using the active canvas and active Source Board or active Source Scopes;
- existing proposal review panel support for `canvas_layout`;
- preview list of planned node actions and frame count;
- apply/discard through the existing proposal review controls.

Optional first preview:

- show proposed node rectangles as a non-editing overlay on the canvas surface.

---

## 6. Tests

Server tests must cover:

- proposal creation has no projection mutation;
- existing node layout proposal;
- Source Board missing node proposal;
- apply creates/updates projection rows only;
- discard leaves layout unchanged;
- invalid ownership / empty input fail safely.

Client build must pass after the proposal UI is wired.
