# V2.BN.8.6.13-8.6.22 手动测试清单

> 范围：ContentGroup、GroupFolder、Groups Rail、Group Gallery、Single Group Editor、拖拽收纳、刷新持久化。
>
> 目标：确认这一轮不是一堆零散按钮，而是能作为第一版成熟 ContentGroup Editor 地基继续往上盖。

## 0. 测试准备

- [ ] 使用一个干净测试账号，或者一次性测试账号。
- [ ] 新建一个 project。
- [ ] 在这个 project 里新建一个 note。
- [ ] 新建一个 TextBlock，至少写 5 行普通文本。
- [ ] 在一段文本上创建至少一个 label。
- [ ] 如果当前 UI 支持，创建至少一个 block 级对象。
- [ ] 正式测试前先刷新一次页面，避免旧的前端状态掩盖持久化问题。

## 1. 基础页面健康

- [ ] 打开 Home，应用不应该崩溃。
- [ ] 打开 Projects，已有 project 应该正常显示。
- [ ] 打开某个 project，project 页面应该正常加载。
- [ ] 打开某篇 note，已有 block 应该正常渲染。
- [ ] 从左侧导航进入 Group Gallery，它应该是完整页面，而不是小浮窗。
- [ ] 从 Group Gallery 回到普通 note / project 导航，不应该丢失应用状态。

失败条件：

- 页面黑屏。
- 普通导航必须刷新才能恢复。
- Group Gallery 显示成局部气泡窗，而不是完整管理页面。

## 2. GroupFolder 地基

- [ ] 在 Group Gallery 里确认 workspace / project / note 对应的 group folder 可见或可进入。
- [ ] 刷新后，project root folder 和 note root folder 不应该重复生成。
- [ ] 如果 UI 暴露了入口，尝试新建一个普通 folder。
- [ ] 同一区域里，folder 应该优先显示在 ContentGroup 前面。
- [ ] 如果 UI 暴露了路径，尝试创建或移动一个 ContentGroup 到某个 folder 里。
- [ ] 刷新页面后，folder 和 ContentGroup 的位置应该保持不变。

失败条件：

- root folder 刷新后重复出现。
- ContentGroup 没有任何 folder 归属。
- 刷新后 folder 位置或 group 归属丢失。

## 3. Groups Rail / Content 入口

- [ ] 打开一篇 note，点击 Content / Groups 入口。
- [ ] 右侧 rail 应该打开当前 note 范围下的内容。
- [ ] rail 应该是轻量入口，默认不应该像一个巨大表单。
- [ ] 没有选中文本时，rail 不应该出现误导性的 Add selected 操作。
- [ ] 如果支持，从 rail 新建一个 ContentGroup。
- [ ] 展开一个已有 ContentGroup，只应该看到概要级内容。
- [ ] 如果入口可用，从 rail 跳到 Gallery 或完整 editor。

失败条件：

- rail 试图一次性承载所有操作。
- rail 的 scope 明显错误。
- rail 过度遮挡内容区，让正常写作变得难受。

## 4. Draft Range / Label / Block 收纳

### Draft Range

- [ ] 选中一小段普通文本。
- [ ] 右键点击选区。
- [ ] 右键菜单应该提供 ContentGroup 相关操作，并且不能弹出浏览器原生 `prompt()`。
- [ ] 用这段选中文本创建一个 ContentGroup。
- [ ] 再选中另一段文本，把它加入已有 ContentGroup。
- [ ] 确认原文仍然留在原地，没有被搬走。

### Label

- [ ] 用一个文本范围创建 label。
- [ ] 如果多段选区可用，用多个 range 创建一个 label。
- [ ] 把这个 label 加入已有 ContentGroup。
- [ ] ContentGroup member preview 应该能反映 label 的内容。
- [ ] 加入 label 不应该删除或改变原 label。

### Block

- [ ] 选中或聚焦一个 block。
- [ ] 使用当前可用的命令入口，把这个 block 加入 ContentGroup。
- [ ] ContentGroup member 应该能区分它来自 block，而不是普通文本范围。
- [ ] 原 block 应该仍然留在 note 里。

失败条件：

- 任意操作打开浏览器原生 alert / prompt。
- 加入 item 后，原文从 note 里被移走。
- 加入后无法区分来源类型。

## 5. 拖拽地基

- [ ] 选中一个 Draft Range，尝试把它拖进 ContentGroup 目标区。
- [ ] 如果支持，把 label badge 或 label 区域拖进 ContentGroup 目标区。
- [ ] 如果支持，把 block 拖进 ContentGroup 目标区。
- [ ] 成功 drop 后，应该创建一个 member。
- [ ] source text / label / block 应该仍然留在原 note 里。
- [ ] 把内容拖到不支持的区域时，应该明确取消或 no-op，不能假装成功。
- [ ] 如果适用，在拖拽或选区状态中按 Esc / 点击外部，draft 状态应该安全清空。

高风险观察项：

- 如果选中文本后无法自然开始拖拽，记录卡住的具体位置。
- 如果 drop target 不明显，即使数据层成功，也记录为 UX 问题。

## 6. Group Gallery

- [ ] 从左侧导航打开 Group Gallery。
- [ ] 确认它占据主页面，而不是局部浮窗。
- [ ] 左侧区域应该像资源管理器 / folder browser。
- [ ] 切换 Folder 视图。
- [ ] 切换 Topic 视图。
- [ ] 切换 Role 视图。
- [ ] 切换视图不应该删除当前 selection 或数据。
- [ ] ContentGroup card / row 应该提供足够信息，让用户知道这是哪个 group。
- [ ] 点击某个 ContentGroup，进入它的 detail editor。
- [ ] 从 detail editor 返回 Gallery。

视觉期望：

- Gallery 应该像管理页面，而不是拥挤表单。
- Folder / Topic / Role 是浏览维度，不应该像三个互不相关的表单。

已知设计缺口：

- Role 后续应该变成小 type / tab / badge。
- Topic 后续应该变成颜色 / 路径信号。
- 如果当前 UI 仍然把它们显示成普通输入框，记录为视觉成熟度债务，不一定算阻塞性数据 bug。

## 7. Single ContentGroup Editor

- [ ] 打开一个 ContentGroup 的 detail editor。
- [ ] 修改 display name。
- [ ] 修改 topic。
- [ ] 修改 role。
- [ ] 修改 summary。
- [ ] 如果 UI 暴露了 Draft / Accepted / Rejected / Archived，切换 identity 状态。
- [ ] 如果有显式保存按钮，点击保存；如果是自动保存，确认行为一致。
- [ ] 添加至少两个 members。
- [ ] 删除一个 member。
- [ ] 删除 member 不应该删除原始 source content。
- [ ] 创建一个 Petal。
- [ ] 重命名这个 Petal。
- [ ] 删除这个 Petal。
- [ ] 如果 UI 暴露了分配能力，把至少一个 member 分配到 Petal。
- [ ] 刷新页面，确认字段、members、identity、Petals 都还在。

失败条件：

- Petal 表现得像旧 child label。
- 字段修改刷新后丢失。
- 删除 member 时删除了原文。
- editor 和 rail 几乎没有角色差异。

## 8. 持久化与完整性

- [ ] 创建 folder、group、member、petal。
- [ ] 刷新浏览器。
- [ ] folder 应该仍然存在。
- [ ] group 应该仍然在同一个 folder 里。
- [ ] group 字段应该保持。
- [ ] members 应该保持。
- [ ] petals 应该保持。
- [ ] 修改某个 member 对应的原始文本。
- [ ] 如果支持刷新 preview，preview 应该可刷新；如果不支持，应显示 stale 状态或保持明确语义。
- [ ] 删除一个 member，确认原文仍然存在。
- [ ] 如果支持，删除或 archive 一个 ContentGroup，再刷新确认状态符合预期。

失败条件：

- 任意 ContentGroup 变成孤儿对象。
- 任意 member 丢失 source locator，只剩 preview text。
- 刷新改变 folder 归属。

## 9. Annotation 回归

- [ ] 创建一个普通 label。
- [ ] 创建重叠 label。
- [ ] 如果支持，创建多段 range label。
- [ ] 修改 label 颜色并刷新。
- [ ] parent label badge 应该仍然显示。
- [ ] 旧 child label 行为不应该重新变成主要工作流。
- [ ] 打开 Annotation Stack，已有 label 管理不应该崩溃。
- [ ] 如果有 label 高亮开关，确认开关仍然可用。

失败条件：

- 颜色修改刷新后不保存。
- parent label 名字消失，只剩 child label 名字。
- Annotation Stack 崩溃，或异常膨胀成破碎全屏状态。

## 10. 文本编辑回归

- [ ] 新建一个 TextBlock。
- [ ] 创建后立刻输入文本。
- [ ] 点击 block 外部，再点回文本继续输入。
- [ ] 点击某行中间并输入。
- [ ] 在已有 block 中按 Enter。
- [ ] 在不同 block 之间切换点击时，光标不应该跳到错误位置。
- [ ] ContentGroup 功能不应该明显压缩可书写区域。
- [ ] 右键菜单不应该阻断正常选区和光标行为。

失败条件：

- block 失焦后无法再次编辑。
- 在 paragraph / definition-like block 之间切换后，光标跳错位置。
- TextUnit 控件明显统治书写区域。

## 11. Command Surface / 右键菜单

- [ ] 右键普通文本选区。
- [ ] 右键 label / highlight 区域。
- [ ] 右键 block 表面。
- [ ] 如果 ContentGroup member preview 可编辑，右键其中内容。
- [ ] 菜单内容应该匹配当前上下文。
- [ ] 低频操作不应该全部浮在表面按钮里。
- [ ] label 或 group 命名不应该使用浏览器原生 alert / prompt。

期望方向：

- 面向用户的文字优先使用 Label / Add to group / Turn into / Inline 这类产品语言。
- Annotation、DraftRange、source locator 这类内部术语不应该主导普通用户界面。

## 12. 最终成熟度评审

只有满足这些条件，这一轮才算通过：

- [ ] 用户不理解内部数据名，也能创建 ContentGroup。
- [ ] 用户能把文本、label、block 放进 group。
- [ ] 用户之后能在 Gallery 里找回这个 group。
- [ ] 用户能打开一个 group，并检查 / 编辑它的基础字段。
- [ ] 刷新不会破坏 folder、group、member、petal 数据。
- [ ] 原文仍然是真相源；ContentGroup member 是引用 / 整理视图，不是破坏性移动。

这些问题记录为后续项，不一定阻塞本轮通过：

- Topic color 和 role type 的视觉语言还不成熟。
- Gallery card 设计仍然粗糙。
- Petal 编辑存在但不够顺手。
- 拖拽手感别扭，但不破坏数据。
- 三个界面能工作，但仍需要 taste-level 视觉重设计。
