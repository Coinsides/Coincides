# V2.BN.8.6.25 Unified Item And Content Range Drag Foundation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 建立 Draft Range、Label、Block 的统一 item 拖拽地基，让用户能把内容碎片拖进 ContentGroup，也为未来拖到 Page / Canvas / TextBlock 位置打下安全模型。

**Architecture:** 本版本把拖拽定义为全局编辑基础能力，而不是 ContentGroup 专属按钮。实现上先统一 drag payload、drag source、drop target、drop preview 和安全写入规则；ContentGroup intake 是第一批目标，Page / Canvas 创建 block 是受控扩展目标，同 TextBlock 内部重排只保留设计口子，不开放完整复杂行为。

**Tech Stack:** React, TypeScript, Canvas Engine, HTML Drag and Drop API or pointer-based internal drag layer, existing selection draft engine, ContentGroup services, TextBlockProjection.

---

## 1. 背景

当前已经有一条数据通路：

```text
Draft Range badge / Label badge / Block payload
  -> drag payload
  -> ContentGroupPanel drop target
  -> ContentGroup members
```

但用户体验还不成立：

- 用户拖的是小 badge，不是自然的蓝色选区本体。
- Draft Range 和 Label 的本质关系没有在交互里表现出来。
- 右键可以打开 Rail，但直接加入目标 group 的体验不稳定。
- Drop target 主要集中在 Rail，Gallery / Single Editor 还不完整。
- 拖到 Page 空白处、Canvas scratch、TextBlock 内部位置这些全局行为还没建立。

因此 8.6.25 的重点不是“再补一个拖拽按钮”，而是建立统一 item drag foundation。

## 2. 本版本核心定义

### 2.1 Item

Item 是动作层对象：

```text
凡是可以被选中、拖拽、右键加入 ContentGroup 的对象，都是 item。
```

第一阶段 item：

```text
Draft Range item
Label item
Block item
```

暂不做：

```text
TextUnit as standalone item
Table region item
Image region item
Canvas object item
ContentGroup reference item
```

### 2.2 Draft Range 和 Label

```text
Draft Range = 临时 range package
Label = 有名字、持久化的 range package
```

两者进入 ContentGroup 时处理方式应基本一致：

```text
Draft Range -> ContentGroup member from ranges
Label -> ContentGroup member from annotation ranges, with label name
```

Label 不是不可拆的神秘对象。未来在 Single Editor 中，Label 可以展开成内部 ranges，再分配给 Petal。

### 2.3 Drop 行为分区

```text
Drop into ContentGroup
  创建引用 / member。
  不搬走原文。
  不改变正文布局。

Drop into document / page / canvas
  创建或改变可见内容。
  默认 copy / projection。
  破坏性 move 必须有显式模式和 undo。
```

8.6.25 必须先保护原文，不要默认做破坏性移动。

## 4. Task 1: 统一 Drag Payload

**Files:**

- [ ] **Step 1: 定义统一 item drag payload**

Payload 第一阶段支持：

```ts
type ContentItemDragPayload =
  | {
      kind: 'draft_range';
      ranges: AnnotationRangeV1[];
      text_preview: string;
      source_note_id: string;
    }
  | {
      kind: 'label';
      annotation_id: string;
      label: string;
      ranges: AnnotationRangeV1[];
      source_note_id: string;
    }
  | {
      kind: 'block';
      block_id: string;
      label: string | null;
      source_note_id: string;
    };
```

如果现有代码仍使用 `draft_ranges` 复数形式，可以在 8.6.25 中保留兼容读取，但新写入统一使用 `draft_range`。如果不需要兼容测试数据，可以直接清理旧形式。

- [ ] **Step 2: 写入 payload validator**

要求：

```text
读取 drag payload 时必须校验 kind。
range 必须有 block_id 或 source path。
空 ranges 不可写入。
未知 kind 直接返回 null。
```

- [ ] **Step 3: 合同文档同步**

在 ContentGroup 合同里写：

```markdown
## Item Drag Payload

Draft Range, Label, and Block are the first supported item drag payloads.
Drop into ContentGroup creates member references and must not move source text.
Drop into document/page/canvas creates visible content and must use copy/projection by default.
```

## 5. Task 2: Draft Range 拖拽入口成熟化

**Files:**

- Modify: `client/src/pages/Notes/canvasEngine/blocks/TextBlockProjection.tsx`
- Modify: `client/src/pages/Notes/canvasEngine/layers/NoteWritingSurfaceLayer.tsx`

- [ ] **Step 1: Draft Range 不再只能拖 badge**

当前 badge 可以保留，但拖拽入口要扩展到 draft range 的高亮层或选区浮层。

第一版可接受交互：

```text
用户选中文字形成 Draft Range。
高亮区域上出现轻量 drag affordance。
用户从高亮区域或 affordance 拖动。
拖动 payload 是 draft_range。
```

如果因为浏览器原生 selection 干扰，第一版可以让高亮区域边缘出现一个小拖动 handle，但不能只剩 `Draft Range` 文字 badge。

- [ ] **Step 2: 普通点击不误触拖拽**

规则：

```text
单击高亮区域:
  保持选区 / 打开轻量操作状态。

拖动超过阈值:
  开始 drag。

点击外部:
  清掉 draft range。
```

- [ ] **Step 3: 多段 Draft Range 保持完整**

Ctrl 多段选区拖拽时，payload 必须包含全部 ranges。

手动测试：

```text
选中 range A。
按 Ctrl 选中 range B。
拖动 draft range。
Drop 到 group。
group member preview 中包含 A 和 B。
```

## 13. 合格标准

8.6.25 合格意味着：

- Draft Range / Label / Block 使用统一 item payload。
- Draft Range 拖拽不再只依赖小 badge。
- Label 拖入 ContentGroup 后仍保留正文 label。
- Block 拖入 ContentGroup 后不移动原 block。
- Rail / Gallery / Single Editor 至少各有一个可用 ContentGroup drop target。
- Page 空白区域可以接收 Draft Range / Label 并创建新 TextBlock，或明确记录为受 guard 保护的未开放目标。
- Drop into ContentGroup 不改变原文。
- Drop 失败不丢 selection / draft range。
- 同 TextBlock 内复杂重排没有被偷偷开放。
