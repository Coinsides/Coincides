# V2.BN.8.9.3.1 PageFrame Print Scale And Document Typography Baseline Patch Note

Date: 2026-06-26

Status: completed scoped pre-8.9.4 patch.

## Why This Patch Exists

8.9.3 made PageFrame margins visible and snappable, but the default PageFrame still behaved too much like a content-height rectangle. Before adding header / footer / page number slots in 8.9.4, PageFrame needs a more document-like baseline:

- a named paper-size baseline;
- a paper-like height / width ratio;
- a stable default document typography profile;
- runtime and AI-readable markers that can tell future export / Agent layers how the page is scaled.

This patch does not implement the full TextFlow font system. It only establishes the PageFrame and document-default baseline that later TextFlow typography can use.

## What Changed

### PageFrame Print Scale Service

Added `pageFramePrintScaleService.ts`.

It owns:

- `DEFAULT_PAGE_FRAME_PAGE_SIZE`
- `DEFAULT_DOCUMENT_TYPOGRAPHY_PROFILE`
- `PAGE_FRAME_PRINT_PRESETS`
- `createPageFramePrintProfile`
- `createDefaultDocumentTypographyProfile`
- `normalizePageFramePrintBaseline`
- `documentTypographyToCssVars`

The default page size is `A4`. The current writing content width is preserved, while the PageFrame height now follows an A4-like logical paper ratio.

### Runtime Contract

Extended runtime types with:

- `PageFramePageSize`
- `DocumentTypographyProfile`
- `PageFramePrintProfile`
- optional `PageFrameModel.pageSize`
- `PageFrameExtension.documentTypography`

`engineModel.ts` now derives the default PageFrame from the print profile instead of hard-coding a short page height.

### Legacy Test Geometry

`pageFrameCollectionService.ts` now normalizes PageFrames without explicit `pageSize` through the active print baseline.

This is intentional. The product is not in production, current saved data is test data, and we are not carrying long-term compatibility for old squat PageFrame geometry.

### AI-Readable Layout

PageFrame AI-readable nodes now expose:

- `pageFrameRef.pageSize`
- `pageFrameRef.documentTypography`

This keeps PageFrame readable as a document surface, not just a rectangle.

### Visible Writing Surface

`NoteWritingSurfaceLayer.tsx` now exposes:

```text
data-page-frame-page-size
data-document-typography-profile
data-document-font-size
data-document-line-height
```

`NoteDetail.module.css` now applies document typography variables to writing text areas.

## Not Included

- No user-facing font picker.
- No TextFlow style schema.
- No per-block font size / line height controls.
- No header / footer / page number slots.
- No PageFrame template / background system.
- No export engine rewrite.
- No ContentGroup projection.
- No Relation runtime.
- No Agent write path.

## Validation

Run:

```text
npm run smoke:canvas-engine-model-contract
npm run check:canvas-runtime-boundary
npm run build:client
git diff --check
```

Browser smoke should check:

1. Open a note in Page Mode.
2. Confirm writing surface has `data-page-frame-page-size="A4"`.
3. Confirm writing surface has document typography markers.
4. Confirm text area computed font size / line height match the baseline.
5. Confirm PageFrame still renders guides from 8.9.3.
