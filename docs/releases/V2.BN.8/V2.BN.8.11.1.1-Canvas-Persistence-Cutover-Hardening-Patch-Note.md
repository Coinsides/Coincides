# V2.BN.8.11.1.1 Canvas Persistence Cutover Hardening Patch Note

> Status: completed
> Date: 2026-06-28
> Owner: Henry + Codex
> Scope: Canvas persistence cutover hardening / migration regression / import-once cleanup

## 完成结果

本补丁已完成。它没有引入新的 structured object family，也没有提前推进 ContentGroup projection；本次只修 Canvas persistence cutover 的几颗雷。

完成项：

1. block-backed CanvasObject 改成 per-placement / per-projection 合成身份，不再裸用 `block_id` 当 `canvas_objects.id`。
2. `ContentMount` 继续指向共享内容真相：`targetKind = note_block`，`targetId = block_id`。
3. `getNoteCanvasPersistence` 与保存响应查询都补了 note / placement 维度的 mount join 去歧义，避免同一个 block 被跨 note 复用时扇出。
4. migration 035 的 legacy block layout backfill 同步改为 per-placement CanvasObject，并补回 PageFrame `documentTypography` backfill。
5. 新增 migration 037，修复已经跑过旧 035 的本地/开发数据库，把旧的 `canvas_objects.id = block_id` 记录迁到 per-placement 对象。
6. PageFrame 与 AnnotationTruth 的 legacy metadata strip 从两个 repository 并发 PUT，收敛到 adapter 边界的一次合并 strip PUT，避免 stale metadata key 互相复活。
7. 补了 cutover regression：跨 note 共享 block、legacy backfill、block identity repair、AnnotationTruth parent/child hierarchy 都进入测试。

验证结果：

npm run build:client

结果均通过。`build:client` 仍有既有的 Vite dynamic import / chunk-size warning，不是本补丁引入的新失败。

## 为什么插入这个补丁

V2.BN.8.11.1 已经把 PageFrame、block layout、AnnotationTruth 从 legacy metadata / display override 移进实体层。Claude 对 cutover 做了对抗式审查后确认：主体方向成立，但有一颗会影响后续 reuse / projection 的 P0 哑雷。

这个补丁不做新功能，也不提前进入 structured object family。它只负责把已经完成的 cutover 打硬，确保 8.11 后续普通 CanvasObject、8.12 ContentGroup projection / reuse 不会建在会串 note / 串 placement 的对象身份上。

## 核心问题

### P0：block projection 的 CanvasObject 身份错误

当前 block projection 把 `canvas_objects.id` 直接设为 `block_id`。这在单 note 内暂时不响，但同一个 block 内容未来可以被多个 note / placement 复用。

正确模型应该是：

```text
一个 NoteBlock / block = 内容真相
N 个 CanvasObject = N 个投影实例
N 个 CanvasPlacement = 各自所在 note / canvas 的几何位置
N 个 ContentMount = 都挂回同一个 block 内容
```

因此 block-backed CanvasObject 必须改成 per-projection / per-placement identity，而不是裸 `block_id`。

### P1：legacy metadata strip 存在竞态

`loadCanvasPersistenceForNote` 和 `loadAnnotationTruthsForNote` 现在可能基于同一份 `hydratedNote.metadata` 快照并发 PUT `/notes/:id`。一个 loader 删 PageFrame legacy key，另一个 loader 删 Annotation legacy key，后写者可能把前写者删掉的 key 又带回数据库。

实体真相不会坏，但旧 key 可能残留，破坏 import-once 的收口语义。

### P2：PageFrame typography backfill 丢字段

migration 035 的 PageFrame collection backfill 里，`page_frame_extensions.typography_json` 仍写死 `{}`，没有带入旧 frame 上可能存在的 `documentTypography`。live save 路径已经会保存 typography，因此 migration 路径需要补齐一致性。

### P2：cutover 测试盲区

当前 cutover 测试偏向新建空 metadata note，没有充分覆盖 legacy note 的 backfill round-trip，也缺少 parent / child AnnotationTruth 层级树的非平凡回归。

## 本补丁计划做什么

1. 将 block-backed CanvasObject id 改为 per-placement / per-projection 合成 id。
2. 保持 `ContentMount.targetKind = note_block`、`ContentMount.targetId = block_id`，让 mount 指回共享内容真相。
3. 在 `getNoteCanvasPersistence` 和保存响应查询中，对 content mount join 增加 note / placement 去歧义，避免一对多扇出。
4. 同步修改 migration 035 的 `backfillBlockLayouts`，旧 `better_notebook_layout` backfill 也生成 per-placement CanvasObject。
5. 合并 legacy PageFrame / Annotation metadata strip，避免两个 loader 并发 PUT 互相复活旧 key。
6. 修复 migration 035 PageFrame typography backfill，把 `frame.documentTypography` 写入 `page_frame_extensions.typography_json`。
7. 补充回归测试：
   - 同一 `block_id` 跨 note / placement 时，各 note 只读回自己的 layout；
   - legacy PageFrame + Annotation + block layout backfill round-trip；
   - AnnotationTruth parent / child 层级 round-trip；
   - 双 legacy key strip 后不复活。

## 明确不做

- 不做新的 structured object family。
- 不做 ContentGroup as CanvasObject projection。
- 不做 full CanvasObject reuse UI。
- 不做 Relation runtime / GraphRAG / Agent write。
- 不改变 V2.BN.8.11 与 V2.BN.8.12 的路线顺序。
- 不迁移用户真实生产数据；当前只针对本地开发 cutover 和测试数据路径加固。

## 验收标准

必须满足：

```text
cd server; npm run test:v2
npm run verify:v2-bn8-runtime
git diff --check
```

重点断言：

- 同一 block 内容跨 note 投影时，不会因为共享 `block_id` 导致 `canvas_objects.note_id` 被后写覆盖。
- `getNoteCanvasPersistence(noteA)` 不会读出 noteB 的 placement / mount。
- 带 `canvas_engine_page_frames_v1` 与 `canvas_engine_annotations_v1` 的 note 完成 load 后，两个 legacy key 都被清理且不复活。
- 迁移旧 PageFrame 时，`documentTypography` 不会丢成 `{}`。
- 新增测试覆盖 legacy backfill，而不是只覆盖空 metadata 新建路径。

## 给审查者的重点

Claude 审查时重点看三件事：

1. Item 1 是否同时做了 per-placement 合成 id 与 mount join 去歧义。
2. Item 2 是否真的消除了两个 loader 各自 PUT metadata 的竞态，而不是只在前端 state 里清理。
3. 新测试是否能在没有当前修复时失败，而不是只补了通过型快照。
