# V2.BN.8.5 Selection And AnnotationTruth Seed Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 建立第一版选区模型和 `AnnotationTruth` 语义根，让用户可以在自然写作后的 TextFlow / Block / CanvasObject 范围上做可确认、可显示、可投影的标注。

**Architecture:** V2.BN.8.5 不做完整 AI、Relation runtime 或 Structure Studio。它在 V2.BN.8.4 的 TextUnit editor 上新增 selection capture、annotation truth service、annotation overlay、selection toolbar / right-click entry、annotation inspector seed 和 model contract checks。TextFlow 继续负责自然写作，AnnotationTruth 负责被确认的语义/整理标注，ReadingInterpretation 只作为 AI proposal / interpretation seed，不反向锁死全局 schema。

**Tech Stack:** React 18、TypeScript、Vite、现有 Note Canvas Runtime、TextFlow service、Annotation contract、`client/scripts/canvasEngineModelContractCheck.ts`、Browser Use / Henry manual visual pass。

## 0. Scope Lock

V2.BN.8.5 是 selection + AnnotationTruth seed，不是完整 annotation editor，也不是完整 AI reading system。

### In Scope

- TextFlow 内选区捕获 first pass。
- 第一版 `AnnotationTruth` runtime type 和 service。
- Annotation range 支持 TextUnit / Text span / Block whole range。
- Annotation 高亮 / underline / badge 的低噪声第一版渲染。
- 右键菜单或 selection toolbar 的 `Annotate` / `Mark` 入口。
- Annotation inspector seed：查看、重命名 label、删除 annotation、显示 range 摘要。
- AnnotationProposal / ReadingInterpretation 的最小数据边界。
- `/definition` 或未来 slash command 的目标改为 annotation workflow，不再创建 DefinitionBlock。
- Inline formula / inline code / inline link 只作为 special render anchor 的边界文档，不在 8.5 做完整 runtime。
- 文档同步：Annotation contract、TextFlow contract、Block contract、README、Plan、Roadmap、CHANGELOG。

### Out Of Scope

- 完整 AI agent。
- 自动发现 definition / example / theorem。
- 全局 canonical role / slot schema。
- 固定角色字段编辑器。
- 完整 Annotation Studio。
- 完整多范围 annotation 编辑体验。
- Relation runtime。
- SourceReference attach。
- CanvasObject drawing tool。
- Media annotation 的完整实现。
- 完整 rich text editor。

## 1. Product Decisions

### AnnotationTruth 是语义根

用户自然写作时不会被迫先选择结构。用户写完后，或者未来 AI 读完后，可以把某个范围标注成一个 label。

```text
TextFlow answers:
  how the user wrote it

InlineStructure answers:
  how a local span should render or behave

AnnotationTruth answers:
  what selected content means after user confirmation
```

### 不做固定角色表

V2.BN.8.5 不预设全局 `definition / example / theorem / claim / evidence` 的硬 schema。

第一版允许：

```text
raw_label = "definition"
raw_label = "power series definition"
raw_label = "我觉得很难的地方"
raw_label = "Assignment 1 step 2"
```

系统只保证它们是可见、可寻址、可编辑、可投影的 annotation。后续 AI 可以通过 ReadingInterpretation 临时解释它们，而不是把用户锁进固定 schema。

### Child annotation 代替 slot schema

如果用户或 AI 想进一步标出 `concept name`、`description`、`equation`，不使用固定 role slot，而使用子标注。

```text
AnnotationTruth raw_label="Power Series Definition"
  range: several selected text ranges
  child annotation raw_label="concept name"
    range: "power series"
  child annotation raw_label="description"
    range: "a series of the form ..."
```

8.5 只需要为 child annotation 留数据和 projection 边界；完整 UI 可进入 8.6。

### AnnotationSet 先做 contract，不做重 UI

`AnnotationSet` 是多个 annotation 的集合，也是未来 CompositeEndpoint 的用户可见形态。8.5 可做 model seed / projection seed，不要求完整 group editor。

```text
AnnotationSet "Power Series prerequisites"
  AnnotationTruth A
  AnnotationTruth B
  AnnotationTruth C
```

## 3. Data Rules

### Annotation Range

第一版 range 必须稳定到 TextFlow 层，不直接保存脆弱 DOM offset。

```ts
type AnnotationRangeTargetKind =
  | 'text_unit'
  | 'text_span'
  | 'block'
  | 'inline_structure'
  | 'canvas_object'
  | 'source_region';

type AnnotationRangeV1 = {
  id: string;
  target_kind: AnnotationRangeTargetKind;
  block_id?: string;
  text_flow_id?: string;
  text_unit_id?: string;
  inline_structure_id?: string;
  canvas_object_id?: string;
  source_region_id?: string;
  start_offset?: number;
  end_offset?: number;
  range_text_cache?: string;
};
```

8.5 实现范围：

```text
text_unit
text_span
block
```

8.5 只预留：

```text
inline_structure
canvas_object
source_region
```

### AnnotationTruth

```ts
type AnnotationStatus = 'active' | 'hidden' | 'deleted';
type AnnotationCreatedBy = 'human' | 'ai_proposal' | 'importer';

type AnnotationTruthV1 = {
  id: string;
  note_id: string;
  canvas_id: string;
  raw_label: string;
  ranges: AnnotationRangeV1[];
  child_annotation_ids: string[];
  visual_style: {
    color_token: string;
    marker_kind: 'highlight' | 'underline' | 'badge' | 'quiet';
  };
  created_by: AnnotationCreatedBy;
  status: AnnotationStatus;
  created_at: string;
  updated_at: string;
};
```

Rules:

```text
raw_label cannot be empty after commit.
AnnotationTruth can cover one range or multiple ranges.
Deleted annotations are soft-deleted in 8.5.
No global normalization is required in 8.5.
No canonical role is required in 8.5.
```

### AnnotationProposal / ReadingInterpretation

V2.BN.8.5 只需要 seed，不做 AI。

```ts
type AnnotationProposalV1 = {
  id: string;
  note_id: string;
  proposed_label: string;
  proposed_ranges: AnnotationRangeV1[];
  reasoning_summary: string;
  status: 'pending' | 'accepted' | 'rejected';
  created_by: 'ai' | 'importer';
};
```

Accept behavior:

```text
pending proposal
  -> user accepts
  -> create AnnotationTruth
  -> proposal status = accepted
```

## 6. Risk Register

### Risk 1: Browser selection is fragile inside TextUnit editors

Mitigation:

```text
Keep selection capture small.
Only support same-TextUnit text span first.
Route multi-TextUnit selection to 8.6 if the DOM selection becomes unstable.
```

### Risk 2: Annotation marks make normal writing noisy

Mitigation:

```text
Default to subtle highlight.
Hide label badge until hover or selection.
Keep debug all-label mode in Preview / Inspector, not normal writing mode.
```

### Risk 3: Accidentally recreating canonical role schema

Mitigation:

```text
Store raw_label only.
Do not normalize label.
Do not require slots.
Use child annotations for local detail only after user/AI marks them.
```

### Risk 4: Annotation range breaks after text edit

Mitigation:

```text
8.5 only guarantees stable enough behavior for simple edits.
Keep range_text_cache for debugging.
If target text is edited heavily, mark annotation degraded instead of silently moving it.
Full resilient range rebasing enters 8.6 or later.
```

### Risk 5: Inspector becomes another heavy panel

Mitigation:

```text
Inspector seed stays compact.
No source graph.
No relation graph.
No AI confidence table.
Only label, ranges, style, status, rename, delete.
```
