# V2.BN.8.6.15 Scope Aware Groups Rail Shell Plan

> **For agentic workers:** Follow this plan exactly. Use `superpowers:executing-plans` when implementing. Keep the rail lightweight; do not turn it into the full editor.

**Goal:** 建立 scope-aware 的 Groups Rail 外壳，让 Content 入口在 project / note 等上下文中能打开正确范围的轻量侧边栏。
**Experience Test Policy:** 默认不使用 browser harness。体验测试优先 browser-use / in-app browser。
**Stop Point:** 当前页面能打开对应 scope 的 Groups Rail，但复杂编辑仍留给 Gallery / Single Group Editor。

---

## 0. 版本定位

8.6.15 解决入口问题。Content 入口不是只属于 note 右侧，它应该成为更全局的资源整理入口：在 project 里打开 project root，在 note 里打开 note root，在 workspace 入口打开 workspace root。

## 1. 不做什么

- 不做全屏 Group Gallery。
- 不做 Petal 细编辑。
- 不做复杂拖拽。
- 不把所有按钮都浮在表面。
- 不让 rail 继续承担完整编辑器职责。

## 3. 实施任务

### Task 1: 定义 scope resolver

- [ ] 新增或整理 `resolveGroupScope(routeOrContext)`。
- [ ] workspace 层返回 workspace root folder。
- [ ] project 层返回当前 project root folder。
- [ ] note 层返回当前 note root folder。
- [ ] 若 scope 缺失，返回明确空状态，不默默展示错误 folder。

### Task 2: Content 入口全局化

- [ ] 在 note 页面保留 Content / Groups 入口。
- [ ] 在 project 页面加入同一入口。
- [ ] 在需要时在 workspace/home 级别加入入口或预留入口。
- [ ] 入口只负责打开 rail，不直接打开完整编辑器。

### Task 3: Rail 信息瘦身

- [ ] Rail 默认显示当前 folder 下的 folder 和 ContentGroup 摘要。
- [ ] 默认不展开任何 ContentGroup。
- [ ] 新建 group 按钮可以保留，但不要把复杂字段表单铺满。
- [ ] Add selected 等高干扰按钮只在有有效 selection 时出现。
- [ ] Insert 固定模板功能隐藏或移除，因为当前设计不再以 block template 为核心。

### Task 4: Rail 到 Gallery 的通道

- [ ] Rail 顶部增加进入 Group Gallery 的轻入口。
- [ ] 入口打开全屏 Gallery，而不是局部气泡窗。
- [ ] Gallery 实现留给 8.6.18，本版可先打开占位或 disabled 状态。

### Task 5: 空状态

- [ ] 没有 active selection 时显示安静文案，不占据主注意力。
- [ ] 当前 folder 没有 group 时显示创建提示。
- [ ] 当前 scope 无法解析时显示可理解错误。

## 4. 合格标准

- 在 note 内打开 Content 入口，rail 指向 note root folder。
- 在 project 内打开 Content 入口，rail 指向 project root folder。
- Rail 不再像完整表单堆叠。
- 无 selection 时不展示误导性 Add selected 操作。
- Rail 中有通往全屏 Gallery 的明确路径。
