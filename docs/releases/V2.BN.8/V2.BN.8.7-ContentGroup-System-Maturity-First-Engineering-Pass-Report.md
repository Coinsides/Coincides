# V2.BN.8.7 ContentGroup System Maturity First Engineering Pass Report

Date: 2026-06-22

Status: first engineering pass completed.

## Scope

This pass pushes ContentGroup System maturity to the point where later CanvasObject / Canvas projection work can continue on a cleaner foundation.

In scope:

- Rail = collect.
- Gallery = organize.
- Single Editor = refine.
- ContentGroupMember = group-local content truth.
- ContentRange / SourceAnchor = source location truth.
- preview_text = display cache, not second truth.
- GroupFolder organizes placement only; it does not move source truth.
- Petal remains ContentGroup internal structure.
- Reference / Duplicate / Fork / Materialize / Open original are explicit reuse semantics.

Out of scope:

- destructive source mutation;
- true reorder / offset rebase;
- relation runtime;
- GraphRAG;
- full database entity migration;
- CanvasObject reuse / projection;
- media / drawing seed.

## Sub-plan Result

### A. Three-surface role and visual closure

Completed.

- Added a small surface-role service for Rail / Gallery / Single Editor.
- Rail now communicates `Groups · Collect`.
- Gallery now communicates `Content groups · Organize`.
- Single Editor now communicates `Single ContentGroup Editor · Refine`.
- The three surfaces now have stable product language instead of competing as three editors.

### B. Member / Source boundary hardening

Completed.

- `ContentGroupMember` now carries group-local `current_content`.
- `source_ref` records source location / source snapshot data.
- `source_sync_status` expresses whether member content still matches source.
- Display helpers prefer member-local content and treat source text as provenance, not writable truth.

Engineering judgment: after creation, member content and source range are no longer assumed to be identical. A user can refine a ContentGroup without silently rewriting the original note.

### C. GroupFolder / Gallery resource manager maturity

Completed.

- GroupFolder read paths now prefer active folders.
- Archived folders are excluded from normal organization views.
- Folder delete guards block unsafe deletion when active or archived children still exist.
- Moving a ContentGroup between folders preserves member/source truth.

Engineering judgment: Folder is organization metadata. It must not imply source relocation.

### D. Reuse semantics service boundary

Completed.

- Added a service boundary for `reference`, `duplicate`, `fork`, `materialize`, and `open_original`.
- Duplicate and Fork create new group identities.
- Fork preserves lineage.
- Materialize returns a plan only; it does not mutate TextFlow or original source.
- Open original is represented as a route/descriptor instead of hidden data mutation.

Engineering judgment: reuse semantics must be explicit before Canvas projection exists. Dragging a group into another context cannot silently decide whether it is a link, copy, fork, or materialized text.

### E. Petal refinement maturity

Completed as technical seed.

- Added pure `moveContentGroupPetal`.
- Single Editor has a drag handle for Petal local reorder.
- Model contract verifies Petal reorder does not rewrite members, source snapshots, or fragments.
- Petal remains internal to ContentGroup and does not become a source-text Label.

Remaining browser gap: reorder hand feel still needs a two-or-more-Petal smoke pass.

### F. Stability state and integrity pass

Completed.

- Added derived `ContentGroupStabilitySummary`.
- Covered empty group, empty Petal, stale source, orphaned member, deleted source note context, archived folder context, accepted-with-stale, and materialize-target-unavailable states.
- Rail / Gallery / Single Editor now expose lightweight stability hints.
- Single Editor disables unsafe `Accept` for empty/deleted/unresolved states.

Engineering judgment: stability is derived state, not a new source of truth.
