# V2.BN.8.9.12 PageFrame Operable Object Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make PageFrame behave like an actual operable CanvasObject: selectable, movable, resizable, minimally configurable, and persistable.

**Architecture:** PageFrame operation stays inside the current transitional `PageFrameCollectionModel` metadata boundary. PageFrame movement changes PageFrame geometry only; it does not move TextFlow blocks, does not create Block/PageFrame ownership, and does not implement PageStack. Block/PageFrame affiliation continues to be geometry-derived after placement changes.

**Tech Stack:** React + TypeScript client runtime, Vite, CSS modules through `NoteDetail.module.css`, Canvas Engine services under `client/src/pages/Notes/canvasEngine`, model-contract checks under `client/scripts`, V2.BN.8 release docs.

**Status:** First implementation pass completed on 2026-06-27. PageFrame selection, move, resize, persistence path, model/runtime checks, and browser first-pass smoke are complete. Continuous PageStack, PageSlice, lock, rich styling, and PageFrame toolbar refinement remain deferred to later 8.9.x/8.10+ work.

## 0. Product Scope

This version fixes the current usability gap:

```text
PageFrame is visible and creatable, but not yet operable as an object.
```

In scope:

- Click a PageFrame shell in Canvas/Layout Mode to select it.
- Show selected PageFrame affordance and stable DOM markers.
- Move selected PageFrame by dragging its shell.
- Resize selected PageFrame with visible handles.
- Persist PageFrame x/y/width/height through `savePageFrameCollection(...)`.
- Keep PageFrame focus and dynamic Canvas world behavior from 8.9.10.
- Keep independent PageFrame numbering guard from 8.9.11.
- Add model-contract and runtime-boundary checks.
- Add browser/manual smoke expectations.

Out of scope:

- Continuous PageStack.
- PageSlice extraction / split / merge.
- Moving blocks together with PageFrame.
- Durable generic CanvasObject / CanvasPlacement DB cutover.
- Full template picker or rich PageFrame style editor.
- Header/footer text editing.
- Real PDF export execution.

## 1. Rules

1. PageFrame movement changes PageFrame geometry only.
2. Blocks are not owned by PageFrames; after a PageFrame moves, block affiliation is recalculated by geometry.
3. Page Mode should not become the primary PageFrame layout editor. PageFrame operation is a Canvas/Layout Mode behavior.
4. Resize must respect minimum size constraints.
5. Resize must preserve print-scale sanity: width and height cannot collapse below usable content inset.
6. `primaryFrameId` and `selectedFrameId` must survive move/resize.
7. No PageStack numbering or PageSlice state is introduced in this version.

## 3. Task A - PageFrame Geometry Service Boundary

### Goal

Add service-level PageFrame operations before touching UI.

### Model checks

Add a failing check named:

```text
PageFrame operable object geometry updates
```

The check should create a collection with two PageFrames, then assert:

```ts
const moved = movePageFrameInCollection(collection, 'page-frame-2', { dx: 120, dy: 80 });
assertEqual(moved.pageFrames.find((frame) => frame.id === 'page-frame-2')?.x, original.x + 120, 'move updates PageFrame x');
assertEqual(moved.pageFrames.find((frame) => frame.id === 'page-frame-2')?.y, original.y + 80, 'move updates PageFrame y');
assertEqual(moved.primaryFrameId, collection.primaryFrameId, 'move preserves primary frame');
assertEqual(moved.selectedFrameId, 'page-frame-2', 'move selects operated frame');

const resized = resizePageFrameInCollection(collection, 'page-frame-2', { width: original.width + 160, height: original.height + 120 });
assertEqual(resized.pageFrames.find((frame) => frame.id === 'page-frame-2')?.width, original.width + 160, 'resize updates PageFrame width');
assertEqual(resized.pageFrames.find((frame) => frame.id === 'page-frame-2')?.height, original.height + 120, 'resize updates PageFrame height');
```

### Implementation

Add to `pageFrameCollectionService.ts`:

```ts
export function updatePageFrameInCollection(
  collection: PageFrameCollectionModel,
  frameId: string,
  patch: Partial<Pick<PageFrameModel, 'x' | 'y' | 'width' | 'height' | 'contentInset' | 'templateId' | 'pageSize' | 'background' | 'exportable'>>,
): PageFrameCollectionModel
```

Add:

```ts
export function movePageFrameInCollection(
  collection: PageFrameCollectionModel,
  frameId: string,
  delta: { dx: number; dy: number },
): PageFrameCollectionModel
```

Add:

```ts
export function resizePageFrameInCollection(
  collection: PageFrameCollectionModel,
  frameId: string,
  size: { width: number; height: number },
): PageFrameCollectionModel
```

Rules:

- Missing frame returns normalized collection unchanged.
- Operated frame becomes `selectedFrameId`.
- Primary id is preserved unless the operation targets a deleted frame, which is not part of this task.
- Width and height are clamped to a conservative minimum.
- Normalization runs after update.

## 5. Task C - Selection And Move Affordance

### Goal

Make PageFrame selectable and movable in Canvas/Layout Mode.

### UI behavior

- Clicking PageFrame shell selects it.
- Selected PageFrame shell exposes:
  - `data-page-frame-selected="true"`
  - a visible selected outline
  - move affordance through shell drag
- Non-selected PageFrames expose `data-page-frame-selected="false"`.
- PageFrame shell drag should not start when the user drags a resize handle.
- Page Mode should not show move affordances.

### Implementation notes

Use existing viewport zoom to convert pointer delta:

```ts
const deltaX = (moveEvent.clientX - startClientX) / noteCanvasRuntime.viewport.zoom;
const deltaY = (moveEvent.clientY - startClientY) / noteCanvasRuntime.viewport.zoom;
```

Call:

```ts
onMovePageFrame(frameId, { dx: deltaX, dy: deltaY });
```

For first implementation, save on pointer-up rather than every pointermove if that keeps the code safer. The shell can visually follow final persisted movement after save.

## 6. Task D - Resize Handles

### Goal

Add basic PageFrame resize handles without turning this into a full design tool.

### UI behavior

Render handles only for the selected PageFrame in Canvas/Layout Mode:

- right edge
- bottom edge
- bottom-right corner

Stable DOM markers:

```text
data-page-frame-resize-handle="right"
data-page-frame-resize-handle="bottom"
data-page-frame-resize-handle="corner"
```

### Implementation notes

Handle mapping:

- right: width changes, height unchanged
- bottom: height changes, width unchanged
- corner: width and height change

Call:

```ts
onResizePageFrame(frameId, { width: nextWidth, height: nextHeight });
```

Do not edit document typography or TextFlow content.

## 9. Acceptance

- PageFrame can be selected as a visible object in Canvas/Layout Mode.
- PageFrame can be moved and resized.
- PageFrame x/y/width/height persist through refresh.
- PageFrame operation does not mutate TextFlow content.
- PageFrame operation does not create Block/PageFrame ownership.
- Export Preview and AI-readable layout can continue deriving affiliation from geometry.
- Continuous PageStack remains deferred to 8.9.13.

## 10. Stop Conditions

Stop and record an Open Issue if:

- Moving PageFrame requires moving blocks as owned children.
- Resize creates invalid content inset or negative content area.
- Page Mode must become a layout editor to make the feature work.
- Persistence would require the final generic CanvasObject database cutover.
- PageFrame operation breaks existing block drag/resize behavior.
