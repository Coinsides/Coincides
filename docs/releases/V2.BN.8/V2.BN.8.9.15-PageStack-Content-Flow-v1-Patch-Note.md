# V2.BN.8.9.15 PageStack Content Flow v1 Patch Note

Date: 2026-06-27

## Summary

This patch gives PageStack its first real content-flow behavior.

Before this patch, PageStack could be created, inspected, split, merged, collapsed, and navigated, but natural writing still behaved like it belonged to one isolated sheet. After this patch, the default continuation path can read the current PageStack context and decide whether the next draft belongs on the current page, an existing next page, or a newly appended next page.

## Added

- Added `pageStackContentFlowService.ts`.
- Added `resolvePageStackContentFlowPlan(...)` as a pure model service.
- Added model-contract coverage for:
  - fitting draft remains on the current PageFrame;
  - overflowing draft moves to an existing next PageFrame in the same PageStack;
  - overflowing draft on the stack tail returns an append-next-page plan.
- Routed default natural writing through PageStack content flow.
- Kept explicit Canvas double-click placement free: a user-chosen point still creates a draft at that point.
- Updated runtime wiring so natural writing can save PageFrameCollection changes when it appends or selects a next page.

## Product Judgment

```text
PageStack content flow is a writing affordance.
It is not automatic pagination.
```

The implementation deliberately keeps TextFlow truth and block identity intact. It does not split a paragraph block, does not materialize PageSlice snapshots, and does not infer durable Block ownership from PageFrame geometry.

## Deferred

- Cross-page Block fragment projection remains `V2.BN.8.9.16`.
- PageSlice snapshot/reference/member semantics remain `V2.BN.8.9.17`.
- Full Word-like automatic pagination remains blocked on typography and font-metric maturity.
- Very long PageStack navigation still needs later polish.
