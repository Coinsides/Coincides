# V2.BN.8.9.10 Canvas World Auto-Expand And PageFrame Focus Patch Note

Date: 2026-06-27

## Why

V2.BN.8.9.9 made PageFrame creation reachable from toolbar and blank Canvas commands, but the Canvas world was still fixed to the old default bounds. After several PageFrames, a newly created frame could be inserted outside the reachable/visible area, making the user feel like the object was created but lost.

This patch fixes that immediate usability problem without pretending to finish the full infinite Canvas.

## What Changed

- Added dynamic finite Canvas world derivation in `viewportService.ts`.
- Canvas Mode world bounds now include current PageFrames, block placements, and reserved Canvas objects, with an 800px right/bottom buffer.
- Page Mode world behavior remains unchanged.
- Added `focusViewportOnWorldRect(...)` for focusing a world-space object rect.
- Updated viewport controller operations so pan, scroll, zoom, resize, and focus can clamp against the current runtime world.
- Updated runtime model construction so Canvas world bounds are derived from the active PageFrame collection and block placements.
- Added PageFrame focus routing after create / insert / duplicate / set-primary / select commands.
- Made Layout panel PageFrame rows clickable and keyboard-focusable so users can jump to a PageFrame.
- Added `data-canvas-world-width` and `data-canvas-world-height` smoke markers to the writing surface.
- Added model-contract and runtime-boundary coverage for dynamic Canvas world and PageFrame focus behavior.

## What This Does Not Do

- It does not implement complete infinite Canvas.
- It does not implement chunked/streamed world loading.
- It does not implement Continuous PageStack.
- It does not implement PageSlice extraction, split, merge, or collapse.
- It does not implement PageFrame drag/move/resize.
- It does not replace transitional PageFrame metadata persistence with durable generic CanvasObject / CanvasPlacement database truth.

## Product Judgment

This patch treats the current Canvas as an expandable finite world:

```text
finite Canvas first
dynamic world bounds second
full infinite/chunked Canvas later
```

That is enough to stop new PageFrames from disappearing while keeping the larger infinite Canvas design open.

## Verification

- `npm run smoke:canvas-engine-model-contract` passed 37 groups.
- `npm run check:canvas-runtime-boundary` passed 80 checks.
- `npm run build:client` passed with existing Vite warnings.

Browser/manual smoke confirmed:

1. A zero-PageFrame test note can create its first PageFrame from the toolbar.
2. Creating the second PageFrame increased Canvas world height from `3400` to `3436` and focused `page-frame-2`.
3. Creating the third PageFrame from the blank Canvas context menu increased Canvas world height to `4794` and focused `page-frame-3`.
4. Layout panel row click jumped back to the first PageFrame.
5. Refresh preserved all three PageFrames.
