# V2.BN.8.8.3 PageFrame v1 Foundation Patch Note

Date: 2026-06-25

Status: completed scoped engineering pass and verified.

## Summary

8.8.3 把 PageFrame 从“已经能被派生为 CanvasObject 的页面对象”，推进到“有自己专属服务边界的第一特殊 CanvasObject”。

这一步仍然不做完整可见 UI，也不做 PageFrame 数据库迁移。它先回答 PageFrame 最基础的工程问题：

```text
PageFrame 的外框是什么？
PageFrame 的内容区是什么？
哪个 PageFrame 是 primary？
删除 primary 之后如何兜底？
Page Mode 如何默认聚焦 primary？
AI-readable snapshot 如何把 PageFrame 当成 container？
```

## Completed

- Added PageFrame outer/content rect service:
  - `getPageFrameOuterRect`
  - `getPageFrameContentRect`
- Added primary PageFrame resolution:
  - requested primary wins when it exists;
  - single remaining PageFrame auto-becomes primary;
  - missing requested primary falls back conservatively.
- Added delete-primary fallback seed:
  - deleting current primary promotes the next remaining PageFrame;
  - deleting a non-primary keeps current primary when possible.
- Added Page Mode focus viewport seed:
  - Page Mode can reset to primary PageFrame content rect;
  - focus zoom resets to readable `1`.
- Updated Canvas AI-readable snapshot:
  - PageFrame node now carries formal-page child nodes;
  - workspace objects remain top-level nodes.
- Added `PageFrame v1 foundation` model contract group.
- Updated runtime boundary check so PageFrame v1 service functions are protected.
- Added `V2.BN.8.8-Canvas-Engine-Implementation-Checklist.md` as the engineering progress ledger.
- Wrote checklist maintenance requirement back into `V2.BN.8.8-Canvas-Engine-Foundation-Plan.md`.

## Engineering Boundary

This patch deliberately keeps PageFrame v1 as service-level foundation.

Important boundaries:

- PageFrame remains runtime-level model in this patch.
- No durable multi-PageFrame database table is introduced.
- No visible PageFrame toolbar, template UI, ruler UI, snap-wall UI, header/footer, page number, or export editor is implemented.
- PageFrame child grouping in AI snapshot is derived from placement `frameId`; it is not a second content truth.
- Workspace objects are not hard-clipped or forced back into PageFrame during mode changes.

## Not Included

- No complete PageFrame UI redesign.
- No multi-PageFrame creation/deletion UI.
- No actual ruler / snap-wall interaction.
- No PageFrame template library.
- No header/footer/page-number editing.
- No export engine refinement.
- No CanvasObject DB migration.
- No infinite canvas.
- No ContentGroup projection, Relation runtime, Agent write path, or GraphRAG.

## Remaining Risks

- Page Mode focus viewport is not yet wired into the visible mode-switch UI.
- AI snapshot child ordering is still simple placement order, not a rich reading-order algorithm.
- PageFrame fallback rules are service-level only; durable multi-frame persistence will need a later pass.
- Ruler and snap-wall are still reserved concepts, not interactive behavior.
