# V2.BN.8.6.5 Context Menu And Command Surface Design

Status: living design note / pre-research draft
Date: 2026-06-17
Scope: Better Notebook V2.BN.8 context menu, selection command surface, and future inventory sync

## 1. Why This Exists

右键菜单不是一个单独的菜单，而是一组按上下文变化的命令入口。

它要解决的问题是：用户已经选中了某个东西，下一步最自然能做什么。

在 Better Notebook 当前阶段，很多能力被迫浮在表面上，例如选区工具条、Annotation Stack 按钮、inline structure 快捷按钮等。随着 TextFlow、Annotation Truth、Inline Structure 的职责越来越清楚，这些按钮不应该全部常驻在明面上。右键菜单要承担一部分“上下文转换”和“局部管理”的职责，让界面更安静。

核心原则：

- Slash menu 偏向创建和插入。
- 右键菜单偏向转换、管理当前对象、处理当前选区。
- TextUnit handle 偏向行/段落级结构操作。
- Annotation Stack 偏向正式检查和管理 annotation，不应该塞太多临时操作按钮。
- 同一个底层 command 应该能被右键菜单、selection toolbar、TextUnit handle、快捷键复用。

## 2. Command Surface Family

我们需要的不是一个全局万能菜单，而是一组 command surface：

| Surface | 用户正在操作什么 | 主要职责 |
| --- | --- | --- |
| Text selection context menu | TextBlock / TextUnit 里的文本选区 | 标注、转 inline formula/code/link、复制剪切等 |
| Annotation range context menu | 已经属于某个 parent annotation 的文本范围 | 添加 child label、复制、局部 inline 转换 |
| Annotation badge / highlight menu | 已存在的 label badge 或高光 | 打开 stack、改名、改色、隐藏、删除 |
| TextUnit handle menu | 某一行 / 某一段 / 某个 TextUnit | Turn into、Annotate unit、split、extract、duplicate、delete |
| Block shell menu | 整个 block 的外壳 | 复制、删除、隐藏 AI/export、复制引用、整体标注 |
| Canvas blank menu | PageFrame / workspace 空白区域 | 粘贴、插入 block/object、未来 page/canvas settings |
| CanvasObject menu | 图片、shape、drawing、future media object | 图层、样式、复制、删除、裁剪、标注区域 |

## 3. Normal Text Selection Menu

普通写作时，用户选中一段文字后，右键菜单应该优先提供：

- Annotate / 标注
- Inline Formula / 转为行内公式
- Inline Code / 转为行内代码
- Link / 加链接
- Quote / 转为引用样式
- Copy
- Cut
- Paste

这里的重点是：右键菜单负责“把当前选区变成某种东西”。

示例：

- 用户复制了一段经济学笔记，其中夹杂 `a^2+b^2=c^2` 一类文本公式。
- 用户不一定想把它变成单独 formula block。
- 他只需要选中这一小段，右键，选择 Inline Formula。
- 这个文本就被转换成 inline structure。

这类操作如果全放进明面按钮，会很吵；如果只放 slash menu，又不符合“先选中再转换”的心智。

## 4. Selection Toolbar Display Rule

当前选中文字后自动弹出的工具条包含 Annotate、formula、code、link、close 等按钮。这个工具条需要收束。

新的规则建议：

### 4.1 单次普通选区

如果用户只是用鼠标拖选了一段连续文字，不应该自动弹出完整工具条。

原因：

- 很多人阅读时会边读边框选。
- 单次选区不一定代表用户要做结构化操作。
- 自动弹工具条会打扰阅读。

这种情况下：

- 默认只保留浏览器式选区视觉。
- 用户右键时，再打开 context menu。
- 用户按快捷键或调用菜单时，再触发 annotation / inline conversion。

### 4.2 Ctrl 多段选区 / 多次选区

如果用户按住 Ctrl 进行多个 range 的选取，这个意图更明确。

这种情况下，可以显示轻量 selection draft toolbar：

- Draft range count
- Annotate
- Inline Formula / Code / Link，视情况出现
- Close / cancel

原因：

- 多段选取是我们自定义 selection draft engine 的能力。
- 用户主动按 Ctrl，说明他更可能在准备后续操作。
- 这时弹出工具条是可接受的。

### 4.3 点击外部行为

- 点击已选区内部：保持 selection draft，并允许后续操作。
- 点击未被选中的文本或空白区域：取消 selection draft。
- Esc：取消 selection draft。

## 5. Annotation Stack Context Menu

Annotation Stack 不应该通过一堆常驻按钮完成所有操作。

### 5.1 Child Label

Child label 不应该和 parent label 平级。它是为了解释 parent label 内部的语义部分而存在的。

正确交互：

1. 用户打开某个 parent annotation。
2. 在 parent 的 range preview 内选中一小段文字。
3. 右键打开菜单。
4. 选择 Add child label。
5. child label 出现在该 parent annotation 下方。

这比常驻 `Add child label` 输入框更自然，也避免用户误以为 child label 可以脱离 parent 独立存在。

### 5.2 Same Range Label

`Add same-range label` 不应该作为显眼按钮保留。

如果用户真的想给同一段内容加另一个 label，可以重新选中同一段内容并创建新的 annotation。这个动作更符合“标记”的自然心智，也能减少 Annotation Stack 内部按钮噪音。

### 5.3 Range Preview Text

Range preview 未来需要支持双向同步：

- 原文 TextUnit 改动后，range preview 更新。
- range preview 中编辑内容后，写回原始 TextUnit。

这属于 V2.BN.8.6.3/8.6.x 的后续事项，不应由 context menu 本身直接承担，但 context menu 要预留入口，例如 Copy / Add child label / Inline conversion。

## 6. Annotation Badge / Highlight Menu

用户点击或右键某个 label badge / 高光区域时，可以出现：

- Open annotation stack
- Rename label
- Change color
- Hide label
- Delete label
- Add child label，只有存在 parent 内部选区时才出现

这类菜单负责管理已有 annotation。

未来 label badge 不应该全部堆在 block 右上角，而应该更靠近实际高光区域。右键菜单也应该锚定到具体 label，而不是锚定整个 block。

## 7. TextUnit Handle Menu

TextUnit 左侧 handle 或段落行级入口，应该服务于写作结构：

- Turn into paragraph
- Turn into heading
- Turn into bullet list
- Turn into numbered list
- Turn into todo list
- Turn into toggle list
- Annotate this unit
- Split block from here
- Extract to new block
- Duplicate unit
- Delete unit

这里不要塞 inline formula/code/link，因为那些属于文本选区菜单。

TextUnit handle 是“这一行/这一段怎么变”的入口。

## 8. Block Shell Menu

Block 右键菜单管理的是外壳和布局，不是内部语义。

可能包含：

- Duplicate block
- Delete / Move to trash
- Copy block link
- Annotate whole block
- Hide from AI context
- Exclude from export
- Convert block shell
- Bring forward / send backward，未来 CanvasObject 化后考虑

Block 的职责已经退化为显示、布局、外壳和特殊渲染能力。因此 block 菜单不应该再承担 definition / knowledge role 之类的语义分类。

## 9. Canvas And PageFrame Menu

Canvas / PageFrame 空白区域菜单可以先预留，不急着做重。

未来可能包含：

- Paste here
- Insert TextBlock
- Insert Image
- Insert Shape
- Insert Drawing
- PageFrame settings
- Canvas background / grid settings
- Change page size

当前阶段如果没有明确功能，不需要急着展示空白区域菜单。避免为了“有菜单”而增加无意义入口。

## 10. What Surface Buttons Can Be Reduced

右键菜单成熟后，以下浮在表面的按钮可以逐步收束：

### 10.1 Selection toolbar

当前选区后自动出现的 Annotate / formula / code / link / close 工具条需要变轻。

建议：

- 单次普通文本选区：不自动弹完整 toolbar。
- Ctrl 多段选区：可以弹轻量 draft toolbar。
- Inline formula/code/link：主要放入右键菜单。
- Annotate：单次选区通过右键触发，多段选区可以在 draft toolbar 中保留。

### 10.2 Annotation Stack child label input

常驻 `Add child label` 输入框可以移除。

替代方式：

- 在 parent range preview 中选中子范围。
- 右键 Add child label。

### 10.3 Add same-range label

这个按钮应移除。

替代方式：

- 用户重新选择同一段文本，再创建新 annotation。

### 10.4 Annotation Stack 内部过多显性元数据

Created by、status、ranges、children 这类信息不需要常驻显示。

它们应进入 Details 折叠区域。

### 10.5 Label 管理按钮

Hide / Delete / Color / Rename 等可以保留在 Annotation Stack 中，但也应在 label badge context menu 中可达。

最终目标不是删除所有按钮，而是让按钮出现在最合适的上下文里。

## 11. Research Questions For AFFiNE / Notion

后续调研 AFFiNE / Notion 时，需要重点观察：

- 普通文本选区时是否自动弹 toolbar？
- 右键菜单和浮动 toolbar 如何分工？
- block handle 菜单里有哪些操作？
- slash menu 是否只负责插入/创建？
- 文字选区、block 选区、空白 canvas 右键菜单是否不同？
- edgeless / canvas 模式下右键菜单是否变化？
- inline formula、link、comment、AI 操作分别放在哪里？
- delete / duplicate / move / turn into 这类操作是在右键菜单、handle 菜单，还是更多菜单？
- 选中内容在 inspector / sidebar 里时，是否也有独立 context menu？

## 12. V2.BN.8.6.5 Candidate Scope

如果单独开 V2.BN.8.6.5，建议命名：

`V2.BN.8.6.5 Context Menu And Command Surface Seed`

推荐第一版只做：

1. 普通文本选区右键菜单：
   - Annotate
   - Inline Formula
   - Inline Code
   - Link
   - Copy

2. Annotation Stack range preview 右键菜单：
   - Add child label
   - Inline Formula
   - Inline Code
   - Copy

3. Selection toolbar 收束：
   - 单次普通选区不自动弹完整 toolbar。
   - Ctrl 多段选区保留轻量 draft toolbar。

4. Annotation Stack 按钮收束：
   - 移除 Add same-range label。
   - 移除常驻 Add child label 输入框。
   - Details 默认折叠。

5. Command registry seed：
   - 让右键菜单、selection toolbar、TextUnit handle 未来可以复用同一批 command。

Canvas blank menu、完整 block menu、CanvasObject menu 可以进入预留，不一定在 8.6.5 完整实现。
