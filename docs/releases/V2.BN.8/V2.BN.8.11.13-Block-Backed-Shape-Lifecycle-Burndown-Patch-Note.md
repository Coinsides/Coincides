> **Status**: implemented
> **Date**: 2026-07-02
> **Owner**: Henry + Codex
> **Source handoff**: `docs/agent-ops/handoffs/2026-07-02-8.11-lifecycle-burndown.md`
> **Scope**: V2.BN.8.11 post-closure lifecycle burn-down / block-backed shape / backing note block truth

## 为什么补这个小版本

8.11.12 已经烧掉 PageFrame extension 丢失和 AI-readable snapshot 污染的第一阶段高危问题。本轮继续处理第二阶段：**block-backed shape 与 backing note block 的生命周期不一致**。

当前风险集中在同一个根上：shape 里的文字由 note_block 承载，但这块文字既可以被 shape 生命周期管理，也可以被 note block 的普通删除/恢复入口碰到。若不收束，会出现：

- 独立删除 backing block 导致 shape 整体消失；
- 删除 shape 时 client/server 双重 trash backing block；
- remove-text 后恢复出来的 block 仍带 `canvas_object_backing`，变成隐藏 zombie；
- remove-text / add-text 反复循环时不断新建 backing block；
- 清空 shape 文本后留下 active 空 backing block；
- extensionless / snapshot 侧的 Stage-1 残尾测试还不够锋利。

本轮目标不是扩展新对象，而是把已有 block-backed shape 的生命周期变成一条自洽脊椎。

## 核心判断

- backing 块身份由 **live shape 拥有关系** 派生，不由 `metadata.render_scope` 单独决定。
- `render_scope='canvas_object_backing'` 只是提示/缓存，不是真相。
- live shape 还在、backing 块死了：shape 退化为无文本图形，不应整体消失。
- backing 块还在、但没有 live shape 拥有：它应恢复为普通可见 block，不应隐藏成 zombie。
- 独立 trash 一个仍被 live shape 拥有的 backing block：应被 server 拒绝，生命周期归 shape。
- shape demote/delete 对 backing block 的处理以 server 为权威，client 不做二次 trash。

## 本轮修复范围

### A. Server lifecycle spine

- 给 note block 的 `DELETE` 与 `PUT status -> non-active` 增加 live backing ownership 守卫。
- `getNoteCanvasPersistence` 的 liveness 改成 kind-aware：
  - `paragraph_block_projection` 的 backing block 死亡时，投影整体隐藏；
  - `shape + backing='note_block'` 的 backing block 死亡时，只去掉 mount，保留 shape 与 placement。
- backing block 被 shape demote/delete 时，清理相关 `note_block_placements` 与 `content_mounts`，但只做软删除/软清理，不 hard-delete。
- restore note block 时，如果没有 live shape 拥有该 block，则剥掉 `canvas_object_backing` / `block_backed_shape` 焊接元数据，让它回到普通 block。

### B. Client lifecycle behavior

- demote 非空 shape text 前弹确认；取消不丢内容，确认后文本进入回收站。
- 空文本 demote 不弹确认。
- re-promote 时优先复用/恢复该 shape 历史 backing block，不反复制造新 block。
- 清空 shape text 保存时自动 demote，避免 active 空 backing block 进入 AI/搜索。
- 删除 shape 后不再由 client 二次 trash backing block。

### C. Stage-1 residual locks

- 扩 PageFrame extensionless hydration 测试：缺 extension 时必须保留可恢复字段，或显式带 `recovered/degraded` 标记。
- 为 server projection snapshot 增加正常块正控：过滤 hidden backing block 时，不能误清空普通 note block。

## 不做什么

- 不碰 annotation range / offset rebase。
- 不碰 table undo / structured object lifecycle。
- 不推进 ContentGroup projection / Source / Agent / Relation。
- 不重写 CanvasObject identity。
- 不整理整个 dirty workspace。

## 验收标准

- 独立删除 live backing block 被拒绝，shape 仍在。
- demote / rollback 合法路径不被误伤。
- block-backed shape 的 backing block 死亡后，shape 仍作为无文本图形返回。
- paragraph block projection 的 backing block 死亡后仍整体隐藏。
- 无 live shape 拥有的 `canvas_object_backing` block 恢复为普通可见 block。
- demote 后 mount / placement 不再留下 active orphan。
- 连续 remove-text / add-text 不导致 backing block 无界增长。
- 清空 shape text 后不留下 active 空 backing block。
- Stage-1 extensionless 与 snapshot 正控测试锁住。

## 完成记录

2026-07-02 Codex 已完成 Stage 2 burn-down 第一轮落地：

- 服务端加入 live shape ownership guard：仍被 live block-backed shape 拥有的 backing block 不能被普通 note block DELETE / 非 active status 更新独立打掉。
- `getNoteCanvasPersistence` 改为 kind-aware liveness：`paragraph_block_projection` 的 backing block 死亡时继续整体隐藏；`shape + backing='note_block'` 的 backing block 死亡时保留 shape / placement，仅卸掉文字 mount。
- shape demote / delete 对 backing block 做软删除与孤儿清理：清理 `content_mounts` 与 `note_block_placements`，不 hard-delete block，并记录可恢复生命周期 metadata。
- note block restore 下沉到服务端：无 live shape 拥有时剥离 `canvas_object_backing` / `block_backed_shape` 焊接 metadata，恢复成普通可见 block；re-promote 需要复用时仍可带 shape backing metadata 恢复。
- 客户端 demote 非空 shape text 前增加确认；空文本无需确认；清空 shape text 保存时自动 demote，避免 active 空 backing block。
- 客户端 re-promote 会优先恢复 / 复用 shape metadata 记住的 `last_backing_block_id`，减少 remove-text / add-text 循环造成的 backing block 无界增长。
- 删除 shape 后客户端不再二次向服务端 trash backing block，只做本地撤出；真实生命周期由 server cleanup 负责。
- Stage-1 residual locks 已补：extensionless PageFrame hydration 带 `recovered/degraded` read-time marker；projection snapshot 增加正常 block 正控。
