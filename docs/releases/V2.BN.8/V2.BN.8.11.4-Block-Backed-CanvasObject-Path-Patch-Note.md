# V2.BN.8.11.4 Block-Backed CanvasObject Path Patch Note

Date: 2026-06-28

Status: implemented + verified

## Summary

This patch turns `shape` from a pure visual CanvasObject into a first usable block-backed object path.

The important product result:

- Pure shape can stay visual-only.
- Shape can be promoted to `block-backed` by adding text.
- Shape text is stored in a real paragraph note block, not in shape metadata.
- The backing paragraph block is hidden from ordinary page/canvas block rendering.
- The backing paragraph block is still available to the runtime model and AI-readable layout.
- Shape can be demoted back to pure shape through `Remove text`.
- Deleting a block-backed shape cleans the owned backing block instead of leaving an active orphan.
- During browser smoke, a PageFrame persistence bug was found and patched: `page_frame_extensions.frame_id` is no longer globally unique across notes; it is scoped by `(note_id, frame_id)`.

## Engineering Changes

### Server

- Shape save validation now accepts two legal states:
  - pure shape: `backing='none'`, `object_class='pure'`;
  - block-backed shape: `backing='note_block'`, `object_class='block_backed'`.
- Block-backed shape save requires:
  - `extension.block_id`;
  - a matching note-block `ContentMount`;
  - backing block metadata marking it as a shape-owned backing block.
- Pure shape save rejects stray mount/extension data.
- Shape delete and demotion clean owned backing blocks by marking them trashed.
- Added migration `039_v2_page_frame_extension_note_scope` so different notes can safely reuse frame ids such as `primary-page-frame`.

### Client Runtime

- Added `shapeTextMountService`.
- Runtime model can receive text lookup data for mounted content targets.
- Canvas AI-readable snapshot can read block-backed shape text through `ContentMount`.
- Surface filtering hides canvas-object backing blocks from normal block lists.

### UI

- Shape context menu now supports:
  - `Add text`;
  - `Edit text`;
  - `Remove text`;
  - `Delete object`.
- Block-backed shape renders a minimal textarea inside the shape.
- Shape text edits reuse the existing paragraph block save path.
- Moving/resizing a block-backed shape preserves its mount and does not silently demote it.

## Verification

Passed:

- `npm run smoke:canvas-engine-model-contract`
- `node --import tsx --test src/__tests__/v2CanvasPersistenceCutover.test.ts`
- `npm run build:client`

Browser smoke so far:

- Reproduced stale-server validator failure, then restarted dev server against current code.
- Confirmed `Add text` promotes a shape to `backing='note_block'` and creates an owned `ContentMount`.
- Confirmed shape textarea text persists into the owned paragraph backing block after reload.
- Confirmed `Remove text` demotes the shape back to pure visual state and trashes the owned backing block.
- Found and patched the PageFrame extension note-scope bug exposed by manual smoke.
- Confirmed no PageFrame save 500 after migration `039` was applied locally.

Known existing warnings:

- Vite still reports the pre-existing large chunk / dynamic import warning.

## Remaining Limits

- The shape text editor is intentionally minimal; typography toolbar integration is later work.
- Empty text does not automatically demote the shape. Demotion is explicit through `Remove text`.
- This does not implement sticky note style presets yet. That belongs to the next object-style/sticky pass.
- Browser smoke covered add/edit/reload/remove. Delete cleanup is covered by the persistence test suite; a destructive browser delete pass was not repeated on the existing test note.
