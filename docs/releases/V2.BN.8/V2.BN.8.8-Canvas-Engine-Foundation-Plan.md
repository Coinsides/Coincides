# V2.BN.8.8 Canvas Engine Foundation Plan

> 目标：把 ContentGroup System 1.0 之后的下一根支柱正式切到 Canvas Engine Foundation。8.8 不追求完整无限画布，也不追求完整 Object Family；它只负责让 Coincides 自己的 Canvas 底座成立。

## 0. Scope Lock

### 本版本做什么

V2.BN.8.8 做：

```text
Canvas Engine Foundation:
  CanvasObject / CanvasPlacement / ContentMount
  PageFrame v1
  paragraph block projection
  finite expandable world
  viewport / coordinate / hit testing seed
  shape / block-backed shape seed
  visual connector seed
  CanvasCommand / CanvasDelta seed
  Canvas AI Tree read-only snapshot
```

### 本版本不做什么

V2.BN.8.8 不做：

- 完整无限画布。
- 完整 diagram / mind map / chart / math graph。
- 完整 image/table/media editor。
- 完整 ContentGroup projection / Materialize UI。
- Relation runtime / GraphRAG。
- Agent 直接写入。
- Raw Ink / handwriting 视觉理解。
- 完整 PageFrame template / export engine。

## 2. 固定产品判断

### 三条真相

```text
TextFlow     = 内容真相
ContentGroup = 知识结构真相
Canvas       = 空间 / 布局真相
```

### 四重角色

Coincides Canvas 是：

1. 白板。
2. 页面系统。
3. 空间组织层。
4. AI-readable layout。

### PageFrame 优先级

PageFrame 是第一特殊 CanvasObject。它优先于 diagram、chart、math graph、3D viewer、Raw Ink 等 Object Family。

### CanvasObject 边界

```text
Block != CanvasObject
```

Block 是内容对象；CanvasObject 是空间对象。Block 可以通过 CanvasObject projection 出现在画布上。

## 3. 版本成功标准

8.8 完成时，应该能证明：

1. 一个 note 可以拥有稳定 NoteCanvas。
2. CanvasObject / CanvasPlacement / ContentMount 合同成立。
3. PageFrame 是 Canvas 内的正式对象，不是普通 DOM 页面假象。
4. paragraph block 可以在 PageFrame 内或 workspace 中稳定放置。
5. placement 改变不改写 TextFlow 内容。
6. shape 可以是 pure object，也可以挂载 paragraph block。
7. visual connector 不会自动创建 Relation。
8. Canvas AI Tree 可以读到 bbox / frameId / zIndex / selected context。
9. 后续 image/table/ContentGroup projection/Relation/Agent 可以继续接入，不需要推翻底座。

## 4. Sub-plan A - Canvas Data Contract

### 目标

建立 V2.BN.8.8 的实体和类型合同。

### 任务

1. 审计当前 `canvasEngine/types.ts`、runtime data types、existing placement metadata。
2. 定义或更新：
   - `NoteCanvas`
   - `CanvasObject`
   - `CanvasPlacement`
   - `ContentMount`
   - `PageFrameExtension`
   - `VisualStyle`
   - `VisualConnector`
   - `CanvasAIReadableSnapshot`
   - `CanvasCommand`
   - `CanvasDelta`
3. 明确 pure / block-backed / structured / projection-backed object 分类。
4. 明确 `AddressableKnowledgeObjectKind` 是否仅预留 CanvasObject，或在本版本扩展。
5. 写 model / contract check。

### 验收

- 新合同能表达 PageFrame、paragraph block projection、shape、visual connector。
- `BlockPlacementModel` 的职责可以拆进新合同。
- snapshot 被声明为派生物，不是 durable truth。

## 5. Sub-plan B - Canvas Runtime Kernel

### 目标

建立最小 runtime，使数据合同能被真正渲染和交互。

### 任务

1. 建立或整理：
   - `NoteCanvasRuntimeProvider`
   - `CanvasDataAdapter`
   - `CanvasViewportController`
   - `CanvasSceneRuntime`
   - `CanvasPlacementIndex`
   - `CanvasMeasurementService`
   - `CanvasHitTestService`
   - `CanvasSelectionService`
2. world / viewport / screen 坐标转换。
3. finite expandable world seed。
4. render layer 分层。
5. hit test 与 selection seed。

### 验收

- pan / zoom 后命中测试仍稳定。
- placement 以 world 坐标保存。
- DOM scroll 不成为主坐标系统。
- PageFrame / block / shape 都能进入 scene index。

## 6. Sub-plan C - PageFrame v1

### 目标

让 PageFrame 作为第一特殊 CanvasObject 成立。

### 任务

1. PageFrame object + placement + extension。
2. primary PageFrame。
3. Page Mode 默认聚焦 primary。
4. Canvas Mode 显示 PageFrame + workspace。
5. outer rect / content rect 分离。
6. content inset 合同。
7. ruler / snap 合同预留。
8. 删除 primary 兜底规则。

### 验收

- 有 primary PageFrame 时 note 默认能进入 Page Mode。
- 只剩一个 PageFrame 时自动成为 primary。
- PageFrame 外 object 不会被模式切换硬夹回 PageFrame。
- AI snapshot 能把 PageFrame 作为 container node 输出。

## 7. Sub-plan D - Block Projection v1

### 目标

让 paragraph block 作为 TextFlow-backed object 稳定进入 Canvas。

### 任务

1. 创建 paragraph block 时同时创建 CanvasObject / Placement / ContentMount。
2. PageFrame 内创建 block。
3. workspace 创建 block。
4. block move / resize 只改 placement。
5. block style 进入 VisualStyle。
6. refresh 后恢复 block 位置。

### 验收

- TextFlow 内容不被 placement/style 污染。
- block 移动后内容不变。
- width resize 触发 reflow / measurement。
- snapshot 能读 text + bbox。

## 8. Sub-plan E - Shape / Block-backed Shape / Visual Connector

### 目标

建立第一批非 PageFrame / 非 block 的 CanvasObject。

### 任务

1. pure shape。
2. shape fill text。
3. 清空 text 后退回 pure shape。
4. visual connector / arrow。
5. connector optional binding。
6. 明确 visual connector 不创建 KnowledgeRelation。

### 验收

- pure shape 不创建 NoteBlock。
- shape 填文字创建 paragraph block 和 ContentMount。
- 清空文字清理空 block/mount。
- visual arrow 不触发 Relation 数据写入。

## 9. Sub-plan F - Canvas Command / History Seed

### 目标

防止 Canvas 写入散落在 UI 事件里，为 undo/redo、Agent proposal、协作留底。

### 任务

1. 定义 command 类型。
2. 定义 delta 类型。
3. 关键写入走 command dispatcher。
4. 至少覆盖 create/move/resize/style/delete。
5. 预留 undo seed。

### 验收

- move / resize / create shape 不绕过 command。
- command 能输出 delta。
- 后续 proposal 可以转 command batch。

## 10. Sub-plan G - Canvas AI Tree v1

### 目标

让 Canvas 从第一版开始就是 AI-readable layout。

### 任务

1. snapshot service。
2. PageFrame node。
3. paragraph block node。
4. shape node。
5. visual connector node。
6. selected context。
7. bbox / frameId / zIndex / visible / contentRef。

### 验收

- snapshot 可从 runtime 派生。
- snapshot 不写回 durable truth。
- PageFrame 内对象有阅读顺序 hint。
- workspace object 与 PageFrame object 可区分。

## 11. Sub-plan H - Browser / Manual Experience Gate

### 目标

用最小真实流程确认 8.8 的底座不是纸面成立。

### 必测流程

1. 新建 note。
2. 创建/打开 PageFrame。
3. Page Mode / Canvas Mode 切换。
4. 创建 paragraph block。
5. 移动 block 到 PageFrame 外。
6. 创建 shape。
7. shape 填文字。
8. 清空 shape 文字。
9. 创建 visual arrow。
10. 刷新页面。
11. 检查 snapshot/debug 输出。

### 验收

- 关键对象刷新后保留。
- 用户心智能解释 page 和 canvas 的区别。
- 没有把普通 arrow 误做 Relation。
- 没有把 TextFlow 内容复制成第二份文本真相。

## 13. Roadmap Handoff

8.8 之后不急着进入 Relation / GraphRAG。

建议后续路线：

```text
V2.BN.8.9
  PageFrame maturity:
  multi PageFrame, ruler, margin guides, header/footer/page number, export preview.

V2.BN.8.10
  Object projection and reuse:
  image/table maturity, ContentGroup projection, Reference/Duplicate/Fork/Materialize.

V2.BN.8.11
  Structured object family:
  diagram / mind map / chart / math graph choose one or two.

V2.BN.8.12+
  ContentGroup Mode / Relation View:
  RelationProposal, ContentGroup/Petal endpoint visualization.

V2.BN.9.x
  Agent / GraphRAG integration.
```
