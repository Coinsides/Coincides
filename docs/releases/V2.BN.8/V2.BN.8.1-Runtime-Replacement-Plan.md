# V2.BN.8.1 Runtime Replacement Plan

> 本文是 `V2.BN.8` 下第一个小版本的执行蓝图。
> 目标不是继续给旧 `NoteDetail.tsx` 打补丁，而是在一个小版本内完成 Canvas Engine 对旧 runtime 的逐层接管。
> 后续 `V2.BN.8.x` 小版本只负责打磨、补丁、性能验证和体验优化。

## 1. 核心结论

本文最初编写时，当前 branch 只有 `canvasEngine` seed，旧 `NoteDetail.tsx` 仍是主 runtime。

当前代码状态已经推进到新的 checkpoint：

```text
NoteDetail.tsx
  只负责读取 noteId route param
  只挂载 NoteCanvasRuntimeProvider
  只渲染 NoteCanvasRuntime

canvasEngine/
  已成为 note 页面 runtime root
  已接管 layout / page-canvas mode / selection / drag-resize
  已接管 slash menu / measurement-reflow / preview-toolbar-overlay 的主逻辑
```

所以 `V2.BN.8.1` 的目标已经从“迁出旧 NoteDetail runtime”推进为：

```text
证明 Canvas Engine 已经成为 Note 页面真正 runtime。
继续收紧 Canvas Engine 内部 controller / layer / service 边界。
完成 L12 decommission acceptance、browser smoke、performance seed 和 Henry manual pass。
```

历史段落中提到“NoteDetail 仍是旧 runtime”的判断，只代表本计划开工前状态；后续验收以本文 L12 的 current evidence checkpoint 和 `Review.md` 最新审计为准。

## 2. 小版本目标

`V2.BN.8.1` 必须在一个小版本内完成“逐层替代”。

完成后：

- `NoteDetail.tsx` 不再直接拥有 layout、measurement、selection、drag、resize、overlay anchor、page/canvas mode 的核心逻辑。
- `NoteDetail.tsx` 只负责：
  - 读取 route params；
  - 加载 note/project 数据；
  - 调用现有 API 保存 block；
  - 把数据交给 `NoteCanvasRuntime`；
  - 承接页面级 loading/error/back navigation。
- Canvas Engine 负责：
  - NoteCanvas；
  - PageFrame；
  - workspace；
  - placement；
  - block projection；
  - measurement；
  - interaction；
  - overlay；
  - viewport；
  - Page/Canvas mode。

## 3. 不做什么

本版本不做：

- 完整多 frame 产品化；
- presentation mode；
- 完整 drawing tool；
- relation runtime；
- source picker；
- Template Studio；
- GraphRAG adapter；
- Electron / desktop shell；
- 数据库 migration；
- 对外部用户数据的兼容迁移。

由于当前产品尚未公开投入使用，现有本地数据均为测试数据，本版本允许做 local dev data reset。

## 4. 分层接管总览

本版本分为 12 层。

```text
L0  Startup Gate And Baseline
L1  Local Test Data Reset
L2  Runtime Root
L3  Viewport And World
L4  PageFrame And Workspace
L5  Placement Service
L6  Block Projection Layer
L7  Measurement And Reflow Service
L8  Interaction Controller
L9  Floating Overlay Layer
L10 Page / Canvas Mode Policy

```

其中：

- `L0-L1` 是开工前门槛；
- `L2-L11` 是真正的 runtime 接管；
- `L12` 是旧 runtime 清退和验收。

## 6. L1 - Local Test Data Reset

### 目标

清空旧测试数据，避免旧 `better_notebook_layout` payload、旧 note、旧 canvas document、旧 source/test fixture 干扰 Canvas Engine 验收。

### 推荐路线

由于当前是本地开发、尚无真实用户数据，推荐使用 hard local reset。

```text
Stop server
  -> backup server/coincides.db, server/coincides.db-wal, server/coincides.db-shm
  -> remove active db files
  -> optionally clear server/uploads test files
  -> restart server
  -> initDb recreates schema
  -> create one smoke account
  -> create one smoke project
  -> create one smoke note
```

### 为什么不用只删 users

`users` 表有大量 `ON DELETE CASCADE` 外键，但系统里还有：

- FTS virtual table；
- sqlite-vec virtual table；
- upload snapshots；
- possible orphan test files；
- 旧 runtime 写入的 layout payload；
- 历史实验表和 proposals。

如果只是 `DELETE FROM users`，可能会留下不需要的索引/虚拟表残留或文件残留。当前阶段最干净的做法是重建本地 dev database。

### 安全规则

- 不在 server 运行时删除 db。
- 删除前必须备份。
- 只删除本地 `server/coincides.db*` 和明确的本地测试 upload 文件。
- 不删除源代码。
- 不删除 migrations。
- 不删除 docs。
- 不删除外部用户文件夹。

### 备用路线

如果 Henry 临时不想删 db 文件，则走 scoped cleanup：

```text
BEGIN
DELETE FROM users;
DELETE FROM doc_chunk_vec;
DELETE FROM agent_memory_vec;
DELETE FROM document_chunks_fts;
DELETE FROM agent_memories_fts;
COMMIT
VACUUM
```

备用路线必须先列出用户清单和表计数，再执行。

## 7. L2 - Runtime Root

### 目标

建立真正的 runtime root，让 `NoteDetail.tsx` 不再作为 canvas runtime 主体。

### 新结构建议

```text
client/src/pages/Notes/canvasEngine/
  NoteCanvasRuntime.tsx
  NoteCanvasRuntimeProvider.tsx
  hooks/
    useNoteCanvasRuntime.ts
    useNoteCanvasDataAdapter.ts
  model/
    types.ts
    geometry.ts
    engineModel.ts
```

### Runtime root 负责

- 接收 note blocks；
- 接收 project/note metadata；
- 接收保存函数；
- 建立 runtime state；
- 输出 canvas UI；
- 暴露 debug data attributes；
- 把旧页面壳和 runtime 解耦。

### NoteDetail 目标形态

```tsx
export default function NoteDetailPage() {
  const pageData = useNoteDetailData();

  return (
    <NoteCanvasRuntimeProvider data={pageData}>
      <NoteCanvasRuntime />
    </NoteCanvasRuntimeProvider>
  );
}
```

`NoteDetail.tsx` 不应继续保留大段 block layout、measurement、overlay 和 interaction 逻辑。

### Current document data controller checkpoint

- `useRuntimeDocumentDataController()` now owns the first composition boundary for layout draft state, note load reset, note data adapter, and note-level source stats.
- `useNoteCanvasRuntimeController()` no longer calls `useLayoutDraftController()`, `useNoteLoadResetController()`, `useNoteCanvasDataAdapter()`, or `useRuntimeDocumentStatsController()` directly.
- Note/block API behavior, layout draft truth, source reference count, title saving, block create/save/trash, source anchors, and source jump state remain unchanged.

## 8. L3 - Viewport And World

### Current controller checkpoint

- `useRuntimeLayoutModelController()` now owns the current content-width seed from `useCanvasContentWidth()`.
- `useNoteCanvasRuntimeController()` no longer directly turns block list viewport width into layout model input.
- Full pan / zoom viewport ownership is still not implemented; this is a width/viewport seed boundary only.

### 目标

Canvas Engine 接管 world coordinate、screen coordinate、viewport、pan/zoom seed。

### 必做

- 建立 `CanvasViewportState`：
  - `x`
  - `y`
  - `width`
  - `height`
  - `zoom`
- 所有 overlay anchor 使用 world/screen 转换，不再使用页面流位置硬算。
- Canvas mode 不再依赖全局页面 scroll。
- Page mode 可以保留自然上下滚动，但坐标仍然来自同一套 world model。

### 验收

- slash menu 在当前 caret 附近出现；
- preview panel 不和 selected toolbar 层级混乱；
- Canvas mode 没有双滚动条；
- sidebar 收起后 canvas workspace 自动填充；
- viewport 改变不改变 placement truth。

## 9. L4 - PageFrame And Workspace

### Current controller checkpoint

- `useRuntimeFrameModelController()` now owns the frame/runtime model entrypoint.
- `useNoteCanvasRuntimeController()` no longer calls `useNoteCanvasFrameModel()` directly.
- PageFrame height, primary PageFrame, Canvas runtime model, relation endpoint reserve, and export preview model are still produced by existing Canvas Engine model functions; this checkpoint only clarifies ownership.
- Multi-frame productization, full pan/zoom transforms, and ruler controls are still out of scope for V2.BN.8.1.

### 目标

把 PageFrame 和 FrameOutsideWorkspace 做成 NoteCanvas 内的正式区域。

### Current seed status

```text
status: in progress
implemented seed:
  - PageFrame outer boundary and content area are separated by contentInset
  - Canvas mode formal PageFrame boundary renders the outer frame
  - block coordinates remain content-area-relative to avoid current layout migration
not implemented yet:
  - draggable ruler UI
  - persisted page margin/page style settings
  - automatic block width policy after ruler changes
```

### 必做

- PageFrame 是 canvas world 里的 formal frame，不是 DOM 卡片假象。
- PageFrame 必须保留：
  - boundary；
  - background；
  - page margin；
  - content inset；
  - exportable flag seed。
- workspace 是 PageFrame 外区域。
- workspace block 不应在切回 Page mode 时污染 formal page。

### 当前已发现问题纳入验收

- Canvas mode 不能丢 PageFrame 外边框。
- Canvas mode 不能把 PageFrame 高度撑成巨大空白。
- PageFrame height 应接近：

```text
max(base page height, bottom-most page block bottom + bottom padding)
```

- 若用户要把 block 放到 PageFrame 下方 workspace，应先水平拖出 PageFrame，再绕到下方。

- `useNoteCanvasRuntimeController()` no longer calls `useNoteCanvasResolvedLayoutModel()` or `useLayoutPersistenceController()` directly.

### 目标

```text
object_kind

frame_id optional
x
y
width
height
rotation
z_index
surface
boundary_role
snap_state

```

### 必做

- `rotation` 先保留字段，不做 UI；

### 验收

- block 移动后 reload 仍保持位置；

## 12. L7 - Measurement And Reflow Service

### Current controller checkpoint

- `useRuntimeBlockEditingController()` now also owns the first composition boundary for measured block height reflow.
- `useNoteCanvasRuntimeController()` no longer calls `useMeasuredBlockReflowController()` directly.
- Measured height, active structured block expansion, movement suppression, and collision resolution behavior are unchanged.

### 目标

把高度测量、内容扩张、resize 后重排、active editor 高度变化从 block component 里抽离。

### 必做

- 建立 measurement registry；
- 每个 block projection 上报 measured rect；
- formula input expanded/collapsed 触发 measurement；
- definition fields active/editing 触发 measurement；
- resize width 改变触发 text reflow；
- measurement 更新通过 placement service 推开后续 block。

### 验收

- 长文本粘贴不会重复，也不会撑爆 layout；
- Definition active 后不会压住下方 block；
- Formula input 展开后不会压住下方 block；
- resize 后下方 block 稳定避让；
- block 最小高度只略高于内容，不产生巨大底部空白。

```text

selectedBlock
editingText
```

## 15. L10 - Page / Canvas Mode Policy

### 目标

把 Page mode 和 Canvas mode 的规则集中到 engine。

### Current seed status

```text
status: in progress
implemented seed:
  - mode label / next label / primary page offset are produced by modePolicyService
  - Page mode workspace visibility policy is produced by modePolicyService
  - blank double-click draft placement policy is produced by modePolicyService
  - mode transition cleanup is produced by createSurfaceModeTransitionPolicy
  - useSurfaceModeController executes transition policy instead of owning the rules
```

### Page mode

- 用户主要写正式内容；
- 默认展示 PageFrame；
- workspace 内容默认隐藏或弱化；
- 普通滚轮上下浏览；

- 不展示所有 relation/debug label。

### Canvas mode

- top bar 以下交给 canvas workspace；
- 无全局页面 scroll；
- PageFrame 是 canvas 内的 formal frame；
- PageFrame 外是 workspace；
- 允许用户看到 PageFrame 外对象；
- 预留 pan/zoom；
- 不做完整多 frame 产品化。

### 验收

- 切换模式不丢 block；
- 切换模式不把 workspace block 硬夹回 PageFrame；
- Canvas mode 保留 PageFrame 边界；
- Canvas mode 不出现巨大无意义 page blank；
- Page mode 看起来仍然像可写作页面。

## 16. L11 - State Persistence And Undo Boundary

### Current controller checkpoint

- `useRuntimeBlockHistoryController()` now owns the runtime block lifecycle history bridge.
- `useNoteCanvasRuntimeController()` no longer calls `usePlacementHistory()` directly.
- Toolbar trash continues to call `trashBlock()` first, then records `pushTrashedBlockHistory()` only after the mutation succeeds.
- Draft creation history still enters the same history boundary through `pushCreatedBlockHistory`.

### 目标

定义本版本最低可用的保存与撤回边界。

### Current seed status

```text
status: in progress
implemented seed:
  - layout move / resize undo-redo
  - created block undo-redo through soft-delete / restore
  - toolbar block trash undo-redo through soft-delete / restore
  - RuntimeHistoryEntry and keyboard intent rules are centralized in historyService
  - usePlacementHistory executes keyboard intent instead of owning shortcut semantics
  - draft creation history now connects directly to pushCreatedBlockHistory without a runtime root ref bridge
not implemented yet:
  - empty draft undo
  - convert block type undo
  - inline formula conversion undo
  - source / relation mutation undo
```

当前 L11 的原则是：能落到真实数据状态的撤回才算进入 runtime history。创建 block 的撤回走 `trashed`，重做走 `active` 恢复；这比前端隐藏 block 更接近后续正式产品的 trash / restore 语义。

### 必做

- block content 保存仍走现有 API；
- placement 保存走 engine placement writer；
- undo stack 至少支持：
  - move；
  - resize；
  - create block；
  - delete empty draft；
  - convert block type seed；
  - inline formula conversion future placeholder。
- redo stack 对应 Ctrl+Y。

### 暂不做

- 跨 note undo；
- source/reference mutation undo；
- relation mutation undo；
- long-term history version UI。
