# V2.BN.8.9.2 Multi-PageFrame Management Patch Note

Date: 2026-06-26

Status: completed scoped engineering pass and verified.

## Summary

8.9.2 把 PageFrame 从“只有一个 primary PageFrame 的可读对象”推进到“一个 note 可以拥有 PageFrame collection”。

本轮重点不是完整 CanvasObject 数据库迁移，而是先建立多 PageFrame 的第一条可用链路：

```text
PageFrame collection service
  -> runtime model pageFrames[]
  -> Canvas Mode visible boundaries
  -> Layout panel minimal management actions
  -> note metadata transitional persistence
```

## Completed

- Added `pageFrameCollectionService.ts`.
- Added `PageFrameCollectionModel` and `pageFrames: PageFrameModel[]` to the runtime model.
- Added collection operations:
  - create seed collection;
  - normalize collection;
  - insert PageFrame after current frame;
  - duplicate PageFrame;
  - set primary PageFrame;
  - select PageFrame;
  - delete PageFrame with primary fallback.
- Updated runtime assembly so every PageFrame becomes a CanvasObject / CanvasPlacement / PageFrameExtension.
- Updated AI Tree PageFrame role derivation so secondary PageFrames are not reported as primary.
- Rendered every PageFrame boundary in Canvas Mode.
- Added primary / secondary boundary styles.
- Added minimal Layout panel actions:
  - insert page after;
  - duplicate page;
  - set as primary;
  - delete page.
- Added transitional persistence under note metadata key `canvas_engine_page_frames_v1`.
- Added model-contract coverage for PageFrame collection behavior.
- Added runtime-boundary checks for the collection service, WritingSurface multi-frame rendering, and Layout panel controls.
- Updated the 8.9 plan and Canvas Engine implementation checklist.

## Engineering Boundary

- The active multi-PageFrame truth for this patch is PageFrame-specific note metadata.
- This is intentionally transitional. It is not the final generic CanvasObject / CanvasPlacement database truth.
- Page Mode still focuses only the current primary PageFrame.
- Canvas Mode can show multiple PageFrames, but existing TextFlow blocks are still projected through the current compatibility layout path.
- Deleting a PageFrame only removes that PageFrame record. It does not yet migrate or delete blocks that visually overlap that frame.
- The Layout panel is a minimal management entry, not the final PageFrame navigator.

## Not Included

- No generic CanvasObject database migration.
- No full PageFrame drag / resize / reorder UI.
- No automatic movement of blocks between PageFrames.
- No ruler / margin guide / snap wall.
- No header / footer / page number slots.
- No PageFrame template / background / style system.
- No PageFrame-aware export preview.
- No crossing-object export policy.
- No ContentGroup projection.
- No Relation runtime.
- No Agent write path.

## Remaining Risks

- The persistence path is transitional note metadata, so 8.10+ still needs a deliberate CanvasObject / CanvasPlacement durability decision.
- Current visible UI does not yet solve PageFrame content ownership. Blocks are not assigned to a PageFrame collection item as durable truth.
- The PageFrame panel is intentionally simple and may need a richer navigator once PageFrame templates, rulers, and export preview are added.
