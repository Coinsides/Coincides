# V2.BN.8.7.9 ContentGroup System Closure Gate Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Close the V2.BN.8.7 ContentGroup System maturity lane by proving what is mature enough to carry into Canvas work, and by explicitly handing Canvas-dependent semantics to V2.BN.8.8+.

**Architecture:** This is a closure and hardening version, not a new feature expansion. It runs the ContentGroup system through focused data, UI, browser, and documentation gates: ContentGroup / GroupFolder / Member / Petal entity integrity, Rail / Gallery / Single Editor surface flow, source/member boundary clarity, and Canvas-dependent reuse handoff.

**Tech Stack:** React 18, TypeScript, CSS Modules, Vite, existing Coincides ContentGroup entity APIs, Canvas Engine model-contract checks, Browser Harness/manual screenshots, release docs.

---

## 1. Product Decision

V2.BN.8.7.9 exists because ContentGroup is now stable enough to stop expanding it for the moment, but not something we should close by feeling alone.

The product pillars are:

```text
TextFlow      = first pillar, natural writing and content truth.
ContentGroup  = second pillar, reusable serious content packages.
Canvas        = third pillar, spatial medium for projection, reuse, and object-level work.
```

8.7.9 should answer:

```text
Can ContentGroup System 1.0 serve as a stable foundation before V2.BN.8.8 CanvasObject work starts?
```

The expected answer is not "everything is finished." The expected answer is:

```text
The ContentGroup foundation is mature enough.
Canvas-dependent capabilities are clearly handed to 8.8+.
Known unresolved risks are named instead of hidden.
```

## 3. Closure Standards

### Data Closure

The following statements must be true or explicitly recorded as failed:

```text
ContentGroup is the root content package entity.
GroupFolder is organization truth, not source truth.
ContentGroupMember is group-local content truth.
ContentGroupPetal is internal ContentGroup structure.
ContentGroupFragment / Petal assignment is internal structure, not source Label.
preview_text is display cache, never second truth.
```

### UX Closure

The user must be able to explain the system without reading implementation notes:

```text
Rail = collect.
Gallery = organize.
Single Editor = refine.
```

The current UI does not need to be final, but it must not actively teach the wrong model.

### Reuse Closure

Reuse language is allowed to exist as service vocabulary:

```text
Reference
Duplicate
Fork
Materialize
Open original
```

But 8.7.9 must state clearly:

```text
The real reuse experience depends on CanvasObject / projection.
Without CanvasObject, ContentGroup reuse has no mature medium.
Therefore reuse UI is intentionally deferred to 8.8+.
```

### Canvas Handoff

8.7.9 should produce the handoff boundary for Canvas:

```text
Canvas may consume ContentGroup as a stable object.
Canvas must not reinterpret Member as source truth.
Canvas projection must create usage/projection records, not mutate the ContentGroup root.
Canvas materialization must be explicit, not silent source movement.
```
