# V2.BN.8.6.17 Global Drag Foundation Plan

> **For agentic workers:** Follow this plan exactly. Use `superpowers:executing-plans` when implementing. Drag is a global foundation, not only a ContentGroup shortcut.

**Goal:** 建立 DraftRange、Label、Block 的拖拽地基：可拖入 ContentGroup，也为拖到页面空白、canvas、block 内部重排留下统一模型。
**Experience Test Policy:** 默认不使用 browser harness。体验测试优先 browser-use / in-app browser。
**Stop Point:** 第一阶段完成 ContentGroup drop，并为未来页面/canvas drop 留好接口。

---

## 0. 版本定位

拖拽不是小按钮替代品，而是知识整理的核心体感。用户应像把拼图碎片丢进整理盒一样，把选区、label、block 放入 ContentGroup。

## 1. 不做什么

- 不做复杂同 TextBlock 内文本重排的最终形态。
- 不做跨 canvas 的复杂 drop。
- 不做图片/table 局部拖拽。
- 不做动画精修。
- 不做多用户协同拖拽。

## 3. 实施任务

### Task 1: 统一 drag payload

- [ ] 定义 `DragPayload`。
- [ ] 支持 `draft_range`。
- [ ] 支持 `label`。
- [ ] 支持 `block`。
- [ ] payload 必须包含 source id / range locator / preview text。
- [ ] preview text 不作为 truth。

### Task 2: DraftRange 可拖

- [ ] 选区形成 draft 后，显示可拖把手或拖拽 affordance。
- [ ] 单段 selection 和多段 selection 都能生成 payload。
- [ ] 拖拽状态必须可取消。
- [ ] 点击空白应清理 draft 状态。

### Task 3: Label 可拖

- [ ] Label badge 或高光区域可作为拖拽源。
- [ ] 拖 label 时，payload 表达 label 下的全部 ranges。
- [ ] Label 拖入 ContentGroup 后显示为一个 member，不展开成一堆噪音。

### Task 4: Block 可拖为 member

- [ ] Block handle 可作为 block member 的拖拽源。
- [ ] 拖入 ContentGroup 后，member 显示 block 摘要。
- [ ] 不改变 block 在页面上的原位置。

### Task 5: Drop target 第一阶段

- [ ] Groups Rail 中的 active group 可接收 drop。
- [ ] Gallery / editor 的 group 区域可接收 drop，如果本版尚未有 Gallery，则预留接口。
- [ ] Drop 成功后创建 ContentGroup member。
- [ ] Drop 失败不能吞掉原文。

### Task 6: 未来 drop 接口预留

- [ ] 定义拖到 page blank 的处理接口：未来可变成新 TextBlock。
- [ ] 定义拖到 canvas scratch 的处理接口：未来可按坐标生成 block。
- [ ] 定义拖到 TextBlock 内的处理接口：未来可移动文本位置。
- [ ] 当前未完成的 drop target 必须 disabled 或 no-op，不能假装成功。

## 4. 合格标准

- DraftRange 可以拖入 ContentGroup。
- Label 可以拖入 ContentGroup。
- Block 可以拖入 ContentGroup。
- 原文不被搬走，只建立引用/成员。
- Drop 失败时不丢数据。
- 未来 page/canvas/text reorder 接口有清晰扩展点。
