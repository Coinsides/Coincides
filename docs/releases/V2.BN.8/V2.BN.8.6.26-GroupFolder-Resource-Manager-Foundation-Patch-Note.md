# V2.BN.8.6.26 GroupFolder Resource Manager Foundation Patch Note

## Implemented

- GroupFolder service now exposes deletion safety helpers for resource-manager UI.
- Folder deletion safety checks active child folders and active ContentGroups placed in the folder.
- Gallery delete action now passes current groups into the folder deletion check, so deleting a folder cannot silently orphan active groups.
- Gallery disables folder delete unless the selected folder is an empty user-created folder.
- ContentGroup index sorting keeps folder path first, then orders groups by recent update time inside the folder.

## Confirmed Existing Foundation

- `GroupFolderV1` already exists as the organization/path object.
- Workspace / Project / Note root folders are seeded through `ensureGroupFolderRoots`.
- `ContentGroupV1.folder_id` and `placements` are already the primary placement fields.
- `ContentGroup.depth` is still present for compatibility, but is derived from folder path when groups are normalized with folders.
- Folder move already blocks system root movement and parent-chain cycles.

## Safety Rules

- System root folders cannot be deleted.
- A folder with child folders cannot be deleted unless a caller explicitly opts into non-empty cleanup.
- A folder containing active ContentGroups cannot be deleted unless a caller explicitly opts into non-empty cleanup.
- Gallery first version uses the conservative path: non-empty folder delete is disabled.
