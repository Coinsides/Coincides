# V2.BN.8.9.16 Cross-page Block Fragment v1 Patch Note

Date: 2026-06-27

## What Changed

- Added `pageStackBlockFragmentService.ts` as the pure model boundary for cross-page Block fragment projection.
- Added `derivePageStackBlockFragments(...)`.
- Added `PageStackBlockFragmentProjection` and `PageStackBlockFragmentRef`.
- Extended `NoteCanvasRuntimeModel` with `blockFragmentProjections`.
- Extended Canvas AI-readable Block nodes with `pageStackBlockFragments`.
- Wired runtime fragment projections into `BlockEditorLayer`.
- Added stable DOM markers:
  - `data-cross-page-block-fragment`
  - `data-cross-page-fragment-count`
  - `data-cross-page-fragment-role`
  - `data-cross-page-continuation-marker`
- Added subtle visual continuation chrome for Blocks that intersect more than one PageFrame content area in the same PageStack.

## Product Boundary

This patch is not automatic pagination.

It does not split a paragraph into line-level page slices. It does not create new NoteBlocks. It does not rewrite TextFlow. It only says:

```text
This one logical Block has visible fragments on these PageFrames.
```

That is enough for:

- user-facing continuation markers;
- AI-readable layout metadata;
- future PageSlice snapshot/reference work;
- later explicit split/materialize proposals.

## Engineering Notes

- The fragment service avoids importing `pageFrameService` and `runtimeLayout` so it does not create an `engineModel` circular dependency.
- Fragment projection is conservative: if a Block intersects multiple unrelated PageStacks, the service returns no PageStack fragment claim instead of guessing.
- Runtime derives fragment projections once from normalized PageFrame/PageStack data and block placements.
- AI Tree consumes the same runtime projection rather than recalculating layout independently.

## Deferred

- Real line-level pagination.
- User-confirmed split/materialize flow.
- PageSlice snapshot/reference/member semantics.
- Export/PDF clipping for cross-page Blocks.
- Typography-aware measurement and pagination.
