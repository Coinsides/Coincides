# V2.BN.8.6.25.1 Drag Handle And Drop Guard Hardening Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:systematic-debugging` for the drag-handle bugfix path, then use `superpowers:executing-plans` to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 把 8.6.25 做出的 Draft Range / Label / Block 拖拽地基收稳，重点修正 Draft Range handle 点不到、拖不动、影响正文布局的问题，并把不该在本阶段开放的 drop 行为加上明确护栏。

**Architecture:** 8.6.25 已经建立统一 item drag payload 和 ContentGroup drop target。25.1 不扩大对象范围，不做新的大型 UI，而是把拖拽入口、全局点击清理、payload 解析、drop target 反馈和失败保护做扎实。Draft Range handle 应该是浮层交互对象，不应该插入文字流；ContentGroup drop 仍然只创建 member reference，不搬走原文。

**Tech Stack:** React, TypeScript, Canvas Engine, HTML Drag and Drop API, existing selection draft engine, ContentGroup drag service.

---

## 1. 背景

8.6.25 已完成：

- Draft Range 写入 `draft_range` payload。
- Label badge 可以作为 persistent range package 拖拽。
- Block toolbar label action 可以作为 block item 拖拽。
- Rail / Gallery / Single Editor 的第一批 ContentGroup drop target 已接入。
- Drop into ContentGroup 只创建 member reference，不移动原文。

但人工测试发现：

- Draft Range 上方 handle 视觉出现了，但鼠标点不到或拖不动。
- 点击 handle 会让选区被清掉。
- handle 像插进文本行里的元素，会挤动正文布局。
- `DRAG RANGE` 文字 badge 对用户过重，应该换成小图标。
- 高亮区域本体暂时不需要直接拖拽，用户拖 handle 即可。
- Draft Range / Label 拖到 Page / Canvas 空白处生成 block 暂时仍不能开放，需要明确作为后续版本处理。

25.1 就是为了把这些小而关键的地基问题一次收紧。

## 2. 本版本原则

### 2.1 Handle 是浮层，不是正文内容

```text
Draft Range handle
  浮在选中区域上方
  不参与 text flow
  不改变 line height
  不把文字水平或垂直挤开
```

### 2.2 Handle 可以点击和拖拽

```text
pointer down on handle
  不清理 draft selection
  不让外层 block selection 误接管

drag start from handle
  写入 draft_range payload
  可以 drop 到已有 ContentGroup 目标
```

### 2.3 不开放高风险 drop

```text
drop into ContentGroup
  allowed
  append member reference

drop into Page / Canvas / TextBlock body
  guarded
  no visible content mutation yet
```

## 5. Task 2: Draft Range Handle 浮层化

**Files:**

- Modify: `client/src/pages/Notes/canvasEngine/blocks/TextBlockProjection.tsx`
- Modify: `client/src/pages/Notes/NoteDetail.module.css`

- [ ] **Step 1: handle 不再使用文字 badge**

把用户可见的 `DRAG RANGE` 文案替换为小图标。

推荐第一版：

```text
一条短竖线 + 一个圆形按钮
圆形按钮内是四向移动图标
```

如果项目已有 lucide 图标，优先用：

```text
Move
MoveDiagonal
Grip
```

不要使用九宫格点阵作为最终第一版视觉，因为当前看起来像调试控件。

- [ ] **Step 2: handle 使用 absolute / overlay 定位**

要求：

```text
position: absolute;
z-index: high enough above selection paint;
pointer-events: auto;
```

不能：

```text
插入 text unit inline flow
改变行高
把正文推下去
把 selection highlight 挤变形
```

- [ ] **Step 3: handle 位置在选区上方**

规则：

```text
handle anchor = first selected range visual rect
handle y = selection top - handle height - small gap
handle x = selection left or selection start center
```

如果第一版拿不到精确 rect，可以先锚定在当前 TextUnit row 的 selection 起点附近，但必须仍然是浮层。

- [ ] **Step 4: 处理窄行和顶部溢出**

当选区靠近 block 顶部时：

```text
优先仍然放上方
如果被 block clip，允许向下轻微 fallback
但不能插入文本行
```

## 10. 验收标准

### 10.1 功能验收

- [ ] 选中一段正文后，选区上方出现小型 Draft Range drag handle。
- [ ] handle 不挤动正文，不改变行高，不把文字推开。
- [ ] 点击 handle 不会取消 Draft Range。
- [ ] 从 handle 拖到 Groups Rail group row，可以增加 member。
- [ ] 从 handle 拖到 Gallery card，可以增加 member。
- [ ] 从 handle 拖到 Single Editor members area，可以增加 member。
- [ ] Label badge 仍然可以拖进上述目标。
- [ ] Block item 仍然可以拖进上述目标。
- [ ] 拖到无效区域不会创建空 member，不会删除原文。

### 10.2 视觉验收

- [ ] 不再显示 `DRAG RANGE` 文字 badge。
- [ ] handle 看起来像轻量移动入口，不像调试按钮。
- [ ] handle 位于选区上方或选区起点附近，不在选区下方反直觉位置。
- [ ] handle 在深色背景下可见，但不喧宾夺主。

### 10.3 数据验收

- [ ] ContentGroup member source reference 仍然指向原文 / label / block。
- [ ] preview 仍然只是缓存，不成为第二份真相。
- [ ] 刷新后 ContentGroup members 仍然存在。
