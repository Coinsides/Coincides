# V2.BN.8.9.11 PageFrame Numbering Scope Guard Patch Note

Date: 2026-06-27

Status: completed

## What Changed

This patch fixes a small but important PageFrame mental-model problem:

```text
PageFrameCollection is not PageStack.
```

Before this patch, multiple independent PageFrames in one note-level collection could display generated page-number chrome as `1 / 2`, `2 / 2`, etc. That made a plain Canvas-level collection look like a continuous document stack even though `PageStack / Continuous PageFrame` has not been designed or implemented yet.

Now runtime PageFrame extensions are stack-neutral by default:

- Each independent PageFrame still gets generated page-number chrome.
- Independent PageFrames no longer derive `index / total` numbering from the whole `PageFrameCollection`.
- The lower-level slot formatter still supports explicit page index and total, so a future `PageStack / Continuous PageFrame` pass can provide stack-local numbering deliberately.

## Files Changed

- `client/src/pages/Notes/canvasEngine/engineModel.ts`
  - Stopped passing collection-global `index` and `runtimePageFrames.length` into `buildPageFrameExtension(...)`.
- `client/scripts/canvasEngineModelContractCheck.ts`
  - Added `PageFrame collection does not imply PageStack numbering`.
- `client/scripts/canvasRuntimeBoundaryCheck.mjs`
  - Added guard checks that prevent runtime PageFrame extension construction from reusing collection-global total as page-number total.

## Product Boundary

This patch does not implement:

- Continuous PageFrame.
- PageStack.
- PageSlice extraction / split / merge / collapse.
- PageFrame move / resize / configuration UI.
- Durable generic CanvasObject / CanvasPlacement database cutover.

It only prevents the current UI/runtime from implying a feature that does not exist yet.
