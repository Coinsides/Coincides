# V2.BN.8.12 ContentGroup Projection And Reuse Plan

> Status: draft
> Date: 2026-06-28
> Owner: Henry + Codex
> Depends on: V2.BN.8.11 Structured Object Family closure

## 1. Version Goal

V2.BN.8.12 returns to ContentGroup as a special CanvasObject after ordinary CanvasObjects are stable.

ContentGroup projection is not just a card on a canvas. It is a projected use of an existing knowledge package, with its own source/member boundary, reuse verbs, possible mini editor, and future Petal / Relation endpoint reserve.

## 2. Why This Moved Out Of 8.11

ContentGroup is too special to be the first object family.

It carries:

- group identity and status;
- members and source anchors;
- petals/fragments;
- folder/gallery organization;
- reuse semantics;
- possible cross-note / cross-project use;
- write-back vs duplicate/fork decisions.

V2.BN.8.11 should first stabilize ordinary object lifecycle. V2.BN.8.12 can then map ContentGroup onto that lifecycle deliberately.

## 3. Non-Scope

- No full Relation runtime.
- No GraphRAG / Agent write.
- No ContentGroup Mode graph view.
- No automatic source mutation.
- No destructive materialization without user confirmation.
- No Petal-as-source-label confusion.

## 4. Subversion Draft

### V2.BN.8.12.1 ContentGroup Projection Boundary

Define:

- ContentGroup original;
- ContentGroup projection;
- usage record;
- projection context;
- open original;
- write-back / duplicate / fork decision points.

### V2.BN.8.12.2 ContentGroup Tile Projection

Make ContentGroup visible on Canvas as a tile/folder/object.

Minimum behavior:

- visible tile;
- display name/topic/status;
- open original;
- collapse/expand shell;
- placement persistence;
- AI-readable summary.

### V2.BN.8.12.3 ContentGroup Reuse Actions

Expose safe verbs:

- Reference;
- Duplicate;
- Fork;
- Materialize;
- Open original.

Each verb must state whether it creates a projection, a copy, a new group, source blocks, or only a link/reference.

### V2.BN.8.12.4 Petal Projection Reserve

Reserve Petal visibility and endpoint semantics only after ContentGroup projection exists.

Rules:

- Petal remains ContentGroup-internal structure.
- Petal does not become a source-side Label.
- Petal projection must always show parent ContentGroup context.
- No Relation runtime yet.

### V2.BN.8.12.5 ContentGroup Projection And Reuse Closure Gate

Close when:

- ContentGroup can exist on Canvas without becoming duplicated source truth.
- Reuse verbs are visible and understandable.
- Member/source boundary remains intact.
- Petal reserve is documented and not accidentally turned into Relation.
- 8.13+ ContentGroup Mode / Relation View can start from clear endpoints.
