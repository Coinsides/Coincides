# V2.BN.8.11.4 Block-Backed CanvasObject Path - Implementation Plan

> For agentic workers: REQUIRED SUB-SKILL: superpowers:test-driven-development or superpowers:executing-plans. This plan is intentionally detailed because this version creates the first durable bridge between a pure CanvasObject and TextFlow-backed content.

**Goal:** 建立“图形里写字”的 durable 路径：一个 `shape` 可以从纯视觉对象升级为 `block-backed canvas object`，底下挂一个真实的 `paragraph` note block，并通过 `ContentMount(targetKind='note_block')` 连接。

**Architecture:** `canvas_objects` + `canvas_placements` 继续负责身份和几何；`note_blocks` / TextFlow 继续负责内容真相；`content_mounts` 负责把 shape object 和 backing paragraph block 连接起来。文本绝不复制到 shape metadata 里。

**Why now:** 8.11.3 已经证明纯 `shape` 能走 generic CanvasObject 管线。8.11.5 的 sticky note、后续 image caption / table title / shaped text 都需要同一条 block-backed 路径，所以本版本必须先把这条路打稳。

---

## 0. Scope Fence

### 0.1 This Version Does

- 支持 pure shape 显式升级为 block-backed shape。
- 支持 block-backed shape 挂载一个真实 paragraph block。
- 支持 shape 内部最小文字编辑。
- 支持 reload 后 shape、placement、content mount、backing block 都能恢复。
- 支持 AI-readable layout 读取 shape 的 bbox + contentRef + paragraph text。
- 支持删除 block-backed shape 时，不留下 active orphan backing block。
- 支持显式 remove text / demote：把 block-backed shape 降回 pure shape，并清理 owned backing block。
- 支持 model / contract / server tests 证明“TextFlow 是内容真相，shape metadata 不是第二份文本”。

### 0.2 This Version Does Not Do

- 不做 sticky note 视觉预设。
- 不做 object-style preset 系统。
- 不做 visual connector。
- 不做 image / asset。
- 不做 table。
- 不做 ContentGroup projection。
- 不做 Relation runtime。
- 不做 rich text span 级样式。
- 不做 formula / table / image 填充到 shape 内。
- 不做多 block 填充到同一个 shape。
- 不做自动文字自适应、复杂垂直居中、沿曲线排版。
- 不做完整 inspector、top bar、ribbon。
- 不做 undo/redo history stack。
- 不做自动“空文本就降级”。降级必须是用户显式操作，避免用户编辑时临时清空文本导致数据被删。

### 0.3 Non-Negotiable Boundary

本版本的核心红线：

- `CanvasObject` 不是文本真相。
- `shape.metadata` 只能保存 shape 自己的轻量信息，例如 `shape_type`。
- shape 内文字必须存进 `note_blocks.content_json` 的 TextFlow 结构。
- `ContentMount` 是 shape object 和 paragraph block 的唯一 durable 连接。
- backing block 不应作为普通独立 block 再渲染一遍。

## 1. Current State

### 1.1 What Already Exists

- `kind='shape'` pure object 已能创建、移动、缩放、删除、持久化、读回。
- `shapeProjectionService.ts` 已有 seed helper：
  - `createPureShapeProjection`
  - `fillShapeWithParagraphBlock`
  - `clearBlockBackedShapeText`
- `CanvasObject` type 已支持：
  - `kind: 'shape'`
  - `backing: 'note_block'`
  - `objectClass: 'block_backed'`
- `ContentMount` type 已支持：
  - `targetKind: 'note_block'`
  - `projectionMode: 'owned'`
  - `syncPolicy: 'manual'`
- AI-tree 已有 `textByContentTargetId` 入口，但 runtime 当前没有把 mounted generic object 的 backing block text 喂进去。

### 1.2 What Is Still Missing

- Server validator 目前只允许 shape：
  - `backing='none'`
  - `object_class='pure'`
- Server shape handler 目前不验证 backing note block，也不写 `content_mounts`。
- Frontend `shapeSavePayload()` 目前永远写 pure shape。
- Shape context menu 目前只有 delete。
- `ShapeObjectLayer` 目前只渲染图形 shell，不渲染 mounted text。
- `createBlock()` 会创建普通 note block placement；如果直接复用，会导致 backing block 作为普通 block 重复出现。
- `getVisibleBlocksForSurface()` 当前不知道“canvas-object backing block”这种隐藏内容块。
- 删除 block-backed shape 时，`content_mounts` 会因 FK 级联删除，但 `note_blocks` 不会被 FK 删除，可能留下 active orphan block。

## 2. Product Semantics

### 2.1 Pure Shape

Pure shape 是普通视觉对象：

- 用于布局、框选、背景强调。
- 没有内容真相。
- 没有 `ContentMount`。
- AI 只能读取它的 kind、bbox、shape type、可见性。

Data shape:

```ts
{
  kind: "shape",
  backing: "none",
  object_class: "pure",
  metadata: {
    shape_type: "rectangle" | "ellipse"
  }
}
```

### 2.2 Block-Backed Shape

当用户对 shape 执行 “Add text” 时，shape 升级为 block-backed shape：

- 同一个 CanvasObject identity 不变。
- 同一个 CanvasPlacement 不变。
- 新建一个 backing paragraph block。
- 新建一个 `ContentMount` 指向该 paragraph block。
- 文本编辑读写 backing block 的 TextFlow。

Data shape:

```ts
{
  kind: "shape",
  backing: "note_block",
  object_class: "block_backed",
  metadata: {
    shape_type: "rectangle" | "ellipse"
  },
  extension: {
    block_id: "..."
  },
  mount: {
    mount_id: "...",
    target_id: "...",
    projection_mode: "owned",
    sync_policy: "manual"
  }
}
```

### 2.3 Demotion

用户显式执行 “Remove text” 时：

- shape 降回 pure shape。
- 删除或 trash owned backing paragraph block。
- 删除该 shape 的 `note_block` content mount。
- shape placement 和 shape metadata 保留。

不要做自动 demotion。一个空文本的 block-backed shape 仍然是合法状态，因为用户可能刚打开编辑器还没输入。

### 2.4 Deletion

删除 block-backed shape 时：

- 删除 CanvasObject。
- FK 级联删除 placement 和 content mount。
- 同步清理 owned backing block，不能留下 active orphan block。
- 如果 mount 是 `projectionMode='reference'` 或 `read_through'`，不能删 backing block；但 8.11.4 暂时只发布 `owned`。

## 3. Data Contract

### 3.1 Shape Save Payload Union

`saveShapeObjectSchema` 从单一 pure schema 改成 shape-specific union：

```ts
type SavePureShapeObject = {
  kind: "shape";
  backing?: "none";
  object_class?: "pure";
  placement: CanvasPlacementCore;
  metadata: { shape_type: "rectangle" | "ellipse" };
  source?: JsonObject;
};

type SaveBlockBackedShapeObject = {
  kind: "shape";
  backing: "note_block";
  object_class: "block_backed";
  placement: CanvasPlacementCore;
  metadata: { shape_type: "rectangle" | "ellipse" };
  extension: {
    block_id: string;
  };
  mount?: {
    mount_id?: string;
    target_id?: string;
    projection_mode?: "owned";
    sync_policy?: "manual";
  };
  source?: JsonObject;
};
```

Validation rules:

- pure shape must not provide `extension.block_id` or `mount.target_id`。
- block-backed shape must provide `extension.block_id`。
- if `mount.target_id` exists, it must equal `extension.block_id`。
- block-backed shape must use `projection_mode='owned'` in 8.11.4。
- block-backed shape must point to an active note block owned by the same user and note。
- backing block metadata must mark that it is a canvas-object backing block:

```ts
{
  projection_kind: "block_backed_shape",
  shape_object_id: "<canvas object id>",
  render_scope: "canvas_object_backing"
}
```

### 3.2 ContentMount

The mount should be deterministic enough to update safely:

```ts
{
  mountId: `${objectId}:mount:shape-text`,
  objectId,
  targetKind: "note_block",
  targetId: blockId,
  projectionMode: "owned",
  syncPolicy: "manual",
  metadata: {
    source: "block_backed_shape"
  }
}
```

### 3.3 Backing Block Visibility

Backing paragraph block must be loadable by note block API, because the client needs the TextFlow content.

But it must not be rendered as an ordinary block in the main surface.

Therefore:

- keep the backing block in `sortedBlocks` / local block state;
- filter it out before `visibleBlocks`;
- expose it through a shape text lookup map for ShapeObject rendering and AI-tree text.

This gives us both:

- content available to editor and AI；
- no duplicate visual block。

## 4. Implementation Plan

### Task 1 - Add Failing Contract Tests First

Add tests before implementation.

#### 1.1 Server tests

File:

- `server/src/__tests__/v2CanvasPersistenceCutover.test.ts`

Add tests:

- pure shape still round-trips exactly as 8.11.3 expects。
- block-backed shape payload currently fails, then should pass after implementation:

- deleting block-backed shape cleans:
  - `canvas_objects` gone;
  - `canvas_placements` gone;
  - `content_mounts` gone;
  - owned backing block no longer active。

#### 1.2 Model contract tests

File:

Add tests:

- AI-tree node for block-backed shape has:
  - `kind='shape'`;
  - `contentRef.kind='note_block'`;
  - `contentRef.id=<backing block id>`;

### Task 2 - Server Contract And Persistence

Files:

- `server/src/validators/index.ts`
- `server/src/services/canvasObjects.ts`

#### 2.1 Extend shape validator

Change `saveShapeObjectSchema` to accept both:

- pure shape；
- block-backed shape。

Do not weaken validation back to `z.record(z.unknown())`。

#### 2.2 Add shape backing validation

Add a shape-specific validator:

- pure shape: no block check。
- block-backed shape:
  - resolve `block_id` from `extension.block_id`;
  - verify active `note_blocks` row;
  - verify a `note_block_placements` row attaches it to current note;
  - verify user and course match current note;
  - verify metadata marks this as shape backing, or apply a narrow compatibility rule for newly created backing block if the metadata patch has not yet been persisted。

#### 2.3 Shape handler writes mount conditionally

Update `KIND_HANDLERS.shape`:

- if pure:
  - `backing='none'`;
  - `objectClass='pure'`;
  - remove stale `note_block` mounts for this object。
- if block-backed:
  - `backing='note_block'`;
  - `objectClass='block_backed'`;
  - upsert one note_block content mount;
  - use deterministic mount id if not provided。

#### 2.4 Cleanup on delete

Add `cleanupOnDelete` for shape:

- find owned `note_block` mounts for this object;
- if target block metadata says `projection_kind='block_backed_shape'` and `shape_object_id` equals current object id:
  - mark note block inactive/trashed using current note block deletion semantics, or hard-delete only if the existing note block system already supports safe hard-delete;
  - remove its drafts client-side after delete response。

Do not delete unrelated referenced blocks.

### Task 5 - Client Promotion / Demotion Operations

Files:

- `client/src/pages/Notes/canvasEngine/hooks/useNoteCanvasDataAdapter.ts`
- `client/src/pages/Notes/canvasEngine/layers/NoteWritingSurfaceLayer.tsx`
- `client/src/pages/Notes/canvasEngine/shapeProjectionService.ts`

#### 5.1 Promote shape

Add action:

- right-click pure shape -> `Add text`。

Flow:

1. create backing paragraph block with:
   - empty TextFlow paragraph;
   - metadata `projection_kind='block_backed_shape'`;
   - metadata `shape_object_id=<objectId>`;
   - metadata `render_scope='canvas_object_backing'`;
   - no independent canvas layout save。
2. persist same shape object as:
   - `backing='note_block'`;
   - `objectClass='block_backed'`;
   - same placement;
   - content mount to backing block。
3. if shape save fails:
   - delete/trash the newly created backing block;
   - revert local state;
   - show error toast。
4. if save succeeds:
   - select shape;
   - enter shape text editing mode。

Important: do not call `saveBlockCanvasPlacementForNote()` for the backing block. That path creates a standalone `paragraph_block_projection` object and would duplicate the text visually.

#### 5.2 Demote shape

Add action:

- right-click block-backed shape -> `Remove text`。

Flow:

1. resolve backing block from content mount。
2. trash/delete backing block using existing note block deletion path。
3. persist same shape as pure:
   - `backing='none'`;
   - `objectClass='pure'`;
   - no content mounts。
4. keep placement and shape type unchanged。

Do not demote automatically when text is empty.

## 6. Acceptance Criteria

This version is complete only when:

- pure shape still works exactly as 8.11.3。
- pure shape can be promoted to block-backed shape。
- block-backed shape stores text in paragraph block TextFlow。
- shape metadata does not contain user text。
- `ContentMount` links shape object to backing block。
- backing block is hidden from ordinary block rendering。
- AI-tree can read block-backed shape text through `contentRef`。
- remove text demotes shape without deleting shape。
- delete block-backed shape does not leave active orphan backing block。
- reload round-trip works。
- browser smoke confirms no duplicate visual block appears。

## 9. Downstream Impact

8.11.4 should make 8.11.5 much smaller:

- sticky note becomes paragraph block + style preset;
- shape text has already proven `block-backed CanvasObject`;
- object-style no longer has to solve content mounting at the same time。

It also gives later object families a clean rule:

- if an object owns text, mount a paragraph block;
- if an object owns structured data, add a typed extension;
- if an object owns binary media, mount/point to asset;
- do not hide user content inside visual metadata。
