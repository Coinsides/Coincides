# V2.BN.8.6.13 ContentGroup Object And Data Contract Plan

> **For agentic workers:** Follow this plan exactly. Use `superpowers:executing-plans` when implementing. Keep edits scoped. Do not add migration adapters for old test data unless this plan explicitly asks for one.

**Goal:** 把 ContentGroup 相关对象的语义先钉死：TextFlow 是内容根，ContentRange 是定位根，Label 是可见高光/可复用 range 包，ContentGroup 是严肃内容包，Petal 是组内局部角色。
**Experience Test Policy:** 默认不使用 browser harness。若需要体验检查，优先使用 browser-use / in-app browser。
**Stop Point:** 完成数据契约和服务层整理后，停在可进入 8.6.14 的状态。

---

## 0. 版本定位

8.6.13 不追求新界面。它是 ContentGroup Editor 后续小版本的地基，目标是避免我们继续在旧对象名上堆功能。

这版要明确几件事：

- `AnnotationSet` 不再作为未来主对象继续扩张。
- `TextUnitGroup` 如果仍存在，只能作为历史残留或临时实现细节，不再作为产品概念。
- `child label` 不再承担结构化字段职责，未来由 `Petal` 承接组内细分。
- `KnowledgeObject` 不再作为独立表或独立产品对象，必要时只理解为 `ContentGroup.identity = accepted` 的工程口径。
- `KnowledgeIndex` 暂不做，未来若需要，口径应改为 `GroupIndex` 或动态查询，而不是固定旧知识对象表。

## 1. 不做什么

- 不做 Gallery。
- 不做右侧 Groups Rail 重设计。
- 不做拖拽。
- 不做 AI 自动整理。
- 不做数据兼容 adapter。
- 不保留旧测试数据作为设计约束。当前所有账号都是测试账号，必要时可清空重建。

## 3. 实施任务

### Task 1: 盘点现有对象出口

- [ ] 列出现有 `ContentGroup`、`GroupFolder`、`AnnotationSet`、`TextUnitGroup`、`AnnotationTruth`、`SelectionDraft`、`ContentRange` 类型。
- [ ] 标出哪些是正式对象，哪些是历史对象，哪些只是 UI 状态。
- [ ] 检查是否有 UI 仍把 `AnnotationSet` 当作正式未来对象展示。
- [ ] 检查是否有服务仍把 `TextUnitGroup` 当作 relation endpoint 或知识节点。

### Task 2: 统一核心定义

- [ ] 在类型注释或邻近 contract helper 中写清楚：`Label = persistent range package + visible marker`。
- [ ] 写清楚：`DraftRange = transient selection range`。
- [ ] 写清楚：`ContentGroupMember = reference item`，不是复制正文。
- [ ] 写清楚：`Petal = local role inside one ContentGroup`，不是 child label。
- [ ] 写清楚：`ContentGroup.identity = draft | accepted | rejected | archived`，其中 `accepted` 可被工程上当作被采纳的知识对象，但不要引入独立 `KnowledgeObject` 表。

### Task 3: 建立成员来源规范

- [ ] 在 `contentGroupService.ts` 中整理或新增 helper，用来从 draft range 创建 member。
- [ ] 整理或新增 helper，用来从 label 创建 member。
- [ ] 整理或新增 helper，用来从 block 创建 member。
- [ ] 成员必须保存可追溯定位，不能只保存 preview 文本。
- [ ] preview 文本只作为显示缓存或快照，不可成为 truth。

### Task 4: 降级旧结构

- [ ] 标记 `AnnotationSet` 为 legacy 或待退场对象。
- [ ] 标记 `TextUnitGroup` 为 legacy 或待改造对象。
- [ ] 清理新代码中的 `KnowledgeObject` / `KnowledgeIndex` 命名扩张。
- [ ] 保留必要兼容只限当前代码能运行，不写迁移承诺。

### Task 5: 合同检查

- [ ] 更新 `canvasEngineModelContractCheck.ts`，让它检查 ContentGroup member 必须有定位来源。
- [ ] 检查 Petal 不能依赖 child label。
- [ ] 检查 ContentGroup 不能只存 annotation id。
- [ ] 检查旧 `AnnotationSet` 不应作为新版 editor 的主入口。

## 4. 合格标准

- 核心对象名义清楚：开发者能一眼区分 DraftRange、Label、ContentGroup、Petal。
- ContentGroup 的成员模型支持 draft range、label、block 三种来源。
- preview 文本和源内容定位被明确区分。
- 不新增旧结构 adapter。
- 不把 `KnowledgeObject` / `KnowledgeIndex` 作为新表或新主对象继续推进。
