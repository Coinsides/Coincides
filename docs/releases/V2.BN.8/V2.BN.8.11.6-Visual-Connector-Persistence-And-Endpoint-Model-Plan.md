# V2.BN.8.11.6 Visual Connector Persistence And Endpoint Model Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 把 `visual_connector` 从 8.8 的 seed / runtime-only 能力推进成真正的普通 CanvasObject：可创建、可持久化、可读回、可渲染、可被 AI-readable layout 读取，同时严格保持 `visual_only`，不进入 Relation / Graph / ContentGroup endpoint 体系。

**Architecture:** 继续沿用 8.11 已建立的通用管线：`canvas_objects` 保存身份，`canvas_placements` 保存画布占位与 z-order，新的 `visual_connector_extensions` 保存连线端点与视觉样式。Connector endpoint 只绑定 CanvasObject 或自由点，是空间布局信号，不是知识关系端点。

**Tech Stack:** React 18 + TypeScript + Vite；Node/Express + SQLite；现有 `saveCanvasObject` generic persistence；现有 canvas runtime / command / AI-tree model contract checks。

## 0. Version Position

8.11.3 已证明 `shape` 可以作为第一个真实 pure CanvasObject 走通端到端。
8.11.4 已证明 CanvasObject 可以挂 paragraph block，形成 block-backed object。
8.11.5 已证明 sticky note 只是 block-backed shape 的 presentation preset，不是新的内容类型。

8.11.6 要证明第四件事：

```text
普通 CanvasObject 之间可以出现视觉连接
但这条连接只表达 layout / visual hint
它不是 Relation
它不拥有知识关系语义
它不复用 RelationEndpointReserve
```

这一步是后续 diagram、ContentGroup mode、Relation view 之前必须守住的边界。普通画布上的线先只做视觉线；真正有语义的 Relation 以后只在专门的 relation / content-group 视图里建立。

## 1. Scope Fence

### 1.1 This Version Does

- 新增 `kind='visual_connector'` 的服务端 validator 和 kind handler。
- 新增 `visual_connector_extensions` typed sidecar table，保存端点与视觉线基础样式。
- 支持保存和读回 `visual_connector`，并把 extension 正常返回给客户端。
- 支持 runtime model 从 persistence payload hydrate `visualConnectors`，不再只依赖 command seed。
- 支持 AI-tree 输出 `connectorRef`，让 AI 能读到“这里有一条视觉线，从 A 指向 B / 或从点到点”。
- 支持一个最小可用的用户入口：从 shape 右键菜单开始连接，再在另一个 shape 上完成连接。
- 支持一个最小渲染层：在 canvas 上画出直线 / 箭头，随 endpoint object 的 placement 变化重新计算端点位置。
- 支持删除 connector 本体。
- 支持删除 endpoint object 时同步清理引用它的 visual connector，避免孤儿线。
- 增加 model / contract / server persistence 测试，确认它不污染 Relation。
- 增加 browser smoke：两个 shape 之间创建视觉线、刷新后仍存在、删除 endpoint 后线被清理。

### 1.2 This Version Does Not Do

- 不做 Relation runtime。
- 不做 KnowledgeRelation / GraphEdge。
- 不做 ContentGroup relation endpoint。
- 不复用 `RelationEndpointReserve`。
- 不给 visual connector 添加关系名称、描述、类型、权重、证据字段。
- 不做 connector label。
- 不做复杂自动布线、避让、折线编辑器、Bezier 曲线编辑器。
- 不做 connector anchor 的完整 UI 编辑器。
- 不做多选连接、批量连接、flowchart mode。
- 不做 diagram family。
- 不做 ContentGroup projection。
- 不做 image / table / asset-backed object。

### 1.3 Non-Negotiable Boundary

Visual connector 是画布对象，不是知识关系。

```text
Right:
  CanvasObject.kind = visual_connector
  CanvasObject.backing = none
  CanvasObject.objectClass = pure
  VisualConnector.relationKind = visual_only

Wrong:
  KnowledgeRelation
  RelationEndpointReserve
  ContentGroupPetal endpoint
  semantic edge
  relation label
```

如果用户在普通 Canvas Mode 里画箭头，这条箭头只能帮助人和 AI 理解 layout；它不能自动代表“概念 A 推导出概念 B”。

## 3. Data Contract

### 3.1 CanvasObject Core

Connector 本体仍然是普通 CanvasObject：

```ts
{
  kind: 'visual_connector',
  backing: 'none',
  object_class: 'pure',
  source: 'visual_connector',
  metadata: {
    connector_type: 'straight'
  }
}
```

`canvas_placements` 仍保存它的画布 bbox，用于 z-index、hit-test、选择、可见性与 AI bbox。

### 3.2 Visual Connector Extension

新增表：`visual_connector_extensions`。

建议字段：

```sql
CREATE TABLE IF NOT EXISTS visual_connector_extensions (
  object_id TEXT PRIMARY KEY REFERENCES canvas_objects(id) ON DELETE CASCADE,
  user_id TEXT NOT NULL,
  note_id TEXT NOT NULL,
  canvas_id TEXT NOT NULL,

  start_kind TEXT NOT NULL CHECK (start_kind IN ('object', 'point')),
  start_object_id TEXT,
  start_anchor TEXT NOT NULL DEFAULT 'auto',
  start_x REAL,
  start_y REAL,

  end_kind TEXT NOT NULL CHECK (end_kind IN ('object', 'point')),
  end_object_id TEXT,
  end_anchor TEXT NOT NULL DEFAULT 'auto',
  end_x REAL,
  end_y REAL,

  line_style TEXT NOT NULL DEFAULT 'solid',
  stroke TEXT NOT NULL DEFAULT '#94a3b8',
  stroke_width REAL NOT NULL DEFAULT 1.5,
  start_marker TEXT NOT NULL DEFAULT 'none',
  end_marker TEXT NOT NULL DEFAULT 'arrow',
  relation_kind TEXT NOT NULL DEFAULT 'visual_only' CHECK (relation_kind = 'visual_only'),

  metadata TEXT NOT NULL DEFAULT '{}',
  created_at TEXT NOT NULL DEFAULT CURRENT_TIMESTAMP,
  updated_at TEXT NOT NULL DEFAULT CURRENT_TIMESTAMP,

  CHECK (
    (start_kind = 'object' AND start_object_id IS NOT NULL AND start_x IS NULL AND start_y IS NULL)
    OR
    (start_kind = 'point' AND start_object_id IS NULL AND start_x IS NOT NULL AND start_y IS NOT NULL)
  ),
  CHECK (
    (end_kind = 'object' AND end_object_id IS NOT NULL AND end_x IS NULL AND end_y IS NULL)
    OR
    (end_kind = 'point' AND end_object_id IS NULL AND end_x IS NOT NULL AND end_y IS NOT NULL)
  )
);
```

索引：

```sql
CREATE INDEX IF NOT EXISTS idx_visual_connector_extensions_note
  ON visual_connector_extensions(user_id, note_id, canvas_id);

CREATE INDEX IF NOT EXISTS idx_visual_connector_extensions_start_object
  ON visual_connector_extensions(user_id, note_id, start_object_id);

CREATE INDEX IF NOT EXISTS idx_visual_connector_extensions_end_object
  ON visual_connector_extensions(user_id, note_id, end_object_id);
```

### 3.3 Endpoint Rule

Endpoint 有两类：

```ts
type VisualConnectorEndpoint =
  | {
      kind: 'object';
      objectId: string;
      anchor: 'auto' | 'center' | 'north' | 'east' | 'south' | 'west';
    }
  | {
      kind: 'point';
      x: number;
      y: number;
    };
```

本版本用户入口优先支持 object-to-object；point endpoint 作为数据能力和测试能力保留，不急着给复杂 UI。

Endpoint object id 暂不加 FK。原因是 endpoint 删除策略需要业务层明确：删除 endpoint object 时同步删除引用它的 connector。这样行为清楚，不让数据库隐式 cascade 出现“删了一个 shape，某些线突然半残”的状态。

### 3.4 Cleanup Rule

V1 采用硬清理：

```text
删除 connector object
  -> 删除 canvas_objects
  -> FK cascade 删除 visual_connector_extensions

删除 endpoint object
  -> 服务端先查 start/end 指向该 object 的 visual connector
  -> 删除这些 connector object
  -> 再删除 endpoint object
```

不做 broken endpoint 状态，不做 soft detach。视觉线连接的对象没了，线也没有继续存在的意义。

### 3.5 AI-Readable Payload

AI-tree 中的 connector node 应包含：

```ts
connectorRef: {
  relationKind: 'visual_only';
  startObjectId?: string;
  endObjectId?: string;
  start: { x: number; y: number };
  end: { x: number; y: number };
  startAnchor?: string;
  endAnchor?: string;
}
```

其中 `start` / `end` 是渲染时可用的最终世界坐标；object endpoint 则由 placement 计算出来，不把静态坐标当第二真相。
