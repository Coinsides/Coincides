# V2.BN.8.9.4 Header / Footer / Page Number Slots Patch Note

Date: 2026-06-26

Status: implemented

## Why

8.9.3.1 gave PageFrame a paper-like scale and default document typography. Before PageFrame templates, export preview, and crossing-object policy can become useful, PageFrame also needs its own page chrome boundary: header, footer, and page number.

The important boundary is that these are PageFrame-owned slots. They are not loose CanvasObjects, and they are not hidden TextFlow content.

## What Changed

- Added `client/src/pages/Notes/canvasEngine/pageFrameSlotService.ts`.
- Added `PageFrameSlot`, `PageFrameSlots`, `PageFrameSlotKind`, and `PageFrameSlotTextSource` contracts.
- Extended `PageFrameExtension` with `slots?: PageFrameSlots`.
- Runtime PageFrame extension assembly now creates default slots for every PageFrame.
- Generated page number is derived from PageFrame order.
- Empty header and footer slots use `textSource: 'empty'`, so they do not create a second content truth.
- Canvas AI-readable PageFrame nodes now expose:
  - `pageFrameRef.headerFooterEnabled`
  - `pageFrameRef.pageNumberEnabled`
  - `pageFrameSlots`
- The writing surface renders quiet slot markers with stable DOM attributes:
  - `data-page-frame-slot`
  - `data-page-frame-slot-frame`
  - `data-page-frame-slot-source`
  - `data-page-frame-slot-enabled`

## Not Included

- No rich header/footer editor.
- No TextFlow-backed header/footer editing.
- No PageFrame template/background system.
- No export preview refinement.
- No crossing-object export policy.
- No CanvasObject database migration.
