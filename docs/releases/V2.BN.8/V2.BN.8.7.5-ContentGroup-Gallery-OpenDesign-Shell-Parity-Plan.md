# V2.BN.8.7.5 ContentGroup Gallery OpenDesign Shell Parity Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:executing-plans` to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 把 ContentGroup Gallery 打磨成接近 OpenDesign `group-gallery.html` 的资源管理器界面，让用户第一眼能理解 `Gallery = organize`。

**Architecture:** 8.7.5 只处理 Gallery surface 的壳体、视觉密度、资源管理器心智和现有交互闭环，不改变 ContentGroup / GroupFolder / Member / Petal 的数据 truth。实现上先做工程边界检查，再做视觉对比截图；工程过关但视觉不像，版本仍然不能验收。

**Tech Stack:** React + TypeScript + CSS Module + Vite；现有 ContentGroup / GroupFolder entity repository 和 service；轻量 Node contract check；Browser / browser-harness 截图 smoke。

## 0. Version Scope

### Visual Target

本版本视觉目标是用户自有 OpenDesign 原型：

```text
C:/Users/70208/OneDrive/Desktop/Working/Open design/Coincides_Content_group_design/group-gallery.html
```

这个目标不是“照抄 HTML 文件”，而是要求最终页面在第一屏结构、密度、卡片形态和资源管理器心智上足够接近。差异必须被分类：

- `fix`：不必要差异，必须在本版本修掉。
- `keep`：真实产品必要差异，可以保留，但必须写明原因。
- `defer`：需要 8.7.6 / 8.7.7 / 8.8+ 的差异，记录到 patch note 或 Open Issues。
- `reject`：原型里的未来信号或与当前 doctrine 冲突的内容，不实现。

### In Scope

- Gallery 全幅资源管理器壳体。
- 顶栏：`Group Gallery`、副标题、Search、New folder、New group、返回。
- 左侧 Folder pane：workspace / project / note / custom folder 层级和数量。
- 右侧 browser pane：Folder / Topic / Role view、breadcrumb、visible count、statusbar。
- ContentGroup tile：role tab、topic 色条、title、summary、topic/source、status chip、info affordance。
- 保留现有创建 folder、删除空 folder、创建 group、打开 editor、打开 source note、跨 folder placement move 的能力。
- URL state 保留：`note_id`、`folder_id`、`mode`、`query`。
- 工程 contract check 和 browser screenshot visual gate。

### Out Of Scope

- 不做 Groups Rail shell parity，这是 8.7.6。
- 不重写 Single ContentGroup Editor，这是 8.7.7 轻量收口和 8.8+ Canvas/workbench 问题。
- 不做 CanvasObject / ContentGroup projection / mini editor。
- 不做 Graph scope runtime。
- 不做 Reference / Duplicate / Fork / Materialize UI。
- 不做 SourceArtifact / SourceAnchor migration。
- 不新增测试框架；本版本用现有 Node checks、build、browser smoke 和截图对比。

## 1. Two Acceptance Gates

8.7.5 必须同时过两个门。

### Gate A: Engineering Gate

工程面必须过得去。最低命令：

```bash
npm run check:group-gallery-shell

```

通过标准：

- 所有命令 exit 0。
- `build:client` 的既有 Vite large chunk / dynamic import warning 可以接受。
- `git diff --check` 只能有既有 Windows line-ending warning，不能有 whitespace error。
- Gallery 不得绕过 `moveContentGroupFolderPlacement` 等既有 entity route。
- Gallery 不得写回 legacy note metadata 作为 active truth。
- Gallery 不得引入 CanvasObject / GraphRAG / Materialize / Fork 等超范围 runtime。
