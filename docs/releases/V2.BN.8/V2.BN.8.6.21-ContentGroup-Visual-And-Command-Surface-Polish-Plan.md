# V2.BN.8.6.21 ContentGroup Visual And Command Surface Polish Plan

> **For agentic workers:** Follow this plan exactly. Use `superpowers:executing-plans` when implementing. For visual judgment, use the `design-taste-frontend` / taste direction if invoked by the user in the implementation turn.

**Goal:** 让 ContentGroup Editor 第一版从“施工现场”进入可长期使用的界面状态：减少气泡窗嵌套，整理按钮层级，统一右键菜单和表面按钮的分工。
**Experience Test Policy:** 默认不使用 browser harness。体验测试优先 browser-use / in-app browser。
**Stop Point:** 视觉不要求最终精修，但开发者和用户能看懂三个界面的角色。

---

## 0. 版本定位

8.6.21 是体验瘦身版。它不改变核心数据模型，而是把 Groups Rail、Group Gallery、Single Editor 的职责和视觉语言分开。

## 1. 不做什么

- 不做完整品牌视觉设计。
- 不做动画大改。
- 不做 AI 自动整理。
- 不做 relation 图。
- 不做复杂 dashboard。

## 3. 实施任务

### Task 1: 三界面角色固定

- [ ] Groups Rail：只做轻量收纳、快速查看、进入 Gallery / Editor。
- [ ] Group Gallery：做全局浏览、folder tree、topic / role 视图。
- [ ] Single Editor：做具体 group 的精加工。
- [ ] 移除把所有操作堆到 Rail 的倾向。

### Task 2: 视觉风格收敛

- [ ] 减少大圆角气泡窗套气泡窗。
- [ ] 输入区用更安静的 property/editor 风格。
- [ ] 信息密度适中，不用卡片套卡片。
- [ ] 主要按钮与次要按钮层级明确。
- [ ] 保持暗色模式可读。

### Task 3: 表面按钮瘦身

- [ ] 表面只保留必须按钮：打开/关闭、进入 Gallery、新建 group 等。
- [ ] 低频操作进入右键菜单或更多菜单。
- [ ] 不再显示意义不明的 Insert。
- [ ] 不把 Add selected 固定显示给无 selection 状态。

### Task 4: 右键菜单同步

- [ ] Selection 菜单包含 Label、Add to ContentGroup、Inline 转换、Turn into。
- [ ] Label / highlight 菜单包含 Add to ContentGroup、Change color、Remove label。
- [ ] Block 菜单包含 Add block to ContentGroup。
- [ ] Annotation Stack / Label Stack 相关菜单标记为需要后续更新，不在本版过度扩张。

### Task 5: Badge 和高光展示

- [ ] Label badge 不再全部堆到 block 右上角。
- [ ] 高光附近显示 label 名字。
- [ ] 多 label 局部聚合要避免遮挡正文。
- [ ] 保留全局 label 显示/隐藏开关。

## 4. 合格标准

- 三个界面一眼能区分角色。
- Rail 不像复杂表单。
- Gallery 是资源管理式页面。
- Single Editor 是精加工页面。
- 常用操作不迷路，低频操作不占满表面。
- 视觉不再像大量气泡堆叠。
