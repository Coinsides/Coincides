# V2.BN.8.6.5 Context Menu Foundation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the first Coincides-owned context menu foundation for text selection, label range editing, annotation highlight management, and TextUnit handle operations without expanding into Canvas blank menus, CanvasObject menus, or comments.

**Architecture:** Add a small command-surface contract and a shared menu resolver so right-click menus, future mini toolbars, TextUnit handles, and keyboard shortcuts can reuse the same command definitions. Keep the implementation focused: menus execute existing TextFlow / SelectionDraft / AnnotationTruth operations where available, and show reserved disabled commands where the product decision is confirmed but the editing engine is not ready.

**Tech Stack:** React 18, TypeScript, Vite, Coincides NoteCanvas runtime, TextFlow / TextUnit editor, SelectionDraft engine, AnnotationTruth services, lucide-react icons, existing CSS module styling.

---

## 0. Scope Boundary

### In Scope

- Text selection context menu.
- Annotation Stack / Label panel range preview context menu.
- Annotation highlight context menu seed.
- Badge click / double-click rules.
- TextUnit handle menu seed.
- A shared command-surface service / resolver.
- A formal command surface contract document.
- A contract inventory sync gate that records every researched / planned menu as `active`, `reserved`, `deferred`, or `removed`.
- V2.BN.8 docs sync and patch note.

### Out Of Scope

- Canvas blank menu.
- CanvasObject menu.
- Comment / margin note system.
- Word-like mini toolbar.
- Full rich text inline structure editor.
- Full block shell menu.
- Full browser-native Copy / Cut / Paste replacement.
- Relation endpoint menus.

## 1. Current State Summary

The current code already has these ingredients:

- `SelectionDraft` exists as the runtime selection truth.
- `AnnotationTruth` exists as durable semantic truth.
- `AnnotationInspectorPanel` manages label stack content.
- `AnnotationContextMenuLayer` exists, but it is still a narrow annotation-entry menu rather than a full command surface.
- `SelectionToolbarLayer` exists, but the new direction is to reduce or remove the single-selection annotation toolbar.
- `TextUnitGutterLayer` exists as the line-level affordance.
- `BlockControlBarLayer` exists, but block-level controls should not be mixed into text selection menus.

This version should not delete those layers blindly. It should route the right operations into clearer contextual surfaces first.

## 2. Menu Taxonomy

### 2.1 Text Selection Menu

Trigger:

- User selects text in a TextBlock / TextUnit and opens the context menu.

First-level items:

- `Copy`
- `Cut`
- `Paste`
- `Label`

Submenus:

- `Turn into`
  - Heading
  - Quote
  - Bullet list
  - Numbered list
  - To-do list
  - Toggle list
- `Inline`
  - Formula
  - Code
- `Link`

Rules:

- External product language uses `Label`, not `Annotate`.
- Internal data still uses `AnnotationTruth`.
- `Copy / Cut / Paste` stay on the surface because they are basic user expectations.
- `Turn into` and `Inline` must not be flattened into the first menu level.
- `Duplicate block`, `Delete block`, `AI visibility`, and `Export status` must not appear here.

### 2.2 Annotation Range Preview Menu

Trigger:

- User selects text inside an Annotation Stack / Label panel range preview and opens the context menu.

First-level items:

- `Copy`
- `Cut`
- `Paste`
- `Child label`

Submenus:

- `Inline`
  - Formula
  - Code
- `Link`

Rules:

- This menu is a contextual specialization of the Text Selection Menu.
- The key difference is that `Label` becomes `Child label`.
- Range preview is not just a plain text snapshot. It is a light editing projection that must eventually preserve rich text / inline structure sync with the source TextFlow.
- If full rich text sync is not ready, show inline conversion commands as disabled with a clear reserved state.

### 2.3 Annotation Highlight Menu

Trigger:

- User right-clicks a visible annotation highlight in the writing surface.

First-level items:

- `Open label`
- `Change color`
- `Hide label`
- `Remove label from this range`
- `Copy`

Rules:

- Do not show `Rename` here.
- Rename belongs to badge double-click or the Label panel.
- If a highlighted area contains multiple labels, the menu must resolve the target label before destructive actions.
- For 8.6.5, if multi-label disambiguation is too costly, open the Label panel for the cluster instead of performing direct remove.

### 2.4 Badge Interaction Rule

Trigger:

- User interacts with the badge itself.

Rules:

- Single-click badge: open Label panel / Annotation Stack.
- Double-click badge: start rename, if technically safe.
- Do not prioritize badge right-click in this version because the target is too small.

### 2.5 TextUnit Handle Menu

Trigger:

- User opens the left-side TextUnit handle / row handle command menu.

Items:

- `Turn into`
  - Paragraph
  - Heading
  - Quote
  - Bullet list
  - Numbered list
  - To-do list
  - Toggle list
- `Label this unit`
- `Split block from here`
- `Extract to new block`
- `Duplicate unit`
- `Delete unit`

Rules:

- This menu is line / paragraph / TextUnit level.
- It must not own inline formula/code/link.
- If split/extract/duplicate/delete are not safe yet, show them disabled or keep them out of the visible implementation while preserving the contract.

## 7. Contract Decision

There is no standalone formal right-click / command surface contract in the current V2.BN.8 contract set.

Existing materials:

- `docs/releases/V2.BN.8/V2.BN.8.6.5-Context-Menu-And-Command-Surface-Design.md` is a living design note.
- `docs/brainstorm/BetterNoteBook Research/Better-Notebook-UX-Inventory-and-Interaction-Contract.md` is broad inventory research, not a narrow executable contract.
- `docs/contracts/TextFlow-Contract.md`, `docs/contracts/Annotation-Contract.md`, and `docs/contracts/Notebook-Object-Inventory-Contract.md` mention command surfaces but do not define menu taxonomy.

Recommendation:

Create `docs/contracts/Command-Surface-Contract.md`.

Reason:

The difficulty of this feature is not rendering a menu. The difficulty is that Coincides has many command surfaces with different object scopes. A standalone contract prevents menu hell and keeps future right-click, slash menu, mini toolbar, TextUnit handle, inspector, and keyboard shortcuts from drifting into separate systems.
