## 0. Scope Lock

V2.BN.8.4 是 TextUnit editor seed，不是完整文本编辑器，也不是 Structure Studio。

### In Scope

- TextUnit 编辑纯函数。
- Enter / Backspace / Tab 的第一版 TextUnit 行为。
- TextUnit gutter 的低噪声第一版。
- `heading` / `quote` / `bullet_item` / `numbered_item` / `todo_item` / `toggle_item` writing role。
- Paste-to-TextFlow parser first pass。
- TextBlock / TextUnit split-merge seed。
- Heading active independent block entry retirement。
- Code / source-like writing 的边界收束。

### Out Of Scope

## 1. Historical Debt Decisions

### Heading

`Heading` 适合在 V2.BN.8.4 正式退化为 TextUnit writing role。

```text
Before:
  Heading as independent block / template entry

After:
  TextUnit.writing_role = heading
```

原因：

- Heading 是写作结构，不是知识对象。
- Heading 需要支持导航和视觉层级，但不需要独立 placement / resize / canvas object identity。
- `/heading` 应优先改变当前 TextUnit / TextBlock 的 writing role，而不是创建一个新的独立 HeadingBlock。

### Definition

`Definition` 已在 V2.BN.8.3 从 active independent block entry 退场。V2.BN.8.4 不重新打开 DefinitionBlock。

```text
Definition
  -> future AnnotationTruth.raw_label = definition
  -> future child annotations for concept name / description if the user or AI marks them
  -> future ReadingInterpretation proposal before user confirmation
```

原因：

- Definition 是语义标注，不是默认独立 block family。
- TextUnitGroup 只作为 range helper / stable range package，不再作为 knowledge role 容器。
- InlineStructure 只处理公式、代码、链接等特殊显示或交互锚点，不负责定义 semantic kind。

### Code / Source Code

`Code` 不能像 Heading 一样完全退场。它必须拆成三层：

```text
inline code
  -> future InlineStructure.kind = inline_code

code line inside TextBlock
  -> TextUnit.writing_role = code_line

multi-line / copyable / language-aware region
  -> independent CodeBlock remains active
```

V2.BN.8.4 要做的是边界收束，不是删除 CodeBlock。独立 CodeBlock 仍然有价值，因为它需要代码背景、monospace、行 gutter、复制、语言标签、未来 syntax highlight 和代码解释工作流。

### Quote / Source Quote

普通 quote 应下沉为 TextUnit writing role：

```text
ordinary quote
  -> TextUnit.writing_role = quote
```

但 provenance-oriented source citation 不能被普通 quote 替代：

```text
SourceReference answers: 凭什么说
ordinary quote answers: 这段文字怎样显示 / 怎样被写作
```

V2.BN.8.4 可以把普通 quote 的 active writing 入口收束成 quote writing role。真正 SourceReference / source chain 工作仍属于 source provenance phases，不应被 quote 样式替代。

## 3. Data Rules

### TextUnit

First-version behavior:

```text
Enter
  creates a new TextUnit after the caret.

Shift+Enter
  inserts a soft line break inside the current TextUnit text.

Backspace at TextUnit start
  merges current TextUnit into previous TextUnit.

Tab
  increases indent_level for list-like roles.

Shift+Tab
  decreases indent_level.
```

Recommended constraints:

```text
indent_level minimum = 0
indent_level maximum = 6
empty TextUnit is allowed only while editing
all persisted TextUnits must keep stable ids
order_index must be rewritten after split / merge / paste
```

### Writing Roles

V2.BN.8.4 active roles:

```text
paragraph
heading
quote
bullet_item
numbered_item
todo_item
toggle_item
code_line
```

Role display rules:

```text
heading
  larger / stronger text; not independent block.

quote
  quiet left rule or quote style; not SourceReference.

bullet_item
  bullet marker from writing_role.

numbered_item
  numbering derived from sibling order + indent_level.

todo_item
  checkbox seed; checked state in metadata.

toggle_item
  disclosure seed; collapsed state in metadata.

code_line
  monospace line inside TextBlock; not full CodeBlock replacement.
```

### Paste Parser First Pass

Input forms:

```text
plain text
markdown-ish text
clipboard text fallback
```

Parser output:

```text
TextUnit[]
```

Detection table:

```text
"# Title"
  -> heading

"> quote"
  -> quote

"- item" / "* item"
  -> bullet_item

"1. item" / "1) item"
  -> numbered_item

"- [ ] item" / "[ ] item"
  -> todo_item with checked = false

"- [x] item" / "[x] item"
  -> todo_item with checked = true

"```" fenced code block
  -> code_line units or recommend independent CodeBlock if pasted outside active TextBlock

normal line
  -> paragraph
```

V2.BN.8.4 must not pretend to preserve every Word / Notion / AFFINE formatting detail. It should preserve line boundaries, list intent, indentation, checkbox intent, heading intent, quote intent, and plain text.

```text
