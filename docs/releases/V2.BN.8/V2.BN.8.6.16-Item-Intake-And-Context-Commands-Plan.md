# V2.BN.8.6.16 Item Intake And Context Commands Plan

> **For agentic workers:** Follow this plan exactly. Use `superpowers:executing-plans` when implementing. Command surfaces must reduce clutter, not add new visible button piles.

**Goal:** 建立把 DraftRange、Label、Block 加入 ContentGroup 的第一版入口，并把高频操作放进右键菜单。
**Experience Test Policy:** 默认不使用 browser harness。体验测试优先 browser-use / in-app browser。
**Stop Point:** 用户能通过右键菜单创建 group 或加入已有 group，不需要依赖一排暴露按钮。

---

## 0. 版本定位

8.6.16 解决 “东西怎么进入 ContentGroup” 的问题。DraftRange 和 Label 是最重要的两个来源；Label 可以理解为可复用的 DraftRange 包。

## 1. 不做什么

- 不做完整拖拽。
- 不做 Gallery 全屏视图。
- 不做 Petal 细拆。
- 不做 block template 插入。
- 不做 AI 自动标注。

## 3. 实施任务

### Task 1: 定义 intake item

- [ ] 建立统一 `ContentGroupIntakeItem` 或等价结构。
- [ ] 支持 `draft_range`。
- [ ] 支持 `label`。
- [ ] 支持 `block`。
- [ ] 每个 item 都必须能转成 ContentGroup member。

### Task 2: 右键菜单加入 group

- [ ] 选中文本右键菜单增加 `Add to content group`。
- [ ] 选中文本右键菜单增加 `Create content group from selection`。
- [ ] Label 高光区域右键菜单增加 `Add label to content group`。
- [ ] Block 右键菜单增加 `Add block to content group`。
- [ ] 菜单文案面向用户，不使用内部术语 `annotation`。

### Task 3: 减少表面按钮

- [ ] 不再默认展示一排 Add / Annotate / Insert 式按钮。
- [ ] 单段普通 selection 不弹强干扰 toolbar。
- [ ] 多段 selection 可保留轻提示，但操作应能从右键完成。
- [ ] `Label` 替代面向用户的 `Annotate` 文案。

### Task 4: ContentGroup 目标选择

- [ ] 若当前 rail 有 active group，则提供加入 active group。
- [ ] 若没有 active group，提供新建 group。
- [ ] 若存在多个 group，可先用简单列表选择。
- [ ] 目标选择不能使用浏览器 `prompt()`。

### Task 5: 失败反馈

- [ ] 无有效 selection 时禁用相关菜单。
- [ ] 无有效 source range 时给轻量提示。
- [ ] 加入成功后 rail 或 group 摘要应能看到 member 数变化。

## 4. 合格标准

- DraftRange 可以通过右键创建 ContentGroup。
- DraftRange 可以加入已有 ContentGroup。
- Label 可以作为整体加入 ContentGroup。
- Block 可以作为成员加入 ContentGroup。
- 没有 `prompt()` 弹窗。
- 用户界面不再被固定按钮挤占。
