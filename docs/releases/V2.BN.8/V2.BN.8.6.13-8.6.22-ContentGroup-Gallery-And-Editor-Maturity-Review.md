# V2.BN.8.6.13-8.6.22 ContentGroup Gallery And Editor Maturity Review

**Date**: 2026-06-19
**Status**: ready for Henry manual test after automated verification
**Scope**: ContentGroup object contract, GroupFolder foundation, Groups Rail, full-page Group Gallery, Single ContentGroup Editor v1, drag intake seed, persistence and integrity checks.

## Maturity Verdict

The first ContentGroup Editor foundation is mature enough for manual testing, but it is not the final product-quality editor.

It now satisfies the first-version structure:

```text
Groups Rail = collect
Group Gallery = organize
Single ContentGroup Editor = refine
```

The important shift is that ContentGroup is no longer a cramped right-panel feature. It now has a real organization layer, a full-page management surface, and a focused editor surface.

## What Is Stable Enough

- `ContentGroup` is the durable content package.
- `GroupFolder` is the organization/path layer.
- ContentGroup `depth` is derived from folder path instead of being a primary edited field.
- `ContentGroupMember` keeps traceable member references and preview text.
- `Petal` remains the internal part/role layer inside one ContentGroup.
- Draft Range and Label can be represented as ContentGroup drag payloads.
- Note metadata read/write now goes through shared ContentGroup metadata helpers.
- Contract checks can detect missing folders, folder cycles, missing group member sources, stale accepted groups, and Petal members that are not present in the parent group.

## Implemented Surfaces

### Groups Rail

Purpose: collect current-note content quickly.

Implemented:

- Open from note workspace.
- Create a new group from selected content path.
- Drop dragged Draft Range / Label payloads into intake or existing group.
- Jump to full Group Gallery with note/folder/group context.

Still rough:

- Direct block drag is reserved because it can conflict with layout drag.
- Full right-click ContentGroup routing is still a later command-surface pass.

### Group Gallery

Purpose: organize folders and content groups across projects/notes.

Implemented:

- Left navigation entry: `Group Gallery`.
- Full-page route: `/group-gallery`.
- Folder tree grouped by project and note.
- Folder / Topic / Role modes.
- Create folder under selected folder.
- Rename non-system folder inline, without native browser prompt.
- Delete empty non-system folder.
- Create ContentGroup in selected folder.
- Select group and open the editor pane.
- Jump back to source note.

Still rough:

- Gallery is structurally usable, but it still needs the later `taste` visual pass.
- Folder moving / cross-project copy / cross-note aggregation are not done.
- Direct drag from note canvas into the already-open full Gallery is not done.

### Single ContentGroup Editor

Purpose: refine one group.

Implemented:

- Edit group title.
- Edit topic, role, and summary.
- Save draft identity.
- Accept / reject identity.
- View members.
- Add Petal.
- Rename Petal.
- Archive Petal.
- Open source note.

Still rough:

- Petal fragment assignment is not done.
- Member source preview is read-only.
- No detailed split UI for decomposing one Label into multiple Petals yet.

## Retired Or Demoted Concepts

- `AnnotationSet` remains a historical seed and should not be expanded as the future package model.
- `TextUnitGroup` remains a predecessor / inspiration and should not continue growing as normal UX.
- `child label` is superseded by Petal for ContentGroup internal parts.
- Label remains a marker / reusable range package, not the main content package truth.

## Henry Manual Test Checklist

### 1. Entry And Navigation

- Open the app.
- Confirm left navigation has `Group Gallery`.
- Click `Group Gallery`.
- Confirm it opens a full-page workspace, not a floating panel.
- Return to a note.
- Open the note Groups Rail.
- Click its Gallery button.
- Confirm Gallery opens with the current note/folder/group context.

### 2. Folder Basics

- In Gallery, select a note root folder.
- Create a new folder.
- Select the new folder.
- Rename it using the inline folder-name field.
- Refresh the page.
- Confirm the folder persists.
- Try deleting an empty non-system folder.
- Confirm system root folders are not deletable through normal UI.

### 3. Group Basics

- Select a folder.
- Create a new ContentGroup.
- Confirm the group appears in the current folder.
- Edit title, topic, role, and summary.
- Save.
- Refresh.
- Confirm all fields persist.

### 4. Identity State

- Set a group to accepted.
- Refresh.
- Confirm accepted state persists.
- Reject a group.
- Confirm rejected state persists.
- Edit members or Petals later and check whether identity invalidation remains acceptable in the follow-up version.

### 5. Members

- In a note, select text and create/confirm a Draft Range.
- Drag the Draft Range badge into the Groups Rail intake.
- Confirm a new group can be created from it.
- Drag the Draft Range badge onto an existing group.
- Confirm it appends as a member.
- Create a Label in the note.
- Drag the Label badge into the Groups Rail.
- Confirm it becomes a member.
- Refresh and confirm member previews remain.

### 6. Petals

- Open a group in Gallery.
- Add a Petal.
- Rename the Petal.
- Archive the Petal.
- Refresh and confirm the Petal state persists.

### 7. View Modes

- Create groups with different topics and roles.
- Switch Gallery to `Folder`.
- Switch Gallery to `Topic`.
- Switch Gallery to `Role`.
- Confirm each mode changes grouping without moving the source groups.

## Known Gaps That Do Not Block This Handoff

- Full `taste` visual redesign.
- Full command surface update for ContentGroup operations.
- Direct drag from source note into full-page Gallery.
- Block-level drag source.
- Petal fragment assignment UI.
- Cross-project / cross-note folder copy and move.
- Table/image region members.
- Relation graph runtime.
- AI-created groups and AI review flow.
