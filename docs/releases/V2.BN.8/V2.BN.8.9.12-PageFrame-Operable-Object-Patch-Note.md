# V2.BN.8.9.12 PageFrame Operable Object Patch Note

Date: 2026-06-27

## Scope

This patch makes PageFrame behave like a first-pass operable CanvasObject in Note Canvas Mode.

Completed:

- PageFrame can be selected in Canvas/Layout Mode.
- PageFrame can be moved by dragging its shell.
- PageFrame can be resized through a bottom-right handle.
- PageFrame geometry changes persist through the existing `PageFrameCollectionModel` save path.
- Runtime boundary checks now cover PageFrame move/resize service helpers, controller wiring, writing-surface props, and DOM smoke markers.
- Model contract checks now cover PageFrame x/y/width/height updates while preserving primary and selected frame identity.

Product boundary:

- Moving a PageFrame changes PageFrame geometry only.
- Blocks are not owned by PageFrames and do not move with the PageFrame.
- Block/PageFrame relation remains geometry-derived.
- This patch does not introduce Continuous PageStack, PageSlice, PageFrame lock, rich template editor, or generic CanvasObject DB cutover.

## Browser Findings

Browser Harness first pass covered:

- Canvas Mode + Layout Mode entry.
- PageFrame selected marker and resize handle visibility.
- Dragging the primary PageFrame: screen position changed from about `(690,208)` to `(750,243)`.
- Resizing the primary PageFrame: visible size changed from about `407x575` to `457x600`.

During testing, the first implementation reused the select-and-focus path on pointer down. That caused the viewport to jump before drag. The patch now avoids focus on pointer down for PageFrame move/resize; geometry update commits the selected frame instead.
