# V2.BN.8.11.8 Table / Structured Object Model Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:executing-plans` to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 让表格作为第一类 `structured_object` CanvasObject 进入 8.11 通用画布管线：可创建、可编辑基础行列与单元格文本、可持久化、可读回、可渲染、可移动 / 缩放 / 删除，并能以结构化行列形式进入 AI-readable layout。
**Architecture:** `canvas_objects` 保存对象身份，`canvas_placements` 保存画布布局，新建 `structured_object_extensions` typed sidecar 保存结构化对象数据。表格 v1 使用 `kind='table'`、`backing='structured_object'`、`object_class='structured'`，单元格文本保存在 table payload 里，不挂 TextFlow / paragraph block；AI-tree 通过 `structuredRef` 读取行列与单元格内容。
**Tech Stack:** React 18 + TypeScript + Vite；Node / Express + SQLite；现有 generic CanvasObject persistence；现有 canvas runtime / AI-tree / command surface；现有 boundary / model-contract / runtime verification scripts。

---

## 0. Version Position

8.11.3 证明 `shape` 可以作为 pure CanvasObject 跑通通用管线。
8.11.4 证明 CanvasObject 可以挂 paragraph block，形成 block-backed object。
8.11.5 证明 sticky note 是 paragraph block 的 presentation preset，而不是新内容真相。
8.11.6 证明 `visual_connector` 可以作为 visual-only object 持久化，并且不污染 Relation。
8.11.7 证明 `image` 可以作为 asset-backed object 持久化，并进入 AI-readable layout。

8.11.8 要证明第六件事：

```text
CanvasObject 可以承载结构化数据
表格的行 / 列 / 单元格不是一条扁平 text
AI-tree 可以直接寻址第几行第几列
未来 Excel / Word / PDF 表 / 图片表导入可以填同一套 table payload
TextFlow 不被表格 v1 牵扯进去
```

这一版不是做一个迷你 Excel。它是给 CanvasObject 家族补上“结构化对象”这一类背板。

## 1. Scope Fence

### 1.1 This Version Does

- 新增 `structured_object_extensions` typed sidecar 表，作为结构化 CanvasObject 的持久化扩展层。
- 新增 `kind='table'` CanvasObject server handler。
- 新增 table v1 数据模型：
  - 行。
  - 列。
  - 单元格文本。
  - 基础行列尺寸。
  - 基础元数据。
- 支持创建默认 3 x 3 table object。
- 支持编辑单元格纯文本。
- 支持基础增删行列：
  - 在当前单元格下方添加行。
  - 在当前单元格右侧添加列。
  - 删除当前行。
  - 删除当前列。
- 支持表格对象移动、缩放、删除。
- 支持刷新后读回表格对象。
- 支持 AI-tree 输出 `structuredRef`，让 AI 读到：
  - `rowCount`
  - `columnCount`
  - `rows`
  - `columns`
  - `cells[{ rowIndex, columnIndex, text }]`
- 增加 server / model / runtime / browser smoke 覆盖。
- 更新 8.11 主计划、patch note、Review、CHANGELOG、current-state。

### 1.2 This Version Does Not Do

- 不做 Excel 公式。
- 不做 Excel / CSV / Word / PDF / 图片表导入。
- 不做排序、筛选、冻结行列。
- 不做复杂合并单元格。
- 不做富文本单元格。
- 不把每个单元格变成 paragraph block。
- 不把 table 放进 TextFlow 正文。
- 不做表格作为 ContentGroup member 的复用 UI。
- 不做 table export / PDF 精确导出。
- 不做 spreadsheet engine。
- 不做跨表引用。
- 不做复制粘贴 Excel 区域。
- 不做 undo / redo 专门栈。
- 不做大表虚拟滚动。
- 不做公式求值安全沙箱。

### 1.3 Non-Negotiable Boundary

表格是 `structured-backed CanvasObject`，不是正文 block，不是图片，不是 SourceArtifact，也不是 Excel 引擎。

```text
Right:
  CanvasObject.kind = table
  CanvasObject.backing = structured_object
  CanvasObject.objectClass = structured
  StructuredObjectExtension.structuredKind = table
  StructuredObjectExtension.schemaVersion = table.v1
  Table cells are plain structured text fields

Wrong:
  paragraph_block_projection
  image asset OCR result
  SourceArtifact table parsing result
  ContentGroup truth
  Excel workbook runtime
  cells as arbitrary JSON without validation
```

## 3. Data Contract

### 3.1 Structured Extension Table

Add migration, suggested name: `042_v2_structured_object_extensions.ts`.

```sql
CREATE TABLE IF NOT EXISTS structured_object_extensions (
  object_id TEXT PRIMARY KEY,
  user_id TEXT NOT NULL,
  note_id TEXT NOT NULL,
  canvas_id TEXT NOT NULL,
  structured_kind TEXT NOT NULL,
  schema_version TEXT NOT NULL,
  row_count INTEGER,
  column_count INTEGER,
  data_json TEXT NOT NULL,
  metadata TEXT,
  created_at TEXT NOT NULL,
  updated_at TEXT NOT NULL,
  FOREIGN KEY (object_id) REFERENCES canvas_objects(id) ON DELETE CASCADE
);

CREATE INDEX IF NOT EXISTS idx_structured_object_extensions_note
  ON structured_object_extensions(user_id, note_id);

CREATE INDEX IF NOT EXISTS idx_structured_object_extensions_kind
  ON structured_object_extensions(user_id, structured_kind);
```

Rules:

- v1 only accepts `structured_kind='table'`.
- v1 only accepts `schema_version='table.v1'`.
- `object_id` is the same durable id as `canvas_objects.id`.
- `row_count` and `column_count` are read-side convenience fields; `data_json` remains the payload truth.
- `data_json` must be strongly validated before write and after read.
- Deleting a table object deletes its structured extension through FK cascade.
- Do not store table payload in `canvas_objects.metadata`.
- Do not create a separate SourceArtifact or Document row for a manually created table.

### 3.2 Table Payload

Use a backend-agnostic model. Manual creation and future importers should produce this same shape.

```ts
export interface TableStructuredPayload {
  version: 'table.v1';
  rows: TableRowModel[];
  columns: TableColumnModel[];
  cells: TableCellModel[];
}

export interface TableRowModel {
  rowId: string;
  index: number;
  height?: number;
}

export interface TableColumnModel {
  columnId: string;
  index: number;
  width?: number;
  label?: string;
}

export interface TableCellModel {
  cellId: string;
  rowId: string;
  columnId: string;
  rowIndex: number;
  columnIndex: number;
  text: string;
  valueType: 'text';
}
```

Validation rules:

- `rows.length >= 1` and `rows.length <= 50`.
- `columns.length >= 1` and `columns.length <= 20`.
- `cells.length === rows.length * columns.length`.
- `row.index` must be continuous from `0`.
- `column.index` must be continuous from `0`.
- Every cell must reference an existing row and column.
- Every row / column pair must have exactly one cell.
- `cell.text.length <= 2000`.
- v1 only accepts `valueType='text'`.
- Row and column ids must be stable across edits.
- Adding a row or column creates new stable ids; it must not rewrite all existing ids.

### 3.3 CanvasObject Payload

Persist table object through the generic object route:

```ts
{
  kind: 'table',
  backing: 'structured_object',
  object_class: 'structured',
  placement: {
    x: number,
    y: number,
    width: number,
    height: number,
    rotation: 0,
    z_index: number
  },
  extension: {
    structured_kind: 'table',
    schema_version: 'table.v1',
    rows: TableRowModel[],
    columns: TableColumnModel[],
    cells: TableCellModel[],
    metadata: {}
  },
  metadata: {}
}
```

Validation:

- `kind='table'` requires `backing='structured_object'`.
- `kind='table'` requires `object_class='structured'`.
- `kind='table'` requires a table extension.
- `kind='table'` rejects `mount` / `contentMount`.
- `kind='table'` rejects `asset_id`.
- `kind='table'` rejects visual connector endpoints.
- `placement.width` and `placement.height` must be positive.
- `rotation` remains `0` in v1.

## 4. User Experience Contract

### 4.1 Creation

Minimum acceptable v1:

1. User right-clicks blank canvas / page frame area.
2. Menu shows `Table`.
3. User clicks `Table`.
4. Client creates a default 3 x 3 table object at the clicked canvas point.
5. Table object appears immediately.
6. Table object persists after reload.

Creation defaults:

```ts
const DEFAULT_TABLE_ROWS = 3;
const DEFAULT_TABLE_COLUMNS = 3;
const DEFAULT_TABLE_CELL_WIDTH = 120;
const DEFAULT_TABLE_CELL_HEIGHT = 36;
const DEFAULT_TABLE_WIDTH = DEFAULT_TABLE_COLUMNS * DEFAULT_TABLE_CELL_WIDTH;
const DEFAULT_TABLE_HEIGHT = DEFAULT_TABLE_ROWS * DEFAULT_TABLE_CELL_HEIGHT;
```

### 4.2 Editing

Minimum acceptable v1:

- Clicking a cell selects it.
- Double-clicking a cell enters text edit mode.
- `Enter` commits text and exits edit mode.
- `Shift+Enter` inserts a newline in the cell text if the cell editor is a textarea.
- `Escape` cancels the active edit and restores the previous cell text.
- Blur commits current text.
- Empty cell text is valid.

Cell selection state:

```ts
interface TableCellSelection {
  objectId: string;
  rowId: string;
  columnId: string;
}
```

### 4.3 Row / Column Actions

Minimum acceptable v1 actions:

- Add row below selected cell.
- Add column right of selected cell.
- Delete selected row.
- Delete selected column.

Rules:

- If no cell is selected, add row at the end.
- If no cell is selected, add column at the end.
- Deleting is disabled when row count is `1`.
- Deleting is disabled when column count is `1`.
- Row / column mutation must preserve existing cell text.
- Row / column mutation must keep row / column indexes continuous.
- Row / column mutation must preserve row / column ids for untouched rows / columns.

### 4.4 Rendering

Table object should feel like a compact canvas object, not a dashboard card.

Required DOM markers for smoke tests:

```html
data-canvas-object-kind="table"
data-canvas-structured-object="table"
data-canvas-table-object="true"
data-canvas-table-rows="3"
data-canvas-table-columns="3"
data-canvas-table-cell="row-0:col-0"
```

Visual rules:

- Use a simple grid.
- Preserve object placement bounds.
- Cells should not resize the object while typing.
- Long text should wrap inside cell.
- Object resize changes the rendered table bounds, not the row / column count.
- v1 can distribute width evenly across columns after object resize.
- v1 can distribute height evenly across rows after object resize.

## 5. AI-Readable Layout Contract

Add `structuredRef` to `CanvasAIReadableNode`:

```ts
structuredRef?: {
  kind: 'table';
  schemaVersion: 'table.v1';
  rowCount: number;
  columnCount: number;
  rows: Array<{
    rowId: string;
    index: number;
  }>;
  columns: Array<{
    columnId: string;
    index: number;
    label?: string;
  }>;
  cells: Array<{
    cellId: string;
    rowId: string;
    columnId: string;
    rowIndex: number;
    columnIndex: number;
    text: string;
    valueType: 'text';
  }>;
}
```

Rules:

- AI-tree reads table layout and structured cell text.
- AI-tree does not invent formulas.
- AI-tree does not infer semantic headers unless the payload later explicitly marks them.
- AI-tree does not collapse the table into one newline-separated string.
- `CanvasAIReadableNode.text` may contain a short fallback summary such as `Table 3 x 3`, but the authoritative table content is `structuredRef`.
- Do not expose internal SQLite payload as raw JSON.

Example AI node:

```ts
{
  id: 'table-abc',
  kind: 'table',
  label: 'Table 3 x 3',
  bbox: { x: 200, y: 160, width: 360, height: 108 },
  zIndex: 12,
  surface: 'page',
  visible: true,
  structuredRef: {
    kind: 'table',
    schemaVersion: 'table.v1',
    rowCount: 3,
    columnCount: 3,
    rows: [{ rowId: 'row-1', index: 0 }],
    columns: [{ columnId: 'col-1', index: 0 }],
    cells: [
      {
        cellId: 'cell-row-1-col-1',
        rowId: 'row-1',
        columnId: 'col-1',
        rowIndex: 0,
        columnIndex: 0,
        text: 'Power series',
        valueType: 'text'
      }
    ]
  }
}
```

## 9. Risks and Mitigations

| Risk | Severity | Mitigation |
| --- | --- | --- |
| Table becomes a mini Excel and bloats this version | High | Hard scope: text-only cells, row/column add/delete only, no formulas/import/sort/filter. |
| Cells become paragraph blocks too early | High | v1 stores plain cell text in table payload; rich cell/TextFlow is a later explicit design. |
| Table data hides as arbitrary JSON | Medium | Use typed extension table + strict payload validator + row/column count fields. |
| AI can only read flattened text | High | Add `structuredRef`; contract checks must assert row/column/cell addressing. |
| Future Excel/PDF import conflicts with v1 model | Medium | Use backend-agnostic rows/columns/cells payload and stable ids; importers can fill same model later. |
| Large tables hurt runtime | Medium | v1 caps rows at 50, columns at 20, cells at 1000. |
| Row/column mutation corrupts indexes | Medium | Centralize mutation in `tableObjectService.ts`; model-contract checks cover add/delete behavior. |
| Table editing interferes with canvas drag | Medium | Editing cells stops propagation; canvas drag only applies outside active editor. |
