# V2.BN.8.6.14 GroupFolder Foundation Plan

> **For agentic workers:** Follow this plan exactly. Use `superpowers:executing-plans` when implementing. This version builds the folder foundation only; do not redesign the Gallery yet.

**Goal:** 从零建立 GroupFolder 作为 ContentGroup 的摆放与浏览支柱。Folder 负责组织位置，ContentGroup 负责内容包本体。
**Experience Test Policy:** 默认不使用 browser harness。若需要体验检查，优先使用 browser-use / in-app browser。
**Stop Point:** Folder 数据稳定，ContentGroup 能被放进 folder，Project / Note root folder 能自动存在。

---

## 0. 版本定位

8.6.14 是 ContentGroup Editor 的第二根柱子。它解决之前 `depth` 字段太抽象的问题：ContentGroup 的层级不再靠自由填写的数字表达，而由它所在的 GroupFolder 路径表达。

## 1. 不做什么

- 不做全屏 Group Gallery。
- 不做完整文件夹管理 UI。
- 不做拖拽移动 folder。
- 不做跨 project relation view。
- 不做 pin / link folder 的复杂设计。

## 3. 实施任务

### Task 1: 定义 GroupFolder 数据模型

- [ ] GroupFolder 至少包含 `id`、`name`、`parent_id`、`scope_type`、`scope_id`、`system_kind`、`created_at`、`updated_at`。
- [ ] `system_kind` 至少区分普通 folder、workspace root、project root、note root。
- [ ] Folder 本身只有一种能力模型，不拆出 project folder / note folder 等多个类型。
- [ ] 系统 root folder 不能被用户删除。

### Task 2: 自动生成 root folder

- [ ] 进入 workspace 时确保 workspace group root 存在。
- [ ] 进入 project 时确保 project group root 存在。
- [ ] 进入 note 时确保 note group root 存在。
- [ ] root folder 的生成必须幂等：重复打开不能重复创建。

### Task 3: ContentGroup 绑定 folder

- [ ] ContentGroup 新增或整理 `folder_id`。
- [ ] 移除或降级 `depth` 作为主字段的地位。
- [ ] 若 UI 暂时仍显示 depth，只能显示为从 folder path 推导出的辅助信息。
- [ ] 新建 ContentGroup 时按当前 scope 自动落入对应 root folder。

### Task 4: Folder 路径解析

- [ ] 新增或整理 `resolveGroupFolderPath(folderId)`。
- [ ] 返回可用于 UI 的 breadcrumb。
- [ ] 支持 workspace / project / note root 的路径显示。
- [ ] 支持 ContentGroup 通过 folder_id 找到完整路径。

### Task 5: 基础操作服务

- [ ] `createGroupFolder(parentId, name)`。
- [ ] `renameGroupFolder(folderId, name)`。
- [ ] `moveGroupFolder(folderId, targetParentId)`，第一版可只在服务层支持。
- [ ] `deleteGroupFolder(folderId)`，必须拒绝删除系统 root。
- [ ] `moveContentGroupToFolder(groupId, folderId)`。

## 4. 合格标准

- Project / Note 打开后，对应 root folder 必然存在且不重复。
- ContentGroup 必须有 folder 归属。
- Folder path 可以稳定解析。
- 系统 root 不可删除。
- 不再依赖 `depth` 作为 ContentGroup 的主定位方式。
