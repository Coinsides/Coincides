## 0. Why This Version Exists

当前 `ContentGroupV1` 的对象形状已经比较成熟，但持久化仍在 note metadata 中：

```text
notes.metadata.canvas_engine_content_groups_v1
```

这会造成四个问题：

1. Gallery 要跨 note / project 管理 ContentGroup 时，只能扫描 note metadata。
2. ContentGroup 未来要被 Canvas projection、AI、relation、reuse 引用时，没有自己的 entity boundary。
3. `ContentGroup` 与 `Note` 生命周期耦合过紧，跨 note / project 复用会变得别扭。
4. 后续拆 `Member`、`Petal`、`GroupFolder` 时，如果根对象仍是 metadata 数组项，所有后续版本都会背着旧债施工。

所以 `V2.BN.8.7.1` 的任务不是视觉套壳，也不是完整图数据库迁移，而是先建立一个干净的根：

```text
ContentGroup = independent root entity
Member / Fragment / Petal = embedded payload for now
GroupFolder = metadata-backed organizer for now
Legacy note metadata groups = import source, not truth
```

## 4. Compatibility Strategy

### Read Compatibility

The client should load groups in this order:

```text
1. GET /api/content-groups?note_id={noteId}
2. If API returns active groups, use them.
3. If API returns empty and note.metadata has legacy groups, import legacy groups through API.
4. After import succeeds, use imported entity groups.
5. If import fails, show legacy groups read-only enough for visibility and show a console/error toast.
```

For this version, "import" means upserting legacy groups into `content_groups`; it does not need to rewrite note metadata immediately.

### Write Compatibility

New writes must go to `content_groups`.

Do not write new groups back to:

```text
notes.metadata.canvas_engine_content_groups_v1
```

Folder metadata is still allowed to use:

```text
notes.metadata.canvas_engine_group_folders_v1
```

This keeps GroupFolder work isolated for 8.7.2.

### Legacy Metadata Cleanup

The plan does not require a polished user-facing cleanup migration. It should add a safe helper:

```ts
export function stripLegacyContentGroupMetadata(
  metadata: Record<string, unknown> | undefined,
): Record<string, unknown> {
  const next = { ...(metadata || {}) };
  delete next[NOTE_CONTENT_GROUPS_METADATA_KEY];
  return next;
}
```

Use it only after an import/save succeeds for the current note, and only if this does not risk deleting folder metadata or annotations.

Because the product is not deployed to real users yet, Henry may choose to clear test data before execution. The code should still be safe enough not to destroy source text or note blocks.

### Routes


Why `PUT /by-note/:noteId` exists:

- Current frontend saves a complete `ContentGroupV1[]` list for one note.
- Rewriting every caller to single-object commands is unnecessary in 8.7.1.
- The endpoint can transactionally upsert provided groups and mark missing note-owned groups as `deleted`.

```ts
  if (!value) return fallback;
  try {

  } catch {
    return fallback;
  }
}

function stringifyJson(value: unknown, fallback: unknown): string {

function cleanText(value: unknown, fallback: string): string {
```

```ts
    FROM content_groups

export function upsertContentGroup(db: Database.Database, userId: string, input: any) {
  const values = contentGroupDbValues(userId, input);
  ensureCourse(db, userId, values.course_id);
  if (values.note_id) {
    const note = ensureNote(db, userId, values.note_id);
    if (note.course_id !== values.course_id) throw new AppError(400, 'Note does not belong to course');
  }

  db.prepare(`
    INSERT INTO content_groups (
      id, user_id, course_id, note_id, canvas_id, primary_folder_id, parent_group_id,
      title, status, created_by,
      identity_status, identity_role, identity_topic, identity_summary,

      identity_updated_at, identity_accepted_at,

      view_state_json, metadata, created_at, updated_at
    )
    VALUES (
      @id, @user_id, @course_id, @note_id, @canvas_id, @primary_folder_id, @parent_group_id,
      @title, @status, @created_by,
      @identity_status, @identity_role, @identity_topic, @identity_summary,
      @identity_created_by, @identity_reviewed_by, @identity_confidence,
      @identity_updated_at, @identity_accepted_at,
      @placements_json, @members_json, @fragments_json, @petals_json,
      @view_state_json, @metadata, @created_at, @updated_at
    )
    ON CONFLICT(id) DO UPDATE SET
      course_id = excluded.course_id,
      note_id = excluded.note_id,
      canvas_id = excluded.canvas_id,
      primary_folder_id = excluded.primary_folder_id,
      parent_group_id = excluded.parent_group_id,

export function replaceNoteContentGroups(
  db: Database.Database,
  userId: string,
  noteId: string,
  groups: any[],
) {
  const note = ensureNote(db, userId, noteId);
  return db.transaction(() => {
    const nextGroups = groups.map((group) => upsertContentGroup(db, userId, {
      ...group,
      project_id: group.project_id || note.course_id,
      course_id: group.course_id || group.project_id || note.course_id,
      note_id: noteId,
    }));
    const keepIds = new Set(nextGroups.map((group) => group.id));
    const existing = listContentGroups(db, userId, { course_id: note.course_id, note_id: noteId, status: 'all' });
    for (const group of existing) {
      if (!keepIds.has(group.id) && group.status !== 'deleted') {
        db.prepare("UPDATE content_groups SET status = 'deleted', updated_at = ? WHERE id = ? AND user_id = ?")
          .run(new Date().toISOString(), group.id, userId);
      }
    }
    return listContentGroups(db, userId, { course_id: note.course_id, note_id: noteId });
  })();
}
```
