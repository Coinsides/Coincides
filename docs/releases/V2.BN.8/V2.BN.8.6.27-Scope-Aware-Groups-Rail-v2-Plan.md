# V2.BN.8.6.27 Scope-Aware Groups Rail v2 Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:executing-plans` to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 把右侧 Groups Rail 从“小表单 / 半个编辑器”改造成当前 scope 的轻量收集盒。它只负责快速查看、快速新建、快速接收 item、跳转到 Gallery / Single Editor，不再承载完整 ContentGroup 表单和复杂管理职责。

**Architecture:** Rail 依赖 8.6.26 的 GroupFolder resolver。用户在 workspace / project / note 的不同位置打开 Rail 时，Rail 自动进入对应 root folder。Rail 显示当前 folder 下的轻量 folder/group 列表、active group、drop target 和少量入口按钮；完整资源管理交给 Group Gallery，单包精加工交给 Single ContentGroup Editor。

**Tech Stack:** React, TypeScript, Canvas Engine, ContentGroupPanel, GroupFolder helpers, unified item drag payload, right-side rail layout.

---

## 1. 背景

15:10 会议记录已经把三层界面分开：

```text
Groups Rail
  collect
  当前页面右侧迷你资源管理器

Group Gallery
  organize
  全屏资源管理器

Single ContentGroup Editor
  refine
  单个内容包精加工台
```

当前 Rail 的问题是：

- 很容易塞入过多按钮。
- 像缩小版表单，而不是收集盒。
- 用户一眼看不出当前 scope 是 project、note，还是 workspace。
- 添加内容、打开 Gallery、打开 Single Editor、编辑字段混在一起。

8.6.27 的目标就是把 Rail 的角色钉死。

## 2. 本版本原则

### 2.1 Rail 只做轻量收集

Rail 可以做：

```text
查看当前 scope 下的 folder/group 列表
设置 active group
新建 group
把当前 item / dragged item 加入 group
打开 Gallery
打开 Single Editor
关闭自己
```

Rail 不做：

```text
完整编辑 topic / role / summary
完整管理 Petal
批量整理所有 ContentGroup
全局 folder 复杂管理
```

### 2.2 Scope 决定默认 root folder

```text
Home / global context
  workspace root folder

Project context
  current project root folder

Note context
  current note root folder
```

如果当前页面属于某个 note，就优先打开 note root。
如果只在 project 页面，就打开 project root。
如果不在 project / note 内，就打开 workspace root。

### 2.3 操作要少而明确

浮在表面的按钮只保留必要项：

```text
New group
Open Gallery
Close
optional Search / Filter placeholder
```

其它操作进入：

```text
group row context menu
folder row context menu
drag/drop
```

## 4. Task 1: Scope Resolver

**Files:**

- Modify: `client/src/pages/GroupGallery/groupGalleryData.ts`
- Modify: `client/src/pages/Notes/canvasEngine/panels/ContentGroupPanel.tsx`

- [ ] **Step 1: 定义 RailScope**

建议 UI 内部使用：

```ts
type RailScope =
  | { kind: 'workspace'; workspaceId: string | null }
  | { kind: 'project'; projectId: string }
  | { kind: 'note'; noteId: string; projectId?: string | null };
```

如果当前应用没有 workspace id，就使用稳定 local workspace scope。

- [ ] **Step 2: Rail 打开时 resolve root folder**

规则：

```text
note page
  -> note root folder

project page
  -> project root folder

global / home
  -> workspace root folder
```

如果 root folder 不存在，调用 8.6.26 的 ensure helper。

- [ ] **Step 3: 当前 folder 状态**

Rail 需要内部状态：

```text

expandedFolderIds
```

第一版可以：

```text

```

不强制持久化 active group；如果已有 metadata 槽位可安全写入，可以持久化 note-level active group。

## 11. 验收标准

### 11.1 Scope 验收

- [ ] 在 note 页面打开 Rail，默认进入该 note root folder。
- [ ] 在 project 页面打开 Rail，默认进入该 project root folder。
- [ ] 在全局入口打开 Rail，默认进入 workspace root folder。
- [ ] root 不存在时能自动 seed，不崩溃。

### 11.2 Rail 角色验收

- [ ] Rail 没有完整 topic / role / summary 表单。
- [ ] Rail 没有 Petal 编辑器。
- [ ] Rail 只显示轻量 folder/group 列表。
- [ ] 点击 group row 可以设置 active group。
- [ ] active group 有清晰但安静的视觉指示。

### 11.3 Intake 验收

- [ ] Draft Range 可以 drop 到 group row。
- [ ] Label 可以 drop 到 group row。
- [ ] Block item 可以 drop 到 group row。
- [ ] Drop 到 new group area 可以创建 group 并加入 member。
- [ ] 有 active group 时，可以通过菜单把当前 Draft Range 加入 active group。
- [ ] 所有 intake 都不移动原文。

### 11.4 导航验收

- [ ] Rail 可以打开 Group Gallery。
- [ ] Rail 可以打开某个 group 的 Single Editor。
- [ ] 从 Editor / Gallery 返回不会丢当前 note 操作上下文。

## 12. 手动测试清单

1. 打开一个 note，点击右侧 Groups 入口。
2. 确认 Rail 显示的是该 note 的 groups，而不是全局混合列表。
3. 在 Rail 里新建 group。
4. 选中正文一段文字，拖 Draft Range handle 到新 group row。
5. 确认 group member count 增加。
6. 创建一个 Label，拖 Label badge 到同一个 group。
7. 确认原文 label 没消失。
8. 点击 group row，确认 active group 指示出现。
9. 右键 group row，试 `Open editor` 和 `Add current selection`。
10. 点击 Rail 顶部 Gallery icon，确认进入 Gallery。
11. 回到 note，确认 Rail 仍能打开同一 scope。
12. 尝试在 system root folder 上 delete，确认禁用。
