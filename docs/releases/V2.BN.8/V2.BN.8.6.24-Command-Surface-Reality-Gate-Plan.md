# V2.BN.8.6.24 Command Surface Reality Gate Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 把 ContentGroup 相关按钮、右键菜单、浮层入口和占位动作清点并诚实化，先让用户看到的每一个入口都能解释清楚。

**Architecture:** 本版本不做全局拖拽、不改 GroupFolder 数据模型、不重写 Single Editor。它只处理 command surface 的可见性、命名、启用状态和动作边界，并生成一份按钮/菜单现实清单，作为 8.6.25 拖拽地基和 8.6.31 视觉对齐的前置 gate。

**Tech Stack:** React, TypeScript, CSS Modules, Vite, existing Canvas Engine command surface, ContentGroup services, GroupGallery pages.

---

## 1. 背景

8.6.23 把 ContentGroup 的三层界面拆出来了，但界面上仍然有一批“看起来能做很多事”的按钮：

- 有些按钮是真可用。
- 有些按钮只是打开 Rail 或 Editor。
- 有些按钮只写了 disabled。
- 有些按钮是未来功能，但现在摆在表面。
- 有些动作名称不符合用户心智，例如内部叫 annotation，外部更应该叫 Label。

这会造成两个问题：

1. 用户以为功能已成熟，点击后发现只是半成品。
2. 后续 8.6.25 拖拽、8.6.26 Folder、8.6.28 Editor 都会继续继承这些不诚实入口。

所以 8.6.24 是一个 reality gate，不是视觉 polish。

## 2. 本版本原则

### 2.1 操作分级

所有 ContentGroup 相关入口必须归入以下状态之一：

```text
ready
  当前版本可用，点击后能完成明确写回或明确导航。

opens_surface
  当前版本只负责打开 Rail / Gallery / Editor，不假装已经完成写入。

disabled_with_reason
  当前版本不能用，但用户能看到合理禁用原因。

hidden_until_ready
  当前版本不应该出现在表面，避免制造噪音。

deferred
  已记录到后续版本，不在当前 UI 暴露。
```

### 2.2 三种操作面

```text
浮在表面的按钮
  只放高频、明确、不依赖复杂上下文的操作。

右键菜单
  放对象上下文操作，例如 Label、Create group、Add to group、Open editor、Archive、Delete。

拖拽
  放空间整理操作，例如 Draft Range / Label / Block 进入 group。
```

### 2.3 外部语言

用户可见语言：

```text
Label
Group
Content group
Open editor
Create group
Add to group
```

内部语言仍可保留：

```text
annotation
content_group
draft_range
```

用户界面里不要要求用户理解 annotation / draft payload / source range 这些内部词。

## 5. Task 2: 正文选区右键菜单诚实化

**Files:**

- Modify: `client/src/pages/Notes/canvasEngine/commandSurfaceService.ts`
- Modify: `client/src/pages/Notes/canvasEngine/layers/NoteWritingSurfaceLayer.tsx`

- [ ] **Step 1: 把用户可见 annotation 文案改成 Label**

要求：

```text
Annotate -> Label
Add annotation -> Label
Add child label -> 不在正文选区菜单显示
```

内部函数名可以不改，但 UI 文案必须是 `Label`。

- [ ] **Step 2: 分开 Create group 和 Add to group**

正文选区右键菜单里只显示符合当前状态的动作：

```text
没有 active group:
  Create group

有 active group:
  Add to group
  Create group
```

`Add to group` 的目标必须是 active group。如果没有 active group，不显示 `Add to group`，避免用户不知道加到哪里。

- [ ] **Step 3: 右键菜单中的 Add to group 不能只“假装写入”**

如果当前已有 active group，`Add to group` 应直接把当前 item 加入 active group。

如果暂时拿不到 current item，动作必须禁用并说明：

```text
Select text, label, or block first.
```

不能只打开 Rail 然后让用户猜下一步。

- [ ] **Step 4: 保留 Open Groups Rail 作为独立动作**

如果需要只打开侧栏，动作名必须是：

```text
Open Groups
```

而不是 `Add to group`。

## 10. 合格标准

8.6.24 合格意味着：

- 用户看见的按钮都有清楚目标。
- `Add selected` 不再作为无目标顶部大按钮存在。
- `Add to group` 不再只是打开 Rail。
- 单段普通选区不被大型 toolbar 打扰。
- 半成品按钮被隐藏或禁用并说明原因。
- 右键菜单成为 ContentGroup intake 的主入口之一。
- 8.6.25 可以在清爽的 command surface 上继续做拖拽地基。
