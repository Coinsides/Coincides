# V2.BN.8.6.30 TextFlow Drag-Reorder / Insert Safety Gate Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 为“把 Draft Range / Label 拖入正文改变位置”建立第一版安全门：先支持 copy 插入，再记录 destructive move / reorder 的风险边界。

**Architecture:** 8.6.29 只在空白处生成 block；8.6.30 进入更危险的 TextFlow 原文编辑层。第一版必须默认 copy insertion，不默认删除源文字；同一 TextBlock 内的 move / reorder 先做安全判断和禁用提示，避免 annotation/content range offset 被静默破坏。

**Tech Stack:** React, TypeScript, Vite, Canvas Engine TextBlockProjection, TextFlow editor service, ContentGroup drag payload, selection draft, history guard.

---

## 1. 本版本边界

本版本做：

```text
Draft Range / Label -> 拖入已有 TextBlock 正文 -> copy 插入到 caret 附近
TextBlock 内部 target resolver -> unit id + offset
source range / preview safety gate -> 不静默破坏已有 ContentRange
```

本版本不做：

- 默认 destructive move；
- 复杂同块重排编辑器；
- 跨 block 的精确 move；
- table / image / formula block 内部 drag；
- AI 自动改写 TextFlow；
- 完整 offset rebase 引擎。

## 3. 安全原则

必须写死三条：

```text
1. 拖入正文第一版默认 copy，不删除 source。
2. 同一 TextBlock 内 move / reorder 默认不开放 destructive move。
3. 任何会改变已有 source range offset 的操作，都必须至少触发 stale 标记或明确 no-op。
```

用户心智：

```text
拖到空白处 = 生成新 block
拖到正文里 = 插入一份内容
移动原文位置 = 未来需要显式 move 模式或更强 undo
```

## 5. Task 2: TextFlow 插入 helper

**Files:**

- Modify: `client/src/pages/Notes/canvasEngine/textUnitEditorService.ts`
- Test: `client/scripts/canvasEngineModelContractCheck.ts`

- [ ] **Step 1: 增加显式 copy insertion helper**

在 `textUnitEditorService.ts` 增加：

```ts
export function insertPlainTextIntoTextFlow(
  flow: TextBlockContentV1,
  targetUnitId: string,
  offset: number,
  insertedText: string,
): TextBlockContentV1 {
  return pasteTextIntoTextFlow(flow, targetUnitId, offset, insertedText);
}
```

这个 helper 是语义别名：它明确表示 drag insertion 是 copy insert，不是 paste event，也不是 move。

## 6. Task 3: TextBlockProjection drop target resolver

**Files:**

- Modify: `client/src/pages/Notes/canvasEngine/blocks/TextBlockProjection.tsx`
- Modify: `client/src/pages/Notes/NoteDetail.module.css`

- [ ] **Step 1: 给 text unit body 增加 drop target**

Text unit DOM 需要在 drag over 时提供：

```text
current text_unit_id
approximate caret offset
drop preview caret
```

第一版可以使用 `document.caretRangeFromPoint` / `document.caretPositionFromPoint` 的浏览器能力；如果拿不到准确 offset，就 fallback 到 unit 末尾。

- [ ] **Step 2: 只接收支持的 payload**

规则：

```text
draft_range payload -> accept
label payload -> accept
block payload -> reject unless text_preview exists
unknown payload -> reject
```

Reject 时不阻止默认行为，不写入 TextFlow。

- [ ] **Step 3: drop 时调用 onTextFlowChange / onSave**

Drop 成功后：

```text
read payload
plainTextFromContentGroupDragPayload(payload)
insertPlainTextIntoTextFlow(currentFlow, targetUnitId, offset, text)
emitFlowChange(nextFlow)
save silently or follow existing text editing save path
focus target block
```

验收：拖入正文后内容能立即显示，刷新后仍存在。

## 7. Task 4: NoteWritingSurfaceLayer 安全门

**Files:**

- Modify: `client/src/pages/Notes/canvasEngine/layers/NoteWritingSurfaceLayer.tsx`
- Modify: `client/src/pages/Notes/canvasEngine/historyService.ts`
- Modify: `client/src/pages/Notes/canvasEngine/hooks/usePlacementHistory.ts`

- [ ] **Step 1: 区分 copy insert 与 move**

第一版固定写入：

```text
operation: copy_insert
source_deleted: false
```

如果 payload 表示 same TextBlock source，仍然只 copy，不 move。

- [ ] **Step 2: destructive move 入口禁用**

如果 UI 中出现“move source”或“reorder source”入口，本版本必须禁用并显示：

```text
Moving original text is not enabled yet.
```

不允许半成品按钮执行删除源内容。

- [ ] **Step 3: 记录最小历史条目**

TextFlow 插入成功后，至少能被现有保存流程恢复；如果已有 undo 栈支持 TextFlow 变化，则写入：

```text
type: textFlowChanged
blockId
beforeTextFlow
afterTextFlow
reason: drag_insert
```

如果当前 undo 栈没有 TextFlow change 类型，本版本 patch note 必须记录“TextFlow drag insert uses save history only; full undo is deferred”，不能假装已经支持完整 undo。

## 8. Task 5: ContentRange / preview 保护

**Files:**

- Modify: `client/src/pages/Notes/canvasEngine/contentGroupService.ts`
- Modify: `docs/contracts/TextFlow-Contract.md`

- [ ] **Step 1: 明确第一版不做 offset rebase**

因为本版本默认 copy insert，不删除 source，所以 source range 不应移动。

但 target TextBlock 如果已有 annotation/content range，插入文字可能改变后续 offset。第一版保护策略：

```text
如果插入位置所在 block 存在 active AnnotationTruth / ContentGroup member range:
  标记相关 preview 为 stale 或显示需要刷新。
如果当前代码无法追踪全部引用:
  在 patch note 写明 stale coverage limit。
```

- [ ] **Step 2: 合同文档同步**

在 `TextFlow-Contract.md` 写清：

```text
Drag into TextFlow first supports copy insertion.
Destructive move/reorder requires a later offset rebase or stronger undo gate.
ContentGroup preview cache is not source truth.
```
