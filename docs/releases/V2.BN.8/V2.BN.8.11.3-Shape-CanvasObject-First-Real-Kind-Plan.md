# V2.BN.8.11.3 Shape CanvasObject First Real Kind - Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:test-driven-development or superpowers:executing-plans. Follow the tasks in order. This plan is intentionally detailed because it is the first user-visible consumer of the kind-general CanvasObject pipeline.

**Goal:** 让 `shape` 成为第一种真正用户可见的普通 CanvasObject，证明 8.11.1.2/8.11.1.3 建好的 generic pipeline 可以承载 page-frame / block 之外的新对象。

**Architecture:** 通用 `canvas_objects` + `canvas_placements` 核心表继续作为身份与几何真相；`shape` v1 不新建 extension 表，使用 `metadata.shape_type` 和默认视觉样式承载最小图形语义。active editor 必须开始消费 persisted generic objects。

**Tech Stack:** React + TypeScript client canvas engine, Express route/service, SQLite migrations already in place, Node test runner, existing canvas runtime/model contract scripts.

---

## 0. Scope Fence

### 0.1 This Version Does

- 发布 `kind='shape'` 的最小真实产品路径。
- 支持纯对象：`backing='none'`，`objectClass='pure'`。
- 支持最小形状：`rectangle`、`ellipse`。
- 支持最小操作：blank canvas context menu 新建、select、move、resize、delete、reload 后仍存在。
- 支持 AI-readable layout：AI-tree 能看到 shape 的 `kind`、bbox / placement，但不把 shape 当 content truth。
- 支持 active editor 数据流消费 generic persisted object：repository normalization、adapter state、runtime model injection、rendering layer。

### 0.2 This Version Does Not Do

- 不做 shape 填字。
- 不做 block-backed shape。
- 不做 sticky note。
- 不做 visual connector。
- 不做 image / asset。
- 不做 table。
- 不做 ContentGroup projection。
- 不做 Relation runtime。
- 不做 shape typed extension table。
- 不做完整 style inspector。
- 不做 top bar / ribbon。
- 不做完整 context menu system。
- 不做 undo/redo 历史栈。
- 不做 multi-select。
- 不做 rotate 交互。

### 0.3 Why Shape First

`shape` 是第一块真正的“普通画布对象”试金石：

- 它没有 TextFlow truth。
- 它没有 ContentMount。
- 它没有 PageFrame collection 语义。
- 它只依赖 CanvasObject identity + CanvasPlacement geometry。

如果 shape 跑顺，就说明 generic pipeline 不再只是 page-frame / block 两个特例。

## 1. Current Gaps To Close

### 1.1 Generic Objects Persist, But Active Editor Does Not Consume Them Yet

8.11.1.2/8.11.1.3 已经补了 generic save/delete 和 runtime 最小注入能力，但 active editor 真实 UI 数据流还主要消费：

- `pageFrameCollection`
- `blockLayouts`

8.11.3 必须把 persisted generic arrays 正式接入：

- `canvasObjects`
- `canvasPlacements`
- `contentMounts`

否则 shape 即使存进数据库，也不会在真实笔记页面里稳定显示。

### 1.2 Server Returns Snake Case, Client Runtime Expects Camel Case

后端 read path 返回的对象大概率是 snake_case：

- `object_id`
- `canvas_id`
- `object_class`
- `placement_id`
- `frame_id`
- `z_index`
- `boundary_role`
- `visibility_state`
- `render_visibility`

前端 runtime types 期望 camelCase：

- `objectId`
- `canvasId`
- `objectClass`
- `placementId`
- `frameId`
- `zIndex`
- `boundaryRole`
- `visibilityState`
- `renderVisibility`

8.11.3 必须在 repository 层 normalize，不能让 snake/camel 混进渲染层。

### 1.3 Existing Shape Seed Is Runtime-Only

`shapeProjectionService.ts` 已经有 seed helper，但它还不是用户真实路径：

- 可以创建 runtime shape object。
- 可以生成 placement。
- 可以生成 visual style。
- 但没有 UI entry。
- 没有 active editor persisted path。
- 没有 reload round-trip 证明。

8.11.3 的任务不是重写它，而是把它接入真实管线。

### 1.4 Rendering Layer Has PageFrame And Block, But No Generic Shape Layer

`NoteWritingSurfaceLayer.tsx` 目前主要渲染：

- PageFrame / PageStack
- Paragraph block projection

8.11.3 要新增轻量 shape rendering，而不是把所有对象逻辑继续塞进 page-frame/block 分支。

## 2. Data Contract

### 2.1 Shape CanvasObject

Server payload v1:

```ts
{
  kind: "shape",
  backing: "none",
  object_class: "pure",
  status: "active",
  source?: {
    type: "user_created" | "runtime_seed" | "shape_object"
  },
  metadata: {
    shape_type: "rectangle" | "ellipse"
  },
  placement: {
    placement_id: string,
    x: number,
    y: number,
    width: number,
    height: number,
    rotation: number,
    surface: "canvas",
    frame_id?: string | null,
    boundary_role?: "none",
    z_index: number,
    visibility_state?: "visible",
    render_visibility?: "visible",
    export_role?: "default",
    ai_visibility?: "readable",
    metadata?: Record<string, unknown>
  }
}
```

Client normalized runtime shape:

```ts
{
  objectId: string,
  canvasId: string,
  kind: "shape",
  backing: "none",
  objectClass: "pure",
  status: "active",
  source: { type: "user_created" },
  metadata: {
    shapeType: "rectangle" | "ellipse"
  }
}
```

Client placement:

```ts
{
  placementId: string,
  objectId: string,
  x: number,
  y: number,
  width: number,
  height: number,
  rotation: number,
  surface: "canvas",
  frameId: null,
  boundaryRole: "none",
  zIndex: number,
  visibilityState: "visible",
  renderVisibility: "visible",
  exportRole: "default",
  aiVisibility: "readable",
  metadata: {}
}
```

### 2.2 Metadata Naming Rule

Server payload may persist snake_case metadata:

- `shape_type`

Client runtime should expose camelCase helper fields only after normalization:

- `shapeType`

Rendering code can tolerate both during transition, but new writes should be consistent.

### 2.3 No Extension Table In 8.11.3

`shape` v1 has no typed extension table. Reason:

- It is the simplest pure object.
- Shape type can live safely in object metadata for v1.
- Style system is coming in 8.11.5.
- Typed extension tables are more valuable for connector / table / asset-backed objects.

If implementation discovers metadata is not enough, pause and record an open issue instead of silently adding a larger schema migration.

## 6. Risk Notes

### 6.1 Generic State Duplication

Risk: page-frame/block objects appear twice if generic arrays are blindly merged with existing specialized arrays.

Guard:

- Dedupe by `objectId`.
- Treat `page_frame` and `paragraph_block_projection` as already consumed by specialized current views unless runtime builder already dedupes.

### 6.2 Snake/Camel Leakage

Risk: UI components start reading snake_case server fields.

Guard:

- Repository owns normalization.
- Component layer only reads camelCase.
- Boundary check should search for `object_id` / `placement_id` inside layer files and fail unless explicitly allowed.

### 6.3 Shape Style Drift

Risk: 8.11.3 accidentally becomes style-system work.

Guard:

- Use fixed default CSS.
- Store only `shape_type`.
- Defer style preset/editor to 8.11.5.

### 6.4 Context Menu Bloat

Risk: blank canvas menu becomes a dumping ground.

Guard:

- Add only two shape actions.
- Do not design global menu taxonomy in this version.

### 6.5 AI Tree Overclaim

Risk: AI-tree pretends shape has semantic knowledge.

Guard:

- Shape AI node only says: this object exists here with this kind and bbox.
- It does not infer meaning.
- It does not become Relation.
