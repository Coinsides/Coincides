# V2.BN.8.9.1 PageFrame Visible Contract And Primary Focus Patch Note

Date: 2026-06-26

Status: completed scoped engineering pass and verified.

## Summary

8.9.1 把 8.8 里已经存在的 PageFrame seed 往前推进了一步：PageFrame 不再只是视觉上的页面边界，也开始成为 AI Tree 和浏览器 DOM 都能稳定识别的特殊 CanvasObject。

本次补丁的重点不是新增多页、标尺、页眉页脚或导出系统，而是先把第一张 primary PageFrame 的可读契约打稳：

```text
PageFrame outer bbox = CanvasObject placement area
PageFrame content bbox = text / export / AI-readable writing area
```

## Completed

- Extended `CanvasAIReadableNode` with `contentBbox`.
- Added `pageFrameRef` to PageFrame AI Tree nodes, exposing:
  - `role`;
  - `exportable`;
  - `contentInset`;
  - `primary`.
- Updated `canvasAiTreeService.ts` so PageFrame nodes derive `contentBbox` from `PageFrameExtension`.
- Updated `engineModel.ts` so AI Tree snapshot generation receives `pageFrameExtensions` and `primaryPageFrameId`.
- Wired Page Mode runtime viewport through `createPageModeFocusViewport`, so Page Mode is explicitly focused on the primary PageFrame content area.
- Added stable PageFrame DOM markers to `NoteWritingSurfaceLayer.tsx`:
  - `data-canvas-object-id`;
  - `data-page-frame-id`;
  - `data-page-frame-role`;
  - `data-page-frame-primary`;
  - `data-page-frame-exportable`.
- Added model-contract checks for PageFrame AI Tree content bbox and primary/exportable metadata.
- Updated runtime boundary checks so the PageFrame visible contract cannot disappear silently.
- Updated the Canvas Engine implementation checklist.

## Engineering Boundary

- PageFrame remains derived runtime state in 8.9.1.
- AI Tree remains a derived read model, not durable truth.
- `contentBbox` is not a second content truth; it is a layout-readable content area.
- The visible DOM markers are smoke/debug/agent hooks, not user-facing UI text.
- Page Mode focus is now explicit, but multi PageFrame focus selection is still deferred to 8.9.2.

## Not Included

- No multi PageFrame insertion / delete / set-primary UI.
- No PageFrame durable persistence cutover.
- No ruler / margin guide / snap wall.
- No header / footer / page number slot model.
- No PageFrame template / background / style system.
- No export preview refinement.
- No ContentGroup projection.
- No Relation runtime.
- No Agent write path.

## Remaining Risks

- The runtime still has only one visible PageFrame.
- PageFrame persistence is not solved; 8.9.2 must decide the first safe persistence boundary.
- DOM markers are present, but browser/manual smoke for visible PageFrame behavior has not yet been run in this patch.
- Header/footer/page number/template/export behavior remains design-and-implementation work for later 8.9.x versions.

## Next
