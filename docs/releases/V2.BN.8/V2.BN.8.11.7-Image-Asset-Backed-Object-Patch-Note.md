# V2.BN.8.11.7 Image / Asset-Backed CanvasObject Patch Note

> **Status:** implemented
> **Date:** 2026-06-29
> **Scope:** Structured Object Family / image object / canvas asset storage

## 1. 本次完成了什么

8.11.7 把图片推进成第一类 `asset-backed CanvasObject`。它不再只是未来媒体系统的愿望，而是已经能通过通用 CanvasObject 管线创建、保存、读回、渲染，并进入 AI-readable layout。

边界如下：

```text
CanvasObject.kind = image
CanvasObject.backing = asset
CanvasObject.objectClass = media
ImageObject.assetId -> canvas asset
ImageObject.caption / altText -> readable metadata
```

它不是 TextFlow 内容真相，不是 SourceArtifact，也不触发 OCR / parsing / document import。

## 2. 工程改动

- 新增 `canvas_assets` 表，用于保存 canvas-local 图片资产元数据和受控本地 storage key。
- 新增 `image_object_extensions` 表，用于保存 image object 与 asset 的引用、fit、caption、alt text、natural size 和 metadata。
- 新增 canvas asset 服务和 `/api/canvas-assets` 路由，支持图片上传、资产元数据读取和鉴权 blob 读取。
- `saveCanvasObject` 新增 `kind='image'` handler，图片对象继续走通用 `canvas_objects` / `canvas_placements` 管线，扩展信息进入 typed sidecar。
- `getNoteCanvasPersistence()` 现在返回 `imageObjects`，并携带安全 asset metadata，不暴露本地绝对路径。
- 客户端新增 `canvasAssetRepository.ts`、`imageObjectService.ts` 和 `ImageObjectLayer.tsx`。
- Canvas/PageFrame 右键菜单新增最小 `Image` 入口：选择文件后先上传 asset，再创建 image CanvasObject。
- 图片对象支持选择、移动、缩放、删除、caption / alt text 编辑，以及 contain / cover 切换。
- AI-readable tree 新增 image readout：bbox、asset id、filename、mime、natural size、fit、caption、alt text。
- 修复浏览器 smoke 中发现的 blob 鉴权问题：图片不直接用裸 `/api/.../blob` 地址，而是通过 API helper 带鉴权取 blob，再生成 `blob:` URL 渲染。

## 3. 没有做什么

- 没有做 OCR。
- 没有做 MinerU / document layout parsing。
- 没有做 SourceArtifact / SourceAnchor。
- 没有做图片裁剪、旋转、滤镜、标注或局部框选。
- 没有做 inline image in TextFlow。
- 没有做图片作为 ContentGroup member 的完整复用 UI。
- 没有做 asset library / media library / 工程包 export。
- 没有做 remote URL image embed。

## 5. 剩余风险

- 当前 blob 文件存储是本地 v1，后续需要 asset garbage collection / library / export 打包策略。
- 当前图片 UI 是最小可用，不是成品级媒体编辑器。
- Object inspector 还没做，用户暂时无法统一查看 kind / backing / asset ref / AI-readable 状态。
- 图片与 ContentGroup、Source、工程包导出的关系仍需在后续版本单独设计。
