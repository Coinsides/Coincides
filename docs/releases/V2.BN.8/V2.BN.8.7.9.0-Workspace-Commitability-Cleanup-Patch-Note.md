## Cleanup Rules

- No `git reset --hard`.
- No broad `git clean`.
- No broad recursive delete from the repo root.
- No `git add .`.
- No staging by top-level folder without checking the actual paths.
- No deletion of untracked docs or assets merely because they are untracked.
- No line-ending-only cleanup pass.
- Prefer pathspec staging by coherent version boundary.

## Suggested Execution Order

1. Create this patch note.
2. Run a fresh `git status --short` and save the classification result into the final cleanup report if needed.
3. Identify true generated artifacts, if any.
4. Delete only verified generated artifacts with narrow paths.
5. Run `git diff --check`.
6. Stage the first coherent commit boundary with explicit paths.
7. Run the relevant verification commands for that boundary.
8. Repeat for the next boundary.
9. Only after the workspace is readable, run the real V2.BN.8.7.9 closure gate.

## Acceptance Criteria

- A future reader can tell why the workspace was dirty.
- The dirty set is separated into product code, docs, design evidence, prior foundation work, and generated artifacts.
- Cleanup does not destroy uncommitted real work.
- The next agent can stage by boundary without guessing.
- V2.BN.8.7.9 closure can run against a workspace that is readable and committable.
