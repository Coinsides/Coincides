# V2.BN.8.7.2 GroupFolder Legacy Cleanup Patch Note

status: implemented and verified
date: 2026-06-22

## Scope

This patch cleans up two pieces of legacy residue left after the V2.BN.8.7.2 GroupFolder entity cutover:

- stale duplicate system roots in `group_folders`;
- old `notes.metadata.canvas_engine_group_folders_v1` snapshots after a successful entity import.

Product rule for this patch:

- Coincides is not in production.
- The current local accounts and notes are test data.
- Old test-era compatibility data should be removed instead of preserved as hidden fallback truth.

## Implemented

- Added a server-side cleanup gate when deterministic GroupFolder roots are ensured.
- The server now deletes stale duplicate system roots for the same workspace, project, or note scope.
- Added a regression test proving an old `group-folder-root-workspace-` / `Workspace groups` root is physically removed once the deterministic workspace root is ensured.
- Updated the client GroupFolder repository so legacy folder metadata is stripped from a note after the legacy folder cutover path runs.
- The strip runs after import, and also handles the case where entity folders are already present but the old metadata key is still on the note.
- Added a runtime boundary check so the repository cannot silently return to leaving legacy folder metadata behind.
- Tracked the unrelated Vite large chunk / dynamic import warning in `Open-Issue-And-Brainstorm-Checklist.md` as a deferred frontend performance cleanup.
