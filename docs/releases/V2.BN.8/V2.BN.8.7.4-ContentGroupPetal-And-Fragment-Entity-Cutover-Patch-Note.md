# V2.BN.8.7.4 ContentGroupPetal And Fragment Entity Cutover Patch Note

Date: 2026-06-22

## Summary

V2.BN.8.7.4 moves ContentGroup Fragment and Petal persistence out of `content_groups.fragments_json` / `content_groups.petals_json` and into group-owned child entity tables.

The client-facing DTO remains stable:

```text
ContentGroupV1.fragments[]
ContentGroupV1.petals[]
```

The active database truth is now:

```text
content_group_fragments
content_group_petals
content_group_petal_fragments
```

## Completed

- Added migration `034_v2_content_group_petals`.
- Added `content_group_fragments`.
- Added `content_group_petals`.
- Added `content_group_petal_fragments`.
- Backfilled legacy Fragment / Petal JSON into entity rows.
- Hydrated existing `ContentGroupV1.fragments[]` and `ContentGroupV1.petals[]` from entity rows.
- Cut normal save paths over to entity-backed Fragment / Petal writes.
- Cleared active `fragments_json` and `petals_json` after entity writes.
- Preserved source text, labels, blocks, ContentGroupMember rows, and source references during Petal / Fragment edits.
- Changed client Petal deletion to hard DTO removal while keeping `softDeleteContentGroupPetal` as a compatibility wrapper.
- Added model-contract coverage for Petal hard removal preserving member/source truth.
- Added runtime-boundary coverage so client runtime files do not depend on Petal / Fragment database field names.
