# V2.BN.8.6.26 GroupFolder Resource Manager Foundation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:executing-plans` to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 把 GroupFolder 做成 ContentGroup Editor 的资源目录地基，让 ContentGroup 的位置、浏览边界、project / note root、未来 relation view 边界都由 folder path 承担，而不是继续依赖模糊的 depth、临时 scope 或 note metadata 拼接。

**Architecture:** GroupFolder 是组织目录，不是 ContentGroup，不是 Project / Note，也不是 relation truth。Project / Note 可以拥有系统 root GroupFolder；用户和 AI 可以在 root 下创建普通 GroupFolder；ContentGroup 通过 folder placement 被放入目录。第一版只要求一个 primary folder placement，先不做 pin、shortcut、link folder，也不做跨项目高级 relation view。

**Tech Stack:** React, TypeScript, Canvas Engine runtime metadata, ContentGroup services, GroupGallery data helpers, local note metadata persistence.

---

## 1. 背景

15:10 会议记录里已经确定：

```text
ContentGroup = 内容包
GroupFolder = 资源管理器 / 摆放目录
Petal = ContentGroup 内部局部角色
```

我们不能再让 ContentGroup 自己承担：

```text
scope
depth
folder
topic hierarchy
relation boundary
gallery browsing path
```

这些职责必须交给 GroupFolder。

当前 8.6.11 / 8.6.12 已经有 `GroupFolderV1` seed，但它仍偏 note-side runtime metadata，不足以支撑一个真正的 Group Gallery 和 Rail v2。因此 8.6.26 的目标是把 GroupFolder 的数据规则、根目录规则、路径规则和安全操作规则补齐。

## 2. 核心定义

### 2.1 GroupFolder

```text
GroupFolder
  组织 ContentGroup 的目录对象
  决定浏览路径
  派生内容层级
  提供未来 relation view 的局部边界
```

它不回答：

```text
这个内容是什么意思？
这个定义和哪个定理有 relation？
这个 range 是 concept name 还是 description？
```

这些属于 ContentGroup、member、Petal、未来 relation。

### 2.2 System Root Folder

每个 Project / Note 都应该有系统 root folder：

```text
Project
  Project root GroupFolder

Note
  Note root GroupFolder
```

规则：

```text
root folder 跟随 Project / Note 生命周期
root folder 用户不能删除
root folder 可以包含普通 folder 和 ContentGroup
```

### 2.3 Folder Path 替代 Depth

旧想法：

```text
depth 0 = project
depth 1 = note
depth 2+ = content
```

新规则：

```text
ContentGroup.folder_id
  -> GroupFolder.parent chain
  -> derived path
  -> derived depth
```

ContentGroup 不再把 `depth` 作为主要定位字段。

```text

```

- [ ] **Step 3: Move folder**


```text

```

先不要做“删除 folder 时自动移动所有 group”，避免误伤。

## 11. 验收标准

### 11.1 数据验收

- [ ] 新建 project 后有 project root GroupFolder。
- [ ] 新建 note 后有 note root GroupFolder。
- [ ] system root folder 不能被删除。
- [ ] user folder 可以在当前 root 下创建。
- [ ] user folder 可以 rename。
- [ ] empty user folder 可以删除或 archive。
- [ ] non-empty user folder 删除被阻止。
- [ ] ContentGroup 新建后有合法 folder placement。
- [ ] ContentGroup move folder 后 members 不变。
- [ ] 刷新后 folder tree 和 group placement 仍然存在。

### 11.2 UI 验收

- [ ] Group Gallery 左侧 folder tree 来自真实 folder model。
- [ ] 当前 folder 下先显示 folders，再显示 ContentGroups。
- [ ] Topic / Role view 不改变 folder placement。
- [ ] orphan group 不会消失，至少能在可理解位置显示。

### 11.3 安全验收

- [ ] 不允许 folder 循环。
- [ ] 不允许 move folder 到自己的 descendant。
- [ ] 不允许 delete system root。
- [ ] 删除 folder 不会让 group 静默丢失。
