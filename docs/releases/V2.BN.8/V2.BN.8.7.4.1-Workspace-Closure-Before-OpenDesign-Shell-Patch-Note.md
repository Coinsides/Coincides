# V2.BN.8.7.4.1 Workspace Closure Before OpenDesign Shell Patch Note

## Decision

Before moving into the OpenDesign visual shell work, do a small workspace-closure patch.

This is not a visual patch and not a broad refactor. The goal is to make the current V2.BN.8.7 ContentGroup System maturity work explainable, recoverable, and ready for the next UI pass.

The immediate order is:

```text
1. Close and document the current dirty workspace.
2. Preserve the V2.BN.8.7.1-8.7.4 entity-cutover work.

4. Only then start OpenDesign shell parity work.
```

## Why This Patch Exists

The current workspace contains several layers of work at once:

- V2.BN.8.7.1 ContentGroup entity cutover.
- V2.BN.8.7.2 GroupFolder / placement entity cutover.
- V2.BN.8.7.3 ContentGroupMember entity cutover.
- V2.BN.8.7.4 ContentGroupPetal / Fragment entity cutover.
- The follow-up Single Editor Petal save patch.
- Many older V2.BN.8.6 and V2.BN.8.7 documents that are still untracked locally.
- The OpenDesign shell direction, which has not yet started as the active implementation pass.

If the OpenDesign shell work starts before this state is closed, visual changes, entity work, browser smoke data, and documentation drift will become hard to separate.

## Cleanup Principle

This cleanup is a closure pass, not a deletion pass.

Rules:

- Do not run destructive reset / checkout / clean commands.
- Do not delete untracked files just because they are untracked.
- Do not revert Henry's or earlier local work unless the specific file is proven unrelated and Henry explicitly confirms.
- Do not touch GitHub; local workspace remains source of truth.
- Do not stage or commit unless Henry explicitly asks.
- Do not start OpenDesign shell implementation during this patch.
- Do not do database migration redesign, CanvasObject work, relation runtime, GraphRAG, or data model expansion.
