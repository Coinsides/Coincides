# V2.BN.8.6.6 TextUnitGroup And AnnotationSet Editor Foundation Patch Note

Status: ready for Henry manual test

Date: 2026-06-17

## What Changed

V2.BN.8.6.6 closes the main organization gap left after annotation editing:

```text
TextUnitGroup
  writing-layer grouping of rows

AnnotationSet
  semantic organization of confirmed labels
```

The important split is preserved:

- `TextUnitGroup` helps the writing layer keep several rows together.
- `AnnotationTruth` remains the confirmed semantic label.
- `AnnotationSet` groups several confirmed labels for organization, AI reading projection, and future CompositeEndpoint use.

## Implemented

- Added TextUnitGroup editor service helpers:
  - create group from selected TextUnits;
  - rename group;
  - resolve grouped text;
  - soft delete / ungroup group;
  - find active groups for a row.
- Added row selection from the TextUnit gutter and a quiet group rail beside grouped rows.
- Added TextUnitGroup context commands for grouping and ungrouping rows.
- Extended AnnotationSet data with:
  - `description`;
  - `set_kind`;
  - `visual_style.color_token`;
  - ordered member ids.
- Added AnnotationSet editor service helpers:
  - normalize;
  - rename;
  - update description;
  - update kind;
  - update color;
  - replace members;
  - reorder members;
  - add / remove member;
  - soft delete.
- Added Annotation Organizer panel:
  - create set from selected labels;
  - edit set label, kind, description, and color;
  - add selected labels to a set;
  - reorder members;
  - remove members;
  - delete a set without deleting labels.
- Added context-menu paths to open the label organizer or create a set from a label.
- Upgraded reading projection so sets print member labels, previews, child summaries, and set kind.
- Normalized AnnotationSet persistence in the note metadata adapter.
- Synced contracts, roadmap references, changelog, and open issue handoff notes.

## Black-Screen Patch - 2026-06-17

Status: patched and browser-harness verified.

Root cause:

- Annotation Organizer read `event.currentTarget.value` inside React state updater callbacks for set label / description drafts.
- The updater may run after the event handler returns, at which point `event.currentTarget` is `null`.
- Editing the AnnotationSet description therefore threw `Cannot read properties of null (reading 'value')` inside `AnnotationOrganizerPanel`, unmounted the React tree, and produced the black-screen state.

Fix:

- Capture `event.currentTarget.value` synchronously in the input / textarea `onChange` handler before calling the state updater.
- Applied to both AnnotationSet label draft and description draft input paths.

Browser-harness verification after patch:

- Typing into AnnotationSet description no longer black-screens.
- Description blur saves through the API.
- Set kind changed to `all_of` and persisted after refresh.
- Set color changed to `annotation-teal` and persisted after refresh.
- Member order was changed to `Gamma label -> Beta label` and persisted after refresh.
- Existing UI issues remain open: native prompt flows, narrow row-group rail hit target, `+ Insert` overlap, and loose-label selection flow.

## Command Surface Follow-Up Patch - 2026-06-17

Status: patched and browser-harness verified.

Root causes:

- Text selection label creation, TextUnitGroup create / rename, and AnnotationSet creation still used temporary native browser prompt dialogs.
- Organizer loose-label clicks reused the global label inspection callback, so selecting a loose label for membership could switch the panel back to Annotation Stack.
- The row group rail was visually correct but physically too narrow to hit reliably.
- The floating `+ Insert` rail lived in a separate overlay layer and could still compete with Annotation Stack / Organizer controls.

Fix:

- Added a Coincides-owned inline name prompt for selection labels, child labels, create-set-from-label, TextUnitGroup creation, and TextUnitGroup rename.
- Added an inline create-set row inside Annotation Organizer.
- Split Organizer member picking into a local draft selection so loose labels can be selected without leaving Organizer.
- Widened the row group rail hit target while keeping the visible rail quiet.
- Hide the floating `+ Insert` rail while Annotation Stack / Organizer is open.

Browser-harness verification after patch:

- Text selection `Label` opens the Coincides inline prompt, not a native browser dialog.
- `Group selected rows` opens the Coincides inline prompt and creates a row group.
- Row group rail right-click opens the Row Group menu; `Rename group` opens the Coincides inline prompt.
- Annotation Stack `Sets` can be opened without `+ Insert` overlap.
- Organizer loose-label selection stays inside Organizer and marks labels as member-selection draft.
- Organizer `Create set` uses an inline input row instead of a native browser dialog.

## Floating Insert Retreat Patch - 2026-06-17

Status: patched for Henry manual retest.

Product finding:

- The fixed viewport `+ Insert` entry no longer fits the current TextFlow-first notebook direction.
- It suggests a permanent block-template insertion path at the exact moment the product is moving toward natural writing, slash commands, right-click command surfaces, annotation tools, and CanvasObject tools.
- It also competes with the writing surface and nearby inspector / organizer panels.

Fix:

- Hide the fixed `+ Insert` rail and Advanced Insert panel from the active note surface.
- Keep the underlying code path intact for now so this is a reversible retreat, not a destructive deletion.
- Record the future deletion / redesign question in Open Issue.

Follow-up:

- Before deleting the Advanced Insert code path, confirm no remaining manual or slash-command flow depends on it.
- Re-evaluate TextUnit gutter controls separately. `Insert row`, `Annotate row`, and row grouping may need to move into quieter hover/context-menu surfaces instead of permanently narrowing the writing column.

## Manual Test Protocol

1. Create or open a note with one TextBlock containing at least five TextUnits.
2. Click row handles for two TextUnits in the same TextBlock.
3. Right-click the row / row handle and run `Group selected rows`.
4. Confirm a quiet group rail appears beside those rows.
5. Rename the group from the group rail menu.
6. Refresh the note and confirm the grouped rows persist.
7. Ungroup the rows and confirm source text remains.
8. Create several labels in the note.
9. Open Annotation Stack and click `Sets`.
10. Create a set from selected labels.
11. Change set kind between `collection`, `sequence`, and `all_of`.
12. Add and remove labels from the set.
13. Reorder set members.
14. Refresh the note and confirm set label, kind, color, description, and member order persist.
