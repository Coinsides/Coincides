# V2.BN.8.9 PageFrame Maturity Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn the 8.8 PageFrame service seed into the first mature special CanvasObject: visible, testable, multi-frame-capable, AI-readable, export-aware, and still grounded in TextFlow.

**Architecture:** 8.9 does not replace the 8.8 Canvas foundation. It hardens PageFrame on top of `CanvasObject / CanvasPlacement / ContentMount / PageFrameExtension / CanvasAIReadableSnapshot`, keeping TextFlow as content truth and Canvas as layout truth. The work should move from service contracts to visible runtime behavior in small, reversible passes.

**Tech Stack:** React + TypeScript client runtime, Vite, CSS modules through `NoteDetail.module.css`, Canvas Engine service layer under `client/src/pages/Notes/canvasEngine`, model-contract checks under `client/scripts`, V2.BN.8 release docs.

The next active engineering lane is `V2.BN.8.10 TextFlow Typography Maturity`, provided Henry's holistic manual test does not expose a basic PageStack blocker.

Product naming correction: the user-facing page unit is `PageStack`. A PageStack may contain one PageFrame or many PageFrames. A standalone PageFrame is an internal/transition phrase only, not a user-facing top-level concept. Creating a "page" creates a single-page PageStack; adding pages grows that stack.

### 本版本不做什么

- 不做完整 infinite / chunked canvas。
- 不做完整 CanvasObject database migration。
- 不做 ContentGroup / Petal projection。
- 不做 Relation runtime / semantic relation arrows。
- 不做 Agent write path。
- 不做 diagram / chart / math graph / Raw Ink / 3D viewer。
- 不把 header/footer 普通文本做成第二份 TextFlow 真相。
- 不把普通 visual connector 变成 KnowledgeRelation。

### 数据边界

8.9 必须承认一个现实：8.8 还没有 durable CanvasObject / CanvasPlacement database migration。

因此 8.9 的 PageFrame 数据策略是：

1. `CanvasObject / CanvasPlacement / PageFrameExtension` 继续作为 runtime contract。
2. 多 PageFrame 的第一版持久化可以走 note-level PageFrame metadata seed，但必须写清楚这是 PageFrame-specific transition，不是最终 generic CanvasObject truth。
3. 如果 8.9.2 发现没有 durable PageFrame state 就无法继续，先暂停，写 Open Issue，再决定是否插入 `V2.BN.8.9.x PageFrame Persistence Cutover`。
4. 不为旧测试数据做长期兼容；当前未投产，可以清理测试数据。

## 6.1 Sub-plan C.1 - V2.BN.8.9.3.1 PageFrame Print Scale / Document Typography Baseline

### 目标

在进入 8.9.4 页眉 / 页脚 / 页码之前，先把 PageFrame 的“纸张感”和正文默认排版基线锁住。

这不是完整 TextFlow 字体系统。它只解决三个底层问题：

1. 默认 PageFrame 不应该再是随内容高度增长的矮矩形，而应该有 A4 逻辑比例。
2. PageFrameExtension 应该能告诉 AI / 导出层当前页面是什么纸张基线。
3. 正文 textarea / TextUnit 的默认 font size、line height 和测量估算应该来自文档排版 token，而不是散落 CSS 数字。

### Files

- Create: `client/src/pages/Notes/canvasEngine/pageFramePrintScaleService.ts`

- Modify: `client/scripts/canvasEngineModelContractCheck.ts`
- Modify: `client/scripts/canvasRuntimeBoundaryCheck.mjs`

1. PageFrame print scale is PageFrame state, not TextFlow content.
2. Document typography baseline is a default profile, not a full user-facing font system.
3. Existing test PageFrames without an explicit page size may be normalized to the active default. The product is not in production and we are not carrying long-term compatibility for legacy test geometry.
4. Canvas zoom remains viewport state; it must not mutate document font size.
