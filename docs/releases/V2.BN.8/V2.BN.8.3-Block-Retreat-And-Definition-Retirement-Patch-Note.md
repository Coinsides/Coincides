# V2.BN.8.3 Block Retreat And Definition Retirement Patch Note

status: closed; non-browser verification passed; Henry manual pass recorded
date: 2026-06-15

## Why This Patch Exists

V2.BN.8.3 manual testing confirmed that Coincides should not keep expanding the active block taxonomy for ordinary knowledge roles.

The product direction is now:

```text
TextFlow is the primary writing and knowledge structure.
Block is a spatial / rendering / interaction object.
Definition is a knowledge role, not a default independent block type.
```

This patch keeps the TextFlow seed focused. It removes the most obvious old-direction entry point, `DefinitionBlock`, from ordinary user creation paths while preserving compatibility code until the next clean data reset or runtime cleanup.

## Scope

### In Scope

- [x] Remove `Definition` from active slash menu block creation.
- [x] Remove `Definition` from Advanced Insert active creation.
- [x] Keep `/definition` only as a disabled future command or future mark-role command.
- [x] Update user-facing command language so Definition is described as a future `knowledge_role` / TextUnitGroup / inline structure action.
- [x] Sync docs that still describe Definition as a primary block type.
- [x] Record follow-up TextFlow work in later V2.BN.8.x handoff buckets instead of keeping it inside the 8.3 patch chapter.

### Out Of Scope

- No full TextUnit editor.
- No TextUnit gutter runtime.
- No right-click / selection menu.
- No inline definition runtime.
- No TextUnitGroup visual editor.
- No Role Slot Mapping UI.
- No relation endpoint runtime.
- No production migration or legacy adapter.
- No destructive deletion of Definition renderer code in this patch.

## Product Rules

```text
Definition as writing/knowledge identity
  -> TextUnitGroup knowledge_role
  -> InlineStructuredObject semantic_kind
  -> future role slot mapping

Definition as independent spatial object
  -> not part of the default active block set
```

Independent blocks remain appropriate when a thing needs:

- independent placement;
- independent resize;
- special rendering;
- special interaction;
- canvas-level manipulation;
- a visible shell separate from natural writing flow.

Definition usually does not need those properties. It should therefore live in TextFlow unless the user later explicitly promotes a selected region into a special object.
