# V2.BN.8.6.28 Single ContentGroup Editor Petal v1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 把 Single ContentGroup Editor 从“能看 members / 能新建 Petal”推进到“能把一个粗糙内容包拆成局部角色”的第一版。

**Architecture:** ContentGroup 仍然是严肃内容包，Petal 是 ContentGroup 内部的局部角色，不再延续 child label 思路。本版本只处理 ContentGroup 内部拆分：member 进入 group 后仍保留顶层引用，Petal 只保存对 member fragment 的局部引用；删除 Petal 不删除原文、不删除 Label、不删除顶层 member。

**Tech Stack:** React, TypeScript, Vite, Canvas Engine runtime metadata, ContentGroup service helpers, Group Gallery / Single ContentGroup Editor.

---

## 1. 本版本边界

8.6.28 只解决一个问题：

```text
- ContentGroup 已经收进来一堆粗糙 members。
- 用户现在要在 Single Editor 里把这些 members 拆成 concept name / description / condition / statement / example result 等局部角色。
- 这些局部角色就是 Petal。
```

本版本不做：

- Petal 高级排序；
- Petal 拖拽排序；
- AI 自动创建 Petal；
- block 内复杂 fragment 自动抽取；
- table / image / canvas object fragment；
- OpenDesign 最终视觉对齐；
- relation endpoint 成熟定义。

## 3. 数据规则

Petal 必须使用现有 ContentGroup 数据方向，而不是重新创造 child label：

```ts
ContentGroupV1 {
  members: ContentGroupMemberV1[];
  fragments?: ContentGroupFragmentV1[];
  petals: ContentGroupPetalV1[];
}

ContentGroupPetalV1 {
  members: ContentGroupMemberV1[];
  fragment_ids?: string[];
}
```

8.6.28 的优先级：

1. `fragments` 成为 Petal 细分的主路径。
2. `petal.members` 只保留兼容显示，不再作为新增细分的首选写入方式。
3. `ContentGroupFragmentV1.source_member_id` 必须指向顶层 member。
4. `ContentGroupFragmentV1.content_range` 可以是顶层 member 内的局部 range，也可以在第一版中复用整个 member 的 range。

- [ ] **Step 2: 增加 fragment 从 member 生成的明确入口**

在 `contentGroupService.ts` 增加或收紧这个入口：

```ts
export function createContentGroupFragmentFromMember(input: {
  member: ContentGroupMemberV1;
  contentRange?: AnnotationRangeV1 | null;
  label?: string | null;
  previewText?: string | null;
  orderIndex?: number;
}): ContentGroupFragmentV1 {
  return createContentGroupFragment({
    sourceMemberId: input.member.id,
    contentRange: input.contentRange || input.member.content_range || null,
    label: input.label || input.member.label || null,
    previewText: input.previewText || input.member.preview_text || null,
    orderIndex: input.orderIndex,
  });
}
```

验收：fragment 一定有 `source_member_id`；没有 source member 的 fragment 不允许创建。

- [ ] **Step 3: 增加 assign member fragment to petal 的组合 helper**

在 `contentGroupService.ts` 增加组合入口：

```ts
export function addMemberFragmentToPetal(input: {
  group: ContentGroupV1;
  petalId: string;
  memberId: string;
  contentRange?: AnnotationRangeV1 | null;
  label?: string | null;
  previewText?: string | null;
}): ContentGroupV1 {
  const normalized = normalizeContentGroup(input.group);
  const sourceMember = normalized.members.find((member) => member.id === input.memberId);
  if (!sourceMember) return normalized;
  const fragment = createContentGroupFragmentFromMember({
    member: sourceMember,
    contentRange: input.contentRange,
    label: input.label,
    previewText: input.previewText,
    orderIndex: normalized.fragments?.length || 0,
  });
  const withFragment = addContentGroupFragment({
    group: normalized,
    sourceMemberId: sourceMember.id,
    contentRange: fragment.content_range,
    label: fragment.label,
    previewText: fragment.preview_text,
  });
  const createdFragment = withFragment.fragments?.[withFragment.fragments.length - 1];
  return createdFragment
    ? assignFragmentsToPetal({ group: withFragment, petalId: input.petalId, fragmentIds: [createdFragment.id] })
    : withFragment;
}
```

验收：同一个顶层 member 可以分配到多个 Petal；删除 Petal 只移除 Petal 引用，不移除顶层 member。
