## 为什么补这个小补丁

8.11 Structured Object Family 已经工程收口，但 CloudCode 的高危审查继续点出了两类不能带进 V2.BN.8 最终收口 commit 的问题：

1. **PageFrame extension 数据完整性风险**：旧 cutover migration 可能把不同 note 中同名 `primary-page-frame` 的 extension 压塌，8.11.3.1 的 extensionless hydration 只是 read-time mask，甚至可能在 load 后 re-save 时把默认值固化。
2. **AI-readable snapshot 污染风险**：Canvas runtime / server projection 里可能把不该给 AI 读的对象读进去，包括重复的 page/block 节点、隐藏 backing block、trashed backing block 的 ghost projection。

这批问题不是普通 UI 磨皮。它们会影响后续 Source、ContentGroup projection、Agent 读取和未来 Graph/RAG 的输入洁净度，所以需要在 V2.BN.8 收口前单独烧掉。

## 本补丁要修什么

### A. PageFrame extension 数据丢失链

覆盖问题：

- `CR-8.11.1-01`：migration 035 的 `page_frame_extensions` 以 `frame_id` 单列作为主键，遇到多篇 note 共用 `primary-page-frame` 时可能跨 note 覆盖。
- `CR-8.11.3.1-01`：extensionless hydration 兜底后，adapter 可能立即 re-save，把默认 `content_inset/page_size/background/template` 当成真值写回。
- `CR-8.11.3.1-02`：现有测试没有复现跨 note frame id 塌缩，也没有断言 page style / margin / page size 的恢复边界。

计划处理：

1. 对 extension 缺失但仍能从 object + placement 恢复出来的 PageFrame，增加明确的 recovered / degraded 标记。
2. `savePageFrameCollection` 不把 recovered frame 的兜底默认值静默写成新真相。
3. 新增 migration `043_*`，按 `(note_id, frame_id)` 补齐缺失的 `page_frame_extensions`：
   - geometry 从 placement 恢复；
   - 若 legacy `canvas_engine_page_frames_v1` 仍存在，则尽量恢复 page size / inset / background / template / exportable；
   - 若 legacy 已被 strip，则退默认，并在 metadata 中标记 recovered，不假装恢复了真实样式。
4. 补 server 回归测试：
   - 双 note 共用 `primary-page-frame` 的塌缩 fixture；
   - extensionless recovery 必须断言 page size / content inset 被保留，或显式标 recovered。

### B. AI-readable snapshot 污染链

覆盖问题：

- `CR-8.11.3-01`：generic 持久化数组里混入 `page_frame` / `paragraph_block_projection`，runtime builder 又从 pageFrames / blockPlacements 重建一份，导致 AI tree 出现重复节点。
- `CR-8.11.4-01`：server projection snapshot 没有过滤 `render_scope='canvas_object_backing'` 的隐藏 backing block。
- `CR-8.11.1-05`：trashed note block 的 projection / placement / mount 仍可能在 read path 中被返回，形成 ghost projection 并漏进 AI 快照。

计划处理：

1. client runtime merge 前过滤 generic objects：
   - `page_frame` 和 `paragraph_block_projection` 只允许由专属 runtime path 重建；
   - generic objects 只保留 shape / sticky / visual connector / image / table 等普通对象；
   - 补 boundary regression，确保合成 id 的 page/block generic object 不会造成重复 AI node。
2. server snapshot build 下沉隐藏规则：
   - server 选块时过滤 `metadata.render_scope = canvas_object_backing`；
   - backing block 不再作为独立顶层文本进入 AI projection。
3. paragraph block projection read path 派生 backing block liveness：
   - 读路径 join `note_blocks`；
   - backing block 非 active 时，该 projection 不再进入 persistence / runtime / AI snapshot；
   - 本轮优先采用 read-join，不把 liveness 焊死到 mount identity 上。
4. 补 server 回归测试：
   - block-backed shape 的 hidden backing block 不进 `buildSnapshotFromNote`；
   - trashed backing block 不再留下 AI-readable ghost projection。

## 明确采用的判断

- **A2 repair 的不可恢复边界接受**：pre-cutover 已经被 035 strip 掉的自定义 PageFrame 样式不可恢复。本补丁只退默认并标记 recovered，不伪造真实恢复。
- **B1 采用 kind 过滤，不做 runtime id 全面归一**：当前优先小改动止血，保持 page/block 专属 runtime truth 和 ordinary generic object truth 分开。
- **B3 采用 read-join，不做 cascade-trash 第一选择**：liveness 属于读时派生状态，暂不把它焊进 mount / object identity。若测试证明 read-join 不够，再升级为 cascade cleanup。

## 不做什么

- 不处理第 2 阶段 MED 项：
  - demote 销毁文本；
  - 表格删行列无 undo；
  - restore hidden backing orphan；
  - annotation range / offset rebase；
  - 其他 lifecycle / validation / annotation 中危项。
- 不做用户友好化提示、撤销系统、导出族修复。
- 不推进 ContentGroup projection / Source / Agent / Relation。
- 不重写 CanvasObject identity 体系。
- 不整理整个 dirty workspace。
