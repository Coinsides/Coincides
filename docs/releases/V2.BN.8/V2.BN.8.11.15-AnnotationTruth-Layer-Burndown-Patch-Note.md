# V2.BN.8.11.15 AnnotationTruth Layer Burndown Patch Note

> **Status:** implemented
> **Date:** 2026-07-02
> **Scope:** 8.11 closure burn-down / AnnotationTruth integrity / migration 036 / range invalidation
> **Source handoff:** `docs/agent-ops/handoffs/2026-07-02-8.11-annotation-truth-burndown.md`

## Why This Patch Exists

8.11 的 object family 已经把普通 CanvasObject 管线推进到可用状态，但 AnnotationTruth 这一层还剩三类结构欠账：

- 036 legacy backfill 在重复 annotation id 上会有静默覆盖风险；
- AnnotationTruth parent / child 层级只靠前端自律，服务端缺少完整性闸；
- AnnotationRange 的 block / offset 引用在文本变化、块软删、overlap 失效后容易留下“看似有效”的旧坐标。

这次补丁的目标不是扩展 annotation 功能，而是让 AnnotationTruth 作为 label / marker truth 时更加自洽。

## What Changed

- 036 migration 改为先全量预扫 legacy annotation id，发现重复 id 时在任何 insert / strip 之前中止；迁移插入从 `INSERT OR REPLACE` 收紧为纯 `INSERT`，并把 legacy metadata strip 放到所有 durable insert 成功之后。
- `replaceNoteAnnotationTruths` 增加服务端规范化闸：parent 指针成为唯一层级真相，child list 由服务端重算；悬空、自指、成环 parent 会被 repair 掉，但 annotation 行本身不会被删除。
- range target 增加基础完整性检查：`text_span` / `text_unit` / `block` 必须带 `block_id`，`canvas_object` 必须带 `canvas_object_id`，避免半截 range 进入 durable store。
- AnnotationRange 增加读时派生失效：目标 block 不存在、已 trashed、或 offset 超出当前文本长度时，range 会以 pending metadata 表示，不再被正文高亮层按旧坐标渲染。
- overlap rebase 失效时不再保留旧 start / end offset，避免把已经不可信的旧位置继续当成可渲染真相。
- code / formula / shape text 这几条普通 paragraph 之外的编辑路径补进现有 rebase 流程，避免这些文字承载块上的 range 偏移长期不更新。

## What This Patch Does Not Do

- 不加 schema 级硬 FK / cycle trigger；这会和 repair-and-persist 的迁移策略冲突，适合放到后续硬化版本里单独讨论。
- 不做跨 block 的结构 rebase，例如 block split / merge / reorder 后的语义迁移。
- 不做已经被旧迁移 strip 掉的历史数据恢复；本轮是预防性硬化，不伪造无法恢复的 legacy truth。
- 不推进 ContentGroup、Source、Relation、Agent 或 GraphRAG。

## Follow-up Fix: Read-time Pending Must Not Become Durable Truth

Date: 2026-07-02

Source handoff: `docs/agent-ops/handoffs/2026-07-02-8.11-annotation-truth-fix.md`

This follow-up closes the Stage-4 blocker found after the first 8.11.15 pass.

What changed:

- `anchor_status` and `anchor_reason` are now treated as derived read-time advisory fields only.
- `replaceNoteAnnotationTruths` strips `anchor_status` / `anchor_reason` before writing range metadata.
- `deriveRangeMetadata` strips any stored `anchor_*` values first, then recomputes pending state from the live block status and current text length.
- `AnnotationRangeV1` now formally allows `metadata`, so read-time pending and re-anchor provenance are represented in the client contract.
- Pending ranges no longer create TextBlock badges, markers, previews, ContentGroup Rail previews, drag text, or ReadingInterpretation / AI-readable annotation projection text.
- Overlap invalidation still clears stale offsets, but now preserves `pre_edit_offsets` and the last `range_text_cache` for future re-anchor work.

Regression locks added:

- Trash block -> read pending AnnotationTruth DTO -> save annotations -> restore block must revive the range with original offsets and no durable `anchor_*`.
- `offset_out_of_bounds` must recompute on read: when the source text grows enough, the range becomes non-pending without a migration.
- PUT -> GET -> PUT no longer churns `anchor_*` into durable range metadata.
- Duplicate legacy annotation id assertion now checks that both note ids are present.
- Service hierarchy repair now explicitly asserts row count is not dropped.
- Model contract now checks pending ranges do not enter AI-readable annotation projection and overlap invalidation keeps re-anchor provenance.

## Follow-up Fix 2: Null-offset Ranges Must Use Renderable Gate

Date: 2026-07-02

Source handoff: `docs/agent-ops/handoffs/2026-07-02-8.11-annotation-truth-fix-2.md`

This follow-up closes the last Stage-4 consumer leak: overlap-invalidated `text_span` ranges can have `start_offset` / `end_offset` cleared to null without being marked pending. Those ranges are valid repair records, but they are not safe render/AI/copy records.

What changed:

- Rendering, badge, marker, TextUnit summary, ContentGroup preview/member projection, ReadingInterpretation projection, label drag text, and annotation-copy paths now use `annotationRangeIsRenderable`.
- `AnnotationInspectorPanel` remains the repair surface: it still lists unrenderable ranges, but marks them with `Needs review` instead of hiding them.
- Migration `036_v2_annotation_truths` now strips derived `anchor_status` / `anchor_reason` from legacy range metadata before durable insert.

Regression locks added:

- Legacy migration with polluted `anchor_*` metadata now asserts durable `annotation_ranges.metadata` is clean after cutover.
- Read-side compatibility now asserts a healthy active range with stale durable `anchor_status` reads back as non-pending while preserving real durable metadata.
- Model contract now asserts null-offset text ranges are not renderable, do not create TextUnit badge/summary/highlight output, do not enter AI-readable annotation projection, and do not expose stale cache through label drag text.
- Valid-offset text ranges are covered as a positive control so the renderable gate does not over-suppress healthy ranges.
