# V2.BN.8.8.6 Canvas Command History Seed Patch Note

Date: 2026-06-25

Status: completed scoped engineering pass and verified.

## Summary

8.8.6 给 Canvas Engine 补上第一版 command dispatcher：

```text
CanvasCommand -> next runtime model + CanvasDelta
```

这一步不是可见 UI，也不是完整 undo/redo 栈，而是让 Canvas 写入不再只能散落在 UI 事件里。后续用户操作、AI proposal、协作同步、undo/redo 都可以接同一条命令边界。

## Completed

- Added `canvasCommandService.ts`.
- Added command helper functions:
  - `createCanvasObjectCommand`;
  - `createResizeCanvasObjectCommand`;
  - `createUpdateVisualStyleCommand`;
  - `createDeleteCanvasObjectCommand`.
- Added `applyCanvasCommandToRuntime`.
- Covered command application for:
  - create CanvasObject / Placement / optional ContentMount / optional VisualStyle / optional VisualConnector;
  - move CanvasObject by updating placement only;
  - resize CanvasObject by updating placement only;
  - update or create VisualStyle;
  - delete CanvasObject and directly owned placement / mount / style / visual connector records.
- Added `Canvas command dispatcher foundation` model contract group.
- Updated runtime boundary check to protect the command service.
- Updated the Canvas Engine implementation checklist.

## Engineering Boundary

- Command application is pure and runtime-level.
- The command result returns a next model plus a delta.
- Move and resize do not mutate TextFlow content.
- Visual connector creation remains visual-only.
- Delete only removes directly owned Canvas records; it does not invent source mutation, Relation cleanup, or GraphRAG behavior.

## Not Included

- No visible toolbar wiring.
- No full undo / redo stack UI.
- No persisted command log.
- No collaboration transport.
- No Agent proposal execution UI.
- No durable CanvasObject database migration.

## Remaining Risks

- Canvas AI-readable snapshot is not regenerated by the command service yet; 8.8.7 handles AI Tree hardening separately.
- This is a command seed, not a durable event-sourcing layer.
