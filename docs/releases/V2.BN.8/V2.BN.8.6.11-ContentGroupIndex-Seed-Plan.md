# V2.BN.8.6.11 GroupFolder Manager And ContentGroup Editor Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:subagent-driven-development` (recommended) or `superpowers:executing-plans` to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the first complete `GroupFolderManager` and `ContentGroupEditor` foundation: Gallery-first organization, hybrid scope switching, full folder operations, ContentGroup member management, and fragment-to-Petal refinement.

**Architecture:** Move ContentGroup work from a single right-side panel into three surfaces: a lightweight `GroupsRail`, a full `ContentGroupGallery` with `GroupFolderManager`, and a `ContentGroupDetailEditor` for refining members into fragments and Petals. `GroupFolder` becomes the organization/path layer; `ContentGroup` remains the serious content package. `ContentGroup.depth` and `parent_group_id` should stop being primary user-facing organization fields and be replaced by folder placement/path.

**Tech Stack:** React 18, TypeScript, existing canvas engine runtime metadata, CSS modules / existing global CSS tokens, lucide-react icons, existing `canvasEngineModelContractCheck` smoke contract, client build verification.

---

## Implementation Checkpoint

2026-06-18 current implementation stops at a hand-testable seed rather than a finished full-screen Gallery:

- `GroupFolderV1` and folder metadata persistence are implemented.
- Project and Note system root folders are seeded when note runtime data loads.
- ContentGroups can be created in the selected folder and moved between folders.
- Selection ranges, selected labels, and selected blocks can become ContentGroup members through the Groups panel.
- ContentGroup fragments and fragment-to-Petal data fields are seeded at the model/service layer.
- The current visible UI is still a right-side Groups panel with folder/gallery/detail sections, not the final parallel Gallery surface.
- Full drag-and-drop, batch Gallery management, and source-region/media-region refinement remain follow-up work.

## 0. Locked Product Decisions

This plan is based on the 2026-06-18 visual companion decisions:

- Primary surface: **B, Gallery-first**.
- Scope model: **C, hybrid scope switcher**.
- Folder creation: **A, Workspace / Project / Note all allow user-created folders**.
- Detail Editor depth: **A, first version supports `fragment -> Petal` assignment**.
- AI temporary folder: **A, data model and UI placeholder only, no AI generation workflow**.
- Visual direction: quiet property-sheet / resource-manager style, closer to VS Code Settings than nested rounded bubble panels.

## 1. Product Meaning

### 1.1 Core Objects

```text
GroupFolder
  organization, placement, path, browsing boundary, AI reading context, relation-view boundary

ContentGroup
  serious content package made from traceable member references

ContentGroupMember
  an item placed into a ContentGroup, such as a text range, multi-range, label, block, future table region, future image region, or another ContentGroup

ContentGroupFragment
  a refined piece cut from a member for Petal assignment

ContentGroupPetal
  a user-defined local part inside one ContentGroup, such as concept name, description, example, condition, statement, result, or any user label
```

Short rule:

```text
Folder organizes.
Group contains.
Member references.
Fragment cuts.
Petal refines.
```

### 1.2 Three Surfaces

```text
GroupsRail
  collect, quick view, set active group, open Gallery / Editor

ContentGroupGallery
  organize, browse folders, manage groups, batch move/copy/delete, open local relation boundary placeholder

ContentGroupDetailEditor
  refine, inspect members, split fragments, assign fragments to Petals, preserve traceability
```

### 1.3 Out Of Scope For This Version

This version does not implement:

- AI automatic temporary folder generation.
- Full relation graph runtime.
- Multi-placement shortcuts, pin, linked folder aliases, or folder shortcuts.
- Source document region extraction beyond existing ContentRange / annotation range references.
- Production migration for real users. Current data is test data and may be reset during development.

```ts
const nowIso = () => new Date().toISOString();
const createId = (prefix: string) => `${prefix}_${Math.random().toString(36).slice(2, 10)}_${Date.now().toString(36)}`;

export function createGroupFolder(input: {
  title: string;
  scope: GroupFolderScopeV1;
  parentFolderId?: string | null;
  origin?: GroupFolderOrigin;
  status?: GroupFolderStatus;
  systemRoot?: boolean;
  ownerProjectId?: string | null;
  ownerNoteId?: string | null;
  colorToken?: string | null;
}): GroupFolderV1 {
  const now = nowIso();
  const origin = input.origin ?? 'user';
  return {
    id: createId('group_folder'),
    scope: input.scope,
    parent_folder_id: input.parentFolderId ?? null,
    title: input.title.trim() || 'Untitled folder',
    origin,
    status: input.status ?? (origin === 'ai' ? 'temporary' : 'active'),
    system_root: input.systemRoot ?? false,
    owner_project_id: input.ownerProjectId ?? null,
    owner_note_id: input.ownerNoteId ?? null,
    color_token: input.colorToken ?? null,
    created_at: now,
    updated_at: now,
  };
}
```

```ts
export function assignFragmentsToPetal(input: {
  group: ContentGroupV1;
  petalId: string;
  fragmentIds: string[];
}): ContentGroupV1 {
  const availableIds = new Set((input.group.fragments ?? []).map((fragment) => fragment.id));
  const nextIds = input.fragmentIds.filter((id) => availableIds.has(id));
  return invalidateAcceptedIdentity({
    ...input.group,

        fragment_ids: [...(petal.fragment_ids ?? []), ...nextIds.filter((id) => !existingIds.has(id))],
        updated_at: nowIso(),
      };
    }),
    updated_at: nowIso(),
  });
}
```

```ts
export function folderPath(input: {
  folderId: string;
  folders: GroupFolderV1[];
}): GroupFolderV1[] {
  const byId = new Map(input.folders.map((folder) => [folder.id, folder]));
  const path: GroupFolderV1[] = [];
  const seen = new Set<string>();
  let current = byId.get(input.folderId) ?? null;
  while (current && !seen.has(current.id)) {
    path.unshift(current);
    seen.add(current.id);
    current = current.parent_folder_id ? byId.get(current.parent_folder_id) ?? null : null;
  }
  return path;
}
```
