# V2.BN.8.1 Final Smoke Protocol

> 本文是 `V2.BN.8.1` 的最终浏览器与人工验收协议。
> 当前不执行 Browser Harness；等 Henry 确认全部工程准备好后，再按本文一次性补跑。

## Purpose

`V2.BN.8.1` 的代码目标不是继续给旧 `NoteDetail.tsx` 打补丁，而是完成 Canvas Engine 对旧 note runtime 的逐层接管。

最终 smoke 要验证两件事：

1. 工程上，Note 页面确实挂在新的 Canvas Engine runtime 上；
2. 体验上，核心写作、布局、overlay、Page/Canvas mode 没有因为 runtime replacement 发生明显回归。

## Hard Completion Rule

只有同时满足以下条件，`V2.BN.8.1` 才能标记为 passed：

- non-browser gates passed；
- Browser Harness smoke passed；
- Henry manual visual / interaction pass confirmed；
- `Review.md` / `Experience-Review.md` / `CHANGELOG.md` 已记录结果；
- worktree clean；
- branch pushed。

如果 Browser Harness 或 Henry manual pass 没有完成，即使代码和非浏览器测试全绿，也不能关闭本小版本。

## Preflight

执行最终 smoke 前先确认：

- 当前分支：`codex/v2-bn-canvas-engine`；
- server 正在运行；
- client 正在运行；
- 当前工作区没有未提交产品代码；
- 是否需要 local test data reset 已由 Henry 决定。

建议命令：

```text
git status --short --branch
npm run build:client
npm run smoke:canvas-engine-performance
cd server && npm run build
git diff --check
changed-file secret scan
```

## Local Test Data Decision

不要默认清空本地数据库。

只有在以下情况才考虑 reset：

- 旧测试数据污染 Browser Harness / manual smoke；
- 旧 `better_notebook_layout` payload 让 Page/Canvas 行为无法判断；
- Henry 明确要求从干净 smoke account / project / note 开始。

如果 reset，必须：

1. 停 server；
2. 备份 `server/coincides.db*`；
3. 删除 active dev db；
4. 重启 server；
5. 创建 smoke account / project / note；
6. 在 Review 记录 reset 证据。

## Browser Harness Gate

Browser Harness 连接前置条件：

- Chrome remote debugging 已授权；
- 如果出现授权提示，Henry 需要在 Chrome 中允许；
- 如果 Browser Harness 报 CDP websocket handshake timeout，则不能把 browser smoke 记为 passed。

Browser Harness 至少要证明：

- 当前 URL 是本地 client；
- note 页面可打开；
- 页面 runtime root 存在；
- 没有明显 console runtime error；
- Page mode / Canvas mode 可以切换；
- overlay 层不被 selected block toolbar 错压；
- block 操作不会触发明显布局崩溃。

建议 Browser Harness 检查组：

```text
Runtime mount
  - confirm current note route
  - confirm Canvas Engine runtime root marker
  - confirm NoteDetail shell no longer owns runtime

Writing
  - create text block
  - paste long paragraph
  - create DefinitionBlock
  - create FormulaBlock
  - create CodeBlock

Overlay
  - slash menu near caret
  - preview panel above toolbar
  - info / more / insert / preview mutual exclusion
  - preview overlay toggles retain state

Layout
  - select block
  - move block
  - resize block
  - blank click clears selection
  - double-click blank creates draft according to snap policy

Mode
  - switch Page mode -> Canvas mode
  - switch Canvas mode -> Page mode
  - PageFrame boundary remains visible
  - workspace blocks do not pollute Page mode unexpectedly

History
  - move then Ctrl+Z
  - Ctrl+Y restores
  - create/trash history does not visibly break
```

## Henry Manual Pass

Henry 手动验收不是形式签名。它要覆盖 Browser Harness 很难判断的“手感”：

- 视觉是否安静、清晰；
- Page mode 是否仍像一个可写页面；
- Canvas mode 是否仍像一个工作区，而不是被外层滚动条/气泡边框困住；
- block 选中、取消选中、移动、resize 是否自然；
- slash menu 是否贴近当前输入位置；
- FormulaBlock / DefinitionBlock 展开时是否穿模；
- Preview panel 是否遮挡合理；
- top bar / floating insert / layout / preview 是否不妨碍写作；
- Ctrl+Z / Ctrl+Y 是否符合直觉；
- 是否存在 Henry 认为必须当前小版本修复的体验问题。

Henry 只需要给出以下三种结论之一：

```text
passed
passed with follow-up polish
failed, must patch before closing V2.BN.8.1
```

只有第一种或第二种可以关闭 `V2.BN.8.1`。
