# V2.BN.8.6.9 ContentGroup Hardening And Integrity Gate Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn the V2.BN.8.6.7 ContentGroup seed into a reliable content-package foundation before adding identity or index behavior.

**Architecture:** This version does not add accepted identity, GroupFolder / ContentGroup Gallery, or relation runtime. It hardens the existing ContentGroup / Petal path: references must remain traceable, previews must not become detached truth, deleted targets must not leave silent broken members, and the right-side rail/detail surface must be stable enough for daily manual use. ContentGroup remains a content package; semantic identity comes later in V2.BN.8.6.10.

**Tech Stack:** React 18, TypeScript, Vite, canvas engine runtime metadata, TextFlow source-backed ranges, ContentGroup service helpers, model contract smoke scripts.

## 3. Data Rules

ContentGroup and Petal members must be references, not copied content:

```ts
ContentGroupMemberV1
  kind: 'content_range' | 'annotation' | 'block' | 'future_object'
  target_id?: string | null
  content_range?: AnnotationRangeV1 | null
  label?: string | null
  preview_text?: string | null
  order_index: number
```

`preview_text` is a cache. It is allowed for display, but it must never become the source of truth.

Integrity states:

```text
valid
  member target still exists and source preview can be resolved

stale
  member target exists but preview cache is older than source

orphaned
  member target or source range no longer resolves

unsupported
  future object type exists but current runtime cannot resolve it yet
```

- [ ] **Step 2: Add member preview refresh helper**

Add:

```ts
export function refreshContentGroupMemberPreview(
  member: ContentGroupMemberV1,
  resolver: ContentGroupPreviewResolver,
  now = new Date().toISOString(),
): ContentGroupMemberV1 {
  const normalized = normalizeContentGroupMember(member);
  let nextPreview: string | null = null;

  if (normalized.kind === 'annotation' && normalized.target_id) {
    nextPreview = resolver.resolveAnnotationPreview(normalized.target_id);
  } else if (normalized.kind === 'block' && normalized.target_id) {
    nextPreview = resolver.resolveBlockPreview(normalized.target_id);
  } else if (normalized.kind === 'content_range' && normalized.content_range) {
    nextPreview = resolver.resolveRangePreview(normalized.content_range);
  }

  if (nextPreview === null) {
    return markContentGroupMemberIntegrity(normalized, 'orphaned', 'preview source no longer resolves');
  }

  return {
    ...normalized,
    preview_text: nextPreview,
    metadata: {
      ...(normalized.metadata || {}),
      integrity_status: 'valid',
      integrity_reason: null,
      preview_refreshed_at: now,
    },
  };
}
```

- [ ] **Step 3: Add group-level preview refresh helper**

Add:

```ts
export function refreshContentGroupPreviews(
  group: ContentGroupV1,
  resolver: ContentGroupPreviewResolver,
): ContentGroupV1 {
  const normalized = normalizeContentGroup(group);
  return {
    ...normalized,
    members: normalized.members.map((member) => refreshContentGroupMemberPreview(member, resolver)),
    petals: normalized.petals.map((petal) => ({
      ...petal,
      members: petal.members.map((member) => refreshContentGroupMemberPreview(member, resolver)),
    })),
  };
}
```
