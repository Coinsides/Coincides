# V2.BN.8.6.19 Single ContentGroup Editor v1 Plan

> **For agentic workers:** Follow this plan exactly. Use `superpowers:executing-plans` when implementing. This editor is a dedicated page, not a nested bubble stack.

**Goal:** 建立单个 ContentGroup 的详细编辑页面：编辑 topic / role / summary / identity，管理 members，创建 Petals，并把 members 分配到 Petals。
**Experience Test Policy:** 默认不使用 browser harness。体验测试优先 browser-use / in-app browser。
**Stop Point:** 用户能把粗暴丢进来的内容包拆成更细的花瓣。

---

## 0. 版本定位

8.6.19 是 ContentGroup 真正成为 “整理盒子” 的版本。Groups Rail 负责轻量入口，Group Gallery 负责浏览，Single Editor 负责精加工。

## 1. 不做什么

- 不做 AI 自动拆 Petal。
- 不做 Petal 高级排序。
- 不做表格/图片局部 item。
- 不做 relation graph。
- 不做最终视觉设计系统。

## 3. 实施任务

### Task 1: 页面入口

- [ ] 从 Gallery 点击 group 进入 single editor。
- [ ] 从 Groups Rail 的 group 摘要进入 single editor。
- [ ] 页面有返回 Gallery 的路径。
- [ ] 页面显示 group 所在 folder path。

### Task 2: Group 基础字段

- [ ] 编辑 display name。
- [ ] 编辑 topic。
- [ ] 编辑 role。
- [ ] 编辑 summary。
- [ ] 编辑 identity：draft / accepted / rejected / archived。
- [ ] 所有字段自动保存或明确保存，但行为必须一致。

### Task 3: Members 管理

- [ ] 显示 member 列表。
- [ ] 每个 member 显示来源类型：draft range / label / block。
- [ ] 每个 member 显示 preview。
- [ ] 每个 member 可从 group 移除。
- [ ] 移除 member 不删除原文。

### Task 4: Petal 管理

- [ ] 新建 Petal。
- [ ] Rename Petal。
- [ ] Delete Petal。
- [ ] Petal 至少包含 `name`、`role` 或等价局部说明、`members`。
- [ ] Petal 不依赖 child label。

### Task 5: Member 分配到 Petal

- [ ] 用户可以把 member 分配到一个 Petal。
- [ ] 一个 member 可暂时只支持属于一个 Petal。
- [ ] 如果未来需要多 Petal 复用，先留服务接口，不在本版强做。
- [ ] 未分配 member 应清楚显示。

### Task 6: 文本同步边界

- [ ] Single editor 中展示的 member preview 要能反映原文更新。
- [ ] 本版不强制支持在 Single editor 中直接改写原文。
- [ ] 如果已有 range preview 编辑功能，必须确认不会破坏 source truth。

## 4. 合格标准

- 能从 Gallery / Rail 进入 single editor。
- 能编辑 group 基础字段。
- 能查看、移除 members。
- 能创建、重命名、删除 Petals。
- 能把 member 分配到 Petal。
- Petal 不再是 child label 的另一个名字。
