# V2.BN.8.9.14 Layout Panel And PageStack Navigator Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the Layout panel a real PageStack navigator, so users manage single-page and multi-page PageStacks instead of hidden or standalone PageFrames.

**Status:** Completed first implementation pass on 2026-06-27. See `V2.BN.8.9.14-Layout-Panel-And-PageStack-Navigator-Patch-Note.md`.

**Architecture:** Keep `PageFrame` as the internal physical page and make `PageStack` the user-facing page unit. Normalize user-facing page operations so creating, inserting, duplicating, detaching, splitting, and merging pages never leave a top-level standalone PageFrame. Reuse the existing PageFrame collection metadata and PageStack service instead of introducing a new persistence table in this version.

**Tech Stack:** React, TypeScript, CSS modules, existing Canvas Engine runtime services, `canvasEngineModelContractCheck.ts`, Vite client build.

---

## 1. Product Contract

The 8.9.14 naming and behavior contract is:

1. User-facing page unit is `PageStack`.
2. A PageStack can contain one PageFrame or many PageFrames.
3. Creating a page creates a single-page PageStack.
4. Adding page below grows the selected PageStack.
5. Detaching a page creates a new single-page PageStack.
6. Splitting a PageStack creates two PageStacks.
7. Merging PageStacks appends source stack pages into target stack.
8. PageFrame remains the internal physical page object.
9. This version does not implement automatic pagination, PageSlice snapshots, cross-page block fragments, or TextFlow typography controls.

1. Layout panel can serve as the main PageStack navigator.
2. Visible page creation creates PageStacks, not standalone PageFrames.
3. Existing legacy/unstacked PageFrames are normalized into single-page PageStacks.
4. Split / merge / detach preserve PageStack coverage.
5. No visible UI calls a user-facing page an independent PageFrame.
6. Model contract, runtime boundary, client build, and diff check pass.
