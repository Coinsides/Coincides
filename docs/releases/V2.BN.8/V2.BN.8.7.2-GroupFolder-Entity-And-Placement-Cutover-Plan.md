# V2.BN.8.7.2 GroupFolder Entity And Placement Cutover Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 把 `GroupFolder` 和 `ContentGroup` 的 folder placement 从 note metadata / ContentGroup JSON payload 中切出来，成为独立、可查询、可迁移、可被 Gallery / Rail / Single Editor 共用的资源管理实体。

**Architecture:** `GroupFolder` 是组织位置和 Gallery scope 的 truth，不是 source truth，也不是 ContentGroup 的语义内容。8.7.2 新增 `group_folders` 与 `content_group_folder_placements` 两层：前者保存 folder 树和 scope，后者保存 ContentGroup 出现在 folder 中的关系；`content_groups.primary_folder_id` / `placements_json` 在本版本只作为兼容镜像或 hydrate cache，不再作为长期 truth。旧 `notes.metadata.canvas_engine_group_folders_v1` 只保留为 legacy import/fallback 输入。

**Tech Stack:** SQLite / better-sqlite3 migrations, Express routes, Zod validators, React 18, TypeScript, existing ContentGroup repository, existing GroupFolder runtime services, model-contract smoke checks, browser/manual experience gate.

---

## 0. Why This Version Exists

8.7.1 已经把 `ContentGroup` root entity 从 note metadata 中切出来了，但 `GroupFolder` 仍然存在于：

```text
notes.metadata.canvas_engine_group_folders_v1
```

同时 ContentGroup 的组织位置还以两种兼容字段存在：

```text
content_groups.primary_folder_id
content_groups.placements_json
```

这在 8.7.1 可以接受，因为当时目标是先把 ContentGroup 本体独立出来。但如果继续让 folder 留在 note metadata，后续会出现几个明显问题：

1. Gallery 作为资源管理器时，必须扫描所有 notes 才能知道 folder 树。
2. Project / Workspace / Cross-project folder 不能自然成立，因为 folder truth 绑在某篇 note 上。
3. ContentGroup 移动 folder 时，组织行为和 ContentGroup body payload 继续耦合。
4. 未来 saved graph scope / AI temporary projection folder / cross-note review folder 会被迫复用 note metadata。
5. Member / Petal 独立化之后，如果 folder 仍未独立，整个 ContentGroup System 的组织层还是不稳。

所以 8.7.2 的目标不是视觉套壳，而是把资源管理器的地基补上：

```text
GroupFolder = independent organization entity
ContentGroupFolderPlacement = relationship between a group and a folder
Folder move/copy/delete = organization operations only
ContentGroup member/source/petal truth = unchanged
```

## 2. Product Rules

### 2.1 The Core Split

```text
GroupFolder
  organization truth
  browsing path
  Gallery scope
  future local graph boundary

ContentGroup
  serious content package
  identity/status
  members/fragments/petals

ContentGroupFolderPlacement
  "this group appears in this folder" relationship

ContentGroupMember / SourceAnchor
  content truth and source location truth
```

### 2.2 What Folder Operations Must Not Do

Folder operations must not:

- edit original TextFlow;
- edit AnnotationTruth;
- edit member `current_content`;
- refresh member source snapshot;
- move Petal fragments;
- rewrite source provenance;
- create relation truth;
- materialize blocks.

The most important invariant:

```text
moving a group between folders changes organization, not source truth.
```

### 2.3 System Root Folders

Project and Note remain document scopes, not folders. But each may own lifecycle-bound system roots:

```text
Workspace root folder
Project root folder
Note root folder
```

Rules:

- system roots are created by server service, not by ad hoc client metadata helpers;
- system roots cannot be deleted by user folder delete;
- system roots can contain user-created folders and ContentGroups;
- deleting a project/note later may archive or cascade its roots, but that is not implemented in this version beyond safe ownership checks.

### 2.4 Folder Placement Rule

First version supports one primary placement per ContentGroup.

The schema should still allow later reference placements:

```text
primary:
  the canonical organization location for normal browsing

reference:
  future additional appearance without changing canonical home

temporary:
  future AI projection / saved scope candidate
```

8.7.2 only needs `primary` in normal UI.

```ts
import type Database from 'better-sqlite3';

  description: 'Add v2 GroupFolder entity and ContentGroup folder placement tables',
  up(db: Database.Database): void {
    db.exec(`
      CREATE TABLE IF NOT EXISTS group_folders (
        id TEXT PRIMARY KEY,
        user_id TEXT NOT NULL REFERENCES users(id) ON DELETE CASCADE,
        course_id TEXT REFERENCES courses(id) ON DELETE CASCADE,
        note_id TEXT REFERENCES notes(id) ON DELETE CASCADE,
        parent_folder_id TEXT REFERENCES group_folders(id) ON DELETE SET NULL,

        scope_kind TEXT NOT NULL DEFAULT 'note',
        scope_project_id TEXT,
        scope_note_id TEXT,
        scope_label TEXT,

        title TEXT NOT NULL,
        origin TEXT NOT NULL DEFAULT 'user',
        system_root INTEGER NOT NULL DEFAULT 0,
        status TEXT NOT NULL DEFAULT 'active',
        order_index INTEGER NOT NULL DEFAULT 0,
        metadata TEXT NOT NULL DEFAULT '{}',
        created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
        updated_at DATETIME DEFAULT CURRENT_TIMESTAMP
      );

      CREATE INDEX IF NOT EXISTS idx_group_folders_user_scope
        ON group_folders(user_id, scope_kind, scope_project_id, scope_note_id, status);
      CREATE INDEX IF NOT EXISTS idx_group_folders_course_note
        ON group_folders(user_id, course_id, note_id, status);
      CREATE INDEX IF NOT EXISTS idx_group_folders_parent
        ON group_folders(user_id, parent_folder_id, status);
      CREATE INDEX IF NOT EXISTS idx_group_folders_order
        ON group_folders(user_id, parent_folder_id, order_index, title);
    `);
  },
};
```

Why keep both `course_id/note_id` and `scope_*`:

- `course_id` / `note_id` support fast ownership joins and route filters.
- `scope_*` preserves the runtime `GroupFolderScopeV1` shape and future custom scope labels.
- workspace folders can have `course_id = null`, `note_id = null`, `scope_kind = 'workspace'`.

### 4.3 Compatibility With content_groups

Do not remove these columns in 8.7.2:

```text

```

Instead:

- on read, hydrate them from placement table when placement rows exist;
- on write, update them as compatibility mirror only after placement upsert succeeds;
- if placement table has no row, fallback to old fields and import a placement row.

## 6. Compatibility Strategy

### 6.1 Read Order

For a note:

```text
1. GET /api/group-folders?note_id={noteId}
2. If entity folders exist, use them.
3. If entity folders are empty and note metadata has legacy folders, import note metadata folders.
4. After import, use entity folders.
5. If import fails, show legacy folders read-only enough for visibility and log the degraded state.
```

For a project:

```text
1. GET /api/group-folders?course_id={courseId}
2. Ensure workspace/project roots exist.
3. Include note roots when notes are part of Gallery record loading.
```

### 6.2 Write Order

New writes:

```text
folder create/rename/archive/delete -> group_folders
group move between folders -> content_group_folder_placements
```

Do not write new folder state back to:

```text
notes.metadata.canvas_engine_group_folders_v1
```

### 6.3 Legacy Cleanup

Add helper:

```ts
export function stripLegacyGroupFolderMetadata(
  metadata: Record<string, unknown> | undefined,
): Record<string, unknown> {
  const next = { ...(metadata || {}) };
  delete next[NOTE_GROUP_FOLDERS_METADATA_KEY];
  return next;
}
```

Use it only after successful import/save, and only if it does not delete ContentGroup metadata fallback needed by old tests. Because 8.7.1 already strips legacy ContentGroup metadata on folder-only saves, 8.7.2 should be careful not to reintroduce either metadata key as active truth.

```ts
type GroupFolderStatus = 'active' | 'temporary' | 'archived' | 'deleted';
type GroupFolderOrigin = 'user' | 'system' | 'ai';
type GroupFolderScopeKind = 'workspace' | 'project' | 'note' | 'custom' | 'temporary';

interface GroupFolderRow {
  id: string;
  user_id: string;
  course_id: string | null;
  note_id: string | null;
  parent_folder_id: string | null;
  scope_kind: string;
  scope_project_id: string | null;
  scope_note_id: string | null;
  scope_label: string | null;
  title: string;
  origin: string;
  system_root: number;
  status: string;
  order_index: number;
  metadata: string;
  created_at: string;
  updated_at: string;
}

function parseJson(value: string | null | undefined): Record<string, unknown> {
  if (!value) return {};
  try {
    return JSON.parse(value) as Record<string, unknown>;
  } catch {
    return {};
  }
}

function hydrateGroupFolder(row: GroupFolderRow) {
  return {
    id: row.id,
    title: row.title,
    parent_folder_id: row.parent_folder_id,
    scope: {
      kind: row.scope_kind as GroupFolderScopeKind,
      project_id: row.scope_project_id,
      note_id: row.scope_note_id,
      label: row.scope_label,
    },
    origin: row.origin as GroupFolderOrigin,
    system_root: row.system_root === 1,
    status: row.status as GroupFolderStatus,
    order_index: row.order_index,
    created_at: row.created_at,
    updated_at: row.updated_at,
    metadata: parseJson(row.metadata),
  };
}
```

- [x] **Step 5: Implement upsertGroupFolder**

The upsert must:

- preserve deterministic id when supplied;
- verify parent folder belongs to same user;
- reject moving a folder under itself;
- reject direct parent cycles before writing;
- set `system_root` from input only for system calls, not arbitrary public calls.

Minimum function:

```ts
export function upsertGroupFolder(db: Database.Database, userId: string, input: Record<string, any>) {
  const id = typeof input.id === 'string' && input.id.trim() ? input.id.trim() : `group-folder-${uuidv4()}`;
  const scope = input.scope || {};
  const now = new Date().toISOString();
  const values = {
    id,
    user_id: userId,
    course_id: typeof scope.project_id === 'string' ? scope.project_id : null,
    note_id: typeof scope.note_id === 'string' ? scope.note_id : null,
    parent_folder_id: typeof input.parent_folder_id === 'string' ? input.parent_folder_id : null,
    scope_kind: typeof scope.kind === 'string' ? scope.kind : 'note',
    scope_project_id: typeof scope.project_id === 'string' ? scope.project_id : null,
    scope_note_id: typeof scope.note_id === 'string' ? scope.note_id : null,
    scope_label: typeof scope.label === 'string' ? scope.label : null,
    title: typeof input.title === 'string' && input.title.trim() ? input.title.trim() : 'Untitled folder',
    origin: input.origin === 'system' || input.origin === 'ai' ? input.origin : 'user',
    system_root: input.system_root ? 1 : 0,
    status: ['temporary', 'archived', 'deleted'].includes(input.status) ? input.status : 'active',
    order_index: Number.isInteger(input.order_index) ? input.order_index : 0,
    metadata: JSON.stringify(input.metadata || {}),
    created_at: now,
    updated_at: now,
  };

  db.prepare(`
    INSERT INTO group_folders (
      id, user_id, course_id, note_id, parent_folder_id,
      scope_kind, scope_project_id, scope_note_id, scope_label,
      title, origin, system_root, status, order_index, metadata, created_at, updated_at
    ) VALUES (
      @id, @user_id, @course_id, @note_id, @parent_folder_id,
      @scope_kind, @scope_project_id, @scope_note_id, @scope_label,
      @title, @origin, @system_root, @status, @order_index, @metadata, @created_at, @updated_at
    )
    ON CONFLICT(id) DO UPDATE SET
      parent_folder_id = excluded.parent_folder_id,
      scope_kind = excluded.scope_kind,
      scope_project_id = excluded.scope_project_id,
      scope_note_id = excluded.scope_note_id,
      scope_label = excluded.scope_label,
```

```ts
export function shouldImportLegacyGroupFolders(input: {
  entityFolders: GroupFolderV1[];
  legacyFolders: GroupFolderV1[];
}): boolean {
  return input.entityFolders.length === 0 && input.legacyFolders.length > 0;
}

export function mergeEntityAndLegacyGroupFolders(input: {
  entityFolders: GroupFolderV1[];
  legacyFolders: GroupFolderV1[];
}): GroupFolderV1[] {
  if (input.entityFolders.length > 0) return input.entityFolders.map(normalizeGroupFolder);
  return input.legacyFolders.map(normalizeGroupFolder);
}

export async function loadGroupFoldersForNote(input: {
  note: Note;
  importLegacy?: boolean;
}): Promise<GroupFolderV1[]> {
  const response = await api.get<GroupFolderV1[]>('/group-folders', {
    params: {
      course_id: input.note.course_id,
      note_id: input.note.id,
    },
  });
  const entityFolders = normalizeGroupFolders(response.data);
  const legacyFolders = groupFoldersFromNoteMetadata({
    metadata: input.note.metadata,
    projectId: input.note.course_id,
    noteId: input.note.id,
  });

  if (input.importLegacy !== false && shouldImportLegacyGroupFolders({ entityFolders, legacyFolders })) {
    const imported = await api.post<GroupFolderV1[]>('/group-folders/import-note-metadata', {
      note_id: input.note.id,
      folders: legacyFolders,
    });
    return normalizeGroupFolders(imported.data);
  }

  return mergeEntityAndLegacyGroupFolders({ entityFolders, legacyFolders });
}
```
