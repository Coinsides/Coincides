# V2.BN.8.6.31 ContentGroup OpenDesign Visual Parity Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 把 8.6.23 已经拆出来的 ContentGroup 三层界面，真正迁移成 OpenDesign 三个 HTML 壳子的视觉和交互形态，而不是继续停留在临时表单 UI。

**Architecture:** 本版本不重写 ContentGroup 数据模型，只重写三层 surface 的视觉结构、组件边界和浏览器验收方式。OpenDesign HTML 是本版本的视觉契约，15:10 会议记录是交互边界契约：Rail = collect，Gallery = organize，Editor = refine。

**Tech Stack:** React, TypeScript, CSS Modules, Vite, lucide-react, existing ContentGroup / GroupFolder services.

---

## 1. 为什么必须单开 8.6.31

本计划原编号为 `V2.BN.8.6.24`。2026-06-21 复盘后，视觉对齐被后移到 `V2.BN.8.6.31`：原因是 Rail / Gallery / Single Editor 的按钮、菜单、拖拽、Folder、Petal、Source 同步还没有接稳，不能先给半成品套 OpenDesign 外观。

8.6.23 的计划目标是正确的：把 OpenDesign 三个 HTML 壳子本地化为 Coincides 的 ContentGroup 三层界面。

但当前落地结果只完成了功能结构拆分，没有完成视觉和交互等价迁移。用户看到的仍然像临时施工现场：

- Group Gallery 仍然像旧式资源页加表单页，缺少 OpenDesign 的资源管理器秩序。
- Groups Rail 仍然承载过多信息，不能只作为轻量收集入口。
- Single ContentGroup Editor 仍然像 metadata form，不像知识加工台。
- topic / role / identity 仍然偏向普通输入字段，没有形成清晰的视觉语言。
- 缺少“参考 HTML 截图 vs 本地页面截图”的硬验收。

所以 8.6.31 的目标不是“再补一点 UI”，而是在 8.6.24 到 8.6.30 把结构梁柱接稳之后，再纠正 8.6.23 没完成的核心迁移。

8.6.31 的前置条件：

- 8.6.24 已完成 Command Surface Reality Gate。
- 8.6.25 已完成 Unified Item / Content Range Drag Foundation。
- 8.6.26 已完成 GroupFolder Resource Manager Foundation。
- 8.6.27 已完成 Scope-Aware Groups Rail v2。
- 8.6.28 已完成 Single ContentGroup Editor Workbench Seed。
- 8.6.29 已完成 Petal Fragment Assignment v1。
- 8.6.30 已完成 Source Preview And Integrity Gate。

## 5. 视觉语言硬规则

### 5.1 总体风格

采用更接近 VS Code Settings / local resource manager 的密集工具风格：

- 边界清晰。
- 圆角克制。
- 不堆叠气泡卡片。
- 不把一堆输入框挤在一个浮窗里。
- 页面优先用分栏、列表、表格感、工作台，而不是“卡片套卡片”。

### 5.2 三种语义必须视觉分离

```text
Role = 小 type / badge / tab
Topic = color signal / color rail / path hint
Identity = status chip / icon
Folder = placement / hierarchy / resource path
```

要求：

- `role` 不再只是一个普通 input。
- `topic` 不再和 `role` 并排成两个毫无区分的表单格。
- `identity` 使用状态 chip 或 icon，不占大块文字空间。
- `folder` 通过树、路径、层级表达，不通过 ContentGroup 嵌套伪装。

### 5.3 禁止回退的 UI 形态

以下形态在本版本视为失败：

- Gallery 右侧常驻一组说明卡片，但主区仍旧稀疏。
- Rail 顶部出现大标题和大按钮堆。
- Rail 展开后出现完整 summary / topic / role / petal 表单。
- Single Editor 看起来像一个竖向 CRUD 表单。
- 每个输入框都是圆角气泡，密密麻麻挤在一起。
- 用户无法一眼区分“整理入口”“全局管理”“细节加工”三个界面。

## 14. 手动测试清单

用户手动测试时按这个顺序：

## 15. 版本合格标准

8.6.31 合格必须同时满足：

- 三个界面能用。
- 三个界面角色不混。
- 三个界面视觉接近 OpenDesign 壳子。
- 不再把 topic / role / identity 处理成同质表单字段。
- Rail 不再像 mini editor。
- Gallery 不再像临时管理表。
- Single Editor 不再像 CRUD form。
- Browser 截图能证明本地页面已经从旧视觉迁移到 OpenDesign 方向。

如果只是构建通过，但视觉仍然像当前截图，这个版本不算完成。

## 16. 后续版本候选

8.6.31 完成后，后续才继续考虑 relation 和 AI 相关能力。以下内容不应该倒灌回 8.6.31：

- relation endpoint readiness。
- relation graph / inspector。
- AI 自动整理 ContentGroup。
- AI 自动生成 Petal。
- table / image / canvas object item。
- source document structured snapshot 新体系。

这些不能混进 8.6.31，否则会再次把视觉迁移做散。
