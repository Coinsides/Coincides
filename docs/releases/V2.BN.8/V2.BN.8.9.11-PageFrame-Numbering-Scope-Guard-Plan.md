# V2.BN.8.9.11 PageFrame Numbering Scope Guard Plan

Date: 2026-06-27

Status: completed

## Goal

Stop independent PageFrames in a note-level `PageFrameCollection` from being displayed as one continuous page-number sequence before `PageStack / Continuous PageFrame` exists.

## Product Judgment

`PageFrameCollection` is only the Canvas-level collection of PageFrame objects. It is not a continuous document stack.

Until a real `PageStack / Continuous PageFrame` model exists, a newly created independent PageFrame must not automatically become page 2 of the previous PageFrame. Page numbering can still exist as generated PageFrame chrome, but its scope must not imply a stack that the user did not create.

## Scope

In scope:

- Keep header/footer/page-number slots available.
- Keep single PageFrame page number behavior.
- Guard runtime PageFrame extension generation so independent PageFrames do not receive collection-global `index / total` numbering.
- Add model-contract coverage for this decision.
- Add runtime-boundary coverage so the regression is harder to reintroduce.
- Record that true stack-local numbering belongs to the future PageStack / Continuous PageFrame pass.

Out of scope:

- Implementing PageStack / Continuous PageFrame.
- Implementing PageSlice extraction, split, merge, or collapse.
- Implementing PageFrame move/resize.
- Implementing durable generic CanvasObject / CanvasPlacement DB cutover.
- Implementing typography controls.
