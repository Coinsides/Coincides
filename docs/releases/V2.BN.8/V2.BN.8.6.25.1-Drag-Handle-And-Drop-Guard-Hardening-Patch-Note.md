# V2.BN.8.6.25.1 Drag Handle And Drop Guard Hardening Patch Note

## Fixed Draft Range Drag Handle

- Draft Range drag entry is now a floating overlay handle, not a text badge inserted into the writing flow.
- The handle uses a small move icon with a larger invisible hit area.
- The selected TextUnit row is lifted above neighboring rows while a Draft Range handle is visible, so the handle is not covered by adjacent textarea layers.
- Clicking or mouse-down on the handle no longer clears the current Draft Range.
- The handle keeps writing `draft_range` payload through the unified ContentGroup drag service.

## Source Protection

- Dragging Draft Range into ContentGroup targets continues to create member references only.
- Original text remains in place.
- The member preview remains cache; source ranges remain truth.

## Guarded Behaviors

These are intentionally still not opened in 25.1:

- Dragging directly from the highlight paint layer.
- Dropping Draft Range or Label onto Page / Canvas blank space to create a new block.
- Reordering text inside the same TextBlock through drag.
- Assigning dragged ranges directly into Petals.

## Manual Test Checklist

- Select part of one TextUnit and confirm the handle appears above the selected text without moving the text line.
- Click the handle and confirm the Draft Range stays visible.
- Drag the handle into a Groups Rail row and confirm the group member count increases.
- Drag the handle into Gallery / Single Editor targets and confirm members are appended.
- Try dropping the handle on a non-ContentGroup area and confirm no source text is moved or deleted.
