# V2.BN.8.6.13-8.6.22 ContentGroup Gallery And Editor Patch Note

**Date**: 2026-06-19

**Status**: ready for manual test

## What Changed

- Added a shared ContentGroup metadata service so note metadata reads/writes use one source for `content_groups`, `group_folders`, annotations, reading interpretations, and proposals.
- Added folder-derived ContentGroup depth normalization. `depth` is now derived from `GroupFolder` path instead of being treated as an independent user-facing field.
- Added ContentGroup / GroupFolder graph integrity checks:
  - missing folder placement
  - missing member source
  - Petal member source not present in the parent ContentGroup
  - accepted group containing stale or orphaned member data
  - missing folder parent
  - folder parent cycles
- Added a reusable ContentGroup drag payload service for `Draft Range`, `Label`, and future block/object intake.
- Added draggable `Draft Range` and `Label` badge sources in TextBlock projection.
- Added drop support in the Note-side Groups Rail:
  - dropping on the rail intake area creates a new group
  - dropping on an existing group appends members
  - selected text / selected label / selected block member creation still works through the existing selection path
- Added a full-page `Group Gallery` route at `/group-gallery`.
- Added a left navigation entry for `Group Gallery`.
- Added a Groups Rail button that opens the current note/folder in the full Gallery.
- Added Gallery v1 with three modes:
  - `Folder`: organization/path browsing
  - `Topic`: local topic grouping
  - `Role`: local role grouping
- Added Gallery-level folder browsing and folder creation for the selected note scope.
- Added Single ContentGroup Editor v1 inside the Gallery:
  - title editing
  - topic / role / summary editing
  - identity state actions: save draft, accept, reject
  - member preview list
  - Petal creation, rename, and archive
  - note jump link
- Added a dedicated canvas model contract check group: `ContentGroup and GroupFolder contract`.

## Product Shape

This patch moves ContentGroup work from a cramped right-side-only workflow toward the three-surface model from the 2026-06-18 15:10 meeting:

```text
Groups Rail = collect
Group Gallery = organize
Single ContentGroup Editor = refine
```

The first version is now structurally usable:

- Rail can collect current note content and send the user to the Gallery.
- Gallery can browse folders/groups across projects and notes.
- Single Editor can refine a selected group without pretending to be the global manager.

## Boundaries

Not finished in this patch:

- Full visual redesign with `taste` quality pass.
- Complete right-click command surface update for ContentGroup actions.
- Dragging selected content directly from the main note canvas into the full-page Gallery after navigation.
- Block-level drag source. This is intentionally deferred because it can conflict with layout dragging.
- Petal-level member splitting UI for breaking one Label into multiple Petal assignments.
- Full folder manager operations such as moving folders and cross-project copy/move.
- Browser/manual UX verification. This patch stops at the code + contract + build readiness gate.
