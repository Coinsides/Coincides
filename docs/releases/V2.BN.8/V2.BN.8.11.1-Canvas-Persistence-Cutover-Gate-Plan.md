# V2.BN.8.11.1 Canvas Persistence Cutover Gate Plan

> Status: completed
> Date: 2026-06-27
> Owner: Henry + Codex
> Source spec: `docs/agent-ops/handoffs/2026-06-27-canvas-persistence-cutover.md`

## 1. Goal

Turn the three load-bearing Canvas persistence seeds into durable DB-backed truth before ContentGroup projection begins.

Seeds to cut over:

1. PageFrame / PageStack collection from `note.metadata['canvas_engine_page_frames_v1']`.
2. per-block layout from `note_block_placements.display_overrides_json['better_notebook_layout']`.
3. AnnotationTruth from `note.metadata['canvas_engine_annotations_v1']`.

This version is infrastructure. It should make later Object Projection and Reuse safer, not add new visible product scope.

## 2. Decisions Already Accepted

- This belongs to V2.BN.8.11, not V2.BN.8.10.
- This is not a patch; it is the first 8.11 subversion.
- Use one unified `canvas_placements` table for PageFrame, block projection, and future CanvasObject placement.
- Use `annotation_ranges` as a child table, not only a `ranges_json` blob.
- No long-term dual-write compatibility shim.
- Import legacy seed once, strip old keys after successful import, and prevent re-import duplication.
- Test data can be discarded; production-user backward compatibility is not the priority.

## 3. Data Model Target

### CanvasObject

Identity only:

- `object_id`
- `canvas_id`
- `note_id`
- `kind`
- `backing`
- `object_class`
- `status`
- `source_json`
- timestamps

No geometry and no content mount live here.

### CanvasPlacement

Geometry and placement:

- `placement_id`
- `object_id`
- `canvas_id`
- `note_id`
- `x`
- `y`
- `width`
- `height`
- `rotation`
- `frame_id`
- `surface`
- `boundary_role`
- `z_index`
- `snap_state_json`
- `visibility_state`
- `render_visibility`
- timestamps

This is a unified table.

### ContentMount

Content backing:

- `mount_id`
- `object_id`
- `target_kind`
- `target_id`
- `projection_mode`
- `sync_policy`
- metadata / timestamps

PageFrame objects with `backing = none` do not need ContentMount.

### PageFrameExtension

PageFrame-specific meaning:

- `frame_id`
- `object_id`
- `page_stack_id`
- `page_index`
- `page_size_json`
- `content_inset_json`
- `typography_json`
- `background_json`
- `template_json`
- `slots_json`
- metadata / timestamps

### Page Collection Header

Add a small collection-level home for:

- `primary_frame_id`
- `selected_frame_id`
- `primary_stack_id`
- `selected_stack_id`
- `page_stacks_json`

Working name: `canvas_page_collections`.

### AnnotationTruth

Durable truth:

- `annotation_id`
- `note_id`
- `canvas_id`
- `raw_label`
- `parent_annotation_id`
- `child_annotation_ids_json`
- `visual_style_json`

- `status`
- timestamps
- metadata

### AnnotationRange

Child table:

- `range_id`
- `annotation_id`
- `block_id`
- `text_unit_id`
- `canvas_object_id`
- `start_offset`
- `end_offset`
- `snapshot_text`
- `range_json`
- metadata / timestamps

## 4. Work Plan

### Step 1 - Audit Existing Persistence

Confirm current read/write points:

- `pageFrameCollectionService.ts`
- `placementService.ts`
- `runtimeLayout.ts`
- `annotationTruthService.ts`
- `useNoteCanvasDataAdapter.ts`
- existing content group cutover migrations/services/routes/tests.

Output:

- short implementation note in the patch note;
- no code changes yet unless an audit check is trivial and safe.

### Step 2 - Server Migrations

Create:

- `035_v2_canvas_objects.ts`
- `036_v2_annotation_truths.ts`

Migration responsibilities:

- create durable tables idempotently;
- backfill from legacy note metadata and placement override blobs;
- strip `canvas_engine_page_frames_v1`;
- strip `canvas_engine_annotations_v1`;
- strip placement-level `better_notebook_layout`;
- avoid duplicate import on repeated migrate/load.

### Step 3 - Server Services / Validators / Routes

Add server modules mirroring the ContentGroup entity cutover style:

- `services/canvasObjects.ts`
- `services/annotationTruths.ts`
- `routes/canvasObjects.ts`
- `routes/annotationTruths.ts`
- validator schemas in `validators/index.ts`
- route registration in `server/src/index.ts`

Service semantics:

- replace-by-note for Canvas objects / placements / mounts / page frame extensions;
- replace-by-note for annotation truths / ranges;
- transaction boundaries around object + placement + mount writes;
- keep runtime IDs as strings, not UUID-only.

### Step 4 - Client Repositories And Cutover Gates

Add:

- `canvasObjectRepository.ts`
- `annotationTruthRepository.ts`
- pure cutover gate modules for import/merge/strip decisions.

Repository responsibilities:

- load durable entities first;
- import legacy seed only when durable truth is absent;
- save only durable truth after cutover;
- never resurrect stripped legacy blobs.

### Step 5 - Adapter Rewire

Update `useNoteCanvasDataAdapter.ts`:

- load PageFrame collection through repository;
- load AnnotationTruth through repository;
- persist PageFrame collection through repository;
- persist AnnotationTruth through repository;
- persist block layout through CanvasPlacement path;
- preserve existing save-generation optimistic guards and rollback behavior.

### Step 6 - Runtime Boundary Checks

Update boundary checks so they fail if:

- page frame collection writes to note metadata after cutover;
- annotation truth writes to note metadata after cutover;
- block layout writes `better_notebook_layout` after cutover;
- geometry is stored outside `canvas_placements`;
- annotation ranges are only stored as an opaque JSON blob.

### Step 7 - Tests

Add tests mirroring the group folder/content group cutover tests:

- migration creates tables idempotently;
- page frame round-trip;
- block placement round-trip;
- annotation truth + range round-trip;
- import-once does not duplicate rows;
- legacy keys are stripped after successful import;
- pageStacks / primary / selected state survives cutover.

## 7. Open Implementation Notes

- Use runtime IDs as strings; do not force UUID format.
- Prefer durable truth over legacy blob on load.
- Strip old seed only after successful import/write.
- Keep the migration best-effort but the runtime mechanism strict.
- If a malformed legacy entry cannot be mapped safely, skip it and record the decision in the patch note rather than guessing.
