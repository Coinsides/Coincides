# V2.BN.8.11.1.3 CanvasObject Pipeline Hardening Patch Note

> Status: completed
> Date: 2026-06-28
> Owner: Henry + Codex
> Scope: CloudCode review hardening / note_block mount uniqueness / delete and payload test coverage

## 为什么补这个小补丁

8.11.1.2 已经把 CanvasObject 的 kind-general pipeline 立起来，但 CloudCode 的审查继续指出了几个不会立刻在当前 UI 中爆炸、却会在 8.11.x 接入真实对象后踩响的缝。这个补丁只做 hardening，不发布任何新 CanvasObject kind，也不引入 shape / sticky / connector / image / table 的产品入口。

## 做了什么

1. 新增 migration `038_v2_canvas_note_block_mount_uniqueness`：
   - 清理历史重复 `note_block` mount。
   - 增加 partial unique index：同一个 CanvasObject 只能有一个 `target_kind='note_block'` 的 `content_mount`。
2. `paragraph_block_projection` 写入 mount 前会清掉同 object 的旧 `note_block` mount，避免合法更新撞唯一约束。
3. `saveCanvasObject` 增加防御：
   - 如果目标 objectId 已经是 `page_frame`，拒绝 generic save。
   - 如果目标 objectId 已存在且 kind 不同，拒绝 kind flip。
4. 补齐 cutover 测试：
   - duplicate `note_block` mount 被 DB 拒绝，`blockLayouts` 不会 fan-out。
   - block projection hard delete 会级联清掉 placement 与 content_mount。
   - probe round-trip 断言 metadata / placement / z_index 等 payload 保真。
   - `content_group_members kind='canvas_object'` 软指针删除后会变成 `target_id=NULL` 且 `source_sync_status='stale'`。
   - PageFrame objectId 不能被 generic save 改成 test probe。

## 明确没做

- 不补 NoteBlock 软删时的反向 projection 清理；这仍属于后续 NoteBlock/Object lifecycle hardening。
- 不把 active editor 的真实 UI 数据流改为 generic object 注入；这仍留给 8.11.3+ 的真实对象入口。
- 不发布任何新对象 UI。

## 处理 CloudCode H1-H5

- H1：已处理。用 DB partial unique index + 写入前清旧 mount，阻止 block-mount fan-out。
- H2：已处理。补 block delete 级联 placement/content_mount 的测试。
- H3：已处理。补 probe payload 保真断言。
- H4：已处理。补 ContentGroupMember 软指针清理测试。
- H5：已处理。generic save 拒绝已有 PageFrame objectId / kind flip。
