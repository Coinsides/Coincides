# V2.BN.8.11.7 Image / Asset-Backed CanvasObject Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:executing-plans` to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 让图片作为第一类 `asset-backed` CanvasObject 进入 8.11 通用画布管线：可上传 / 创建、可持久化、可读回、可渲染、可移动 / 缩放、可带 caption / alt text，并能进入 AI-readable layout。

**Architecture:** `canvas_objects` 保存对象身份，`canvas_placements` 保存画布布局；新增轻量 asset 存储层保存图片文件元数据与本地文件位置；新增 image typed extension 保存 CanvasObject 到 asset 的引用、展示参数、caption、alt text。图片是 media object，不是 TextFlow block，不是 SourceArtifact，不触发 OCR / parsing。

**Tech Stack:** React 18 + TypeScript + Vite；Node / Express + SQLite；现有 generic `saveCanvasObject` persistence；现有 canvas runtime / command / AI-tree model contract checks；现有 multer upload middleware 可作为参考，但本版需要 canvas image 专用边界。

---

## 0. Version Position

8.11.3 证明 `shape` 可以作为 pure CanvasObject 走通通用管线。
8.11.4 证明 CanvasObject 可以挂载 paragraph block，形成 block-backed object。
8.11.5 证明 sticky note 是 block-backed shape 的 presentation preset。
8.11.6 证明 `visual_connector` 可以作为 visual-only CanvasObject 持久化，并且不污染 Relation。

8.11.7 要证明第五件事：

```text
CanvasObject 可以引用外部文件资产
对象身份和布局仍然走 generic canvas pipeline
文件内容由 asset 层管理
AI-readable layout 读取图片的布局和可读元数据
TextFlow 不复制图片内容
SourceArtifact / OCR / Export 暂不进入本版
```

这一步是后续 table、media object family、工程包 export、Source parsing 之前必须打稳的 asset 接缝。

## 1. Scope Fence

### 1.1 This Version Does

- 新增图片 asset 存储基建：本地文件保存、数据库元数据、权限校验、读取 URL / blob route。
- 新增 `kind='image'` CanvasObject handler。
- 新增 `image_object_extensions` typed sidecar table，保存 `asset_id`、caption、alt text、fit mode、natural size 等。
- 支持创建 image object：从画布入口选择图片文件，上传 asset，再在指定位置创建 CanvasObject。
- 支持图片对象渲染、选择、移动、缩放、删除。
- 支持图片 caption / alt text 的最小编辑入口。
- 支持图片对象持久化和刷新后读回。
- 支持 AI-tree 输出 image readable node：bbox、asset ref、filename、mime、natural size、caption、alt text。
- 支持基础验证：只允许 image MIME；拒绝缺失 asset 的 image object；拒绝 image object 挂 TextFlow content mount。
- 增加 server / model / runtime / browser smoke 覆盖。
- 更新 8.11 主计划、Review / CHANGELOG / current-state 中本小版本结果。

### 1.2 This Version Does Not Do

- 不做 OCR。
- 不做 MinerU / document layout parsing。
- 不做 SourceArtifact / SourceAnchor。
- 不做图片裁剪、旋转、滤镜、标注、局部框选。
- 不做 inline image in TextFlow。
- 不做图片作为 ContentGroup member 的正式复用 UI。
- 不做工程包 export。
- 不做 PDF export 图片嵌入。
- 不做图片库 / asset library / 多文件管理器。
- 不做 drag from OS file explorer 的复杂路径；如果浏览器原生 file picker 已可用，本版先用 file picker。
- 不做 remote URL image embed，避免引入外链缓存、安全和离线问题。

### 1.3 Non-Negotiable Boundary

图片对象是 `asset-backed CanvasObject`，不是文档源，也不是正文内容：

```text
Right:
  CanvasObject.kind = image
  CanvasObject.backing = asset
  CanvasObject.objectClass = media
  ImageObject.assetId -> local canvas asset
  ImageObject.caption / altText -> readable metadata

Wrong:
  documents table
  SourceArtifact
  TextFlow block content
  ContentGroup member truth
  OCR result cache
  base64 blob inside note metadata
```

## 3. Data Contract

### 3.1 Canvas Asset Table

Add a canvas-specific but future-compatible asset table. Suggested name: `canvas_assets`.

Suggested columns:

```sql
CREATE TABLE IF NOT EXISTS canvas_assets (
  id TEXT PRIMARY KEY,
  user_id TEXT NOT NULL,
  course_id TEXT,
  origin_note_id TEXT,
  kind TEXT NOT NULL,
  storage_kind TEXT NOT NULL,
  storage_key TEXT NOT NULL,
  filename TEXT NOT NULL,
  mime_type TEXT NOT NULL,
  byte_size INTEGER NOT NULL,
  width INTEGER,
  height INTEGER,
  sha256 TEXT,
  metadata TEXT,
  created_at TEXT NOT NULL,
  updated_at TEXT NOT NULL
);
```

Rules:

- `kind` v1 only accepts `image`.
- `storage_kind` v1 only accepts `local_file`.
- `storage_key` is internal; do not expose absolute local file paths to client.
- `course_id` may be populated for current project context, but asset identity must remain project-independent-capable.
- `origin_note_id` records where the asset was first created, but does not mean the asset belongs only to that note forever.
- Do not put base64 image data into SQLite.
- Do not use `documents.file_path` as image asset truth.

### 3.2 Image Extension Table

Add a typed sidecar table. Suggested name: `image_object_extensions`.

Suggested columns:

```sql
CREATE TABLE IF NOT EXISTS image_object_extensions (
  object_id TEXT PRIMARY KEY,
  asset_id TEXT NOT NULL,
  fit TEXT NOT NULL DEFAULT 'contain',
  caption TEXT,
  alt_text TEXT,
  natural_width INTEGER,
  natural_height INTEGER,
  metadata TEXT,
  created_at TEXT NOT NULL,
  updated_at TEXT NOT NULL,
  FOREIGN KEY (object_id) REFERENCES canvas_objects(id) ON DELETE CASCADE,
  FOREIGN KEY (asset_id) REFERENCES canvas_assets(id)
);
```

Rules:

- Deleting an image object deletes its extension row through `ON DELETE CASCADE`.
- Deleting an image object does **not** delete the asset file in v1; asset garbage collection is a later cleanup job.
- `fit` v1 accepts `contain` and `cover`; default `contain`.
- `caption` is human-visible optional text.
- `alt_text` is AI / accessibility oriented optional text.
- `natural_width` / `natural_height` can duplicate asset dimensions for read convenience, but asset table remains the canonical asset metadata source.

### 3.3 CanvasObject Payload

Persist image object through the generic object route:

```ts
{
  id: string,
  kind: 'image',
  backing: 'asset',
  object_class: 'media',
  placement: {
    x: number,
    y: number,
    width: number,
    height: number,
    rotation: 0,
    z_index: number
  },
  image: {
    asset_id: string,
    fit: 'contain' | 'cover',
    caption?: string,
    alt_text?: string,
    natural_width?: number,
    natural_height?: number
  },
  metadata: {}
}
```

Validation:

- `kind='image'` requires `backing='asset'`.
- `kind='image'` requires `object_class='media'`.
- `image.asset_id` is required and must belong to the authenticated user.
- `placement.width` and `placement.height` must be positive.
- `rotation` v1 should remain `0`; rotation UI can come later.
- Reject `content_mount` for image.
- Reject `page_frame_extension`, `shape_extension`, `visual_connector_extension`, or sticky presentation as image payload.

## 4. User Experience Contract

### 4.1 Creation

Minimum acceptable v1:

1. User right-clicks blank canvas / page frame area.
2. Menu shows `Image`.
3. User selects a local image file.
4. Client uploads the file to canvas asset route.
5. Client creates an image CanvasObject at the clicked canvas point.
6. Object appears immediately and persists after reload.

Creation defaults:

- Initial width should respect natural image ratio.
- If natural width is large, clamp visible width to a reasonable v1 size, e.g. 360 px.
- Initial height follows aspect ratio.
- If dimensions cannot be read, use a stable fallback size, e.g. 320 x 200.
- Use `fit='contain'`.
- Empty caption and alt text are allowed.

### 4.2 Editing

Minimum acceptable v1:

- Select image object.
- Drag to move.
- Resize using existing object resize path if available.
- Right-click image object:
  - `Edit caption`
  - `Edit alt text`
  - `Fit: contain / cover`
  - `Delete`

If a polished inspector is too large, use a small dedicated prompt layer. Avoid relying on permanent browser `window.prompt` if an in-app prompt pattern already exists; if no pattern exists, a temporary prompt is acceptable only if documented as a v1 compromise.

### 4.3 Rendering

Image object should render as a plain media object, not as a card-heavy component.

Required DOM markers for smoke tests:

```html
data-canvas-object-kind="image"
data-canvas-image-object="true"
data-canvas-asset-id="..."
```

If caption exists, render it below the image within the object bounds or as a stable caption band. Caption must not resize the object unexpectedly.

## 5. AI-Readable Layout Contract

Image should enter AI-tree as a layout-readable media node:

```ts
{
  type: 'canvas_object',
  kind: 'image',
  objectId: string,
  bbox: { x, y, width, height },
  imageRef: {
    assetId: string,
    filename: string,
    mimeType: string,
    byteSize: number,
    naturalWidth?: number,
    naturalHeight?: number,
    caption?: string,
    altText?: string
  }
}
```

Rules:

- AI-tree reads image metadata and layout only.
- AI-tree does not pretend it has OCR / visual understanding.
- If caption / alt text are empty, output empty or omitted fields honestly.
- Do not invent image summaries.
- Do not expose local filesystem paths.

## 8. Risks and Mitigations

| Risk | Severity | Mitigation |
| --- | --- | --- |
| Accidentally reusing document upload as source truth | High | Keep canvas asset routes/tables separate from `documents`; document the boundary. |
| Base64 blobs pollute note metadata / SQLite | High | Store files on disk; DB stores metadata and storage key only. |
| Asset deletion semantics become dangerous | Medium | Do not delete files on object delete in v1; leave garbage collection for later. |
| Image object becomes invisible on failed blob load | Medium | Render placeholder with object bounds. |
| Cross-user asset leak | High | Auth-check metadata and blob route; return 404 for unauthorized. |
| Future SourceArtifact conflicts with canvas asset | Medium | Treat this as canvas-local asset substrate, not source/document parsing. |
| Caption changes resize object unexpectedly | Low | Caption band has stable constraints; object size remains placement truth. |
