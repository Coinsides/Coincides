# V2.BN.8.7.9 ContentGroup System Closure Gate Report

Date: 2026-06-23

Status: closure gate completed.

## Closure Question

```text
Can ContentGroup System 1.0 serve as a stable foundation before V2.BN.8.8 CanvasObject work starts?
```

Final answer:

```text
Yes. The core data model and three-surface workflow are mature enough to close the 8.7 ContentGroup lane.
Canvas-dependent reuse remains intentionally deferred to 8.8+.
```

## Scope Boundary

This report closes the ContentGroup maturity lane. It does not open a new feature track.

In scope:

- ContentGroup / GroupFolder / ContentGroupMember / ContentGroupPetal / ContentGroupFragment entity truth.
- Rail / Gallery / Single Editor role clarity.
- Member versus source boundary.
- Reuse vocabulary and Canvas handoff.
- Release evidence and known carry-forward risks.

Out of scope:

- CanvasObject implementation.
- SourceArtifact / SourceAnchor full migration.
- ContentGroupProjection records.
- relation runtime / GraphRAG.
- destructive source mutation.
- true source-text reorder / offset rebase.
- freeform Single Editor workbench.

## Task 1 - Entity And Metadata Closure Audit

Status: completed.

### Findings

- `ContentGroup` is now persisted through `/content-groups` and `content_groups`, not as the active `canvas_engine_content_groups_v1` note metadata array.
- Normal client save paths go through:
  - `client/src/pages/Notes/canvasEngine/contentGroupRepository.ts`
  - `client/src/pages/GroupGallery/groupGalleryData.ts`
  - `server/src/routes/contentGroups.ts`
  - `server/src/services/contentGroups.ts`
- `ContentGroupMember` is active truth in `content_group_members`.
- `ContentGroupPetal` is active truth in `content_group_petals`.
- `ContentGroupFragment` and Petal assignment are active internal structure in `content_group_fragments` and `content_group_petal_fragments`.
- `GroupFolder` is active organization truth in `group_folders`.
- ContentGroup placement is active organization relation in `content_group_folder_placements`.
- `GroupFolder` legacy metadata import strips `canvas_engine_group_folders_v1` after successful import.
- ContentGroup legacy metadata remains as import/fallback compatibility through `canvas_engine_content_groups_v1`, but normal save paths no longer write active truth back into note metadata.

### Legacy Compatibility Classification

| Path | Current role | Closure classification |
| --- | --- | --- |
| `canvas_engine_content_groups_v1` | legacy import / fallback when entity groups are absent | safe fallback; cleanup candidate |
| `canvas_engine_group_folders_v1` | legacy import only; stripped after import | accepted cleanup behavior |
| `members_json` on `content_groups` | legacy hydration fallback when member rows are absent | safe fallback; no active write truth |
| `fragments_json` / `petals_json` on `content_groups` | legacy hydration fallback when entity rows are absent | safe fallback; no active write truth |

### Source Boundary

Confirmed:

- `ContentGroupMember.current_content` is group-local content truth.
- `source_ref` / `content_range` locate where the member came from.
- `preview_text` is display cache and fallback preview, not a second editable truth.
- Editing a ContentGroup persists group/member/petal rows and does not mutate source note text.
- Deleting a member hard-deletes the member row and prunes Petal/Fragment structures that depend on it.

### Plan Drift

The 8.7.9 plan lists `client/src/pages/GroupGallery/contentGroupRepository.ts`, but the current file is:

```text
client/src/pages/Notes/canvasEngine/contentGroupRepository.ts
```

This is a stale path in the plan, not a product blocker.

## Task 5 - Release Closure Judgment

Status: completed.

Final judgment:

```text
ContentGroup System is mature enough to stop expanding in 8.7 and enter CanvasObject work in 8.8.
```

### Completed Foundations

- Root `ContentGroup` entity.
- `GroupFolder` and `content_group_folder_placements`.
- `ContentGroupMember` entity and group-local content truth.
- `ContentGroupPetal`, `ContentGroupFragment`, and Petal-fragment assignment entities.
- Three-surface role model:
  - Rail = collect.
  - Gallery = organize.
  - Single Editor = refine.
- OpenDesign shell alignment for Gallery, Rail, and scoped Single Editor.
- Stability summary and integrity visibility.
- Reuse vocabulary and service boundary.

### Accepted Carry-Forward

- SourceArtifact / SourceAnchor full system.
- CanvasObject projection / ContentGroup usage records.
- Reference / Duplicate / Fork / Materialize product UI.
- relation runtime / GraphRAG.
- AI-created Petals and AI organization flows.
- richer mobile/narrow Gallery polish.
- bundle/code-splitting cleanup for existing Vite warnings.

### Not Part Of 8.7

- destructive source mutation.
- true source-text reorder.
- offset rebase.
- full Single Editor freeform workbench.
- complete CanvasObject implementation.
