# V2.BN.8.6.2 TextUnit Immediate Editing Bugfix Patch Note

Date: 2026-06-16

## Problem

Henry's manual test found a blocking TextBlock / TextUnit editing regression after the selection and annotation work.

Observed behavior:

- A newly double-click-created block can accept temporary text, but the first real TextUnit appears only after the user clicks outside the block.
- Pressing Enter in that temporary state does not reliably create a visible, editable next TextUnit immediately.
- After the block is persisted into TextUnits, clicking inside existing text does not reliably restore a caret for normal text editing.
- The current selection / annotation layer may be stealing ordinary text clicks that should belong to TextUnit editing.

Product rule:

- Creating a text block must create an editable TextUnit immediately.
- A normal click inside text must mean "edit here."
- Drag selection or explicit selected ranges should mean "selection draft / annotate."
- Annotation interaction must not block ordinary writing.

## Patch Scope

- Make draft block creation TextUnit-first enough that the first TextUnit exists immediately.
- Keep the created block's local TextFlow draft in sync with its created `content_json.text_flow`; otherwise the UI can briefly fall back to plain text draft behavior after creation.
- Ensure Enter creates the next TextUnit immediately while editing.
- Ensure clicking existing TextUnit text can restore normal caret editing.
- Delegate ordinary TextBlock container clicks to the nearest TextUnit textarea so selecting the block shell does not leave the user in a no-caret state.
- Keep ordinary caret clicks out of the selection-draft hit-test path unless a draft selection already exists.
- Let native textarea clicks own exact caret placement; the annotation draft layer must not recompute and override caret position after a normal click.
- Guard delayed block autofocus so switching from another block does not override a caret the user has already placed inside the clicked TextUnit.
- Keep selection draft behavior for real text selection, not plain caret clicks.
