# V2.BN.8.11.1.2 Kind-General CanvasObject Pipeline Patch Note

> Status: completed
> Date: 2026-06-28
> Owner: Henry + Codex
> Scope: CanvasObject kind-general dispatch preflight / generic persistence / generic delete guard

## 为什么插入这个补丁

在正式进入 V2.BN.8.11 Structured Object Family 前，CloudCode 的 handoff 指出了一个会影响后续所有对象的地基问题：CanvasObject 数据层已经有 `canvas_objects` + `canvas_placements` 的通用核心，但 service / route / validator / repository 仍主要按 `page_frame` 与 `paragraph_block_projection` 两条特例路径工作。

本补丁作为 8.11.1.2 前置小版本，先把“通用派发地基”补上。它不发布 shape UI，不做 sticky / connector / image / table，也不提前进入 ContentGroup projection。

## 做了什么

1. 新增 server-side kind handler registry，现阶段注册：
   - `paragraph_block_projection`
   - `__test_probe`，仅用于测试通用派发，不进入产品 UI。
2. 新增 generic CanvasObject 保存入口：
   - `PUT /api/canvas-objects/by-note/:noteId/objects/:objectId`
   - payload 必须带 `kind` discriminator。
3. 新增 generic CanvasObject 删除入口：
   - `DELETE /api/canvas-objects/by-note/:noteId/objects/:objectId`
   - 第一阶段只服务普通对象；`page_frame` 明确拒绝走这条路。
4. `paragraph_block_projection` 旧保存 API 保留，但内部改为走 generic `saveCanvasObject`，旧前端调用不需要立刻重写。
5. `getNoteCanvasPersistence` 增加通用核心读回字段：
   - `canvasObjects`
   - `canvasPlacements`
   - `contentMounts`
   同时保留旧的 `pageFrameCollection` / `blockLayouts`，避免现有前端震荡。
6. block mount 读路径不再依赖 `content-mount:${placementId}` 的 id 约定，只按 `object_id + target_kind + note_id` 关联。
7. validator 从黑盒 `z.record(z.unknown())` 起步收紧：
   - 新增 generic `saveCanvasObjectSchema`
   - block layout 改用 placement core schema
   - malformed probe payload 会被拒绝，而不是静默兜底。
8. generic delete 会硬删普通对象，并清理 `annotation_ranges.canvas_object_id` 与 `content_group_members kind='canvas_object'` 的软指针。
9. 前端 repository 做兼容扩展：能接收通用核心字段，并提供 generic save/delete 方法；现有页面仍走旧调用。
10. `engineModel` 增加 persisted generic object / placement / mount 的最小注入入口，AI-readable snapshot 可以读取这些对象；契约测试用 persisted `shape` 证明通用 runtime/AI-tree 通道，不发布 shape UI。

## 明确没做

- 不发布用户可见 shape。
- 不做 object-style / sticky。
- 不做 visual connector。
- 不做 image asset 存储。
- 不做 table model。
- 不做 ContentGroup as CanvasObject projection。
- 不让 PageFrame 走 generic delete；PageFrame/PageStack 仍由专属 collection 语义管理。

## 决策点

1. `content_mount` id：本版不迁移旧 id，但读路径不再依赖 `content-mount:${placementId}` 约定。理由是避免数据迁移放大，同时拆掉后续 kind 继承 block-only id 约定的风险。
2. note_block 反向缺口：本版不处理“note_block 软删后清理 projection”的反向链路。理由是这属于 NoteBlock lifecycle，不是 CanvasObject kind-general dispatch 的最小地基；后续单独补。
3. block 旧路由：本版保留旧路由，但内部改为走 generic service。理由是保护现有前端调用，同时让写入地基先统一。
