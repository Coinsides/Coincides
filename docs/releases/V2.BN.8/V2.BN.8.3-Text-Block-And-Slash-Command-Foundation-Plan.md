## 1. Why This Version Exists

V2.BN.8.2 已经让 Canvas Shell、PageFrame、workspace、overlay anchor 进入可继续打磨的状态。下一步如果直接做画笔、shape 或无限画布高级体验，会有即时操作感，但会绕开一个更根本的问题：

```text
用户每天最常用的能力不是画笔，而是写字。
```

这次 philosophy 讨论确认了一个新的产品主轴：

```text
Coincides = text-first, structure-aware, canvas-capable notebook
```

也就是：

```text
Human writes naturally.
Coincides structures quietly.
AI reads clearly.
Canvas organizes spatially.
Relations keep knowledge alive.
```

因此 V2.BN.8.3 的价值不在于增加更多漂亮按钮，而是把“写作真相层”先想清楚。否则 heading、list、definition、formula、inline formula、source marker、relation endpoint、AI projection 会继续互相污染。

## 3. Foundation Decisions

本小版本先锁定以下产品判断。

### 3.1 TextBlock

```text
TextBlock = 默认自然写作容器。
```

它不是狭义 paragraph。它应该能承载：

- 连续文本；
- 段落 / heading / list / quote 等轻写作结构；
- inline formula / inline definition / inline source marker 等局部结构；
- 普通 rich text span；
- 未来 TextUnit / TextUnitGroup 的结构投影。

第一版实现不要求完整 TextUnit tree，但命名和 contract 必须避免把 `TextBlock` 误写成单行 paragraph。

### 3.2 TextUnit

```text
TextUnit = TextBlock 内部的语义写作单位。
```

规则：

```text
Enter 创建新的 TextUnit。
视觉自动换行不创建新的 TextUnit。
```

用户不需要看到 `TextUnit` 这个词。用户看到的是：

- 一段话；
- 一个 heading；
- 一个 bullet item；
- 一个 numbered item；
- 一个 todo item；
- 一个 toggle item；
- 一个 quote line。

V2.BN.8.3 应实现最小 TextUnit 数据结构和 fresh TextBlock 初始化路径，但不实现完整 TextUnit tree editor，也不为旧测试数据背 legacy adapter。第一版目标是让新建普通文本从一开始进入 TextUnit 路径，并让后续 writing role、AI projection、split/merge、TextUnitGroup 能在同一条数据路径上生长。

### 3.3 InlineStructuredObject

```text
InlineStructuredObject = TextUnit 内部被结构化标记的局部知识对象。
```

候选类型：

```text
InlineFormula
InlineDefinition
InlineCode
InlineSourceMarker
InlineLink
InlineConceptMention
InlineClaim
```

V2.BN.8.3 只需要保留概念和最小入口，不实现完整 inline object runtime。当前阶段尤其要避免用脚本猜 definition / formula 的内部含义。

### 3.4 TextUnitGroup

```text
TextUnitGroup = 可递归、可命名、可寻址的知识区域。
```

它可以包含：

```text
TextUnit
TextUnitGroup
```

不要新建 `GroupOfTextUnitGroup` 这种概念。递归的 `TextUnitGroup` 足够表达：

- 三个自然段共同构成一个 definition；
- A/B/C 三组共同构成理解 D 的前置条件；
- 一组 proof steps 作为一个 relation endpoint；
- 一个 source claim 对应多个 TextUnit。

V2.BN.8.3 不做 TextUnitGroup 编辑器，但要实现最小类型和 projection/debug seed。它可以先不被用户直接操作，但代码层不能继续假设“只有 NoteBlock 才能成为未来可寻址知识对象”。

### 3.5 Three Roles

必须分开三层：

```text
writing_role
  它如何作为文本被写和显示。

knowledge_role
  它在知识结构里扮演什么角色。

semantic_kind
  它作为局部 inline 对象是什么。
```

例子：

```text
TextUnit:
  writing_role: bullet_item
  knowledge_role: example

InlineStructuredObject:
  semantic_kind: inline_formula
```

V2.BN.8.3 的代码实现优先做 `writing_role`。`knowledge_role` 和 `semantic_kind` 先写入 contract / open issue，除非已有低风险入口。

### 3.6 Addressable Content Endpoint

未来 relation / source / AI projection 不应只认 `NoteBlock`。

```text
AddressableContentEndpoint:
  Note
  PageFrame
  NoteBlock
  TextUnit
  TextUnitGroup
  InlineStructuredObject
  AnchoredSpan
  SourceSnapshotObject
```

V2.BN.8.3 不实现这些 endpoint runtime，只更新 relation / product 文档边界，避免后续继续把 `NoteBlock` 写成唯一节点。

## 5. Slash Command Model

Slash command 的正式定位：

```text
Slash Command = context-aware writing command palette
```

它至少要区分四类动作。

```text
create_block
  在空位置或空 draft 中创建新的 NoteBlock。

convert_block
  把当前 block 或当前 TextUnit 转换为另一种 writing role / block type。

insert_structure
  在当前 TextBlock 内插入结构，例如 list item、divider seed、inline link seed。

inline_action
  对选区或光标附近内容执行动作，例如 convert selected text to inline formula。
```

### Context Rules

同一个命令必须根据上下文改变含义：

```text
empty draft
non-empty text block
selected text
structured block
page frame
scratch workspace
```

例子：

```text
空 draft + /formula
  -> create_block: FormulaBlock

非空 TextBlock + /formula
  -> convert_block: 原文保守搬入 FormulaBlock.latex_input

选中文本 + /formula
  -> inline_action: future InlineFormula

FormulaBlock 内部 + /formula
  -> 不创建嵌套 FormulaBlock；显示 help 或保持无操作
```

```text
空 draft + /heading
  -> create_block: TextBlock with heading role

非空 TextBlock + /heading
  -> convert_block: 当前 TextUnit / block 转 heading role

选中文本 + /heading
  -> 暂不支持或解释原因，不要默默破坏文本
```

### First Command Groups

V2.BN.8.3 第一版 command groups：

```text
Default
  Text
  Heading 1
  Heading 2
  Heading 3
  Bullet List
  Numbered List
  Todo List
  Toggle List
  Quote
  Divider
  Code

Math
  Formula Block
  Inline Formula
  Definition

User Defined
  future templates / future knowledge roles
```

暂时不做：

```text
Table
Image
PDF
Callout
Add Source
Create Relation
Role Slot Mapping
```

这些可以在菜单里保留 disabled / future label，但不要让用户误以为当前可用。

## 15. Risks And Guardrails

- [ ] **Risk: Menu hell.**
  - Guardrail: Slash command only exposes current-context useful commands. Future AI/source/relation commands can live in right-click, selection toolbar, inspector, side palette, or AI proposal.

- [ ] **Risk: Recreating Notion without Coincides identity.**
  - Guardrail: Copy mature writing grammar only. Coincides identity is text-first writing plus structure-aware knowledge projection.

- [ ] **Risk: Making every visual format a block type.**
  - Guardrail: Heading/List/Quote are writing roles. Independent NoteBlock is for layout, media, code, large formula, table, image, source snapshot, or strong object manipulation.

- [ ] **Risk: Overbuilding TextUnitGroup too early.**
  - Guardrail: Document the model now. Runtime later.

- [ ] **Risk: Script-based semantic guessing.**
  - Guardrail: No colon guessing, no regex definition extraction, no pretend-AI. Conservative transfer only.

- [ ] **Risk: Mixing Link / SourceReference / ObjectRelation.**
  - Guardrail: Link remains navigation. SourceReference remains evidence. ObjectRelation remains semantic relation.

- [ ] **Risk: Breaking existing canvas shell.**
  - Guardrail: V2.BN.8.3 should not rewrite canvas shell unless slash menu / overlay anchor forces a small local change.
