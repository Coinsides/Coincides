# V2.BN.8.6.11-8.6.12 ContentGroup Engine Patch Note

**Date**: 2026-06-18

**Status**: ready for Henry manual test

## What Changed

- Added `GroupFolderV1` as the organization/path layer for ContentGroup work.
- Added note/project system root folder seeding in note runtime metadata.
- Added `canvas_engine_group_folders_v1` metadata persistence next to existing ContentGroup metadata.
- Added folder-aware ContentGroup creation and move-to-folder support.
- Added model support for ContentGroup members that can reference annotations, text ranges, blocks, other ContentGroups, and future object/region placeholders.
- Added `ContentGroupFragmentV1` and fragment references on Petals as the seed for later member-to-Petal refinement.
- Added derived `ContentGroupIndex` for folder-scoped listing, filtering, and integrity summaries.
- Added relation endpoint candidate projection from active ContentGroups and their members/Petals without creating relation edges.
- Added ContentGroup command-surface entries from text selection, annotation highlight, and block shell context menus.
- Updated ContentGroup/GroupFolder and Command Surface contracts to match the current seed.

## Product Boundary

This patch does not finish the full ContentGroup Gallery. The current UI is a hand-testable Groups panel with a folder pane, group list, detail area, member management, and Petal management.

This patch also does not implement relation runtime, AI-generated folders, full drag-and-drop into groups, image/table/source region extraction, or a production migration path. Current data remains test data.

## Technical Notes

- Folder placement changes organization only. It does not rewrite source truth.
- Older ContentGroups without `folder_id` are still visible from the note root so test data does not disappear before reset.
- `ContentGroupIndex` and relation candidates are derived views, not database truth.
- Future object/region member kinds are represented but treated as placeholder/unsupported until their real editors exist.
