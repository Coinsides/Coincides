# V2.BN.8.6.3 Source-Backed Annotation Range Editing Patch Note

## Scope

This patch closes the data-consistency gap between Annotation Stack range previews and the original TextFlow source.

Before this patch, a range preview could behave like a saved copy of text. That was dangerous because editing the TextUnit source could leave stale preview text behind, and editing the preview had no clear source of truth.

## Implemented

- Added source-backed range edit helpers in `rangeRebaseService.ts`.
- Added single TextUnit text edit diffing.
- Added range preview edit flow:
  - edit preview text;
  - write the edit back into the original TextUnit source;
  - rebase affected annotation ranges;
  - refresh `range_text_cache`;
  - preserve parent and child annotation hierarchy.
- Added direct TextUnit edit rebase flow:
  - edit TextUnit text;
  - refresh annotation offsets and caches for matching TextUnit ranges.
- Kept ambiguous overlapping ranges conservative by marking them for review instead of guessing.
- Added editable range preview UI in Annotation Stack for text-backed ranges.
- Added model contract smoke coverage for source-backed annotation range editing.

## Rules Confirmed

- `range_text_cache` is cache only. It is not content truth.
- The original TextFlow / TextUnit source remains the writable text truth.
- Label input changes annotation names only. It does not edit source text.
- Range preview editing is limited to same-TextUnit text-backed ranges in this seed.
- Cross-block and media/source region range editing remain deferred.
