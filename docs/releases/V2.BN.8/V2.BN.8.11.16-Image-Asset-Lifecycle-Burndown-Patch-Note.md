## Why This Patch Exists

8.11.7 made image a real `asset-backed CanvasObject`, but its asset lifecycle still had a gap: deleting an image object removed the image extension through cascade, while the `canvas_assets` row and local blob file stayed behind.

After 8.11.9 added safe duplicate for image objects, this became a refcount problem rather than a simple cascade problem. Duplicate image objects intentionally share one `assetId`, so asset cleanup must delete the blob only when the final live image reference is gone.

## What Changed

- Added `releaseAssetReference(db, userId, assetId, excludeObjectId)` as the server-side asset lifecycle choke point.
- Added image kind `cleanupOnDelete` support in the generic CanvasObject deletion path.
- Image delete now removes the deleting object's image extension before asset release, avoiding `ON DELETE RESTRICT` conflicts.
- Asset reference counting is user-scoped, not note-scoped, so cross-note duplicate / future AI reuse does not delete shared blobs too early.
- When the final image reference is deleted, `canvas_assets` is deleted and the local blob is unlinked best-effort.
- When another image object still references the same asset, the asset row and blob remain alive.
- Image duplicate now has an explicit code comment that sharing `assetId` is intentional.
- Model contract now asserts duplicated image objects get a new object identity while preserving the same `assetId`.

## Regression Locks

- Single-reference image delete now asserts:
  - `image_object_extensions` row is gone;
  - `canvas_assets` row is gone;
  - the real blob file is gone.
- Shared-reference image delete now asserts:
  - two image objects can reference one asset;
  - deleting the first object keeps the asset row and blob alive;
  - deleting the final object releases both row and blob.
- Model contract locks image duplicate semantics:
  - duplicate gets a new CanvasObject identity;
  - duplicate image extension follows the new object identity;
  - duplicate reuses the original `assetId`.

## Deferred

- `CR-8.11.7-02`: zero-reference upload orphan sweep is not implemented in this patch. The shared unlink primitive exists now, but sweep timing / age threshold remains a follow-up decision.
- `CR-8.11.7-04`: upload failure toast / friendly error feedback remains deferred.
- No note/user bulk asset teardown was added.
- No asset library, export packaging, source integration, crop / annotation, or media management was added.
