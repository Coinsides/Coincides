# V2.BN.8.6.12 ContentGroup Stabilization And Relation Readiness Gate Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:subagent-driven-development` (recommended) or `superpowers:executing-plans` to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在 `V2.BN.8.6.11 GroupFolder Manager And ContentGroup Editor` 完成之后，把 ContentGroup / GroupFolder / Petal / fragment / selection / command surface 收口成进入 `V2.BN.8.7 CanvasObject / media / drawing / image seed` 之前可信赖的地基。

**Architecture:** 本版本不新增另一套大模型，也不做完整 relation runtime。它把现有 ContentGroup 变成稳定、可追踪、可查询、可被后续 relation 读取的内容包：Folder 负责组织边界，ContentGroup 负责内容集合，member / fragment / Petal 负责可追溯局部，accepted identity 负责是否可被后续 relation 当作候选节点。

**Tech Stack:** React 18, TypeScript, existing Canvas Engine runtime metadata, existing ContentGroup / annotation / selection services, CSS module or local canvas styles, lucide-react icons, `canvasEngineModelContractCheck`, client build verification.

---

## Implementation Checkpoint

2026-06-18 current implementation reaches the manual QA gate with these relation-readiness pieces:

- `ContentGroupIndex` is implemented as a derived service, not a new persisted truth layer.
- `ContentGroupRelationProjection` is implemented as candidate projection only; it does not create relation edges.
- accepted ContentGroups can be downgraded back to draft when preview refresh finds unresolved content.
- folder path, group placement, member count, Petal count, and integrity summary are available to the derived index.
- command surfaces now expose ContentGroup entry points from text selection, label highlight, and block shell menus.
- unsupported future member kinds are represented as placeholders and are not treated as valid source truth yet.

The version is intentionally stopped before Henry manual testing. Passing automated checks is necessary but not sufficient.

## 0. 版本定位

`8.6.11` 是把东西做出来：

```text
GroupFolder Manager
ContentGroup Gallery
ContentGroup Detail Editor
fragment -> Petal refinement
```

`8.6.12` 是把东西接稳：

```text
source range stability
accepted identity safety
derived group index
relation endpoint candidate projection
command surface entry points
legacy surface cleanup
manual QA gate
```

这不是 `8.7`，也不是 relation runtime。它是进入 `8.7` 之前的地基收口门槛。

## 1. 不做什么

本版本明确不做：

- 完整 relation edge 创建、编辑、删除；
- 完整 graph view / local relation graph；
- AI 自动生成 GroupFolder 或 ContentGroup；
- CanvasObject / image / table region 的真实编辑器；
- 跨 source document 的真实 region extraction；
- 新的 `KnowledgeObject` 或 `KnowledgeIndex` 表；
- 复杂 pin / shortcut / linked folder 语义；
- 完整视觉重设计。

本版本可以做 relation-ready 的投影和占位，但不能创造假 relation 事实。

## 2. 核心产品规则

### 2.1 ContentGroup 仍然是唯一严肃内容包

```text
ContentGroup
  title
  identity/status
  members
  fragments
  petals
  folder placement
```

不再引入单独的 `KnowledgeObject`。如果未来需要“知识对象”这个说法，它只表示：

```text
accepted ContentGroup
```

这是工程解释，不是用户需要管理的另一种对象。

### 2.2 GroupIndex 是派生视图，不是新 truth

不新增 `KnowledgeIndex` 表。需要列表、过滤、relation candidate 时，从现有对象派生：

```text
GroupFolder[]
ContentGroup[]
ContentGroup.members[]
ContentGroup.petals[]
AnnotationTruth[]
TextFlow / ContentRange
```

派生视图可以叫 `GroupIndex`，但它不是数据库真相。

### 2.3 accepted identity 必须可降级

当用户改动 ContentGroup 的实际内容时：

```text
members changed
fragments changed
petals changed
identity role/topic/summary changed
source range stale
```

如果原来是 `accepted`，必须降回 `draft`，因为被接受过的含义已经可能不再匹配。

只移动 folder 位置不改变内容本身，不应自动降级。

### 2.4 Relation readiness 的定义

一个 ContentGroup 可以作为后续 relation endpoint candidate，需要满足：

```text
identity.status = accepted
status = active
members.length > 0
all required member refs are valid or explicitly marked stale
folder placement can be resolved
source previews can be refreshed or explain why stale
```

这个版本只产出候选节点，不产出 relation edge。

```ts
import type {
  ContentGroupIdentityStatus,
  ContentGroupMemberIntegrityStatus,
  ContentGroupV1,
} from './runtimeDataTypes';

export interface ContentGroupIndexItem {
  group_id: string;
  title: string;
  folder_id: string | null;
  identity_status: ContentGroupIdentityStatus;
  member_count: number;
  petal_count: number;
  stale_member_count: number;
  orphaned_member_count: number;
  unsupported_member_count: number;
  is_relation_candidate: boolean;
}

export interface ContentGroupIndexFilter {
  folder_id?: string | null;
  identity_status?: ContentGroupIdentityStatus | 'any';
  relation_candidates_only?: boolean;
  include_deleted?: boolean;
}

function countMembersByIntegrity(
  group: ContentGroupV1,
  status: ContentGroupMemberIntegrityStatus,
): number {
  const memberMatches = group.members.filter((member) => member.metadata?.integrity_status === status).length;
  const petalMatches = group.petals.reduce((count, petal) => (
    count + petal.members.filter((member) => member.metadata?.integrity_status === status).length
  ), 0);
  return memberMatches + petalMatches;
}

export function isContentGroupRelationCandidate(group: ContentGroupV1): boolean {
  if (group.status !== 'active') return false;
  if (group.identity.status !== 'accepted') return false;
  if (group.members.length === 0 && group.petals.every((petal) => petal.members.length === 0)) return false;
  if (countMembersByIntegrity(group, 'orphaned') > 0) return false;
  if (countMembersByIntegrity(group, 'unsupported') > 0) return false;
  return true;
}

export function buildContentGroupIndex(
  groups: ContentGroupV1[],
  filter: ContentGroupIndexFilter = {},
): ContentGroupIndexItem[] {
  return groups
    .filter((group) => filter.include_deleted || group.status !== 'deleted')
    .filter((group) => !filter.folder_id || group.metadata?.folder_id === filter.folder_id)
    .filter((group) => (
      !filter.identity_status
      || filter.identity_status === 'any'
      || group.identity.status === filter.identity_status
    ))
    .map((group) => {
      const item: ContentGroupIndexItem = {
        group_id: group.id,
        title: group.title,
        folder_id: typeof group.metadata?.folder_id === 'string' ? group.metadata.folder_id : null,
        identity_status: group.identity.status,
        member_count: group.members.length,
        petal_count: group.petals.filter((petal) => petal.status !== 'deleted').length,
        stale_member_count: countMembersByIntegrity(group, 'stale'),
        orphaned_member_count: countMembersByIntegrity(group, 'orphaned'),
        unsupported_member_count: countMembersByIntegrity(group, 'unsupported'),
        is_relation_candidate: isContentGroupRelationCandidate(group),
      };
      return item;
    })
    .filter((item) => !filter.relation_candidates_only || item.is_relation_candidate);
}
```

```ts
export interface RebaseContentGroupRangesInput {
  group: ContentGroupV1;
  textUnitId: string;
  deltaStart: number;
  deltaLength: number;
}

function rebaseMemberRangeForTextUnitEdit(
  member: ContentGroupMemberV1,
  input: Omit<RebaseContentGroupRangesInput, 'group'>,
): ContentGroupMemberV1 {
  if (member.kind !== 'content_range') return member;
  if (!member.content_range) return member;
  if (member.content_range.text_unit_id !== input.textUnitId) return member;

  const start = member.content_range.start_offset;
  const end = member.content_range.end_offset;
  if (typeof start !== 'number' || typeof end !== 'number') {
    return markContentGroupMemberIntegrity(member, 'stale', 'range offsets missing after text edit');
  }

  if (end <= input.deltaStart) return member;

  const nextStart = start >= input.deltaStart ? Math.max(0, start + input.deltaLength) : start;
  const nextEnd = Math.max(nextStart, end + input.deltaLength);

  return {
    ...member,
    content_range: {
      ...member.content_range,
      start_offset: nextStart,
      end_offset: nextEnd,
    },
    metadata: {
      ...member.metadata,
      integrity_status: 'valid',
      integrity_reason: null,
    },
  };
}

export function rebaseContentGroupRangesForTextUnitEdit(input: RebaseContentGroupRangesInput): ContentGroupV1 {
  const normalized = normalizeContentGroup(input.group);
  return updateContentGroupIdentityDraft({
    group: {
      ...normalized,
      members: normalized.members.map((member) => rebaseMemberRangeForTextUnitEdit(member, input)),
      petals: normalized.petals.map((petal) => ({
        ...petal,
        members: petal.members.map((member) => rebaseMemberRangeForTextUnitEdit(member, input)),
      })),
    },
  });
}
```

```ts
import type {
  ContentGroupMemberV1,
  ContentGroupPetalV1,
  ContentGroupV1,
} from './runtimeDataTypes';
import { isContentGroupRelationCandidate } from './contentGroupIndexService';

export interface ContentGroupRelationEndpointCandidate {
  endpoint_id: string;
  group_id: string;
  folder_id: string | null;
  title: string;
  topic: string | null;
  role: string | null;
  member_refs: ContentGroupMemberV1[];
  petal_refs: Array<{
    petal_id: string;
    label: string;
    members: ContentGroupMemberV1[];
  }>;
  source_warning_count: number;
}

export function projectContentGroupRelationEndpointCandidate(
  group: ContentGroupV1,
): ContentGroupRelationEndpointCandidate | null {
  if (!isContentGroupRelationCandidate(group)) return null;

  const activePetals = group.petals.filter((petal) => petal.status !== 'deleted');
  const sourceWarningCount = [...group.members, ...activePetals.flatMap((petal) => petal.members)]
    .filter((member) => {
      const status = member.metadata?.integrity_status;
      return status === 'stale' || status === 'orphaned' || status === 'unsupported';
    }).length;

  return {
    endpoint_id: `content-group:${group.id}`,
    group_id: group.id,
    folder_id: typeof group.metadata?.folder_id === 'string' ? group.metadata.folder_id : null,
    title: group.title,
    topic: group.identity.topic ?? null,
    role: group.identity.role ?? null,
    member_refs: group.members,
    petal_refs: activePetals.map((petal: ContentGroupPetalV1) => ({
      petal_id: petal.id,
      label: petal.label,
      members: petal.members,
    })),
    source_warning_count: sourceWarningCount,
  };
}

export function projectContentGroupRelationEndpointCandidates(
  groups: ContentGroupV1[],
): ContentGroupRelationEndpointCandidate[] {
  return groups
    .map(projectContentGroupRelationEndpointCandidate)
    .filter((candidate): candidate is ContentGroupRelationEndpointCandidate => Boolean(candidate));
}
```
