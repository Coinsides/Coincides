# V2.BN.8.6.2 Annotation Hierarchy And Range Source Contract Patch Note

Date: 2026-06-16

## Summary

This patch turns child labels from a visual nesting convention into an explicit AnnotationTruth hierarchy.

Before this patch, a child label could still behave like a top-level annotation because the data model only kept parent-side `child_annotation_ids`. That made the UI easy to confuse: child labels could appear as sibling cards in Annotation Stack even though their product meaning is subordinate to a parent label.

After this patch, child ownership has a child-side truth field:

```ts
parent_annotation_id: string | null
```

`parent_annotation_id === null` means root annotation.

`parent_annotation_id !== null` means child annotation.

Parent-side `child_annotation_ids` remains as compatibility/cache while old code paths are retired, but new hierarchy readers prefer child-side parent ownership.

## Implemented

- Added `parent_annotation_id` to `AnnotationTruthV1`.
- Added annotation hierarchy helpers for root detection, parent lookup, child lookup, root resolution, normalization, attach, detach, and visible hierarchy filtering.
- Updated child label creation so created children store their parent annotation id.
- Updated Annotation Stack root selection so children render inside parent cards rather than as sibling top-level cards.
- Added focused child styling inside the parent card when a child annotation is selected.
- Updated annotation rendering and overlay counting so children under hidden/deleted parents do not remain visible ghosts.
- Added old metadata normalization so existing parent-side child ids can be read into the new child-owned shape.
- Added a conservative range rebase service seed for same-TextUnit text edits.
- Updated Annotation Contract, TextFlow Contract, Object Inventory, Open Issue, Plan, and Changelog with the hierarchy and range-source rules.

## Manual Retest Scope

1. Create a parent annotation from selected text.
2. Select text inside the parent annotation range and create a child label.
3. Confirm the child label appears inside the parent card, not as a sibling card.
4. Select or click the child label path and confirm Annotation Stack resolves to the parent context.
5. Hide/delete the parent and confirm the child does not remain visible as a ghost.
6. Delete a child and confirm the parent remains active.
7. Refresh/reopen the note and confirm child labels stay nested under the parent.
