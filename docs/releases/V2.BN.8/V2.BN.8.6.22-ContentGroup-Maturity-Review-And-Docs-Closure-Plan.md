# V2.BN.8.6.22 ContentGroup Maturity Review And Docs Closure Plan

**Status**: implementation plan
**Date**: 2026-06-19
**Stop point**: stop at Henry manual test handoff.

## Goal

This version closes the V2.BN.8.6.13-8.6.21 ContentGroup / GroupFolder work by judging whether the first ContentGroup Editor foundation is mature enough to hand to manual testing.

It is not a new feature sprint. It is a maturity gate across code, UX surfaces, persistence, integrity checks, and documentation.

## Product Standard

The first mature version must support the three-surface model:

```text
Groups Rail = collect
Group Gallery = organize
Single ContentGroup Editor = refine
```

Minimum acceptable behavior:

- Groups Rail can collect selected content and route the user to the full Gallery.
- Group Gallery is a full-page workspace, not a floating bubble panel.
- Group Gallery has folder, topic, and role browsing modes.
- GroupFolder is the organization/path layer for ContentGroups.
- ContentGroup depth is derived from folder path, not edited as a primary field.
- Single Group Editor can edit title, topic, role, summary, identity status, members, and Petals.
- Draft Range and Label can become ContentGroup member sources.
- Data refresh preserves groups, folders, members, identity, and Petals.
- Contract checks can detect broken group/folder/member graphs.

## Non-goals

- No relation graph runtime.
- No AI automatic grouping.
- No source snapshot extraction.
- No table/image region member support yet.
- No final visual redesign.
- No legacy data adapter for old prototype accounts.
- No browser harness requirement; experience checks should prefer browser-use / in-app browser when needed.

## Implementation Tasks

### 1. Maturity Review

- Check whether the three surfaces exist: Groups Rail, Group Gallery, Single Group Editor.
- Check whether ContentGroup, GroupFolder, Member, Petal, Draft Range, and Label have clear responsibilities.
- Check whether AnnotationSet, TextUnitGroup, and child label no longer define the long-term product truth.
- Check whether group/folder metadata can be refreshed and persisted.
- Check whether there are any remaining native `prompt` / `alert` interactions in the new Gallery path.

### 2. Manual Test Checklist

Write a checklist for Henry, grouped by user scenario rather than implementation file:

- enter Group Gallery from left navigation

- create folder
- rename folder
- create group
- edit group identity fields

- add / rename / archive Petal
- drag Draft Range into Groups Rail
- drag Label into Groups Rail

- The model contract smoke includes ContentGroup / GroupFolder graph checks.

- GroupFolder path and ContentGroup derived depth are covered by contract checks.
- The manual test handoff is specific enough that Henry can test without reading implementation code.
