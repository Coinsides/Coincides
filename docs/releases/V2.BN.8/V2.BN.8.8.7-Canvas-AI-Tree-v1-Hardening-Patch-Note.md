# V2.BN.8.8.7 Canvas AI Tree v1 Hardening Patch Note

Date: 2026-06-25

Status: completed scoped engineering pass and verified.

## Summary

8.8.7 把 Canvas AI-readable layout 从 engine model 里的临时派生逻辑，收束成独立的 AI Tree 服务：

```text
Canvas runtime records -> CanvasAIReadableSnapshot
```

它仍然是 derived runtime data，不是 durable truth。它的职责是让 AI 可以读取页面容器、对象位置、文本挂载、视觉连线、selected context 和 PageFrame 内阅读顺序。

## Completed

- Added `canvasAiTreeService.ts`.
- Extended `CanvasAIReadableNode` with:
  - `selected`;
  - `readingOrder`;
  - `connectorRef`.
- Added `createCanvasAIReadableSnapshot`.
- AI Tree now supports:
  - PageFrame container node;
  - PageFrame children nesting;
  - PageFrame child reading order by y / x / zIndex;
  - block-backed object text through `textByContentTargetId`;
  - workspace shape as top-level layout node;
  - visual connector node;
  - selected object context;
  - connector endpoint and `visual_only` semantics.
- Updated `engineModel.ts` so runtime snapshot derivation goes through the new service.
- Added `Canvas AI-readable tree foundation` model contract group.
- Updated runtime boundary checks to protect the AI Tree service and node fields.
- Updated the Canvas Engine implementation checklist.

## Engineering Boundary

- AI Tree is a read model, not a write model.
- Snapshot is derived from CanvasObject / Placement / ContentMount / VisualConnector records.
- Text is read through content target ids, not duplicated as a second truth.
- Visual connector remains visual-only; AI can read it as a layout signal, not as KnowledgeRelation.
- PageFrame reading order is a hint, not a full export engine.

## Not Included

- No OCR / image layout understanding.
- No overlap / occlusion scoring.
- No Agent write path.
- No durable AI snapshot storage.
- No Relation runtime.
- No ContentGroup projection.
