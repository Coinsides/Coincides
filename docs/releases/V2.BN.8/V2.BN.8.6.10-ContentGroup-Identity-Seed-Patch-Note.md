# V2.BN.8.6.10 ContentGroup Identity Seed Patch Note

Date: 2026-06-18

## Summary

V2.BN.8.6.10 replaces the active ContentGroup `interpretation` field with a clearer `identity` state machine.

The product rule is:

```text
ContentGroup
  user-facing content package

ContentGroup.identity.status = draft
  proposed meaning / former interpretation idea

ContentGroup.identity.status = accepted
  accepted ContentGroup identity
```

No separate user-facing accepted-content object, table, or panel was added.

## Runtime Changes

- Added `ContentGroupIdentityV1`.
- Added identity statuses:
  - `none`
  - `draft`
  - `accepted`
  - `rejected`
  - `archived`
- Replaced active `ContentGroup.interpretation` output with `ContentGroup.identity`.
- Kept a small normalization bridge for stale local objects that still contain `interpretation`.
- Added identity helpers:
  - draft update
  - accept
  - reject
  - archive
- Added conservative invalidation:
  - member changes turn accepted identity back to draft;
  - Petal changes turn accepted identity back to draft;
  - title rename does not invalidate accepted identity.

## UI Changes

- ContentGroup detail now edits:
  - Role
  - Topic
  - Summary
  - Identity status
- Added compact controls:
  - Save draft
  - Accept
  - Reject
  - Archive
- UI says `Identity`, so users still manage ContentGroups.

## Reading Projection

Reading projection now treats accepted ContentGroup identity as a projection alias:

```text
knowledge_objects[]
  accepted ContentGroup identities

draft_knowledge_candidates[]
  draft ContentGroup identities
```

This projection does not create a separate persisted accepted-content list.
