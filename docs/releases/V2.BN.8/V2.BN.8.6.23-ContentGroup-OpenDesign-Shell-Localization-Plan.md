# V2.BN.8.6.23 ContentGroup OpenDesign Shell Localization Plan

> Status: Draft
> Date: 2026-06-21
> Goal: 把 OpenDesign 三个 HTML 壳子本地化为 Coincides 自己的 ContentGroup 三层界面，而不是继续在当前粗糙表单 UI 上修修补补。

## 1. 背景

当前 ContentGroup UI 的主要问题不是单个按钮丑，而是三层界面职责混在了一起：

```text
Groups Rail
Group Gallery
Single ContentGroup Editor
```

现在的实现里：

- `ContentGroupPanel` 同时承担 rail、detail editor、folder、drop zone、summary、identity、petal 等职责。
- `GroupGallery` 同时承担 full gallery 和 detail draft 编辑。
- `topic` / `role` 仍像普通表单字段，没有落实成视觉语义。
- `Single Editor` 还没有成为真正的 knowledge workbench。

OpenDesign 已经产出三份 HTML 壳子，可作为新的视觉和交互参考。

归档位置：

```text
docs/brainstorm/产品完善/assets/2026-06-20-contentgroup-visual-reference/opendesign-html/
```

文件：

- `group-gallery.html`
- `groups-rail.html`
- `single-contentgroup-editor.html`

## 2. 设计读法

这不是 landing page，也不是展示页。

它是一个密集产品 UI 重构，应该靠近：

```text
VS Code / 资源管理器 / 知识工作台 / 本地开发工具
```

视觉原则：

- 低装饰。
- 高信息密度。
- 边界清楚。
- 圆角克制。
- 按钮不要全浮在表面。
- 表单不要堆气泡。
- role / topic / identity 必须有不同视觉语言。

## 3. 核心目标

本版本不追求一次性做完全部 ContentGroup Editor 成熟态。

它只解决一个问题：

```text
把三层界面的骨架立正。
```

完成后应该达到：

- Groups Rail 看起来像极简资源抽屉。
- Group Gallery 看起来像全屏资源管理器。
- Single ContentGroup Editor 看起来像知识加工台。
- 三个界面不再互相替代。
- OpenDesign 壳子的视觉语言进入本地 React 组件，而不是停留在截图和 HTML 里。

## 4. 不做什么

本版本暂不做：

- 完整 Petal 复杂编辑流。
- 完整 member 自由拖拽布局持久化。
- 完整 relation / graph。
- 完整 cross-project reference / duplicate / materialize。
- 完整 source chain UI。
- AI 自动生成 Petal / summary。

这些可以由后续 8.6.x 或 8.7 承接。

## 5. 组件拆分方案

### 5.1 新增共享组件

建议新增目录：

```text
client/src/pages/GroupGallery/components/
```

或后续抽到：

```text
client/src/pages/Notes/canvasEngine/contentGroups/
```

第一版可以先放在 `GroupGallery/components`，避免过早抽象。

建议组件：

- `GroupFolderTree`
- `GroupFolderBreadcrumb`
- `ContentGroupCard`
- `ContentGroupRow`
- `ContentGroupViewSwitcher`
- `RoleBadge`
- `TopicSignal`
- `IdentityChip`
- `ContentGroupDropZone`
- `MemberPiece`
- `PetalDock`
- `SummaryBar`

### 5.2 Groups Rail

目标：替换当前 `ContentGroupPanel` 的重表单感。

Rail 应保留：

- 当前 folder path。
- 打开 Gallery 的入口。
- 关闭按钮。
- 小型 `+` 新建 group。
- 搜索入口。
- Folder / Topic / Role / All 微缩视图。
- ContentGroup rows。
- 展开 group 后的 drop zone。
- Open editor 入口。

Rail 应移除：

- 常驻完整 members preview。
- 常驻 topic / role / summary input。
- Petal 创建和管理。
- source locator 等工程字段。

迁移目标：

```text
client/src/pages/Notes/canvasEngine/panels/ContentGroupPanel.tsx
```

可以改造为：

```text
GroupsRail.tsx
```

或保留文件名，先内部重构出 rail-only UI。

### 5.3 Group Gallery

目标：替换当前 `GroupGallery` 的表单和 detail 混合感。

Gallery 应保留：

- 左侧 folder tree。
- 顶部搜索。
- New folder。
- New group。
- Folder / Topic / Role 视图。
- ContentGroup cards。
- card 上的 role badge / topic signal / identity chip。
- 点击 card 进入 Single Editor。

Gallery 应移除：

- 常驻右侧完整 editor。
- 大段 member preview。
- topic / role / summary 的表单式常驻编辑。

迁移目标：

```text
client/src/pages/GroupGallery/GroupGallery.tsx
client/src/pages/GroupGallery/GroupGallery.module.css
```

### 5.4 Single ContentGroup Editor

目标：新增或抽出一个完整页面，承接 OpenDesign 的 workbench 壳子。

建议路由：

```text
/group-gallery/groups/:noteId/:groupId
```

或暂时继续使用 query：

```text
/group-gallery?note_id=...&group_id=...&mode=editor
```

更推荐独立 route，因为它是平级页面，不是 Gallery 内部右栏。

Editor 应包含：

- 返回 Gallery。
- 可编辑 display name。
- identity chip。
- role/type badge。
- topic signal。
- summary 折叠条。
- workbench grid。
- member pieces。
- Petal dock / Petal panel。
- source / evidence drawer 的占位入口。

第一版 member pieces 可以先按 order_index 自动布局，不强求自由拖拽。

## 6. 数据接入原则

本版本尽量不大改数据结构。

沿用：

- `ContentGroupV1`
- `ContentGroupMemberV1`
- `ContentGroupPetalV1`
- `GroupFolderV1`

允许新增轻量 `view_state` 写法：

```ts
group.view_state = {
  editor_layout: {
    members: {
      [memberId]: { x, y, width, height, collapsed }
    }
  }
}
```

但第一版可以不持久化自由坐标，只保留 UI 壳子和稳定布局。

必须保持：

- ContentGroup 引用原文，不搬走原文。
- member 必须保留 source locator。
- preview text 不能取代 source locator。
- 删除 member 不删除原文。

## 7. Topic / Role / Identity 视觉规则

落实 15:10 和 06-20 会议记录里的方向：

```text
Role = 小 type / badge / tab
Topic = color / path / corner mark / signal
Identity = status chip / icon
Folder = hierarchy / placement
```

具体要求：

- `role` 不再像普通 input 一样长期裸露。
- `topic` 用颜色点、色条、路径或轻 tint 表达。
- `identity` 使用 Draft / Accepted / Rejected / Archived chip。
- Gallery card 中 `role` 和 `topic` 必须能一眼区分。
- Rail 中 `role` 更轻，不能压缩 display name。

- [ ] Gallery card 使用 role badge、topic signal、identity chip。

- [ ] 删除 / 添加 member 不破坏原文。
- [ ] 刷新后基础 group / folder 数据不丢。

- [ ] Rail 不展示 source locator / members count / petals count 等工程字段。
