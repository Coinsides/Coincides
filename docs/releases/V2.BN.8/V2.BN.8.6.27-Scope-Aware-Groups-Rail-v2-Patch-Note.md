# V2.BN.8.6.27 Scope-Aware Groups Rail v2 Patch Note

## Implemented

- Groups Rail now behaves as a lightweight collection rail instead of a miniature full editor.
- The Rail resolves to the current note root folder and displays the current folder path in the header area.
- The old two-column mini Gallery layout was reduced to a single-column Rail.
- The Rail keeps only lightweight surface actions:
  - open Group Gallery;
  - close Rail;
  - create a new group;
  - drop current item into a new group;
  - open a group editor;
  - add current item to an active group.
- Child folders are shown as lightweight navigation rows.
- Group rows can be selected as the active group.
- Active group rows receive a quiet visual highlight.
- Full topic / role / summary editing remains outside the Rail.
- Petal editing remains outside the Rail.

## Item Intake

- Draft Range, Label, and Block items can still be dropped into group rows.
- Dropping into the new-group target creates a ContentGroup in the current folder.
- Adding the current item to a selected group still creates member references only.
- Source text, labels, and blocks are not moved by Rail intake.

## Navigation

- Rail can open Group Gallery with the current `note_id` and `folder_id`.
- Rail can open the Single ContentGroup Editor for a selected group.

## Follow-up Fix

- Group Gallery folder tree is now rendered by scope instead of flattening every note record's root folders.
- `Workspace groups` is shown once at the gallery root.
- `Project groups` is shown once under its project.
- `Note groups` is shown only under the corresponding note.
- Folder-mode group filtering now aggregates workspace/project scoped root groups across their matching records instead of treating every root as a child of one note.

## Deferred

- Full project/workspace-level Rail entry outside the note page.
- Rail context menus for folder row / group row.
- Full GroupFolder manager inside Rail.
- Petal assignment.
- OpenDesign visual parity.
- Page / Canvas drop-to-block.
