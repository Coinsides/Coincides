# V2.BN.8.9.12.1 PageFrame Layout Affiliation And Zoom Control Patch Note

Date: 2026-06-27

## Scope

This patch closes two usability gaps found during PageFrame manual testing before the Continuous PageStack pass.

Completed:

- Added `layoutAffiliationService.ts` as a sparse geometry-derived layout-container boundary.
- Added `LayoutAffiliation` with `page_frame` / `workspace` container kinds and `fully_contained` / `crossing` / `floating` relations.
- Added PageFrame move cohort derivation so only fully-contained Blocks move with a moved PageFrame.
- Routed PageFrame move transactions through block layout draft application and changed-layout persistence.
- Added a visible Canvas zoom control with zoom out, slider, zoom in, and reset percent button.
- Added model-contract and runtime-boundary coverage for layout affiliation, move cohort behavior, PageFrame move wiring, and zoom-control DOM markers.

Product boundary:

- This patch does not create hard PageFrame ownership for Blocks.
- This patch does not make every CanvasObject a `LayoutContainer`.
- Layout affiliation remains derived from geometry and is used as a transactional helper.
- Crossing Blocks are not moved automatically with a PageFrame.
- Continuous PageStack, PageSlice extraction, cross-page Block fragments, and final generic CanvasObject database persistence remain deferred.

## Product Decision

The settled short-term rule is:

```text
CanvasObject is the base object.
LayoutContainer is an optional capability.
LayoutAffiliation is sparse and derived, not mandatory ownership.
```

PageFrame is the first special LayoutContainer because it carries formal-page, export, and reading-view meaning. A plain shape does not need affiliation unless it becomes a content-bearing container.
