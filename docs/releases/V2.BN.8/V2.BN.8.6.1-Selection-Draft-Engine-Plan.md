# V2.BN.8.6.1 Selection Draft Engine Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 把 Coincides 的文字选区从浏览器原生 selection/focus 副作用中抽离出来，建立第一版成熟的 `SelectionDraft` 地基，并让 annotation / child label / selection toolbar 都消费同一个 Coincides 自有选区 truth。

**Architecture:** 浏览器 selection 只作为输入信号，不再作为知识选区 truth。`SelectionDraft` 记录用户当前临时选中的范围、追加模式、可见高亮、toolbar 锚点、父 annotation 上下文和提交目标；AnnotationTruth 创建、同范围 label、child label 和后续 inline action 都从 `SelectionDraft` 读取范围。第一版成熟范围聚焦同一个 TextBlock 内的单段、多段、跨 TextUnit 选取；跨 block 选取在数据结构中预留，但不作为 8.6.1 手测验收主线。

**Tech Stack:** React 18, TypeScript, Vite, Coincides NoteCanvas runtime, TextFlow / TextUnit editor, AnnotationTruth service, canvas model contract smoke, Henry manual visual pass.

---

## 1. Why This Version Exists

V2.BN.8.5 建立了 AnnotationTruth seed。V2.BN.8.6 把 annotation editor 推进到多 label、重叠 annotation、child annotation、AnnotationSet 和 ReadingInterpretation seed。

Henry 手测后确认：浏览器原生 selection 不能继续作为 Coincides 的知识选区地基。它在 textarea、focus、Ctrl/Command、跨 TextUnit、多段选取、外点击清理、临时高亮和 child label 场景里都不稳定。

因此 V2.BN.8.6.1 插入到 8.6 与 8.7 之间，专门完成：

```text
Browser selection signal
  -> Coincides SelectionDraft truth
  -> visible draft highlight
  -> selection toolbar
  -> AnnotationTruth / child annotation / future inline action
```

8.6.1 是地基组件版本，不是临时 UI patch。

## 2. Mature Definition

8.6.1 的“成熟”不是支持未来所有选区幻想，而是满足以下标准：

1. Coincides 自己知道用户临时选中了什么。
2. 用户看见的临时高亮、系统记录的 `SelectionDraft`、最终提交的 AnnotationTruth ranges 三者一致。
3. 普通拖选替换 draft；Ctrl / Command 拖选追加 draft。
4. 用户先普通选中一段，之后才按 Ctrl / Command 继续选第二段时，第一段会自动升级进入 draft。
5. 点击空白、点击别的 block、按 Esc 或关闭 toolbar 时，临时 draft 和临时高亮自然消失。
6. selection toolbar 是轻量、临时、可逃离的，不像 inspector 一样粘住用户。
7. child label 入口不再以 Inspector 普通输入框为主，而是在“已有 parent annotation 内再次选区”时出现。
8. 跨 block 选区必须在类型和 range ordering 中预留，但不要求 8.6.1 做完整跨 block UI。

## 3. Scope

### In Scope

- `SelectionDraft` 数据模型和 reducer/service。
- 单段选区、同 TextBlock 多段选区、同 TextBlock 跨 TextUnit 选区。
- Ctrl / Command 追加选区。
- 普通选区后再 Ctrl / Command 追加时，自动把第一段选区纳入 draft。
- 自有 draft 高亮，不依赖浏览器蓝色选区。
- selection toolbar 外点击关闭。
- selection toolbar 与 draft 生命周期绑定。
- AnnotationTruth 创建消费整个 `SelectionDraft`。
- child label 入口改为 parent annotation 内部二次选区触发。
- Object inventory / Annotation contract / V2.BN.8 docs 同步。

### Out Of Scope

- 完整跨 block 选区 UI。
- 完整自研文本编辑器 / 光标系统。
- 完整 rich text editor。
- 完整 right-click action menu。
- 完整 inline formula / inline code conversion。
- 完整 relation endpoint editor。
- CanvasObject / image / region selection；这些仍属于 V2.BN.8.7。
- AI 自动识别 child annotation；8.6.1 只做用户操作地基。

## 4. User Experience Rules

### 4.1 Replace Selection

普通鼠标拖选：

```text
drag text range
  -> replace current SelectionDraft
  -> show Coincides draft highlight
  -> show lightweight toolbar
```

如果已有多段 draft，普通拖选会清掉旧 draft，换成新单段 draft。

### 4.2 Additive Selection

Ctrl / Command + 鼠标拖选：

```text
Ctrl + drag text range
  -> append range to SelectionDraft
  -> keep prior draft ranges visible
  -> update toolbar range count
```

### 4.3 Upgrade Existing Selection

用户先普通选中一段，之后才按 Ctrl / Command 去选第二段：

```text
normal selection A
Ctrl + selection B
  -> A becomes first range in SelectionDraft
  -> B becomes second range
```

这是关键体验：用户不需要一开始就记得按 Ctrl。

### 4.4 Escape / Outside Click

以下动作必须清理临时状态：

- 点 PageFrame 空白；
- 点 Canvas workspace 空白；
- 点其他 block；
- 点 selection toolbar 外部；
- 按 Esc；
- 点击 toolbar close。

清理对象：

```text
SelectionDraft
selection toolbar
temporary draft highlights
browser visual selection if present
```

已有 AnnotationTruth 不受影响。

### 4.5 Child Label Entry

child label 不是 Inspector 普通创建入口。

正确入口：

```text
select existing annotation / click annotation badge
  -> parent annotation becomes active
select text inside parent annotation range
  -> toolbar shows Add child label
Add child label
  -> create child AnnotationTruth with selected subrange
  -> parent.child_annotation_ids includes child id
```

如果二次选区不在 parent annotation range 内，toolbar 不显示 child label 入口，只显示普通 annotate / same-range label 入口。

## 5. Data Model

### 5.1 SelectionDraftV1

Create a local runtime type:

```ts
export interface SelectionDraftRangeV1 {
  id: string;
  block_id: string;
  text_flow_id: string;
  text_unit_id: string;
  start_offset: number;
  end_offset: number;
  text_snapshot: string;
  order_index: number;
}

export interface SelectionDraftV1 {
  id: string;
  mode: 'replace' | 'additive';
  ranges: SelectionDraftRangeV1[];
  anchor: {
    x: number;
    y: number;
    width: number;
    height: number;
  } | null;
  parent_annotation_id?: string;
  created_at: number;
  updated_at: number;
}
```

Rules:

- `SelectionDraftV1` is runtime state, not persistent note truth.
- It may later become an undo/history-aware editor state, but not in 8.6.1.
- Ranges deduplicate by block/textFlow/textUnit/start/end.
- Ranges are sorted by document order inside the current TextBlock.
- Cross-block order is reserved but not required for 8.6.1 acceptance.

### 5.2 Browser Selection Boundary

Browser selection can still provide:

```text
pointer start / move / end
textarea selectionStart / selectionEnd snapshot
temporary OS-level highlight during drag
```

Browser selection must not own:

```text
draft truth
draft rendering
range list
annotation commit payload
child annotation parent context
outside click lifecycle
```

## 9. Risks

### Risk 1: Selection Engine Becomes A Full Text Editor

8.6.1 must avoid rewriting caret/input. The engine owns knowledge selection, not all text editing.

### Risk 2: Browser Selection Still Leaks

The browser may still show blue selection temporarily during drag. That is acceptable only as transient feedback. Coincides draft highlight must be the stable feedback.

### Risk 3: Child Label UX Becomes Too Hidden

If parent annotation selection is not obvious, users may not discover child labels. 8.6.1 should keep the first UI simple and visible enough for Henry manual testing.

### Risk 4: Cross Block Selection Pressure

The data model should not block cross-block selection, but 8.6.1 should not expand into full cross-block selection UI unless same TextBlock selection is already stable.

## 10. Acceptance

8.6.1 can close when:

- `SelectionDraft` is an explicit runtime/editor object.
- Annotation creation consumes SelectionDraft instead of browser selection directly.
- User-visible draft highlights are generated from Coincides state.
- Ctrl / Command additive selection works after an initial normal selection.
- Outside click / Esc reliably clears draft and toolbar.
- Child label creation is based on selecting content inside an active parent annotation.
- Contracts and V2.BN.8 docs name SelectionDraft as a foundation component.
- Engineering checks pass.
- Henry manual pass confirms the selection behavior feels predictable.
