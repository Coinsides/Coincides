# V2.BN.8.7 ContentGroup System Maturity Master Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn the current ContentGroup surfaces into a coherent `ContentGroup System 1.0`: stable, understandable, reusable, and ready to be referenced by future Canvas projections.

**Architecture:** V2.BN.8.7 hardens the object boundaries that future Canvas projection and AI reuse will need: ContentGroup, Member, Petal, GroupFolder, source reference, and reuse projection. After the 2026-06-22 roadmap correction, the maturity lane starts with staged entity cutover sub-versions: `V2.BN.8.7.1` cuts the root `ContentGroup` out of note metadata, `V2.BN.8.7.2` cuts `GroupFolder` and folder placement into independent entities, and later 8.7.x versions cut ContentGroupMember and ContentGroupPetal. The version proceeds through small closed loops: audit, sub-plan, failing model check, implementation, verification, code-quality review, UX review, and documentation closure.

**Tech Stack:** React 18, TypeScript, CSS Modules, Vite, existing Coincides NoteCanvas runtime, ContentGroup / GroupFolder services, model-contract smoke checks, browser/manual visual pass.

## 2. Version Boundary

V2.BN.8.7 is the ContentGroup maturity version.

```text
In 8.7:
  ContentGroup System maturity.

Deferred to 8.8+:
  CanvasObject / media / drawing seed.

Deferred to 8.9+:
  Canvas reliability / scale / export reserve.

The allowed database exception is the staged ContentGroup System cutover lane: one root object per small version, starting with `V2.BN.8.7.1` for the `ContentGroup` root entity.

### Keep As 8.7 Optional

These can enter 8.7 only if the core maturity loop is already stable:

- Project / workspace Rail entry outside the current note page.
- Minimal folder row context menu inside Rail.
- Minimal group row context menu inside Rail.
- Complex block copy fidelity for non-simple blocks.

### Defer Past 8.7

These should not be pulled into the maturity version:

- Full GroupFolder manager inside Rail.
- Petal assignment from Rail.
- AI-created Petals.
- Table / image / canvas-object internal fragments.
- Relation truth / mature relation endpoint behavior.
- Destructive move semantics.
- True reorder of original source text.
- Full offset rebase engine for AnnotationTruth ranges, ContentGroup member ranges, and Petal fragments.
- Cross-block precise move.
- Table / image / formula block internal drag.
- AI-driven TextFlow rewrite.
- Full undo stack support for destructive drag insert / move operations.

The rule is simple:

```text
If it mutates source truth positions, needs relation truth, needs CanvasObject, or needs AI authorship, it waits.
```

## 4. Maturity Standards

### Product Standard

The user must be able to explain the three surfaces without guessing:

```text
Rail = collect.
Gallery = organize.
Single Editor = refine.
```

The user must also understand these actions:

```text
Reference = point to an existing group.
Duplicate = copy a group into the current context.
Fork = copy with lineage for local editing.
Materialize = write members into note blocks.
Open original = navigate to the source group or source note.
```

### Data Standard

ContentGroup must not pretend that Member and source range are the same object.

```text
ContentGroupMember = group-local content truth.
ContentRange / SourceAnchor = source location truth.
preview_text = display cache, never second truth.
```

8.7 should introduce or prepare these stable fields:

```ts
export type ContentGroupMemberSourceSyncStatus =
  | 'fresh'
  | 'changed'
  | 'missing'
  | 'detached'
  | 'unsupported';

export interface ContentGroupMemberSourceRefV1 {
  source_artifact_id?: string | null;
  note_id?: string | null;
  block_id?: string | null;
  range?: AnnotationRangeV1 | null;
  snapshot_text?: string | null;
  snapshot_hash?: string | null;
  status?: ContentGroupMemberSourceSyncStatus;
  updated_at?: string | null;
  metadata?: Record<string, unknown>;
}
```

The implementation can embed this under `ContentGroupMemberV1` first; the member/source database entity migration is deferred to a later small version after the root `ContentGroup` entity cutover.

### Code Standard

- Business logic belongs in service files, not duplicated in UI components.
- UI components may choose display mode, but should not decide source truth.
- `ContentGroupPanel.tsx` should stay a lightweight collect surface.
- `GroupGallery.tsx` should act as resource manager, not detail editor.
- `SingleContentGroupEditor.tsx` should own deep refinement.
- New helper files should be small enough to review independently.

Every sub-plan must finish with:

```

If a sub-plan changes secrets, auth, or file scanning paths, also run:

```

Browser/manual checks are required for the three ContentGroup surfaces once visual or interaction behavior changes.

## 5. Implementation Loop

```text

The "can this be better" review must answer:

- Did this make Rail / Gallery / Editor roles clearer?
- Did this reduce or increase source/member ambiguity?
- Did this avoid creating a second truth?
- Did this avoid moving source text silently?
- Did this avoid turning Rail into a mini editor?
- Did this preserve future Canvas projection boundaries?

If the answer is negative, open a follow-up item before moving to the next sub-plan.

## 15. Close Criteria For V2.BN.8.7

V2.BN.8.7 can close only when:

- Rail, Gallery, and Single Editor have distinct roles.
- Member and source are separated in data model, service language, and UI copy.
- GroupFolder / Gallery can organize groups without implying source movement.
- Reference / Duplicate / Fork / Materialize / Open original have stable meanings.
- Petal can structure a group without becoming a standalone source marker.
- Stale, orphaned, archived, deleted, accepted, rejected, and empty states are safe and readable.
- The full verification standard passes.
- Manual checklist is written and filled.
- Review, Experience Review, CHANGELOG, and Open Issues are updated.
- CanvasObject seed remains deferred until this object boundary is stable.
