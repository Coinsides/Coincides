# V2.BN.8.11.17 Course Asset Teardown Patch Note

## Why

Stage five fixed image asset cleanup when a single image CanvasObject is deleted. A later review found one live bulk-delete path was still leaking assets: `DELETE /api/courses/:id`.

Course deletion is a hard delete. FK cascade removes `image_object_extensions`, but `canvas_assets.course_id` is `ON DELETE SET NULL`, so the asset row and local blob could remain forever with no extension row left for refcount cleanup.

## What Changed

- Added `releaseCourseCanvasAssets(db, userId, courseId)`.
- Course deletion now releases image assets before deleting the course row.
- The release logic keeps the same invariant as object delete:
  - delete the current image extension first;
  - count remaining live image references by `user_id + asset_id`;
  - only delete the asset row and blob when the count reaches zero.
- Cross-course shared assets are preserved until the final course reference is deleted.
- Same-course shared assets are released once, after all course-local image extensions are removed.
- Added a future-warning comment for in-place image replacement: if a future flow reuses an image object id with a new asset id, it must release the previous asset.
- Image asset tests now use env-aware asset directory resolution.

## Not Changed

- No FK migration change.
- No asset refcount column.
- No note/user hard-delete teardown path.
- No zero-reference upload orphan sweep.
- No upload failure toast / friendly feedback change.
