# V2.BN.8.10.2 Font Family And Font Size Controls Lab Plan

> For agentic workers: Execute this plan step by step. Do not broaden the scope into line-height controls, paragraph spacing controls, rich text spans, auto-pagination, export, or per-block typography. Run the listed checks after implementation and update the patch note with exactly what changed.

## 1. Goal

V2.BN.8.10.2 adds the first user-facing typography controls on top of the V2.BN.8.10.1 note-level typography profile.

This lab should let a user change:

- document font family;
- document font size;
- reset the typography profile back to the document default.

The important product move is simple: typography stops being a hidden runtime default and becomes a visible, editable document-level setting.

## 2. Current Ground

V2.BN.8.10.1 already created the data foundation:

- `typographyProfileService.ts` owns the active document typography metadata contract.
- `text_flow_typography_profile_v1` is the note metadata key.
- `DocumentTypographyProfile` currently contains `profileId`, `fontFamily`, `fontSizePx`, `lineHeightPx`, `paragraphSpacingPx`, and `averageCharWidthPx`.
- `patchDocumentTypographyProfile(...)` already normalizes changes and recalculates average character width when font size changes.
- PageFrame runtime extensions receive the active typography profile.
- `NoteWritingSurfaceLayer` already applies document typography CSS variables to the writing surface root.

The missing part is the editing path:

```text
Note metadata typography profile
  -> runtime controller
  -> chrome UI controls
  -> patchDocumentTypographyProfile(...)
  -> saveDocumentTypographyProfile(...)
  -> writing surface / PageFrame runtime reflects the result
```

## 3. Scope

### Must Do

- Add stable exported font-family options.
- Reuse the same options for normalization allowlist and UI select options.
- Wire `documentTypographyProfile` and `saveDocumentTypographyProfile` to `NoteChromeLayer`.
- Add compact controls in the existing note chrome, preferably under `More`.
- Save font family changes through `patchDocumentTypographyProfile(...)`.
- Save font size changes through `patchDocumentTypographyProfile(...)`.
- Reset to `DEFAULT_DOCUMENT_TYPOGRAPHY_PROFILE`.
- Add model and runtime boundary checks.
- Add a patch note after implementation.
- Run browser/manual smoke because this changes visible UI.

### Must Not Do

- Do not add line-height or paragraph-spacing UI. That belongs to V2.BN.8.10.3.
- Do not add per-block typography or rich text spans.
- Do not mutate TextFlow content when typography changes.
- Do not store typography inside CanvasObject / CanvasPlacement persistence.
- Do not add a Word-like toolbar.
- Do not implement auto-pagination, PageSlice export, PDF export, or project-package export.
- Do not make Canvas zoom affect saved font size.

## 4. Product Shape

The control should feel like a compact document setting, not a full formatting ribbon.

Recommended placement:

```text
Top chrome -> More -> Typography section
```

Controls:

- `Font`: select menu.
- `Size`: compact number input or stepper.
- `Reset`: icon or small button.

No tutorial text is needed. Labels are allowed because these are actual controls, not explanatory product copy.

Expected user experience:

1. User opens a note.
2. User opens `More`.
3. User changes font family.
4. Visible text changes.
5. User changes font size.
6. Visible text changes without resizing the PageFrame itself.
7. User reloads the note.
8. The chosen font family and font size persist.

## 5. Architecture

The source of truth remains note metadata:

```text
note.metadata.text_flow_typography_profile_v1.activeProfile
```

The UI must not build a second truth. It should only call the existing profile service:

```ts
const nextProfile = patchDocumentTypographyProfile(documentTypographyProfile, {
  fontSizePx: nextFontSizePx,
});

void onSaveDocumentTypographyProfile(nextProfile);
```

The visual update should continue to flow through existing runtime state and CSS variables:

```text
saveDocumentTypographyProfile(...)
  -> documentTypographyProfile state
  -> PageFrame extension documentTypography
  -> NoteWritingSurfaceLayer documentTypographyStyle
  -> --document-font-family / --document-font-size / --document-line-height
```

## 7. Task 1 - Add Failing Contract Checks

Start by making checks fail for the missing 10.2 behavior.

### 7.1 Model Contract Check

Update `client/scripts/canvasEngineModelContractCheck.ts`.

The check should import:

```ts
import {
  DEFAULT_DOCUMENT_TYPOGRAPHY_PROFILE,
  DOCUMENT_FONT_FAMILY_OPTIONS,
  DOCUMENT_TYPOGRAPHY_LIMITS,
  patchDocumentTypographyProfile,
} from '../src/pages/Notes/canvasEngine/typographyProfileService';
```

Add or extend a typography test that verifies:

- font-family options exist;
- the default font family is present in the options;
- invalid font family normalizes back to default;
- font size patch clamps to the configured range;
- font size patch recalculates or preserves a valid `averageCharWidthPx`;
- line height remains at least `fontSizePx + 2`;
- profile patching does not touch TextFlow content.

Expected assertions:

```ts
const familyValues = DOCUMENT_FONT_FAMILY_OPTIONS.map((option) => option.value);
assert(
  familyValues.includes(DEFAULT_DOCUMENT_TYPOGRAPHY_PROFILE.fontFamily),
  'default font family option is available',
);

const patched = patchDocumentTypographyProfile(DEFAULT_DOCUMENT_TYPOGRAPHY_PROFILE, {
  fontFamily: 'Georgia, serif',
  fontSizePx: 18,
});

assert(patched.fontFamily === 'Georgia, serif', 'font family patch is accepted');
assert(patched.fontSizePx === 18, 'font size patch is accepted');
assert(patched.lineHeightPx >= patched.fontSizePx + 2, 'line height remains valid');
assert(
  patched.averageCharWidthPx >= DOCUMENT_TYPOGRAPHY_LIMITS.minAverageCharWidthPx
    && patched.averageCharWidthPx <= DOCUMENT_TYPOGRAPHY_LIMITS.maxAverageCharWidthPx,
  'average char width remains valid',
);
```

## 10. Task 4 - Add Compact Typography Controls

Modify `NoteChromeLayer.tsx`.

Imports:

```ts
import type { ChangeEvent } from 'react';
import type { DocumentTypographyProfile } from '../types';
import {
  DEFAULT_DOCUMENT_TYPOGRAPHY_PROFILE,
  DOCUMENT_FONT_FAMILY_OPTIONS,
  DOCUMENT_TYPOGRAPHY_LIMITS,
  patchDocumentTypographyProfile,
} from '../typographyProfileService';
```

Extend props:

```ts
documentTypographyProfile: DocumentTypographyProfile;
onSaveDocumentTypographyProfile: (profile: DocumentTypographyProfile) => void | Promise<void>;
```

Add handlers inside `NoteChromeLayer`:

```ts
const handleTypographyFontFamilyChange = useCallback((event: ChangeEvent<HTMLSelectElement>) => {
  const nextProfile = patchDocumentTypographyProfile(documentTypographyProfile, {
    fontFamily: event.target.value,
  });
  void onSaveDocumentTypographyProfile(nextProfile);
}, [documentTypographyProfile, onSaveDocumentTypographyProfile]);

const handleTypographyFontSizeChange = useCallback((event: ChangeEvent<HTMLInputElement>) => {
  const nextFontSizePx = Number(event.target.value);
  const nextProfile = patchDocumentTypographyProfile(documentTypographyProfile, {
    fontSizePx: nextFontSizePx,
  });
  void onSaveDocumentTypographyProfile(nextProfile);
}, [documentTypographyProfile, onSaveDocumentTypographyProfile]);

const handleResetTypographyProfile = useCallback(() => {
  void onSaveDocumentTypographyProfile(DEFAULT_DOCUMENT_TYPOGRAPHY_PROFILE);
}, [onSaveDocumentTypographyProfile]);
```

Add the section inside the existing More popover:

```tsx
<div
  className={styles.typographyControls}
  data-typography-controls="document"
>
  <div className={styles.typographyControlHeader}>
    <span>Typography</span>
    <button type="button" className={styles.subtleButton} onClick={handleResetTypographyProfile}>
      Reset
    </button>
  </div>

  <label className={styles.typographyControlRow}>
    <span>Font</span>
    <select
      className={styles.typographySelect}
      value={documentTypographyProfile.fontFamily}
      onChange={handleTypographyFontFamilyChange}
      data-typography-font-family
    >
      {DOCUMENT_FONT_FAMILY_OPTIONS.map((option) => (
        <option key={option.id} value={option.value}>
          {option.label}
        </option>
      ))}
    </select>
  </label>

  <label className={styles.typographyControlRow}>
    <span>Size</span>
    <input
      className={styles.typographyNumberInput}
      type="number"
      min={DOCUMENT_TYPOGRAPHY_LIMITS.minFontSizePx}
      max={DOCUMENT_TYPOGRAPHY_LIMITS.maxFontSizePx}
      step={1}
      value={documentTypographyProfile.fontSizePx}
      onChange={handleTypographyFontSizeChange}
      data-typography-font-size
    />
  </label>
</div>
```

Implementation notes:

- If `NoteChromeLayer` currently imports `useCallback` from `react`, extend the import with `ChangeEvent` only as a type.
- Do not add uncontrolled local state unless browser typing behavior becomes poor.
- Keep the control compact. It should not visually dominate the note chrome.

## 16. Risks

### Risk: UI Becomes Too Large

Trigger:

```text
The More popover turns into a formatting toolbar.
```

Response:

```text
Keep only Font / Size / Reset in 10.2. Move line height and paragraph spacing to 10.3.
```

### Risk: Typography Becomes Content Truth

Trigger:

```text
Typography changes rewrite block text, TextFlow units, or source content.
```

Response:

```text
Stop and move the change back to note metadata + CSS variables.
```

### Risk: Profile Options Drift

Trigger:

```text
UI accepts a font family that normalization later rejects.
```

Response:

```text
Make UI options and normalization derive from DOCUMENT_FONT_FAMILY_OPTIONS.
```

### Risk: Font Size Breaks Later Measurement

Trigger:

```text
fontSizePx changes but averageCharWidthPx or lineHeightPx becomes invalid.
```

Response:

```text
Always use patchDocumentTypographyProfile(...), never raw object spread in UI handlers.
```
