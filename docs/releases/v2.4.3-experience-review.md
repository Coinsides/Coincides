# v2.4.3 Experience Review - Agent Canvas Layout Proposal UX

**Created**: 2026-05-23
**Updated**: 2026-05-23
**Current Experience Status**: `PASS_WITH_FOLLOWUP`

---

## UI / Visual Findings

- `Plan layout` is available directly in the Canvas Document toolbar.
- Layout proposal preview appears both in the existing proposal review panel and as a light overlay on the canvas.
- This is still foundation UI, not final canvas polish.
- In-app browser smoke after restart saw the `Plan layout` entry, created a layout proposal, applied it, and reloaded with the canvas nodes still present.

## Interaction Findings

PASS for the v2.4.3 boundary:

```text
Canvas Document -> Plan layout -> review proposal -> apply/discard
```

Apply refreshes the canvas after writing layout records. Discard uses the existing proposal discard path and does not change layout.

## Workflow Findings

Layout proposal should feel like arranging objects on the canvas, not generating or rewriting content.

The review copy explicitly says the proposal changes canvas layout records only.

## Product Fit Findings

v2.4.3 should make the canvas feel more like a real workspace while preserving the rule that canvas remains projection.

Result: directionally correct. It gives the agent/system a proposal-first way to arrange canvas objects while keeping knowledge truth separate.

## Accessibility / Density Findings

- Preview overlays are non-interactive and do not block node selection.
- Canvas density remains rough and will need later layout preset controls.
- Heavy visual acceptance remains deferred.

## Deferred UX Debt

- polished layout controls;
- editable layout presets;
- relation-aware layout;
- keyboard shortcuts;
- visual edge drawing;
- ViewPreset management.
