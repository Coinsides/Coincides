## 1. Goal

v2.4.1 makes the Learning Canvas usable as a real interaction surface:

```text
Canvas Document
  -> pan / zoom
  -> select nodes
  -> move / resize nodes
  -> save CanvasNode layout
  -> open source-backed targets
```

Canvas remains a projection over Coincides-owned objects. The external canvas engine, if adopted later, must stay an adapter and must not become the source of truth.

## 3. Canvas Engine Gate Result

Henry selected `tldraw` as the preferred first engine path. The gate result for this patch is:

- `tldraw` has the strongest interaction fit for future custom shapes, bindings, arrows, frames, and editor tooling.
- `tldraw` SDK production/packaged use requires a license key and its own license terms.
- The current client does not include a `tldraw` dependency.
- The current implementation should not be blocked on dependency installation or license setup.
- v2.4.1 therefore implements the local fallback now and preserves an adapter boundary for a later tldraw spike.

Adapter rule:

```text
Coincides data
  -> learning_canvases / canvas_nodes / canvas_viewport_states
  -> canonical

Canvas engine state
  -> local React/CSS now, possible tldraw later
  -> adapter/cache only
```

---

## 4. Implementation Contract

Frontend:

- replace the static `Canvas Document` preview with an interactive canvas surface;
- support pointer panning on empty canvas space;
- support wheel zoom and toolbar zoom/reset controls;
- support node selection;
- support node movement and bottom-right resize handle;
- persist layout on drag/resize end;
- display selected object scope with stable object ids;
- keep open/jump and archive actions available.
- render Canvas Document as a primary course workspace, not as a nested card inside the infinitely growing source/material rail;
- provide a focus mode so the canvas can occupy a near-full workspace when the user needs room to operate.

Server:

- reuse existing `/api/canvases`, `/api/canvas-nodes`, and `/api/canvases/:id/viewport`;
- persist node layout through existing `PUT /api/canvas-nodes/:id`;
- persist viewport through existing `PUT /api/canvases/:id/viewport`;
- no schema migration is required.

Data safety:

- moving/resizing a node changes only `canvas_nodes`;
- panning/zooming changes only `canvas_viewport_states`;
- no NoteBlock, source, evidence, proposal, source board, or source scope row is rewritten by canvas interaction;
- the canvas can be rebuilt from Coincides tables without any external canvas snapshot.
