## 1. 结论

V2.BN.11.4 已完成 Package A：Purpose 的直接成员边现在同时支持 `content_group | item`，并建立了不反写数据库的 Purpose compiled scope。Item Inspector 具备最小 direct membership 操作面，后续 Relation Inspector 可以复用 Purpose-bounded Item 搜索。

本回执只声明工程实现、自动验证与浏览器 smoke 完成，不代替第三方复验，也不声明 Henry 已完成主观体验验收。

## 2. 数据与领域语义

- `purpose_members` 沿用已有 `member_kind / member_id` 形状，无需数据库迁移；两类成员在 server、validator、client DTO 与模型函数中同版升级。
- 新 direct Item edge 只允许指向当前用户的 active Item；missing、retired 与跨用户 Item 均拒绝。
- Purpose 全量替换会保留当前客户端不可见的历史边：deleted / missing ContentGroup，以及 retired / missing Item。
- stale client 若在 Item 退役前已加载 direct edge，退役后保存不会把该边当作新建边，也不会改写其历史 role / fitness / order 收据。
- compiled scope 只在读取时汇总 direct Item 与 `Purpose -> ContentGroup -> Item` 路径；同一 Item 按身份去重，但保留每条 direct / derived 来源。
- retired Item 不进入 active compiled scope；derived Item 从不写成新的 `purpose_members` 行。

## 3. 实现结果

### Server

- Purpose member normalizer、可见读取、存在性检查与 hidden-edge recovery 支持 Item。
- 新增 compiled scope service，返回 Item 摘要、direct / derived facts、membership kind 与可解释来源路径。
- 新增 `GET /api/purposes/:purposeId/compiled-scope`；带 `q` 时执行 Purpose-bounded Item search，支持结果上限。
- Purpose / Item / ContentGroup 的组合查询继续按 `user_id` 限域。

### Client

- `PurposeMemberKind`、compiled scope DTO、repository 与 normalizer 已补齐。
- Item direct membership 提供 upsert、remove、move、role / fitness 更新模型函数。
- Purpose 保存改为 generation-safe optimistic write；失败时只回滚仍属于该保存代次的状态。
- Item Inspector 显示 direct / via current group / no direct edge，并提供新增、显式保存、排序与移除操作；retired Item 不开放修改。

## 4. RED / GREEN

新增 server 契约覆盖：

1. Item validator 与 direct membership 完整 roundtrip；
2. active direct edge 的 role / fitness / reorder / removal；
3. retired / missing Item hidden-edge recovery；
4. 退役前 stale payload 不误删、不改写历史边；
5. retired / cross-user 新边拒绝；
6. direct + 多条 ContentGroup-derived path 去重与解释；
7. ContentGroup membership 动态变化即时进入下次 compiled read；
8. retired Item 排除、Purpose search 与 derived zero-persistence。

Client model contract 同时覆盖 Item kind 不洗型、direct membership 变更，以及 compiled scope 的防御性 active-only 过滤与 membership kind 推导。

## 5. 浏览器体验检查

真实浏览器完成以下旅程：

1. 打开已有 Note / ContentGroup / active Item；
2. 将 Item 加入默认 Purpose，刷新后 direct 状态仍在；
3. 修改 role 为 `exam_core`、fitness 为 `essential` 并显式保存，刷新后仍在；
4. 移除 direct edge，刷新后保持移除；
5. 直接验证 Purpose list 与 compiled-scope search endpoint 均返回 200；
6. 测试数据最终恢复为无 direct edge。

首次 smoke 暴露出一个真实 UI 崩溃：React synthetic event 的 `currentTarget` 被延迟到 state updater 内读取。实现已改为在 updater 外先复制 primitive value，随后重新走完上述旅程并通过。前后端进程已在测试后关闭。

## 7. 有意保留的边界与风险

- 本版没有建设完整 Purpose 工作台、Relation Inspector 或图布局。
- compiled scope API 已可用，但尚未成为独立 UI 视图的数据源；Item Inspector 的 `via current group` 只陈述当前打开 ContentGroup 的已知路径。
- 浏览器 smoke 只有一个 direct Item，未在 UI 中实际演练多 Item 排序；排序已由 server 与 client model contract 覆盖。
- Purpose 保存仍是全量替换协议；hidden-edge 与 generation-safe rollback 已加硬，但第三方仍应重点对抗 stale client、并发保存及异常回滚。
- V2.BN.11.5 不得在第三方签收本版前发车。
