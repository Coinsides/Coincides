> **状态 (Status)**: engineering complete; third-party browser gate pending
> **日期 (Updated)**: 2026-07-11
> **上游范围**: `docs/releases/V2.BN.10-plan.md` v3

> **定位**: 薄施工单；把已经成立的 Source identity、placement、intake 与 materialization 交给用户，不扩张删除、出版或 Agent 范围
> **工程回执**: `docs/releases/V2.BN.10.4-Source-Library-And-Project-Experience-Review.md`
> **体验交接**: `docs/agent-ops/handoffs/2026-07-11-v2bn10.4-source-experience-browser-smoke.md`

## 目标

让用户可以在一个全局 Source Library 和 Project Sources 中完成：

```text
上传 / 去重放置
  -> 看见 received / parsing / publishing 状态
  -> 打开提取阅读视图或事实原件
  -> 在 SourceProjection 上继续 Annotation / ContentGroup / Purpose
```

同时让 SourceProjection 的内容锁在界面上可见，不再依赖服务端 `4xx` 才让用户发现正文不可改。

## 本版施工面

### 1. 共享 Source 客户端边界

- 建立统一 DTO、派生状态与状态感知打开矩阵；
- Library 与 Project 面板复用 list / precheck / upload / materialize / retry / blob 获取；
- 上传前 client SHA-256 仅作网络优化，服务端仍是最终裁判；
- 只有 `received / parsing / publishing` 存在时约 3 秒轮询，页面隐藏时暂停；
- 原件必须通过认证请求取得 Blob，再预览或下载，不暴露裸受保护 URL；
- 明确区分 `materialized`、`stored_only`、`failed` 与 `projection_missing`。

### 2. Source Library

- 替换当前占位页，提供名称搜索、类型筛选、状态筛选、上传和刷新；
- 行项目显示名称、格式、派生状态、上传时间与 placement 数；
- 详情展示 Origin receipt、当前 placements、文件事实、materialization 与 typed error；
- 可重试失败才显示 Retry；
- 同时提供“打开提取内容”“查看原件”“下载原件”；
- 删除只保留明确不可用的生命周期边界，不在 10.4 伪造删除行为。

### 3. Project Sources

- 在 Project 详情中建立 Sources 区和唯一主上传入口；
- 跨 Project hash 命中后幂等 placement，并立即刷新当前 Project 列表；
- 旧 Documents 若存在只读显示，但其 Upload / Manage 不再作为正常入口；
- Project 列表里的 Sources 命令导航到 Project Sources，而不是打开 legacy DocumentManager；
- Origin 与 Placement 分开显示，不把 Project 表现为 Source owner。

### 4. SourceProjection 锁定体验

- 标题、正文编辑、Block 新建 / 删除 / 拖动 / 重排、PageFrame 与 CanvasObject 内容变更入口按 read-only policy 禁用或隐藏；
- 显示“Source 内容锁定，解释与组织可编辑”的紧凑状态；
- 页面浏览、原件访问、Annotation、ContentGroup、Purpose 与明确允许的表现层操作继续可用；
- 服务端 guard 仍是最终写边界，客户端只负责正确表达与减少无效请求。

## RED-first 与验证

先加入会失败的 Source Experience contract，至少锁定：

1. Source Library 不再是占位页，并使用共享 Source 数据层；
2. CourseDetail 使用 Project Sources，Courses 不再唤起 legacy DocumentManager；
3. 状态派生和打开矩阵覆盖 active / materialized / failed / stored-only / projection-missing；
4. SourceProjection 锁策略已经传入真实 Chrome 与 Writing Surface；
5. detail DTO 能诚实报告 projection 是否仍存在。

本轮由 Codex 执行 model / contract / server / build / diff / secret 验证。浏览器 Smoke 按 Henry 的决定移交第三者，并由单独 `to: claude, status: ready` handoff 列出真实文件矩阵、操作步骤和预期结果。

## 非目标

- Source 硬删除、quarantine、receipt survival 与 Project 删除迁移；
- legacy Documents 数据迁移；
- Edition / Publication / 重物化 UI / parser 切换；
- OCR、MinerU、表格高保真还原；
- Agent、embedding、Relation 或 GraphRAG；
- 浏览器主观验收由 Codex 在本轮直接执行。

## 退出门

- Source Library 与 Project Sources 使用同一 Source truth 和同一上传路径；
- 所有 Source 状态都有确定打开行为，不进入空路由或半成品投影；
- 跨 Project 去重后当前 Project 立即可见；
- SourceProjection 锁定在提交写请求前即可被用户理解；
- legacy Documents Upload 不再是正常入口；
- 新契约、Source server suites、client/server build、`verify:v2-bn8-runtime`、secret scan 与 `git diff --check` 通过；
- Review、current-state 与第三者浏览器 Smoke handoff 同步。

## 自检问题

收口前再问：

> 用户只看界面，能否准确判断一个 Source 当前在哪里、发生了什么、现在能做什么，以及为什么某些正文操作不可用？

如果答案仍依赖猜测、死点击或服务端报错，10.4 不得收口。
