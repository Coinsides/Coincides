# V2.BN.7 Review - Runtime Autopsy, Branch Closure, And Canvas Engine Gate

## Review Result

V2.BN.7 是一次阶段性收口，不是功能发布。

本版本完成了 Better Notebook 当前 branch 的 runtime autopsy、branch closure 和 Canvas Engine gate 文档。核心结论是：

```text
当前 runtime 有很高的证据价值。
当前 runtime 不应继续作为未来 Canvas Engine 的长期地基。
V2.BN.8 应进入 clean branch Canvas Engine Foundation。
V2.BN.8.x 必须预留反复打磨空间。
```

## 质量判断

### 已经足够明确的判断

- Coincides Core 仍然拥有 content / layout / source / relation / template truth。
- Runtime 是连接用户操作、临时状态、交互计算和持久 truth layer 的运行层。
- 当前 `NoteDetail.tsx` runtime 已经证明产品体验方向，但也暴露了长期技术债。
- 未来 Canvas Engine 应在 clean branch 中重建 coordinate / measurement / selection / overlay / viewport。
- 当前 branch 应保留为 fallback，而不是删除或否定。
- AFFiNE / BlockSuite 是参考和 fallback，不是默认主权层。

### 仍需 Henry 拍板的点

1. 是否确认当前 branch 正式进入 experiment / fallback / reference 状态？
2. 是否确认 V2.BN.8 使用 clean branch 做 self-owned Canvas Engine？
3. 是否允许 Canvas Engine clean branch clean reset 当前实验性 layout 数据？
4. 是否确认不为 `better_notebook_layout` 写长期 converter，除非未来出现真实用户数据？
5. 是否确认 V2.BN.8.x 可以持续打磨，直到 Canvas Engine 达到工程可靠和体验可靠？
6. 是否确认 AFFiNE / BlockSuite 暂时作为参考和 fallback，而不是默认 substrate？

## 风险

- Canvas Engine 是硬工程，不应低估 text editing under transform、measurement、overlay、selection 的复杂度。
- 如果 V2.BN.8 试图一次性做完整无限画布、relation、media、export、Template Studio，会进入过大范围。
- 如果忽略 current branch 的失败经验，未来很可能复现 auto-height、popover、z-index、collision、page/canvas filtering 的问题。
- 如果过早进入 Template Studio / Source Library / Relation Runtime，会把高级能力建在不稳 runtime 上。

## Review Verdict

V2.BN.7 产物足够支撑进入 V2.BN.8 Canvas Engine Foundation 的准备阶段。

但进入 V2.BN.8 前必须接受一个现实：

```text
Canvas Engine 是新地基，不是旧 NoteDetail runtime 的继续补丁。
```

4. V2.BN.8.x 持续验证工程可靠和体验可靠。
