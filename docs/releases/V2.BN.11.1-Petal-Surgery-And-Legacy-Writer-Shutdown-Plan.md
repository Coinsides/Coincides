# V2.BN.11.1 Plan - Petal Surgery And Legacy Writer Shutdown

> **状态 (Status)**: engineering complete; pending third-party review
> **日期 (Updated)**: 2026-07-13
> **上游范围**: `docs/releases/V2.BN.11-plan.md` §0.2 / §11.1
> **Go 与审查依据**: `docs/agent-ops/handoffs/2026-07-13-v2bn11-go-decision-and-11-1-authorization.md`
> **施工回执**: `docs/releases/V2.BN.11.1-Petal-Surgery-And-Legacy-Writer-Shutdown-Review.md`
> **定位**: Package C 代码手术；只停活读写与旧入口，不做 migration 047 数据清场

## 目标

让旧 Petal / Fragment 与 Courses Learning Canvas Relation 世界停止继续生产或复活数据，同时保持当前 Better Notebook、ContentGroup 成员组织、Source Floor、CanvasObject 和 `visual_connector` 正常工作。

完成后应满足：

```text
ContentGroup active model = identity + members + placements/view state
Petal / Fragment tables = schema 仍在，但 active code 无 read/write/prune/seed
legacy Courses Learning Canvas = UI 不可达，五组 API route 未挂载
current Note Canvas / visual_connector = 不受影响
```

## 锁定不变量

1. 11.1 不新增 migration，不 DROP、重建或主动清空数据库表。
2. `content_group_fragments / content_group_petals / content_group_petal_fragments` 三表完整保留到 11.2 migration 047。
3. 11.1 后保存任意 ContentGroup 不得增加、替换或主动 prune 三表行。
4. 11.1 后读取 ContentGroup 不得从 entity tables 或 legacy JSON hydrate `fragments / petals`。
5. Client active DTO、normalizer 和 UI 不再包含 Petal / Fragment；不能只把按钮藏起来。
6. 旧 Learning Canvas route 必须 unmount；只隐藏 CourseDetail 区块不算下架。
7. 仍被 Source Floor / composition / Canvas infrastructure 调用的底层 helper 按引用保留；不以“legacy”名义误删现役能力。
8. Better Notebook `visual_connector` 与旧 `canvas_edges` 是不同系统；前者必须有正控回归。

## 非目标

- migration 047 与五张 Item / Relation 新表；
- 重建 `content_group_members` 或加入 `item_id`；
- DROP Petal 支持表、`object_relations`、`canvas_edges`、`relation_layers`；
- Item 认领、Purpose Item membership、Relation commands、freshness 或 inspector；
- 图谱 UI、Agent、embedding、GraphRAG；
- 对旧 Petal 数据做迁移、导出或恢复体验。

## 当前代码实证

### Client Petal 活面

- `runtimeDataTypes.ts` 定义 `ContentGroupFragmentV1 / ContentGroupPetalV1`，并把 `fragments / petals` 放入 `ContentGroupV1`；
- `contentGroupService.ts` 包含 create / normalize / assign / move / rename / remove / prune / graph validation 等完整 Petal helper；
- `SingleContentGroupEditor.tsx` 暴露 Petal dock、拖放、分配、改名、排序和删除；
- `contentGroupRelationProjectionService.ts` 把 group / petal / member 投影为旧 Relation endpoint，当前无消费者。

### Server Petal 活面

- `contentGroups.ts` 从三张 entity table 或 `fragments_json / petals_json` hydrate；
- upsert 全量 replace 三张 entity table，并清空 legacy JSON；
- member delete 会显式 prune entity 与 embedded Petal 结构；
- schema 与 migration 034 定义三张支持表，本小版本只读不改。

### Legacy Learning Canvas 活面

- `CourseDetail.tsx` 仍 fetch/create/select/render `LearningCanvasSurface`，并暴露 seed、edge、relation bind 与 layout proposal 操作；
- `server/src/index.ts` 仍挂载 `/api/canvases`、`/api/canvas-nodes`、`/api/canvas-edges`、`/api/relation-layers`、`/api/object-relations`；
- `learningCanvases.ts` 与 composition / Source paths 有交叉引用，必须先按函数消费者拆分，不能默认整文件删除。

## RED-first 证明

实现前先建立会在旧代码下失败的检查：

1. Client contract：active runtime type、ContentGroup service 与 Single Editor 不得出现 Petal / Fragment active symbol 或交互文案。
2. Server roundtrip：预置三表遗产行后，读取 ContentGroup 不返回 `fragments / petals`；保存普通成员修改后，三表行与 legacy JSON 保持不变。
3. Route contract：`server/src/index.ts` 不再 import 或 mount 五组 legacy route。
4. UI contract：`CourseDetail.tsx` 不再 import/render `LearningCanvasSurface`，也不再调用 legacy `/canvases` 路径。
5. Dead projection contract：仓库不存在 active `contentGroupRelationProjectionService` 消费者或文件。
6. 正控：Note Canvas / CanvasObject 的 `visual_connector` 仍通过既有 model/runtime contract。

优先复用现有静态 contract 和 Node test 习语；若新增检查脚本，必须进入 package script 与主验证命令，不能成为无人运行的孤立文件。

## 施工批次

### Batch A - Contract RED

- 添加 V2.BN.11.1 静态边界检查；
- 把 server no-read/no-write roundtrip 写进 `v2ContentGroups.test.ts`；
- 先运行并记录旧实现下的预期失败面。

### Batch B - Client 停产

- 从 active runtime DTO 移除 Fragment / Petal 类型与字段；
- 删除 `contentGroupService.ts` 的 Petal / Fragment helper 和相关 stability / graph 分支；
- Single Editor 改为直接管理 ContentGroup members，不显示或编辑 Petal；
- 保持 identity、Purpose role、GroupFolder、成员拖入/移除与来源预览可用；
- 删除 dead relation projection。

### Batch C - Server 停读停写

- ContentGroup hydrate 只返回 identity / placement / members / view state / metadata；
- upsert 固定保留旧 JSON 列，不再接收或 replace Petal / Fragment；
- member delete 移除显式 Petal prune；数据库旧 FK 的被动行为不冒充 active writer；
- 不改 migration 031/034，不删 schema 表定义。

### Batch D - Legacy Learning Canvas 下架

- 从 CourseDetail 移除旧 canvas state、fetch、handlers 与 surface；
- 从 server index 移除五组 route imports / mounts；
- 经引用审计删除只服务于旧 route/UI 的 dead modules；
- 对仍被 Source Floor / composition infrastructure 使用的函数或表保持不动，留给 047 和后续专门清理。

### Batch E - 验证与回执

- 定向 contract 与 `v2ContentGroups`；
- `server npm run test:v2`；
- client/server production build；
- Canvas runtime/model contract 与 `visual_connector` 正控；
- `git diff --check`、changed-file secret scan；
- 写 11.1 Review，列明实际删除/保留触点与未执行 DROP 的证据。

## 退出门

- 三张 Petal 表仍存在于 schema 和 migration history；本小版本 diff 无 migration / DROP；
- ContentGroup read/write path 对 Petal / Fragment 零 active read/write/prune；
- client build 无 `ContentGroupFragmentV1 / ContentGroupPetalV1` active 引用；
- Single Editor 保留成员组织主流程，Petal UI 与文案消失；
- 五组 legacy route unmount，CourseDetail 不再进入旧 Learning Canvas；
- `visual_connector`、Note Canvas、PageFrame、ContentGroup member roundtrip 全绿；
- 全量机器门通过并留下第三方可复核回执。

## 自检问题

收口前必须回答：

> 如果 047 永远不运行，11.1 之后系统是否仍能正常使用 ContentGroup，而三张 Petal 表只作为无人读写的冻结遗产存在？

若答案不是明确的“是”，说明 11.1 偷做了数据清场、仍依赖旧表，或把 11.2 的责任提前混入本版本，不得收口。

**施工回答（2026-07-13）**：是。047 不运行时，ContentGroup 的 identity、members、placements/view state 仍可独立读写；三张 Petal 表只保留为活动代码不再 hydrate、replace、prune 或 seed 的冻结遗产。
