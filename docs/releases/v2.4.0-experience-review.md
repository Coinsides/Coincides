# v2.4.0 Experience Review - Canvas-first Document Model + Canvas Data Contract

**Created**: 2026-05-22
**Updated**: 2026-05-22
**Current Experience Status**: `PASS_WITH_FOLLOWUP`

---

## UI / Visual Findings

v2.4.0 addresses the product direction behind several v2.3 UX findings by adding the first `Canvas Document` seed surface:

- source workspace panels are too vertically expanded;
- Source Snapshot display feels nested and awkward;
- Source Snapshot, Source Scope, and Source Board responsibilities overlap in the UI;
- generated NoteBlock surfaces are still too raw before Canvas;
- Henry wants AFFiNE-like layout clarity without copying AFFiNE's dual-mode architecture.

The exact theme is not the target. The target is layout discipline, canvas-first document clarity, and a cleaner workspace hierarchy.

Current v2.4.0 result:

- Course Detail now has a dedicated `Canvas Document` panel.
- New canvases default to an A4-style finite page preview.
- Source Board nodes can be seeded into the canvas as positioned node cards.
- This is still a foundation preview, not a full AFFiNE-like canvas.
- Light browser smoke confirmed the `Canvas Document` entry appears in Course Detail.

## Interaction Findings

Current intended direction:

```text
Canvas-first document surface
  -> page-like reading preset
  -> finite canvas preset
  -> infinite board preset

Source/context drawer
  -> inspect references, anchors, scopes, and board nodes when needed
```

v2.4.0 should not overbuild keyboard shortcuts or gesture input. Those belong in the later Command & Interaction System track.

Implemented interaction level:

- create/select canvas;
- seed from selected Source Board;
- open source-backed canvas nodes through existing jump-target behavior;
- archive canvas nodes.

Not implemented yet:

- free drag/drop;
- pan/zoom;
- selection handles;
- edge drawing;
- canvas keyboard shortcuts.

## Workflow Findings

The source workflow should gradually move from long stacked panels toward contextual surfaces:

```text
Source Snapshot / Anchor / Scope / Board
  -> projected into the canvas-first document surface
  -> raw mechanics hidden unless needed
```

v2.4.0 starts this move but does not complete it. The rough v2.3 panels still exist; Canvas is now present as a new projection layer that v2.4.1+ can make primary.

## Product Fit Findings

Canvas fits Coincides only if it remains source-grounded.

It should help users understand, arrange, and inspect learning/source objects. It should not become a separate whiteboard where AI-generated layout is mistaken for verified knowledge.

v2.4.0 follows this rule: nodes reference existing objects and do not become new truth copies.

## Accessibility / Density Findings

v2.4 must reduce vertical sprawl over time.

Likely future tools:

- projection preset selector;
- source drawer;
- inspector panel;
- canvas zoom controls;
- selected node detail panel;
- hidden-by-default debug labels.

## Deferred UX Debt

Deferred unless v2.4.0 explicitly promotes them:

- full visual redesign;
- final Note editor redesign;
- polished Source Snapshot viewer;
- drag/drop NoteBlock editor;
- custom visual styles for arrows, frames, shapes, backgrounds, stickers, and flowchart themes;
- 2.5D or 3D note space.
- full AFFiNE-like app shell polish.

## Henry Acceptance / Priority Decisions

Pending Henry release/hold decision.

Henry's v2.4.0 acceptance should focus on:

- whether the canvas-first single-surface direction is right;
- whether the v2.4.x patch breakdown is controllable;
- whether the v2.4.0 A4 canvas seed is enough foundation for v2.4.1;
