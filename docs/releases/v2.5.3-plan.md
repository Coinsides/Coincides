# v2.5.3 Plan - Domain Block Set + Package Manifest

## Goal

v2.5.3 adds the first runtime foundation for `DomainBlockSet` and `PackageManifest`.

The purpose is to organize v2.5 runtime templates and composition templates into safe, inspectable domain packages. A package is data, not executable code. A domain block set is a composable domain capability bundle, not a rigid taxonomy tree.

## Scope

v2.5.3 includes:

- persistent `PackageManifest` runtime;
- persistent `DomainBlockSet` runtime;
- domain membership links to `TemplateDefinition` and `CompositionTemplate`;
- system seed package `coincides.core.domain-seeds@0.1.0`;
- starter domain sets:
  - `learning.math.basic`;
  - `research.evidence.basic`;
  - `briefing.general.basic`;
- package validation and preview;
- domain compatibility report;
- Template Studio lightweight Domain Packages entry;
- AI operating manual and continuity updates;
- graph-native migration evidence.

## Out Of Scope

v2.5.3 does not include:

- full Package Studio;
- package import/export;
- marketplace or remote registry;
- executable plugins;
- automatic domain research agent;
- template migration proposal;
- graph database migration;
- rich editor integration;
- real provider/API evaluation.

## Acceptance Criteria

v2.5.3 is complete when:

- system package/domain seeds are idempotent;
- package manifests validate and preview without mutating runtime records;
- domain sets can resolve linked templates and compositions;
- unsafe package content is blocked by validation;
- Template Studio can display package/domain summaries and preview warnings;
- existing v2.5 template and composition flows still pass;
- review records graph-native migration evidence;
- browser smoke is run only after Henry confirms frontend/backend restart.
