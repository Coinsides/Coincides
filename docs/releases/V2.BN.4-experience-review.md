# V2.BN.4 Experience Review - Page / Canvas / Export Boundary

## Status

Browser-use experience smoke completed after Henry restarted frontend/backend. Henry accepted current V2.BN.4 scope for closure.

## Experience Questions

V2.BN.4 should be accepted only if the page/canvas boundary becomes understandable without forcing the user to think like an engineer:

- Can the user tell whether they are in Page mode or Canvas mode?
- Does Page mode still feel calm and document-like?
- Does Canvas mode clearly reveal a scratch workspace without making the page feel lost?
- Can the user understand what will export?
- Can the user understand that AI visibility is different from export visibility?
- Do policy badges stay light enough not to ruin reading?

## Observations

Impeccable review lens:

- The feature moves the product toward a clear mental model: formal document surface plus thinking workspace.
- Keeping Page mode as the default respects the user's current writing workflow.
- Canvas mode now has a visible formal page boundary, which is necessary before relation/scratch/source work can become coherent.

Taste review lens:

- Export and AI policy badges are intentionally compact.
- The preview is small and explanatory, not a heavy modal.
- The scratch workspace label is light and should not compete with real note content.

Browser smoke observations:

- Page mode opens as the default and still reads as the formal writing surface.
- Preview is discoverable from the top chrome and explains included/excluded plus AI visible/hidden counts.
- Canvas mode exposes a larger workspace while keeping a visible formal page boundary.
- Selected-block export and AI visibility controls are compact and reversible.
- The tested smoke note was restored to export included / AI visible after toggle checks.

Remaining risks:

- Whether the wider Canvas mode feels cramped on smaller screens.
- Whether policy badges overlap text in small/narrow blocks.
- Whether switching back to Page mode hides scratch objects in a way that feels explainable rather than alarming.
- Whether real outside-page scratch blocks feel obvious enough once Henry creates or moves blocks outside the formal boundary.

Accepted follow-up behavior:

- Preview no longer forces page labels to appear.
- Page labels can remain visible after the Preview panel is closed.
- Canvas workspace blocks are hidden from Page mode and visible in Canvas mode.
- Page mode block spacing is close enough for the current writing pass.
- Full edgeless behavior remains intentionally deferred.

## Browser Smoke Checklist

Completed with browser use after Henry restarted backend/frontend:

```text
Open an existing note. Done.
Confirm Page mode is default. Done.
Open Preview and inspect included / excluded / AI visible / AI hidden counts. Done.
Toggle Canvas mode. Done.
Confirm formal page boundary and scratch workspace are visible. Done.
Select a block and toggle export inclusion. Done, then restored.
Select a block and toggle AI visibility. Done, then restored.
Switch back to Page mode and confirm the formal writing surface still feels calm. Done.
```

Not completed in this smoke:

```text
Move or create a block outside the formal page boundary.
Confirm page-outside block gets scratch / AI hidden behavior by default.
Reload the note and confirm outside-block policy state persists.
```

Reason: the existing smoke note did not already contain an outside-page scratch block, and this smoke avoided making a disruptive layout mutation before Henry's visual acceptance.
