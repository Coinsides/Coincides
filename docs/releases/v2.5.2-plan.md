## Goal

Create the first runtime seed for reusable section-level templates. A composition describes how multiple runtime templates fit together into a repeatable section such as a theorem/proof/example block, formula sheet, evidence comparison, or briefing section.

## Version Boundary

v2.5.2 includes:

- persistent `CompositionTemplate` runtime;
- system composition seeding;
- slot schema with required, optional, and repeatable slots;
- validation against runtime `TemplateDefinition` keys;
- deterministic composition proposal creation;
- proposal-first apply into new NoteBlocks, CanvasNodes, CanvasFrame, CompositionInstance, and slot records;
- relation blueprint suggestions stored as proposal/metadata only;
- Canvas-side entry to create and review a composition proposal;
- graph-native migration evidence.

v2.5.2 excludes:

- full Composition Studio;
- drag/drop composition designer;
- Package Studio;
- DomainBlockSet;
- rich editor adapter;
- confirmed ObjectRelation creation;
- graph database migration;
- silent migration or rewrite of existing NoteBlocks.

## API / Contracts

New composition template routes:

```text
GET /api/composition-templates
GET /api/composition-templates/:id
POST /api/composition-templates/seed-system
GET /api/composition-templates/compatibility-report
```

New proposal route:

```text
POST /api/proposals/composition-template
```

Existing proposal routes:

```text
POST /api/proposals/:id/apply
POST /api/proposals/:id/discard
```

Rules:

- proposal creation is non-mutating except for the proposal record;
- apply creates new content/projection records only;
- relation blueprints do not create confirmed ObjectRelations;
- old blocks, sources, templates, and existing relations are not modified.

## Data Model

Migration:

```text
server/src/db/migrations/026_v2_composition_templates.ts
```

Tables:

- `composition_templates`
- `composition_instances`
- `composition_instance_slots`

`composition_templates` stores identity, display fields, slot schema, layout behavior, source behavior, relation blueprint, proposal behavior, and `summary_for_agent`.

`composition_instances` records applied usage of a composition.

`composition_instance_slots` records each filled or skipped slot and links it to created blocks/nodes/frames.

## Agent Tool Contract

Agents may propose compositions when a section needs a reusable structure.

Agents must:

- resolve slot templates through runtime `TemplateDefinition`;
- treat missing or skipped slots as explicit preview warnings;
- preserve source references when provided;
- keep relation blueprints suggested-only;
- apply only through proposal review.

Agents must not:

- silently rewrite old content;
- create confirmed ObjectRelations from blueprints;
- invent unknown template keys;
- treat a composition as source truth or graph truth.
