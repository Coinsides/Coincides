## 1. 收口判断

V2.BN.10.2 已完成工程收口，可以进入 V2.BN.10.3 Parser And Atomic Materialization。

本版本把真实文件安全接入 10.1 的四层 Source 数据脊柱，并闭合了临时文件、数据库 staging identity、最终 blob 与 ready 状态之间的故障补偿。它没有提前把“文件已收存”冒充成“内容已解析”，也没有为了演示而增加半成品 Source UI。

## 2. 已完成

- 新增独立 Source multipart middleware，文件先写入应用管理的 `<SOURCE_BLOB_DIR>/.tmp`，统一限制为 50MB 且一次只接收一个文件。
- 建立文件能力矩阵。PDF、DOCX、TXT、Markdown、PNG、JPEG、WebP 进入 materializable candidate；PPTX、XLSX、CSV 作为 stored-only candidate 安全收存，但本版本不承诺内容提取。
- 校验扩展名、MIME、最小 magic/text sanity、空文件、伪文本 NUL 与体积上限；服务端从磁盘临时文件流式计算 SHA-256，数据库唯一约束仍是并发去重的最终边界。
- 打通 `temp -> DB staging -> same-volume rename -> DB ready` 生命周期。成功响应只在最终 blob 存在且 `storage_state='ready'` 后返回。
- 同用户同 hash 幂等复用既有 Source，并补当前 Project placement；不同 Project 不再出现“提示已存在但当前 Project 看不到”的死路。
- 同名不同 hash 分配稳定 `(1) / (2)` 后缀，同时保留原始文件名收据。
- Source Library 上传会幂等建立或复用 Home system course；Project/import 入口要求目标 Project 真实归属于当前用户。
- 新增认证接口：hash precheck、multipart upload、list、detail、inline/download blob。DTO 不返回 `storage_key`、绝对路径或服务器目录。
- ready 行缺失 blob 时返回稳定 `blob_missing` 诊断；跨用户 list/detail/precheck/blob 均不可见。
- 服务启动时执行存储 reconciliation sweep：清理过期 temp；恢复“rename 已完成但 ready flip 中断”的 staging；删除超过窗口且没有最终 blob 的 stale staging；保留 fresh in-flight 状态。
- `Content-Disposition` 同时提供安全 ASCII fallback 与 RFC 5987 UTF-8 文件名，并清理控制字符、引号和反斜杠。

## 3. 故障语义

本版本对主要断点给出唯一、可验证的动作：

```text
校验失败 / target 失败
  -> 删除受管 temp，不建立 Source identity

DB identity stage 后、rename 前失败
  -> 删除 source_record，依靠级联清除 file/materialization/placement，并删除 temp

rename 失败
  -> 回滚本次四层 identity，删除 temp，不留下 final blob

rename 成功、ready flip 前中断
  -> 保留 staging + final blob，启动 sweep 确定性恢复为 ready

ready 行对应 blob 缺失
  -> 不伪造可用状态，返回 blob_missing；相同文件可重新上传修复
```

请求中断或异常遗留的临时文件由启动 sweep 兜底；清扫窗口不会误删仍可能在途的 fresh staging/temp。

## 5. 诚实边界与明确未做

- SHA-256 由服务端对 Multer 已落盘的受管临时文件进行流式读取，不把整份文件读入内存；当前没有自定义 Multer storage 在网络接收字节的同时计算 hash。服务端裁决权和内存边界已满足，若未来要减少一次磁盘读取，可在性能证据出现后替换上传适配器。
- 本版本只做 format capability classification。OOXML 解压膨胀、PDF 页数、parser 语义验证与各格式内容上限属于 10.3。
- 未执行 PDF/DOCX/TXT/image 解析，未生成 SourceArtifact，也未发布投影 Note/Block。
- 未实现 materialization claim/retry、parser run worker、原子 projection publication 或崩溃恢复。
- 未实现 Source Library / Project Sources UI、client WebCrypto precheck 或 SourceProjection 写守卫。
- 未实现 Course 删除迁 Home、Source 硬删 quarantine、legacy Documents 迁移、Edition、Agent、embedding、Relation 或 GraphRAG。

## 6. 工程判断

10.2 证明四层 Source 脊柱可以承接真实文件，而不退化为 metadata 或第二套上传真相：

```text
source_records             = 稳定 Source identity
source_files               = 事实附件与存储状态
source_materializations    = 后续 parser/materialization run
source_project_placements  = Project 可见镜头
```

下一步 10.3 应只把 parser 与原子物化接到现有 `source_materializations` 上：收存成功不等于解析成功，解析失败不得破坏 ready blob，投影发布也不得产生半篇 Note。文件 intake 层不应继续吸收 parser 职责。
