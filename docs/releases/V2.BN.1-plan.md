# V2.BN.1 Plan - Product Shell And Note-First Navigation

## Summary

V2.BN.1 starts the Better Notebook productization track in product code. Its goal is not to rewrite the editor yet, but to make Coincides enter the right product hierarchy:

```text
Projects
  -> Project detail / note list
      -> Note workspace
          -> Canvas Document / page editor surface
```

This version corrects the current engineering-shell feeling where opening a Project drops the user directly into a `Canvas Document` card inside a larger Project page. A Project may contain many notes, so the Project surface must become note-first. Once a note is opened, the note/canvas workspace should feel like a top-level working surface, not a nested dashboard card.

Visual theme reset is important, but it is split into `V2.BN.1.1` so that `V2.BN.1` can stay focused on navigation and information architecture.

## User Workflow

### Project Entry

User opens the app and chooses a Project.

Expected result:

- the user sees a Project detail page;
- the Project detail page shows notes first;
- source/debug/template/proposal surfaces are not the main default view;
- opening a note is a deliberate action.

### Note Entry

User selects a note from the Project detail page, Favorites, Recent, or direct navigation.

Expected result:

- the note opens as a top-level workspace;
- the main area is the note/canvas surface;
- the canvas is not visually trapped inside nested cards or floating dashboard panels;
- note metadata, source summary, and advanced actions can exist, but they should not compress the writing surface.

### Canvas Document Entry

User opens the current Canvas Document note.

Expected result:

- Canvas Document behaves as a note surface;
- existing v2.x canvas nodes and canvas block workflows remain reachable;
- the UI no longer suggests that Canvas Document is merely a sub-panel inside Course Detail.

## Data / State Impact

This version should prefer UI/routing reuse over data migration.

Touched:

- Project/Course presentation state;
- route aliases and navigation labels;
- Project detail UI state;
- note/canvas workspace presentation;
- sidebar/favorites/recent placeholders, if backed by existing data or local UI state.

Not touched unless current code proves it is required:

- NoteBlock content truth;
- CanvasNode placement truth;
- SourceReference / provenance truth;
- ObjectRelation truth;
- TemplateDefinition / package truth;
- GraphRAG or adapter state.

Data repair question:

- Existing `course_id` may remain as internal storage.
- User-facing language should prefer `Project`.
- If the app does not yet have a mature note list API, V2.BN.1 may use existing notes/canvas documents available under the current Project rather than inventing new persistence.
- Do not create fake persisted favorites if the data model is not ready. Use a clearly marked placeholder or existing recoverable state.
- Opening a note must not mutate content, sources, relations, templates, or canvas nodes.

## Key Changes

### Project Shell

- Main navigation should present `Projects`, `Source Library`, `Template Studio`, and `Settings`.
- Daily writing entry should favor Projects and Notes.
- Advanced tooling should remain reachable without being the first thing the user sees.

### Project Detail

- Project detail should be a landing surface for the selected Project.
- It should show notes/canvas documents as selectable items.
- It should not auto-open a Canvas Document as the primary default body.
- Existing source or board panels should become supporting sections, not the main writing path.

### Note Workspace

- A selected note should open in a workspace route/state that can later host Natural Page Writing, freeform block layout, page/canvas boundaries, source badges, and relation tools.
- The first workspace layout should remove obvious nested-dashboard framing around the canvas.
- Full editor rewrite is deferred, but the shell must not fight the future editor.

### V2.BN.1.1 Follow-Up Patch

The current purple glassmorphism visual language is not the Better Notebook baseline.

`V2.BN.1.1 - Visual Baseline And Theme Reset` should follow immediately after V2.BN.1 and cover:

- pure light and pure dark baseline modes;
- removal of decorative glassmorphism as the default product style;
- restrained accent palette;
- solid, readable surfaces;
- button and control styling reset;
- consistent app-level visual vocabulary before deeper editor work begins.

## Out Of Scope

V2.BN.1 does not implement:

- Natural Page Writing;
- blank page caret behavior;
- slash command;
- freeform NoteBlock resize;
- field layout;
- A4 page/export boundary;
- source chain/provenance behavior;
- relation runtime changes;
- local graph view;
- visual theme reset beyond obvious blockers required to avoid unusable navigation;
- AI note generation;
- OCR/VLM import;
- GraphRAG adapter;
- database migration unless the existing route/data shape cannot support note-first navigation safely.

## Acceptance Criteria

- Opening a Project does not immediately drop the user into a Canvas Document work area.
- Project detail clearly exposes notes/canvas documents as selectable work items.
- Opening a note presents it as the main workspace.
- Canvas Document is no longer visually framed as a small card inside a larger dashboard card.
- Source Library and Template Studio remain available without dominating the daily writing flow.
- Existing Course/Project data still loads.
- Existing canvas nodes remain reachable.
- No content/source/relation/template truth is silently mutated by navigation changes.
- The plan explicitly records `V2.BN.1.1` as the visual baseline/theme reset patch.

## Graph-Native / Adapter Evidence

V2.BN.1 should produce no graph-native migration or adapter evidence beyond a clearer product boundary:

- Project/Course is a user-facing organization unit;
- Note workspace is the surface that will later host source, relation, concept, and adapter signals;
- navigation and projection state must not become semantic truth.

## Assumptions

- Internal database names such as `course_id` can remain.
- `Project` is the user-facing term.
- `Canvas Document` is currently the practical note surface, but the product should treat it as a note/workspace, not as a Course Detail sub-panel.
- `V2.BN.1.1` is the right place to remove the purple glass/glassmorphism style and establish light/dark visual baseline.
