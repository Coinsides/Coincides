# V2.BN.5 Review - Block Visual Language And Control Layer

## Scope

V2.BN.5 moved the block layer from engineering-card behavior toward a notebook object model.

This review covers the implemented code slice:

- visible default block entry is narrowed;
- Definition and Formula are the first structured block seeds;
- structured field values are written into `content_json.field_values`;
- legacy body/structured_fields fallback remains readable;
- category membership is treated as menu discovery, not canonical identity.

## Risk Notes

- Existing persisted runtime templates may still carry older default content. The editor normalizer keeps old content readable, but fully refreshing seeded template content belongs to a future data-contract pass if needed.
- Field layout is intentionally fixed in this version. User-controlled field box layout is deferred.
- Category membership is currently a discovery/menu rule. It should not be treated as a durable taxonomy until the later Template Studio productization phase.
- The floating Insert panel should be rechecked in a wider viewport. The narrow in-app browser side panel made the Insert interaction difficult to judge cleanly.

## Graph-Native / Adapter Evidence

- Structured fields make future graph export safer because a Definition node label can come from `concept_name` instead of inferred paragraph text.
- Formula graph/export payloads can use `latex_input` as explicit semantic payload.
- Category membership remains presentation/discovery metadata, not graph truth.
