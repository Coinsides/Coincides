## 1. 收口判断

V2.BN.10.3 已完成工程收口，可以进入 V2.BN.10.4 Source Library And Project Experience。

本版本把 10.2 安全收存的 ready blob 接入真实 parser，并把解析结果一次性发布为只读 SourceProjection。解析失败只改变 durable materialization run；发布失败会回滚 Note、Block、Canvas、receipt 与 operation batch；重试复用同一 run，不会制造第二份 current projection。

## 2. 已完成

### 2.1 Transient SourceArtifact 与 parser registry

- 新增版本化内部 DTO `source-artifact.v1`。它只存在于解析与 materializer 之间，不落数据库，也不冒充 Agent API。
- PDF 使用 `pdf-parse` 2.x，保留 1-based `page_index`；DOCX 使用 `mammoth` 输出段落流；TXT / Markdown 输出 paragraph/heading 基线；PNG / JPEG / WebP 输出 image artifact，不伪造 OCR 文本。
- PPTX / XLSX / CSV 继续保持 `stored-only`。收到 materialize 请求时在 claim 前稳定返回 `unsupported_format`，run 保持 `received/attempt_count=0`，不会被误显示为解析失败。
- 建立统一资源门：PDF 最多 1000 页、artifact 最多 5000 blocks、DOCX 展开量最多为压缩文件 5 倍、parser 预算 120 秒。
- 稳定错误分类：`unsupported_format / invalid_or_corrupt / resource_limit` 不可重试；`parser_failure / internal_interrupted` 可重试。

### 2.2 Durable claim、retry 与恢复

- `source_materializations` 仍是唯一 durable run truth；没有新增持久化 SourceArtifact 表。
- claim 使用带旧状态条件的单条 `UPDATE`。并发请求只有一个赢家会启动 parser，`attempt_count` 只增加一次。
- retry 复用原 materialization id；不可重试错误返回稳定 409，已经 materialized 的 run 幂等返回既有 projection。
- 新增进程内异步 scheduler 与 `POST /api/sources/:sourceId/materialize`、`POST /api/sources/:sourceId/retry`。HTTP 请求在成功 claim 后返回 202，不等待 parser 完成。
- 服务启动时扫描超时的 `parsing / publishing` run，将其标为可重试 `internal_interrupted`，清理无 DB 引用的投影图片副本，并重新调度 ready blob 对应的 `received` run；`stored-only` 不会被误调度。

### 2.3 原子 SourceProjection 发布

- 文本 artifact 在一个数据库事务内发布 operation batch、`source_projection` Note、TextFlow-compatible Blocks、note placements、PageStack/PageFrames、CanvasObjects、CanvasPlacements、ContentMounts、source receipts 与 run final flip。
- Note 同时标记 `note_class='source_projection'` 与 `source_kind='source_projection'`；物化 Block 标记 `source_kind='source_projection'`。
- 图片 artifact 先建立独立、确定性的 Canvas asset 副本，再在同一 DB 事务内发布 image CanvasObject；Canvas 资产删除路径不会触碰 Source blob。
- DB 发布失败会立即删除未被引用的图片副本；进程中断遗留副本由启动 sweep 回收。
- materializer 使用专用 SQL 路径，不复用会注入模板、proposal 或旧 Documents 假设的普通内容 helper。

### 2.4 SourceProjection 写边界

- 服务端统一拒绝 SourceProjection 的 title/description/page format/status 修改、Note 删除、Block 创建/修改/删除/恢复/重排、PageFrame collection 修改、Canvas placement 与 CanvasObject 修改/删除。
- 保留 note metadata、`note_block_placements.display_overrides_json`、Annotation、ContentGroup 与 Purpose 的解释和组织写路径。
- `system` Note 与普通用户 Note 不受 SourceProjection guard 误伤。
- 客户端从真实 Note DTO 的 `note_class/source_kind` 派生只读 policy，现有内容写动作会在发请求前短路；完整禁用控件、状态文案与 Source 打开体验留给 10.4。

### 2.5 Legacy scanner 隔离

以下旧管线统一排除 `source_kind='source_projection'` 的 Block：

- template migration；
- domain refinement（包括显式 reclassification）；
- template usage；
- template compatibility report；
- legacy source-anchor generation。

这避免只读投影被旧模板或领域工具当作用户内容二次改写。

## 3. 故障语义

```text
ready blob + received run
  -> conditional claim -> parsing
  -> transient SourceArtifact
  -> publishing
  -> one transaction publishes the whole SourceProjection
  -> materialized + projection_note_id

parse failure
  -> typed failed run
  -> ready blob remains untouched

publish failure
  -> all DB projection rows roll back
  -> prepared image copy is compensated
  -> retry reuses the same durable run
```

任何非 `materialized` 状态都不持有 `projection_note_id`。单看数据库和两个受管 blob root，可以判断继续、重试、清理或打开哪一个投影，不依赖人工猜测。

## 6. 诚实边界与剩余风险

- 当前 120 秒 timeout 是服务层逻辑预算；第三方 parser 在同一 Node 进程内运行，超时后不能被强制终止。若未来出现真实资源压力，应将 parser 隔离到 Worker/子进程，而不是在本版本伪造可取消能力。
- DOCX 当前只保留 raw text 段落；PDF 表格、公式、嵌图重建，DOCX 结构化内容与 OCR/MinerU 均未实现。
- SourceProjection 初始 PageFrame/Block 高度采用保守估算，不等于 Word 级测量分页。
- scheduler 是进程内执行器，durable 状态在 SQLite；本版本没有引入外部任务队列、分布式 worker 或任务进度推送。
- 完整 Source Library / Project Sources 页面、上传进度、状态轮询、失败文案、只读控件与打开原件体验属于 10.4。
- 未实现 Source 删除、Course 删除迁 Home、quarantine、legacy Documents 迁移、Edition、Agent、embedding、Relation 或 GraphRAG。

## 7. 工程判断

10.3 证明 Source 的“事实附件”和“可读投影”可以分离：原件安全收存后，parser 可以失败、重试或更换执行方式，而不会污染原件；投影只有完整发布与完全不存在两种可见结果。

下一步 10.4 应只把真实 Source 状态呈现给用户，并使用现有 materialize/status/blob 接缝。不要在 UI 层再造第二套 upload、parser 或 projection truth。

## 8. Claude 复核（2026-07-11）— ✅ PASS

- **原子发布亲验**：单事务覆盖 run 复查→op batch→note（note_class+source_kind **双标记**）→page collection→页框（对象+placement+extension,带 source_page_index）→blocks（块级 source_kind+富 metadata:locator/page_index/artifact_block_id/parser）→note placements→**收据**（note_block_sources: source_record_id+materialization_id+页区间+摘录+reference_type）→块投影对象+mounts→（图片:asset 副本行+对象+extension）→**条件 final flip（changes≠1 即 throw 全回滚）**。半成品在事务语义下不可见,`projection_note_id ⇔ materialized` 不变量由 flip 条件+CHECK 双保。
- **图片副本补偿**：文件副本在事务**外**准备（补偿协议纪律）,异常即清理,进程中断由 orphan sweep 按 managed_by 标记+时龄回收——canvas 资产与 Source blob 生命周期隔离（副本语义）。
- **claim/retry/sweep**：claim 单条件 UPDATE（并发单赢家,attempt 只加一）;**stored-only 在 claim 前稳定 409、attempt=0、sweep/resume 双跳过——10.2 复核交接线完整接住**;不可重试错误不给 retry;超时 parsing/publishing → internal_interrupted(可重试);resume 只理 ready blob 的 received 行。
- **守卫矩阵亲验**：notes PUT **字段级**（title/description/page_format/status 拦,metadata-only 放行）/DELETE/块创建/重排 + noteBlocks PUT/DELETE（按块 source_kind,note 无关上下文也守得住）+ canvasObjects 四写路径——全部 409 带 code;'system' 与普通笔记不误伤（有测试）。
- **五台扫描机六个注入点全中**（domainRefinement 扫描+apply 写、sourceAnchors 候选、templateDefinitions 用量+兼容、templateMigration 扫描）,统一走 `legacyScannerBlockPredicate`（带 alias 注入防护）。

- **客户端接缝**：policy 从 note_class/source_kind 派生,allow-flags 形状合理;完整只读 UI 归 10.4。
- **亲跑**：materialization 11/11;test:v2 **214/214**（203+11 自洽）。
