# v2.3.3 Engineering Spec - Source Board Seed

**Created**: 2026-05-22
**Updated**: 2026-05-22
**Status**: Implemented

---

## 1. Implementation Boundary

v2.3.3 adds persistent SourceBoards and SourceBoardNodes as structured source-range workspaces.

It implements:

- additive SourceBoard tables;
- board and node APIs;
- idempotent board seeding from active SourceScopes;
- proposal creation narrowed by `source_board_id`;
- Course Detail Source Board panel.

It does not implement Canvas, drag/drop layout, edges, annotation editing, PDF rendering, or default real-provider tests.

## 3. API Behavior

Routes:

```text
GET /api/source-boards?course_id=...&status=...
POST /api/source-boards
GET /api/source-boards/:id
PUT /api/source-boards/:id
POST /api/source-boards/:id/archive
POST /api/source-boards/:id/restore
POST /api/source-boards/:id/seed-from-scopes
POST /api/source-boards/:id/nodes
PUT /api/source-board-nodes/:id
POST /api/source-board-nodes/:id/archive
POST /api/source-board-nodes/:id/restore
GET /api/source-board-nodes/:id/jump-target
```

Creation rules:

- Board creation requires `course_id`; `title` defaults to `Source Board`.
- Board nodes require a valid active board.
- `source_scope` nodes require an active SourceScope in the same course/user.
- `source_anchor` nodes require a SourceAnchor in the same course/user.
- Unsupported or missing targets fail clearly.
- Archive/restore only changes status.

---

## 4. Proposal Behavior

Proposal creation accepts:

```json
{
  "source_board_id": "board-id"
}
```

Resolution rules:

- Active board SourceScope nodes resolve to `source_scope_ids`.
- Explicit `source_scope_ids` are combined with board scope ids.
- Archived boards are rejected.
- A valid board with no active SourceScope nodes returns a warning and keeps course-level proposal behavior.
- Proposal JSON records `source_board_id`, resolved `source_scope_ids`, and `scope_summary`.

---

## 5. UI Behavior

- Course Detail shows a Source Board panel near Source Snapshots and Selected SourceScopes.
- Users can create multiple boards for the course.
- Users can select an active board.
- Users can seed active SourceScopes into the selected board.
- Board nodes can jump back to source pages when backed by SourceScopes or SourceAnchors.
- Board nodes can be archived.
- Proposal buttons use selected board scopes when a board is selected and has active SourceScope nodes; otherwise they keep existing active SourceScope behavior.
