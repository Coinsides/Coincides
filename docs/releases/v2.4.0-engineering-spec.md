## 1. Version Boundary

v2.4.0 introduces the first Canvas-first document foundation.

This version implements Coincides-owned canvas persistence, APIs, and a minimal Course Detail preview. It does not adopt `tldraw`, `Excalidraw`, or any other canvas SDK.

Canvas remains a projection layer:

```text
NoteBlock / SourceScope / SourceAnchor / SourceBoardNode / EvidenceSet / Proposal
  -> existing source-grounded objects

LearningCanvas / CanvasNode / CanvasEdge / CanvasFrame
  -> layout and presentation records
```

Default new canvas:

```text
canvas_kind = finite
preset = page
page_size = a4
orientation = portrait
width = 794
height = 1123
background_style = plain
```

## 2. Data Model

Migration:

```text
server/src/db/migrations/023_v2_learning_canvas.ts
```

Schema mirror:

```text
server/src/db/schema.sql
```

Tables:

- `learning_canvases`
  - course-level canvas document;
  - stores title, status, finite/infinite kind, preset, page size, orientation, dimensions, background style, metadata.
- `canvas_nodes`
  - layout node records referencing existing objects;
  - supported node types: `note_block`, `source_scope`, `source_anchor`, `source_board_node`, `source_material`, `material_segment`, `evidence_set`, `proposal`;
  - stores x/y/width/height/z-index and summary/title for display.
- `canvas_edges`
  - future relationship/visual edge foundation;
  - v2.4.0 stores data only and does not expose a full edge UI.
- `canvas_frames`
  - future grouping/page-area foundation;
  - v2.4.0 stores data only and does not expose full frame UI.
- `canvas_viewport_states`
  - per-user viewport/session state;
  - uses `UNIQUE(user_id, canvas_id)`;
  - does not mutate `learning_canvases`.

Compatibility:

- Existing notes, NoteBlocks, source snapshots, source anchors, source scopes, source boards, evidence, and proposals remain unchanged.
- Creating or seeding a canvas does not mutate target objects.
- Archiving canvas/node rows is reversible status change only.

## 3. API Contracts

Routes mounted:

```text
GET /api/canvases?course_id=...&status=...
POST /api/canvases
GET /api/canvases/:id
PUT /api/canvases/:id
POST /api/canvases/:id/archive
POST /api/canvases/:id/restore
POST /api/canvases/:id/nodes
POST /api/canvases/:id/seed-from-source-board
PUT /api/canvases/:id/viewport

GET /api/canvas-nodes/:id/jump-target
PUT /api/canvas-nodes/:id
POST /api/canvas-nodes/:id/archive
POST /api/canvas-nodes/:id/restore
```

`POST /api/canvases` minimum payload:

```json
{
  "course_id": "course-id",
  "title": "Canvas Document 1"
}
```

`POST /api/canvases/:id/seed-from-source-board` payload:

```json
{
  "source_board_id": "source-board-id"
}
```

Rules:

- user/course scoping is enforced for canvas, source board, and source-backed targets;
- archived canvases cannot receive nodes;
- archived source boards cannot seed canvases;
- seeding is idempotent by active `source_board_node` target;
- node jump target delegates to existing SourceScope, SourceAnchor, or SourceBoardNode jump behavior.

## 4. Frontend Surface

Course Detail adds a minimal `Canvas Document` panel inside the existing source/material workspace.

Available in v2.4.0:

- list active canvases;
- create default A4 canvas;
- select a canvas;
- seed canvas nodes from the active Source Board;
- preview nodes on an A4-like canvas surface;
- open/jump source-backed nodes;
- archive canvas nodes.

Explicitly deferred:

- real pan/zoom;
- drag/move/resize interactions;
- canvas SDK;
- template-aware manual block insertion;
- AI canvas layout proposal;
- edge editing;
- final visual polish.

## 6. External Tool Gate

No external canvas tool is adopted in v2.4.0.

Current decision:

- v2.4.0 keeps the domain model independent.
- v2.4.1 may evaluate `tldraw` as the likely interactive canvas SDK candidate.
- `Excalidraw` remains a lightweight prototype/reference candidate.

Before adoption, the active spec must record license/runtime constraints, Windows/local behavior, adapter strategy, rollback path, and how Coincides objects remain independent from tool-native stores.
