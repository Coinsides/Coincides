## 1. 施工结论

V2.BN.11.1 已完成其单一职责：让 Petal / Fragment 与旧 Courses Learning Canvas Relation 世界停止继续生产或复活数据，同时保留现役 ContentGroup 成员组织、Note Canvas、CanvasObject、Source Floor 与 `visual_connector`。

活动模型现在是：

```text
ContentGroup = identity + members + placements/view state
Petal / Fragment = frozen legacy, schema still present, no active read/write/prune/seed
```

11.2 没有开工。本次没有创建 migration 047，没有建立 Item / Relation 表，也没有重建 `content_group_members`。

## 2. 数据库安全硬结论

本次 diff：

- 没有 migration 文件变更；
- 没有 `schema.sql` 变更；
- 没有 `DROP TABLE`、表重建、启动清场或主动清空；
- migration 034 与三张支持表原样保留：
  - `content_group_fragments`
  - `content_group_petals`
  - `content_group_petal_fragments`
- 真正 DROP 仍只属于 V2.BN.11.2 的 `047_v2_item_relation_floor`；047 还必须在同一迁移边界中建立 Item / Relation 地板并重建 `content_group_members`。

旧 schema 自身的 FK cascade 仍可能在删除被引用成员时产生被动级联。本版本没有新增显式 Petal 清理命令，也不把被动级联冒充成 047 清场。

## 3. RED-first 证据

实现前先建立两类失败面：

1. `v2Bn11LegacyShutdownContractCheck.mjs` 在旧代码下发现 active Petal / Fragment symbol、旧 Learning Canvas UI/route 与 dead relation projection，按预期失败。
2. 新增 server freeze roundtrip 后，旧实现仍会 hydrate 并重写 Petal 数据，测试按预期失败。

随后才进行 client 停产、server 停读停写与旧入口下架。最终专项合同已进入 client/root package scripts，不是孤立脚本。

## 4. 实际改动

### Client

- 从 active `ContentGroupV1` 移除 Fragment / Petal 类型与字段；
- 删除 ContentGroup service 的 Petal create / normalize / assign / move / rename / remove / prune 与相关 graph/stability 分支；
- Single ContentGroup Editor 改为成员直管，保留 identity、Purpose role、summary、成员拖入/移除、accept/reject/archive 与返回来源；
- Group Gallery / index / reuse / surface-role model 不再显示或复制 Petal；
- 删除无消费者的 `contentGroupRelationProjectionService.ts`；
- 删除旧 `LearningCanvasSurface` 与两条旧详情 URL；CourseDetail 不再 fetch/create/select/render Learning Canvas；
- 删除 CourseDetail 中 `canvas_layout / composition_template` proposal 的旧 UI 类型与应用分支。

### Server

- ContentGroup list/get 不再查询或 hydrate 三张 Petal 表，也不再从 legacy JSON 返回 `fragments / petals`；
- ContentGroup upsert 不再接收、replace 或清空 Petal / Fragment；既有 JSON 列保持原值；
- member delete 移除显式 Petal prune；
- active ContentGroup request schema 不再列出 `fragments / petals`；
- unmount `/api/canvases`、`/api/canvas-nodes`、`/api/canvas-edges`、`/api/relation-layers`、`/api/object-relations`；
- 移除 `/api/proposals/canvas-layout` 与 `/api/proposals/composition-template` 创建 writer；既有这两类 pending proposal 若尝试 apply，明确返回 `410 Gone`，仍可 discard；
- migration/schema 与现役 CanvasObject / `visual_connector` route 保持不动。

### 有意保留

- migration 023/024/034、legacy 表定义与历史测试证据保留到 047；
- 未挂载的旧 route module 与仍被历史测试、composition/source 代码引用的底层 legacy helper 暂不做物理扫除；它们已不在生产 route 写路径上；
- `visual_connector` 属于现役 Better Notebook CanvasObject extension，不等于旧 `canvas_edges`，完整保留。
