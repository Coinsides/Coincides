# v2.5.4 Plan - Template Proposal + Migration Proposal

## Goal

v2.5.4 adds the first proposal-first migration loop for active `TemplateDefinition` changes.

When a template is already used by NoteBlocks, structural edits must not be saved directly. They must become a `TemplateMigrationProposal` with dry-run impact, diff, warnings, blockers, apply mode, and recovery records.

## Scope

v2.5.4 includes:

- `template_migration` proposal creation;
- migration dry-run impact reports;
- alias mapping apply;
- soft migration apply;
- conservative hard cascade apply;
- per-block migration records;
- Template Studio migration preview/apply/discard entry;
- AI operating manual updates;
- continuity update for deferred `DomainRefinementProposal`;
- graph-native migration evidence.

## Out Of Scope

v2.5.4 does not include:

- full domain migration;
- `DomainRefinementProposal`;
- package import/export;
- complete Package Studio;
- rich editor adapter;
- real AI provider calls;
- graph database migration;
- destructive content rewrites.

## Acceptance Criteria

v2.5.4 is complete when:

- creating a migration proposal does not mutate templates or NoteBlocks;
- alias mapping creates compatibility mapping and migration records only;
- soft migration updates NoteBlock template metadata while preserving original creation metadata and history;
- hard cascade is blocked for destructive or ambiguous field changes;
- migration apply writes operation batch, migration record, and item rows;
- discard changes only proposal status;
- Template Studio can create, preview, apply, and discard migration proposals;
- `DomainRefinementProposal` deferral is recorded in v2.x continuity;
- review records graph-native migration evidence.
