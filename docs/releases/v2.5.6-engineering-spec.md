# v2.5.6 Engineering Spec - DomainRefinementProposal Seed

## Contract

`DomainRefinementProposal` governs domain taxonomy changes for v2.5 runtime objects. It is proposal-first and must never silently rewrite NoteBlock content, source truth, canvas objects, or confirmed relations.

## Schema

Migration: `server/src/db/migrations/030_v2_domain_refinement_proposals.ts`

Tables:

- `domain_refinement_mappings`: alias/successor mapping evidence between old and new domain identities.
- `domain_refinement_records`: one applied refinement run, linked to a proposal and operation batch.
- `domain_refinement_record_items`: per-object before/after provenance.
- `domain_object_classifications`: explicit domain assignment records for `note_block`, `template_definition`, and `composition_template`.

## Proposal Contract

Route:

```text
POST /api/proposals/domain-refinement
```

Payload fields:

- `source_domain_id`
- `target_domain_id` or `target_domain_patch`, except `deprecate`
- `refinement_action`: `rename | promote | split | merge | fork | deprecate | reclassify`
- `migration_mode`: `alias_mapping | soft_migration | hard_cascade`
- optional course, membership changes, object reclassifications, and reason.

Proposal data includes:

- `proposal_kind: domain_refinement`
- source and target snapshots;
- domain diff and membership diff;
- package impact;
- affected counts;
- samples;
- warnings and blockers;
- recovery plan;
- `apply_behavior: domain_refinement_records_and_classification_updates`.

## Apply Behavior

`alias_mapping`:

- creates `domain_refinement_mappings`;
- creates record and item evidence;
- mutates no domains, packages, memberships, templates, compositions, notes, sources, or canvas objects.

`soft_migration`:

- creates a target domain from patch when needed;
- copies existing source memberships to the target domain;
- applies explicit membership additions/updates;
- writes `domain_object_classifications`;
- updates NoteBlock domain metadata only for explicit NoteBlock reclassifications;
- preserves created-with fields and classification history.

`hard_cascade`:

- allowed only for explicit, mechanically safe changes;
- may update package manifest domain contents and current classifications;
- blocks ambiguous `split`, `merge`, and `reclassify` when no explicit object or membership mapping is provided.

All apply paths create one `operation_batches` row. Blocked proposals fail before partial writes.

## UI Contract

Template Studio includes a compact Domain Refinement panel:

- choose source domain;
- choose action and migration mode;
- choose existing target or preview target patch;
- optionally include selected template as a classification sample;
- create, preview, apply, or discard proposal;
- show recent refinement records for the selected domain.

No separate Domain Studio is introduced.

## Graph-Native Evidence

- `DomainBlockSet` remains a graph node candidate.
- `domain_refinement_mappings` are future compatibility/successor edges.
- `domain_object_classifications` are future classification edges.
- `domain_refinement_records` and items are operation/provenance candidates, not knowledge truth by default.
- Hard-cascade behavior should be studied before v3.x Neo4j planning.
