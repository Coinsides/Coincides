# v2.1.1 Engineering Spec - Learning Block Template Engine Seed

**Created**: 2026-05-21
**Updated**: 2026-05-21
**Status**: Implemented / pending Henry release-hold decision

---

## 1. Implementation Contract

v2.1.1 introduces template-aware NoteBlocks without changing the database schema.

The contract is metadata-first:

```json
{
  "system_type": "text",
  "learning_role": "definition",
  "template_id": "definition.basic",
  "taxonomy_version": "v2.1.1"
}
```

These fields live in `note_blocks.metadata` and must preserve any existing unknown metadata keys.

---

## 2. Registry

Add a static template registry with:

- static template definitions;
- legacy block type mapping;
- metadata normalization;
- template label lookup;
- legacy-compatible `block_type` production.

Implementation note:

- client runtime uses the shared registry exported from `shared/types`;
- server runtime uses a matching local registry module to avoid depending on unbuilt shared package output during production build;
- the definitions must stay aligned until Coincides has a formal shared runtime package.

System types:

```text
text, latex, code, source_quote, task, media, table
```

Learning roles:

```text
note, concept, definition, theorem, proof, formula, example, exercise, answer, warning, source
```

Required seed templates:

```text
text.paragraph, text.heading, concept.basic, definition.basic, theorem.basic,
proof.basic, formula.math, example.general, exercise.general, answer.general,
source.quote, warning.callout, code.snippet
```

---

## 3. Server Behavior

Manual block creation and update:

- accept optional template metadata;
- normalize missing or invalid template metadata;
- infer metadata from legacy `block_type` when absent;
- never erase unrelated metadata keys.

Organized note proposal creation:

- deterministic fallback emits template-aware blocks;
- AI prompt requests template-aware JSON;
- valid AI template metadata is preserved;
- unknown AI template or role falls back safely and adds warning.

Organized note apply:

- writes block metadata to `note_blocks.metadata`;
- keeps source references unchanged;
- keeps proposal-first review/apply unchanged.

---

## 4. Client Behavior

Note editor:

- replace hardcoded block type options with registry-backed template options;
- show readable labels;
- keep textarea-first editing and current reorder controls;
- infer labels for old blocks without metadata.

Course proposal preview:

- show template or role label instead of only raw `block_type`;
- keep warnings visible.

---

## 5. Verification

Required:

- `server npm run test:v2`
- `server npm run build`
- `client npm run build`
- `git diff --check`
- secret scan over changed files

No browser-heavy visual acceptance is required for v2.1.1 unless the basic add/apply flow breaks.
