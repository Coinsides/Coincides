# V2.BN.5 Engineering Spec - Block Visual Language And Control Layer

## Status

Draft for Henry review before code implementation.

This spec converts the V2.BN.5 plan and `docs/contracts/Block-Contract.md` into an implementation contract. Do not start product code until Henry confirms this direction.

## Contract

V2.BN.5 makes individual blocks feel like notebook objects instead of engineering cards.

The core truth split remains:

```text
NoteBlock content truth
  stays in note_blocks and structured field values.

Template truth
  stays in TemplateDefinition / runtime template metadata.

BlockBox layout truth
  stays in placement / display override data.

Visual state
  stays in the editor surface and does not become content truth.
```

V2.BN.5 does not rewrite the template runtime. It uses the existing runtime and adds a first-version product contract for default blocks, field values, fixed field layouts, and category grouping.

## Default Block Set

Daily insert/slash entry should prefer:

```text
Basic:
  Text / Paragraph
  Heading

Structured:
  Definition
  Formula

Technical:
  Code

Source:
  Source Quote

Workspace:
  Sticky / Scratch Note
```

Deferred or template-only:

```text
Theorem
Proof
Example
Exercise
Answer
Table
Image / Diagram
Concept
Callout
```

Deferred blocks may remain readable through compatibility/runtime paths. They should not dominate the first writing menu.

## Field Values

The first-version content contract is:

```text
TemplateDefinition.field_schema
  defines fields.

NoteBlock.content_json.field_values
  stores values for this concrete block.

NoteBlock.plain_text
  is derived from field values and fallback body.

NoteBlock.metadata
  stores compatibility, template, migration, and UI hints only.
```

Definition:

```text
required:
  concept_name
  description
```

Formula:

```text
required:
  latex_input

optional:
  formula_name
  explanation

future:
  variables
```

Rules:

- `latex_input` is canonical content truth for Formula.
- Rendered math is display output.
- Invalid LaTeX must preserve raw input and show a warning.
- Missing field values render as empty/fallback states, not invented text.
- Paragraph -> structured block conversion uses deterministic guess + user confirm.
- AI must not be required for the first conversion path.

## Field Layout

V2.BN.5 only needs fixed visual seeds:

- Definition displays `concept_name` and `description` in a stable readable layout.
- Formula displays rendered math in reading mode and raw LaTeX + preview in editing mode.
- Whole block resize should reflow field display.
- Debug/inspector can show field keys.
- Reading mode should not expose field keys or template machinery.

Do not implement mature field-level drag/resize yet.

Long-term target, not required in this version:

```text
template_default_layout
  default render arrangement from the template.

block_layout_override
  per-block visual override.
```

## Category Membership

V2.BN.5 category membership is a discovery rule only.

Allowed category entrances:

```text
Default
Math
User Defined
```

Rules:

- Category affects menu grouping and Template Studio organization.
- Category does not change template identity.
- Category does not replace concept, domain, source, relation, or primitive family.
- A template variant may appear in more than one category.
- V2.BN.5 may use front-end grouping or existing template metadata as a temporary display layer.
- V2.BN.6 decides whether category membership needs a formal data contract.
- V2.BN.7 productizes category management in Template Studio.

## UI State Contract

Reading:

- content first;
- no engineering labels;
- no permanent heavy borders.

Hover:

- subtle affordance only.

Selected:

- show block border, drag handle, resize affordance, delete/save/type controls where relevant.

Editing:

- show text input, formula raw input, or field editor as appropriate.

Layout:

- prioritize block movement and resizing.

Inspector / Debug:

- show template, field keys, ids, compatibility, source/relation/debug state.

## Insert And Slash Behavior

The primary writing path is natural page writing and slash command.

Examples:

```text
empty block + /formula
  creates Formula.

non-empty paragraph + /formula
  offers deterministic conversion to Formula.

empty block + /definition
  creates Definition.

non-empty paragraph + /definition
  offers deterministic conversion to Definition.
```

Advanced insert remains available as a fallback for precise runtime/template selection, but it should not be the main everyday writing action.

## Compatibility

- Old NoteBlocks remain readable.
- Unknown runtime templates render safely.
- Old theorem/proof/example/exercise blocks can continue rendering through compatibility paths.
- `legacy_block_type` remains compatibility metadata.
- Category membership must not duplicate or fork template truth.

## Data Decision Before Code

Recommended direction for Henry confirmation:

```text
Use content_json.field_values as the first canonical structured field container.
Keep body as fallback readable content.
Generate plain_text from field_values + fallback body.
Keep formula_name and explanation optional in V2.BN.5.
Keep variables as future.
Represent category grouping through temporary metadata/front-end grouping unless a code audit proves existing runtime metadata is already sufficient.
```
