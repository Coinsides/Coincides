## 1. 当前判断

V2.BN.10.4 的工程实现已经完成，但浏览器体验门尚未由第三者签收，因此本回执不把小版本伪写成完整验收。

10.1–10.3 已经存在的 Source identity、事实附件、Project placement 和 atomic SourceProjection，现在拥有了真实用户入口：用户可以在全局 Source Library 或 Project Sources 上传文件、等待状态推进、打开提取阅读视图、查看或下载原件，并在另一个 Project 复用同一 Source。SourceProjection 的正文锁也已经从隐形服务端 guard 变成可见且先于请求生效的界面策略。

## 2. 已完成

### 2.1 单一 Source Experience 模型

- 新增共享 `SourceRecordDetail` DTO、派生状态和打开矩阵；Library 与 Project 不再各自解释 materialization。
- 明确处理 `received / parsing / publishing / materialized / failed / stored_only / projection_missing / original_missing`。
- 只有 active 状态存在时才进行约 3 秒轮询；页面隐藏时暂停，回到前台立即刷新，完成后自动停止。
- Source detail API 增加 `projection_available`，客户端不再仅凭一个历史 `projection_note_id` 假设投影仍可打开。
- 原件统一通过带 Bearer 鉴权的 Axios Blob 请求取得，再创建 object URL 预览或下载；没有把受保护 API URL 直接交给新标签页。

### 2.2 上传、去重与自动物化

- Library 上传以 Home placement 为镜头；Project 上传以当前 Project placement 为镜头。
- 浏览器 WebCrypto SHA-256 precheck 只负责节省网络；服务端 hash UNIQUE 仍是最终并发边界。
- precheck 命中既有 Source 时仍幂等建立当前 Project placement，并刷新当前 Project 列表。
- 新收或既有但仍处于 `received` 的 materializable Source 会调用既有 materialize route；Capability 0 不会被伪装成解析失败。
- 上传进度、typed error、可重试失败与去重结果进入统一 toast / detail 体验。

### 2.3 Source Library

- 原占位页已替换为真实资源列表。
- 支持按名称搜索、文件类型筛选、派生状态筛选和手动刷新。
- 列表显示 display name、格式、大小、上传时间、placement 数与派生状态。
- 详情展示 Origin receipt、事实文件、parser/version/attempt、typed error 与全部 Project placements。
- 行项目和详情提供状态感知主动作、查看原件、下载原件和条件 Retry。
- 删除入口保持禁用，明确没有在 10.4 伪造 10.5 才能闭合的硬删除生命周期。

### 2.4 Project Sources 与 legacy 隔离

- Project 详情新增复用同一 Source 数据层的 Sources 区和主上传入口。
- Project 列表卡片的 Sources 命令改为导航到该区域，不再打开 legacy DocumentManager。
- legacy Documents 只在已有数据时显示为只读 archive；旧 Upload / Manage 不再是正常摄入入口。
- Origin 与 Placement 分开展示，Project 没有被写成 Source owner。

### 2.5 SourceProjection 显式锁定

- Chrome 在展开和折叠状态都显示 `Source locked`；标题 input 直接只读。
- Layout、PageStack/PageFrame 创建与修改、document typography 修改、Block 保存/移动/缩放/删除、空白处建块和 CanvasObject 编辑入口在界面层禁用或隐藏。
- paragraph / formula / code、shape text 与 table cell 均进入只读呈现；图片、shape、table 和 visual connector 不再暴露可变 object inspector/context menu。
- Page/Canvas 切换、平移缩放、文本选择、Annotation、ContentGroup 和允许的解释组织路径继续保留。
- 服务端 10.3 guard 仍是最终安全边界；客户端 policy 负责不让 4xx 成为正常用户反馈。

### 2.6 可重复 Smoke 材料

新增 `npm run fixtures:source-smoke`，会在 `.codex-tmp/source-smoke-fixtures` 生成：

- PDF、DOCX、TXT、Markdown、PNG；
- Capability 0 的 CSV 与 XLSX；
- 用于失败状态的损坏 DOCX。

这些文件不进入 Git 真相，只服务于第三者浏览器验收。

## 5. 诚实边界

- Source hard delete、quarantine、receipt survival、Project 删除动态默认与 move-to-Home 属于 10.5。
- legacy Documents 数据没有迁移；只是撤掉正常上传入口并保留已有数据的只读显示。
- 小型文件可能在一次轮询前已经完成 materialization，因此浏览器不一定肉眼捕获每个瞬时 active badge；状态矩阵由 model contract 锁定，第三者应同时观察 Network 与较大文件行为。
- `projection_missing` 与 `original_missing` 是保护性降级状态，正常受约束数据不应主动制造它们；本版通过 DTO 与 model contract 验证，不要求第三者破坏开发数据库。
- Vite 仍有既有 dynamic import 与主 chunk 体积警告；本版没有扩大为 Source 专属 bundle 故障。
- 删除图标当前禁用，不应被理解为功能已完成。

## 6. 工程判断

10.4 没有在 React 页面里重新发明一套 Source 真相。客户端只是把 durable Source 状态编译成人类可操作的视图：同一 Source 在 Library 与不同 Project 中共享身份，原件和投影各有明确入口，失败不会抹掉事实文件，内容锁也不妨碍解释层继续生长。

第三者体验门通过后，V2.BN.10 才适合进入 10.5 的删除、收据和生命周期 closure；若体验门发现状态死点击或锁定漏口，应先回补 10.4，不把问题推给删除版本。
