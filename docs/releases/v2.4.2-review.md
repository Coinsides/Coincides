## Code Review

Implemented a focused canvas insertion path:

- `POST /api/canvases/:id/note-blocks` creates semantic content from the Canvas Document surface.
- `createCanvasNoteBlock` validates the template, finds or creates a canvas backing note, writes a template-aware `note_blocks` row, creates a placement, and projects it through a `canvas_nodes` row.
- `targetForNode` now validates `note_block` canvas nodes against the owning user/course instead of accepting arbitrary IDs.
- `LearningCanvasSurface` gained a compact Add block panel backed by the shared template registry.

No visual-only objects, CanvasEdge, ObjectRelation, or RelationLayer were introduced.

## Graph-native Migration Notes

v2.4.2 should preserve this distinction for v3.x planning:

- `NoteBlock` is semantic content and a future node candidate.
- `CanvasNode` is projection/layout over a target.
- `CanvasEdge` is visual connector, not automatically semantic truth.
- `ObjectRelation` is the future confirmed semantic edge.

v2.4.2 adds a concrete migration lesson: a user-created canvas block can be a future graph node only when it is semantic content (`NoteBlock`). Layout state remains projection (`CanvasNode`) and should not become knowledge truth.
