## 1. Goal

v2.2.3 makes reconciliation proposals understand likely learning roles.

The user should be able to review a material reconciliation candidate group and see whether the system thinks the group is probably a definition, theorem, proof, formula, example, exercise, answer, warning, concept, or generic note.

Core product rule:

```text
role-aware reconciliation = interpretation hint
role-aware reconciliation != canonical truth or automatic content merge
```

---

## 2. Version Boundary

v2.2.3 includes:

- deterministic learning-role inference for reconciliation candidate groups;
- template candidate hints using the v2.1.1 NoteBlock taxonomy registry;
- confidence and warnings for weak or ambiguous role guesses;
- safety-aware proposal enrichment from active exclusions and open conflicts;
- EvidenceSet metadata preservation for accepted role-aware groups;
- Course Detail proposal UI labels for roles, templates, confidence, and safety warnings;
- docs, tests, quality review, experience review, and changelog.

v2.2.3 excludes:

- canonical NoteBlocks;
- automatic truth resolution;
- stronger merge apply;
- source authority ranking;
- Source Snapshot Viewer;
- Source Board;
- Canvas;
- full user template editor;
- cross-course reconciliation;
- external tools or new dependencies.

---

## 3. API / Contract

`POST /api/proposals/material-reconciliation` keeps the existing route and enriches each candidate group with:

```json
{
  "learning_role_candidates": [
    {
      "learning_role": "definition",
      "confidence": 0.78,
      "reason": "heading/content uses definition language",
      "source_fragment_ids": ["..."]
    }
  ],
  "template_candidates": [
    {
      "template_id": "definition.basic",
      "label": "Definition",
      "confidence": 0.78,
      "reason": "best template for learning role definition"
    }
  ],
  "role_confidence": 0.78,
  "role_warnings": [],
  "blocked_by_safety": false,
  "safety_reasons": []
}
```

`POST /api/proposals/:id/apply` keeps existing v2.2.1/v2.2.2 behavior.

If an accepted group has role-aware metadata, the created `evidence_sets.metadata` must preserve:

```json
{
  "learning_role_candidates": [],
  "template_candidates": [],
  "role_confidence": 0.78,
  "role_warnings": [],
  "blocked_by_safety": false,
  "safety_reasons": []
}
```

---

## 4. Safety Rules

- Active exclusions mark matching candidate groups as `blocked_by_safety = true`.
- Open conflicts add safety warnings and should not recommend direct acceptance.
- Restored exclusions and resolved conflicts do not block the group.
- Safety warnings must be visible in the proposal JSON and Course Detail UI.
- Safety state must not delete, hide, rewrite, or mutate source/material/note records.

---

## 5. Test Matrix

Automated tests:

- role inference detects definition/theorem/proof/formula/example/exercise style material;
- weak material falls back to `note` with a warning;
- material reconciliation proposal includes role/template metadata;
- active exclusion marks a candidate group as safety-blocked;
- open conflict adds warning and avoids direct acceptance recommendation;
- accepted EvidenceSet preserves role hints in metadata;
- existing v2.2.0 proposal shell behavior still works;
- existing v2.2.1 EvidenceSet apply tests still pass;
- existing v2.2.2 exclusion/conflict/recovery tests still pass;
- material map and organized note proposal flows remain usable.
