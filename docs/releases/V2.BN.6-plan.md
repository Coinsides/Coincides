# V2.BN.6 Plan - Better Notebook Data Contract

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:executing-plans` to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 把 Better Notebook 前五个小版本沉淀出的产品经验正式整理成数据契约，确保后续 Template Studio、Source Library、Relation、GraphRAG、导入重建和导出能力不会破坏 Coincides Core 的 truth layer。

**Architecture:** V2.BN.6 是合同与审计版本，不是大规模功能版本。Coincides Core 继续拥有内容、布局、来源、关系、模板和操作历史的 canonical truth；editor/canvas 只负责显示、编辑、投射和临时交互状态；OCR/VLM、GraphRAG、AFFiNE/BlockSuite、import/export adapter 只能生成候选、proposal、projection 或 index，不能直接覆盖 truth。

**Tech Stack:** Markdown docs, existing TypeScript shared types, existing SQLite migrations, React editor/canvas substrate, server validators/routes, current v2.5 template/source/relation runtime, optional CodeGraph audit, docs-only verification unless contract audit reveals a required compatibility fix.

---

## Summary

V2.BN.6 的核心任务是“把地基说清楚”。

V2.BN.1 到 V2.BN.5 已经把产品从旧式 course/canvas 工程界面推向了更接近真实笔记软件的体验：Project 入口、note-first surface、自然写作、自由 block layout、page/canvas/export boundary、Definition / Formula structured block seed、preview overlay 和 block control layer 都已经有了第一版。

但这些体验背后还有很多概念必须锁定，否则 V2.BN.7 的 Editor Runtime Spike Gate、V2.BN.8 的 Template Studio Productization、V2.BN.9 的 Canvas Engine Foundation、V2.BN.10 的 Source Library、V2.BN.11+ 的 Relation 和 Local Graph 都会踩空：

```text
内容 truth 是什么？
布局 truth 是什么？
field schema / field value / field layout 分别是谁拥有？
source provenance 和 semantic relation 是否混在一起？
link 是导航还是证据？
template category 是发现入口还是 block 身份？
editor state 哪些可以丢，哪些必须持久化？
adapter 生成的东西什么时候只是 proposal，什么时候可以写入 truth？
```

本版本要用中文写清楚这些边界，并审计当前代码是否已经能承载这些边界。原则是：先合同，后扩建；先保住 truth，再谈高级体验。

## Version Boundary

V2.BN.6 是 Better Notebook 的数据契约版本。

本版本应该做：

- 审计当前实现已经有哪些 truth objects；
- 写清楚第一批 contract/spec 文档；
- 统一 V2.BN.1 到 V2.BN.5 中已经出现的临时概念；
- 标记哪些字段、状态、表、runtime object 是可以继续使用的；
- 标记哪些只是 editor cache、UI projection、adapter index 或 proposal；
- 把未来必须做的 migration/backfill/rebuild/recovery 记录成风险和后续任务；
- 如果发现当前已上线的 V2.BN.2 到 V2.BN.5 体验因为数据缺口会出错，允许做小型兼容修补。

本版本不应该做：

- 不重写 note editor；
- 不重做无限画布引擎；
- 不做完整 Template Studio Productization；
- 不做 Source Library UI；
- 不做 GraphRAG adapter；
- 不做 OCR/VLM import pipeline；
- 不做完整 relation runtime；
- 不做完整 export engine；
- 不做大规模 schema migration，除非审计证明某个现有体验无法可靠保存。

## Canvas Engine Branch Decision

本节只记录当前阶段性决策。Roadmap / PRD / Architecture / Data Model 暂不在本轮同步，等 Henry 审完 V2.BN.6 后再统一更新。

V2.BN.6 和 V2.BN.7 的共同价值，是把 V2.BN.1 到 V2.BN.5 中已经做出来的编辑体验、布局经验、truth layer 边界和 runtime 风险沉淀下来，为后续 Canvas Engine 阶段做准备。

当前 branch 的定位：

- 它是 Better Notebook 早期交互与数据契约的实验场；
- 它也是未来 Canvas Engine 失败时的后备道路；
- 它应该完整保留当前有限页面 / 大画布实验成果，作为后续重写时的 UX reference 和 fallback implementation；
- 它不应该被迫承担未来无限画布引擎的长期兼容债。

未来 Canvas Engine 阶段的默认策略：

- 新开独立 branch，而不是在当前 branch 上直接硬改到底；
- 新 branch 可以删除或重写 `NoteDetail.tsx` 中的实验性 layout runtime；
- 以当前分支沉淀出的产品目标、交互经验和 contract 为参考，重新实现 Canvas-native runtime；
- 不承诺为当前实验性 `better_notebook_layout` / placement runtime 写长期 converter；
- 因为产品尚未公开、当前没有真实用户数据，允许在 Canvas Engine branch 中做 clean layout reset / destructive dev-data reset；
- 如果 Canvas Engine 证明无法承载大量 blocks、relation 渲染、connector endpoint / animation 或整体交互复杂度，可以回退到当前 branch，并采用有限大画布作为替代路线。

这不是 V2.BN.6 的开发任务，只是本阶段必须记录的工程边界：当前实现是实验和后备，不是未来 Canvas Engine 的不可丢弃包袱。

## User Workflow

V2.BN.6 本身不是一个“用户看到新按钮”的版本，但它必须服务后续用户流程。

### Workflow 1: 用户自由写作，但系统知道什么是内容 truth

1. 用户在 note 里写 paragraph、definition、formula、code、scratch note。
2. 用户看到的是自然笔记，不是数据库表单。
3. 系统内部能稳定回答：
   - 这个 block 的 primitive family 是什么；
   - 它是否来自 template variant；
   - 它有哪些 field values；
   - 它的 layout 是 block-level placement 还是 template default；
   - 它是否会导出；
   - 它是否对 AI 可见。

期望结果：

- 用户自由写作不被 schema 感打断。
- 后续 AI、导出、relation、local graph 不需要靠猜测读 block。

### Workflow 2: 用户拖动、resize、进入 page/canvas，但布局 truth 不污染内容 truth

1. 用户在 page mode 调整 block 宽高和位置。
2. 用户切到 canvas mode，看到同一张 note canvas 上 Page frame 外的 workspace 区域。
3. 用户打开 export preview 或 overlay。
4. 系统能区分：
   - 内容是什么；
   - 出现在页面哪里；
   - 是否属于 formal page；
   - 是否在 formal Page frame 内；
   - 是否在 Page frame 外的 canvas workspace；
   - 是否进入导出；
   - 是否只是临时 UI selection。

期望结果：

- 拖动不会改写内容。
- preview overlay 不会成为 canonical state。
- Page frame 外的对象不会被错误夹回 formal page。

### Workflow 3: 用户引用 source，但 source chain 不等于 relation

1. 用户上传 textbook、PDF、网页、手写笔记、agent briefing 或自己以前整理的 note。
2. 用户把其中一个 source attach 到当前 block。
3. 用户之后复制某个 NoteBlock 到另一篇 note。
4. 系统能区分：
   - external source root；
   - internal note/block source；
   - direct source；
   - root source；
   - full chain；
   - source version；
   - missing/degraded/broken/recovered 状态。

期望结果：

- source 是 evidence chain，不是普通文件附件。
- SourceReference 不自动变成 ObjectRelation。
- 内部 note/report/block 可以成为后续笔记的 source artifact。

### Workflow 4: 用户点击 link，但 link 不自动变成证据或语义关系

1. 用户在 block 里插入一个内部链接。
2. 点击 link 可以跳到另一个 note、page、section 或 NoteBlock。
3. 如果这段内容确实引用了另一个对象，用户还要明确添加 SourceReference。
4. 如果两个对象之间有语义关系，用户还要明确添加 ObjectRelation。

期望结果：

```text
Link = navigation
SourceReference = provenance / evidence
ObjectRelation = semantic relation
```

三者可以共存，但不能互相冒充。

### Workflow 5: 后续 Template Studio 能安全建立用户自己的 block

1. 用户复制 system template 成 user-owned template variant。
2. 用户给它加入 Default、Math 或 User Defined category。
3. 用户编辑 field schema 的安全子集。
4. 用户编辑 field layout / render template 的安全子集。
5. slash / insert menu 能按 category 展示。

期望结果：

- V2.BN.8 可以基于 V2.BN.6 合同开发，而不是临时发明字段。
- category membership 是发现入口，不是 block identity。

## Data / State Impact

### NoteBlock content truth

V2.BN.6 必须确认：

- `NoteBlock` 是内容对象；
- `content_json.field_values` 是否正式成为 structured field value 的第一版容器；
- `plain_text` 是可重建派生文本，不是 canonical content；
- `metadata` 只存兼容、迁移、UI hints 或 template hints，不能成为唯一内容 truth；
- legacy `body` / `structured_fields` / `latex` path 如何继续被读取。

### BlockBox / CanvasNode / placement layout truth

V2.BN.6 必须确认：

- block 的 x/y/width/height 属于 layout truth；
- formal page、canvas workspace、scratch layer 的归属属于 placement/surface truth；
- export role 和 AI visibility 是 placement-level 还是 block-level，需要明确；
- selection、hover、drag ghost、preview popover 只是 editor state；
- 弹性避让、snap alignment、overlay badge 是 interaction/projection，不是内容 truth。

### Page / Canvas state

V2.BN.6 必须定义：

- `NoteCanvas` / `DocumentSurface`；
- `PageFrame` / formal page；
- canvas workspace；
- Page frame 外 workspace / scratch area；
- page boundary / export frame；
- page size / page preset；
- canvas-first note；
- page-first note；
- canvas preset conversion future；
- page mode / canvas mode；
- export preview；
- overlay visibility。

关键口径：

```text
Canvas 是 Note 的底层承载面。
Page 是 Canvas 上的 formal export frame。
Scratch / Workspace 不是第三种 surface，而是 Page frame 外的 canvas area。
Page size 指 Page frame 的尺寸，不是整张 canvas 的尺寸。
```

第一版不要求完整无限画布引擎，但 contract 必须能解释“formal Page frame 外的 block 为什么不应该在普通 page mode 里挤进页面”。

### Source attachment or provenance

V2.BN.6 必须定义：

- `SourceDocument`；
- `SourceVersion`；
- `SourceArtifact`；
- `SourceReference`；
- `SourceUsage`；
- `SourceChain`；
- `SourceTombstone / DeletedSourceRecord`；
- `SourceRegion` future boundary；
- `ImportMode`；
- `SourceKind / SourceIntent`；
- `Condensed Raw Source`。

V2.BN.6 不实现完整 Source Library UI，但要给 V2.BN.10 留出清楚边界。

### CanvasConnector / CanvasEdge

V2.BN.6 必须确认：

- visual connector / drawn arrow 是视觉对象；
- semantic `ObjectRelation` 是语义对象；
- 两者可以映射，但不能默认等同。

### ObjectRelation / RelationType / RelationGroup

V2.BN.6 不做完整 relation runtime，但必须把 boundary 写清楚：

- Link 不是 relation；
- SourceReference 不是 relation；
- ObjectRelation 是 semantic relation；
- source evidence 可以产生 `source_supports` 这类 relation proposal，但不是自动 confirmed relation；
- GraphRAG adapter 读取 relation 时只能作为 index/proposal，不拥有 relation truth。

### TemplateDefinition / CompositionTemplate / DomainBlockSet / PackageManifest

V2.BN.6 必须确认：

- `TemplateDefinition` 拥有 field schema；
- `TemplateVariant` 是用户实际选择或创建的具体模板；
- `PrimitiveBlockFamily` 是最粗 block 家族；
- `TemplateCategory / TemplateDomainMembership` 是发现入口；
- `CompositionTemplate`、`DomainBlockSet`、`PackageManifest` 是高级组织和复用能力，不应该污染日常 writing surface。

### Concept-lite

V2.BN.6 只定义 concept 边界：

- concept 是 search/AI/local graph 的辅助维度；
- concept 不是第一版用户 insert block；
- concept 不能替代 template category、source、relation 或 embedding。

### Export behavior

V2.BN.6 必须确认：

- export role 是明确状态；
- export preview 是 projection；
- exclude-from-export 不等于 delete；
- scratch block 默认不导出，但仍然是 NoteBlock；
- 当前版本不实现最终 PDF/export engine。

### AI visibility

V2.BN.6 必须确认：

- AI visibility 是 AI context 控制；
- hide-from-AI 不等于 hide-from-user；
- AI visibility overlay 是查看工具，不是 canonical content；
- 未来 AI 读取 structured fields 时，应优先读取 field values，而不是猜整段文本。

### Adapter / index state

V2.BN.6 必须确认：

- OCR/VLM 输出是 `SourceRegion` / `NoteBlockCandidate` / proposal；
- GraphRAG 输出是 index、query result、relation candidate 或 adapter projection；
- AFFiNE/BlockSuite 只能作为 editor bridge 或 import/export bridge；
- adapter 不能直接覆盖 Coincides Core truth。
