# v2.4.2 Engineering Spec - Template-aware Block Insertion on Canvas

**Created**: 2026-05-23
**Updated**: 2026-05-23
**Status**: Implemented

---

## 1. Scope

v2.4.2 adds a canvas-side path for creating semantic content blocks.

This spec intentionally does not add visual-only canvas objects or relation records.

---

## 2. Data Model

No new database migration is required.

Existing tables used:

- `learning_canvases`
- `canvas_nodes`
- `notes`
- `note_blocks`
- `note_block_placements`
- `operation_batches`

Backing note rule:

- one active backing note per `(user_id, course_id, canvas_id)`;
- backing note metadata includes:

```json
{
  "purpose": "canvas_backing_note",
  "canvas_id": "canvas-id",
  "canvas_title": "Canvas Document"
}
```

Backing notes are canonical containers for canvas-created NoteBlocks, but the UI should not treat them as a separate document mode.

---

## 3. API Contract

Add:

```text
POST /api/canvases/:id/note-blocks
```

Request:

```json
{
  "template_id": "definition.basic",
  "title": "Optional title",
  "plain_text": "Definition body",
  "content_json": { "body": "Definition body" },
  "note_id": "optional existing note id",
  "x": 120,
  "y": 160,
  "width": 300,
  "height": 180
}
```

Response:

```json
{
  "note": {},
  "block": {},
  "canvas_node": {}
}
```

Rules:

- `template_id` must exist in the v2.1.1 template registry.
- If `note_id` is present, it must belong to the same user/course as the canvas.
- If `note_id` is missing, find or create the canvas backing note.
- `block_type` is derived from `legacyBlockTypeForTemplate(template_id)`.
- metadata is produced through the template compatibility helper.
- unknown templates fail before any row is written.

---

## 4. Server Behavior

Create one service function for the route:

```text
createCanvasNoteBlock(db, userId, canvasId, input)
```

The function must:

- load the active canvas;
- validate or create the target note;
- create an operation batch with `source_type = manual`;
- create `note_blocks`;
- create `note_block_placements`;
- create a `canvas_nodes` row with `node_type = note_block`;
- return hydrated note/block/node records.

Every write happens inside one transaction.

---

## 5. Frontend Behavior

`LearningCanvasSurface` gains:

- an Add block toolbar action;
- a small insertion panel;
- a template selector using the shared registry;
- body text input;
- create/cancel controls.

The component computes an insert point near the current viewport center and sends layout fields to the parent.

`CourseDetail` sends the request to `/api/canvases/:id/note-blocks`, refreshes the active canvas, and shows a toast.

---

## 6. Graph-native Migration Notes

v2.4.2 records one important future graph boundary:

```text
NoteBlock
  -> candidate graph node / knowledge object

CanvasNode
  -> projection/layout over a target

CanvasShape
  -> future visual-only object

CanvasEdge
  -> future visual connector

ObjectRelation
  -> future semantic graph edge
```

This version should not blur those boundaries.
