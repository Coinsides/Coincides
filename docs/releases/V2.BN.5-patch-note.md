# V2.BN.5 Patch Note - Structured Block Seed

## Summary

This patch implements the first product-facing slice of the V2.BN.5 block contract.

The goal is not to finish the future Template Studio productization layer. The goal is to prove that Better Notebook can support:

- a narrowed default block set;
- structured Definition / Formula field values;
- fixed first-version structured block rendering;
- slash / insert categories: Default, Math, User Defined;
- compatibility with existing NoteBlock `content_json.body` data.

## Implemented

### Default Block Entry

The normal insert surface now treats the visible block set as a product decision instead of exposing every historical runtime template.

Visible first-version categories:

- `Default`
  - Text
  - Heading
  - Source Quote
  - Definition
  - Code
- `Math`
  - Formula
- `User Defined`
  - runtime user templates, when available

Theorem / Proof / Example / Exercise remain compatibility/runtime template concepts, but they are not first-version Better Notebook default writing choices.

### Definition Field Values

Definition now writes and reads structured field values:

```json
{
  "field_values": {
    "concept_name": "...",
    "description": "..."
  }
}
```

Legacy fallback remains supported through `structured_fields`, `body`, and `plain_text`.

### Formula Field Values

Formula now writes and reads structured field values:

```json
{
  "field_values": {
    "latex_input": "...",
    "formula_name": "",
    "explanation": ""
  }
}
```

`latex_input` is the first-version canonical formula payload. `body` remains as compatibility text.

### Fixed Field Layout Seed

V2.BN.5 only implements fixed visual seeds:

- Definition displays concept/name and description as separate fields.
- Formula displays rendered LaTeX in reading mode.
- Formula editing keeps the raw LaTeX input visible and editable.

Field layout editing remains deferred to later Better Notebook phases.

### Slash Create / Convert Path

Slash command grouping now matches the Better Notebook categories.

Existing create/convert behavior is preserved:

- empty draft + `/definition` creates Definition;
- non-empty paragraph + `/definition` converts conservatively: current text becomes `description`, `concept_name` stays empty;
- empty draft + `/formula` creates Formula;
- non-empty paragraph + `/formula` converts conservatively: current text becomes `latex_input`.

Passed:

## Known Boundaries

- No database migration.
- No TemplateDefinition runtime rewrite.
- No mature field layout editor.
- No heavy category manager.
- No AI-driven block classification in this version.

## Patch - Layout Interaction Stabilization

### Fixed

- Dragging a structured Definition block into nearby Formula/Text blocks now keeps the whole affected layout group in one draft snapshot.
- Blocks pushed by vertical collision avoidance are now persisted together instead of leaving only the dragged block saved.
- Structured block height now follows real rendered content through a resize observer, reducing text/frame desync after drag, resize, formula render, or field editing.
- Clicking a block now clears stale active/focus state from the previous block, so layout mode no longer appears to select multiple blocks accidentally.
- The selected block and its toolbar now render above adjacent blocks, so tightly stacked blocks do not hide move/save/export/AI/trash controls.
- Added first-version layout undo/redo for non-text-editing context:
  - `Ctrl+Z` reverts the latest move/resize layout operation.
  - `Ctrl+Y` or `Ctrl+Shift+Z` reapplies it.

### Notes

- Undo/redo is currently scoped to layout movement/resize history only. It intentionally does not intercept normal text editing undo while an input or textarea is focused.
- This patch does not implement true multi-select. It stabilizes single-block selection until the future batch layout mode is intentionally designed.

## Patch - Conservative Structured Conversion And Block Identity UI

### Fixed

- Removed the deterministic paragraph-to-structured conversion preview path.
- Removed the mechanical `noteBlockConversion.ts` conversion helper.
- Definition conversion no longer splits content by colon, dash, first sentence, or punctuation.
- Formula conversion no longer requires `$...$` delimiters before text can become `latex_input`.
- Definition field editing now keeps `concept_name` and `description` as explicit field values instead of repeatedly reparsing combined text.

### Changed

- `/definition` on an existing paragraph now maps current text to `description` and leaves `concept_name` empty.
- `/formula` on an existing paragraph now maps current text to `latex_input`.
- Formula preview treats bare LaTeX input as formula content for rendering.
- Minimum block width is reduced so users can intentionally create very narrow blocks.
- Block type identity is separated from the floating operation surface:
  - the operation surface is treated as the `Block Control Bar`;
  - block type is now shown as a separate outside-first `Block Type Badge`.
- Export preview now includes a first-version review overlay control for showing block type, AI visibility, and export status on the page.

### Notes

- This preserves the structured block foundation while avoiding brittle non-AI semantic guessing.
- Future AI-assisted conversion should return a proposal for user review rather than silently rewriting fields.

## Patch - Slash Menu Anchor, Review Overlay, And Elastic Avoidance Gate

### Fixed

- Slash command menus now anchor near the active input/block instead of appearing at the top of the page.
- Slash menu positioning now uses the current input element and clamps against the page surface so long notes do not detach the menu from the active block.
- Vertical elastic avoidance is now gated to `Page mode + Snap alignment off`.
- `Snap alignment on` now keeps the snap guide behavior without also triggering elastic block pushing.

### Changed

- `Move up` and `Move down` are removed from the visible Block Control Bar. Dragging remains the primary layout operation.
- Preview now exposes three review overlay switches:
  - block type overlay;
  - AI visibility overlay;
  - export status overlay.
- Block overlays are shown as one compact status row rather than scattered labels.

### Notes

- Height-change reflow remains separate from elastic dragging. It still helps prevent text/content growth from covering following blocks.
- The order-changing helper remains available internally for future keyboard or context-menu work, but it no longer occupies the normal block toolbar.

## Patch - Elastic Avoidance Stable Baseline

### Fixed

- Drag elastic avoidance now computes each pointer frame from the drag-start layout snapshot instead of the previous pushed draft.
- Blocks below the dragged block no longer accumulate distance frame by frame while being pushed downward.
- Releasing a dragged block after elastic avoidance no longer saves an inflated gap caused by cumulative pushed layouts.

### Notes

- This patch only changes drag avoidance. Resize/content-height reflow still uses the current measured layout because it is correcting real content height changes, not simulating elastic dragging.

---

## Patch - Elastic Avoidance Activation Boundary

### Fixed

- Page rendering no longer runs elastic collision cleanup by itself when snap alignment is off.
- Elastic avoidance now belongs to the active drag gesture only.
- Tiny drag movements no longer push the block below. Dragging must cross a small activation distance before avoidance starts.
- Content-height measurement reflow is paused while a block is actively being dragged, so structured Definition editing chrome cannot silently push lower blocks during a move.

### Notes

- Resize/content-height reflow remains active outside drag gestures.
- Snap alignment remains separate from elastic avoidance: snap on aligns; snap off may elastically avoid only during intentional drag movement.

## Patch - Drag Measurement Reflow Cooldown

### Fixed

- A tiny block drag no longer lets the post-drag content-height observer push lower blocks downward.
- Dragging a structured block now keeps the move gesture separate from Definition / Formula editor chrome measurement.
- The elastic avoidance threshold now has a clean path to work because height reflow is briefly suppressed after pointer release.
- Hovered block controls now rise above adjacent tight blocks, so a toolbar handle does not accidentally activate the block above it.
- The Block Control Bar now opens to the right side of the block instead of above it, avoiding hit-test collisions in tightly stacked vertical layouts.
- Selecting or focusing a structured block now briefly suppresses measured layout reflow, so read-mode to edit-mode chrome does not push neighboring blocks.
- Active Formula blocks are exempt from that selection cooldown because expanded LaTeX input is real editor content and must push following blocks down instead of overlapping them.

### Notes

- The cooldown only applies immediately after a move gesture.
- Normal content-height reflow remains available after the cooldown, so real text growth can still expand the layout.
- Tight vertical block stacks still need a fuller control-bar placement design later, but the current toolbar no longer sits in the previous block's content zone.
- Selection chrome is treated as interaction UI, not document content height.
- Formula input expansion is treated as editor content height, so it still participates in page reflow.

## Patch - Preview Overlay Control Cleanup

### Fixed

- Preview popover now sits above selected block chrome, so the panel no longer visually interleaves with the active Block Control Bar.

### Changed

- Preview overlay controls are now three compact icon toggles instead of three full-width text rows.
- Block type, AI visibility, and export status overlays use clear active/inactive icon states.
- Each overlay toggle has a small help icon with hover guidance, keeping the panel quiet while still explaining the control.

### Notes

- This keeps Preview focused on review controls instead of turning it into another dense settings panel.
