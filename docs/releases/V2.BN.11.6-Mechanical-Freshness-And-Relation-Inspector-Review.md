## 1. 本轮实际完成

### Server read model

- 导出 Item canonical `plain_text` hash 口径，Relation 不另造第二套内容摘要；
- Relation 读取时比较当前两端 Item hash 与双判断 Snapshot hash，派生 `fresh / from_changed / to_changed / both_changed`；
- 返回双 changed flag、`inspection_checkpoint_at` 与 latest assessment 摘要；
- latest assessment 只决定最近检查 checkpoint，不会把 changed Relation 宣称为 fresh；
- reaffirm 更新双 Snapshot 后，返回值立即恢复 `fresh`；
- 没有 schema migration，也没有 freshness / stale / sync 持久列。

### Item candidate search

- 现有 Item list query 增加受限 `q + limit`；
- 搜索 `plain_text / item_type / topic`，仍强制当前用户限域；
- Inspector 默认只搜索 active Item，候选空间不受当前 Project、Note、ContentGroup 或 Purpose 限制；
- 客户端不预载整个知识库，单次候选上限为 24。

### Relation Inspector

- 在现有 Item Inspector 内加入 active Relation 分区；
- 行模型解释 relation type、相对方向、对端 Item、note、机械 freshness 与 endpoint lifecycle；
- directed 类型明确选择“当前 Item 指出”或“当前 Item 接收”，undirected 不伪造方向；
- 支持全局搜索候选、选择 seed type、可选 Purpose 出处收据、可选 note，以及 create / reaffirm / revoke；
- retired endpoint 仍可读取和 revoke，但不能 reaffirm；
- revoked Relation、Snapshot 全文、diff 与 assessment 历史保持隐藏；
- freshness 只作低噪声局部信息，不发全局 toast、badge 或催办。

## 2. RED-first 与修正

- 新增四态 freshness、格式变化不漂移、reaffirm-to-fresh 与 assessment checkpoint 非权威测试；
- 新增用户隔离的全局 Item 搜索测试；
- 补齐 11.5 第三方 LOW：directed 同向重复创建直接断言 409，并携带既有 Relation ID；
- 新增 client Inspector 行模型契约：相对方向、相对 freshness、无关 Relation 过滤、retired action 规则与无 Snapshot 正文泄漏；
- 新增静态 absence contract，防止后续误加 sync 列、timer、sweep、queue、freshness route 或 RelationGraph。

## 4. 隔离浏览器 smoke

使用独立临时数据库与临时账号完成以下真实旅程，结束后服务与数据库已清理：

1. 打开 Note -> Groups Rail -> Item tools -> Inspect Item；
2. changed Item 的已有 Relation 显示 `This Item changed`；
3. 点击 reaffirm 后，同一行立即变为 `Current`；
4. 搜索不属于当前 ContentGroup 的全局 active Item，并创建新 Relation；
5. active 数量从 1 变为 2；
6. revoke 新 Relation 后，默认 active 列表恢复为 1。

本 smoke 只证明入口、读取与命令闭环，不签发集中磨合期的主观 UX PASS。

## 5. 明确没有完成

- 没有 Relation graph、Relation Mode、节点布局或视觉边；
- 没有 AI assessment 执行器、proposal 机器或自动建边；
- 没有 Snapshot diff、assessment history 或 revoked history browser；
- 没有后台 freshness pump、批量 stale queue 或持久同步状态；
- 没有对当前 Inspector 做最终视觉精修；
- 没有开始 V2.BN.11.7 生命周期与收口工作。

## 6. 当前风险与复验重点

- `plain_text` hash 是当前机械事实口径；第三方应确认所有格式型变化都不会产生假漂移；
- assessment checkpoint 必须永远低于 hash 事实，尤其要检查晚于 affirmed 的 `still_holds` 记录；
- 全局 Item 搜索扩大了候选范围，必须复验跨用户不可见且 Project/Purpose 不构成错误过滤；
- ContentGroupPanel 已较大，本轮沿现有 Item Inspector 所有权落地，没有为一段尚待磨合的 UI 提前抽象新工作台；若后续 Inspector 继续增长，应在明确稳定边界后再拆组件；
- 独立复验 PASS 前，11.6 仍不能视为关闭，11.7 不得发车。
