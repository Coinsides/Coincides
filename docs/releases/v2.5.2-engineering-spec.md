# v2.5.2 Engineering Spec - Composition / Section Template Seed

**Status**: implemented

## Summary

v2.5.2 adds the first persistent `CompositionTemplate` runtime. A composition is a section-level contract over multiple `TemplateDefinition` slots. It can be proposed, previewed, and applied into new NoteBlocks and Canvas projection records without changing existing user content.

## Schema

Migration:

```text
026_v2_composition_templates
```

Tables:

```text
composition_templates
composition_instances
composition_instance_slots
```

`composition_templates` fields:

- identity: `id`, `user_id`, `composition_key`, `version`, `origin`, `scope_type`, `scope_id`
- display: `label`, `description`, `composition_kind`
- contract JSON: `slot_schema`, `layout_behavior`, `source_behavior`, `relation_blueprint`, `proposal_behavior`
- AI guidance: `summary_for_agent`
- lifecycle: `status`, `is_system`, `metadata`, timestamps

`composition_instances` fields:

- `course_id`, optional `canvas_id`, optional `note_id`
- `composition_template_id`, applied `composition_key`, applied `composition_version`
- `source_proposal_id`, `operation_batch_id`
- metadata for graph-native migration evidence

`composition_instance_slots` fields:

- `composition_instance_id`
- `slot_key`, `slot_index`, `status`
- optional `note_block_id`, `canvas_node_id`, `canvas_frame_id`
- warnings and metadata

## Seed Contract

System seeds are user-scoped and idempotent:

- `formula_sheet.basic`
- `theorem_proof_example.basic`
- `source_quote_interpretation.basic`
- `evidence_comparison.basic`
- `briefing_section.basic`
- `side_note_cluster.basic`

Each slot declares:

- `slot_key`
- `label`
- allowed `template_keys`
- `default_template_key`
- `required`
- `repeatable`

Compatibility report validates all referenced runtime template keys against active `TemplateDefinition` records.

```json
  "composition_key": "optional-key",
  "source_scope_ids": [],
  "source_board_id": "optional-board-id",

```

Proposal data includes:

- `proposal_kind: "composition_template"`
- template key/version/identity
- `slot_plan`
- `layout_plan`
- `relation_blueprint_suggestions`
- warnings
- `apply_behavior: "create_new_content_and_projection_records_only"`

## Apply Behavior

Apply creates:

- one `operation_batches` row with `source_type = proposal`;
- one canvas backing note when needed;
- new `note_blocks`;
- new `note_block_placements`;
- optional `note_block_sources`;
- one `canvas_frames` row;
- new `canvas_nodes`;
- one `composition_instances` row;
- one `composition_instance_slots` row per filled or skipped slot.

Apply does not:

- update old NoteBlocks;
- mutate source/material/evidence records;
- mutate templates;
- create confirmed ObjectRelations;
- delete or hide existing data.

## Frontend Contract

Course Detail Canvas Document adds:

- composition template selector;
- `Use composition` action;
- proposal preview for slots and relation blueprint count;
- apply/discard through the existing proposal panel;
- preview overlay using the existing canvas layout preview layer.

This is intentionally not Composition Studio.

## Validation / Safety

- Unknown composition template fails cleanly.
- Unknown slot fails cleanly.
- Slot template references must be allowed by the composition slot schema.
- Required missing slots may be filled with deterministic placeholder content and warning.
- `partial_slot_keys` may intentionally skip slots and records the skip.
- Relation blueprints remain `suggested_only` and are not graph truth.

## Graph-Native Migration Evidence

- `CompositionTemplate` is a graph node candidate.
- `CompositionInstance` is a graph node candidate if applied usage becomes important to query.
- `CompositionTemplate -> TemplateDefinition` is a `USES_TEMPLATE` edge candidate.
- `CompositionInstance -> NoteBlock` slot usage may become an edge or edge-like property.
- `relation_blueprint` is not a graph edge; confirmed `ObjectRelation` is still the graph edge candidate.
