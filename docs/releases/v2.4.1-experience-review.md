# v2.4.1 Experience Review - Canvas Engine Gate + Basic Canvas Viewer / Editor

**Created**: 2026-05-23
**Updated**: 2026-05-23
**Current Experience Status**: `PASS_WITH_FOLLOWUP`

---

## UI / Visual Findings

v2.4.1 makes the Canvas Document panel feel less like a static debug card and more like the beginning of an actual workspace.

Current result:

- the canvas has a dedicated top-level course workspace instead of being nested inside the Course Material right rail;
- focus mode gives the canvas a larger near-full workspace when needed;
- nodes can be moved and resized;
- zoom and reset controls are visible;
- selected object scope is readable;
- source-backed node open/jump remains available.

This is still not the final AFFiNE-like shell. The main value of this patch is interaction direction and data boundary, not polish.

## Interaction Findings

Implemented:

- pan;
- zoom;
- select;
- move;
- resize;
- open target;
- archive node.

Local browser smoke confirmed the interaction model is enough to validate the Canvas-first document direction and selected-object foundation. The first surface can create a canvas, seed Source Board nodes, select source-backed nodes, zoom, move nodes, reload without losing the canvas, and return from a node to the source inspection area.

Deferred:

- smooth production-grade tldraw interactions;
- multi-select;
- connector drawing;
- keyboard shortcut system;
- command palette;
- block insertion tools.

## Workflow Findings

Canvas can now serve as the main surface for Source Board nodes and source-backed objects. This begins reducing the v2.3 stacked-panel feeling, but lower-level source panels still remain nearby for inspection.

Henry found that placing the canvas inside the right-side Course Material rail made it hard to discover and visually framed it as another source bubble. v2.4.1 was corrected so the canvas reads as the primary document surface, while source snapshots/scopes/boards remain supporting panels.

## Product Fit Findings

The current implementation respects the key product rule:

```text
Canvas is where objects are arranged.
Coincides tables are where source-grounded truth remains.
```

Selected object scope is promising because it gives future AI operations a stable, structured target instead of vague screen coordinates or raw text.

## Accessibility / Density Findings

The UI remains dense but more spatial. Future work should add:

- better node type labels;
- hidden-by-default debug metadata;
- inspector/drawer layout;
- clearer separation between main canvas workspace and supporting source panels;
- multi-select affordances;
- keyboard-accessible canvas commands.

## Deferred UX Debt

- tldraw-quality interaction polish;
- final workspace shell;
- relation layer visibility controls;
- custom background/shape/arrow style system;
- page-like export and project package UX;
- Source Snapshot / Source Board panel consolidation.

## Henry Acceptance / Priority Decisions

Henry v2.4.x batch acceptance remains pending.

Suggested Henry checks:

- is the basic canvas interaction direction correct;
- does selected object scope feel like the right foundation for AI commands;
- should tldraw remain the preferred next adapter spike;
