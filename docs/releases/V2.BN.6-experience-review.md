# V2.BN.6 Experience Review - Data Contract As User Protection

## 体验前提

V2.BN.6 不增加一个用户立刻能点到的新按钮。它的 UX 价值是间接的：防止后续产品工作变得混乱、噪声过多，或者根本解释不清。

## 它怎样保护用户体验

### 写作

用户可以继续自由写作。Structured block 存在，但转换必须保守、可预测。系统不应该因为冒号、美元符号、缩写或公式片段就静默重排用户的意思。

### 布局

移动和 resize block 不应该改写内容。Page mode 和 Canvas mode 之所以能被用户理解，是因为 PageFrame、workspace、export role、AI visibility 是分开的概念。

### Source Trust

Source 是证据链，不只是 file attachment。用户应该能理解某个 block 是无来源、外部来源、内部加工来源、broken、degraded，还是引用了旧 source version。

### Relation Clarity

用户不应该被所有“可能存在的关系”淹没。Confirmed relation、visible connector、AI-discovered candidate、GraphRAG query result 是不同东西。这个边界能避免产品变成 relation 噪声机器。

### Template Growth

Template category 是发现入口，不是 block 身份。未来用户可以自定义 block variant，而不需要把每一个学科都硬塞进默认菜单。

## 带到后续的体验风险

- 当前 editor runtime 仍需要 V2.BN.7 对照 AFFiNE / BlockSuite 和当前代码行为做系统 review。
- Canvas Engine 的性能必须在大规模 relation 或 media-heavy canvas 之前验证。
- Source Library 和 relation UX 仍然是后续阶段；V2.BN.6 只保护它们的概念边界。

## Experience Verdict

V2.BN.6 成功的标准是：未来 UX 可以从稳定的 truth boundaries 出发，而不是在实现过程中反复重新发明这些边界。
