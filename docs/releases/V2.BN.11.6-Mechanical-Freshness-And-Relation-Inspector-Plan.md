# V2.BN.11.6 Plan - Mechanical Freshness And Relation Inspector

> **状态 (Status)**: in progress
> **日期 (Updated)**: 2026-07-14
> **层 (Layer)**: 执行计划 / Release Plan
> **权威 (Authoritative)**: 否；范围服从 `V2.BN.11-plan.md`、当前状态层与 11.5 第三方 PASS

## 1. 本小版本解决什么

V2.BN.11.5 已经建立 Relation 真相与双 Snapshot 判断收据，但用户还不能直接消费这些真相。11.6 要完成从“数据库里有一条边”到“人在 Item Inspector 里能解释并维护这条判断”的最短纵切。

```text
current Item text hash + judgment Snapshot hash
  -> read-time mechanical freshness
  -> quiet Inspector row
  -> create / reaffirm / revoke
  -> no graph runtime / no stale queue / no sync column
```

本版不画节点、边或局部图，不执行 AI assessment，不展示 Snapshot 全文、diff、assessment 历史或 revoked Relation。Relation Inspector 是 Item 工作面的一个安静分区，不是新的图谱工作台。

## 2. 已获放行与随行项

11.5 第三方复验结论为 `PASS`，准予 11.6 发车。随行只有一项 LOW：为 directed Relation 的同向重复创建补一条直接 409 断言。

## 3. 必守不变量

1. 机械新鲜度只由当前端点 canonical `plain_text` hash 与 Relation 双 Snapshot hash 比较得出。
2. 四态固定为 `fresh / from_changed / to_changed / both_changed`；不得保存到 Relation、assessment 或其他同步表。
3. Item 的格式、type、topic、metadata 或 `body_json` 表达变化，只要 canonical `plain_text` 未变，就不得产生假漂移。
4. latest assessment 可以提供最近检查时间与排序 checkpoint，但不能覆盖 hash 事实，不能把 changed Relation 宣称为 fresh。
5. reaffirm 成功后双 Snapshot 更新，返回结果必须立即恢复 `fresh`；retired endpoint 继续可读，但不能 reaffirm。
6. Relation Inspector 默认只读取 active Relation；revoked 历史、Snapshot 全文、diff 与 assessment 历史隐藏。
7. 新建 Relation 的候选搜索来自当前用户的全局 active Item 空间，不被当前 Project、Note、ContentGroup 或 Purpose 困住。
8. Purpose 只作为可选 `origin_purpose_id` 出处收据；不限制 Relation 的适用范围。
9. directed Relation 的 UI 必须允许明确选择“当前 Item 指向对端”或“对端指向当前 Item”；undirected 类型不伪造方向。
10. freshness 是安静信息：无全局 toast、红点、轮询、后台 sweep、任务队列或批量刷新器。

## 4. RED-first 契约矩阵

### 4.1 Server freshness

- 新建 Relation 为 `fresh`；
- 只改 from、只改 to、两端都改，分别派生三种 changed 状态；
- `body_json` / 展示信息变化但 `plain_text` 不变仍为 `fresh`；
- assessment checkpoint 晚于 affirmed 时进入读取结果，但不能改变 freshness；
- reaffirm 后恢复 `fresh`；
- endpoint retired、origin Purpose missing 时 Relation 仍可读取并诚实降级；
- directed 同向重复创建返回 409 与既有 Relation ID。

### 4.2 Inspector client model

- normalizer 严格保留 freshness、双 changed flag、checkpoint 与 latest assessment；
- Inspector row 能解释 type、相对方向、对端、note、endpoint lifecycle 与可用 actions；
- unrelated Relation 不进入当前 Item 的 Inspector；
- retired endpoint 禁止 reaffirm，但 active Relation 仍可 revoke；
- row model 不暴露 Snapshot 全文、diff 或 assessment 历史。

### 4.3 Static absence

- `relations` 与 `relation_assessments` schema 不存在 freshness / stale / sync 列；
- Relation active code 不出现全局 timer、freshness route、sweep 或 queue；
- Item Inspector 使用局部读取和局部错误状态，不发全局 freshness 通知；
- 本版不引入 graph / edge layout / Relation Mode。

## 5. 实现纵切

### 5.1 Read model

- 在 `relations.ts` 内集中实现 hash 与四态派生；
- Relation 查询一次带回 latest assessment 摘要；
- 返回 `freshness / from_changed / to_changed / inspection_checkpoint_at / latest_assessment`；
- assessment 仅参与 checkpoint，freshness 始终由 hash 决定。

### 5.2 Candidate search

- 扩展现有 Item list query，支持受限的 `q + limit + active` 搜索；
- 搜索 plain text、type 与 topic，按用户限域；
- 客户端不预载整个知识库，也不把候选绑定到当前 Project。

### 5.3 Inspector surface

- 新建纯 `relationInspectorService`，把 Relation DTO 转成当前 Item 视角的行模型；
- 在现有 Item Inspector 增加 Relations 分区；
- 支持搜索对端、选择 seed type、选择 directed 相对方向、可选 Purpose 收据与 note；
- 支持局部 refresh、reaffirm、revoke；
- freshness 使用低噪声文案与样式，不抢占 Item 正文编辑。

## 7. 退出条件

- Item Inspector 能解释并维护 active Relation；
- 四态 freshness 在下一次读取立即派生，reaffirm 后恢复 fresh；
- 候选搜索尊重用户级知识空间与 active Item 边界；
- retired / missing receipt 状态诚实且不崩溃；
- 没有持久 sync 状态、全局 stale queue 或图谱 UI；
- Review、current-state 与第三方复验材料齐全。
