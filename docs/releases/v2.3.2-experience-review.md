# v2.3.2 Experience Review - Source Scope Selection

**Created**: 2026-05-22
**Updated**: 2026-05-22
**Current Experience Status**: `PASS_WITH_FOLLOWUP`

---

## UI / Visual Findings

Course Detail now exposes a small selected-source-scope area in the Source Snapshot workspace.

This is intentionally functional rather than visually final. It gives Henry enough later testing surface to understand selected pages/ranges without pretending this is the final Source Board or Canvas experience.

## Interaction Findings

Implemented interactions:

- select a single source snapshot page;
- mark a range start and range end;
- list active source scopes;
- jump back to a scope;
- archive a scope;
- create proposals using active scopes when available.

Restore is available through the API and tested. The current Course Detail UI focuses on archive/open for the active-scope list.

## Workflow Findings

Source scopes should feel like reversible selected source ranges, not final imports or destructive edits.

The UI copy explicitly positions scopes as source ranges, not deletion, final import, annotation, or Source Board.

## Product Fit Findings

Source Scope Selection prepares the path from source inspection to Source Board and proposal narrowing.

The feature now creates a bridge:

```text
Source Snapshot / SourceAnchor
  -> selected SourceScope
  -> proposal input
  -> later Source Board organization
```

## Accessibility / Density Findings

Light check only. The controls are simple buttons with readable labels, but the experience is still dense inside Course Detail. Heavy visual acceptance remains deferred.

## Deferred UX Debt

Heavy visual acceptance remains deferred to v2.4/v2.5 batch review after Source Board or Canvas maturity.

Future Source Board work should revisit:

- clearer selected-scope grouping;
- multi-select behavior;
- restore visibility from UI;
- range selection that feels less procedural than start/end buttons.
