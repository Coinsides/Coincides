# V2.BN.2 Patch Note - Natural Page Writing Seed

## Summary

V2.BN.2 replaces the primary Note Detail interaction with a natural page-writing surface.

The old Add Block form still exists as an advanced fallback, but the main workflow is now:

```text
open note -> click page -> type -> persist NoteBlock
```

## Implemented

- Blank page click creates a local draft writing area.
- Draft content persists as a runtime-template-aware NoteBlock on blur, `Ctrl+Enter`, or slash command confirmation.
- Existing blocks are edited in place.
- Block controls appear on hover/active state instead of dominating the reading view.
- Slash command seed supports create/convert paths.
- Definition/formula conversion uses deterministic preview plus confirmation.
- Formula preview remains available through the existing KaTeX renderer.

## Notable Fix

- New block creation no longer sends `title: null`; the backend requires omitted title or a string.

## V2.BN.2.1 Patch - Paragraph Flow Spacing

The first natural writing pass still made paragraph blocks feel like separated cards because each hidden toolbar reserved vertical space. This patch tightens the default paragraph flow:

- Single-line paragraph blocks now render as single-line text areas.
- Block spacing is reduced so adjacent paragraph blocks feel closer to normal line flow.
- Hover/active controls are floated above the block instead of occupying document space.
- The active block surface is lighter, keeping the page closer to AFFiNE/Notion-style writing instead of a database-card stack.
- The page boundary remains visible, but the block content now carries less nested-card visual weight.

## V2.BN.2.2 Patch - Note Chrome And Tool Surface

This patch moves low-frequency controls out of the page flow and fixes long wrapped block content.

- Note title and save action now live in a lightweight note top bar.
- The top bar includes seed chrome entries for favorite, page mode, info, more actions, and hide/show controls.
- The top bar can collapse into a compact recovery strip, matching the sidebar-collapse direction and preserving writing/canvas space.
- The old bottom `Advanced block form` is now a manual insert popover under the top bar more action.
- Draft and existing block text areas now auto-resize from `scrollHeight`, so long wrapped theorem/paragraph text is not clipped or forced into inner scrolling.
- The patch keeps Page/Open Canvas mode switching as future work, but reserves the chrome boundary needed for it.

## V2.BN.2.3 Patch - Note Info And Insert Surface

Henry's smoke pass found two early chrome problems:

- `View info` exposed a future inspector action before the inspector existed.
- Manual block insertion was hidden too deeply under `More note actions`, even though inserting blocks is part of ordinary writing.

This patch keeps scope small:

- `View info` now opens a lightweight note info popover with current mode, block count, source-reference count, and status.
- The manual insertion surface is renamed to `Advanced insert`, avoiding the engineering-flavored `fallback insert` wording.
- A visible page-side `Insert` entry now opens the same advanced insertion panel, so users are not forced to hunt through the top bar.
- `More note actions` now opens a distinct note-actions menu. It can route into `Advanced insert`, but it no longer opens the exact same surface as the side `Insert` button.
- Henry's first smoke pass failed this patch because the right-side insert panel squeezed controls horizontally and the `Insert` entry scrolled away. The panel now uses a vertical layout, and both the `Insert` button and panel are fixed/floating in the viewport.
- Henry's second smoke pass found that the top `More` icon and the side `Insert` button still opened the same panel. This is now split: `More` owns note-level actions, while `Insert` owns block creation.
- The note chrome action order now reads `Save -> Page -> Favorite -> Info -> More -> Hide tools`, matching the intended reading flow.

Deferred:

- Page splitting for long blocks remains part of the later Page / Canvas / Export boundary work. A long NoteBlock should remain one content object; page fragments are a display/export concern until the user explicitly splits the block.
