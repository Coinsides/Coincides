# v2.4.2 Experience Review - Template-aware Block Insertion on Canvas

**Created**: 2026-05-23
**Updated**: 2026-05-23
**Current Experience Status**: `PASS_WITH_FOLLOWUP`

---

## UI / Visual Findings

The Add block action now lives in the Canvas Document toolbar and opens a compact insertion panel over the canvas surface. This is much closer to the intended canvas-first interaction than adding canvas work into the older right-column source/material panels.

The panel is intentionally simple: template selector, optional title, body text, and Add block. It is not a full block editor or template editor.

Local browser smoke confirmed the panel is visible in the Canvas Document area. After the backend restart, creating a Definition block from canvas succeeded and the node persisted after reload.

Follow-up UX fix: `Add board nodes` no longer lets the user click into an `Added 0 board nodes` message when the current Source Board has already been seeded into the active canvas. It now shows `Board nodes added` in the disabled state.

## Interaction Findings

The intended interaction is:

```text
Canvas Document -> Add block -> choose template -> enter body -> create node
```

This should feel like adding a content object to the canvas, not editing a separate hidden document.

Implemented interaction:

```text
Canvas Document -> Add block -> choose template -> enter body -> Add block
```

The new block is inserted near the current viewport center, projected as a canvas node, and can then be moved/resized through the v2.4.1 canvas interaction model.

## Workflow Findings

Canvas-created NoteBlocks should still remain readable outside the canvas through their backing note.

The backing note behavior is deliberately invisible in the main user flow. It exists so canvas-created content remains a real NoteBlock and does not become canvas-only state.

## Product Fit Findings

v2.4.2 should strengthen the product boundary:

- semantic content becomes NoteBlock;
- projection becomes CanvasNode;
- visual helpers and relation edges remain future work.

## Accessibility / Density Findings

The first insertion UI can remain simple, but it should not make the canvas feel like another nested engineering panel.

The current UI is acceptable for the v2.4.2 foundation. It still needs later polish around:

- keyboard-first insertion;
- template search/grouping;
- richer per-template fields;
- better empty-canvas language.

## Deferred UX Debt

- polished block cards;
- visual-only shapes;
- relation edge drawing;
- multi-select insertion;
- command palette;
- full template editor.
