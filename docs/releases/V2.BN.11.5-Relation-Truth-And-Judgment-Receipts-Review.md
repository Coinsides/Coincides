## 1. 结论

V2.BN.11.5 已把 migration 047 的 Relation 表从“数据地板”推进为可用的领域真相：两个 Item 可以建立、读取、撤销、重建和原子重申 Relation，建立判断时的双端 Snapshot 作为不可串线的收据保存。

本回执只声明工程门与真实 HTTP smoke 已通过，不代替 Claude 的独立复验，也不声明 Henry 已完成主观体验验收。本版无用户可见 Relation UI，体验工作留在 11.6 与集中磨合期。

## 2. 领域语义

- Relation 唯一 durable endpoint 是 Item；visual connector、legacy object relation 与 ContentGroup identity 均未复用。
- 九个 seed type 的 directionality 由 server registry 决定；客户端请求不能注入方向性。
- directed 保留 from/to；undirected 按 Item ID 规范序。数据库 CHECK 与 service normalization 双重背书。
- create 拒绝 missing、retired、cross-user 与 self-loop endpoint；同一规范端点对 + type 同时只允许一条 active Relation。
- revoke 保留历史；同对同型可在撤销后建立一条新 ID 的 active Relation。
- active duplicate 返回既有 Relation ID，客户端无需在冲突后重新猜测目标。
- Relation 的双端 Snapshot 指向各自 Item 的 canonical `plain_text` 收据；client 也拒绝缺失或接错 Item 的收据。
- `origin_purpose_id` 只保存判断出处，不决定适用范围；Purpose 删除后 Relation 存活、origin 降级为 `NULL`。
- Purpose-scope list 读取 compiled Item scope，只有双端均在圈内的 Relation 才出现，且 derived 读取不反写任何真相表。

## 3. 实现结果

### Server

- 新增 `services/relations.ts`，集中拥有 seed registry、端点校验、方向规范化、Snapshot receipt、生命周期命令与 hydration。
- 新增 `/api/relations`：types、create、get、list、revoke、reaffirm；没有 DELETE Relation 路由。
- list 明确要求且只允许 `item_id | purpose_id` 二选一，并支持 `active | revoked | all`。
- reaffirm 单事务执行双端 Snapshot ensure、双指针更新与 `affirmed_at / updated_at` 更新。
- reaffirm 与 create 一样要求两端 Item 仍为 active；端点退役后保留既有 Relation，但不能重申为当前判断。
- `relation_assessments` 只提供按用户与 Relation 限域的历史读取，不新增模型执行器或 invalidation 状态。

### Client

- 新增 Relation DTO、seed type、directionality、endpoint 与 judgment receipt 类型。
- 新增防御性 normalizer：保留 directionality/status/origin/双 Snapshot，并拒绝缺收据、Snapshot ID 不一致、Snapshot 或 endpoint 接错 Item。
- 新增 repository：load types、create、get、list、revoke、reaffirm。
- 未建设 Item Inspector Relation UI、机械新鲜度、diff、assessment 执行器或图布局。

## 4. 原子性与安全边界

- reaffirm 在 `after_from_snapshot / after_to_snapshot / after_relation_update / before_commit` 四处注入失败，Relation 双 Snapshot、`affirmed_at` 与 `updated_at` 均保持旧值。
- 相同正文 reaffirm 复用既有 Item Snapshot，不制造重复收据。
- 所有 endpoint、origin Purpose、Relation 与 assessment 读取均按当前用户限域。
- migration 047 已有 self-loop、undirected order、partial active unique 与端点-Snapshot 复合 FK；11.5 没有新增迁移或弱化这些约束。

## 5. 随行修复

- 11.4 的 active Purpose Item edge 显式删除增加第二轮 full replace，证明不会被 hidden recovery 复活。
- stale pre-retirement payload 增加 COUNT 断言，证明不会平行制造重复 edge。
- ContentGroup move/delete 的两个 fire-and-forget 写回入口现在捕获失败并在 Rail 中显示错误，不再产生未处理 Promise rejection。
- Note 独立删除 receipt 测试与 11.5 无直接因果，继续留在对应生命周期版本，不借 Relation 纵切扩张。
