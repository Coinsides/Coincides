## 1. Goal

Create the first reviewable Canvas Layout Proposal flow.

The system can propose where existing or selected objects should appear on a canvas, preview that layout, and apply it only to projection records.

---

## 2. Version Boundary

v2.4.3 includes:

- `canvas_layout` proposal creation;
- deterministic page-first layout planning;
- layout preview with affected objects, frames, warnings, confidence, and apply behavior;
- layout-only apply that creates or updates `canvas_nodes`, creates `canvas_frames`, and may expand canvas projection height;
- Course Detail / Canvas Document UI entry for planning and applying layout.

v2.4.3 excludes:

- AI provider calls by default;
- NoteBlock content creation or rewriting;
- source/material/evidence mutation;
- CanvasEdge, ObjectRelation, RelationLayer, connector editing, or semantic relation inference;
- persistent ViewPreset tables;
- external canvas or layout dependencies.

---

## 3. Object Boundary

Stable rule:

```text
Canvas Layout Proposal = view/projection mutation proposal
NoteBlock = semantic content
CanvasNode = projected object layout
CanvasFrame = visual grouping layout
CanvasEdge = future visual connector
ObjectRelation = future semantic relation
```

Applying this proposal must never turn layout into knowledge truth.

---

## 4. Implementation Contract

Backend:

- add `POST /api/proposals/canvas-layout`;
- validate course/canvas/source board/source scope/note block ownership;
- generate deterministic layout records for existing and selected objects;
- store proposal data in the existing `proposals` table with `type = canvas_layout`;
- extend proposal apply for `canvas_layout`;
- keep discard behavior unchanged.

Frontend:

- add a `Plan layout` action in the Canvas Document workspace;
- create layout proposals from the active canvas and active Source Board or active Source Scopes;
- show canvas layout proposal previews in the existing proposal review panel;
- apply/discard proposals through the existing review workflow;
- refresh canvas after apply.

Data safety:

- create proposal: no mutation beyond inserting the pending proposal row;
- apply proposal: mutate only projection layout rows and operation batch records;
- discard proposal: no canvas/source/note mutation.

## 7. Assumptions

- Deterministic layout is the default.
- Real provider/API evaluation remains out of scope for v2.4.3.
- Existing `canvas_frames` can be used without a new migration.
- ViewPreset remains conceptual until a later version explicitly promotes it.
- Graph-native migration notes should record layout proposal as future view/preset/projection evidence, not graph truth.
