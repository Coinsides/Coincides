# V2.BN.3 Engineering Spec - Freeform NoteBlock Box And Layout Mode

## Contract

V2.BN.3 introduces the first formal-page layout layer for ordinary notes.

The user-facing contract is:

```text
select NoteBlock
  -> move / resize its visible box
  -> text reflows
  -> layout persists after reload
```

The engineering contract is:

```text
NoteBlock content truth
  stays in note_blocks

BlockBox layout truth
  stays in note_block_placements.display_overrides_json
```

This version deliberately reuses the existing `note_block_placements.display_overrides_json` field instead of adding a migration. That field already belongs to the placement/projection layer, so it is a better first home for V2.BN.3 layout than `note_blocks.metadata`.

## Primary Files

- `client/src/pages/Notes/NoteDetail.tsx`
  - reads placement overrides;
  - computes default layout for old blocks;
  - renders blocks as formal-page BlockBoxes;
  - handles layout mode, selection, move, resize, snap guide, and spatial insertion.

- `client/src/pages/Notes/NoteDetail.module.css`
  - page-local BlockBox positioning;
  - layout mode borders;
  - move grip;
  - resize handle;
  - snap guide lines.

- `server/src/routes/notes.ts`
  - accepts `display_overrides_json` during block creation;
  - exposes `PUT /api/notes/:id/block-placements/:placementId` for layout persistence.

- `server/src/validators/index.ts`
  - validates placement override payloads.

## Layout Payload

The first layout payload lives under:

```json
{
  "better_notebook_layout": {
    "x": 0,
    "y": 0,
    "width": 760,
    "height": 72,
    "surface": "formal_page",
    "version": "V2.BN.3"
  }
}
```

Rules:

- `x`, `y`, `width`, and `height` are formal-page local pixels.
- `surface` prevents accidental confusion with open canvas layout.
- `version` records this as a seed layout contract.
- Missing layout is allowed; old blocks receive deterministic default boxes.

## Behavior Rules

### Old Blocks

If a block has no `better_notebook_layout`, the client computes a default stacked layout from `order_index` and text height estimate.

This default is not written back until the user moves or resizes the block.

### Move

- Moving happens through the block grip.
- Dragging updates local layout draft state.
- Pointer release persists to the placement override endpoint.
- Moving does not change `order_index`.
- Moving does not imply semantic relation or source relation.

### Resize

- First version supports right-edge width resize.
- Width is clamped to the page content width.
- Text reflows inside the new width.
- Height grows to at least the estimated content height.
- Resize persists only on pointer release.

### Spatial Insertion

Clicking empty formal-page space creates a draft block at that page-local position.

When the draft is persisted, the initial placement override is sent in the create-block payload.

### Snap Guides

First version supports lightweight snapping to:

- page left edge;
- page right edge;
- nearby block left/right edges;
- nearby block top/bottom edges.

Snap guide is visual and local; it is not persisted as its own object.

## Data Boundaries

- Source references are not touched.
- ObjectRelation is not touched.
- CanvasEdge is not touched.
- TemplateDefinition behavior is reused through existing block creation/conversion helpers.
- GraphRAG adapter is not touched.
- Export behavior is not touched.
