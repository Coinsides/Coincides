## Summary

给 Better Notebook 立「目的（purpose / 圈）」这一层模型地基：**内容按目的组织，组织与内容分离**。新建 `purposes`（目的节点）+ `purpose_members`（(成员,目的) 边，**role/fitness/序 住边上**）；ContentGroup 纯化为 bundling 并补 `identity_type` 轴（是什么），`identity_role` 从节点冻结退役（**修掉"角色焊死在 CG 节点"的相对不焊违例** —— 06-28 §九C 旗标的那颗雷）；每篇笔记懒建一个默认目的。用户可见变化 ≈ 0（badge/分组从 "role" 换名 "type"、值原样），但模型从此支持：同一批内容多目的组织（镜片）、每目的独立的角色/顺序、以及后续 draft 装配 / 关系图 / 跨笔记复用全部挂此。**不依赖 Source** —— 这正是它排在 Source 之前的原因。

## User Workflow

- **入口/主动作**：日常无新入口 —— 用户照常建笔记、建 ContentGroup。打开笔记（或 GroupGallery）时系统懒建该笔记的默认目的并把现有 active CG 挂入（用户无感）。
- **可见状态**：Rail/Panel/Gallery 原来显示 "role" 的徽章与分组改显示 **type**，**值与分组结果原样不变**（'definition' 等旧值已语义归位到 type）；旧 `?mode=role` URL 映射到 type 视图不降级。
- **编辑**：Single ContentGroup Editor 中原 role 文本框变为 **type**（写节点）；新增一行「本笔记默认目的下的角色」（写边）。一次 Save = 两个独立乐观写（group PUT → purposes PUT），各自回滚+toast。
- **数据变化**：见 Data / State Impact。
- **undo/恢复期望**：删目的只删边、内容无损；CG 软删→复活后其边（role/序）原样回来；note trash→restore 后默认目的+边复活。
- **browser smoke 路径**：打开含 CG 的旧笔记 → badge 值不变 → Gallery 三视图切换 + 旧 role-URL → 编辑器改 type + 改边 role 各自保存 → 刷新后均持久。

## Data / State Impact

- **触及**：ContentGroup 身份真相（+type、role 冻结）；新增 purposes / purpose_members 两张真相表；**不触及** NoteBlock 内容真相、placement/layout、Page/Canvas 状态、Source、connector、TemplateDefinition、导出行为。AI 可读投影（readingInterpretation projection）shape 更新但 v1 仅契约消费。
- **迁移**：`044_v2_purposes`（建表 + safeAlter 加列 + backfill COPY `identity_type ← identity_role`，幂等、可恢复；**不改 schema.sql**；044 内不自开事务）。
- **红线保障**：identity_role 列**物理保留冻结**（停写停发）；backfill 是 COPY；过渡期服务端 coalesce（type ?? role）+ hydrate 双发，堵旧客户端清空窗。**CG 软删不清边**（边保留、读时过滤、复活即恢复）—— 防"可撤销删除变不可逆丢数据"。
- **旧数据继续工作**：所有既有 CG 的 role 值经 backfill 变为 type 值照常显示；legacy note-metadata 导入路径经三段回退（type ?? role ?? interpretation.role）不丢值。
- **什么被删/隐藏**：无删除；identity_role 仅停用（未来版本再物理 DROP）。
- **真相 vs 投影**：purposes/purpose_members/content_groups = canonical truth；roleForMember 读时派生 = 投影；gallery/rail label = UI cache。

## Acceptance Criteria

- 用户打开旧笔记：CG badge/分组值与升级前完全一致（type=旧 role 值）；旧 `?mode=role` URL 显示 type 分组、不降级 folder。
- 用户在编辑器改 type、改「默认目的下的角色」并保存：刷新后各自持久；一方失败另一方不受累（独立回滚+toast）。
- CG 软删后复活：其在默认目的下的 role/序原样恢复（**不静默消失**）。
- 删除一个目的：其成员 CG 与 member 内容零损伤。
- note trash → restore：默认目的与边完整复活。
- 任何路径不再写 identity_role；identity_type 不被旧 shape 的保存清空。
- 既有四套 suite（cutover / test:v2 / model-contract / boundary）+ 新增 RED-first 八条 + 新契约断言全绿；`verify:v2-bn8-runtime` 绿。
