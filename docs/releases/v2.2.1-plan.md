## 1. Goal

v2.2.1 turns v2.2.0 reconciliation candidate groups into the first persistent evidence layer.

The key product rule:

```text
conservative merge = accepted evidence relationship
conservative merge != content merge
```

Accepted groups create `EvidenceSet` and `EvidenceItem` records. They do not create canonical truth, rewrite notes, hide sources, or delete materials.

---

## 2. Version Boundary

v2.2.1 includes:

- additive evidence tables;
- group-level decisions for material reconciliation proposals;
- creating EvidenceSets from accepted groups;
- recording decision-only outcomes for kept-separate and deferred groups;
- operation batch audit for reconciliation apply;
- Course Detail group decision selector;
- tests and docs.

v2.2.1 excludes:

- canonical NoteBlock creation;
- source deletion or hiding;
- exclusion scope;
- conflict resolution workflow;
- split / unmerge / recovery;
- Source Snapshot Viewer;
- Source Board;
- Canvas;
- source authority ranking.

## 3. API / Contracts

Extend existing route:

```text
POST /api/proposals/:id/apply
```

For `type = material_reconciliation`, the body may include:

```json
{
  "group_decisions": [
    {
      "group_id": "candidate-group-id",
      "decision": "accepted_evidence_set"
    }
  ]
}
```

Allowed decisions:

```text
accepted_evidence_set
kept_separate
deferred
```

Rules:

- `accepted_evidence_set` creates one EvidenceSet and linked EvidenceItems.
- `kept_separate` creates only a decision row.
- `deferred` creates only a decision row.
- Unknown group ids fail the whole apply transaction.
- If no `group_decisions` are provided, apply remains review-shell-only for old v2.2.0 compatibility.
- Existing proposal status rules still prevent re-apply.
