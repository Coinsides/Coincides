## 1. Goal

Create the first usable edge/relation layer for the Canvas Document surface.

A user can draw a connector from one CanvasNode port to another, keep it as a visual edge, or explicitly upgrade it into a semantic `ObjectRelation` that future AI and graph-native planning can inspect.

---

## 2. Version Boundary

v2.4.4 includes:

- four-direction CanvasNode ports: `top`, `right`, `bottom`, `left`;
- interactive edge drawing on the canvas;
- `incomplete` edges with a loose endpoint;
- `visual_only` edges between two CanvasNodes;
- manual upgrade from visual edge to `ObjectRelation`;
- manual unbind from `ObjectRelation`;
- default `RelationLayer` seed and minimal show/hide behavior;
- docs, tests, review, changelog, and continuity updates.

v2.4.4 excludes:

- AI-generated relation proposals;
- custom edge style editor;
- custom shape/arrow/template editor;
- full RelationLayer management;
- graph database migration;
- external relation editor adoption;
- tldraw/React Flow integration;
- package export/import of edge recovery.

---

## 3. Object Boundary

Stable v2.4.4 rule:

```text
CanvasEdge
  -> projection / interaction connector

ObjectRelation
  -> semantic relation between domain objects

RelationLayer
  -> relation grouping, purpose, and visibility layer
```

An arrow drawn by the user is not automatically knowledge truth.

---

## 4. API / Contracts

New or extended API contracts:

```text
GET /api/canvases/:id/edges
POST /api/canvases/:id/edges
PUT /api/canvas-edges/:id
POST /api/canvas-edges/:id/archive
POST /api/canvas-edges/:id/restore
POST /api/canvas-edges/:id/bind-relation
POST /api/canvas-edges/:id/unbind-relation
GET /api/relation-layers?course_id=...&canvas_id=...
GET /api/object-relations?course_id=...&canvas_id=...
```

Creation rules:

- an edge with only a source port and loose endpoint becomes `incomplete`;
- an edge with source and target ports becomes `visual_only`;
- only a complete edge can bind to an `ObjectRelation`;
- failed relation binding must not create partial semantic records.

---

## 5. Data Model

Migration:

```text
server/src/db/migrations/024_v2_canvas_relations.ts
```

Tables:

- `canvas_edges`: projection connector with source/target ports, loose endpoint, state, style, and optional relation/layer pointers.
- `object_relations`: semantic relation between two domain objects.
- `relation_layers`: minimal layer records for grouping and visibility.

Initial relation types:

```text
uses_definition
uses_formula
example_of
answers
supports
contradicts
read_before
derives_to
source_supports
```

Default layers:

```text
visual
learning_logic
source_evidence
ai_suggested
ai_hidden
```

## 6. Test Matrix

Required automated checks:

- migration creates/updates `canvas_edges`, `object_relations`, and `relation_layers`;
- default RelationLayers are created idempotently;
- incomplete edge can be created and cannot bind relation;
- complete visual edge can be created without ObjectRelation;
- binding creates ObjectRelation and changes edge to `relation_backed`;
- binding failure leaves no partial ObjectRelation;
- unbind keeps visual edge and removes semantic binding;
- archive/restore edge only changes edge status;
- existing v2.4.1 canvas node layout, v2.4.2 Add block, and v2.4.3 layout proposal behavior remain usable.

## 8. Assumptions

- Canvas remains projection.
- Coincides-owned domain objects remain canonical truth.
- ObjectRelation is the v2.x edge candidate for future graph-native migration.
- CanvasEdge may degrade or break without deleting ObjectRelation truth.
- RelationLayer is a minimal visibility/purpose layer in v2.4.4, not a full user-customizable layer engine.
