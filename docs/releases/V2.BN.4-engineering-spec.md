# V2.BN.4 Engineering Spec - Page / Canvas / Export Boundary

## Contract

V2.BN.4 creates the first product boundary around the Better Notebook writing surface:

```text
Page mode
  -> formal document surface
  -> page-in content defaults to export included

Canvas mode
  -> wider scratch workspace around the formal page
  -> page-out content defaults to scratch / export excluded
```

The engineering contract remains:

```text
NoteBlock content truth
  stays in note_blocks

BlockBox layout and boundary policy truth
  stays in note_block_placements.display_overrides_json
```

This version deliberately does not add a migration. The existing placement override JSON is sufficient for the first seed because export intent and AI visibility are placement/projection policy, not NoteBlock body content.

## Primary Files

- `client/src/pages/Notes/NoteDetail.tsx`
  - adds Page / Canvas mode state;
  - renders the first formal page boundary in Canvas mode;
  - stores first-pass `export_role` and `ai_visibility` in `better_notebook_layout`;
  - derives default export and AI visibility from page-in / page-out position;
  - adds a compact export preview seed;
  - exposes selected-block toggles for export and AI visibility.

- `client/src/pages/Notes/NoteDetail.module.css`
  - adds wider canvas workspace styling;
  - adds formal page boundary styling;
  - adds compact export preview and policy badge styling.

## Layout Payload

The first V2.BN.4 placement policy payload lives under:

```json
{
  "better_notebook_layout": {
    "x": 0,
    "y": 0,
    "width": 760,
    "height": 72,
    "surface": "formal_page",
    "version": "V2.BN.4",
    "export_role": "included",
    "ai_visibility": "visible"
  }
}
```

Rules:

- `x`, `y`, `width`, and `height` remain BlockBox placement values.
- `surface` is derived from whether the box is inside the formal page or in the canvas workspace.
- `export_role` is optional. If missing, the client derives a default from page boundary.
- `ai_visibility` is optional. If missing, the client derives a default from page boundary.
- Missing V2.BN.4 policy remains compatible with V2.BN.3 layout.

## Boundary Rules

First version boundary classification:

```text
inside:
  block x + width <= formal page width

outside:
  block x >= formal page width

crossing:
  block overlaps the formal page right boundary
```

Derived defaults:

```text
inside / crossing:
  export_role = included
  ai_visibility = visible

outside:
  export_role = scratch
  ai_visibility = hidden
```

Users can explicitly override these defaults from selected block controls.

## Page / Canvas Mode

Page mode:

- keeps the ordinary formal document surface;
- keeps V2.BN.3 page writing behavior;
- remains the default entry mode.

Canvas mode:

- widens the BlockBox workspace;
- keeps the formal page boundary visible at the left side of the workspace;
- labels the outside area as scratch workspace;
- allows users to drag or create page-outside content.

Mode state is UI state in this seed. It does not rewrite NoteBlock content or existing placements.

## Export Preview Seed

The preview is intentionally compact:

- included count;
- excluded/scratch count;
- AI visible count;
- AI hidden count;
- warning for crossing blocks;
- warning for page-outside blocks;
- first few block rows with export/AI status.

It is not a PDF renderer and does not create export files.

## Data Boundaries

- Source chain / provenance is not implemented here.
- ObjectRelation is not touched.
- CanvasEdge is not touched.
- TemplateDefinition schema is not touched.
- GraphRAG adapter is not touched.
- Full PDF export is not touched.

Important distinction:

```text
export_role
  answers: will this object appear in exported/shared output?

ai_visibility
  answers: may assistant workflows read this object as context?
```

Those two policies must remain separate.
