> **状态 (Status)**: engineering complete
> **日期 (Updated)**: 2026-07-11
> **上游范围**: `docs/releases/V2.BN.10-plan.md` v3
> **实现设计**: `docs/agent-ops/analysis/reference-source-storage-design.md` v2

> **定位**: 薄施工单；锁定解析、原子发布与 SourceProjection 写边界，不预写 Source UI

## 目标

证明两个事实：

1. 解析失败只会改变 durable materialization run，不会伤害 10.2 已安全收存的原件；
2. 解析成功只会一次性发布完整 SourceProjection，任何 crash / retry 都不会留下半篇 Note 或第二份 current projection。

本版本闭合：

```text
received
  -> atomic claim -> parsing
  -> transient SourceArtifact
  -> publishing
  -> one DB transaction publishes Note / Block / placement / CanvasObject / receipt / operation batch
  -> materialized

failure
  -> typed failed state
  -> retryable failures reuse the same run identity
```

## 锁定不变量

1. `source_materializations` 仍是唯一 durable run truth；v1 每个 Source 只有一行，retry 只增加 `attempt_count`。
2. claim 必须是带旧状态条件的单条 `UPDATE`；并发请求只有一个胜者，输者不启动 parser。
3. parser 在发布事务外运行；`SourceArtifact` 是内存中的版本化内部 DTO，不落数据库，也不成为 Agent API。
4. `projection_note_id IS NOT NULL <=> status='materialized'`；`parsing / publishing / failed` 均不得指向可见投影。
5. 投影 Note 使用 `note_class='source_projection'`，全部物化 Block 使用 `source_kind='source_projection'`。
6. materializer 使用专用 SQL 路径，不复用会注入模板 metadata、proposal 身份或旧 Documents 假设的 helper。
7. 投影发布事务至少同时包含 operation batch、Note、Block、note placement、CanvasObject/placement/mount、source receipt 和 run final flip。
8. retry 后最多存在一个投影 Note；已经 `materialized` 的 run 再次执行只返回既有结果。
9. 原件与投影生命周期分离：解析或发布失败不删除 ready blob；投影缺失也不伪造“原件丢失”。
10. SourceProjection 内容锁是服务端事实；`system` Note 与普通用户 Note 不受误伤。

## Parser / Artifact 边界

统一 `SourceParser` registry，输出 `source-artifact.v1`：

- text block：正文、writing role、可空 `page_index`、稳定 locator 与 parser metadata；
- image object：事实图片的类型和收据信息，不承诺 OCR / vision 文本；
- artifact 只包含 materializer 需要的中性结构，不携带 parser 私有对象。

Capability 1：

- PDF：`pdf-parse` 2.x `PDFParse#getText()`，按 `result.pages` 保留 1-based `page_index`；
- DOCX：`mammoth` 段落流，`page_index=null`；
- TXT / Markdown：UTF-8 文本流；Markdown 只保留可靠的 heading/paragraph 基线，不做语义猜测；
- PNG / JPEG / WebP：建立可查看 image CanvasObject，原件不进入 OCR。

Capability 0（PPTX / XLSX / CSV）保持 stored-only；收到 materialize 请求时返回/记录 `unsupported_format`，不伪装解析成功。

资源门：PDF 最多 1000 页；artifact 最多 5000 个 block；DOCX ZIP 展开量最多为压缩文件的 5 倍；单次 parser 预算 120 秒。越界统一为不可重试 `resource_limit`。

## Durable run 与故障恢复

- claim：`received` 或 retryable `failed` 才可转 `parsing`，同时清旧错误、增加 attempt、写 `started_at`；
- typed error：
  - 不可重试：`unsupported_format / invalid_or_corrupt / resource_limit`；
  - 可重试：`parser_failure / internal_interrupted`；
- parse 完成后以条件更新进入 `publishing`；状态已被别人改变时停止发布；
- startup sweep 将超过 10 分钟的 `parsing / publishing` 标为 `failed/internal_interrupted`；
- retry 复用同一行，发布前检查不存在既有 projection；
- 进程内 scheduler 只负责执行已持久 claim 的任务，不能成为第二套任务真相。

## 原子 Projection 发布

文本投影：

- 建立一篇 `source_projection` Note；
- 为 artifact text blocks 建立 TextFlow-compatible paragraph/heading blocks、note placements 与 `note_block_sources` 收据；
- 建立初始 A4 PageStack、PageFrame，以及每个 block 的 CanvasObject / placement / content mount；
- receipt 记录 `source_record_id`、`source_materialization_id`、page range、excerpt 与 locator。

图片投影：

- 原始 Source blob 仍是事实附件；Canvas image asset 使用独立、确定性的投影副本，禁止让 Canvas asset 删除路径触碰 Source blob；
- 副本在 DB publish 前准备，事务失败时立即补偿；进程中断留下的无 DB 引用副本由 startup sweep 清理；
- DB 事务内发布 canvas asset、image CanvasObject、placement、PageFrame 与 run final flip。

发布事务中任一点注入失败，Note / Block / Canvas 卫星 / receipt / operation batch 必须全部回滚。

## SourceProjection 写策略与旧管线隔离

服务端拒绝 SourceProjection：

- 修改 title / description / page format / status；
- trash/delete Note；
- 创建、修改、删除、恢复或重排物化 Block；
- 修改 PageFrame collection、block Canvas placement、创建/更新/删除 CanvasObject。

允许：

- metadata-only Note 更新；
- `note_block_placements.display_overrides_json`；
- Annotation、ContentGroup、Purpose 专用路径。

客户端只建立被实际数据流使用的 read-only policy 接缝；完整禁用控件、文案和 Source 打开体验属于 10.4。

以下 legacy scanner 必须排除 `source_projection` blocks：模板迁移、领域细化、模板用量、模板兼容报告、legacy source-anchor generation。旧 Agent / embedding 继续休眠，不接入新投影。

## RED-first 检查

先写失败测试，至少覆盖：

1. PDF / DOCX / TXT / Markdown / image 产生版本化 transient artifact；page_index 与能力边界正确；
2. stored-only、损坏文件、页数/块数/ZIP 膨胀/timeout 得到稳定 typed error；
3. 并发双 claim 只有一个胜者，attempt 只增加一次；
4. parse 失败保留 ready blob，run 进入 typed failed；不可重试错误拒绝 retry；
5. 发布事务中途失败后所有投影表和 operation batch 均无残留；
6. retry 后只有一个 Note/current projection，重复执行幂等；
7. parsing/publishing crash 经 startup sweep 变为可重试 `internal_interrupted`；
8. 文本投影具 Note/Block 双标记、TextFlow、PageFrame/CanvasObject/mount 与 source receipt；
9. 图片投影副本不与 Source blob 共生命周期，失败/孤儿副本可补偿；
10. SourceProjection 内容写路由拒绝，metadata/display override 与 Annotation/CG/Purpose 保留；`system` Note 全写路径不回归；
11. 五台 legacy scanner 不读取或改写 SourceProjection。

## 非目标

- 持久 SourceArtifact 表、artifact version history、Edition 或 parser 切换 UI；
- OCR、vision、PDF 表格/公式/图片重建或 MinerU 接入；
- Source Library / Project Sources 页面、上传进度与状态轮询 UI；
- SourceProjection 删除、Course 迁 Home、quarantine 与完整 receipt survival；
- legacy Documents 迁移、Agent、embedding、Relation 或 GraphRAG。

## 退出门

- 新专项 RED 全绿，完整 server v2 suite 无回归；
- parser crash、publish rollback、retry、startup sweep 与并发 claim 均有数据库事实断言；
- PDF / DOCX / TXT / MD / image 真实最小样本通过；
- SourceProjection 写守卫和五台 scanner exclusion 有行为测试；
- client/server build、Canvas runtime/model/performance 总门、`git diff --check` 与 secret scan 通过；
- 无新增 UI 的事实写进 Review，不伪造浏览器 smoke；
- Review 与 current-state 同步，下一前沿指向 V2.BN.10.4。

## 自检问题

收口前必须再问：

> 在 parser 被杀死、publish 第 N 条 SQL 报错或用户连续点击 retry 的情况下，单看数据库与两个 blob root，系统能否唯一判断“继续、重试、清理或打开哪个投影”？

如果答案依赖人工猜测，10.3 不得收口。
