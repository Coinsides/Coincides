## 1. 版本目标

V2.BN.10 建立 Coincides 的 **Source Floor**：

```text
收得进来
找得到
当前 Project 看得到
打得开
引得准
删得明白
```

用户把材料交给 Coincides 后，应当可以放心忘记外部文件位于哪里。原件安全复制进系统；可解析格式产生应用内提取阅读视图；不可解析或解析失败的文件仍可在 Source Library 找到并查看原件；同一 Source 可以出现在多个 Project 镜头中；删除 Project 不删除 Source；删除 Source 时已有引用收据不会静默消失。

V10 是可靠摄入、基本阅读与薄引用版本，不是出版、版次、完整血统、智能重建或 Agent 装配版本。

## 2. 锁定的产品与工程判断

### 2.1 一个全局 Source 身份，四种独立生命周期

V10 使用四层数据脊柱：

```text
source_records
  用户心智中的全局 Source 身份。

source_files
  不可变事实附件：blob、hash、mime、size。

source_materializations
  某个事实附件经某个 parser/version 产生提取投影的一次 durable run。

source_project_placements
  Source 在哪些 Project 镜头中可见。
```

四层不可互相代替：

- 换事实附件不等于换 Source 身份；
- retry 解析不等于新增事实文件；
- 删除 projection note 不等于删除 Source；
- 删除 Project placement 不等于删除 Source；
- 同一文件 hash 命中时返回既有 Source record，并把它放进当前 Project；
- 未来 Edition / Publication history 属于 `source_record`，不属于 `source_file`、projection note 或 Project。本版只保留这条 Future Seam，不实现 Edition。

### 2.2 Project 是镜头，不是 owner

- `source_records` 不以 `course_id NOT NULL` 作为 owner。
- `source_project_placements` 负责当前可见位置，并允许同一 Source 同时出现在多个 Project。
- Origin 与 Placement 分开：Origin 是历史收据，Placement 是当前镜头。
- Source Library 上传的 Source 初始放入系统 Home；Project 上传的 Source 初始放入当前 Project。
- 跨 Project hash 命中必须幂等新增 placement，不能只弹“已在库中”。

### 2.3 收转解耦

- 白名单文件先完成 copy-in 和事实行提交，再异步解析。
- 解析失败不回滚已收文件。
- `SourceArtifact` 只是 parser → materializer 的内部接口，不是持久 Source 身份，也不是未来 Agent API。
- parser-specific 输出必须经 materializer 归一化为 Coincides Note / Block / CanvasObject 结构。

### 2.4 SourceProjection 的准确口径

应用内视图统一称为：

> **复用 Note 内容引擎的 `source_projection` 文档类别；Source 内容锁定，解释与组织可编辑。**

允许：

- Annotation / AnnotationRange；
- ContentGroup / Member / Petal / Fragment；
- Purpose 与 PurposeMember；
- 明确允许的表现层 display override；
- 阅读状态等非内容 metadata。

拒绝：

- 修改投影正文；
- 创建、删除、重排或改写投影 Block；
- 通过 CanvasObject 路径旁路修改物化图片或结构对象；
- 修改 SourceProjection 的 title / description / page format / status；
- 从普通 Note 删除 / trash 路径删除 SourceProjection。

投影内容锁必须是服务端事实；客户端 readOnly policy 负责让用户理解，而不是让 4xx 充当正常交互。

### 2.5 删除采用硬删除，但文件副作用必须可补偿

- Source 业务数据不建用户可恢复软删除；删除 Source 时硬删 Source record、事实附件记录、materialization 与 projection。
- 不保留 `status='deleted'` 伪生命周期。
- 为协调 SQLite 与文件系统而使用的 staging / quarantine / cleanup job 是内部操作状态，不是产品垃圾桶。
- 删除 Project 永远不提供“顺便删 Source”。
- 删除 Source 唯一入口在 Source Library，并显示引用与降级影响。

### 2.6 旧 Agent 与旧 Source 管线保持隔离

- 当前 1.x Agent、embedding 和 legacy 扫描器不是 V10 的消费者。
- 新 SourceProjection 默认不进入旧 Agent、embedding、模板迁移、领域细化或 source-anchor legacy 扫描。
- V10 不新增 Agent UI、prompt、GraphRAG 或 AgentReadingView API。
- 未来 Agent 从新的 Source / Purpose / ContentGroup read model 起步，不迁就 legacy Agent 的数据假设。

## 3. 数据脊柱与不变量

> 精确 SQL 由技术底稿 v2 给出；本节锁定职责、FK 方向和必须存在的约束。

### 3.1 `source_records`

职责：全局 Source 身份和用户可见条目。

最低字段：

```text
id
user_id
display_name
origin_course_id             nullable, ON DELETE SET NULL
origin_course_name_snapshot  删除 Project 后仍保留 Origin 收据
origin_entry_kind            project_upload | library_upload | import
metadata                     本版 key 闭集，不作未来概念垃圾场
created_at / updated_at
```

不允许：

- `course_id NOT NULL` owner；
- 把 hash / storage_key 放在身份行；
- 把 parse_status 放在身份行；
- `active | deleted` 软删除状态。

### 3.2 `source_files`

职责：不可变事实附件。

最低字段：

```text
id
source_record_id             ON DELETE CASCADE
user_id                      用于权限与 hash 唯一约束
original_filename
storage_key
mime_type
byte_size
content_hash
file_mtime
uploaded_at                  UTC
```

硬约束：

- `UNIQUE(user_id, content_hash)`；
- 文件一旦 ready，不原地覆盖 blob；
- 同 hash 命中返回其既有 Source record；
- 不按用户外部路径引用；
- 如技术底稿采用 `storage_state`，它只能表达 staging / ready 等内部提交状态，不能演化成产品软删除。

### 3.3 `source_materializations`

职责：durable parse/materialization run。

最低字段：

```text
id
source_record_id
source_file_id
parser_key
parser_version
status                       received | parsing | publishing | materialized | failed
attempt_count
projection_note_id           nullable, ON DELETE SET NULL
error_code
error_message
started_at / completed_at / created_at / updated_at
```

硬约束：

- 每个 Source 同时至多一个 active run；
- v1 必须有唯一 current materialization 选择规则；
- retry 复用稳定 run identity 或建立显式 attempt，不能重复生成可见 projection；
- `materialized` 只能在完整投影原子发布后写入；
- parsing / publishing 的半成品不进入正常列表、扫描器或用户视图；
- 服务启动 sweep 能确定地恢复或失败化卡死 run；
- parser/version 被记录，但本版不提供切换后端或历史版本 UI。

### 3.4 `source_project_placements`

职责：Source 的 Project 可见关系。

最低字段：

```text
id
source_record_id             ON DELETE CASCADE
course_id                    ON DELETE CASCADE
created_at
```

硬约束：

- `UNIQUE(source_record_id, course_id)`；
- placement 不指向 `source_file` 或 projection note；
- 删除 placement 不影响 Source identity、事实文件、materialization 或其他 placement；
- hash 命中时当前 Project placement 仍必须成功创建。

### 3.5 Note / Block / Receipt 接缝

- `notes.note_class`: `user | source_projection | system`，带迁移后列断言与既有 `canvas_backing` backfill。
- 新建 canvas backing note 的全部前向路径显式写 `note_class='system'`。
- 物化 Block 写 `note_blocks.source_kind='source_projection'`，避免 Block 级写路径和旧扫描器看不见 Note class。
- `note_block_sources` 新路径指向稳定 `source_record_id`；需要精确投影定位时，同时记录 `source_materialization_id` / `source_block_id`。
- Source / materialization / source block 删除时相关 FK 使用 `SET NULL`；`source_excerpt`、locator、reference mode 与本地收据必须保留。
- 旧 `document_id / document_chunk_id` 路径保持 legacy-frozen，不在 V10 强迁移。

### 3.6 Home 系统 Project

- 使用 `courses.system_kind='home'`，不只使用含义模糊的 `is_system`。
- 每个用户每种 `system_kind` 至多一个，数据库 partial unique 保证。
- Home 不可删除、不可改变系统身份或显示名；其余明确允许字段可以更新。
- 公共 API 不允许客户端自行设置 `system_kind` 或 `note_class='system'`。
- Home 是 projection 的安全落点和未归档入口，不是 Source identity 的 owner。

## 4. 生命周期协议

### 4.1 上传与去重

```text
选择文件
  → client SHA-256 precheck（仅节省网络）
  → server disk temp
  → size / extension / MIME / magic-byte / parser-safe-limit 校验
  → server streaming SHA-256（最终裁判）
  → UNIQUE 冲突处理
      命中：清 temp + 幂等新增当前 Project placement + 返回既有 Source
      未命中：提交 Source record/file/placement/materialization(received)
  → 确认 blob 与 DB 一致后返回“已收”
  → 异步解析
```

要求：

- precheck 竞争后仍由数据库 UNIQUE 收口；冲突返回既有 Source，不返回 500。
- 同名不同 hash 默认建立新 Source，并给 display name 加 `(1) / (2)` 后缀；“作为新版本”后置到出版机器。
- Source Library 上传确保 Home 并建立 Home placement。
- Project 上传建立当前 Project placement；Origin receipt 写入 record。
- 50MB 为本版统一上传上限；不再出现 100MB 示例。

### 4.2 文件提交与补偿

技术底稿 v2 必须在以下两种协议中选定一种并写完整状态图：

1. DB staging row → rename → DB ready；或
2. rename → DB transaction → 失败补偿 + 启动 orphan sweep。

无论选哪一种，都必须满足：

- temp 文件可在请求中断和服务重启后清理；
- rename 成功但 DB 失败不会永久遗留孤儿 blob；
- DB row 存在但 blob 不存在时能检测并回滚 / 标错；
- hash 冲突时新 temp / blob 被清理；
- API 只有在事实文件可恢复地落位后才返回“已收”。

### 4.3 解析与原子物化

能力分级：

```text
Capability 0
  pptx / xlsx / csv 等：可保存、可查看原件、可整体引用，不解析。

Capability 1
  born-digital PDF：pdf-parse 2.x，保留 page_index。
  docx：mammoth，按段落流，page_index=null。
  txt / md：文本流。
  image：保存并物化为可查看图片对象；本版不承诺 OCR 文本理解。
```

物化协议：

- parser 输出 transient `SourceArtifact`；
- parser 在 DB 发布事务外运行；
- materializer 使用专用插入路径，不复用会注入模板 metadata 的旧 helper；
- 投影 Note / Block / Placement / CanvasObject / receipt 在原子发布边界内完成；
- 大文档若需要分批写，必须使用不可见 staging + 最终 publish flip，不能把半成品暴露给用户；
- 每次物化建立 `operation_batch`，但 run identity 由 `source_materializations` 承担；
- retry 不重复创建可见 Note / Block；
- typed error 至少区分 unsupported、invalid/corrupt、resource_limit、parser_failure、internal_failure；不可重试错误不显示误导性 retry。

### 4.4 Source 条目打开状态机

| 状态 | 默认打开行为 | 仍可做 |
|---|---|---|
| received / parsing | 状态详情 | 查看原件、下载 |
| publishing | 状态详情，不暴露半成品 | 查看原件、下载 |
| materialized + projection | 打开提取阅读视图 | 查看原件、标注、CG、Purpose |
| failed | 错误详情 | 查看原件；可重试错误显示 retry |
| Capability 0 | 文件详情 / 原生预览 | 整体引用、下载 |
| projection missing | 文件详情，明确“原件仍在；重建后续提供” | 查看原件、下载 |

点击 Source 条目永远不能进入空路由或假装存在可重建投影。

### 4.5 Project 删除

Project 删除对话始终提供：

- 删除该 Project 中的 projection / placement；
- 迁移 projection 到 Home；
- 取消。

Source record 和事实文件不在这个对话中删除；文案明确“如需彻底删除，请前往 Source Library”。

默认项动态决定：

```text
纯机器投影
+ 无其他 Project placement
+ 无用户 Annotation / ContentGroup / Purpose / 人工表现层工作
  → 默认删除投影

存在任一用户劳动
或 Source 仍有其他 Project placement
  → 默认迁移投影到 Home
```

技术底稿 v2 必须把 `has_user_work` 写成可测试查询，排除自动生成但未被用户使用的默认 Purpose，明确哪些 metadata / display override 算人工工作。

迁移仍需覆盖 SourceProjection 的 Note、Block、Annotation、ContentGroup、Purpose、Canvas 与 image 资产卫星，但不再依赖永久手写“15 张表”作为唯一保障。新增 lifecycle policy registry：每个 course-scoped 表必须声明 `move | delete | preserve | fk-derived`，contract test 扫描 schema，出现未登记表即失败。

### 4.6 Source 硬删除

```text
Source Library 发起删除
  → 统计 placements / projection / 引用收据影响
  → 明确警告
  → blob 移入同盘 quarantine
  → DB 事务硬删 record 及其 owned rows、内部删除 projection
  → commit 成功后最终 unlink quarantine
  → commit 失败则恢复 blob
```

要求：

- Source 删除不是任何其他操作的副作用；
- 删除后 `note_block_sources` 等引用行仍保留 excerpt / locator / reference mode；
- 活跳转明确降级为仅收据；
- 最终 unlink 失败进入可重试 cleanup，不把 DB 回滚和物理删除混为一谈。

## 5. 用户工作流

### 5.1 Project 内上传

1. 用户从 Project Sources 区拖入 PDF。
2. 文件先安全入库，当前 Project placement 成立。
3. 条目显示 received → parsing → publishing → ready。
4. 用户可随时查看原件；ready 后打开提取阅读视图。
5. Source 正文不可改，但用户可以标注、建立 ContentGroup、加入 Purpose。

### 5.2 跨 Project 去重

1. 用户在 Project B 上传已从 Project A 进入库的同一文件。
2. client precheck 或 DB UNIQUE 命中既有 `source_file`。
3. 系统幂等建立 `(source_record, Project B)` placement。
4. toast 告知“已在源库中，已添加到当前 Project”。
5. Project B 的 Sources 区立即可见并可打开同一 Source。

### 5.3 Source Library

- 左导航提供唯一全局 Source Library。
- 最低能力：文件名搜索、类型筛选、状态筛选。
- 条目显示 display name、文件类型、上传时间、placement 数和派生状态。
- 只有存在 received / parsing / publishing 条目时进行约 3 秒轮询；页面隐藏时暂停，完成后停止。
- 原件通过认证 fetch → object URL 打开 / 下载，不能使用会在 Bearer-only 鉴权下 401 的裸 URL。

### 5.4 旧 Documents 路径

- 正常课程上传入口切换到 Source 管线。
- legacy Documents 区保留只读查看能力时，可继续显示旧数据；其 Upload 入口隐藏或明确降级。
- 不允许新旧两套摄入入口同时作为正常主路径。
- 不在 V10 迁移旧 Documents、SourceAnchors、SourceSnapshots 真相。

## 6. 五个子版本

### V2.BN.10.1 - Source Identity And Placement Floor

目标：先证明 Source 身份、文件、run 与 Project 镜头彼此独立。

实现：

- 技术底稿升级 v2 并过一次 schema / lifecycle 对抗核查；
- migration 045：`source_records / source_files / source_materializations / source_project_placements`；
- hash UNIQUE、placement UNIQUE、current run 唯一规则；
- `notes.note_class` + 断言 + canvas_backing backfill + 两个前向创建路径；
- `note_block_sources` 新 Source receipt FK；
- `courses.system_kind` + Home partial unique + ensureHomeCourse；
- 服务层 repository / model DTO，不开放未闭合上传 UI；
- legacy 列和旧表保持不动；
- 修复 `source_sync_status='stale'` 读写往返被洗回 fresh 的枚举缺口。

退出门：

- migration 幂等；
- 四层职责 model contract 全绿；
- 两次 placement 写入幂等；
- 同一用户同 hash 无法插入两行；
- 每用户只能存在一个 Home；
- 公共 API 无法伪造 system_kind / note_class。

### V2.BN.10.2 - File Intake And Storage Lifecycle

目标：证明文件能安全收进来，并在所有失败点保持 DB / disk 可恢复一致。

实现：

- 独立 multer disk-temp 管线，不修改 legacy upload middleware；
- 50MB 统一上限；扩展名 + MIME + magic-byte / parser validation；
- server streaming SHA-256；client WebCrypto precheck 仅作优化；
- precheck / upload / list / detail / authenticated blob routes；
- hash 冲突返回既有 Source，并新增当前 Project placement；
- 同名不同 hash 自动后缀新建；
- upload compensation、temp cleanup、orphan sweep；
- capability 0 文件可保存、查看、下载和整体引用；
- typed intake errors 与资源限制。

退出门：

- 并发双上传只产生一个 source_file / source_record；
- rename、DB insert、placement insert 任一点注入失败后无永久孤儿；
- 请求中断与服务重启后 temp 可清理；
- 跨 Project hash 命中当前 Project 可见；
- 白名单内解析失败不影响原件安全。

### V2.BN.10.3 - Parser And Atomic Materialization

目标：证明解析失败可恢复，解析成功只发布完整投影。

实现：

- `SourceParser` + transient `SourceArtifact` 接口；
- native PDF / docx / txt / md / image materializer；
- durable run 状态机与 startup sweep；
- 专用 Note / Block / Placement / receipt / object 插入路径；
- projection Note / Block 双层标记；
- server write-policy guard；
- client readOnly policy 接缝；
- retry 幂等、原子 publish、半成品不可见；
- legacy 五类扫描器 must-exclude：模板迁移、领域细化、模板用量、兼容报告、source-anchor generation；
- `operation_batch` 审计，但不替代 run。

退出门：

- 解析任意阶段 crash injection 后无重复投影或半成品；
- retry 后只有一个 current projection；
- Source 内容写路由全部拒绝，metadata-only / Annotation / CG / Purpose 仍可用；
- system note 全写路径无回归；
- 新 SourceProjection 不进入 legacy Agent / embedding / scanners。

## 8. Closure Gate

V10 只有在以下验收全部成立时才能收口：

1. 两个并发上传只产生一个事实文件和一个 Source identity。
2. 同一 Source 在另一个 Project 上传时，当前 Project 立即获得 placement。
3. 服务在 materialization 任意阶段退出，重启后不存在可见半成品或重复投影。
4. temp / rename / DB insert / unlink 任一步失败后，数据库与磁盘最终可恢复一致。
5. PDF / docx / txt / md / image 各用真实材料完成摄入；解析失败仍能查看原件。
6. Capability 0 文件可保存、查看、下载和整体引用。
7. SourceProjection 内容不可改，Annotation / ContentGroup / Purpose 与允许的表现层操作可用。
8. received / parsing / publishing / failed / ready / no projection 状态均有正确打开行为。
9. 删除 Project 永远不删除 Source；动态默认正确保护用户劳动与其他 placement。
10. move-to-Home 后 Annotation、ContentGroup、Purpose、PageFrame、图片和允许的布局信息仍在。
11. 删除 Source 后引用收据仍在，活跳转明确降级，blob 最终清理。
12. Home 每用户唯一，不可删、不可改系统身份，也不成为 Source owner。
13. 新增 course-scoped 表未登记生命周期策略时 contract test 必须失败。
14. 大文件、压缩膨胀、页数 / Block 数超限、解析超时和不可重试错误均稳定降级。
15. Source Library 支持名称搜索、类型筛选和状态筛选。
16. 新 SourceProjection 不进入 legacy Agent、embedding、模板迁移、领域细化或旧 anchor generation。
17. 浏览器完整走通：

```text
上传
→ 等待
→ 阅读
→ 查看原件
→ 建立薄引用 / 标注 / ContentGroup / Purpose
→ 跨 Project 使用
→ 删除 Project
→ 删除 Source
```
