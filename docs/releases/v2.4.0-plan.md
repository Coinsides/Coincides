## 1. Goal

v2.4.0 establishes the first durable foundation for Learning Canvas.

The goal is not to finish an AFFiNE-like canvas in one patch. The goal is to make Coincides ready for a canvas-first document surface by defining canvas as a projection over existing source-grounded objects.

Target mental model:

```text
NoteBlock / Source / Evidence / Proposal
  -> content and source-grounded objects

Canvas-first Document Surface
  -> presentation, layout, movement, reading, and spatial organization
```

Traditional page-like reading is supported as a canvas preset, not as a separate document mode.

v2.4.x is expected to be split into small patches:

```text
v2.4.0: Canvas-first Document Model + Canvas Data Contract
v2.4.1: Canvas Viewer + Basic Layout
v2.4.2: Template-aware Block Insertion on Canvas
v2.4.3: Agent Canvas Layout Proposal UX
v2.4.4: Canvas Edges + BlockRelation Seed
v2.4.5: Command & Interaction System Seed
v2.4.6: Composition / Section Template Seed, only if organized sections become urgent
```

The track should improve the currently rough v2.3 source/note experience, but it should do so through mode structure and projection surfaces rather than polishing temporary Course Detail panels one by one.

## 3. Version Boundary

v2.4.0 includes:

- define Learning Canvas as a projection surface;
- design the first canvas persistence model;
- separate content state, layout state, and session state;
- define finite/infinite canvas behavior and common page-size presets;
- decide how existing objects may appear as canvas nodes;
- reserve support for edges, frames, grouping, and future relation proposals;
- define the single-surface workspace direction for canvas-first documents;
- run the External Tool Gate before adopting any canvas SDK;
- update v2.x continuity and review files with v2.4 decisions.

v2.4.0 excludes:

- finished infinite canvas UI;
- drag/drop production editor;
- canvas AI proposal apply;
- BlockRelation implementation;
- command palette or shortcut system;
- Source Annotation editor;
- PDF visual rendering;
- Source Board edges;
- freeform style/template customization;
- 2.5D or 3D canvas;
- separate document/canvas dual mode;
- full Notion/AFFiNE visual redesign.

## 4. Product Direction

Henry's target reference is AFFiNE-like clarity, not AFFiNE-like dual-mode architecture:

- stable left navigation;
- focused top bar;
- clean document surface;
- canvas surface with spatial nodes as the default document surface;
- page-like reading available as a layout preset;
- layout discipline rather than exact visual copying;
- theme color is secondary.

Coincides should not become a generic Notion clone. The differentiator remains:

```text
source-grounded learning objects
  -> inspected sources
  -> evidence and scopes
  -> notes and proposals
  -> canvas projections
```

The immediate UX problem v2.4 should begin solving is that v2.3 surfaces are useful but stacked too vertically:

- Source Snapshot;
- Selected Source Scopes;
- Source Board;
- NoteBlock editor;
- proposal panels.

v2.4 should start moving these into a clearer workspace model where ordinary users mainly see the active canvas document surface, and lower-level source mechanics are shown contextually.

## 5. Data Model Direction

Candidate entities:

```text
LearningCanvas
CanvasPreset
CanvasPageSpec
CanvasNode
CanvasEdge
CanvasFrame
CanvasViewportState
CanvasLayoutProposal
CanvasBlockInsertion
```

Node targets may include:

```text
note
note_block
source_snapshot
source_anchor
source_scope
source_board
source_board_node
source_material
material_segment
evidence_set
proposal
projection
```

Core rules:

- Canvas nodes reference existing domain objects.
- Canvas nodes may store display/layout metadata, but not duplicate source truth.
- Canvas layout order is separate from document order.
- Page-like reading order can be derived from layout preset and node ordering.
- Canvas session state, such as zoom and viewport, must not pollute learning content.
- Canvas edges are visual/relationship projections and should not silently become canonical truth.
- AI-generated canvas nodes, edges, frames, or layouts must use Proposal -> Review -> Apply.

The engineering spec will decide exact table names, fields, indexes, and whether v2.4.0 implements schema immediately or first creates a narrow adapter layer.

## 6. Canvas-first Workspace Direction

v2.4.0 should design a single-surface canvas document shell:

```text
Course Workspace
  Left navigation
  Top context bar
  Main surface
    Canvas-first Document Surface
      Infinite board preset
      Finite canvas preset
      A4 / Letter / 16:9 / custom preset
      Page-like reading preset
  Context inspector / source drawer
```

Page-like reading presets should prioritize:

- readable notes;
- ordered blocks;
- source references hidden or subtle by default;
- editing/debug metadata available when needed.

Free canvas presets should prioritize:

- spatial nodes;
- pan/zoom/select/move;
- opening referenced objects;
- collecting source scopes and notes without making new truth copies.

This is a direction lock for v2.4.0. The first production canvas interactions belong mainly in v2.4.1.

## 7. External Tool Gate

v2.4.0 may evaluate external canvas tools, but must not adopt one until the engineering spec completes the External Tool Gate.

Candidate tools:

- `tldraw`
  - strong candidate for infinite canvas SDK, custom shapes, tool modes, store/session, and future interaction system;
  - risk: SDK license/production requirements and avoiding domain-model lock-in.
- `Excalidraw`
  - useful for lightweight whiteboard prototyping, arrows, frames, groups, and visual sketches;
  - risk: `.excalidraw` data must not become Coincides domain truth.

Required decision questions:

- Why are current React/CSS surfaces not enough?
- Which tool owns rendering and interaction only?
- Which objects remain owned by Coincides?
- Can the tool run locally on Windows?
- What license/runtime restrictions affect future open-source or personal use?
- What data remains usable if the tool is removed?
- How does this integrate with future Source Board, Command System, and Canvas Proposal UX?

Default recommendation for planning:

```text
Prefer tldraw for v2.4.1 implementation spike if the tool gate passes.
Keep Coincides LearningCanvas / CanvasNode / CanvasEdge independent from the tldraw store.
```

## 8. API / Contracts

The v2.4.0 engineering spec should define candidate contracts for:

- list/create/update/archive canvases;
- list/add/update/remove canvas nodes;
- list/add/update/remove canvas edges;
- list/create/update frames;
- get canvas with resolved target summaries;
- save session state;
- jump from canvas node to source/note/proposal target;
- create a template-aware NoteBlock on the canvas;
- seed a canvas from Source Board nodes or active SourceScopes.

Implemented route groups:

```text
GET /api/canvases?course_id=...
POST /api/canvases
GET /api/canvases/:id
PUT /api/canvases/:id
POST /api/canvases/:id/archive
POST /api/canvases/:id/restore
POST /api/canvases/:id/nodes
PUT /api/canvas-nodes/:id
POST /api/canvas-nodes/:id/archive
POST /api/canvas-nodes/:id/restore
GET /api/canvas-nodes/:id/jump-target
POST /api/canvases/:id/seed-from-source-board
PUT /api/canvases/:id/viewport
```

Canvas edges and block insertion are reserved for later v2.4.x patches.

## 9. Agent Tool Contract

v2.4.0 should not let AI directly mutate final canvas layout without review.

Allowed agent behavior:

- inspect existing notes, NoteBlocks, SourceScopes, SourceBoardNodes, EvidenceSets, and Proposals;
- suggest which objects are useful candidates for a canvas;
- draft a future CanvasLayoutProposal shape;
- explain warnings and confidence.

Disallowed behavior:

- silently create large graph layouts;
- silently infer truth from visual edges;
- overwrite user layout;
- delete source/note/canvas objects;
- claim that spatial layout proves learning relationship correctness.
