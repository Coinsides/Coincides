# V2.BN.5 Experience Review - Block Visual Language And Control Layer

## Scope

This review records the user-facing experience of the V2.BN.5 structured block seed.

Primary surfaces:

- Note detail page;
- slash command menu;
- floating insert panel;
- Definition block rendering/editing;
- Formula block rendering/editing.

## Experience Criteria

- Default reading should not feel like engineering debug cards.
- The insert surface should expose a small useful block set, not every runtime template.
- Definition should feel like a structured knowledge object.
- Formula should feel like a rendered LaTeX object with editable raw input.
- User-defined templates should have an obvious category slot without requiring a full category manager.

## Browser Smoke

Status: completed with local runtime.

Smoke setup:

- Registered a disposable local smoke user.
- Created a local smoke Project and Note.
- Created one Definition block and one Formula block with `content_json.field_values`.
- Reopened the note in the in-app browser and hard-reloaded the page.

Verified:

1. The note opens after local login/registration.
2. Runtime-resolved Definition metadata remains attached.
3. Runtime-resolved Formula metadata remains attached.
4. Definition reading mode displays the concept name and description as separate fields.
5. Formula reading mode displays the formula name, LaTeX payload, and explanation from structured fields.
6. Normal reading surface does not show export/AI labels by default.
7. Page / Canvas mode state remains available.

Partially verified:

1. The floating Insert entry is visible.
2. The narrow in-app browser viewport made the Insert panel awkward to verify visually; clicking the Insert entry in this narrow setup also made the Page/Canvas state feel easy to misread.
3. The code path for Default / Math / User Defined grouping is implemented, but the first browser smoke evidence focuses on rendered structured blocks rather than a clean wide-viewport Insert panel capture.

## Findings

- Structured fields are working as the core user-visible seed: Definition and Formula no longer need the agent or UI to infer field meaning from paragraph text.
- A hard reload was required after API-side smoke data creation before the frontend displayed newly created blocks. This is acceptable for the smoke setup, because normal user-created blocks are created through the frontend state path.
- The current Browser side-panel viewport is too narrow to judge the final wide-layout Insert experience. Future visual review should use a wider browser surface or manual Henry smoke.
- The Insert control should remain a V2.BN.6/V2.BN.7 follow-up target if the next wide smoke still feels ambiguous.

## Experience Decision

Pass for V2.BN.5 structured block seed.

Do not treat this as a final Insert-panel UX approval. The version is acceptable because the main V2.BN.5 contract is the structured Definition / Formula visual language and narrowed block model; the Insert panel still needs later productization polish.

## Closeout Note

Closed for V2.BN.5 on 2026-06-10 after Henry confirmed the current small version can be wrapped. The last patch cycle kept normal writing calmer by moving block metadata into preview overlays and by simplifying preview controls.
