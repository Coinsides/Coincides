# v2.5.4 Engineering Spec - Template Proposal + Migration Proposal

## Contract

`TemplateMigrationProposal` is the only v2.5.4 path for structural changes that affect active templates with existing NoteBlock usage.

It is proposal-first:

- create proposal;
- inspect diff, affected count, samples, warnings, blockers, and recovery plan;
- apply or discard;
- record migration provenance.

## Schema

Migration `028_v2_template_migration_proposals.ts` adds:

- `template_migration_mappings`
- `template_migration_records`
- `template_migration_record_items`

`template_migration_mappings` stores alias/successor mappings and does not mutate NoteBlocks.

`template_migration_records` stores one applied migration run.

`template_migration_record_items` stores per-NoteBlock before/after metadata, content, block type, action, warnings, and status.

## Proposal API

`POST /api/proposals/template-migration`

Payload:

```json
{
  "source_template_id": "template-id",
  "target_template_id": "target-template-id",
  "target_template_patch": {},
  "migration_mode": "alias_mapping",
  "course_id": "optional-course-id",
  "reason": "optional reason"
}
```

Allowed modes:

- `alias_mapping`
- `soft_migration`
- `hard_cascade`

`target_template_id` is the preferred applyable path. `target_template_patch` is preview-only unless the patch is later persisted as a real template.

## Proposal JSON

Proposal data includes:

- `proposal_kind: "template_migration"`
- source and target template snapshots;
- `migration_mode`;
- `diff`;
- `affected_object_count`;
- sample before/after records;
- source, relation, and render impact;
- warnings and blockers;
- recovery plan;
- `apply_behavior: "template_migration_records_only_or_metadata_updates"`.

## Apply Rules

`alias_mapping`:

- creates `template_migration_mappings`;
- creates migration record and item records;
- does not mutate NoteBlocks.

`soft_migration`:

- updates NoteBlock runtime template metadata;
- preserves `created_with_template_*`;
- appends `template_migration_history`;
- does not rewrite content or legacy block type.

`hard_cascade`:

- only applies mechanically safe changes;
- may update runtime metadata, legacy `block_type`, and add default fields;
- blocks destructive field removal and required fields without defaults.

All apply operations create one `operation_batches` row. Blocked apply fails before partial writes.

## Template Studio

Template Studio adds a compact migration panel when an active template has current NoteBlock usage:

- target template selector;
- migration mode selector;
- create proposal;
- preview diff / affected count / warnings / blockers;
- apply / discard.

No separate Migration Studio page is introduced.

## Tests

Required tests cover:

- migration tables;
- proposal dry-run non-mutation;
- alias mapping apply;
- soft migration metadata update;
- hard cascade blocker and no partial writes;
- direct structural edit still returning `proposal_required`.

## Graph-Native Evidence

`TemplateMigrationProposal` is a future operation-history node candidate.

`TemplateMigrationRecord` and item rows prove whether migration history should remain SQL/history or become graph-visible.

Alias mappings may become compatibility edges such as `TEMPLATE_SUCCEEDED_BY`.
