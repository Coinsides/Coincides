# v2.5.0 Plan - Template Definition Runtime

**Status**: implemented, Henry acceptance pending
**Created**: 2026-05-23

## Goal

v2.5.0 starts the Template / Package Runtime Infrastructure track by turning the v2.1.1 static NoteBlock template registry into a persistent, runtime-resolvable `TemplateDefinition` foundation.

The version is infrastructure-first. It does not build a full user template editor, package marketplace, rich editor adapter, or graph database migration.

## Scope

v2.5.0 includes:

- `template_definitions` runtime table.
- lazy per-user system template seeding from v2.1.1 static registry.
- runtime template resolver using UUID, `template_key`, version, legacy `template_id`, and legacy `block_type`.
- compatibility metadata for new NoteBlocks.
- compatibility report for existing NoteBlocks.
- template API routes.
- runtime metadata integration for manual NoteBlock creation/update, organized note proposals, and canvas-created NoteBlocks.
- first AI-readable Coincides operating manual scaffold.
- graph-native migration evidence in review.

## Out of Scope

v2.5.0 does not include:

- full user-facing template editor;
- arbitrary low-level system type editing;
- automatic bulk migration of old NoteBlocks;
- package marketplace;
- CompositionTemplate runtime;
- DomainBlockSet runtime;
- rich editor adapter;
- real AI provider evaluation;
- Neo4j or other graph database migration;
- broad visual polish.

## API / Contracts

New route group:

```text
GET /api/templates
GET /api/templates/:id
POST /api/templates/seed-system
GET /api/templates/compatibility-report
```

`GET /api/templates` supports optional filters:

```text
status
template_key
system_type
learning_role
```

`GET /api/templates/compatibility-report` supports:

```text
course_id
```

Existing creation/update flows now write runtime metadata:

```json
{
  "template_id": "definition.basic",
  "template_key": "definition.basic",
  "template_definition_id": "runtime-uuid",
  "template_version": "1.0.0",
  "template_resolution_status": "runtime_resolved",
  "system_type": "text",
  "learning_role": "definition",
  "taxonomy_version": "v2.5.0"
}
```

## Agent Tool Contract

Agents should treat `TemplateDefinition` as the runtime template contract.

Rules:

- Use runtime templates before generating or applying new NoteBlocks.
- Do not invent unknown template keys silently.
- Manual unknown template creation fails.
- AI/proposal unknown template output maps to a safe fallback and records a warning.
- Use `summary_for_agent`, `source_behavior`, `relation_behavior`, and `proposal_behavior` as guidance, not as authorization to mutate source, relations, or user content.
- Keep proposal-first for bulk structure changes, source grounding changes, relation confirmation, and template migration.

## Migration

Migration is additive:

- no old NoteBlocks are deleted;
- no old NoteBlocks are silently rewritten;
- old `metadata.template_id` remains supported;
- old `block_type` remains supported;
- compatibility report exposes risk instead of mutating data.

## Test Matrix

Codex checks:

- migration creates `template_definitions`;
- seed import is idempotent;
- seeded templates match v2.1.1 registry keys;
- runtime resolver handles UUID, `template_key`, legacy `template_id`, and legacy `block_type`;
- compatibility report classifies runtime, legacy, missing, and review-required blocks;
- manual/canvas/proposal block creation writes runtime metadata;
- invalid manual template fails with no partial rows;
- old NoteBlocks still load and edit;
- existing v2.4 canvas tests still pass;
- server v2 tests;
- server build;
- client build;
- `git diff --check`;
- changed-file secret scan.

Henry checks:

- template runtime direction feels correct;
- old notes remain usable;
- runtime metadata does not create visible UX burden yet;
- deferring full template editor to v2.5.1 is acceptable.

## Acceptance Criteria

v2.5.0 is complete when:

- runtime template definitions persist per user;
- system templates seed idempotently;
- new NoteBlocks can resolve to a runtime template;
- old NoteBlocks remain readable through compatibility resolution;
- compatibility report exposes migration risk without mutating old blocks;
- organized note proposal and canvas block insertion use runtime metadata;
- quality review is `PASS` or `PASS_WITH_FOLLOWUP`;
- experience review records deferred UX/editor work;
- Henry makes the release/hold decision.

## Graph-Native Migration Evidence

v2.5.0 should record:

- `TemplateDefinition` is a graph-adjacent capability node candidate.
- `NoteBlock -> TemplateDefinition` is a future `USES_TEMPLATE` edge candidate.
- `field_schema`, `render_hints`, `source_behavior`, `relation_behavior`, `proposal_behavior`, and `summary_for_agent` remain nested template properties for now.
- compatibility report output is v3.x migration evidence, not graph truth.
