# V2.BN.3 Review - Freeform NoteBlock Box And Layout Mode

## Status

Implemented; browser smoke and Henry acceptance pending.

## Quality Review

Findings:

- No blocking TypeScript build issue found after implementation.
- V2.BN.3 uses `note_block_placements.display_overrides_json` for layout truth. This is intentionally lighter than a migration and keeps layout out of NoteBlock content.
- The implementation adds a first placement endpoint instead of overloading `note_blocks.metadata`.
- Move/resize persist on pointer release, not continuously during drag, which keeps server writes reasonable.
- First version resize is right-edge only. Corner resize and vertical manual resize remain future polish.
- The default layout for old blocks is deterministic but approximate. It is acceptable as a compatibility seed, but long/complex blocks should be watched during smoke.

Implemented:

- Formal-page BlockBox layout rendering.
- Default stacked layout for old blocks.
- Layout mode toggle in the top chrome.
- Block selection state.
- Move grip for moving blocks.
- Right-edge resize handle.
- Text reflow after width changes.
- Basic snap guides.
- Empty-space spatial insertion for new draft blocks.
- Layout persistence through placement overrides.

## Data Decision

Chosen path:

```text
note_block_placements.display_overrides_json
  -> better_notebook_layout
```

Reason:

- It already belongs to the placement layer.
- It avoids creating a migration before the V2.BN.6 data contract consolidation.
- It keeps the distinction between content truth and layout truth clear.

Known limitation:

- The JSON shape is a seed contract, not the final BlockBox table.
- Future V2.BN.6 should decide whether this remains JSON override, becomes a formal typed field/table, or is backfilled into a stronger placement schema.

## Graph-Native / Adapter Evidence

- `NoteBlock` remains the content node candidate.
- `better_notebook_layout` is projection/layout evidence, not semantic graph truth.
- Visual adjacency and side-by-side placement must not be imported as ObjectRelation.
- Future GraphRAG should read explicit ObjectRelations, sources, concepts, and structured fields before considering layout hints.
