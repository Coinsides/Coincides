## 1. Goal

v2.1.1 establishes the first Learning Block Template Engine seed.

It separates fixed system block capability from learning semantics:

```text
system_type -> text / latex / code / source_quote / task / media / table
learning_role -> concept / definition / theorem / proof / formula / example / exercise / answer / note / warning / source
template_id -> definition.basic / formula.math / example.general / exercise.general
```

This prevents Coincides from hard-coding every possible discipline-specific block subtype while keeping future user-editable templates possible.

---

## 2. Version Boundary

v2.1.1 includes:

- fixed NoteBlock taxonomy seed;
- shared template registry;
- legacy block type compatibility mapping;
- metadata-based template information on new NoteBlocks;
- registry-backed manual Note editor selector;
- template-aware organized note proposal generation and apply;
- light proposal preview label improvements;
- docs, review, continuity, changelog updates.

v2.1.1 excludes:

- full user template editor;
- drag-and-drop template builder;
- advanced code-like template editing;
- user-created low-level system types;
- canvas / edgeless workspace;
- BlockSuite/AFFiNE dependency;
- multi-provider AI adapter unless separately approved;
- Material Reconciliation;
- Source Snapshot Viewer;
- full Note editor redesign.

## 3. Implementation Steps

### Step 1: NoteBlock Taxonomy

Define shared types for:

- `NoteBlockSystemType`
- `NoteBlockLearningRole`
- `NoteBlockTemplateDefinition`
- `NoteBlockTemplateMetadata`

Use `note_blocks.metadata` for taxonomy metadata. Do not add a destructive migration.

### Step 2: Template Registry Seed

Create a static shared registry with:

- template id;
- label;
- system type;
- learning role;
- fields;
- default content;
- render hint;
- proposal allowed;
- source reference allowed.

Required templates:

```text
text.paragraph
text.heading
concept.basic
definition.basic
theorem.basic
proof.basic
formula.math
example.general
exercise.general
answer.general
source.quote
warning.callout
code.snippet
```

### Step 3: Compatibility Layer

Map legacy block types to template metadata.

Existing notes without metadata must still load, edit, and render.

New manual and proposal-created blocks should write:

```json
{
  "system_type": "text",
  "learning_role": "definition",
  "template_id": "definition.basic",
  "taxonomy_version": "v2.1.1"
}
```

### Step 4: Manual Note Editor

Replace the hardcoded block type selector with registry-backed template choices.

The UI should remain simple:

- friendly template labels;
- current textarea-first editing;
- existing source reference display;
- existing up/down reorder behavior.

### Step 5: Organized Note Proposal

Update organized note proposals so candidate blocks include template metadata.

AI output should prefer `template_id` or `learning_role`. Unknown values fall back safely and record warnings.

Deterministic fallback must also generate template-aware blocks.

### Step 6: Review And Research Follow-up

Update v2.1.1 review files and continuity.

After v2.1.1 closes, run a separate product/architecture research pass and write:

```text
docs/research/v2.x-product-reference-review.md
```

That research should calibrate v2.2 Material Reconciliation, v2.3 Source Snapshot Viewer / Source Board, and v2.4 Learning Canvas.
