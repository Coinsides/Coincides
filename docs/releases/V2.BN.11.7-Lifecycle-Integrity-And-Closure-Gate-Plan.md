# V2.BN.11.7 Lifecycle, Integrity And Closure Gate Plan

> **状态 (Status)**: engineering complete；待第三方独立复验
> **日期 (Updated)**: 2026-07-14
> **权威 (Authoritative)**: 否；这是 V2.BN.11.7 施工计划，当前事实以 `docs/agent-ops/current-state/` 为准
> **前置门**: V2.BN.11.6 第三方 PASS（2026-07-14）

## 1. 目标

V2.BN.11.7 是 V11 的工程收口版本。它不增加图谱工作台、AI assessment 或新的 Relation 语义，而是通过真实删除、全量替换、迁移升级和遗产清场证明：

- `Item` 与 `Relation` 是独立知识真相，不被 Project、Note、Purpose 或 ContentGroup 的生命周期误删；
- `origin_course_id / origin_note_id / origin_purpose_id` 是可降级 receipt，不是假 ownership；
- 保留同一 Purpose 身份的全量保存不会洗掉 Relation 的 `origin_purpose_id`；
- 真正删除 Purpose 时只删除组织边，并将 Relation origin receipt 诚实降级为 `NULL`；
- migration 047、Package A / B、机械 freshness 与 legacy shutdown 共同构成一条闭合数据链；
- 已卸载且依赖已落表死亡的 legacy Relation 路由和 helper 被物理移除，不再留下可误接回的假入口。

本版本只签发 **engineering complete**。Source / Purpose / Relation / ContentGroup / Canvas 的集中浏览器体验验收继续 deferred，不把机器绿灯冒充 Henry 的主观验收。

## 2. 审计发现

### 2.1 已成立的地基

- migration 047 已建立 `items / item_snapshots / item_anchors / relations / relation_assessments`；
- Item 的 Project / Note origin 使用 `ON DELETE SET NULL`；Relation 的 Purpose origin 使用 `ON DELETE SET NULL`；
- `content_group_members.item_id` 使用 `NO ACTION`，禁止普通 hard delete Item；
- 11.5 / 11.6 已证明 Relation 双 Snapshot、revoke / reaffirm、四态机械 freshness 与 Inspector；
- 047 已 drop Petal 三表及 `object_relations / canvas_edges / relation_layers`；
- 11.1 shutdown contract 已证明旧路由没有 mount。

### 2.2 本版必须关闭的真实缺口

`replaceNotePurposes` 当前先删除 Note 下全部 Purpose，再按相同 ID 重建。SQLite 会在删除阶段将 `relations.origin_purpose_id` 设为 `NULL`，因此普通保存会丢失本应保留的 origin receipt。

修复原则：

- 同 ID、同用户、同 Note 的 Purpose 原地更新；
- 新 Purpose 插入；
- payload 中真正消失的 Purpose 最后删除；
- Purpose member 仍允许 full replacement，但 member 边替换不得重建 Purpose 身份；
- hidden retired/missing Item 与 deleted/missing ContentGroup edge 的并发保护继续成立；
- 来自另一用户或另一 Note 的 Purpose ID 不得被劫持。

### 2.3 遗产物理清扫边界

删除确认未挂载的旧路由模块：

- `server/src/routes/learningCanvases.ts`
- `server/src/routes/canvasNodes.ts`
- `server/src/routes/canvasEdges.ts`
- `server/src/routes/objectRelations.ts`
- `server/src/routes/relationLayers.ts`

从 `server/src/services/learningCanvases.ts` 移除只服务于已 drop 三表的：

- Canvas edge CRUD；
- Relation layer seed / list；
- ObjectRelation list / bind / unbind；
- 依赖上述对象的旧 detail / command-context surface。

保留仍被 Composition、layout proposal、Source 测试使用的 learning canvas、node、viewport、source-board seeding 与 block insertion helper。本版不顺手拆除仍有活调用者的历史 canvas/node 基础。

## 3. RED-first 测试矩阵

### 3.1 Purpose 身份与 receipt

1. 创建 Purpose-origin Relation；用相同 Purpose ID 执行 full replacement；断言 Relation origin 仍指向原 Purpose。
2. 从 replacement payload 真正移除该 Purpose；断言 Item / Relation 存活，membership 删除，Relation origin 降级为 `NULL`。
3. 另一 Note / 另一用户复用 Purpose ID 被拒绝。
4. 既有 filtered hidden-edge recovery 与 stale payload 测试继续通过。

### 3.2 容器生命周期

1. 独立 hard-delete Note fixture：Item、Snapshot、Anchor、Relation 存活；`origin_note_id` 降级；Anchor excerpt / target receipt 保留。
2. 删除 Project：Item / Relation 存活；`origin_course_id` 降级；其他 Project 中的 ContentGroup / Purpose Item edge 继续可读。
3. 删除 ContentGroup root：只级联其 member edge；Item / Relation 存活。
4. retired Item 仍可作为 active Relation 端点读取，但不可 reaffirm；Relation 可 revoke。
5. lifecycle registry 同时覆盖 `course_id` 与 `origin_course_id`，并验证 `SET NULL` 口径。

### 3.3 Migration / replacement / legacy absence

1. 047 从真实 046 member shape 升级、重复启动和 rollback fixture 继续通过。
2. Package A / B 的 kind、ID、hidden edge 与 receipt 不在 full replacement 中被洗掉。
3. 旧 route 文件不存在；`learningCanvases.ts` 不再包含三张退役表名或旧 Relation helper。
4. `server/src/index.ts` 无旧 mount；BN `visual_connector` 与当前 `relations` 保持独立。

## 4. 实现步骤

### Step A - Purpose identity-preserving replacement

- 把 Purpose replacement 改成事务内 identity-preserving reconcile；
- 两阶段处理 default Purpose，避免 unique default 冲突；
- 对 surviving Purpose 原地更新，对 omitted Purpose 最后删除；
- 对每个 surviving Purpose 替换 member edges，并恢复需要隐藏保留的 edge；
- 保持 Note `updated_at` 与现有返回模型不变。

### Step B - Lifecycle integration suite

- 新建 V11 closure suite，并加入 `server/package.json test:v2`；
- 尽量通过现有 domain service / deletion service 走真实写路径；
- 只在验证 FK 降级时使用明确的 fixture hard delete；
- 不新增 soft-delete 垃圾桶或 Relation sync 状态。

### Step C - Legacy physical cleanup

- 删除未挂载 route 文件；
- 精确切除 `learningCanvases.ts` 的 dead edge/layer/ObjectRelation 分支；
- 扩充 legacy shutdown static contract，使“未挂载”升级为“物理不存在 + 活跃 service 不含退役表写入”；
- 跑 Material Library、Composition、Source 与 Canvas persistence 回归，证明保留的老 helper 仍正常。

### Step D - 26 项 closure gate

- 对照父计划 §8 建立逐项证据表；
- 已由前序版本证明的事实引用现有 suite / contract，不复制实现；
- 新发现的缺口先补测试，再做最小修复；
- 更新 V11 Review、CHANGELOG、current-state 与第三方 handoff。
