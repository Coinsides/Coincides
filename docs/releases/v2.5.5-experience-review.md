# v2.5.5 Experience Review - Package Studio Lite / Export-Import Foundation

## Current Experience Status

`PASS_WITH_FOLLOWUP`

## Intended Experience

Template Studio now has a Package Studio Lite area where Henry can:

- preview a Light or Trusted package export;
- export a JSON bundle;
- paste or upload a JSON bundle;
- preview import conflicts;
- apply only when blockers are absent;
- discard a preview without mutation.

## Experience Boundary

This is still an engineering surface, not a polished package marketplace.

It should feel understandable enough for local runtime package testing, but it does not attempt:

- package browsing marketplace UX;
- visual package diff;
- domain migration workflow;
- source-file backup;
- full project restore.

## Deferred UX Debt

- Package Studio Lite may need a dedicated page or clearer split once package editing/import/export grows.
- Import conflict display is compact and should become richer before broader use.
- Source recovery material language must stay very explicit so users do not think source rows are recreated.

## Browser Smoke Status

Passed after Henry confirmed the local runtime restart.

Smoke target:

```text
Template Studio -> Package Studio Lite
Create Light export preview
Create/export JSON bundle
Import same JSON bundle
See resolved-existing/conflict preview
Discard preview
Import a modified safe package
Verify imported runtime objects appear
```

Observed result:

- Light export preview showed the expected package summary, hash, and runtime object counts.
- JSON export populated a `.coincides` bundle.
- Importing the same bundle produced resolved-existing rows and could be discarded without apply.
- Importing a safe renamed smoke package produced imported package/template/domain rows.
- Applying the safe package made the new package, domain, and template visible in Template Studio.
