## 1. Goal

Let users create real template-aware NoteBlocks directly from the Canvas Document surface.

The created object has two layers:

```text
NoteBlock
  -> canonical semantic content

CanvasNode
  -> projection/layout on the canvas
```

Canvas remains a projection. NoteBlock remains the knowledge/content object.

---

## 2. Version Boundary

v2.4.2 includes:

- canvas-side content block insertion;
- template registry-backed choices such as Definition, Formula, Example, Exercise, Source Quote, Callout, and Code Snippet;
- automatic canvas backing note behavior;
- real `note_blocks` and `note_block_placements` creation;
- `canvas_nodes` projection creation for the new NoteBlock;
- browser smoke for Add block -> move/resize -> reload.

v2.4.2 excludes:

- visual-only canvas shapes;
- free arrows;
- CanvasEdge / ObjectRelation / RelationLayer;
- relation editing;
- AI layout proposal;
- full NoteBlock editor replacement;
- Source Annotation / PDF visual rendering;
- tldraw dependency adoption;
- real API provider eval.

---

## 3. Product Boundary Clarification

v2.4.2 records this durable object boundary:

```text
NoteBlock = semantic content
CanvasShape = visual object
CanvasEdge = visual connector
ObjectRelation = confirmed semantic relation
```

Only NoteBlock insertion is implemented in this patch. A user's visual helper object should not be forced into NoteBlock. Visual objects and semantic relations are later canvas/relation work.

---

## 4. Implementation Contract

Backend:

- add `POST /api/canvases/:id/note-blocks`;
- validate canvas ownership and active status;
- validate `template_id` against the v2.1.1 template registry;
- if `note_id` is omitted, find or create a canvas-owned backing note;
- create a template-aware NoteBlock and placement in the backing note;
- create a `note_block` CanvasNode pointing to the new block;
- reject unknown templates without partial rows.

Frontend:

- add an `Add block` action in `LearningCanvasSurface`;
- use registry-backed template labels;
- allow a simple text entry for the block body;
- insert near the current viewport center;
- refresh the active canvas and show the new node.

Data safety:

- creating a block mutates only notes, note blocks, placements, operation batch, and the new canvas node;
- moving/resizing the new node still mutates only `canvas_nodes`;
- no source, evidence, proposal, SourceBoard, or relation rows are modified.

## 7. Assumptions

- Canvas backing notes are implementation containers, not a new user-facing document mode.
- Canvas-created NoteBlocks are real content and must remain readable outside canvas.
- Heavy subjective visual acceptance remains deferred until the v2.4 canvas model matures further.
- Graph-native migration notes should record the distinction between content object, projection node, visual connector, and semantic relation.
