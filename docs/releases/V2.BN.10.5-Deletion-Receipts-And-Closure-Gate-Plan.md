# V2.BN.10.5 - Deletion, Receipts And Closure Gate

> **施工结果（2026-07-11）**：Task 1–4 的工程实现与自动化验证已完成。V2.BN.10.4 + 10.5 的联合浏览器真实旅程尚未执行，因此本小版本不冒充完整体验验收，V2.BN.10 也暂不标记为 fully closed。

## 1. 本次要证明什么

本小版本不把“删除”理解成一条 `DELETE` 语句，而是同时证明五种生命周期彼此独立：

- Project 可以删除，但 Source identity 与事实原件不随之消失；
- SourceProjection 可以删除或迁往 Home，用户劳动不得被默认误删；
- Source 可以从 Source Library 硬删除，但已有 receipt 必须降级而非蒸发；
- SQLite 回滚不能假装恢复已经被 `unlink` 的文件；
- 新增 `course_id` 表若没有生命周期策略，契约检查必须阻止其悄悄进入系统。

## 2. 施工顺序

### Task 1 - 数据与契约地基

- migration 046 修复 receipt 的真实 `SET NULL` 外键，并允许 materialized projection 缺失；
- 增加 durable managed-file cleanup job；
- 建立 course-scoped lifecycle policy registry 与 schema coverage check；
- 先写失败测试覆盖 Project、Source、receipt、blob 与 rollback。

### Task 2 - Project 删除闭环

- 增加删除影响统计；
- 以“用户劳动或其他 placement”决定动态默认；
- 支持 `delete_projection | move_to_home` 两条显式路径；
- move-to-Home 保留 Note、Block、Annotation、ContentGroup、Purpose、PageFrame、CanvasObject、图片与表现层数据；
- Project 删除永远不删除 Source record 或 Source blob。

### Task 3 - Source 硬删除闭环

- 唯一入口位于 Source Library；
- 删除前统计 placements、projection、receipt 与 projection 上的用户劳动；
- 原件先移入同盘 quarantine，再提交数据库硬删除；
- 事务失败恢复原件，提交后最终 unlink；
- 最终清理失败写入可重试 cleanup job；
- receipt 保留 excerpt、locator、reference mode，活跳转降级。

### Task 4 - UI 与收口

- Project 删除对话展示影响、动态默认与两个行为；
- Source 删除对话明确不可恢复以及 receipt 降级结果；
- 跑 model / integration / build / runtime boundary / diff / secrets 验证；
- 更新 Review、Experience Review、CHANGELOG、Open Issues 与 current-state；
- 浏览器真实旅程写入第三方 handoff，V2.BN.10.4 的 pending browser gate 不借此冒充通过。

## 3. 明确不做

- 不引入用户可恢复的 Source 软删除或产品垃圾桶；
- 不实现 Edition、Publication、Source replace 或 projection rebuild；
- 不把 Project 重新变成 Source owner；
- 不把 legacy Agent、embedding、GraphRAG 接入新 Source；
- 不把 cleanup job 暴露成用户可见生命周期。

## 4. 完成定义

1. 删除 Project 的两个分支均经集成测试，Source identity/blob 始终保留。
2. 动态默认可由查询和测试解释，不依赖前端猜测。
3. 迁 Home 后指定卫星数据完整且 Home placement 存在。
4. 删除 Source 后 projection 消失、receipt 行仍在且 Source FK 变为 `NULL`。
5. DB 失败、rename 失败与最终 unlink 失败均不会留下不可解释半状态。
6. asset 文件删除发生在 DB commit 之后，失败进入 durable cleanup。
7. schema 中每张 `course_id` 表都被 lifecycle registry 覆盖。
8. 工程门全部通过；浏览器门若未执行，必须继续明确标为 pending。
