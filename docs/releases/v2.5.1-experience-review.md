# v2.5.1 Experience Review

**Current Experience Status**: `PASS_WITH_FOLLOWUP`
**Version**: v2.5.1 User-facing Template Editor Seed

## UI / Visual Findings

- Template Studio is now an independent page reachable from the main sidebar.
- Layout is intentionally utilitarian: template library, guided editor, preview/compatibility side panel.
- It is not yet visually polished to AFFiNE/Notion quality, but it keeps the daily Course/Canvas surface clean.

## Interaction Findings

- Template Studio should feel guided, not like raw JSON editing.
- System templates expose a copy path rather than direct editing.
- Draft templates expose structured field rows, policy presets, preview tabs, and lifecycle actions.
- Active templates with usage show a warning instead of allowing dangerous structural edits.

## Workflow Findings

- Users should copy system templates before editing variants.
- Daily Course/Canvas flows should remain clean.
- Note editor and Canvas Add Block use runtime templates, so activated user templates can enter real content creation paths.

## Product Fit Findings

- v2.5.1 should prove template editing direction without becoming Package Studio.
- This version demonstrates the right product boundary: Template Studio edits variants; future Package Studio / migration proposal work remains separate.

## Accessibility / Density Findings

- Page uses stable three-panel density on desktop and collapses responsively.
- Detailed keyboard and screen-reader review is deferred.

## Deferred UX Debt

- Full template IDE.
- Migration proposal UX.
- Package Studio.
- Rich editor adapter.
- More polished visual hierarchy after product-facing UX reference research.

## Henry Acceptance / Priority Decisions

- Pending Henry v2.5.1 release/hold decision.
- Recommended Henry check: copy one system template, edit labels/fields/summary, activate it, then use it from Canvas Add Block or Note editor.
