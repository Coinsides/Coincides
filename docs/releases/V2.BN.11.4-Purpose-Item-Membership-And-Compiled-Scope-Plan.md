## 1. 本小版本解决什么

V2.BN.11.4 原子完成 Package A，让 Purpose 的持久成员边同时支持 `content_group | item`，并建立一份不反写数据库的 Purpose 编译视图：

```text
Purpose direct Item edge
  + Purpose -> ContentGroup -> Item derived path
  -> active Item identity de-duplication
  -> explainable membership paths
  -> Purpose-bounded Item search for later Relation Inspector
```

数据库现有 `purpose_members(member_kind, member_id)` 已能承载两种成员，不新增迁移。本版重点是把 server / validator / client / UI 的全量替换路径一次改齐，避免部分升级导致 Item edge 被洗型或误删。

## 2. 必守不变量

1. `Item` 是知识真相，`ContentGroup` 是组织方式，`Purpose` 只保存直接成员边与情景属性。
2. ContentGroup 内的 Item 只在读取时派生进 Purpose scope；不得写成新的 `purpose_members` 行。
3. 编译视图按 Item identity 去重，但保留所有 direct / via-ContentGroup 来源路径。
4. retired / missing Item 不进入 active compiled scope；历史 direct edge 仍必须被全量替换保护。
5. deleted / missing ContentGroup 的历史边继续采用同一 hidden-edge 恢复协议。
6. 新建 direct Item edge 只允许指向当前用户的 active Item；跨用户、missing、retired 均拒绝。
7. Purpose root 不新增权限、图布局、Relation applicability 或 Canvas 字段。
8. 派生 scope 的读取绝不能改变 `purpose_members` 行数或内容。

## 3. 施工纵切

### 3.1 RED - Package A 与绞杀风险

- validator 与 server normalizer 接受 `member_kind = item`；
- client normalizer 保留 Item kind，不静默转成 ContentGroup；
- direct Item 的 add / remove / reorder / role / fitness roundtrip；
- full replacement 抢救 retired / missing Item 与 deleted / missing ContentGroup 隐藏边；
- direct + 一个或多个 ContentGroup 路径去重且来源可解释；
- ContentGroup Item membership 改动在下一次读取动态生效；
- derived Item 与 compiled search 均为纯读，断言零反向持久化。

### 3.2 Server - 直接边与编译视图

- 扩展 Purpose member kind、存在性检查和 active 可见性过滤；
- 把 hidden-edge 查询扩展为两种成员的统一恢复规则；
- 新增 Purpose compiled scope service，返回 Item 摘要、`direct | derived | direct_and_derived` 标记与 membership paths；
- 新增 Purpose-bounded Item search endpoint，按正文、type、topic 过滤，限制结果数量；
- 所有 Purpose / Item / ContentGroup 查询均按 `user_id` 限域。

### 3.3 Client - 原子 DTO 与最小可用操作面

- 扩展 `PurposeMemberKind` 与 compiled scope DTO / repository；
- 提供 direct Item member 的 upsert、remove、move、role / fitness 更新模型函数；
- 将现有 `purposeFrames` 与保存命令穿到 Item Inspector；
- 在 Item Inspector 提供最小 Purpose membership 控件，不建设 Purpose 工作台或 Relation 图。

## 5. 退出条件

- `content_group | item` 两种 Purpose member 完整读写且 client 不洗型；
- 隐藏 Item / ContentGroup 边经过过滤读取与全量保存后仍可恢复；
- compiled scope 对同 Item 去重并完整解释所有来源；
- retired Item 不进入 active scope，derived Item 永不落库；
- Purpose-bounded search 可供 11.5 / 11.6 的 Relation Inspector 直接复用；
- 工程门、浏览器 smoke 与 Review 证据齐全。

## 6. 工程结果（2026-07-13）

V2.BN.11.4 已按本 Plan 完成 Package A 与 compiled scope 纵切：

- Purpose direct member 已完整支持 `content_group | item`，Item edge 可新增、更新 role / fitness、排序与移除；
- hidden-edge recovery 已统一覆盖 deleted / missing ContentGroup 与 retired / missing Item，并保护退役前已加载的 stale client payload 不会误删或改写历史边；
- Purpose compiled scope 在读时汇总 direct Item 与 Purpose-member ContentGroup 内的 active Item，按 Item identity 去重并保留全部来源路径；
- Purpose-bounded Item search 已提供给后续 Relation Inspector，派生结果不会写回 `purpose_members`；
- Item Inspector 已提供最小 direct Purpose membership 操作面，不借本版扩张 Purpose 工作台或 Relation UI。
