## Goal

Create the first guided user-facing editor over runtime `TemplateDefinition`, without turning v2.5.1 into a full template IDE, Package Studio, or migration system.

## Version Boundary

v2.5.1 includes:

- global user template creation from fixed system types and learning roles;
- copy-from-system-template into a user-owned draft;
- guided field schema editor lite;
- render intent editor lite;
- source/relation/proposal policy presets;
- `summary_for_agent` editor lite;
- reading/editing/debug/proposal preview;
- template lifecycle actions;
- compatibility warnings and usage counts;
- Template Studio independent route;
- runtime template fetch for Note editor and Canvas Add Block;
- graph-native migration evidence.

v2.5.1 excludes:

- course-scoped templates;
- domain-scoped or package-scoped templates;
- low-level `system_type` creation;
- automatic migration of existing NoteBlocks;
- TemplateMigrationProposal implementation;
- CompositionTemplate, DomainBlockSet, PackageManifest, or Package Studio;
- rich editor adapter;
- marketplace or executable plugins.

## API / Contracts

Extend `/api/templates`:

```text
POST /api/templates
POST /api/templates/:id/copy
PUT /api/templates/:id
POST /api/templates/:id/activate
POST /api/templates/:id/deprecate
POST /api/templates/:id/archive
POST /api/templates/:id/restore
GET /api/templates/:id/usage
```

Rules:

- system templates are read-only;
- structural edits are allowed only on draft user templates;
- active user templates with usage reject structural edits with `proposal_required`;
- archive rejects templates with current NoteBlock usage;
- deprecated templates remain resolvable;
- old NoteBlocks are not silently rewritten.

## Data Model

No new table is required. v2.5.1 uses `template_definitions`.

New metadata may be stored on `template_definitions.metadata`:

```json
{
  "copied_from_template_definition_id": "uuid",
  "copied_from_template_key": "definition.basic",
  "v2_5_1_editor": {
    "direct_safe_fields": ["label", "description", "render_hints", "summary_for_agent"],
    "structural_fields": ["field_schema", "source_behavior", "relation_behavior", "proposal_behavior"]
  }
}
```

## Agent Tool Contract

Agents should use Template Studio APIs to create and edit user templates.

- Do not mutate system templates.
- Do not invent `system_type` or `learning_role` values.
- Do not silently migrate old blocks.
- Treat compatibility warnings as blockers for direct structural edits.
- Use future migration proposals for bulk or dangerous changes.

## Test Matrix

Codex checks:

- system templates reject direct update;
- copy creates user draft and preserves behavior fields;
- draft creation validates fixed taxonomy and field schema;
- draft structural edits pass;
- active template with usage rejects structural edits;
- active safe metadata edits pass;
- archive rejects template with usage;
- deprecate keeps old blocks resolvable;
- usage endpoint counts runtime and legacy usage;
- Note editor and Canvas block insertion can use runtime user templates;
- v2.5.0 resolver tests still pass;
- existing v2.4 canvas tests still pass;
- server v2 tests, server build, client build, `git diff --check`, changed-file secret scan.

Henry checks:

- Template Studio feels like a guided editor, not raw JSON;
- system template copy flow is understandable;
- compatibility warnings make dangerous edits obvious;
- first preview modes are useful enough as a seed;
- deferring migration proposals and Package Studio remains acceptable.

## Acceptance Criteria

v2.5.1 is complete when:

- a user can open Template Studio and inspect templates;
- a user can copy a system template into a draft;
- a user can edit safe draft fields and activate the template;
- Note editor and Canvas Add Block can use the activated runtime template;
- dangerous edits are blocked or warned instead of silently mutating old blocks;
- quality review is `PASS` or `PASS_WITH_FOLLOWUP`;
- experience review records deferred editor/package UX debt;
- Henry makes the release/hold decision.

## Graph-Native Migration Evidence

v2.5.1 should record:

- user-created and copied `TemplateDefinition` strengthen the future graph node candidate;
- `NoteBlock -> TemplateDefinition` remains a future `USES_TEMPLATE` edge candidate;
- template edit history is not graph truth yet;
- direct-safe versus proposal-required edit classification is migration evidence for v2.5.4 and v3.x.
