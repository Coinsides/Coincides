# v2.1 Experience Review - AI Note Proposal + Course Material Library Seed

**Created**: 2026-05-19
**Branch**: `feat/v2.0-noteblock`
**Experience Status**: `PASS_WITH_FOLLOWUP`

This file is the product experience state machine for v2.1. Engineering quality findings belong in `docs/releases/v2.1-review.md`.

---

## Current Experience Status

`PASS_WITH_FOLLOWUP`

v2.1 now has a usable foundation flow: course material is visible at course level, proposals are reviewed before apply, and applied organized notes open in the existing Note editor. The experience is acceptable for the v2.1 foundation, with product polish deferred.

---

## UI / Visual Findings

Status: `PASS_WITH_FOLLOWUP`

- Course Material / Proposal surface is implemented in Course Detail.
- Material sources show parse, fragment, segment, proposal status, warnings, and a small segment preview.
- Proposal review panes are compact and scannable enough for v2.1.
- Visual treatment is still utilitarian and closer to a foundation workspace than a final product surface.
- v2.0 Note editor polish debt remains deferred unless it blocks proposal review/apply.

---

## Interaction Findings

Status: `PASS`

- User can create a material map proposal from course material.
- User can review/apply/discard material map proposal.
- User can create an organized note proposal.
- User can review/apply/discard organized note proposal.
- Applied organized note opens in the existing Note editor.
- Browser smoke verified the primary proposal -> apply -> note editor path.

---

## Workflow Findings

Status: `PASS_WITH_FOLLOWUP`

Expected workflow:

```text
Course Detail
  -> Course Material / Proposal area
  -> material map proposal
  -> organized note proposal
  -> apply
  -> Note editor
```

The user must never feel that AI silently wrote permanent course notes without review.

Current implementation satisfies the review-first rule. Material map and organized note structures are previewed before apply, and the organized note only becomes a real note after user action.

---

## Product Fit Findings

Status: `PASS_WITH_FOLLOWUP`

v2.1 feels like the first useful bridge from uploaded material to editable study notes. It does not yet feel like a finished source viewer or full learning OS, which is acceptable within the v2.1 boundary.

Required product language:

- "I found these source ranges."
- "I organized these candidate blocks."
- "This proposal needs your review before applying."

Avoid:

- claims of complete course understanding;
- learner diagnosis;
- overconfident source interpretation.

---

## Accessibility / Density Findings

Status: `PASS_WITH_FOLLOWUP`

- Proposal preview is scannable for a small course material set.
- Warnings are visible in the review pane.
- Source references are summarized in the proposal preview, then visible on applied NoteBlocks.
- Course Detail is denser than before, but still acceptable for v2.1 foundation work.

---

## Deferred UX Debt

Carried from v2.0 continuity:

- Note editor feels like an engineering test surface.
- `Add Note` starts from bare `Untitled note`.
- NoteBlock type list is fixed and math-heavy.
- NoteBlock reorder uses up/down buttons.
- NoteBlocks are visually large and only stack vertically.

v2.1 should address these only if they block proposal review/apply.

New v2.1 UX follow-ups:

- Proposal review is foundation-level and should become more product-like in a later proposal UX pass.
- Proposal preview currently shows a limited number of blocks/segments and does not provide deep source inspection.
- Browser smoke required bypassing the onboarding overlay for the test account; onboarding should be reviewed later so it does not obscure deep-link testing.
