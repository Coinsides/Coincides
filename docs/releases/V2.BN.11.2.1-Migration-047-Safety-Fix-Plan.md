## 1. 目标

在 migration 047 尚未提交、尚未进入任何已迁移数据库的窗口内，关闭 V2.BN.11.2 第三方复核发现的两处迁移安全缺口，不扩张到 V2.BN.11.3。

## 2. 锁定范围

### R1. ContentGroup Item membership 删除动作

- `content_group_members.item_id` 使用 SQLite 默认 `NO ACTION`，不再声明 `ON DELETE SET NULL`；
- migration 047 与 clean-database `schema.sql` 必须完全一致；
- 直接删除仍被引用的 Item 必须被拒绝；
- 删除账号时，Item member、ContentGroup、Item 与 Relation 全家必须可靠级联清零，不依赖 SQLite 子表处理顺序。

### R2. Runner 级回滚收据

- 失败注入必须经 `runMigrations` 执行 migration 047；
- 失败后五张 Item / Relation floor 新表均不存在；
- `db_migrations` 不得留下 047 收据；
- 六张退役表、旧 `content_group_members` 形状及原始数据必须完整保留。

### L1. 回执语言

Review 只描述“依赖 runner 既有的逐迁移事务包裹”，不得把 2026-03 已存在的能力写成本补丁新增能力。

## 3. 施工顺序

1. 先补外键动作、账号级联与 runner 回滚断言；
2. 运行专项测试，确认旧实现至少被外键动作断言击红；
3. 修改 migration 047 与 `schema.sql`；
4. 重跑专项与完整验证门；
5. 更新 V2.BN.11.2 Review、V2.BN.11 主计划状态和 handoff Result。

## 5. Definition Of Done

- R1 与 R2 均有行为测试，不只依赖 DDL 文本检查；
- migration 047 与 clean schema 的外键动作一致；
- 失败迁移不留下 schema、退役表删除或收据残片；
- 账号级联 fixture 真实包含 `kind='item'` 的 ContentGroup member；
- handoff 标记 `done` 并附验证数字，但不自签第三方 PASS。
