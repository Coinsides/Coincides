# V2.BN.11.3 Plan - Item Lifecycle And Human Claiming

> **状态 (Status)**: engineering complete after V2.BN.11.3.1; awaiting third-party re-review
> **日期 (Updated)**: 2026-07-13
> **层 (Layer)**: 执行计划 / Release Plan
> **权威 (Authoritative)**: 否；范围服从 `V2.BN.11-plan.md` 与 Relation / Item 概念设计 v1.1

## 1. 本小版本只解决什么

V2.BN.11.3 把 migration 047 已经落库的 `items / item_snapshots / item_anchors` 从静态骨架变成第一条可用纵切：

```text
现有 Block / ContentRange
  -> ContentGroup-scoped 原料 Anchor
  -> 人工选择一条或多条 Anchor
  -> 单事务铸成 Item 并留下 claimed receipt
  -> 通过 Package B 把 Item 身份挂入 ContentGroup
  -> Item 可独立检查、编辑与退役
```

本版不实现 Relation、Purpose 的 Item membership、Graph / RAG、AI 批量收料，也不把 Item 正文复制进 ContentGroup member。

## 2. 必守不变量

1. `Item` 的正文真相住 `body_json`，`plain_text` 是同次写入生成的检索 / 哈希投影。
2. 每次正文发生变化，都按 `plain_text` 生成或复用 `item_snapshots`；格式抖动不能制造伪漂移。
3. active Item 不得带 successor；退役只能通过专门命令完成。
4. successor 禁止自环和循环；旧 Item 只软退役，不开放硬删路由。
5. `item_anchors` 只有池态与认领态：认领后必须清空 pool 坐标并写入 `claimed_at / claimed_by`。
6. Anchor 是使用收据，不是 canonical fragment；同一 Source / target 可被多个 Item 分别使用。
7. target、Source、Note、Project 消失时，Item 与 Anchor excerpt 仍然存活；可空 origin / source receipt 诚实降级。
8. 铸卡事务中 Item、Snapshot、Anchor 必须全成或全退。
9. 所有服务查询都按 `user_id` 限域；不存在跨用户读取、修改或认领。
10. Item 加入 / 移出 ContentGroup 只改 Package B 成员边，绝不删除或复制 Item 真相。

## 3. 施工纵切

### 3.1 RED - 领域契约

- Item create / read / update / retire / successor；
- snapshot hash 与正文更新去重；
- active-with-successor、self-loop、successor cycle 拒绝；
- pool collect / list / discard、单 Anchor 快铸、多 Anchor 融铸；
- same-source multi-use；
- `after_item_insert`、`after_anchor_claim` 故障注入与事务回滚；
- target / Source / Note / Project 删除后的 receipt survival；
- cross-user read / write / claim 拒绝；
- Item 无硬删 route contract；
- ContentGroup 移除 Item member 不删除 Item。

### 3.2 Server - 单一领域入口

- 新建 `services/items.ts`，集中正文规范化、快照、生命周期、池与 cast 事务；
- 新建 `routes/items.ts` 与严格 Zod schemas；
- 挂载 `/api/items`；
- pool v1 只接受 `pool_scope_kind = content_group`；
- Block / ContentRange 收集时复制 `note_block_sources.source_record_id`，后续永不同步。

### 3.3 Client - 最小人工入口

- 新建 Item repository 与 DTO；
- ContentGroup Rail 的展开区域提供“收集当前选择”；
- 池内支持单选快铸和多选融铸；
- cast 成功后通过 Package B 添加 `{ kind: 'item', item_id }`；
- 最小 inspector 显示正文、type、topic、origin、Anchor receipts，并支持编辑、退役和仅移出当前 Group。

这只是存在性地板，不把 Rail 做成最终 Item 工作台，也不提前设计全局 Item Library。

## 4. 验证门

```text
cd server && npm run test:v2
npm run check:v2-bn11-legacy-shutdown
npm run verify:v2-bn8-runtime
git diff --check
```

UI 改动另做一次浏览器 smoke：至少真实完成“选择内容 -> 收集 -> 快铸 / 融铸 -> 检查 -> 移出 Group”，并确认 Page / Canvas 两种模式不被 Rail 状态污染。

## 5. 退出条件

- 人类可以从当前 Note 的既有内容铸成真实 Item；
- Item 与 Anchor 两态、快照、successor、用户隔离均有行为测试；
- Source 与 Item 双向编辑互不改写；
- 删除来源或组织边不抹掉 Item；
- 客户端保存 ContentGroup 后 `kind = item` 完整 roundtrip；
- 所有必跑门通过，Review 明确剩余 UX 风险与 11.4 接缝。

## 6. 实施结果（2026-07-13）

- Item 生命周期、Snapshot、Anchor pool 与人工铸卡纵切已落地；
- ContentGroup Package B 已接入最小 Rail 操作面，Item 真相不复制进 member；
- 浏览器真实走通“收集 -> 快铸 -> 检查 / 编辑 -> 退役 -> 移出 Group”，并验证移出组织边后 Item 仍存活；
- 经 V2.BN.11.3.1 修正后，全量 server V2 测试 224/224 通过，`verify:v2-bn8-runtime`、legacy shutdown、client/server build 与 diff/secret 门均通过；
- 工程证据与剩余边界见 `V2.BN.11.3-Item-Lifecycle-And-Human-Claiming-Review.md`。
- 第三方 R1-R4 修正证据见 `V2.BN.11.3.1-Item-Lifecycle-Review-Fixes-Review.md`。
