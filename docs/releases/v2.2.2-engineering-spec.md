# v2.2.2 Engineering Spec - Exclusion / Conflict / Recovery

**Created**: 2026-05-21
**Updated**: 2026-05-21
**Status**: Implemented

---

## 1. Implementation Boundary

v2.2.2 adds reversible reconciliation safety state on top of v2.2.1 Evidence Sets.

It implements:

- exclusion records;
- conflict review records;
- recovery event records;
- material reconciliation apply decisions for `excluded` and `mark_conflict`;
- minimal Course Detail safety controls and summary.

It does not implement canonical truth, source deletion, note rewrite, source ranking, Source Viewer, Source Board, or Canvas.

---

## 2. Migration


The migration creates:

```text
excluded_material_scopes
conflict_review_items
reconciliation_recovery_events
```

`server/src/db/schema.sql` must mirror the migration for fresh DB initialization.

---

## 3. Apply Contract

`POST /api/proposals/:id/apply` passes request body into `material_reconciliation` apply.

Allowed `group_decisions[].decision`:

```text
accepted_evidence_set
kept_separate
deferred
excluded
mark_conflict
```

Behavior:

- Empty decisions keep v2.2.0 review-shell behavior.
- `accepted_evidence_set` keeps v2.2.1 EvidenceSet behavior.
- `kept_separate` and `deferred` create decision rows only.
- `excluded` creates a material reconciliation decision and one active `excluded_material_scopes` row.
- `mark_conflict` creates a material reconciliation decision and one open `conflict_review_items` row.
- Unknown group ids fail before any write.
- Unsupported decision values fail before any write.

## 4. Safety Routes

Add route module:

```text
server/src/routes/reconciliation.ts
```

Register it under:

```text
/api/reconciliation
```

Routes:

```text
GET /api/reconciliation/safety?course_id=...
POST /api/reconciliation/exclusions/:id/restore
POST /api/reconciliation/conflicts/:id/resolve
POST /api/reconciliation/conflicts/:id/reopen
```

Rules:

- All routes are user-scoped.
- `course_id` is required for safety list.
- Restore exclusion only changes `active -> restored`.
- Resolve conflict changes `open | deferred -> resolved`.
- Reopen conflict changes `resolved | dismissed | deferred -> open`.
- Each state change writes one `reconciliation_recovery_events` row.
- Recovery events are audit records, not full database rollback.

---

## 5. UI Contract

Course Detail remains the only UI surface for v2.2.2.

Reconciliation proposal group actions:

```text
Accept evidence
Keep separate
Defer
Exclude
Mark conflict
```

Safety summary in Course Material workspace:

```text
Active exclusions
Open conflicts
Recent recovery
```

The summary must allow:

- restoring active exclusions;
- resolving open conflicts;
- reopening visible non-open conflict records when available in the safety response.

User-facing copy must clarify:

- exclusions do not delete material;
- conflicts do not decide truth;
- recovery restores state only;
- stronger merge remains out of scope.
