# V2.BN.0 Engineering Spec - Foundation Inventory And Docs Alignment

## Contract

V2.BN.0 is a docs-only alignment version. It creates no product behavior and must not modify runtime code, migrations, APIs, routes, build config, or UI components.

## Active Reference Boundary

The active Better Notebook references are:

- `PRODUCT.md`
- `docs/Coincides-Better-Notebook-Roadmap.md`
- `docs/Coincides-Relation-Product-Design.md`
- `docs/brainstorm/BetterNoteBook Research/Better-Notebook-UX-Inventory-and-Interaction-Contract.md`
- `docs/brainstorm/产品完善/product-improvement-issue-register.md`

These documents guide V2.BN.x planning. Historical release docs remain evidence and should not be rewritten.

## Required Doc Updates

Top-level active docs must be aligned as follows:

- `docs/PRD.md`: product direction, users, goals, non-goals, success criteria, and Better Notebook readiness.
- `docs/ARCHITECTURE.md`: current substrate, Coincides Core truth, projection surfaces, adapters, operation/proposal safety, and future boundaries.
- `docs/DATA_MODEL.md`: conceptual Better Notebook object model, including truth/projection/source/relation/template/package/adapter distinctions.

## New Internal Planning Docs

- `docs/internal/Better-Notebook-Phase-Plan-Template.md`
  - required structure for future `V2.BN.x` version plans.
- `docs/internal/Better-Notebook-Implementation-Reality-Check.md`
  - current code reality snapshot and Better Notebook gaps.

## Verification

Required verification:

- `git diff --check`
- changed-file secret scan

No server/client test or build is required unless code files are accidentally changed.
