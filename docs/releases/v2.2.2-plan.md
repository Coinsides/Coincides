## 1. Goal

v2.2.2 extends the v2.2.1 Evidence Set layer with the safety mechanisms required before reconciliation can become stronger.

The goal is to let a user mark reconciliation candidates as excluded, mark conflict cases for review, and recover or reopen those safety states through auditable events.

Core product rule:

```text
exclusion / conflict / recovery = reversible safety state
exclusion / conflict / recovery != deletion, canonical truth, or note rewrite
```

Henry's subjective acceptance remains deferred to the v2.2.x batch acceptance pass. v2.2.2 only requires Codex-side quality verification and lightweight usability review.

## 3. Data Model

Add migration:

```text
server/src/db/migrations/018_v2_reconciliation_safety.ts
```

Mirror the migration in:

```text
server/src/db/schema.sql
```

New additive tables:

```text
excluded_material_scopes
conflict_review_items
reconciliation_recovery_events
```

### excluded_material_scopes

Represents a reversible user exclusion scope.

Fields:

- `id`
- `user_id`
- `course_id`
- `scope_type`: `source_material | source_fragment | material_segment | evidence_set | candidate_group`
- nullable scope ids:
  - `source_material_id`
  - `source_fragment_id`
  - `material_segment_id`
  - `evidence_set_id`
  - `proposal_id`
  - `group_id`
- `reason`
- `status`: `active | restored`
- `source_proposal_id`
- `source_decision_id`
- `metadata`
- timestamps

### conflict_review_items

Represents a conflict that needs later human judgment.

Fields:

- `id`
- `user_id`
- `course_id`
- `proposal_id`
- `group_id`
- `evidence_set_id`
- `conflict_kind`: `contradiction | version_mismatch | scope_ambiguity | source_disagreement | other`
- `status`: `open | resolved | deferred | dismissed`
- `title`
- `summary`
- `severity`: `low | medium | high`
- `metadata`
- timestamps

### reconciliation_recovery_events

Represents auditable recovery or state-change events.

Fields:

- `id`
- `user_id`
- `course_id`
- `event_type`: `restore_exclusion | reopen_conflict | dismiss_conflict | supersede_evidence_set | restore_evidence_set`
- `target_type`: `excluded_scope | conflict_item | evidence_set | decision`
- `target_id`
- `previous_status`
- `next_status`
- `reason`
- `operation_batch_id`
- `metadata`
- timestamps

## 4. API / Contracts

Extend:

```text
POST /api/proposals/:id/apply
```

For `type = material_reconciliation`, `group_decisions` allows:

```text
accepted_evidence_set
kept_separate
deferred
excluded
mark_conflict
```

Apply behavior:

- `accepted_evidence_set`: keep v2.2.1 behavior, creating EvidenceSet + EvidenceItems.
- `kept_separate`: create decision only.
- `deferred`: create decision only.
- `excluded`: create decision + `excluded_material_scopes`.
- `mark_conflict`: create decision + `conflict_review_items`.
- Empty `group_decisions` remains v2.2.0 review-shell compatibility.
- Unknown group ids fail the entire apply transaction.
- Already resolved proposals remain non-reapplicable.

Add routes:

```text
GET /api/reconciliation/safety?course_id=...
POST /api/reconciliation/exclusions/:id/restore
POST /api/reconciliation/conflicts/:id/resolve
POST /api/reconciliation/conflicts/:id/reopen
```

Route behavior:

- safety list returns active exclusions, open conflicts, and recent recovery events for the course.
- restore exclusion sets `excluded_material_scopes.status = restored` and writes a recovery event.
- resolve conflict sets `conflict_review_items.status = resolved` and writes a recovery event.
- reopen conflict sets `conflict_review_items.status = open` and writes a recovery event.

## 5. UI / Experience

Use Course Detail minimal UI. Do not create a separate review page.

In the existing reconciliation proposal panel, add group actions:

```text
Accept evidence
Keep separate
Defer
Exclude
Mark conflict
```

In the Course Material / Proposal workspace, add a compact safety summary:

```text
Active exclusions
Open conflicts
Recent recovery
```

Minimum interactions:

- select `Exclude` for a group and apply;
- select `Mark conflict` for a group and apply;
- restore an active exclusion;
- resolve an open conflict;
- reopen a resolved conflict if it appears in the recent/recoverable list.

Required product language:

- exclude does not delete material;
- conflict does not decide truth;
- recovery is a state restoration action, not a full database rollback;
- stronger merge remains out of scope.

## 6. Test Matrix
