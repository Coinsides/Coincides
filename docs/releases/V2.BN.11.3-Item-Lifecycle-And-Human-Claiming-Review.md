## 1. 结论

V2.BN.11.3 已在锁定边界内工程完成。migration 047 的静态 Item 地板现在具备真实生命周期、Snapshot、Anchor pool、人工快铸 / 融铸与 ContentGroup Package B 最小操作面。Item 正文不复制进 ContentGroup member，移除组织边不会删除 Item，来源收据失效也不会抹掉已经认领的知识真相。

本文是供独立复验使用的工程证据，不自签第三方 PASS。

## 2. 已交付纵切

- `items`：create / read / update / retire / successor，拒绝 active-with-successor、自环与 successor cycle；不开放硬删路由；
- `item_snapshots`：正文写入时生成 SHA-256 快照，`body_json` 是正文真相，`plain_text` 是同次生成的投影；
- `item_anchors`：ContentGroup-scoped pool 支持收集、列出、丢弃、单 Anchor 快铸和多 Anchor 融铸；
- cast transaction：Item、Snapshot 与 Anchor claim 全成或全退，并覆盖 Item insert 后、Anchor claim 后两处故障注入；
- receipt survival：target、Source、Note、Project 删除后，Item 与 Anchor excerpt / locator 仍可读取；
- Package B：ContentGroup member 只保存 `item_id`，支持加入 / 移出而不复制或删除 Item；
- Rail 最小入口：收集当前选择、选择 Anchor、铸卡、检查 / 编辑 / 退役 Item、仅移出当前 Group，以及 Group edge 写回失败后的显式重试。

## 3. RED / GREEN 与集成修正

专项契约先以失败测试锁定 Item 生命周期、事务回滚、用户隔离、receipt survival 与 Package B 删除边界，再落最小实现。浏览器 smoke 另外暴露并修正三处真实集成问题：

1. clean schema 在 migration 047 重建旧表前提前创建 Item member 索引，导致已有数据库启动失败；索引现在只由 047 在正确时点创建，并有启动回归测试；
2. ContentGroup GET 可能返回空 `canvas_id`，但 PUT validator 拒绝该值；读写契约已统一并有 roundtrip 回归测试；
3. ContentGroup 保存回调吞掉失败，Rail 无法展示 Item 已生成但组织边未写回的恢复状态；保存结果现在显式传播，UI 会保留 durable Item 并提供重试。

## 4. 浏览器体验证据

真实浏览器旅程完成：打开 Groups Rail，展开 ContentGroup 的 `Item tools`，选择未认领 Anchor，快铸 Item，检查两个 linked Items，编辑正文并观察 Snapshot hash 更新，退役 Item，再把它移出当前 Group。API 复核表明移出后 Item 仍以 `retired` 状态独立存在。

该入口默认折叠，没有把 Rail 扩张成最终 Item Library；Page / Canvas 主编辑面未因 Item tools 状态发生结构性变化。

## 6. 剩余边界

1. 一个 Block 存在多条 Source receipt 时，v1 收集路径只复制当前推导出的最新 `source_record_id`；更精细的多来源选择不在本版。
2. `content_range` Anchor v1 需要可定位的 `block_id`，不承担任意跨 Block range 的最终模型。
3. Rail 是最小人工入口，不是全局 Item Library、批量治理台或最终 inspector。
4. cast 与 ContentGroup 全量保存跨越两个请求边界。Item 先成为 durable truth，Group edge 写回失败时当前会话可重试；跨刷新恢复与全局 Item 检索留给后续工作台。
5. V2.BN.11.4 必须继续保持 Item truth 与 Purpose membership / compiled read model 分离，不能把派生成员反写成伪真相。
