# v2.2.3 Engineering Spec - Role-aware Reconciliation

**Created**: 2026-05-21
**Updated**: 2026-05-21
**Status**: Implemented

---

## 1. Implementation Boundary

v2.2.3 enriches `material_reconciliation` proposals with learning-role and template hints.

It implements:

- deterministic role inference;
- template hint mapping through the existing v2.1.1 registry;
- safety-aware group warnings from active exclusions and open conflicts;
- EvidenceSet metadata preservation for role-aware accepted groups;
- minimal Course Detail role/safety display.

It does not implement canonical truth, note rewriting, source deletion, source ranking, Source Viewer, Source Board, Canvas, or external model/provider changes.

---

## 2. Data Model

No migration is required by default.

Role-aware data is stored in proposal JSON and copied into `evidence_sets.metadata` when a group is accepted.

Candidate group extension:

```text
learning_role_candidates
template_candidates
role_confidence
role_warnings
blocked_by_safety
safety_reasons
```

---

## 3. Role Inference

Use deterministic heuristics over candidate group headings, excerpts, and evidence reasons.

Seed learning roles:

```text
definition
theorem
proof
formula
example
exercise
answer
warning
concept
note
```

Fallback behavior:

- if a role is weak or unknown, use `note`;
- weak fallback must add a role warning;
- role hints are advisory and must not become truth records.

Template mapping uses existing v2.1.1 template ids:

```text
definition.basic
theorem.basic
proof.basic
formula.math
example.general
exercise.general
answer.general
warning.callout
concept.basic
text.paragraph
```

---

## 4. Safety Context

Before proposal data is stored, candidate groups must be checked against current course safety state.

Blocking inputs:

- `excluded_material_scopes.status = active`
- `conflict_review_items.status = open`

Rules:

- active exclusion matching the same proposal/group or matching a group evidence scope marks the group blocked;
- open conflict matching the same proposal/group marks the group blocked;
- active exclusion/open conflict matching evidence source ids adds a safety warning;
- restored/resolved rows are not blocking.

---

## 5. Apply Contract

Existing material reconciliation apply remains unchanged except accepted EvidenceSets preserve role-aware metadata.

`accepted_evidence_set` stores role fields under `evidence_sets.metadata`.

`kept_separate`, `deferred`, `excluded`, and `mark_conflict` keep existing behavior.

Empty apply body remains review-shell-only.

---

## 6. UI Contract

Course Detail proposal review should show:

- existing reconciliation kind;
- likely learning role label;
- likely template label;
- role confidence;
- role warnings;
- safety-blocked warning if present.

The UI stays compact and functional. No new review workbench is introduced.
