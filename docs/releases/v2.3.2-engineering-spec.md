# v2.3.2 Engineering Spec - Source Scope Selection

**Created**: 2026-05-22
**Updated**: 2026-05-22
**Status**: Implemented

---

## 1. Implementation Boundary

v2.3.2 adds SourceScopes as a reusable selected-source layer over SourceSnapshots, SourceAnchors, SourceMaterials, and MaterialSegments.

It implements:

- additive SourceScope table;
- scope create/list/detail/update/archive/restore/jump APIs;
- Course Detail source page/page-range selection;
- proposal creation narrowed by selected scope ids.

It does not implement Source Board, annotation editing, PDF rendering, manual text offsets, or Canvas.

## 3. API Behavior

Routes:

```text
GET /api/source-scopes?course_id=...&status=...
POST /api/source-scopes
GET /api/source-scopes/:id
PUT /api/source-scopes/:id
POST /api/source-scopes/:id/archive
POST /api/source-scopes/:id/restore
GET /api/source-scopes/:id/jump-target
```

Creation rules:

- `page` and `page_range` require `source_snapshot_id`.
- `anchor` requires `source_anchor_id`.
- `source_material` requires `source_material_id`.
- `material_segment` requires `material_segment_id`.
- All referenced rows must belong to the authenticated user and course.
- `page_end` defaults to `page_start`.

---

## 4. Proposal Behavior

Proposal creation accepts:

```json
{
  "source_scope_ids": ["scope-id"]
}
```

Resolution rules:

- Active scopes are converted to existing proposal inputs: `document_ids`, `source_material_ids`, `segment_ids`, and scope metadata.
- Archived scopes are rejected.
- Scope ids from another course/user are rejected.
- Proposal JSON records `source_scope_ids` and `scope_summary`.

---

## 5. UI Behavior

- Source Snapshot page sections can create page scopes.
- Users can set a range start and range end from visible page sections.
- Selected SourceScopes are listed in Course Detail.
- Users can archive, restore, and jump back from a scope.
- Proposal creation uses active selected scopes if any exist.
