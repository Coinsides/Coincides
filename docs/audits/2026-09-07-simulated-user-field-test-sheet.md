# Coincides 模拟用户实地测试单

**用途：让评测者带着有限耐心完成真实任务，把难找、难点、难拖、难读、难修改的地方留下可复现证据。**

评测对象包括首次生成，也包括生成之后的人手调整、选区操作、Agent 局部或全局修改、反悔和再次打开。修改轮数本身不扣分；重复劳动、反复解释、意外变化和难以恢复才是问题。

这是随版本复用的现场工作表。每次复制“本轮登记”“逐步记录”和“问题卡”填写；原始记录保留，修复后另开复测记录。

## 1. 一轮测试怎么走

1. **登记版本、目标和环境**，声明本轮实际支持的能力及素材；给每个原子操作一个编号。
2. **按可见界面首次试用**，逐步记录，在耐心预算内完成或停在卡点。
3. **封存首次结果**：保存关键截图、用户原话、动作、实际结果及原有作品状态。
4. **进入诊断**：必要时查源码、日志、API、数据或性能记录，区分产品问题、工具故障与未实现能力。
5. **形成优化条目**：写清影响、证据、原因确认程度和建议；待进入相应工程任务后修改。
6. **按原条件复测**，检查卡点及受影响的相邻操作，保留修前与修后两份结果。

### 首次试用的条件

- 只给评测者用户会知道的材料、需求和可见界面；适合由未读实现细节的评测者执行。
- 通过 Computer Use 的截图、真实指针与键盘操作完成任务。不得用隐藏 API、DOM 直接触发、数据库编辑或外部脚本补齐产品流程。
- 通用快捷键可以使用；应用特有的隐藏快捷键不能凭源码知识猜出。首次从哪个入口发现它，要记下来。
- 测试数据可预先准备，但须声明准备方式。用 API 预置素材，不构成“上传流程已通过”。
- 一次系统性的控件专项测试，与“第一次找入口”分开记；已知道入口后反复测试，不再声称验证了首次可发现性。
- 后续需要提示、绕路或工程介入时，标记“辅助后结果”，不能覆盖首次成绩。

### 对施工现场的处理

- 只对本轮已提供的功能评价使用体验。尚未实现的能力标“未实现”；本轮表面不支持的操作标“不适用”。
- **找不到入口只能先证明“未找到”，不能直接证明“尚未实现”。** 后者在诊断阶段核实。
- 若诊断后确认是未实现能力或工具故障，保留首次 H 等原始观察，追加归因；汇总时从产品摩擦评分分母和产品体验优化项中排除，另列能力覆盖缺口或工具事件。原因未明者单列“待诊断”，不强行算作产品缺陷。
- 页面、现有画布、未来独立板分别登记；不要求所有表面支持相同动作。例如只提供缩放档位的纸面，不因没有自由捏合缩放而扣分。
- 一个阶段卡住后，下游相关步骤标“未测／被前置阻断”。若用预置数据继续测独立步骤，注明新起点，不计整条旅程完成。

## 3. 操作摩擦 rubric 与耐心预算

### 3.1 评分单位

一个评分单位是**一个清楚的用户意图**，例如“找到拖拽入口并移动这张卡”“选中两张卡”“回到适合页宽”。复杂旅程拆成多个意图分别记分；一个用例包含多个动作时，现场表分行记录，不把整个用例共用一个停止预算。

只计算相对任务必要步骤的**额外负担**：错误入口、无效尝试、回退、重复说明、重新选择和补救。正常输入需求、拖动多个对象或做必要选择不扣分。任务固有步骤过多可以另记流程设计问题，不能只用原始点击总数判难用。

**一次失败探索及其返回算一个摩擦事件**，不能把同一次误入、未找到和回退重复计数。累计次数只针对当前原子意图；用例要求的正常重复操作（如缩放往返）不算失败尝试。

### 3.2 E / M / H

| 级别 | 观察标准 | 记录与处理 |
|---|---|---|
| **E · Easy** | 在首个合理入口完成；无错误路径、无无效重试；目标和结果可确认 | 通过此原子操作；仍记录结果 |
| **M · Medium** | 一次误入、回退或无效尝试后独立完成；没有破坏先前工作 | 记录额外成本；同类摩擦在多个步骤重复出现时列入优化候选 |
| **H · Hard** | 累计至少两个摩擦事件；或需要提示、重复交代已明确的要求、额外修补才能继续；或耗尽预算仍未完成 | 封存卡点，进入诊断，不继续无限探索 |
| **— · 未评** | 未进入有效试用，或工具故障使产品表现无法判断 | 必须写原因；不算 E，不伪装成已通过 |

**误改目标、丢失内容、覆盖明确要求保留的修改、恢复失败：立即记录阻断项。** 不能因步骤少就评 E，也不能用其他步骤顺畅抵消。尚未确认是产品原因时写“待诊断”，不提前归责。

### 3.3 默认停止预算（试行）

- **寻找入口：最多 2 个有依据的位置，包括首选。** 每检查一个位置，简记为何认为入口可能在此。第二个位置找到至少为 M；两处都未找到，记 H、未完成、原因待诊断，不继续找第三处。
- **执行动作：同一明确意图最多尝试 2 次，包含首次。** 第二次成功至少为 M；两次都失败，记 H 并停止该步骤。改一种操作方式继续试也计入预算。
- 两类预算和累计摩擦同时生效，先到者先停。例如误入一次、随后动作失败一次，已达到 H，不能再把第二次执行机会当作继续探索的理由。
- 请求外部提示或绕路前先封存首次结果；此后另计辅助次数与结果。
- 经证据确认的自动化工具故障单独记，不扣产品分。恢复工具后的尝试另起记录；未能区分原因时停止并标待诊断，不能不断重试直到成功。
- 生成等待上限在“本轮登记”填写；超时先记录应用是否有反馈、是否仍在运行，再停止等待或进入诊断，不静默无限等候。

阈值是首轮假设，不是行业标准。校准时写明新旧版本及原因，下一轮生效；不为美化成绩回改首轮评分。

### 3.4 时间与“丝滑”

- 可测时分别记**应用输入至首个可见反馈**、**至最终稳定结果**的时间，以及卡顿、跳动和无反馈现象。
- 没有可用计时证据就写“未测”，只描述观察；模型思考、截图传输和工具调用的等待不等于用户操作耗时。
- 点击成功不证明目标好点，拖动成功不证明跟手。另看命中区域、落点、视口跳动、掉帧及操作反馈；长期疲劳和个人舒适度留给 Henry 的体感补充。

## 5. Item、拖拽、缩放与画布专项

**先区分三个量：** 系统／浏览器显示缩放、应用视口缩放、对象尺寸调整（resize）。本专项一次只改变其中一个量，其余记录并固定。缩放是改变观看倍率；resize 是改变对象尺寸，可能合法触发文字重排。

| ID | 实际动作 | 观察点与对照 |
|---|---|---|
| C-01 | 首次打开含 Item 或卡片的笔记，寻找移动入口 | 拖拽按钮是否难找、过小或仅在难以发现的悬停状态出现；有无提示；按入口预算记首次成绩 |
| C-02 | 在专项轮分别观察正文、边缘、拖拽柄的交互反馈，再尝试对应动作 | 可拖区域、可编辑区域、resize 手柄能否区分；是否误进编辑、误选文字或误改尺寸；这轮不冒充首次发现测试 |
| C-03 | 把一个对象拖到明确目标，放下；再试一次取消拖动 | 预览与最终落点是否一致；是否跳动、吸附过强、遮住参照；取消能否保留原位置；记录想放哪与实际落哪 |
| C-04 | 在可见区域边缘或较密对象附近完成一次移动 | 是否被侧栏或悬浮控件挡住；平移、滚动与拖动物体是否冲突；出视口后是否容易找回；不强制要求未承诺的自动滚屏 |
| C-05 | 依次单选、增加选择、框选、取消选择，再重新选中目标并移动 | 选中集合是否符合画面预期；嵌套对象、遮挡对象是否难以选对；能否分清选字、选对象与平移；未选对象不应被误动 |
| C-06 | 使用现役入口放大、缩小，返回常用阅读档位 | 按钮与快捷方式是否可发现；步幅和缩放中心是否可预测；是否容易放过头、迷失位置；支持哪些方式就测哪些 |
| C-07 | 在缩放过程中盯住一个目标，再继续编辑或移动它 | 目标是否突然跑出视野；视口是否非预期跳动；缩放操作是否意外变成页面滚动或对象 resize |
| C-08 | 在小、常用、大倍率下观察正文、公式、图像与细边框 | 分别记文字模糊、公式锯齿、图片像素化、线条粗细异常；先区分原始低分辨率素材、截图缩放和应用渲染，不统称“失真” |
| C-09 | 对照视口缩放前后的文字换行、行高、对象间距和溢出 | 仅改变视口是否意外改变内容布局；按该表面的真实布局约定判断；对象 resize 或明确的响应式重排另记，不能混为缩放缺陷 |
| C-10 | 在各倍率下点击同类小按钮、选择文字，再拖动同类手柄 | 画面位置与实际命中位置是否错位；看得见却点不中、选区覆盖偏移、手柄脱离对象分别记录 |
| C-11 | 放大或缩小后重复一次 C-03 与 C-05 | 检查鼠标轨迹与对象位移是否比例异常，框选结果是否改变；本轮截图与坐标必须新取，不能复用另一倍率的坐标 |
| C-12 | 单独调整对象宽高，再恢复尺寸 | resize 入口是否可发现；预览、最小尺寸、长宽比及内容重排是否可理解；不应无意变成视口缩放；图片拉伸是否来自未说明的比例规则 |
| C-13 | 常用倍率 → 放大 → 缩小 → 回原倍率，连续往返 3 次 | 同倍率下比较清晰度、换行、对象位置和间距，有无累计漂移；待画面稳定再取证；示例倍率只取本版本实际支持的值 |
| C-14 | 完成移动和 resize，正常保存后刷新或重新打开 | 内容与对象几何是否保留；视口位置和倍率是否恢复按已有产品约定检查，不能自行要求所有视图状态持久化 |

### “缩放后失真”问题卡必须选类

- **清晰度**：文字／公式模糊、图像像素化、线条异常。
- **布局**：非预期换行、间距变化、遮挡、溢出。
- **几何**：对象位置或宽高变化、缩放往返累计漂移。
- **命中**：按钮、文字选区、拖拽手柄与可见位置不一致。
- **视口**：缩放中心不明、目标丢失、跳动、难以回到阅读状态。

注明浏览器缩放、系统显示缩放和应用倍率。至少保留开始倍率、异常倍率、回到开始倍率的截图。像素级测量与性能采样放在诊断阶段；不同尺寸的工具截图不能直接证明应用失真。

## 6. 多轮生成、人工整理与 Agent 修改旅程

仅在**面向用户的 Agent 入口**可用时执行生成相关步骤。MCP 或脚本生成的替代结果不能证明此旅程已打通。人工步骤可以用预置笔记独立测试，但须注明起点。

下列话术为可替换样本：保留“初稿 → 人工改动 → 局部改动 → 全局改动 → 功能增减 → 恢复”的结构，按真实材料调整内容。未向 Agent 表达的偏好，不计为其初稿错误。

| ID | 用户动作或示例原话 | 必留证据与判据 |
|---|---|---|
| R-01 | “把选定材料整理成一篇给我自己复习用的短笔记。有简明目录、清楚的结论和能回看的出处；先给可读初稿，风格克制。” | 保存原话、素材范围与初始验收点；入口、提交、等待、生成落点是否清楚；无真实入口则未测 |
| R-02 | 阅读初稿，核对明确要求，挑出两处具体要修改的地方 | 保存初稿；逐项判实现度，区分遗漏要求、内容错误和后来才形成的偏好；不因初稿不完美而直接判流程失败 |
| R-03 | 手动移动两张卡、调整一张宽度，并改写一句文字 | 记录人工改动和“此后须保留”的清单；观察拖拽、resize、焦点与结果保存；建立后续修改的对照状态 |
| R-04 | 单选一个对象：“这张卡的说明改短，保留关键条件和出处，其他卡不动。” | 请求时的真实选区；目标是否唯一明确；正文改动符合要求，位置和其他对象保留 |
| R-05 | 框选两个对象：“只把这两张统一成浅色样式，正文、位置和尺寸保留。” | 保存选区截图、原话与两对象原状态；局部范围是否传到 Agent，是否误改未选对象 |
| R-06 | “整体改成更紧凑、层级更清楚的风格，但保留我刚才调整的位置和那句文字。若有冲突，先指出。” | 是否明确作用于整篇；是否保留人工劳动；冲突是否显露；用户是否被迫逐卡重申同一要求 |
| R-07 | “给指定卡加一个可折叠答案；去掉另一张卡的交互控件，保留其内容和出处。” | 按现役组件能力替换例子；增加、删除的作用范围与结果是否可见；支持不了时是否如实说明 |
| R-08 | “整体方向保留，但刚才改的那两张需要更醒目；其他地方不要再动。” | 局部偏好能否继续细化；是否反复重做已经满意的部分；明确说过的约束有没有遗忘 |
| R-09 | 从人类入口撤销最后一次修改，随后按需要重做或重新修改 | 能否恢复至本轮之前的内容、布局和手工改动；是否误撤更早的人工劳动；无恢复入口须记录 |
| R-10 | 正常保存、退出该笔记，再重新打开继续编辑；导出已支持的成品 | 内容、交互和出处是否保留；能否找回任务；导出与应用内的比例、内容和层级是否符合已承诺的格式行为 |

### 每轮单独记录三个维度

| 维度 | 记录方式 |
|---|---|
| **操作摩擦** | E / M / H / 未评；注明额外找路、重试、重复说明、重新选择及补救 |
| **本轮要求实现度** | 将明确要求拆成可观察项，逐项标“满足／部分满足／不满足／无法判断”；不凭印象报百分比 |
| **先前成果保留情况** | 对照保留清单，逐项标“保留／本轮明确允许改变／意外改变／无法判断”；意外改变独立立问题 |

初稿生成质量、界面可操作性与多轮修改可靠性不合并成一个总分。外部模型波动、素材质量、上下文不足与应用流程问题，在有证据前只列候选原因。

## 8. 从观察进入优化

- **每个 H 都留下原始证据并进入诊断队列**。确认属于产品操作摩擦后列入体验优化候选；未实现能力或工具故障按 §1 单列。封存首轮结果后再开展相应工程工作，不因评为 H 就立即改代码。
- **立即处理**：真实内容丢失、误改对象、明确保留项被覆盖、恢复失败，或现役核心流程无法继续。若原因未明，优先的是诊断与保留现物。
- **下一批**：可复现的 H、经常用到的入口或控件难操作、多个任务中重复出现的 M、明显遮挡与布局问题。
- **观察**：一次性现象、未复现的比例或清晰度异常、需要个人偏好确认的形式选择。记录触发条件与下次检查点。
- 不能用“按钮丑”“交互不自然”作为完整结论。指出哪个控件、在哪一步、造成什么阅读或操作负担，再给替代形式及对照理由。
- 首次记录、辅助后记录、修复后记录分别保留。复测使用相同材料、目标、表面和显示条件；改变了条件就声明。
- 真正需要 Henry 的重点是个人体感与取舍；评测者先交具体对照和证据。没有 Henry 的体验签收，报告不能代写“用户已满意”。

## 9. 本轮结束时的交付清单

- [ ] 本轮登记完整；已测、未测、不适用、未实现各自列明。
- [ ] 已执行步骤有动作与证据；没有拿 API 预置或辅助成功冒充用户流程通过。
- [ ] 产品摩擦 E/M/H 分布注明有效原子操作数量；未评、待诊断、未实现、工具故障和被前置阻断单列，不混分母；首次原始观察仍保留。
- [ ] 多轮修改逐项记录要求实现度与先前成果保留情况。
- [ ] 先列最多 3 个最影响使用的问题，附问题卡；其余进入候选清单。
- [ ] 区分现场观察、原因假设与已验证原因；注明工具故障及证据限制。
- [ ] 若有修复，原场景已复测；若未修复，只交基线，不声称优化完成。
- [ ] 需要 Henry 判断的事项给出具体画面或操作对照；其余可自行诊断的工作不转嫁给用户。
