## 附：对 G1 修法方向的意见（应 Main_Designer 11-08 短讯）

修法方向是：落地前发现焦点在框里，就这一拍不落、下一拍再看。读码看，有以下几个坑。

- **守卫要放在 `placeTyped` 里，对 `!live` 判，不要只放在重试拍（`C:194-198`）。** 留住的条目进 `placeTyped` 不止重试拍一条路，至少还有这几条：
  - 重开 `C:617`；
  - 输入法组字结束 `C:456`（`afterComposition` 回调直接调 `placeTyped`）；
  - busy 轮询 `C:458`；
  - 编辑器等待和替换中的轮询 `C:485`、`C:500`。

  其中组字结束这条最要紧：人在框里用输入法打字时，重试拍撞上组字就会挂一个回调，组字一结束就直接落地。这正是人正在框里写的时刻。只守重试拍，这条路漏掉。
- **焦点停在框里不走，字就永远不落。** 例如人点进框后离开，或者切到别的窗口——窗口失焦后 `document.activeElement` 仍然是框。这不丢字：有存档，也有 Discard。但 G4 的文案说「会自己回去」，这时又兑现不了。
  - 可以考虑改判「框里最近 N 秒有没有 input 或组字」，不判焦点。
  - 或者两者都判：落地时焦点若在框里，就把焦点交给落地后的编辑器（`editorFor(blockId, caretUnitId)`），光标放在落地位置。
- **跳过的那一拍不该让重试延时翻倍。** 走 `keep()` → `retryTimer` 会把 `retryDelay` 翻倍（`C:194`）。人在框里写久了，等人离开，可能要等满 `RETRY_MAX_MS` 才落。
- **同一类问题还有一处旁支**：`C:599-602` 重开时静默移除前一次挂载的框（A-25 的泄漏点）。若焦点正在那个旧框里，也会落到 body。同一笔记重新挂载、人又恰好在框里打字，这种情况罕见，可以并进 A-25 看。
- **3b 落地档和重开恢复不需要另守。** 两者都通过 `C:617` 进 `placeTyped`；守卫放在 `placeTyped` 里就一并盖住了。重开时框是 `focus: false`，第一拍通常不会撞上。
