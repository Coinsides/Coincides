Main_Designer 点名的五项：

1. **text_view 旧库（第一验）**：修前导入的 PDF、docx，页登记没有 `text_view`，冻结后拿修后服务端打开同一个库。默认原页、切换、文本视图（32 块、160 块）、12 个血缘标跳页、离开再回来仍是文本、刷新回原页，与修前逐项一致。

   - 另加「修后前端配修前后端」一臂（部署那一刻浏览器已是新前端、服务端还是旧登记），PDF、docx 照样有切换、能进文本，「缺省当有」成立。
2. **旧图片出生成按钮**：18/18，见上表。
3. **读不出尺寸**：造了三种能过入口、被认作图片、但读不出尺寸的文件——宽度写成 0 的 png、没有 SOF 的 jpeg、块不认识的 webp。
   - 三种都是：导入成功（materialized、native-image），笔记在，第 1 页失败。
   - 界面显示「Pages that could not be generated: 1」「This page could not be generated.」和「Try again」；点了仍失败，没有死路。
4. **builder 申报的两个缺口**：
   - webp 带 EXIF：造了两种写法。Chrome 不理会 webp 里的 EXIF 方向，照存储尺寸显示，所以读取器不读它在 Chrome 里没有可见后果，登记尺寸与显示一致。其他浏览器未核。
   - jpeg 的 SOF 高度为 0、靠 DNL 段给高度：本机没有能写这种文件的编码器，**未覆盖**。
5. **avif、乱码 png**：修后与修前完全相同。上传成功，入口判成「只存不读」，物化一直停在「received」，不出笔记，界面也没有提示。这是修前既有的表现。

### 〇.3 请 Main_Designer 裁定的发现（我判不挡）

1. **原页登记加载失败时，图片笔记是一页空白**。
   - 做法：在浏览器里让 `GET /sources/by-projection-note/:id/pages` 失败（500 和断网两种），取样 4、10、20 秒。
   - 图片笔记（修后）：始终空白，没有图、没有提示、没有重试按钮；放行后 4 秒仍不自动恢复，要刷新才行。
   - PDF：修前修后一样，静默退回文本视图，没有切换、没有提示。这是修前既有行为。
   - 回执写的是「登记加载失败时走原有的报错和重试路径」，但这条原有路径本身就不出任何提示，落到没有文本的图片笔记上，就成了一页什么都没有的空白。这与设计裁定「不留死路」、说明书素材「原页列表加载失败：显示原页加载失败和重试」都对不上。
   - 我判不挡：不丢数据，只在请求失败时出现，刷新即恢复，而且修前图片笔记一直是空白。建议说明书照实写，并给图片笔记的这条路记一个后续项。

### 〇.4 说明书素材要改的地方（逐句对过实测）

要改的：
1. 界面文字是英文。说明书引的中文按钮名与实际不同：
   - 实际是「Generate original page images」，生成前的说明是「Generate them to read it exactly as the original file lays it out.」；

2. 「原页列表加载失败：显示原页加载失败和重试」不成立，见〇.3 第 1 条。

4. 「手机拍的竖照片按相册方向显示」目前只对 jpeg 成立。webp 里的 EXIF 方向，Chrome 和应用都不理会。
5. 建议加一句已知：超宽全景图（例如 16000×300）缩到栏宽后只剩十几像素高，比例没错，但基本看不清。
6. 「图还在生成：短暂显示正在准备原页…」我没测到，生成太快。
