# v2.4 调研大纲 - Canvas、Relation Layer 与可重建知识工程

**Created**: 2026-05-22
**Status**: Draft for Henry review
**用途**: 作为 v2.4.1 开工前的系统调研清单，帮助决定 Canvas 引擎、Relation Layer、可重建工程包、开源工具采用策略，以及它们和 v2.5 Template / Package Studio 的衔接。

---

## 0. 调研总目标

v2.4 的重点不只是“做一个能拖拽的画布”。

真正要解决的是：

```text
如何让 NoteBlock / Source / Evidence / Proposal
被稳定投射到一个成熟 Canvas 上，
同时保留 Coincides 自己的数据主权、source 可信链、AI-readable relation layer，
并为未来 .coincides 工程包、模板引擎和领域知识包留好结构。
```

本轮调研要回答：

- 我们是否需要引入成熟 Canvas / graph / editor 工具；
- 哪些工具可以直接用；
- 哪些工具只能作为 adapter；
- 哪些工具适合 fork / 改编；
- 哪些工具只能作为产品或架构参考；
- 哪些能力必须由 Coincides 自己掌握；
- Relation Layer 如何成为 Coincides 与普通笔记软件的核心差异；
- 未来 `.coincides` 工程包如何重建内容、画布、来源、证据和关系。

## 1. 调研优先级

### P0: v2.4.1 开工前必须完成

- Canvas Engine / Whiteboard Engine
- Knowledge Graph / Relation Layer
- Open-source Adoption / Fork Feasibility
- NoteBlock / Relation Object Model

原因：

v2.4.1 要决定基础画布 viewer/editor 怎样做。如果没有完成这些 P0 调研，容易出现三个风险：

- 盲目自研，后续交互能力不足；
- 盲目接入第三方工具，导致 Coincides 数据模型被外部 store 绑架。
- 盲目把 NoteBlock 当成普通 editor block，导致 Relation / Canvas / AI-readable structure 的建模基础不稳。

### P1: v2.4.x 期间需要完成

- Diagram / Flowchart / Connector Editing
- AI-readable Knowledge Structure
- Project Package / Portable Knowledge Workspace
- Multi-view Projection / View Preset

原因：

这些方向会影响 v2.4.4 Canvas Edges + BlockRelation Seed、v2.4.5 Command & Interaction System、以及后续 `.coincides` 工程包。

### P2: v2.5 前需要完成

- User-customizable Template / Block / Style Engine
- Block Editor / Document Object Model

原因：

这些方向和 v2.5 Template Engine + Domain Block Sets + Package Studio 直接相关，但不应该抢 v2.4.1 的 Canvas 引擎决策。

## 2. 调研方向一：Canvas Engine / Whiteboard Engine

### 目标

判断 Coincides 是否应该：

```text
纯自研 Canvas
直接接入成熟 Canvas 库
使用成熟 Canvas 库作为 adapter 渲染层
fork / 改编成熟开源项目
```

### 重点对象

- tldraw
- Excalidraw
- AFFiNE Edgeless / BlockSuite
- Figma / FigJam 产品参考
- Miro 产品参考

### 必须研究的问题

- 支持哪些基础交互：
  - pan / zoom；
  - drag；
  - select；
  - multi-select；
  - box select；
  - resize；
  - snap / align；
  - undo / redo；
  - keyboard shortcuts。
- 支持哪些对象：
  - text；
  - image；
  - shape；
  - arrow；
  - connector；
  - frame；
  - group；
  - embed；
  - custom shape。
- 数据模型是否可控：
  - store 是什么；
  - shape 如何序列化；
  - session / camera state 如何分离；
  - 能否只保存 layout projection；
  - 能否避免把 NoteBlock / Source / Evidence 塞进第三方 metadata 里。
- 是否支持 adapter：
  - Coincides object -> canvas shape；
  - canvas shape event -> Coincides CanvasNode update；
  - canvas connector -> CanvasEdge / ObjectRelation；
  - external engine state 是否可降级或替换。
- 是否适合工程包：
  - 能否导出 engine snapshot；
  - engine snapshot 是否只能作为缓存；
  - 如果没有该 engine，`.coincides` 是否还能还原核心内容。
- license / runtime：
  - 个人使用；
  - 开源分发；
  - downstream 用户；
  - 是否需要 license key；
  - 是否有商用限制。

### 预期输出

```text
docs/brainstorm/v2.4-research/canvas-engine-reference.md
```

输出中必须给出：

```text
Recommended for v2.4.1:
  self-build / tldraw adapter / Excalidraw adapter / fork / postpone
```

## 3. 调研方向二：Knowledge Graph / Relation Layer

### 目标

研究 Coincides 的 Relation Layer 应该如何设计，使它不只是画布上的线，而是可切换、可隐藏、可提取、可供 AI 读取的知识结构层。

### 重点对象

- Obsidian Graph / Canvas
- Logseq Graph
- Roam Research 思路
- Tana
- Heptabase
- TheBrain
- Kumu / Graph Commons
- Cytoscape.js
- React Flow
- Sigma.js
- AntV G6
- GraphRAG / knowledge graph construction 相关实践

### 必须研究的问题

- 节点是什么：
  - note；
  - block；
  - concept；
  - source；
  - evidence；
  - topic；
  - page；
  - tag。
- 边是什么：
  - explicit user link；
  - AI suggested link；
  - source support；
  - derivation；
  - prerequisite；
  - example-of；
  - contradiction；
  - reading-order；
  - topic membership。
- 是否支持多 relation layer：
  - 用户可见主干层；
  - AI hidden reading layer；
  - source evidence layer；
  - formula derivation layer；
  - topic-specific layer；
  - suggested relation layer；
  - user-defined layer。
- 是否支持子图抽取：
  - 给我所有三角函数相关内容；
  - 给我所有 Green theorem 相关内容；
  - 提取一条学习路径；
  - 提取一个 proof chain；
  - 提取一个 source-backed report view。
- 是否支持隐藏关系：
  - 用户默认看不到；
  - AI 能读取；
  - advanced user 能编辑；
  - 可以转成可见关系。
- 是否支持 relation 状态：
  - suggested；
  - accepted；
  - rejected；
  - hidden；
  - visible；
  - stale；
  - source-backed。
- 是否适合 AI：
  - AI 能不能直接读 graph；
  - graph 如何进入 prompt / retrieval；
  - 如何避免 AI 把 visual edge 当成 truth；
  - 如何审查 AI 生成的 relation。

### Coincides 特别关注

Relation Layer 不只是 macro / micro。

它还可能代表：

```text
目的：学习路径、公式推导、source evidence、复习重点
使用者：用户、人类读者、AI agent
主题：三角函数、Green theorem、某个章节
状态：suggested、accepted、hidden、visible
视图：原始画布、抽取子图、报告视图、复习视图
```

### 预期输出

```text
docs/brainstorm/v2.4-research/knowledge-graph-relation-layer-reference.md
```

输出中必须给出：

- v2.4.4 最小 Relation Layer 设计建议；
- 是否需要独立 `relation_layers`；
- 是否需要 `object_relations`；
- 是否暂时避免 graph database；
- topic-specific view extraction 的最小可行路径。

## 5. 调研方向四：NoteBlock / Relation Object Model

### 目标

研究 NoteBlock 在 Coincides 数据结构里到底应该扮演什么角色，以及它和 Relation、CanvasNode、KnowledgeObject、Source、Evidence、Proposal 的边界。

这不是普通 block editor 调研，也不是 Canvas 调研。

核心问题是：

```text
NoteBlock 是不是 v2.x 的主要知识节点？
Relation 应该连 NoteBlock，还是连更细的 KnowledgeObject？
CanvasNode 到底只是 NoteBlock 的投影，还是可以成为正式知识对象？
```

这轮调研要防止两个错误：

- 把 NoteBlock 降级成普通富文本 block；
- 把 CanvasNode 升级成第二套知识本体。

### 重点对象

- BlockSuite / AFFiNE block model
- Tana supertags / fields
- Anytype object types / relations / templates
- Logseq / Roam block references
- Obsidian file / block / canvas boundary
- Notion block / page / database model
- ProseMirror / Tiptap editor node model
- Lexical editor node model
- Property graph / RDF 基础建模思想
- Coincides 现有 NoteBlock / SourceAnchor / EvidenceSet / CanvasNode / Proposal 模型

### 必须研究的问题

- NoteBlock 到底是什么：
  - 内容块；
  - 学习对象；
  - 知识节点；
  - source 解释结果；
  - AI 操作单元；
  - CanvasNode 的 target；
  - KnowledgeObject 的一种；
  - 还是未来更细对象的组合容器。
- v2.x 是否应该把 NoteBlock 当成主要 graph node：
  - 如果是，边界在哪里；
  - 如果不是，最小 graph node 应该是什么；
  - v3.x 是否需要拆出 ConceptObject / ClaimObject / FormulaObject / EvidenceObject。
- Relation endpoint 应该支持哪些对象：
  - NoteBlock -> NoteBlock；
  - NoteBlock -> SourceAnchor；
  - NoteBlock -> EvidenceSet；
  - NoteBlock -> MaterialSegment；
  - Formula -> Formula；
  - Theorem -> Proof；
  - Concept -> Example；
  - SourceFragment -> EvidenceItem；
  - Proposal -> generated object；
  - CanvasNode -> projected object。
- CanvasNode 和 NoteBlock 的关系：
  - CanvasNode 是否永远只是 projection；
  - 一个 NoteBlock 是否可以出现在多个 Canvas / View；
  - Canvas 删除节点是否绝不能删除 NoteBlock truth；
  - 临时 CanvasVisual 什么时候需要升级成 NoteBlock 或 Proposal；
  - visual connector 什么时候升级成 ObjectRelation。
- BlockSuite 对 Coincides 的真正启发：
  - `BlockSpec` 如何拆 schema / service / view；
  - block tree 如何组织；
  - 一个 block model 如何对应多个 view spec；
  - PageEditor / EdgelessEditor 如何共享同一份 doc；
  - widget / command / selection / history 如何分层；
  - 哪些可以借鉴，哪些不应该引入。
- Tana / Anytype / Logseq 对 Coincides 的启发：
  - typed node；
  - supertag；
  - relation field；
  - object type；
  - template；
  - block reference；
  - bidirectional link。
- NoteBlock 和 template 的关系：
  - system_type / learning_role / template_id 是否足够；
  - template 是否只是渲染规则；
  - template 是否可以定义 relation pattern；
  - template 是否可以定义 source behavior；
  - template 是否可以定义 AI proposal behavior。
- NoteBlock 和 source/evidence 的关系：
  - source reference 是 NoteBlock 的字段，还是独立 relation；
  - EvidenceSet 是否应该成为 graph node；
  - SourceAnchor 是否应该成为 graph node，还是 provenance property；
  - source-backed relation 如何表达。
- NoteBlock 和 proposal 的关系：
  - Proposal 是一次 mutation transaction，还是一个普通对象；
  - proposal 生成的 NoteBlock / Relation 是否必须可追踪；
  - rejected / superseded proposal 是否仍然影响 AI context。
- 对 v3.x graph-native migration 的影响：
  - 哪些 v2.x 表未来可能成为 node；
  - 哪些 v2.x link 未来可能成为 edge；
  - 哪些东西只是 projection/cache；
  - 哪些东西必须进入 migration notes。

### Coincides 特别关注

这轮调研要把以下边界写清楚：

```text
NoteBlock = source-grounded learning/content object
CanvasNode = projection of a domain object
ObjectRelation = semantic / AI-readable relation
CanvasEdge = visual connector, optionally backed by ObjectRelation
RelationLayer = relation collection / view / purpose layer
KnowledgeObject = possible v3.x generalized object model
```

暂定工作假设：

```text
v2.x:
  NoteBlock 是主要知识对象和主要 relation node。

v3.x:
  NoteBlock 可能成为 KnowledgeObject 的一种，
  或成为 Concept / Claim / Formula / Evidence 等更细对象的组合容器。
```

这个假设必须通过调研验证，而不是直接写死。

### 预期输出

```text
docs/brainstorm/v2.4-research/noteblock-relation-object-model-reference.md
```

输出中必须给出：

- NoteBlock 是否适合作为 v2.x 主要 graph node；
- v3.x 是否需要抽象出 `KnowledgeObject`；
- Relation endpoint 最小支持范围；
- CanvasNode / CanvasEdge / ObjectRelation 的边界；
- BlockSuite / Tana / Anytype / Logseq 对 Coincides 的建模启发；
- 对 v2.4.4 Canvas Edges + BlockRelation Seed 的影响；
- 对 v2.5 Template Engine / Package Studio 的影响；
- 对 v3.x graph-native migration notes 的影响。


- AFFiNE document / edgeless
- Notion page / database views
- Obsidian markdown / canvas
- Heptabase card / whiteboard
- Tana object / views
- Figma frame / prototype / presentation
- XMind mind map / outline
- Miro board / presentation

### 必须研究的问题

- 同一份内容如何呈现为不同视图：
  - page-like reading view；
  - infinite canvas view；
  - graph view；
  - source inspection view；

## 14. 当前工作假设

- 不羞于使用开源工具，能用就用，能改编就改编，应该感谢和署名。
- 也不盲目依赖开源工具，Coincides 的 source / evidence / proposal / relation / package 数据主权必须保留。
- v2.4.1 前必须完成至少 P0 调研。
- Relation Layer 不是 UI 小功能，而是未来 AI-readable knowledge structure 的基础。
- `.coincides` 工程包不是当前实现目标，但必须成为 Canvas / Relation / Template 设计约束。
- Canvas 不是唯一事实源，Canvas 是 projection surface。
