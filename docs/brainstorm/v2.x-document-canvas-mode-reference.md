# v2.x Document / Canvas 双模式调研

**创建日期**: 2026-05-21
**状态**: 调研草稿
**范围**: 文档视图、画布视图、Source Board、Learning Canvas、多视图切换

这份文件是 post-v2.1.1 产品/架构调研的一部分。它回答一个核心问题：

> Coincides 未来如果加入 Source Board / Learning Canvas，应该怎样处理“文档模式”和“画布模式”的切换？

结论先行：

```text
Canvas 不应该是第二套知识系统。
Canvas 应该是 Course Material / NoteBlock / SourceReference / Projection 的空间化视图。
```

---

## 1. 调研问题

我们需要判断：

- Document 和 Canvas 是两种编辑器，还是两种 view？
- 一份学习材料在文档里和画布里是否应该共享同一份数据？
- Source Board / Learning Canvas 应该落在 v2.3 还是 v2.4？
- 画布上的节点应该是 NoteBlock 本体，还是 NoteBlock 的投影/引用？
- 坐标、缩放、选择状态、画布布局这些信息应该怎么存？

---

## 2. 参考对象

### BlockSuite / AFFiNE

重点参考：

- Page Editor 和 Edgeless Editor 可以附着到同一个 doc object。
- 同一个 block model 可以有不同 block spec，用于不同编辑体验。
- Edgeless Editor 提供无限画布、图形、连接、frame、presentation mode 等能力。
- 它的价值在于“同一数据，不同编辑器/视图”，不是简单地把一个文档截图放到画布上。

### Obsidian Canvas

重点参考：

- Canvas 可以添加纯文本 card、note card、media card、web card。
- Text card 可以转换成真实文件。
- Note card 可以来自 vault 里的 note。
- Canvas 有 connection、label、group、pan/zoom、zoom to fit、zoom to selection。
- 这说明 Canvas 可以是“内容组织层”，但如果 card 没有变成真正 note，就不会进入 backlinks 等正式知识系统。

### tldraw

重点参考：

- Store 是 reactive database，保存 shapes、pages、bindings、assets 等 records。
- document records 和 session records 分开；document 保存到服务端，session 保存相机、选择、UI 状态。
- shape record 存基础属性和 `props`；shape behavior 由 ShapeUtil 决定。
- frame/group/parent-child、binding、undo/redo、schema validation、migration 都是画布系统的核心基础设施。

### Miro

重点参考：

- Board 是无限可缩放 surface。
- board item 可以是 text、card、link、image、shape 等。
- frame 可以作为 parent item，子元素使用相对坐标。
- viewport 是用户当前观察位置，和 board item 数据不是一回事。

## 3. 他们大概怎么做

### 3.1 BlockSuite / AFFiNE：同一 doc，多种 editor

BlockSuite 的关键做法不是“文档 + 画布两个文件”，而是：

```text
Doc object
  -> PageEditor
  -> EdgelessEditor
```

同一份数据可以被不同 editor 解释。PageEditor 强调线性阅读和编辑，EdgelessEditor 强调空间组织和图形表达。

它还把 block 拆成：

```text
schema
service
view
widgets
commands
selection
history
```

这对 Coincides 很重要：我们不一定要用 BlockSuite，但要学习它的分层。否则未来 canvas 一加入，很容易变成第二套 NoteBlock。

### 3.2 Obsidian Canvas：canvas 是 note/file 的空间组织器

Obsidian Canvas 更像一个“空间化组织层”：

```text
Vault note / media / web / text card
  -> Canvas card
  -> connection / group / layout
```

优点：

- 用户很容易理解；
- 画布可以承载真实 note，也可以承载临时 text card；
- card 之间可以有线和 label；
- group 很自然，适合做主题区块。

风险：

- 临时 text card 如果不转成 file，就不会进入正式知识系统；
- canvas 的结构可能和真实 note 结构脱节；
- 它更像可视化 MOC，不天然解决 source evidence。

对 Coincides 的启发：Canvas 上可以有临时节点，但正式学习节点必须能回到 NoteBlock / SourceMaterial / MaterialSegment。

### 3.3 tldraw：画布数据和会话状态分开

tldraw 的核心启发是数据分层：

```text
document
  shapes
  pages
  bindings
  assets

session
  camera
  selection
  UI state
```

这非常适合 Coincides：

- NoteBlock / SourceReference 是真正学习数据；
- CanvasLayout / CanvasNode / CanvasEdge 是空间组织数据；
- camera / selection / zoom 是用户会话状态，不应该污染学习数据。

### 3.4 Miro：无限 board + frame + 相对坐标

Miro 的启发是空间系统的基本规则：

- board 是无限 surface；
- item 有坐标；
- frame 可以包含 child item；
- child item 在 frame 里使用相对坐标；
- viewport 是当前观察窗口，不是 board 内容。

Coincides 如果做 Learning Canvas，也需要类似区分：

```text
Canvas content:
  node / edge / frame / group

Canvas session:
  viewport / zoom / selection / focused item
```

## 4. Coincides 应该学什么

### 4.1 Canvas 是 projection，不是 source of truth

Coincides 的核心 source of truth 应该继续是：

```text
Course
  -> SourceMaterial / SourceFragment / MaterialSegment
  -> NoteBlock
  -> SourceReference
  -> Projection
```

Canvas 应该是这些对象的空间化投影：

```text
LearningCanvas
  -> CanvasNode references NoteBlock / MaterialSegment / SourceSnapshotRange / Projection
  -> CanvasEdge describes relationship
  -> CanvasFrame groups nodes
```

不要让 Canvas 自己产生一套独立学习对象，否则以后会出现：

- 文档里一套笔记；
- 画布里一套节点；
- source evidence 对不上；
- AI proposal apply 不知道应该改哪里。

### 4.2 Document 和 Canvas 应该共享对象，但可以有不同 layout

推荐模型：

```text
同一个 NoteBlock
  -> DocumentPlacement: 在线性 note 里的位置
  -> CanvasPlacement: 在 canvas 里的位置、尺寸、frame、颜色
```

也就是说：

- 内容本体共享；
- 呈现位置分开；
- 文档里的顺序不必等于画布里的空间位置；
- 用户在 canvas 里移动节点，不应该改写 note 的阅读顺序；
- 用户编辑 block 内容，两个视图都应该看到更新。

### 4.3 Source Board 应该先于 Learning Canvas

从 roadmap 看，v2.3 是 Source Snapshot Viewer + Scope Selection，v2.4 才是更大的 Learning Material OS。

这说明：

```text
v2.3 Source Board:
  以 source trust / scope selection / source-to-note navigation 为核心

v2.4 Learning Canvas:
  以概念结构 / 学习路径 / review projection / 知识地图为核心
```

Source Board 可以是 Learning Canvas 的前置训练场，但不能一上来就做完整自由画布。

### 4.4 Canvas 节点需要类型，但不能复制 NoteBlock taxonomy

CanvasNode 的类型应该描述“画布节点在空间里是什么”，不是重复定义学习语义。

例如：

```text
CanvasNode.kind:
  note_block_ref
  material_segment_ref
  source_range_ref
  projection_ref
  annotation
  frame
```

学习语义继续来自 NoteBlock：

```text
NoteBlock.system_type
NoteBlock.learning_role
NoteBlock.template_id
```

这样可以避免：

```text
CanvasDefinition
CanvasFormula
CanvasExercise
```

这种重复模型。

### 4.5 Canvas edge 应该是轻语义，重语义进入 proposal

画布上的边可以先简单：

```text
supports
explains
depends_on
contrasts_with
source_of
example_of
```

但是 AI 自动生成大量边时，仍然必须走 proposal-first：

```text
RelationshipProposal
  -> Review
  -> Apply
```

不要让 AI 静默改知识图。

## 5. 对 Roadmap 的影响

### v2.2 Material Reconciliation

建议：**小幅修改。**

新增考虑：

- reconciliation proposal 可以产生“block group”或“material segment group”的候选；
- 但不要在 v2.2 做自由 canvas；
- v2.2 只需要保证未来可以把 canonical blocks / material segments 放到 canvas 上。

不建议加入：

- canvas UI；
- spatial layout editor；
- connector/edge editing。

### v2.3 Source Snapshot Viewer + Scope Selection

建议：**修改。**

把 v2.3 从单纯 `Source Snapshot Viewer` 稍微扩展成：

```text
Source Snapshot Viewer
  + Source Board seed
```

但这里的 Source Board 不是完整 canvas，而是轻量空间/列表混合视图：

- 左侧/主区看 source snapshot；
- 可以选择 page / page range / chunk / segment；
- 可以看到这些 source ranges 已经生成了哪些 NoteBlocks；
- 可以把若干 source ranges 加入 selected scope；
- 可以跳到相关 NoteBlock 或 proposal。

v2.3 的重点仍然是 source trust，不是视觉炫技。

### v2.4 Learning Canvas / Edgeless Workspace

建议：**明确新增/强化。**

v2.4 应该正式引入 Learning Canvas，但设计原则必须写清楚：

- canvas 是 projection surface；
- 节点引用 NoteBlock / MaterialSegment / SourceRange；
- canvas layout 独立于 note reading order；
- frame/group 是学习组织工具；
- edge 是关系表达，但高置信知识关系仍然要 proposal-first；
- document 和 canvas 应该能互相跳转。

### v2.4.x / v2.5 Template Engine

建议：**不直接修改，但保留接口。**

Canvas 会影响模板编辑器，因为未来用户可能希望某些模板有默认 canvas 表现：

```text
exercise template -> 默认显示 answer slot
theorem template -> 默认连接 proof/example
formula template -> 默认连接 variable explanation
```

但这不应该提前进入 v2.3/v2.4 的基础工作。

## 6. 推荐的 Coincides 模型草案

### 6.1 核心对象

```text
LearningCanvas
  id
  course_id
  title
  purpose
  created_from

CanvasNode
  id
  canvas_id
  kind
  target_type
  target_id
  x
  y
  width
  height
  frame_id?
  style_json
  metadata

CanvasEdge
  id
  canvas_id
  from_node_id
  to_node_id
  relation_kind
  label
  confidence
  source_type
  proposal_id?

CanvasFrame
  id
  canvas_id
  title
  x
  y
  width
  height
  metadata

CanvasSessionState
  canvas_id
  user_id
  viewport
  zoom
  selected_node_ids
```

### 6.2 关键原则

- `CanvasNode` 默认引用已有对象，不复制对象内容。
- 临时 annotation 可以存在，但进入正式学习系统前要变成 NoteBlock 或 proposal。
- `CanvasSessionState` 不属于学习内容，不进入 source evidence。
- Canvas layout 可以保存，但不改变 Note 的线性阅读顺序。
- AI 生成 canvas nodes/edges 应该走 Proposal -> Review -> Apply。

## 7. 切换体验建议

### 7.1 文档到画布

用户在 Note / Source / Proposal 中可以选择：

```text
Open in Source Board
Open in Learning Canvas
Add to Canvas
```

系统行为：

- 找到或创建一个 canvas；
- 为当前 NoteBlock / SourceRange 创建 CanvasNode；
- 聚焦到该节点；
- 保持文档原来的顺序不变。

### 7.2 画布到文档

用户在 CanvasNode 上可以：

```text
Open NoteBlock
Open Source Range
Open Projection
Open Proposal
```

系统行为：

- 从 CanvasNode 的 `target_type + target_id` 跳回真实对象；
- 如果是 source range，则进入 Source Snapshot Viewer；
- 如果是 NoteBlock，则进入 Note editor 或 block detail。

### 7.3 双模式同步

同步范围：

- 内容编辑同步；
- source reference 同步；
- proposal apply 同步；
- title / role / template label 同步。

不同步范围：

- canvas 坐标不改变文档顺序；
- 文档顺序不自动改变 canvas 坐标；
- zoom / viewport / selection 是个人会话状态。

## 8. 风险

### 风险 1：Canvas 变成第二套知识库

如果 canvas node 可以随意保存完整学习内容，而不链接 NoteBlock / SourceMaterial，就会分裂。

应对：正式学习内容必须有 target object 或 proposal。

### 风险 2：过早做自由画布会拖慢 v2.2/v2.3

画布系统需要选择、拖拽、缩放、连接、框选、层级、碰撞、性能等大量基础设施。

应对：v2.3 只做 Source Board seed；v2.4 再做 Learning Canvas。

### 风险 3：Document / Canvas 双向同步复杂

用户会期待“我在这边改，那边也更新”，但不是所有状态都应该同步。

应对：明确区分 content state、layout state、session state。

### 风险 4：AI 自动连边造成错误知识图

学习关系边如果错误，会误导用户。

应对：AI 生成结构关系必须 proposal-first，并保留 source evidence / confidence / warnings。

---

## 9. 当前结论

Coincides 应该采用这种路线：

```text
v2.2:
  准备 canonical block / material segment / block group
  不做 canvas

v2.3:
  Source Snapshot Viewer
  + 轻量 Source Board seed
  重点是 source trust 和 scope selection

v2.4:
  Learning Canvas
  作为 NoteBlock / MaterialSegment / SourceRange / Projection 的空间化视图

v2.4.x / v2.5:
  结合 canvas 经验，再做用户可编辑模板引擎
```

最重要的产品判断：

```text
Document mode 是阅读和编辑顺序。
Canvas mode 是空间理解和关系组织。
两者共享学习对象，但不共享布局规则。
```

---

## 10. 推荐更新项

- **修改 v2.3 roadmap**:
  - 把 Source Snapshot Viewer 表述为 Source Snapshot Viewer + Source Board seed。
  - 强调 v2.3 不是完整自由画布。

- **修改 v2.4 roadmap**:
  - 明确 Learning Canvas 是 projection surface。
  - 明确 canvas nodes 引用 NoteBlocks / MaterialSegments / SourceRanges / Projections。

- **不动 v2.2 主线**:
  - v2.2 仍然专注 Material Reconciliation。
  - 只在数据设计中避免阻塞未来 canvas。

- **新增长期 guardrail**:
  - Canvas 不创建第二套学习内容本体。
  - Canvas layout 和 document order 分离。
  - AI 生成关系边必须 proposal-first。
