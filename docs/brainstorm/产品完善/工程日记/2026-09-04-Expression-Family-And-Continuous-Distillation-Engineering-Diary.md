## 三 · 表达族(item 形态转换的方向定案)

文字是信息的载体之一而非信息本身;同一信息经不同载体,理解效率与角度不同。方向六件:

1. **转换是生育不是变身**:文字 item 生出组件 item,原件不灭,出处边相连(出生形态=provenance,表达后代=派生件);
2. **概念卡 = 形态族的海关**:⛔ 不做"文字→(不透明跳跃)→组件";必经显式中间物(卡:量/范围/关系/行为申报)。卡升格为持久 item,即语义核;文字与组件皆其表达。人类在卡上纠 AI 于昂贵渲染之前;忠实度在卡上机械可对账;
3. **失同步是状态不是错误**:原文改,派生件挂旧版标注;⛔ 不自动重渲;一键重育带卡 diff 候用户;
4. **保真申报**:每次转换申报保留/丢失/新增假设(转写器保真等级的表达层亲戚);无申报不入真相层;
5. **弃渲零罪**:废渲染件可删,不牵连卡与原文——形态实验从作品级决策降为试穿;
6. **⛔ 不做任意到任意**:卡语法从真实转换标本长出(判据对着真实分歧设计同法);第一刀选一对窄的垂直打穿。

**HTML 选型的架构学理由**:它是唯一"既能演又能被引用"的大众介质——文字在其中保持可选中、可扎锚、可被下轮思考引用,同时能怀抱视频/3D/交互。锚体系要求台子可寻址,HTML 独占"可渲染 × 可寻址"。

## 四 · 不可预判困局的解法(学习+便宜化)

## 十一 · 补层(09-05):四种空间语法(HTML 的媒介自觉)

Henry 观察:笔记软件全体"用 HTML 造纸"(模仿纸质笔记本,不尊重 HTML 特性);留英手册的按钮式分布证明笔记该有 HTML 原生的展现形式。**类比:早期电影只会架着摄影机拍舞台剧,发明蒙太奇后才成为自己——笔记软件仍在拍戏剧阶段。**

核心判语:**纸的秩序是「顺序」,HTML 的秩序是「状态」**——纸把内容摊在空间里供人旅行;HTML 让同一块空间在时间里轮换内容,读者不是旅行,是操作。

一篇笔记的四种空间语法(可混用的呼吸法):

1. **卷轴式**(纵向线性,空间即顺序)——纸的血统,页面组/续页,长文正统;
2. **铺陈式**(平面展开,空间即关系)——板的语法;
3. **舞台式**(同一有界台面分幕轮换:页签/折叠/抽屉/分步揭示/暗门,空间即状态)——阅读顺序由读者手指现场生成;
4. **纵深式**(点入一层再退回,概览与细节分层住)——超文本的深度天赋。

**舞台/纵深是「有界纸叠」的救兵而非叛徒**:有界的纸不长身高长层数,密度不靠蔓延——留英手册即标本#1。

工程回响两条:①**版面模板 schema 缺下半章「揭示语法」**(现只有静态槽位几何;哪些槽位分幕、幕怎么切须预留)——落位:13.0 施工图四增章;②**人看台面,机读后台**:全部幕的内容对锚/检索/AI 永远在场,舞台只骗眼睛不骗真相层(有界页=逐页读法的判据不因舞台破坏,机器读数据不读像素)。

## 十二 · 补层(09-05):动画的依赖边界(Henry 问:可全赖 OD 吗?)

**答:不能——章程旧法「OD 可加工的是资产,不是行为」即答案。**动画拆四类:

1. **装饰性动效**(入场/悬停/滚动揭示/过渡)= 资产,OD 全权——**动效即风格**,时长/缓动/入场方式入 token 家族(皮的延伸),供体解剖照常提取(Atelier Zero 已证:IntersectionObserver+缓动+reduced-motion 皆可提参);
2. **讲解性动画**(数据驱动演示/推演展开)= 行为,⛔ 永远家造——每帧绑语义,骨骼来自概念卡,走产房正路;**极致表达的核心动画全在此类**;
3. **叙事性编排**(分幕揭示)= 分治:揭示逻辑归版面模板「揭示语法」章(家),切换味道归动效风格(OD 可提案);
4. **电影级/生成视频** = 外部生成物当媒体资产进门(收藏路线,进口非依赖)。

分工判语:**家里定骨骼和动机,OD 定味道和节奏**——OD 交节奏表(token 化动效语言),组件拿节奏表跳自己的舞。保三件:行为可控(可暂停/确定性重放)、无障碍原语层强制(reduced-motion 不靠工匠自觉)、机读后台不破(动画是数据描述非不透明像素,AI 读得懂"什么随什么变")。

**工程账一条(落位:产房章程 14.x 修订)**:闭集零件库需**动画原语族**(补间/时间线/弹簧/滚动触发,小而封闭)——否则组件各自带动画方案,风格与性能碎裂;「捏脸不改骨骼」在动效上的前提=骨骼先长好关节。

## 十三 · 补层(09-05):伪动画的统一 + 复合表达的引用机制

**Henry 定性**:讲解动画与叙事编排=「伪动画」——部分动画配自动化演示流程,本质是定时播放的 HTML;先出产品雏形,十几个版本拿到装饰动效入场券已很好;生成视频不归我们管(§十二第 4 类维持)。

**统一(Fable)**:**伪动画 = 舞台式的自动驾驶**——同一套揭示语法,三种时钟:手动换幕=舞台式、定时换幕=伪动画、数据驱动换幕=讲解组件。⛔ 不需要独立动画系统;版面模板揭示语法章建成之日,伪动画地基顺带完工。入场券之后是坡不是墙。

**复合表达(文字+组件联合传达)的引用机制四条**:

1. **引用的对象永远是卡,不是形态**——形态是跟着卡走的衣柜;引用落地时选着装(只文字/只组件/文字配组件);
2. **组件过去靠投影不靠复制**:原样投影(活视图)vs **携参引用**(同一台机器+本篇自己的参数预设+出处边,零复制)——组件=骨骼+卡数据+实例参数三明治,第三层天生留给引用者;
3. **「文字永远住在文字的家」立法**:凡知识性文字要么是卡数据、要么是组件旁的段落块,⛔ 不许烧死在组件渲染内部——住段落块的文字可锚可检索可被下轮思考咬住,烧进组件的是像素级死物(Henry 的 paragraph block 直觉升格;与供体解剖「提取参数不搬 HTML」同法两半;OD 产物可再利用由此天然保证:进门皆参数非壳);
4. **Agent 判断引用=机械命中+提案不独裁**:卡为一等可检索物(申报即高密度语义文本);草稿阶段执行库内优先,命中即三选提案(原样引/携参引/重做,缩略图),点击即收据喂偏好履历。

## 十四 · 补层(09-05):表达块的身份 · 组件的背面 · 碎片的呈现

**Q1 小组件的身份**:块系统只加**一种**公民——**表达块**(筐,装组件实例三明治)。块型闭集(引擎稳),组件开集(创造活)——「别做形态菜单」在类型系统上的对应物。滑杆+说明的组合 ⛔ 不发明复合块型:说明=段落块,与表达块并肩合抱(摆放层轻事);真正的焊点=**共享同一张卡**(一份知识的两件衣服恰好同场)。

**Q3 碎片的待命与呈现**:前半问=V12.9 整版已建成(入库即碎片化带锚带指纹,嵌入索引,检索列队)。后半问立原则:

> **碎片永远不作为一种「东西」给人看——人看文档的脸,碎片是文档的骨。**
