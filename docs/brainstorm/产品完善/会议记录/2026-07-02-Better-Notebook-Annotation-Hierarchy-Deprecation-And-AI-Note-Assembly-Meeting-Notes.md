## 一、annotation 父子层级 = 时代眼泪（可留·无害·会隐形）

**定案：无害留着、不投入、会自然隐形。** 不主动废、不审计、不删（改我之前"赶紧冻结/审计"的过度反应；地基期"没用但无害"就该"留着别管"）。

- **出身**：annotation-first 时代的设计。当年靠"便利贴叠便利贴"表达"这些重点归一坨"。**转型后角色分化**：重的那半（把内容捆成知识）**毕业成 ContentGroup**（更细，带 identity/petal/folder 树）；父子只剩轻的那半。**ContentGroup 是从它长出来的**——健康演化，不是失败实验。
- **实地核查（dead-vestigial，代码坐实）**：无任何创建入口设 parent（三个 create-site 全传 null）；嵌套 setter（attach/detach/addChildLink）**生产零调用**（只契约测试碰）；唯一嵌套渲染点（inspector 子卡）`children.length>0` 门控→**从不触发**；所有 reader 对扁平数据退化为 no-op。**用户当前建不出也看不见嵌套。**
- **跨 note 层级不可能存在**（存储按 note + 创建 UI 单 note + 036 dedup + 无 clone 搬层级）→ 那个"静默清空跨 note parent"的服务端逻辑安全。
- **残余的用户价值（≠纯死重）= 两个个人便利贴职责**：① **视觉提示**自己标了什么；② **复习前的粗 label 预分拣**——随手 label 一遍"这篇有多少块要归置"，再一口气建仨 ContentGroup 分别拖进去。**标签=收件箱（快、便宜、松），ContentGroup=归档柜（慢、结构、定）。**
- 真要删（**不计划**）：先跑只读审计 `count(parent_annotation_id IS NOT NULL OR child_ids<>'[]')`；且**别在删列前拆 CR-8.11.1-04 服务端守卫**（列活着它还挡悬空/成环直写）。cross-ref register §8.11.15 + 记忆 `annotation-hierarchy-is-vestigial`。

## 二、ContentGroup 的双重身份 + 双生命周期 + AI 的外部记忆

> 承 06-28「ContentGroup = 蒸馏精华 + AI 那一半」。今天把"AI 那一半"展开成**外部记忆**，并拆出**两种出身**。

- **双重身份**：① 人的**精心攒的知识件**（第二大脑）；② AI 的**推理脚手架 / 思考痕迹载体**——地位很高：辅助 AI 理解、**记录理解过程、呈现思考过程**、可反推"为什么这么归"。
- **ContentGroup 库 = Agent 的外部记忆（关键立场）**：Agent 不在实时上下文里扛记忆；**不建独立的记忆压缩系统**（Henry：一开始思路不在这、也没必要）——上下文截断了，**回 ContentGroup 库检索**来答用户。与 06-28 的 GraphRAG=可重建 sidecar、二月 MU 记忆框架自洽：**本地结构化存储本身就是记忆系统，再建一套就是第二真相源。**
- **两种出身，同一个原语（别分两类型）**：
  | | 用户自建 | AI 顺手建 |
  |---|---|---|
  | 信任 | 背书=ground truth | 暂定/provisional |
  | 量/位置 | 少、慎、台前 | 多、批量、后台"库" |
  | 生命周期 | 默认留、有意删 | 可弃（笔记落定）/可留（记忆）/可**认领**升级 |
  - **区分靠维度不靠类型**：`created_by`（user/ai）+ 状态（**staging ↔ curated**）。AI 顺手建默认 staging、待库里；用户认领→升 curated 上台前。
  - **"认领/毕业"= 和 annotation 那个"收件箱→归档"同一套 capture→curate 语法**。这个"松捕获→郑重策展"的节奏在产品里**反复出现**——疑似一条**核心 UX 语法**，值得单拎命名。
  - 落法：GroupFolder 里笔记根文件夹=笔记本体；AI 生成时的思考 CG **单独放一个文件夹（后台库）**，不污染用户台前空间。
- **张力**（记着）：AI 想全留（记忆便宜）vs 用户想干净（草稿碍眼）。**v1 默认不清**（偏 AI/检索那头；清不可逆，留着最多占地）。用户想收拾给个"清库"。

## 三、note 与 ContentGroup 的关系：成员是指针，笔记是独立真相

- **ContentGroup 引用到底**：group 是引用、member 也是引用（含缓存预览 + source_ref + 漂移追踪）；**改 member/path 内容不回写原笔记** → CG 和笔记是**彻底分开的两层真相，生成单向、不倒灌**。
- **笔记 ≠ 拼 ContentGroup**。笔记是**独立的 prose 真相（TextFlow）**；ContentGroup 是**指进笔记+源的镜片/计划**（像荧光笔道子不是它划的那句"组成"的）。
- **note-first UX / ContentGroup-first 架构**：用户体验是"给我一篇笔记"，底层笔记是**从固化理解投影出来的**；CG 默认藏引擎盖下、想 steer 再掀。若 AI 直接吐 prose 不固化理解，理解就锁死在文字里→没法 steer、知识不累积、学习闭环断。
- **目的相对（reinforce 06-28 铁律）**：同一批内容按目的换分组——日常学习 theorem 与 example 拆开；期末复习 theorem 里带 1-2 代表 example（紧凑、好复习、好复用）。**因成员是指针**，"theorem(日常)"和"theorem+example(复习)"两个镜片可**同时叠在同一内容上，零复制**。目的决定镜片（同 Relation-服务于目的）。

## 四、生成笔记 = 锚定编排（非凭空生成）——抗幻觉的核心

> 今天最重的工程洞见。起因：把"回填中间内容"误当成"AI 当场生成"。

- **纯生成的三宗罪**：① **幻觉**回来；② **没有记忆压缩/上下文管理 → 写着写着上下文爆、半截 prose 烂掉**（不是 harness 能补的，是模型选错）；③ **不 on-grammar**：源是 provenance，笔记该**保真重建为主**，textbook 内容那么全，凭什么凭空生成。
- **正解**：**回填 ≈ 搬运/paraphrase 源的 span（锚回 source range）+ 极薄的现生成筋腱（过渡/框架）。笔记 = 锚定源料的重编排，不是新作文。**
- **一锚拆三雷**：
  - 内容多数锚回源、可对锚点查真 → **幻觉被关住**；**无锚的内容=生成的→自动标红送审**（天生的 hallucination 探测器）。
  - 每块小、锚定、**可独立重建** → 上下文爆了最多丢那句桥，搬运部分照锚**重造得回来**。**生成从"一条脆弱长流"变成"块状可恢复拼装"。**
- **缺的中间环节 = provenance 锚**：**笔记 content_range ⟷ source range 的双向链**（承 06-28 ③→② 的 bbox 锚，今天定性为**抗幻觉 + 韧性**的关键，不只是溯源）。有锚=搬来的/可查/保真；无锚=生成→标红。
- **粒度反问已拆**：指针再碎（第 17 句、88 句），回填出来也不会是缝合怪——因为回填是**写作（读素材再写连贯 prose）**，不是**拼接**；指针只定"覆盖什么、什么角色、什么顺序"，不定输出句子边界。**碎的是料，不是菜。**

## 五、Draft 层 = 给无序 ContentGroup 上"顺序/布局"（Henry 洞见·比看着大）

**Henry 的关键 refinement（之前没想过、明确说是重要的一层）：ContentGroup 只有角色/小块，本身「无顺序可言」；Draft 才让它有了顺序。** = 做拼图：**ContentGroup 是碎片，Draft 是"把碎片拼成想要样子"的那个排布/布局过程。**

- **Draft = 带收据的半成品笔记**：一篇**有序的 proto-note**，每块要么是**锚定的源 span**（搬来的）、要么是**薄生成的桥**，带 `status=draft/proposal`。
  - 能长成最终笔记（polish + 改 status）；每块带锚→可审、可增量、可重建（正好治"写一半爆了"）；
  - **可整个当 proposal 给用户**："我把三篇整成这样了、锚都在，你看要不要在此基础上生成？"（系统已有 proposal 机制）。给不给用户看是开关。
- **draft 形态待拍**：proto-note（Claude 偏——draft 朝线性 prose 去，CG 是带角色的网状 lens，形状不同）vs mega-ContentGroup（混装 subgroup + 原文 content_range + AI 每节简介）。
- **⚠ 现在还没法定死（Henry 明确）**：draft 和锚**具体怎么设计，得等 Source 先做**——上传后的 Source 保持什么结构/形态，Henry 现在心里没数，所以没法假定锚长什么样。→ 承 06-28：**SourceArtifact / SourceAnchor 契约 = design-later（PI-048 双闸门：早定形状、晚建管线）**。纪律不变：**Source 结构（接缝）先立，anchor+draft（混凝土）后浇。**

## 六、"分块"= 在源上建 ContentGroup（今天讲清的一点）

> Henry 一开始拿"整理好的 textbook（一章一章）"当模板，忽略了乱源（故事会 / 怪报告 / 无 chapter）。今天理清：**分块这个动作，本身就是在源上建 ContentGroup。**

- **两种"block"（承 06-28 ②/③，别塌成一层）**：
  - **② 源自己的可寻址区域**（OCR 忠实产出：这是段落、这是表、bbox、阅读序）——**描述源本身、无解读**，是**锚点的靶子**。
  - **③ 你的解读性分组**（ContentGroup）——"这些区域归一坨、担什么角色"，是**你的内容**。
- **有 chapter = 源替你把框画好了**（② 层已带 chunk 边界，**连续**，退化的省事特例）。
- **没 chapter = 源没画框 → AI 通读、闹清讲啥、自己画框** = 把 ② 的区域 **lasso 成有意义的单元** = **建 ContentGroup**（成员=指针指向那些 ② 区域）。
- **因成员是指针 → 框可非线性**：第 1、7、13、77、88 页能收成**一个语义块**（chapter 只能连续，ContentGroup 能散点）。所以 **ContentGroup 是比 chapter 更一般的"分块"**。
- **一句话**：分块 = 在源上建 ContentGroup；有 chapter = 源替你分好、AI 省事；没 chapter = AI 自己分（就是建 CG）。

## 七、整条管线（今天捋出的形状 · 承 06-28 三层）

```
原始文档
  ↓ 抽取（Notion 式：文字/公式→LaTeX/图 → 干净 Markdown + 可寻址）   = ① / ② 源层，Agent 前，机械、可 eager
② SourceArtifact（忠实、可寻址、bbox）
  ↓ 分块（有 chapter 跟着走；没 chapter AI 通读派生·可非线性）      = 在源上建 ContentGroup（③，解读、按目的、lazy）
  ↓ 理解/角色标注（definition/theorem/derivation/example…，排优先级）  = 更细的 ContentGroup / member 角色
  ↓ 计划（大纲 = 有序 group-of-groups + identity 简述，按目的）
  ↓ 装配 Draft（走大纲 → 逐节点：锚定搬运/改写源 span + 薄桥 → 有序 proto-note，带锚、带 status=proposal）
  ↓ （可选）proposal 给用户看 / steer
最终笔记（TextFlow，独立真相；锚回源；不回写）
```
- **每步的"框架 vs 肉"**：ContentGroup/大纲 = 骨架（无序→Draft 给序）；肉 = 指针取的**源料** + 现生成的**连接筋腱**；装配是**一趟写作走查**（消费 源+CG，产出笔记，单向不回写）。
- **风格 ≠ 内容**：抽取那步已处理格式（LaTeX 等）；**嗓音/叙事风格**在装配的"渲染"步施加。融合三篇 = textbook 的**骨** + 手写笔记的**肉和嗓**（配方里有两个源：内容源 + 风格源）。

## 七.5、圈 / 角色 / topic 的归属细拆（07-02 续聊·修正第六节的糊）

> 第六节"分块 = 建 ContentGroup"**说糊了**（Henry 当场抓到）——把"圈（scope）"和"圈里的知识单元（CG）"塞成一层。此节修准。

- **圈 ≠ ContentGroup，是分形里两层**（承 06-28：目的层 folder → CG 层 → petal 层）：
  - **圈（Chapter 1）= scope/框**（划范围 + 给里面角色一个参照系）；
  - **圈里的 theorem/definition = ContentGroup**（带角色的知识单元）；
  - **theorem 里的 condition/statement/proof/example = Petal**。
  - 判据：圈**自身有无知识含义**——纯收纳的桶→ Folder；本身当一个概念去关联/复用→ 可为粗 CG。多数章/块是桶→ Folder。
- **CG 能套 CG（member 类型含 `content_group`）留给"真·知识组合"，别拿它当组织上的圈**（当圈的隐患：语义过载"是东西还是桶"、生命周期打架"删容器该不该致命"、深嵌套让"角色相对哪个圈"变糊、抹平干净分形）。
- **核心哲学问题（Henry 磨出来的）：CG 到底需不需要「角色」「topic」焊在自己身上？**
  - **角色是 frame-relative 的**（06-28 铁律）：`theorem` 不是 CG 的绝对身份，是"这个 CG 在 Chapter-1 这个圈里扮的角色"；换圈可换角色。
  - **Folder 要保持自由**（Henry 坚持）——所以角色**不该挂 folder**（会给中性桶塞含义）。
  - **解 = 角色住在「边」上，不住任一「节点」**：角色 = "CG-在-某-scope-里"这条**成员关系/placement（= purpose-context）**的属性，既不焊 CG、也不挂 folder。这条边**就是 Henry 感觉"缺的中间层"**。（类比：人在公司的"职位"住在雇佣关系上，不住人、不住公司。）
  - **06-28 已分过两种角色**：**本相角色**（intrinsic，留 CG 合理）vs **per-purpose 角色**（contextual，放 placement）。"怪怪的"来自把角色当成**一个**东西——它是**两个**：内在半留 CG、语境半上边。
  - **今天把 topic 也这么拆**（Henry 新增）：topic 同样 = 内在 gist（可从成员派生、留 CG 当身份/缓存）+ 语境 framing（上边）。所以"角色走了 topic 也该走"**对一半**：两者的**语境半**都上边、**内在半**都留 CG。
  - **结论**：不是"调 folder"（保持自由），也不只是"给/去 CG 焊"——是**把「边/成员关系（purpose-context）」抬成一等承载**：CG 只留内在身份（成员 + 内在 gist + 本相角色）；folder 只当自由 scope；**语境角色 + 语境 topic-framing + fitness-state 住边上**。
  - ⚠ **接现状**：06-28 §九C 已旗标 **`identity_role` 现焊在 content_groups 上（违铁律）**——Henry 今天这个直觉正好确认这颗雷。**待翻实**：现状 role/topic 到底在 CG 表上（焊死）还是有 CG-in-scope 成员关系承载。

### 七.5 续：拆出第四词条「type」→ 干净的三轴 + role 退化（07-02 再续）

> 上面 bullet「topic 也语境半上边」**被这轮修正**：更干净的切法是把 **type** 单拎出来，于是 type/topic 都留 CG（内在），role 纯化上边。

- **多了一根轴「type」**（Henry 切的最准一刀）：以前"角色"糊了两件事——"它**是什么**"(definition) 和 "它**派什么用**"。把 type 拉出来后 → **三轴各答一问**：
  - **type**：它**是什么**？definition/theorem/example——本体、**内在、在 CG（≈标题/标签）**、稳。
  - **topic**：它**讲什么**？连续性——主题、**内在、在 CG、可多标签**（成员碰几个主题就几个）、稳；检索按它。
  - **role**：它这儿**派什么用**？地基/前置回忆/考点/可跳——**语用/功能、语境、在边上**；随 scope 变。
- **role 退化提纯**：type 出来后 role 卸下"说明是什么"的包袱 → 变成**纯粹的"思考痕迹 + 对 Agent/人的操作指引"**（这次这块 CG 该怎么用）。
- **"脱离边角色无意义"**（Henry）= 对：CG 单拿只有 type+topic，**无 role**；role 必挂"CG-在-某圈"的边才存在。Ch1+Ch2 渐进可合并 → 圈自由缩放时 **type/topic 纹丝不动、只 role 动** = 三轴归位的价值（scope 可重划不搅语义）。
- **词表管理（Henry 的真纠结：不预设样板 vs 又要控制/复用/别每次重建）**：
  - **不预设 template**（千人千面、微积分≠代数、理科≠文科、学习≠报告生成 → type/role/topic 靠**强推理 AI 临场生成**，预设=把用户洗成平均值）。
  - 解 = **一个「随用而长、共享、去重」的词表池**（= grow-by-use 用在词汇上）：起点空 → AI **优先复用**、挑不到才提议新建 → 池**跨笔记共享累积**（天然可复用、不每篇重建）→ **去重/归并闸且要松**（concept≈definition 该并就并、**够用就行别分太细**）→ **人点头**（新词是 proposal）。
  - **下拉为主**（挑现有=零打字，治 power series 大小写/空格/漏字）+ 建时**规范化+模糊匹配**；新词偶发且一建就沉淀成资产。
  - **facet（按学科/目的分池）**：先**一个池 + 按上下文智能排序下拉**，**真糊了再拆**（别一上来又变预设结构）。
- **待议**（Henry 点名）：① type/词表这套敲定；② **怎么画圈**（有 chapter 跟走 / 没 chapter AI 通读派生 / 渐进关系可合并 / 非线性散点收一块）——下一根粗线。

## 七.6、成熟模型总览（07-02 全场脑暴收口 · 从两个真实场景长出来）

> 全场从"annotation 父子该不该废"一路长到这套。经两个手动场景（学习复习笔记 / 用户研究报告）验证，骨架同一套、只 role 词汇 + 分块基础不同。以下是当前**成熟形态**（研究层·待落地）。

**词汇统一**：**member = item**（member 是数据/正式名，item 是口头别称，一回事）。**CG = "a group of content"**，纯 bundling，只把 member 相互绑起来，非特殊对象。

**递归"带角色的部件归属"（一个形状，层层自相似）**：
```
圈（purpose-frame / ≈ Reading / = draft） ⊃ member（item：叶子 或 CG，地位平等）
                                          member（CG） ⊃ member（item）
                                          member（item：如 table/图） ⊃ 花瓣（内部子区域标记）
```
- **节点带内在**：type（是什么·稳·坐标无关）+ topic（讲什么·可多标签·派生）。
- **边带语境**：role（派什么用·关系性·相对同圈其他成员）+ fitness + 序（order_index）。**role 在每层的包含边上都成立。**
- **item vs 花瓣**：整体被捆进来的 = item/member；一个整体**内部**标出的子区域 = 花瓣（就算一张 table 也能有多个花瓣，不需 CG 有复数 member）。

**scalar → vector（今天的皇冠比喻）**：item 单拿 = **标量**（大小=type+topic、无方向）；圈 = **参照系**；role = **方向**（离参照系无意义 = "脱离边角色无意义"的物理版）；item 进圈 = **矢量**。同 item 进不同圈 = 同大小、不同方向。**圈只给方向、不改大小。**

**圈 = 一套机制，且 = draft（塌一层）**：
```
圈（节点）：{ 目的, 范围简述, 简介 }
圈成员（边表）：{ 圈, 成员, 角色, fitness, 序 }   ← 合起来 = 圈机制 = draft
```
- 圈边表本带 order_index → 圈成机制那刻就是 draft，不用另起"排序层"。
- **draft = 圈的一种用法**（目的="产出这篇笔记"时）；目的="组织知识留着复用"时 = 常驻 Reading。**同一原语两种用法。**
- **"精华/理解单元"从 CG 挪到了圈**（CG 纯化成 bundling 后，"为某目的选了哪些+各扮啥"= 这次的蒸馏 = 圈接过衣钵）。

**比喻**：知识库那半 = **独立文件管理器**（item=带后缀的文件、folder=文件系统、CG=把文件捆一起）；圈 = **一次策展/展览**（item=展品、role=展中站位、序=动线、同画进两场展扮不同角色、note=导览册）——接 capture→curate 语法。

**管线（两步，非三步）**：member/item（标量）→ **进圈=draft=Reading（参照系，给方向=role）成矢量** → 渲染成 **note（prose，锚回源，不回写）**。

**名字**：`purpose-frame` 难听（Henry 不喜），偏 **Reading**（叉4 + 代码有 ReadingInterpretation），口头继续叫"圈"，回头定。

**⚠ 落地要盯**：① 复杂度必须**待后台**（用户只看"我划的重点被理好了"，不该想"这是花瓣还是 CG 还是圈"）；② "item 可以是 CG" + "花瓣在 item 内部" 别糊边（尺子：整体捆进来=item，整体内部标出=花瓣）；③ role 落成"(成员,圈) 键的边表"（= 06-28 §九C 旗标的 `identity_role` 焊 content_groups 该修的正解）。

## 七.7、Draft 机制 + member 三份真相（07-02 夜→07-03 续 · ⚠ 全部待细化）

> 从"draft 是什么"聊到"draft 其实溶解成笔记的一个视图+态"，再到 member 的快照模型。**都是方向，未定稿。**

### draft 是什么 + 对人/对 AI

- **draft = 圈的"产出笔记"用法**：可编辑、锚定源、带角色、带序的**半成品骨架**，坐在"理解(圈/CG/item)"和"成品(note prose)"之间。同时是：计划/骨架 + 带收据的(锚回源→抗幻觉/爆了能重建) + 可当 proposal。
- **对 AI** = 工作台/思考痕迹/可检索记忆；**对人** = 方向盘/掀开的引擎盖(steer 处) + 审计(为啥在这→顺锚回源)。默认后台搭好(~80%)、想 steer 再开。

### 四个产品参照(搜的，教交互)
- **Gamma**：大纲先行(AI 出大纲+参数让你改→再铺全 deck)；第一版 ~80%、人 review 10–15 分。
- **GitHub Copilot Workspace/Coding Agent**：计划即可审工件；**改上游→下游自动重生**；计划是"要什么"不是 prose。→ **核心循环**。
- **NotebookLM**：只用你的源 + 逐句引用回原文；实测幻觉 ~13% vs 无锚 ~40% → **锚=抗幻觉的实证**。
- **Scrivener 软木板**：索引卡拖排、看全局、Commit 落定；"grow a book rather than write one"。→ draft = 数字版软木板。

### 大跃迁：draft 溶解成"笔记的视图 + 态"（塌一层）
- **没有独立 draft 对象**：它 = 同一份笔记的**「结构视图」+「AI 主导那个阶段」**。
- **一份东西**：一组带角色/序/锚的成员(= 圈 = 骨架)；**四张脸(视图)**：正文(A4)/画布/软木板(卡)/大纲(列表)——乱了切大纲、看全局切软木板、读切正文(接现有 page vs canvas 双视图)；**两个状态**：AI 主导(成员→自动渲染正文) / 人接管(直接改正文→归人、AI 不再自动盖)。
- **「从哪儿来 vs 到哪里去」(Henry 的钥匙句)**：草稿只答"从哪儿来(来路/provenance)"，永远答不了"到哪里去(正文是活的、有自己的未来)"。→ **根本不需要"人改了回灌草稿"**：草稿不是真相、是来路；真相永远是当前正文；AI 读正文(+锚)就懂，草稿只在追来路时翻。

### 两个叉，已拍
- **叉 A（改笔记 vs 改草稿）**：**人必须能直接改正文**(红线：AI 能改的人 100% 能改)。**草稿里改=协作(重生)；直接改正文=接管(AI 停自动盖、标"人已改")。**
- **叉 B（草稿 UI）**：大纲列表 & 软木板是**同一份的两个视图**，非一期二期。软木板=空间/全局，大纲=线性/可搜(找不到元素时的退路)。都要、都融进笔记。

### member 三份真相（Henry 澄清的核心 · 快照是"原文的"不是"member 的"）
1. **原文**：活的源，会变/在别项目/甚至没了；
2. **原文快照(=引用副本)**：抓那一刻**原文长啥样**的**冻结副本 = 一张来路收据**；
3. **member 本体**：工作副本，刚生成=快照，之后可独立改(改通顺/措辞)，**改它不回写原文**。
- **本质区别**：快照是**原文的**(关于源的 provenance 凭证) ≠ member 的(那只会是自己编辑的 undo-history)。选前者才对。
- **payoff**：member 自足 → 怎么改正文/合并/拆分/全删**都坏不了**；冻结收据**随 item 走 → 跨笔记/跨项目血统不丢**(治 06-28"多源 ContentGroup 抹掉血统")；**设计初衷就是为 cross-note/cross-project**。
- **"糊"其实不是事**：我(Claude)一度担心"合并/拆分后成员↔块对应会糊、要硬自动 rebase"——被 Henry 的快照模型消解：不需自动维持；快照永远有效；结构大改就**人肉重选引用**(反正是你自己改的)。**唯一小残 = 漂移检测**(能不能"刷新到源当前态")，和 annotation 的 range_text_cache 同源、可选、优雅降级；光"从哪儿来"冻结快照已答完。

### 高阶/Agent 层（题外·灵感·非现在建）
- **目的间「态射」**：判断近似目的用 homo/iso/单/满——日常复习↠期末复习=满射粗化(商)、期末↪日常=单射嵌入、同结构=同构可复用；**可"用态射从已有目的导出相似目的"**。
- **事件内「可复合思考运算」**：圈/事件可挂一份 Agent 的**前提/透镜/思考模式**(如"按经济学、无税")，透镜**可复合(流水线)、跨事件叠、沿嵌套继承**。
- **数学校准**：真金是"可复合的态射/运算(幺半群/范畴)"，**literal 的环/域装不进**(无自然的乘法+分配律；硬定义得出布尔环[交=共识/对称差=对照]或算子环[复合=非交换、顺序有义]，只作灵感、不落数据模型)。

## 七.8、圈 ≠ draft + 目的=局部知识图平台 + 跨项目综合（07-03 续 · ⚠ 待细化）

> 纠了一刀(圈≠draft)、把 relation/跨项目那块也顺进了同一个平台。

### 圈 ≠ draft（纠正七.6的过早合并）· 三种寿命
- **圈(purpose-frame=目的)= 常驻的「目的组织」**(一目的 + 一组带角色带序的成员)；**durable，笔记生成完它还在、可复用**。
- **draft = 瞬态「提案」**(把某目的渲染成可审半成品)；**点确认即化成正文**。
- **正文 = 常驻成品**。→ **草稿化了、圈没化。** 草稿是"圈→正文"路上一次性的桥。
- **图层**：一份笔记可为多目的画多圈 → 按目的分**图层**(复习一层/日常一层)，v1 一次看一层；**底下 item 共享**，同一段原文可进多个目的的 CG，角色/颗粒度随目的变(theorem±example)。
- **中间衔接**：圈→渲染→草稿；草稿里 steer 改的其实是圈；确认→化正文，圈留下；之后人接管正文(改 prose=归人、AI 停自动盖)。
- **像 Excel 多 sheet**，但**底层 item 共享**(不是三张独立表，是"同一堆内容、三种目的组织")。

### 目的 = 局部知识图的平台（打通 Relation 视图）
- **局部图 = 目的的又一张脸**：item=节点、relation=边。四张脸→五张(正文/软木板/大纲/**关系图**)。**天生 purpose-scoped**，换目的换一张图(图也相对不焊)。
- **废掉旧想法**："图塞进 group folder"不用了；**目的就是图的天然 scope/家**。接 06-28"图是长出来的、GraphRAG=可重建 sidecar"。
- **端点资格 = 向量,不是标量**：光秃秃没进任何目的的 item=标量、连它没意义；进了目的+带角色=向量,才够格当端点。**relation = 同一目的坐标系里两向量之间的边**(反 GraphRAG 那道闸的深层原因)。

### 跨项目综合（Henry 一直卡的"凭什么做跨笔记/跨项目 relation" → 打通）
- **"跨目的 relation"是假问题**：relation 永远**在一个目的里**连；要连分处不同目的/笔记/项目的两端 → **新建一个同时装着两端的目的**(=揉进一个画布),在那儿连。连线动作 = 建一个装两端的目的。**(向量在不同坐标系不能直接连,先拉进同一坐标系。)**
- **打通靠今天两件事合力**：① 目的是**跨笔记/跨项目的 view-scope**(不被 course_id 焊死；落 06-28"local 是视图 scope 非存储边界"，解 cluster C)；② item 自带**原文快照(源收据)** → 跨项目捞进来也**各自带血统**(治"多源 CG 抹掉血统")。
- **目的必须搭一个载体(笔记/画布)**：目的=方向,不能只有方向没大小,得有标量载体；**目的 + 承载内容 = 一个完整向量**。
- **一颗钉**：跨项目的目的**住在用户"无墙空间"(家)**、不被任一项目拥有、跨项目**引用** item(靠快照自足)——依赖"拆墙"。

## 七.9、目的的用户视角 = 图层 / tab + 副本分叉（07-03 晨 · Henry 半梦半醒洞见 · ⚠ 待细化）

> 从"目的在用户视角里到底长啥样"起。Henry 拿 Excel 左下角 sheet tab 打比方，又立刻纠出关键区分。

- **用户视角 ≈ Excel 式左下角 tab，但语义是「图层」不是「白纸」**：Excel 的 sheet = 张张独立白纸（工程文件=一沓纸、随时往下加白纸）；**目的 = 叠在同一堆共享底料上的图层，且不同目的内容可略不同**。tab 切 = 切"看哪个目的的正文"。

- **副本复制正文/布局、但不自动带 item**：新目的进来是"纯文字/纯布局、没被任何 CG 引用"，然后**在里面新建引用或复用已有 CG**。
- **CG 绝对可复用、但不是所有 CG 适用所有目的**：同一 theorem-CG，不同目的挂的 member 不同（日常学习 vs 期末复习 = **同材料的多种使用形态**；为精简可删冗句、不影响 CG 使用）。→ 兑现七.6"CG 共享、(member,目的) 边随目的变、圈只给方向"。

**Claude 的三点（拧 + 分叉 + 提醒）：**
- **拧点（重要）——"引用"有两种，别一起清**（07-03 map 印证）：(a) **溯源锚**（prose ⟷ 源 span，`note_block_sources`/`source_anchors`，已 LIVE）；(b) **CG 组织引用**（member 属哪个 CG、扮啥角色）。副本要**保留 (a)**（否则复制过来的正文=无锚=按抗幻觉规矩=生成/标红，白丢血统），**只清空 (b)** 留给重新策展。

## 七.10、目的的成熟用户模型 + 端到端旅程（07-03 长谈收敛 · Henry×Claude · ⚠ 待细化但方向较定）

> 承七.9。从"目的=图层"一路谈到收敛定义 + 用户旅程 + 精简。**修正七.9"图层 on 一篇笔记"的过早框**。

### 收敛定义（一句）
**目的 = 一个「意图 + 在一池料上的装配」，它渲染出一篇笔记。** 之前打架的三个面（① 生成面：传文档总结 ② 图层面：一篇笔记叠多目的 ③ 装配面：跨笔记拉一起）**是同一个原语，只是「舞台（料池）」宽窄不同**。

### 舞台旋钮（化解 X/Y 之争）
料池是**从窄到宽的连续旋钮**：窄=就这一篇笔记的内容；宽=主笔记+若干辅笔记+源/整个知识库。**"在一篇笔记里换目的（舞台=这篇）"与"跨笔记装配"不是两种机制，是同一操作、旋钮拧窄/拧宽。** 生成默认"这篇+它的源"、复习装配默认"用户挑的笔记/CG"。

### 关键区分：组织 ≠ 正文（拧准七.9）
- **组织**（建 member → 成 CG → 连 relation = **局部知识图/节点+边**）= **镜片**：同一堆内容可叠**多个**目的的镜片、**免费、非破坏、不产新笔记**。
- **正文**（渲染出的成品、人会接管去改）= **一篇 = 一个目的**：只有**提交（apply）**才成笔记；想要第二种组织的**成稿** → **兄弟笔记**（共享内容池）。
- 一句话：**图 = 可随手换的镜片；正文 = 提交的成品。** 该降级的是"多篇正文塞进一篇笔记的 UI"，**不是**"组织可多层"（组织本就该能多层）。

### 用户视角 = 大多在后台（七.6 铁律）
可见单位 = **笔记**。目的只在薄接口露头：生成时问"这篇干嘛用"、复用时"从哪几篇拉"、掀引擎盖 steer、**关系图（purpose-scoped，目的唯一较显式的一张脸）**。**Excel 直觉放对层**：项目=工作簿、笔记=sheet/tab、**底下共享一池内容**（比 Excel 强在这）；tab 切的是**笔记**、不是一篇笔记上的目的。

### 整理 = 建局部知识图（Henry 综合，确认）
"标 member → 成组 CG → 连 relation" = **建局部知识图**（节点=item/CG，边=relation+归属）。与七.8"目的=局部知识图平台"合流。**习题↔definition/theorem 的交叉引用 = 目的图的边**；checklist/formula sheet/带交叉引用的习题库 = relation 丰富的目的图**渲染成正文**——"整理=局部知识图"的兑现处。

### 端到端旅程（精简版）
建 project → 传料（项目/source 库）→ 两条路 **[自建 / Agent 建]** → **目的驱动出草稿**（proto-note，可编辑）→ 在草稿上边玩边改（粗细/布局/截图vs重建/拉 sticky/补漏/括原文）→ **apply 成笔记**（初始目的=默认目的）→ 日后换目的/跨笔记装配 = **舞台拧宽**。

### Claude 挑出的 4 处绕路（精简掉）
1. **冲刺复习别逐篇 re-purpose**：舞台一次拧宽到多篇笔记 → 直接出融合清单（一趟顶五趟）；逐篇是白走，除非独立想要每章一个复习镜片。
2. **Agent 分支别"先建空壳再求建笔记"**：草稿本身=proto-note；"先建空白笔记"只属自建分支。
3. **开场别问微决定**（重建 vs 截图 等）：那类挪到草稿上改（改草稿循环已在干）；开场只收高层（目的+选料+大致风格/重点）。
4. **别用长盘问挡在出草稿前**：快出 ~80% 草稿当对齐工具（人看到草稿才知道要什么）；"AI 判断叙述符不符初始目的、荐改目的"很好，但主要发生在草稿上。=Gamma/Copilot 模式。

### 两个统一/裁决
- **自建 = Agent 建减去 AI 那版初稿**（同一套 member/CG/relation/布局工具、同一个产出；红线：Agent 能编人能编）→ 解 park 的"自建怎么搭知识图"。
- **默认 1 目的 : 1 正文**（提交级）；组织级可多镜片。跨项目 = 同机制、池更宽（要"拆墙"、后议）。primary=默认非父。
