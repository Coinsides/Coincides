# Better Notebook：悬浮参照工具栏设计讨论

## 一、想法来源

在 ECON 课程复习中，AI 生成的 HTML 笔记包含一个跟随页面滚动、可以展开和收起的悬浮气泡窗。气泡窗中只放置了一份 variable table。实际使用证明：用户可以在不离开当前阅读位置的情况下反复查看变量含义，明显减少页面往返、上下文切换和工作记忆负担。

该 HTML 案例只有一份稳定网页和一种参照内容，没有经历 Coincides 中多对象、跨页面、来源锚定和内容更新等问题。

## 二、已经确认的设计核

- 参照入口跟随当前视口，不随正文滚走。
- 入口可以收起和展开。
- 收起后占用空间很小；需要时可以快速恢复参照内容。
- variable table 是已经通过真实复习验证的高价值内容。
- 该设计的目标不是装饰笔记，而是让参照内容与当前学习任务同时在场。
- 它确实能够降低导航成本、上下文切换成本和工作记忆成本。

## 三、已经提出、尚待继续剖析的扩展方向

- 气泡窗可以从“单一 variable table”扩展成类似工具栏或参照架的结构。
- 用户可以主动把当前需要反复查看的参照材料拖入其中。
- 气泡窗不应只服务 variable table；公式、定义、表格、推理依据及其他高切换成本内容都可能适用。
- 当前讨论到的候选材料包括 Item、NoteBlock、Table、ContentRange，以及选定的若干页面。
- 当前倾向是不直接加入整个 PageFrame；是否支持 page slice、页面快照或页面内对象集合，留待后续讨论。
- 气泡是紧凑呈现形态；较大或较复杂的参照内容是否需要升级为停靠面板或并排视图，尚未决定。

## 四、后续讨论问题

1. 一个参照槽位允许指向哪些对象类型？
2. Item、NoteBlock、Table、ContentRange 和页面范围分别应如何进入与呈现？
3. 整个 PageFrame、若干页面、page slice 和 snapshot 的边界是什么？
4. 参照内容默认保持 live，还是允许冻结为 snapshot？
5. 参照架默认只属于当前学习 session，还是可以显式保存并恢复？
6. 多个参照不断积累时，如何避免它变成第二份混乱笔记？

以上问题暂不展开，等待后续真实复习动作继续提供样本。
