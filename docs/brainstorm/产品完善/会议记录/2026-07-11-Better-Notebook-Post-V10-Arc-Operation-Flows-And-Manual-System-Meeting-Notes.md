## 三、导出后移 + 磨合期展望

- **★导出后移（Henry 拍,07-11）**：导出**功能**从 S3 拔出,整体挪入 **V12 后的磨合期**——导出=把内部真相冻成对外格式契约,而 canvas/canvas object 仍在扩容、画布正走向无限画布,过早做=引擎每改一次撕一次格式（"一天一个样"要避免）。**导出不变量的措辞留在契约不动**（必带=原件+版次+锚收据/可抹=痕迹——原则不随引擎变）。

## 四、S2 细则预存：docx 页忠实

- **★页填充保守原则（Henry 提,进契约措辞）**：投影第 N 页永不包含原件第 N 页之外的内容——**宁可欠页,不可越页**（越页=页级溯源撒谎）。docx 导入三层优先级:页码不乱 > 格式尽量贴（标题/列表/行内结构 mammoth 可映射）> 字体放一边。
- **技术事实（免未来惊喜）**：docx 文件内**没有页**（页码=渲染时产物;文件只存文字流+显式分页符）→ "跟 Word 每页一致"无法从文件提取。**正路 = 摄入时 headless 渲染（LibreOffice 类）转 PDF 当「分页见证」**——原件 docx 仍是事实源,渲染 PDF 是派生页面真相,页锚指它（页码让渲染器作证,不让解析器编造）。

## 六、说明书体系（Henry 07-11 新洞察）

- **核心识别**：设计路线册 + 实测的过程,**本身就是建说明书和整理 inventory 的过程**——届时系统梳理:有哪些按钮 / 需要哪些 / 哪些多余 / 每个界面该有哪些;然后写操作说明书,**说明书 ≈ 路线册的 paraphrasing**。
- **双版本**：一版给 **Agent**（=⑮的 MCP skill 使用说明书,机器可读的操作协议）,一版给**用户**（人类可读)——同一路线册的两种投影,一次劳动两处消费（加上测试底稿=一石三鸟）。
- **★活文档纪律**：说明书是活文档——**每次版本更新时,检查改动方向/改动块是否需要说明书同步更新**（与 current-state 同步同族的版本收口检查项;届时进版本收口 checklist）。
- **inventory 审计**：按钮/界面元素的存在性审计（有/需要/多余）挂在路线册撰写过程中自然完成,不单独立项。
