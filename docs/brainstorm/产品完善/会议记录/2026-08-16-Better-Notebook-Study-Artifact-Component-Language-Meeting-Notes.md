## 二、三个深层事实

1. **组件语言 = 手写标本理论的实物化,1:1 映射**:目的声明头↔七轴②目的形状;骨架卡/讲稿页↔双层结构(§九);折叠答案↔提取练习(§二E);"你当时的作答"↔credence 个人层(§六);勘误卡↔缺口/不认同槽(§五);Anchors↔"AI 必须留数字"(§七);checklist map↔目的=终止条件(§十八)。**理论不是被验证了,是被 Henry 在实战中无意识地执行出来了。**
2. **统一 token 系设计系统已 de facto 运行**:不同会话、不同日期产出的 18 件共享同一调色板与组件 CSS——"格式成熟感来自默认值"的活证;导出编译器的设计系统有了现成的 v0(直接从标本提取 token+组件样式)。
3. **分享难题的消解确认**(Henry 前判成立):HTML 单文件=自足播放器——数学排版、图、可折叠交互、YouTube 外链嵌入均无需登录无需工程文件打包;**分享投影,不分享真相**(收据留家,成品旅行),与 fork-not-share 教义相容。

## 四、同日续:六项归位与 canvas 引擎减负声明(Henry 深夜盘 × Claude 定形)

1. **两种复习件类型**(阅读件=提效率/题库件=收题随查)=目的形状轴的两个取值,各配组件配方;模板族开放(闪卡件/错题重练件等自然增员)。
2. **合集串联**:真题合集已是单文件+sidenav 切 pane 结构;推广含义=**导出单位从笔记升到 Purpose**(整书架编译成一本书)——Purpose 级投影,零新概念。
3. **做题组件**:HTML 原生(选择/填空/勾选/拖拽,Möbius 即证;localStorage 可存答题态);"过程不好写"限制诚实认下,主观过程题走划圈问 AI 通道;**AI 判卷=harness+强推理模型,管线现成**。
4. **实时修改难——Henry 感觉正确**:直接改 HTML 成品=Lovable 困境;既定解=回对象层改+重编译("打散回画布"存在的理由),难题不进不绕。
5. **划红圈问 AI=锚+对话**:圈选即造锚(坐标+摘录),锚即 AI 上下文;Henry 在 Claude Code/Codex 的框选提问=同一交互的通用版;**本产品=专项化+简洁化(Henry 自我定位,亦即防淘汰答案:特化在自己的真相底座上)**。
6. **⭐ canvas 引擎减负声明(Henry;方向认可,边界 Claude 划,待拍)**:"没必要强行做永远做不到尽头的 canvas 引擎,只需最基础的"——与装配面优先/组件路线/HTML 交付同一结论第四次出现。**"基础"的边界:保留=写作顺手(12.2/总账第0号,一格不让)+组件摆放与流式装配+圈选与锚+打散重排;释放=自由画布无尽打磨+Figma 级空间编辑+炫技交互。减的是"无尽",不是"画布"。** 真相级范围声明,考后拍。
7. **一键换样式工具:难度低(限编译路线内)**——Henry 想象的难点是任意手写 CSS;编译器产物+统一 token(§一.9 已证 de facto 存在)下,**换样式=换 token 包重编译**,即 08-08 三层分速"样式层快"的具体工具形态(含 harness 调研风格→token 包→用户打磨的 agent 流);不做任意外来 HTML 的风格移植。

## 五、同日续:导出件的编辑模式——"可回家的投影"(Henry 提案 × Claude 定形)

- **Henry 提案**(以真题合集截图为例):导出 HTML 不能实时修改是大问题;设想=阅读模式默认+编辑模式按需;编辑模式**可改文字、增删段落,不必能改布局**;Week 6 文字板块本质可视为一个 paragraph block 在位;inline structure(行内公式)有望现场改/现场加。
- **Claude 判定:成立,且有二十年先例(TiddlyWiki 单文件自编辑自保存模式)**。关键设计=**编辑不是改文件,是在文件里记日志**:编译器给每个组件盖源对象 ID 章(出厂即带出生证:源自哪些对象哪个版本)→ 编辑模式下改动记录为**按块 ID 的编辑日志**(X 的文字 A→B;Y 后插段)→ 自保存(文件连日志重新下载自己,离线可用)→ **回家回放**(导入/同步时日志按 ID 回放到对象层→真相更新→重编译干净成品)。**两份真相的雷由此拆除:离家修改=在途修正层,非分叉**;冲突(家中对象亦变)套第三态规矩——不静默覆盖,按块对齐出候选。**"人类修正不丢失,机器重跑不覆盖"第四次适用,首次跨文件边界。**
- **分级**:v1=文字改/段增删+日志+自保存(难度低:contenteditable+data-id+内嵌 JS,先例成熟);行内公式=v1 标记待改(圈出回家改)、v2 内嵌编辑器(需内嵌 LaTeX→HTML 转换器);布局=不做(Henry 自划,版式归对象层)。
- **深层**:编辑模式的本质=**在投影里显影对象骨架**(阅读见成品,编辑见块身份)——只对编译器产物成立,对任意外来 HTML 不成立,再证"规格→编译"路线红利。命名候选:**可回家的投影(homing projection)**。

## 五之二、Henry 自我纠正:两场景分辨,homing projection 降级选装

- **Henry 分辨**(自察混淆):①**应用内打开**——应是全能力编辑(位置+文字),前提是在自己应用里;②**应用外单独打开 HTML**——场景=展示,修改非必需("修改也挺好"但不是本体)。
- **Claude 定形**:应用内的"它"根本不是 HTML 文件,是**笔记本身**(对象层在手边,全能力编辑天然免费,无需任何新机制);应用外=投影,核心能力是**使用**。**关键区分:「使用」≠「修改」**——折叠/勾选/做题/答题记录(localStorage)全是使用,改变使用状态不碰内容真相,**无需回家机制,v1 即有**(成品作为复习件的功能本体);仅**内容修改**需编辑日志+回家回放。
- **结论:§五 homing projection 由核心机制降级为 v2+ 增值选装**;关键路径零难点:应用内编辑免费/应用外使用便宜/应用外修改选装。"实时修改难"之忧不是被解决,是被**分类**掉——难的部分不在必经之路上。

## 六、逆向需求:自产件凭出生证回家,外来件当标本拆解(Henry 之问 × Claude 定形)

- **Henry 之问**:导出 HTML 自然,但逆向呢?①打开自产 HTML 能否后续工程化、能否定位到原笔记?②若此能力好,应用可成**调研工具**——把喜欢的网站另存为→导入→拆解设计→组件样式甚至功能搬进自己组件库。
- **方向一(自产件):§五 出生证设计已全款买下**——组件盖源对象 ID 章+文件带出生证 ⇒ 应用内打开=读章一键定位原笔记(对象在家,文件是指回家的投影);原笔记已删/异端来源 ⇒ **逆向编译重建**(纪律产物可反解析回对象,出处记"由成品重建")。**自产文件完全可逆:出生即带家门钥匙,圆程闭合(对象→编译→成品→定位或重建→对象)。**
- **方向二(外来网站):不做直接工程化(无章血团,吞并=真相层养异物),做拆解式调研,零件全现成**——①样式层快:senlindesign `/taste`(07-18 清单 C1)逆向提取 token 包+设计原则;②组件层慢道:harness 工程能力拆交互模式与组件结构→设计提案→Henry 拍→kind-general 注册(§三之四"harness 工程能力"首个具体用例);③**内容不吞并**:要用走 Source 管线窄腰门,与 PDF 同门。
- **定位:笔记工厂的逆向车间**——自产件凭出生证回家,外来件当标本拆解;拆解产物永远是自家词汇的 token 与 kind。窄腰哲学第 N 次适用:任何外物映射进我们的词汇表才许进门。

## 七、收官之问:新方向下的编辑形态(Henry 睡前之问 × Claude 定形)

- **Henry 之问**:现有双模式(页面=A4 纸可无限延展分页/画布=自由拖拽可有画笔)若向今日设计靠拢,编辑还和原来差不多吗?会更简洁吗?应用内打开笔记=打开一个网页吗?
- **钉句:视觉上是,本质上不是——所见即将得。** 编辑视图与导出成品**共用同一套组件渲染与 token**(看到的≈导出后的样子),但每块带对象身份与编辑把手,是**网页的活源**非编译产物("网页是笔记的照片,应用里打开的是本人")。
- **三个减法(更简洁的具体形态)**:①默认面从"A4 纸上二维摆放"变**一维组件流**(拖动调序,布局由流接管——装配面教义落到编辑体验);②排版由强默认预设接管(默认路径上无调节);③**A4/分页降级为导出关切**(网页无页;分页只在打印/PDF 输出轴上回答;纸的隐喻退役,PageStack 机器瘦身——Page 模式死胡同 🅰 亦为此转移投票)。
- **画布模式:保留,角色明确**——空间整理(摆卡/全局/墙)+圈选批注(划红圈问 AI/画笔住此),不追自由编辑器的无尽打磨。**流面写和装,画布摆和圈**——简洁不靠删功能,靠每个功能回到自己的 register。

## 八、真·收官:与 Claude design/artifact 的区别(Henry 之问)

- **钉句:区别不在做出来的那一页,在那一页背后有没有真相层**——artifact 的页是**终点**(对话附属孤儿成品,改=重 prompt,页与页互不相识,无溯源,无用户理解层的槽位,住 claude.ai 绑定一家模型);我们的页是**投影**(背后对象真相层:可打散/可定位/可回家;同一张卡的两次投影新鲜度可追;每句有锚;Guess 层/错题史/credence 是产品的中心;住自有服务器,三层不绑架)。**"Claude design 是会做漂亮页面的天才,做完就忘;我们是给这位天才配上记忆、溯源和一个家。"**
- **两个诚实推论**:①重叠真实且是好消息——"一句话得一页"那层智能我们**租**(外骨骼的穿戴者之一),需求被 artifact 验证,它变强我们跟着变强(模型十倍测试老答案);②Henry 的 18 件 artifact 即两种本体的实地对照——每次"不够好"之感,缺的都不是页面质量,是页面背后的真相层。**不是在重做 Claude design,是在补上它没有的那一半。**
- **追问(Henry):Agent 的设计部分可否套用 "open design"?能用我们自己的组件吗?** Claude 结构答案:两个可选位置——①**穿戴者**(经 MCP 工具面,设计动作全部落成对我们组件/token/装配序的调用);②**组件工坊工程师**(Onlook 型可视化改码工具→组件层慢道,产物经审查注册 kind)。成立条件=一条规矩:**穿戴者只许点菜,不许下厨**(菜单=组件库+token 系统;不许直接产 HTML 血团进真相层)。具体项目待查证("OpenDesign"细节我无把握,不猜),Agent 版评估时按老规矩跑调研(仓库实查+核验),连同与 impeccable/taste 已采购件的分工一并出清单。
- **配套落地(Henry 定协议)**:建**外部候选登记册**(`agent-ops/analysis/external-candidate-registry.md`,活文档)——边说边调研、查过即登记、永不重查;存量候选全部归册(穿戴者/品味 skill/专用工具/已排除/已作废各带形态判定与去向);OpenDesign/OpenCode 调研在途,回填待补格。

## 九、期末收官之问:make or buy 之后,不可 fork 的核是什么(Henry 考毕 × Claude 收口)

- **Henry(考完试后)**:很多东西不必自建,直接 fork 即可(make or buy 之理);但也要有自己的东西——**我们无法 fork、只能自己做的核是什么?**
- **Claude 收口(判据=资产专用性)**,三层:
  1. **真相层的语法**(五真相/锚/出生证会员卡/第三态/机械新鲜度/收据不门禁)——难的不是实现是判断:每条规则都是真实使用换来的拍板(V9 软删雷/origin_purpose_id/"使用≠修改")。**可 fork schema,fork 不走产生 schema 的两百次拍板;没有判断史的 schema 下个岔路口就拍错。**
  2. **末端执行器**(锚枪/铸卡钳/组件语言/订单规格/划红圈问 AI)——形状由笔记语义决定(改锥由螺丝决定);为本真相层特化的工具面市场上不存在。
  3. **最深核:学习理论本身**——产品=一套可运行的学习理论(理解前后分工/教学装置/提取练习/囤积解毒/目的=选择函数/Guess 层 AI 不可产),其来源是不可复制的闭环:**Henry 学习→反思→蒸馏成机制→再用它学习**(本期末季即证:18 件 artifact/手写标本/组件语言皆"你学习"的副产品)。**别人 fork 走仓库,fork 不走你。**
- **钉语三连(至此凑齐)**:智能会贬值,真相不会;智能是租的,手是自己的;**手为什么长这个形状——那个"为什么",就是核。** 买手段/租智能/造意义(判断的语法+特化的手+学习理论)。
