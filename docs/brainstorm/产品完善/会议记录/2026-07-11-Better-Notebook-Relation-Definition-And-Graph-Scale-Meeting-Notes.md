## 二、定义（Claude 提案,Henry 暂搁未拍）

- **五边家族对比定义**：Link(去哪看)/收据(凭什么说)/Purpose 成员边(在此目的下演什么)/视觉连接线(画面怎么摆)/**Relation=唯一两端皆知识节点、内容为一个判断的边**。
- **定义句**：Relation = 一条被记录的判断:两个合格知识节点间的语义关系,经人确认(或人验收 AI 提案)后成为真相。承重词:判断(思考行为的沉淀,存在即痕迹)/合格节点(端点资格制)/确认(proposal-first,真相需要人的时刻)。
- **作用三方**：给人=连招的外化(思维动作的自画像,跨域发现);给 AI=联想的基底(GraphRAG 遍历/目的域上下文编译);给系统=第五真相封顶(点 CG+圈 Purpose+线 Relation,知识层三件套齐)。

## 三、视觉线 vs Relation 呈现（Claude 三拆,Henry 暂搁未拍）

- 三个缠在一起的问题剪开:①真相问题(线≠关系,已拍死)②投影问题(真相能否投上画布)③表面问题(消费界面有哪几个)。
- **重量住在创建不住在显示**:Relation 重在建(判断+确认),投影轻在显(开关镜头,读时派生,不落 canvas_edges 行——相对不焊在渲染层)。
- **三窗一家**:画布关系镜头(在场者之间,开关+预算)/局部图谱(跨场邻域遍历)/Inspector(列表,零污染)——同一真相的三扇窗,非竞争。
- **纸上无线**:关系线永不穿 page 内部,page 里 CG 顶多戴徽章。
- **线与关系合法接触点仅两个**:产房(合格端点间的线可递 RelationProposal)+ 自愿绑定(relation_backed=画布上的个人注记)。

## 四、图谱尺度重构（Henry 核心输入,本卷主戏）

- **对现有知识图谱的批判**：市面上（含 Henry 自己此前设想）全画得太大、太浅——花哨的粗糙点线,**点的细节必须展开才能看**,用户日常根本不会启用。Claude 锐化:它们是"用来看的地图",不是"用来看穿的镜片"。
- **★微观·单点射线视图 = 真正能进日常的那个**（Henry 数学生场景:non-cumulative 期末复习,看到上半学期的 definition 发懵→只看专属这个 definition 的一条线/一张小网:连哪些 theorem/lemma/definition=主线,example/remark=二三级支线）。**核心原则:微观尺度下节点渲染为内容,不渲染为符号**——直接可读的小网=阅读视图,不是可视化。**主线/支线分层是视图策略按 item 类型读时排的,不存关系里**（相对不焊,排序都不焊）。
- **Claude 对齐确认**：微观射线视图=Henry 二月认知模型（"点常驻,网被点唤醒"）的 UI 化——唤醒做成了界面。
- **尺度三档定型方向**：微观·单点射线（阅读伴侣,侧栏/浮层,大概率不长在画布上）/ 局部·笔记域（本篇骨架,复习定向）/ 宏观·课程全局（跨域发现,低频不可缺）。**宏微皆需缺一残废（Henry）;三档=同一真相的三个焦距,非三个系统（Claude）**。
- **笔记域图谱的范围定义候选（Claude,接 Henry 的 cross-note 场景）**：域=显式 frame——物理在场 item 默认入域;场外 item 人拉入或 Agent 提案人确认入域。**机制与 V9 目的圈押韵**（默认成员+显式拉入+proposal-first+跨笔记成员;是否直接复用 purposes 机器待议）。
- **★V11 第一颗承重钉（Henry 改名捅出的模型问题,标记不解）**：端点应为 **item**,CG 只是 item 的集合,单个 item 应可独立存在——但现状 member 只作为 CG 的一部分存在,"不进组的 item"无身份。三条路待掰:item 升一等实体(items 表,CG=捆) / 端点多态指针(便宜但无稳定知识身份) / 中间态 item=指针+收据(member 三真相同款形状,脱离 CG 强制)。V10 教训（身份不拆清必烂）适用——先想清再动。

## 五、item 与普通内容的本体论（Henry 抛出混乱 → Claude 提案「第三次身份倒置」,待拍）

- **Henry 的困惑（原话要义）**：Relation 应是视图角度,角度不能脱胎于根本（笔记）;但端点该是 item 而非普通内容——两者混掉了。验金石=Agent 思想实验:Agent 拆解引用源、铺笔记,它建的东西和 item 有什么区别?"我们把自己设定进去了"——item 和普通 content range 的关系没搞清。
- **Claude 诊断**：**CG 一表两魂**——用法 A"知识点本体"（一个 CG=一个知识点,花瓣=侧面）vs 用法 B"收纳篮"（一个 CG=装多个知识点,V9 纯化指的这半）。item 没有自己的身体,寄居在 CG 里;content range 无标记区分"知识点的肉"和"行文"→必然混。
- **★提案:第三次身份倒置（源、目的之后,切知识粒度）**：**Item=知识身份;content=该身份在某处的呈现（occurrence=指针+收据+模式,member 三真相形状复用）**。三层:内容层(呈现,会漂移,多数只是行文)→身份层(item,type/topic 固有=07-02 标量,不漂移,跨笔记)→判断层(relation,端点只能是 item)。"图谱根扎内容、穿过身份层"——内容是土,item 是茎,relation 是枝。
- **Agent 思想实验验货**：Agent=铸 item(身份+第一 occurrence 指源)→写 blocks(渲染某 item 的块登记为新 occurrence 带模式;过渡行文不铸 item)→CG 回归纯捆(装 items,Henry 原话字面成立)→进圈领角色。**"Agent 建的和 item 的区别"=没有区别**;人的内容被认领前只是内容——**item-ness=opt-in 认领**(人划选或 Agent 提案人确认)→稀疏教义在身份层锁死(不是所有文字配有身份,grow-by-use)。
- **成串掉落的问题**：端点漂移免疫(range 漂走收据降级,relation 不动)/cross-note 参与溶解(item 天然多笔记 occurrences,不需拉入机制)/微观射线的"节点渲染为内容"有了机制(occurrence 反查→邻居 items 用各自最佳 occurrence 出肉)/与 V10 咬合(源投影块=最忠实 occurrence 候选地)。
- **诚实账单**：items+item_occurrences 两新表(additive 路径:members 加 nullable item_id,旧 member 照活)/花瓣归属重想/V11 范围变(端点收窄目标从 CG/花瓣变 item,收编方案重排)/命名与认领 UX 待议。**方向待 Henry 拍,细节走老流程。**

## 六、关系连的到底是什么 —— 根源与关系三真相（Henry 挖出空档 → Claude 提案,待拍）

- **语境对齐（Henry 定）**：item = 脱离 CG 的 member,自带三真相包（指针+快照+本体）;Claude 上一轮"纯身份+多 occurrences"降级为将来推广形态,**v1 按 member 形状落**（离现有机器最近）。
- **★根源的精确名字**：**关系绑定的是身份,但关系的依据是内容——而内容（item 本体）是活的**。建关系那一刻看的是两端本体当时的样子;之后本体被人/Agent 修改,身份、指针、快照都没变,**但判断的依据变了**——系统里没有东西记得"判断基于什么作出"。不是端点选错,是**判断没留收据**。
- **两跳两收据看清空档**：源 range →(item 快照守,已建成+stale 刚修)→ item 本体 →(**无人守,空档在此**)→ relation。
- **★解法:关系三真相（宪法第三次应用）**：关系 = **端点身份对**（活,图结构永不漂移）+ **判断收据**（冻结:创建时两端本体的摘录+hash）+ **关系本体**（类型/方向/注记,关系自己的可编辑部分）。端点本体被改 → 读时比对本体 vs 判断收据 → 亮徽章"此判断基于旧版内容"→ 用户三选:**重申**（刷新收据）/**撤销**/**不管**。永不静默失效、永不静默假装成立。
- **对称性**：item 用快照盯它的源,relation 用判断收据盯它的端点——同一套漂移检测文法（source_sync_status 同构),两层各盯各的下游,零新发明。
- **三句话答案**：连的是身份;依据的是本体（冻结成收据）;面对的是活内容（漂了亮徽章,人裁决）。
- **视图后果**：看板 graph/微观射线的"乱"=静默不一致的恐惧 → 收据转化为可见新鲜度（实线=收据吻合/虚线徽章=依据已漂）;微观射线邻居照常用**当前本体**渲染（读要最新）,边上另标判断新鲜度——**读的是现在,判断新鲜度另行标注,两个时态各归各位**。

## 七、关系收据的性能账（Henry 质询"划算吗" → 实算,买+三纪律）

- **场景**：100 页笔记 / ~200 节点 / 稀疏教义下 200~400 条线。
- **存储**：收据=**摘录(每端≤500字)+指纹(hash 64B)**,单条 1~3KB → 全篇 ≈0.5~1MB ≈ 笔记正文一份复印件 ≈ 一个 PDF 的几十分之一;十年百篇 <100MB。**增长跟动作走不跟日历走**（只在建关系/重申时产生）。
- **计算**：**时间戳先行**——端点 updated_at ≤ 收据时间→直接实线零开销;否则才 hash(微秒级)。400 线全量检查 <1ms,读时派生,无后台任务。收据默认不进 AI 上下文(07-10 教义),不烧 token。
- **★真实成本=注意力不是字节:徽章疲劳**（改一张 30 线枢纽卡→30 徽章齐亮）。两颗止痛药:**徽章聚合**（亮卡不亮线:"此卡 5 条关系待复核"）+ **批量重申**（改卡后一键刷新收据）。
- **判定**：买——不买的代价是十年后一张不敢信的图（每条线都可能是静默谎言）,而可信是产品立身之本。**三条纪律**:摘录 500 字封顶 / 时间戳先行 / 徽章聚合+批量重申。

## 八、复核负担的消解（Henry 抗议"每卡每线手动复核太麻烦" → 非强制铁律原样搬入）

- **Henry 的两难**：既不能让用户不知道系统做了什么,又不能让用户做太多（已有 Agent 在场）;每卡每线待复核=难受。
- **Claude 认领错误**：上一轮"待复核"三个字是错误根源——"待"=义务=红点=追人。解法=Henry 自己的铁律搬入:**"爱核不核,但你一旦想核,一切都在"**（非强制原则应用于图谱维护）。
- **三层设计**：①**Agent 过滤泵漏斗**——时间戳/指纹（零成本,多数编辑到此为止）→ Agent 语义等价判定（本地 embedding/小模型:错字润色=挂安静小注"AI 判仍成立",不亮灯不进箱）→ 仅真语义漂移（~1%）进**收件箱**附建议（重申/撤销+理由）,你去找它、它不找你;②**诚实底线**——Agent 不许悄悄刷新人判收据（=伪造"你看过并重申"=洗白）;AI 判定自己署名挂旁边（诠释不冒充证据）→ 新鲜度四档:人判如新/已变·AI判成立/已变·AI存疑/已变·未检,仅"存疑"有视觉重量;③**无为安全**——不复核的最坏结果=一条诚实标注"基于旧版"的线,不烂不骗不传染（图书馆旧书）。
- **★核心反转**：**收据买的不是"让用户干活的机会",是"系统敢于安静的资格"**——什么都烂不掉,才敢不催人;无收据的系统才被迫焦虑。
- **UX 三军规**：徽章改名"新鲜度"（状态非任务）/ 无全局红点（新鲜度只在看到那条线时就地显示,收件箱=想去才去的房间）/ 批量重申=给勤快人的快捷键非作业。

## 十、拍板修正 + Agent 时代维护规则（Henry 复盘两隐患,2026-07-11）

- **★500 字封顶出局（Henry 嗅觉:魔法数=隐患;Claude 认错）**：截断收据防错了地方（改动恰在截断外=收据沦为装饰）。替代 = **快照去重存全文**：建 item 快照表（按 item+内容指纹 去重,同卡同版本全系统一份快照）,关系收据**指向**快照不复制 → 比截断更便宜（30 线共享一份 > 截断×30）、收据永远完整、**顺手预建版次链雏形**（将来出版机器直接住进去,零返工）。病态大 item 的防守挪到策展层提示（"这卡像整页文档,拆?"）——治卡不剪数据。**三纪律修正为:快照去重存全文/时间戳先行/徽章聚合+批量重申**（§九拍板相应修正）。
- **Agent 顺手维护三护栏（Henry 场景:用户改过东西后让 Agent 读笔记答问 → 方向拍,姿势钉死）**：①**加权阅读**——收据是 Agent 食材,漂移关系采信打折,不需问人;②**顺手体检+署名判定,永不代签**——路过跑语义等价、挂 AI 署名判定（过滤泵从"改动时跑"扩展到"被阅读时跑"）;人判收据代签=伪造=洗白,红线不动;③**汇报不打断**——任务中不弹维护询问（=nag,违铁律）;答完问题末尾附一句"读到 N 条依据变过,M 条存疑,在收件箱";用户说清就批量出建议一键验收。
- **★意外礼物:使用驱动的新鲜度**——Agent 按目的域读取→顺手体检的永远是正在用的那片→**常走的路永远干净,没人走的走廊落灰无妨**;维护精力自动按使用分布,零全库扫描。grow-by-use 的镜像:decay-by-disuse,十年尺度系统的正确品格。

## 十一、维护触发器与 harness 形状（Henry 提定期+顺手混合、自疑定期 → 定期判死,三触发器定型）

- **定期(cron)的结构性死因**：①local-first 桌面应用无常驻进程,日历任务大部分时候无人执行（云模式走私品,非参数问题）;②"每 N 小时"=又一个魔法数;③打磨没人走的走廊（违使用驱动新鲜度）;④醒来徽章风暴。

- **★Harness 四零件 + 不建队列的巧**："待体检清单"**不存表、是查询**——端点 updated_at 晚于该边最后判定时间的所有边（时间戳+收据俱在,worklist=派生视图;相对不焊管到维护系统自己头上）。零件:改动防抖钩子/阅读钩子/空闲消化器(限额跑派生查询)/署名判定存储;判定模型=本地小模型/embedding(4060),零 API、零云假设、零日历承诺。

## 十四、原料与铸卡——item 模型完善（Henry 的"背景引用库"直觉 ≡ Claude 的"铸卡",词汇误会拆除后合流;待拍）

- **词汇澄清**：Claude 的"卡"=Henry 已拍的 item（member 形状）,无新概念;"两个原片段铸成一张卡"指**两个尚非 item 的原料片段**共铸**一张** item——**融合发生在原料→卡的边界,不在卡与卡之间**（两个 item 放一起=捆=CG,Henry 直觉对）。
- **病根与解药**：旧模型强制 1 剪藏=1 member → 两 member 融不了（Henry 抓出"目前做不到"）。解药=**收集≠成卡**：收集进来的是**原料**（锚+快照,无知识身份）;卡是**被铸造的**（本体=人/AI 写出的综合文本 + N 条锚指回各原料）。**卡的锚 1→N,融合问题消失**;"用原句"=N=1、本体=快照的退化情形,零特殊处理。
- **★四层楼（Henry 的背景引用库 = 此模型,零距离）**：**原料池**（锚+快照无身份——收进的 range/表格/图片先躺这儿;**不需新实体**:池条目=member 三真相的收据半边单独存在,CG 面板加"原料"区）→ **卡**（铸造,消费原料）→ **捆**（CG 组织卡）→ **圈**（目的下领角色）。原料融进卡,卡捆成组,组进圈——三个介词各管一段。
- **花瓣问题的最终回答（Henry 理解确认:花瓣从来是 Agent 的活）**：装配活→被铸卡接走（花瓣当年的跨 member 装配=铸卡本职）;侧面标注→Agent 需要那一刻现拆（闪卡正反面/射线分组）,**拆完就扔不落盘**;"给谁看"=给那些场合本身;无存储层→无"纠错标记"问题——AI 理解错了,用户改**卡的文本**不修标记（改文字比修标记永远更自然）。

## 十五、四层楼模型的复述确认与两处精化（Henry 逐点核对,2026-07-11）

- **"库"= 收据行的两个状态（精化一）**：CG 的库=**原料区**（未被铸进卡的材料,躺着待用）;卡的库=**锚集**（已被认领消费,随卡走的证据链）。同一种行两种住法;铸卡=把原料从"躺着"变"承重"。非第三个新实体。
- **本体≠库文,指向+模式（Henry 复述=模型心脏,确认）**：卡是你的话,站在它们的证据上;差多远由锚上模式诚实标注（照抄=直引/换说法=转述/融合新写=蒸馏）——抗幻觉文法在卡尺度的落地。
- **"别引太多"的正确表述（精化二）**：**不设硬限,设承重原则**——每条锚必须真正承重（证据非装饰）;自然分布 N=1 居多、综合卡 2~3;超了用策展提示（"引了12处——是不是该拆?"）,同病态大卡提示族,**提示不封顶**（数字过敏适用）。效率无虞:锚=几行字,漂移检测按锚时间戳先行。
- **"一一对应"的警戒（精化二之二）**：卡级对应（卡整体对 N 锚负责）=对;**句级映射（这句对锚1那句对锚2）=花瓣从后门回来,打住**——子卡结构 AI 读时派生,不落盘。
- **收总**：member 三真相复数化——**N 原文/N 快照/一本体**;证据复数,作品单数;每锚各自漂移/模式/血统,机器原样复用零新发明。

## 十六、原料区的纪律问题（Henry 预警:旧模型"每引必用"的强制没了 → 纪律搬家:结构约束→协议约束）

- **Henry 的洞察**：旧 1:1 模型的缺点（融合不可能）背后是优点——**收集与使用焊死**,AI 想囤囤不了;背景引用库拆了耦合,松鼠症风险应运而生（收50铸3剩47烂池里;"稍后读"工具坟场为证）。
- **两个事实改变解法位置**：①**原料=可重建派生物**（锚+快照指向库中活源,删之无损）→不受"心爱之物"红线管,工作台非档案馆,清桌伦理安全（对比:卡有本体是作品,受红线管）;②旧耦合的成本征在人头上（剪藏时刻被迫过早承诺,打断心流）→拆耦合对人纯收益;**纪律问题本质是 AI 行为问题,解在 Agent 协议层不在数据模型层**。
- **★四条协议（全为老文法复用）**：①**剩料必须交代**（任务收尾报告"收12铸5剩7,留还是弃?"——proposal-first 收尾版:收料=暂存提案/铸卡=产出/剩料=待验收）;②**出身分级生命周期**（CG 双重性教义适用:人收的料=永久保留+非强制清桌提示;AI 收且人未碰的剩料=任务级瞬态,默认退场可 pin）;③**度量口径进 harness**（评铸卡承重率不评收集量,松鼠症失去动机）;④**原料区策展提示**（"23条三个月没动——批量清?"提示不强制,清了不心疼）。
- **★原则（今晚第三次同款动作）**：非强制维护/收据=敢安静的资格/**原料区靠"囤积无处藏身+清扫零代价"保持干净,不靠禁止囤积**——结构层管不了的德行协议层管,且管得更温柔。对 AI 的要求变化=升级:旧模型逼 AI 过早承诺,新模型允许先搜集后综合但账要清——**会做账的 AI 比不许进货的 AI 是更好的研究员**。
