## 二、Source 该怎么定义（Claude 综合 · 待拍）

> Henry 抛出的问题组：Source 怎么定义？外部源那么多格式（PDF/Word/Excel/代码/图/音视频/3D/设计工程包），v1 做哪些？**内部源是什么——是不是只有 note？** 内外部文件怎么进系统、怎么复用？content_range 和两种 source 怎么建引用？还要给以后的复杂导入（PSD/视频）留空间。
> 以下是 Claude 的推理整理权衡合并。与 `docs/ARCHITECTURE.md §Source Reconstruction Adapter`（重建≠生成、候选不直写真相）和 roadmap V2.BN.10 范围（上传+基础解析非-Agent+原件不可变+薄绑定）已对齐。

### 2.1 定义：Source 是「角色」，不是「格式」——双层定义

- **第一层（关系/角色，相对不焊）**："source" 是一个**出处角色**——任何内容都可能扮演"另一段内容的原文"。一篇笔记可以是另一篇笔记的源；一个 CG member 的原文可以是外部 PDF 的一块、也可以是本子里的一段。**"是不是源"不焊在对象身上，它是引用关系的一端。**
- **第二层（实体，外部专属）**：**SourceDocument = 用户带进来的外部文件**。它有两条焊死的（intrinsic 的）性质：① **原件不可变**——证据根（①层），进来那一刻冻结，永不原地编辑（想改=产生你自己的内容并引用它）；② 可选地拥有一份**忠实可寻址重建**（②层 SourceArtifact）。
- 一句话切分：**系统里只有两种内容——"你写的"（笔记/CG/画布=活的、可编辑）和"你带来的"（外部源=冻结的证据）。引用文法对两者一视同仁；生命周期把它们分开。**

### 2.2 外部源的 v1 范围：能力阶梯，不是格式清单——**"可保存"与"可解析"解耦（留空间的钥匙）**

核心设计一招：**把"能进系统、能被引用"和"能被解析、能被深入寻址"拆成两个独立能力。**

```
能力 0（day-1 对一切格式成立）：可保存 + 可整体引用
   任何文件 → 原件不可变存（复用 canvas_assets blob 模式）+ content-hash + 文档级引用/预览
能力 1（按格式渐进）：可解析 → ②层 SourceArtifact（typed blocks + 定位器）→ 块级寻址/锚定
   v1 = 文本承载文档：PDF(born-digital)/docx/txt/md/xlsx表格（= 现有 native 解析器的能力面，当 degenerate 后端）
能力 2（后续版本）：强保真解析（PaddleOCR-VL/MinerU 管线，07-04 已选型）→ 扫描件/手写/公式/表格真寻址
```

- **这就是"留空间"的正确形状**：PSD、视频、音频、3D、代码 **day-1 就能进、能整体引用、不会丢**（能力 0 对格式无要求）；它们缺的只是②层解析器——将来加 = 在 SourceParser 注册表插一个后端 + 契约加对应 block kind，**零迁移**。第一版不封死任何门，因为门本来就不在格式上，在解析器上。
- **一个必须现在写进契约措辞（但不建）的口子**：**寻址空间是源类相对的**。页码+bbox 只是"文档类"的定位器；视频=时间段、音频=时间段、代码=行段、PSD=图层/画板、3D=对象节点。②层契约里"块的定位器"要留成 kind-相对的措辞（v1 表结构用 page+bbox 没问题，但契约文档明说"locator 形状随 source kind 扩展"），否则将来加视频就要动契约根。
- 代码文件：本质是文本，能力 1 几乎免费（行段寻址）——但 v1 不做专门处理，进能力 0 即可。

### 2.3 内部源：**不是只有 note——内部引用早已多元；note 是容器，不是源单位**

盘点现状（全部实证于代码）：CG member 的 kind 白名单已有 **9 种**内部指向（content_range / annotation / block / content_group / page_slice / canvas_object / table_region / image_region / future_object）；annotation ranges 指块内文本段；purpose_members 指 CG；note_block_sources 是"笔记→外部文档"的扁平原型。**内部可被引用的单位 = 五真相里一切可寻址的东西**，note 只是它们的容器。

**统一洞见（本次综合最承重的一条）**：内外部引用**共用同一套文法——锚 + 冻结快照（member 三真相）**，差别只在**源端的生命周期**：

| | 外部源 | 内部源 |
|---|---|---|
| 原文 | 冻结的证据（不可变） | 活的内容（随时被编辑） |
| 原文快照（收据） | 天然永真（原文不变） | **必需**（原文会漂） |
| 漂移检测 | 不需要（除 re-parse 出新版本） | **需要**（source_sync_status 的真正用途——目的层核查已确认它今天是死的，激活它属于这条线） |

也就是说：**V10 不是给外部文件另建一套引用系统——是把"已经为内部设计好的锚+快照文法"的外部端做实。** 一套文法、两种生命周期。member 三真相模型（原文/原文快照/本体）本来就同时覆盖内外——外部只是"原文永不变"的退化特例。

### 2.4 进入与复用

- **外部进入**：上传 → **content-hash**（① 去重；② **给源全局身份**——顺手解 06-28 §九C 盲点"同一 PDF 进两项目=两个无关证据根"，也是拆墙/跨项目的预埋缝）→ 原件不可变存 → SourceKind 检测 → 能力 1 格式走 ②层解析（v1 native 后端）→ 可浏览可寻址。不可解析格式停在能力 0。
- **内部复用**：不存在"进入"——引用即建锚+快照。（Reference/Duplicate/Fork/Materialize 复用动词族属 V12 CG 集成，不进 V10。）

### 2.5 引用文法（content_range × 两种 source）

一条锚文法统一：**(使用端：你内容里的 content_range / member) —锚→ (源端：某个 locator + 冻结快照 + 溯源模式)**。
- v1 = **薄绑定**（roadmap 已锁）：文档级 + 块级引用、可跳回、可显示出处。不做完整双向 provenance 链（那是装配时代）。
- 三个**预留字段/措辞**（06-28 §九盲点直接对应，现在留缝不建）：① **溯源模式**（直引|转述|蒸馏|推断——没它，蒸馏被再引时会被洗成证据）；② **note-as-source 的 offset 保留**（内部引用别钉死在整块，丢行级溯源）；③ **源版本身份**（re-parse/换后端出新 artifact 版本、锚指旧版本仍有效——07-04 契约的 content_hash+版本化已覆盖）。

### 2.6 Kano 视角：Source 是"当たり前品質"（must-be 质量）

Henry 引的理论 = **狩野纪昭（Noriaki Kano）的狩野模型**（品质管理，不是经济学——概念完全对）：**基本型需求做好没人夸、做不好必挨骂**。Source 正是典型 must-be：用户感觉不到它存在，但"传的文件丢了/引用断了/跳回跳错地方"任何一条都直接口碑崩。**设计权重因此全押四个不起眼的字上：不丢、不断、跳得准、错了好改**（第四条接 07-04 的置信度纠错 UX——手写中文注定 ~86%，"改得快"比"抽得准"承重）。不押任何炫技。

### 2.8 讨论后定型（Henry×Claude 现场推演 · **本节修正并覆盖 2.1/2.5 的相应表述,以此为准**）

> Henry 对 2.1"角色论"不满意（把冻结/活体的天差地别说轻了）+ 抛出"原始文档能不能编辑"与"多重嵌套引用链会乱"两问；推演三轮后定型如下。

**① 三种上传/使用意图（修正 2.1 的两分法）**：参考（引用）/ **修缮源**（改语病/修 OCR 错——产出仍是源，必须发生在源层，否则修好的版本不被后续引用命中）/ 做我的笔记（产出是你的内容）。Claude 最初的"编辑=物化成笔记"只覆盖 1、3，漏了 2 —— Henry 抓出。

**② 上传无模式 + 引擎级冻结 + "编辑"分流**：上传永远一个动作、无"藏品还是橡皮泥"选择题（用户心智里不存在这个问题）；原件（①层字节）引擎级冻结——**冻结是买简单的钱**（外部锚零维护的技术抵押）；"编辑"按意图分流：修缮 → ②层出新版次；做笔记 → 物化成笔记（CoW，带出处）。

**③ 出版模型（本次讨论的核心产出——内外源统一成同一形状）**：
```
源身份 = 冻结版次 edition(s)（引用锚定的对象）
       + 活副本 living copy（可编辑的那份）
       + 留痕 trace（谁在哪改了什么,delta 日志）
外源：V0=原始字节（天生第一版次），活副本=②层重建（修订出 V1/V2…）
内源：生下来是活的（笔记），升级=出版一个冻结版次；再改再冻=再版替换
```
- **版次 append-only**："编辑"永远产生新版次、不改写旧版次 → 修改痕迹免费保留（修订出处：谁/哪/为什么）。
- **与既有承诺三线合一**：07-04 契约的 artifact 版本化（原为 re-parse 设计）＋ 置信度纠错 UX（改 OCR 错块=修订②层，同一操作）＋ ARCHITECTURE.md 已挂名的 SourceVersion / 06-28 盲点"artifact 需版本身份"。
- **快照经济学（Henry 拍）**：**版次只留痕（delta），不存每版全量快照** —— 因为**收据在锚上不在版上**（每条引用自带 snapshot_text 摘录）。源侧 V0+delta、引用侧各自小摘录 → 存储不爆炸、收据一张不少。**由此锚策略修正**（覆盖 2.5 的"钉死版本"）：锚=浮动解析到当前版 + 本地收据兜底 + delta 痕迹使漂移可读可 diff —— 少一个概念、同等安全。
- **块身份跨版次稳定 = 技术命门**（契约必写）：改内容不改块 id（如 git 文件跨 commit），否则每出新版全锚断。

**④ 链接 vs 引用（进产品词表）**：链接=导航到活体（无保存义务）；**引用=图书馆藏品=带来保存义务** —— 这才是冻结的真正原因（不是"因为它是外部的"）。内部引用两档：**随手引**（指活体+漂移检测,零仪式）/ **郑重引**（升级出版次,opt-in 绝不强制）。未来钩子：**Agent 生成的笔记天生带首版次**（"生成了什么"本身是证据）。

**⑤ 嵌套引用链（Henry 的恐惧:A→B→CG魔改副本→D→原件,断代=不可知错误）→ 已拆解**：我们造的不是指针链是**收据链** —— 每跳自带快照，断代=该跳活跳转失效、收据仍在（删中间笔记/改中间内容/re-parse 三类断法各有定义好的**可见**降级，无一"不可知"）。魔改那跳暴露两件事：每跳需**溯源模式**（直引|转述|蒸馏|推断——不标则诠释被洗成证据）；**出处是 DAG 不是链、没有唯一的根**（魔改=多父）→ 根不焊在对象上、懒遍历得出，断处亮收据。v1 只做单跳（薄绑定），链由单跳自然复合。

**⑥ 导出不变量（Henry 拍）**：必须带走 = V0 原件 + 当前/冻结版次 + 全部锚与收据；**可抹 = delta 痕迹**（岁月痕迹=sidecar,对导出不友好就不带）。

**⑦ 护栏**：删旧版次可以（自己的东西,锚自足→引用方收据仍在,不踩红线），但**必须可见**："N 处引用指向此版次,将退化为仅收据"——点头才删,永不静默。修缮≠创作的分界靠动词分流（源库"修订此源" vs 笔记侧"从源建笔记"）。

**⑧ 三层定名（Henry 定,进产品词表——覆盖①②③层编号的口头表述）**：
```
事实源 = ①层原件（V0 字节）——物理事实,Agent/引用从不直接指它
引用源 = ②层的冻结版次（editions）——锚真正指向的引用层;内部笔记冻结进的是这里
编辑层 = 活副本（working draft）——解冻修改处,提交才更新引用源
```
- **"引用指②"一直是设计**（06-28 锚指②区域、07-04 锚指 artifact block）;本次的新贡献 = 抽取层从黑盒**毕业成用户可见、可修订的一等对象**（"修缮源"因此才可能）。
- **不可改写 ≠ 不可删除**：事实源 immutable 但**可删**（用户自己的文件）。引用不断（从没指过它），但删除代价须可见告知：① 不能再重新解析升级重建;② 原始版面/bbox 叠加失效;③ **引用源从"可重建派生物"升格为"不可再生的根"**。可删+可见+永不静默,同⑦护栏模式。
- **编辑层是"状态"不是第三种副本**：= 引用源上的未提交工作区（git working tree）;提交→新版次,丢弃→消失;**提交前修改对引用世界不存在**（引用稳定与编辑自由由此同时成立）。实现红线：勿落成独立"编辑副本表"（= 第二真相源）。

**⑨ 事实源可更新 + 身份倒置（Henry 周笔记场景推演定型）**：完整命题 = "**没有任何一个地方不能更新,同时没有任何一次更新能悄悄吃掉任何人的工作**"。
- **身份倒置**：持久身份住在**引用源**上;事实源=可更换的证据附件（"我的 week-1 笔记"这个概念活得比任何一次扫描久）。修正早前表述：content-hash=**文件身份**（去重）,**文档身份在引用源**（引用绑定）——两个身份两份工。
- **1:N 缝（免费,契约措辞第 6 条）**：一个引用源可挂多个事实源附件（周场景=两份扫描）;v1 行为 1:1,但 FK 方向 `fact_source.reference_source_id` → 1:N 天然通。"更新事实源"从"删了重传"变成"再挂一份"。
- **reconcile = 三方合并（工程肉,危险点 Henry 未点名、Claude 补）**：base(旧解析)/theirs(新解析)/mine(用户修订版次)——二方对比会让新解析冲掉用户改好的语病。规则：**用户修订默认赢、新增自然流入、真冲突 proposal-first**。底料=⑧的 delta 日志+修订出处（human_correction vs machine_parse）;模式=**v2.2 Material Reconciliation 复用**（保守/proposal-first/证据保留,旧机器新用）。
- **content range 存活（Henry 判定,正宗 house 语法）**：老 range 绑老版次+自带收据→天然有效;AI 重审时 lazy rebind 或保留（哪个省力哪个来）;= annotation rebase/pending（8.11.15）同一套文法在源层重现。大面没变的更新（纯增页）绝大多数 range 不动。
- **极端 case 护栏**：换一点边不沾的文件=新源穿旧源的皮;重解析 diff 幅度过大→提示"建议作为新源上传而非替换",可见选择。
- **三层更新路×安全锁**：引用源(编辑层提交/commit 语义) · 事实源(挂附件重解析/三方合并+proposal+差异护栏) · content range(默认不动收据兜底/lazy rebind)。

**⑩ 事实源也留版本（Henry 从"upload=复制"推出）**：上传天然生成系统内副本（永远复制进来、**绝不按路径引用**——杀死挪文件断链一类 bug,契约条款）→ 保留历史=只是不删,零额外机制;content-hash 站岗去重（同文件重传=指向已有,不建新版）。**由此三层共用同一条语法："追加为常、删除须手动、且永远可见"**（事实源:上传即追加 / 引用源:版次 append-only / 留痕:delta 只增）。
- **两种"多份"要分清但不焊标签**：并列附件（两份扫描共同构成现状）vs 版本序列（新扫描取代旧扫描）。解法：**每个引用源版次带"派生清单"**（"本版次由事实源[A,B]+人工修订派生"）→ "现役 vs 历史"= 从最新版次清单读出的**派生属性**,不在事实源身上贴状态列（相对不焊）。
- **删除护栏分级**：删历史事实源（不在现役清单）低成本随删;删现役事实集才触发"不能再解析"可见警告。
- **导出不变量扩行**：必带=现役事实集+被引用版次+锚收据;可选带=历史事实源版本（与 delta 痕迹同级,岁月痕迹,打包可勾选）。

**⑪ 引用源的工程形态（Henry 判决 + Claude 展开 · 含一个 gating 设计决定）**：
- **一套编辑机器（Henry 判决）**："不可能再独立建一套 TextFlow" —— 引用源要可编辑,结构上**就是一份笔记**（地位不同靠规则不靠另起炉灶）= "不二知识宇宙"老原则的直接推论。**赠品全拿**：标注机器（在源上划重点）/ CG 机器（分块=在源上建 CG,同一套 UI）/ 目的机器（V9 purposes 对源笔记照常生效）/ 纠错 UX（骑笔记编辑器）—— 一套机器俩世界通吃。
- **忠实投影原则（Henry 判决）**：引用源=事实源的投影,**投影无创作自由** —— page frame 按源页尺寸、无自由画布、不许加任意对象;引擎挂点=policy 模式（modePolicyService 先例,加 "faithful-projection 模式"）。bbox=块定位数据来源;诚实标注：v1 native 解析无 bbox → v1 忠实=文字按页流排,像素级忠实=VLM 期。
- **格式难度阶梯**：PPT（页框最顺）> PDF（bbox 等 VLM）> docx（流式无固定页,合理分页即忠实,内容保真>像素保真）> 扫描/手写（VLM 期）> **HTML（特殊解法）**。
- **HTML 拆两半（Henry 麻爪 → 解）**：**事实源=网页快照**（SingleFile 式,视觉真相,"查看原件"）+ **引用源=正文提取**（Readability/Trafilatura,PI-048 R7;广告/导航在提取步剥掉）→ 网页的忠实**降级为内容忠实**,视觉由快照兜底,不在引擎里复刻网页。
- **切分梯子**：V10 地板（事实层+契约六条+最小引用源:native 物化/流排/近只读+薄绑定）→ 出版机器（编辑层/版次/修缮/护栏）→ VLM 期（忠实版面+三方合并+重解析升级）→ Web 专场 → V12+ 打磨。每层只依赖上层接缝不依赖成熟度。
- **⚠ gating 设计决定（不在聊天拍,走设计文档→对抗核查→Henry 拍老流程）**：引用源存储形态 —— 真·同表笔记（note+kind 判别+policy 锁+列表默认过滤,Claude 倾向,则 07-04 的 source_artifact_blocks 从持久表降为**解析器接口形状**）vs 独立 artifact 表+共享渲染。血溅面宽（一切"查所有笔记"处要 status-aware、V9 懒建默认目的会对源笔记生效…）。**V10 事实层那半不被它挡,可先行。**

- **不是我们的表格**：Notion connected DB=其 database 原语+同步 adapter;我们这边的正确身份 = **feed = 一种自动追加版本的事实源**（轮询=自动重传,每次拉取追加一个带时间戳的版本——⑩的版本机器原样复用）。引用=照旧冻收据;**链接 vs 引用原样适用**（看现值=链接,引当时值=引用）。契约零改动（SourceKind 开放注册表,将来加 `feed` kind 即插）。

### 2.9 Source 交互设计（Henry×Claude · 库的形态）

**① 引用源为主、事实源为链接（Henry 拍）**：库里列的是**引用源**（身份住引用源上——⑨身份倒置的 UI 兑现）；事实源=条目下的附件链接，点开**如同打开外部链接**（交浏览器/系统：PDF/图/音/视频原生预览，其余下载自便）。**不做全格式 in-app viewer**（格式宇宙做不完/半吊子 viewer=Kano 负资产/增值在引用源）。**免误读旗**：VLM 期的"对照原件"视图 ≠ viewer——是解析器产出的页面光栅图+bbox 叠加层，便宜且格式无关，另一码事。

**② 库的交互草图**：左侧导航 → Source Library（全局·第一个无墙页面）；条目=源身份（icon/标题/上传时间/物化状态徽章/被引用 N 处=SourceUsage）；点条目=应用内打开引用源（笔记样式,v1 只读）；条目详情=事实源附件区（打开↗/下载；将来 1:N 与版本痕迹挂此）；上传入口=库内+project 内（出身 course 由此记录）；project 页=按 SourceUsage/出身过滤的反查视图（镜头非墙）。

**③ "所有上传都要转成引用源吗"（Henry 问 → 解）**：按能力档分——能力 1 格式**转且 eager**（native 解析便宜,点开秒开,库形态统一）；能力 0 格式**不转**（条目=文件+原生预览）。**承重不变量：「收」与「转」解耦——收永远成功，转允许失败/等待/重试**（解析炸了 = "文件已收,投影生成失败[重试]",绝非上传报错——"文件在不在"与"会不会读"是两个承诺,第一个绝对）。"已收未转"态 = 存储设计 §3.5 孤儿行渲染的同一状态（删course孤儿/上传pending/将来VLM排队解析 = 一个状态机三个入口,零返工）。**一句话：库按源身份陈列,物化状态只是徽章,转换是服务不是门槛。**

**④ course 删除与源的关系（Henry 质疑逃生口 → 模型精确化）**：Henry 的模型——笔记变成源（三点水的源）即**进入 source library**,course 删除与它无关；"隐含的一步"=笔记→源笔记的转变。精确化为**三件套**：①事实源=库居民（生来是,source_files 全局,v1 已如此）；②冻结版次=库居民（**"进库"的确切含义**;机制保障=核查 HIGH 修正"版次链挂 source_files 不挂 note_id"——Henry 用产品直觉独立重推出该修正）；③投影/工作副本=唯一 course 居民。**course 删除永远碰不到库（①②）,死的只有③及长在③上的东西**（标注/分组/目的——重物化=新身份接不回）。"隐含的一步"有名字=§2.8④升级/出版动词；**上传文档生来即"已出版"**（内容第一天就是库居民）。**v1 诚实缺口**：③物理上仍 course_id NOT NULL（C 路线已钢人否掉:整表重建+37卫星表照撕）→ v1=A-d 近似,完全体=拆墙工程。**护栏重定位（变小变诚实）**：警告词从"将删除 N 份源"改为"投影可重建;其上 M 处标注/分组不可恢复;N 条跨 course 引用退化为仅收据"（源不死,别吓唬人）;逃生口重定位为**救长在投影上的东西**（迁 course 连带标注）。**待 Henry 重拍**：逃生口 v1 进（保险）vs 缓（最瘦地板,反正内容不丢）。一句话：**"进库"=内容换户籍;删 course 是拆房子,不是烧户口本。**

**⑤ 引用源的类型（Henry 提两类 → 定型:两类够,且类型是派生的）**：
- **类型一(外源)**=有事实源附件,根基=文件；**类型二(升格)**=零附件,根基=书写行为本身。**类型从数据派生**（数 fact 附件）,不焊 enum；出身（上传/升格/AI生成后升格）= provenance metadata。AI 笔记升格=类型二子案；网页/feed 归类型一。无第三种。
- **"没有根基"更准的说法**：类型一=溯源链**终点**（证据根）,类型二=**中继**（自己的锚继续向上）。中继的搞乱恐惧=§2.8⑤已拆（收据链/DAG/可见降级）。
- **★新契约措辞（防中继抽桥,进清单第七条）**：**出版即冻结全身——版次 = 内容 + 当时全部对外锚（带收据）一起冻**。升格后活副本再怎么改引用,版次内的上游链路不动;下游顺版次永远走得到上游（或其收据）。
- **用户侧露出**：库徽章 📄有原件 / ✍️笔记升格——类型一=证据级,类型二=诠释级,引用类型二继承诠释风险（防"诠释被洗成证据",接 06-28 信任不随链复合）。
- **边界**：事实源附件=派生根基,非"相关文件"；类型二不接受 fact 附件（想附讲义 PDF=另建一个源,靠引用连）——附件语义一松,两类型即混。

**⑥ CG 链路模拟（Henry 场景:α 制于笔记A→复制改成β→β.member 进笔记B,中间删东西怎么办 → 定型）**：
- **链形**：B.块→β.member→A.range→S→文件。**α 不在 B 的路径上**（复制即复制指针,β.member 直指 A;α 只是 duplicated_from 兄弟记录）——删 α 对 B 零影响。
- **删除模拟**：删α=无关;删β/trash A=软删,**链物理上不断**（遍历穿过 tombstone、显示"经由已删分组"）;**唯一真防御=course 硬删抽掉中继**;删 S=§2.8⑦ 老护栏。
- **★新契约措辞（清单第八条）：引用建立时收据冻结「血统摘要」**（沿路各跳 id+溯源模式,几十字节）。语法正当性：焊死的罪是**活的根指针**（漂/维护/DAG多父）;收据本来就是**时点真相**,冻血统=冻原文同一动作。→ 硬删后 B 仍知"经β(已亡)取自A(已亡),根在 S"——**S 是库居民 course 拆不着,终点永远可达,中继随便死**（Henry"最终引用来源是那份引用源"升级为结构保证）。
- **买通老决定**：07-02"AI 脚手架 CG 用完可弃"经此验证安全——**CG/member=运输工具非地基**,血统在目的地冻结,运输工具随便报废;脚手架可弃性与溯源完整性互不欠账。
- **模式沿链复合**：β 改过本体再被引 → B 收据记"经β时文本"+血统记"来自A原位"——直引一个转述≠直引,诠释不被洗成证据在链上的运作。

**⑦ 溯源宪法（Henry 质疑软删依赖 + γ 复合场景 → 定型为三条不变量）**：
- **修正（Henry 对）**：软删=UX 糖非溯源基建（回收站装三种东西/tombstone 堆积=06-28 墓地盲点/用户期待"彻底删除"存在）。**溯源必须在"处处可硬删"的世界里正确**;回收站有无属打磨期 UX 选择,链不在乎。
- **落点递补规则（新契约措辞）**：跳回源沿冻结血统找**最近活祖先**（β死→落A.range,A死→落S=库级身份最耐死）,跳转逐级递补永有落点,收据零损。
- **γ 场景的视角切换**：**CG 从来没有"一条链",链长在 member 上**（CG=纯捆,V9 兑现）——γ1血统=[B.块,β.member,A.range,S]（**冻结传递复制**:建引用时抄被引节点的冻结血统+其id,每深一跳+一个id）;γ2(新写)血统=[]根=作者;γ3=[...,T]。member 自足,上游全灭收据不动。
- **四个推演**：①多父汇流=一段内容挂一组锚各带血统,模式记蒸馏/推断（DAG 扇入兑现）;②**环不可能定理**:血统条目时点冻结、指具体range/版次,引不到未来→冻结血统天然无环（活指针可绕圈,收据数学上不能）;③重物化降粒:老块id死但**终端=库级源身份**（终端规则:类型一以source_files id收尾,类型二以版次id/作者标记收尾）→降粒不断链;④模式沿链冻存=06-28"信任不随链复合"盲点将来要的数据现在就位,deferred 功能到货零回填。
- **★溯源三不变量（宪法,决定产品气质与寿命——Henry 语）**：**1.收据自足**（时点收据=文本+血统+模式,不依赖任何对象活着）;**2.删除只影响活跳转**（软/硬删最多让落点沿血统递补,永不触碰收据与血统）;**3.时点性保无环**（只能引已存在之物→天然DAG）。三条成立→删除策略/回收站/course拆迁全是UX层自由,地基不参与讨论。

**⑧ 血统面板（Henry 提案,取代"逐级回跳"为主机制 → 采纳）**：
- **面板 > 聪明按钮**：把整条冻结血统摊开成可视链路表单——每跳一行（名称/模式/状态徽章）,**活的直接点跳、死的灰显但名字模式仍在、改过的标徽章仅供参考**。"解析落点"逻辑换成"人看着选";逐级递补降级为面板默认快捷键（跳到源=点终端项）。
- **不用建新存储**：面板=血统摘要（⑦已冻进锚收据）的渲染;补一小件——**每跳再冻显示名快照**（否则死节点只剩裸id）。
- **状态语义（Henry 直觉,全对）**：已修改=纯情报（收据时点性,与本member无关,想跟进再看漂移）;已删除=灰掉可点性、行本身永在（宪法第2条可视化）;**每行状态渲染时现查,不存血统**（相对不焊,读时派生）。
- **可选解锁（plan 时选）**：血统存法 JSON冻锚上（地板）vs 归一化行索引（additive、可从收据重建=sidecar 语法）→ 买到**反向传递查询**（"S 被直接引12处、经中继引37处"）+ 删course跨引用计数变索引查询。v1 JSON 够,索引后置。
- **产品意义**：血统面板=**信任面**（宪法三条唯一用户可见形态）+"掀引擎盖/审计"语法落地物。让人看全链,不让系统替人聪明。

**⑨ 最小引用单位 + 链路地位分级（Henry 提 → 定型）**：
- **原子引用 = range ↔ range**：源端最细=content range（非文本=region/对象,VLM期+bbox）;**用端最细也是 range**——"先写一段话再补引用"是一等流程（选中→添加引用→挑源）,且必须到句级而非整块（06-28"内部引用钉死整块丢offset"之雷正式收进原则）。两端各自可粗化到块/对象/文档级,契约地板刻在 range。
- **地位分级（Henry:中间可有可无,写作↔链底引用源的连接最重要,根可复数）→ 形式化**：**根链接**（当前输入↔链底引用源,复数可）=必存必显,承载「信任」（有锚=搬运可查,抗幻觉半边）;**途经链接**（经由的CG/member/笔记）=存而默认折叠,承载「策展痕迹」（怎么带到这儿的）。

- **白送**：①超长链截断规则跟地位走（保根+最近一跳,折中间）;②面板天然分两读层——信任层（根:能不能信）+过程层（途经:当年怎么想）,一张面板养两个 telos（source-grounded + 思考义肢）。
- **逃生口澄清（Henry 问）**：=删 course 对话中"把 N 份源投影连同标注迁往另一 course"选项（一次事务改 course_id,机械）;救的是长在投影上的标注/分组（源本体库里安全）。

**⑩ 删 project + 投影可删 + 非对称删除 + 默认 project（Henry 提 → 定型,逃生口悬案溶解）**：
- **"投影该删就删"= 溯源不变量的推论（非拍脑袋）**：投影=编辑层的物化产物=**派生物非真相**,删派生物不丢信息（可从库里的源+版次重建）——同"AI 脚手架 CG 可弃"/"痕迹是重讲非存储"。删 project→投影跟着删,天经地义。
- **"没投影怎么改"闭环编辑层**：有投影→编辑层直接用;无投影→去 source library 找源、按需重建投影再编辑。投影=懒生成/可丢/可再生的编辑工作面（同收转解耦状态机:有投影/暂无投影皆合法）。
- **★非对称删除原则（Henry 钻石句:"引用源处理谨慎、两个分开"）**：**删 project=廉价随手（只删派生物）;删源本身=谨慎专门（只能去 Source Library,单独动作）**。理由=project 是镜头、源是内容（相对不焊）——删镜头碰不到内容;是宪法第2条在权限层的样子。删源那道额外手续=给不可替代之物配的安全锁（库删自带"N 处引用退化为收据"警告）。
- **默认 project「主页」（Henry 提为逃生口落脚 → 真身份更大）**：=**拆墙第一个用户可见形态 + 孤儿的家**（vision 的"无墙空间"）;不可删/不可改名（系统锚点,像收件箱）/可上传。任何"内容有用但 project 没了"的东西默认落此。
- **→ 逃生口悬案溶解**：删 project 对话给"○一并删投影(源在库,可重建)[默认] / ○迁到「主页」保留 / 引用源本体不受影响(删请去 Source Library)"。**逃生口 v1 进,且几乎免费**——落点(默认 project)本来就该建（拆墙第一砖）,逃生口只是"迁到主页"的一个入口,既有件的用法非新功能。

**⑪ 删除对话边界 + 笔记不自动升格（Henry 提 → 定型）**：
- **单一用途对话框（Henry 拍）**：删 project 对话**故意不提供**"顺便删库里的源"——删源永远不做副作用,唯一入口在 Source Library（带引用计数警告）;对话文案必含提醒「如需彻底删除请去库」。不替用户做他没来做的决定。
- **"要不要自动升格"两难溶解**：两难前提"引用需要升格"为假——**随手引本来就零仪式**（引活笔记=锚+收据+漂移检测,当场成立;收据把引用方保护到位）。升格买的是**源侧郑重声明**（"此版本是定稿藏品"）,故不能自动：自动的郑重=没有郑重（声明性归零）/ 库被淹死（策展空间→全部笔记）/ 诠释洗证据闸门冲开（徽章通胀）/ 版次切点无解（每存都出版=垃圾,定时=随机——有意义的版次需要人的时刻）。
- **三档定型**：**随手引**（默认零仪式,覆盖99%日常）/ **升格出版**（opt-in;系统可"**被引用驱动建议**"——被引 N 处/跨 project 被引时递台阶,grow-by-use,升格需求从使用里长出,用户永不需预先决定）/ **Agent 生成笔记=唯一自动例外**（生来带首版次,生成即郑重时刻+生成证据,§2.8④原判）。
- **类比**：谁都可引用草稿（注明某日所见=收据）,但"出版"永远是作者自己的动作。

**⑫ 网页入口之争 → 四路收敛两分支（Henry 拍 C + 提出 D「屏幕视觉采集」→ 定型）**：

**⑭ 信息搜索与加工平台的潜力（Henry 愿景之问 → Claude 论证:有,且潜力在基座不在搜索）**：

**⑮ 收集外包终判（Henry 战略定调:搜索不自建,连接器接生态 → ⑭时序修正）**：
- **Henry 定调**："A/B/D 只是 brainstorm 产物,没必要非做。AI 时代各扮其角,融合成生态是大公司的事;个人开发者做好一种角色已经很厉害。搜索为什么要自己做?做一个连接器连到 Claude/Perplexity,再写一份 skill 当使用说明书。我不要当啥都能干的最牛逼那个,我只想搞好我自己这一块。"
- **落在三个既有锚点上**：①tool-assisted not tool-owned（roadmap 原教义,推广到搜索）;②连接器+说明书=**MCP server + skill**（行业标准形状,不用发明接口）;③底座 vs 操作者（搜索这个操作者生态里现成,连雇都不用雇）。
- **地图改动**：收集章节从"三个自建器官"缩成"**一个 MCP 插座 + 一份 skill**"。北极星照跑,分工变:外部 AI 找（其看家本领）→连接器推进源库（收据/快照/血统=我们的看家本领）→装配线蒸馏。A 从"器官"降格为"URL→快照收录函数"（薄切片,收录工具身份,非搜索产品）;B/D 归档。
- **★宪法接缝（防连接器走私）**：连接器收录分三档——**甲级**原始字节（完整事实源,满血）/**乙级**仅 URL（我方 URL→快照函数收录）/**丙级**AI 转述文本（照收但溯源模式诚实标「转述/AI 提供」,绝不许长得像有原件）。不守则"连接器收录"=诠释洗证据的新入口;模式字段即为此生。
- **身份升位**："啥都能干的产品"满地绞杀;"所有 AI 的调查结果愿意沉淀进来的那一层"稀缺且无人在做——**不做搜索,做搜索们的记忆与良心**。

**⑯ 规模承载力终判（Henry 忧"网页推不动千页笔记/千节点图/多年积累"→ 拆解,V12 打磨期输入）**：
- **分水岭 = O(看得见的) vs O(全部存在的),不是网页 vs 原生**（Figma/Obsidian/VS Code 为存在性证明——天真架构换原生一样烂）。**Tauri 不加速画布**（壳内仍是同一 WebView 渲染器）——重写动机从"性能焦虑"净化为"分发与体积"。
- **三板斧（平台无关,V12 物质基础工程同族）**：虚拟化（千页只挂视口 3-5 页,其余占位）/ 视口剔除（屏外不画）/ LOD（远缩时页框画简化块）。图视角千级节点时从 DOM 切绘制型画布（Canvas2D/WebGL）。
- **本代码库的真实烂点（全部可修,与渲染无关的优先）**：O(N) 请求模式（GroupGallery 每笔记 3 请求扇出）/ 无剔除 DOM 画布（数百对象时需 culling pass）/ 整课载入取数。后端/SQLite 永不在瓶颈名单（索引范围查询,GB 级无碍）。perf smoke 门已在 verify 管线站岗。**Henry 拍：此件归 V12 打磨。**

**⑰ 音频理解全景 + 音视频终判（Henry 要求先懂全貌再决定 → 判据浮出,整体后置）**：
- **全景三轴+融合趋势**：语音轴（STT/ASR·**diarization 说话人分离**=字幕→会议记录的那一步·副语言·VAD）/ 音乐轴（MIR 学科:歌词对齐·BPM调性和弦曲式·AMT 扒谱→MIDI·**音源分离 stems=处理混合音频的钥匙**·指纹·嵌入检索）/ 通用声学轴（事件标签/音频字幕）/ **2026 融合趋势=Audio-LLM/Omni 模型**（Qwen2.5-Omni、Nemotron Omni 等"直接对音频提问",理解+生成渐统一;今天工程主力仍是专用模型 Whisper/Demucs）。
- **具体案例**：视频解出的人声+BGM=现代 ASR 天然鲁棒,SNR 烂时先分离再转（已解）;带歌词音乐=可做但要问用途;纯音乐=忠实重建是 MIDI/乐谱/stems=**另一个编辑器的工程文件（xlsx 同族,异介质）——收进来也表达不了**。
- **★判据定型：按内容轴收,不按文件格式收**——"mp3"不是一个类:载语音的（讲课/会议/语音日记）=近介质（投影成文本）=我们的赛道,户口在解析器时代（STT+diarization→转写引用源+时间戳locator）;音乐=异介质=不是我们的赛道（"各扮其角":连接器接专门工具,沉淀层收结果）。
- **决策轨迹（诚实记录）**：Claude 初判"整体后置·死文件论"**越位且部分错误**——被 Henry 驳回（"你替我下了判决"）;自纠:"无转写=死文件"与**收转解耦**（已收未转=合法状态）及 **pptx 先例**（存着即有归档价值,回放=真实学习行为）冲突。随后给出完整能力阶梯:0级纯收藏（~零成本）/ 0.5级手动时间戳引用（不需要AI,"引用此刻"按钮+时间段locator）/ 1级STT转写 / 2级说话人分离 / 3级音乐轴（维持"非我们赛道"）/ 4级Audio-LLM。
- **★终判（Henry 拍,2026-07-09;理由 07-09 修正为最终版）**：**音频现在不收,将来的甜品=只做 STT**。不做的理由**不是难,恰恰是太简单**——"一条堪堪能用的 API+解析 transcript"的活,却要背一整条新 API 链的测试验收债,而它对主线工程**零贡献**（纯插件,不同路不顺路不现在）。生态已有好工具（Otter/ElevenLabs）,**我们不解决用户的 STT 问题**（与搜索外包同刀法）。**零损失细节**：转写文本本来就是白名单公民（录音→外部转写→txt 上传→源语法照常工作）——内容能进门,只是原始媒体不进。

**⑱ 视频终判（Henry 拍 + Claude 补机制,2026-07-09）**：
- **2026 视频理解三流派（背景材料）**：①原生端到端（Gemini 原生/Qwen3-Omni,撞 token 经济学墙）②压缩/记忆派（token merging/流式 KV-cache）③**Agentic 分步派**（粗扫→决定看哪→抓关键帧细看——Henry 凭直觉猜中的正是 SOTA 回归的形状）。讲课视频=最简单体裁（画面≈准静态幻灯片:翻页检测=关键帧,帧理解退化为文档解析）——但纯动画讲解（3B1B 式）例外,意义住在运动画面里。
- **★Henry 终判**：**视频在我们这里=储存+展示,仅此而已;永不自建解析**（三流派任一自建=产品长出比本体更大更复杂的第二半,完全没必要）;解析借外部工具。视频看淡。
- **外部工具产物盘点（Claude 查证）**：转写服务（Otter/AssemblyAI→时间戳转写/SRT/章节）/视频转笔记器（→markdown）/幻灯片抽取（→关键帧图组/PDF）/全模态 API（Gemini 视频/Qwen3-Omni→按需结构化输出）。**关键事实:每种产物都已是我们模型的公民**（txt/md/字幕≈纯文本/图片/PDF 全在白名单）——**我们永不解析视频,只收它的影子,而影子全是老朋友**。⑮连接器剧本覆盖自动化版。
- **"根据视频做笔记"（掐脖子场景）拆解**：两跳——视频→影子（外包,永不碰）+ 影子→笔记（=北极星流程,装配线本职）。**每一步都已有主,产品替用户分解。**
- **纯动画的诚实解法：抽不出来的就不抽——引用它**。时间锚（"此推导见 12:34–15:02"+seek 回放）;事实源保持为不可替代的体验,引用源只承载薄影子（旁白转写）;AI 对动画段的诚实输出="需要观看"的锚,非编造描述（无锚=生成反着用:看不懂=标注去看,诠释永不冒充证据）。**产品承诺不是"我看懂了视频",是"能引的都引好了,剩下一秒带你跳回去"。**

**⑲ 第三方账号绑定设想 + 视频工具市场盘点（Henry 问 → 材料+判据,目标产品现在不选）**：
- **Henry 设想**：将来"根据音视频整理笔记"功能=用户在我们这登录第三方账号→用其能力收影子→回来加工。= ⑮插座的**反向:插头模式**（我们驱动别人）。
- **市场三族（2026-07 查证）**：①**学生特化族**（最对口:Mindgrasp 直传 MP4/网课录像→笔记/摘要/闪卡;NoteGPT→带时间戳分章笔记;TurboLearn/Knowt/Coconote 一片红海）②通用摘要器族（Recall/Eightify）③会议记录器族（tl;dv/Fireflies/Fathom）。**产物=时间戳 markdown/PDF/DOCX/SRT/闪卡——再次全是白名单公民（影子理论二次验证）**。
- **现实泼冷水**：API 成熟度天差地别——会议记录器族 API/webhook 成熟（生来 B 端）;**学生特化族大多无公开 API**（网页应用,产物手动导出）→"账号绑定自动收影子"对最对口那族今天走不通;走得通的朴素路=**手动导出 PDF→拖进上传口（门现在就开着,零开发）**。
- **更顺的路（时代在修）**：工具们自己长 MCP 服务的趋势→集成负担翻转:不是我们写 N 个 OAuth,是 Agent 时代的 agent 一手他们的 MCP 一手我们的 MCP 当搬运工（=⑮插座剧本原样覆盖,"账号绑定"届时可能退化成一句 skill 说明）。
- **★目标产品:现在不选**（市场高流动高死亡率,今天锁定=提前焊死）。留**选型判据**：①有 API 或 MCP ②产物=带时间戳 markdown/PDF ③公司活得稳。近期零成本路径始终通着。
- **接入门槛四档（Henry 猜想"集成=谈合作=没戏"→仅第三档成立）**：①自助 API（STT 基建:注册拿 key 当天通,客户即开发者,零谈判）②开发者计划 SaaS（会议记录器族:开发者门户填表注册 OAuth 应用,无人类介入）③**无开发者计划的消费级工具（学生特化族——猜想在此 100% 成立,已用手动导出门绕开）**④MCP 生态（**标准即合作**,发布即可被任何 agent 驱动,无许可制;我们的⑮插座同样不需任何人许可）。**结论:要谈判的恰好都不值得谈,值得接的全都不用谈——单干开发者 2026 年的集成火力远超直觉。**
