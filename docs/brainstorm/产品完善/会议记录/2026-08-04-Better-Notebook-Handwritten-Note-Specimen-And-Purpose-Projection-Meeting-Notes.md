## 二、标本盘点：块类型学（**17 种操作 / 5 个标签**）

Henry 实际使用的标签：`Def / Fact / Ex / Guess / Answer`（5 个）。逐块盘点得到的**实际操作 17 种**：

**A. 锚类（源头原话，不可改写）**：术语条目（英文锚+中文名，**可独立于定义存在**）、Def 定义、Fact 事实、数据点。

**B. 结构类（源头内容，被重铸形状）**：枚举/分类、**映射表**（两套分类的一一对应）、**组合格**（斯滕伯格）、**二维矩阵**（依恋 2×2）、循环流程、链式流程、汇聚图。
> 后四种的源头是**图片或平铺 bullet**，产出物是结构化对象——**这正是「窄腰契约」要交付的东西，用户手工做了四次。**

**C. 自产类（源头没有）**：`Guess` 一个标签下至少跑着 **8 种不同操作**——① 压缩重述 ② **成语把手** ③ 建模 ④ 跨概念连线 ⑤ 结构重组 ⑥ **对比辨析（vs）** ⑦ **批评/缺口** ⑧ **限定/否定源头**；标签外另有：中文注解（挂在某项上）、**外部补入**、格言压缩。

**D. 未完成态（此前未被识别的一族）**：**裸标签/占位符**（写了名字没写内容）、**截断**。

**E. 交互类**：问答对（`Do Attitudes Influence Behaviour? / Answer: Not necessarily`）。
> **用户已经把考题写好了，唯一的问题是纸盖不住答案。**折叠开关 = 零额外撰写成本的提取练习。

**结论：格式的分辨率约为思维分辨率的三分之一，而被压扁的恰好是最稀缺的几类（⑥⑦⑧）。**

## 三、⭐ 为什么标签会被压扁：成本记在注意力上，不在键盘上（Henry 更正 Claude）

Claude 初判为「加一个 `vs` 标签成本只有半秒」。**Henry 更正，且更正成立：**

> **标签的成本不是键盘上的，是注意力上的——它恰好向"正在理解"这个不能被打断的过程收费。**
> Henry 原话：「如果每时每刻都想着维护这套标签系统，人就没办法有效率地学。」

由此得到写入/读取的成本分配定律：

- **写入时值得付费的区分只有一个比特：这不是他说的，是我想的。**（即 `Guess` 本身）
- 其余 8 种细分的价值**全部在读取时兑现，而读取时有的是时间**。

> **正确的写入时槽位数是 2，不是 17。17 是读取时才该出现的分辨率。**

**推论（设计定律）**：把分辨率挪出书写时刻，不要把负担分摊到书写时刻。

## 四、缺席的歧义（三态同形）

同一处空白，可能是三种含义完全相反的状态：

| 空白的真实含义 | 价值 |
|---|---|
| ① **已懂，不必记** | 掌握证明 |
| ② **不认同，不屑记** | **全档案最稀缺**——用户对权威的独立判断 |
| ③ 没看到 / 跳页 | 唯一需要补的洞 |

**纸上三者完全同形。**而应用要做正确投影，必须区分这三个。

**代价：一次点击。**录入时列出省略差集，逐块问一下（懂了 / 不认同 / 跳过）——**歧义的空白变成三种带符号的数据，且不需要用户额外动作，它是已有行为的补集。**

## 五、两个缺失的槽位：`不认同` 与 `缺口`

标本中出现了两个 Henry 自发铸造、但现有标签表无法容纳的类型：

- **`缺口`**（源头**少**了什么）：「**缺少一个变量**：Why we care about social desirability——他人认可度对自身的重要性」。**落了字，但混在 Guess 里。**
- **`不认同`**（源头**说错**了什么）：性别攻击那条（女性关系攻击/男性直接攻击）。Henry 判定其为「适合初学者的二元简化」，**不认同，因此不记**——**产出的是纯粹的沉默。**

> **`缺口` 至少留下一行字；`不认同` 什么也没留下。而后者是任何 AI 都产不出来的一类内容。**

**并列证据**：Claude 核查后确认，该性别差异表述**男性直接攻击一半有扎实元分析支持，女性关系攻击一半证据薄弱**。Henry 的怀疑方向正确但刀切得太齐——**而这正是 `不认同` 该被记录的理由：没写下来的反对意见，永远停在它诞生那天的精度上。**

## 六、credence 是逐块的、属于用户的、与 provenance 正交

标本显示：**同一份 PPT 里，Henry 跑了三种不同的信任政策**：

| 内容类型 | 处理 |
|---|---|
| 权威定义 | **逐字收录** |
| 教学性简化（性别攻击的二元） | **取抓手，弃主张** |
| 无出处统计（53/26/20） | **取序，弃值** |

> **溯源（provenance）回答「它从哪来」；可信度（credence）回答「我买不买账」。两者正交，而现有工具只有来源级的一个信任度。**

**进规格候选**：credence 是**逐块的、属于用户的、可后期修改的一层**；挂在源块上，但不属于源——它是投影层的用户戳。

## 七、⭐ 核心倒置：手写笔记服务「理解之后」，AI 笔记服务「理解之前」

| | 手写笔记 | AI 笔记 |
|---|---|---|
| 产物性质 | 理解发生**之后**的**残渣** | 无过程的**产品** |
| 目标函数 | 理解 × 效率 | **再水化速度** |
| 省略的含义 | **信号**（我懂了） | **纯损失** |
| 编码了谁的状态 | 作者当时的理解状态（**有状态**） | **无状态** |
| 例子/数字 | 丢 | **必须留** |
| 主体价值 | **Guess 块（不可替代）** | **AI 产不出这一层** |

> **他丢掉的，恰好是 AI 必须留的；他留下的（Guess），恰好是 AI 造不出来的。**
> **两者不是竞品，是解剖学上互补的两半。**

**Henry 的定位裁决**：「理解不是我们要管的东西，我们只要做到**可读、清晰、全面**。」
**Claude 的边界补正（Henry 未反对）**：不负责理解 ≠ 对理解无影响。可守的位置是——**我们欠用户真实的成本削减，不欠结果；但绝不能生产关于他自身状态的假信号。**（否则「漂亮到让人误以为学会了」也算合规。）

## 八、⭐ 「废话」是理解的载体：教学装置 ≠ 结构骨架（Henry 提出，本卷最实用的一条）

Henry 原话：「PPT 上有图、有老师讲的废话，这些废话恰恰是辅助我理解的东西。我把它们在笔记中去掉，只留结构性的东西——**恰恰因为我读过了这些废话，我才可以只留结构。**」

于是「AI 笔记要完整」这句话被精确化：

> **源材料里有两种内容：承载信息的，和承载理解的。手写笔记只保留第一种；而第二种恰恰是理解前的读者唯一需要的。**

标本通过**丢掉它们**替我们标注出了这一族：

| 被丢掉的 | 它的职能 |
|---|---|
| 老虎的例子（ABC 模型） | **最小图示**——让抽象落地一次 |
| 战争态度整页 | 同一概念的第二实例（泛化） |
| 费斯汀格 $1/$20 | **反直觉的证据**——让人服气的东西 |
| 麦当劳那组对比 | **程度示范** |
| 「你会说实话吗」讨论页 | **自涉唤起**——把概念接到读者身上 |
| 阿希/米尔格拉姆/津巴多 | **叙事**——让机制可想象 |

**这不是六种废话，是六种教学装置，共同点是：不增加信息量，只降低理解成本。**

> **设计红线：「AI 笔记 = 把源材料缩短」是错的方向——缩短最先删掉的恰好是教学装置（信息密度最低），而那正是唯一不该删的东西。**

## 九、双层结构，与「读」这个动作的两种相反性质

| | 理解层 | 骨架层 |
|---|---|---|
| 内容 | 例子、叙事、反直觉证据、教师的口语铺垫 | 术语、定义、矩阵、组合格、流程 |
| 职能 | **建立**理解 | **索引/唤醒**已有理解 |
| 服务对象 | 理解之前的人 | 理解之后的人 |
| 标本的处置 | 全部丢弃（**因为 PPT 还在**） | 全部保留 |

> **标本的两层并没有丢，只是分开存放：PPT = 理解层，手写 = 骨架层。产品要内建的不是「做一份好笔记」，是把两层放进同一个对象并保住它们之间的链接。**

**由此顺带解决 07-24 卷遗留的「几百页笔记看不完」问题**：不是分装成 20 份（分装解决投递，不解决体量），而是**分层**——底稿保持完整，打开时是骨架，每个节点可展开。

**「读」的两种性质（Henry 观察 + Claude 补正）**：

- **骨架层的读 = 提取**（先自己调出定义再核对）→ **增强记忆**；
- **理解层的读 = 编码**（往里装）→ **重复读只增强流畅感，不增强提取力**。

> **同一个动作，在两层里一个是练习，一个是陷阱。所以折叠/展开不是排版偏好，它决定这次阅读是提取还是编码。**

## 十、需求不是列表，是变量：七个正交轴

Henry 提出两层（理解时序）。Claude 补出六个与之正交的变量，每个都生成一族不同的产品：

| 变量 | 取值 | 备注 |
|---|---|---|
| ① **理解时序**（Henry） | 理解后整理 / 理解前铺路 | 决定默认折叠还是展开 |
| ② **目的形状** | 选择题/简答/论文/做事/教人/决策 | ⭐ **最高杠杆**：用户一句话就能声明，却改变下游一切 |
| ③ **材料规模与关系** | 一份 / 多份 | 多份 = **跨文档对账**（去重、找矛盾），与单章摘要共享零代码 |
| ④ **时间跨度** | 一次性 / **活的** | 后者要求「合并新材料进已有结构」，落在事实流架构上 |
| ⑤ **读者** | 未来的自己 / 别人 / **AI 自己** | 第三种规格与给人读的几乎相反（要完整无歧义带出处，**不需要教学装置**） |
| ⑥ **源头可信度状态** | 教材/论文/网页/自己旧笔记 | 越不可信，「标注」职责比重越大 |
| ⑦ **缺口发现** | 材料内的漏 / **材料外的漏** | 「我漏了什么」——搜索与问答都解不了，因为它们要求你先知道要问什么 |

## 十一、分面分类取代树（回答 Henry 的「细分类横跨大分类」之困）

**Henry 的困惑本身就是诊断**：横跨频繁 = 把本该独立的维度硬压成了树的层级。

反例：「以己度人」同时是——我自产的 · 一个成语把手 · 挂在术语上的注解 · 一次跨概念连线。**树里必须四选一，丢掉三份信息。**

**方案：不建树，建互相正交的面（facet），每块在每面独立取值：**

| 面 | 取值 | 谁填 |
|---|---|---|
| **来源** | 源头的 / 我的 / 外部补入的 | **人（写入时，唯一必填）** |
| **形状** | 定义·枚举·映射·矩阵·组合格·流程·图·散文 | 解析器推断 |
| **职能** | 建立理解 / 索引已有理解 | 由目的声明推出 |
| **完成度** | 完整 / **占位符** / 截断 | 由行为推断 |
| **对源头的态度** | 接受/补充/**质疑**/**拒绝** | 可选，**但值最高，值得单独快捷动作** |

> **五个面，一个由人填、三个机器推、一个可选——这就是「零成本区分」的具体形态：不是分摊负担，是把大部分轴挪出书写时刻。**

## 十二、⭐ 工程侧评审：Purpose 作为投影参数（本卷唯一触及现有实现的一节）

**Henry 的提案**：目的机制应上移；**每篇笔记是一个目的的投影**，而不是每篇笔记各自携带若干目的。

**Claude 查阅现有实现后的现状复核**：

```
Source ──materialize──▶ Note(note_class = 'source_projection')
                          │  contentReadOnly: true
                          │  allowNoteMetadata / PlacementOverrides / InterpretationLayers: true
                          ▼
Note ──owns──▶ Purpose ──bundles──▶ ContentGroup / Item
```

- `client/src/pages/Notes/canvasEngine/sourceProjectionPolicy.ts` —— **`source_projection` 概念已存在**，且「派生内容只读、人类的层可叠加」已落地（**07-20 那条红线在此处已实现**）；
- `server/src/services/purposes.ts` —— **现有 `Purpose` 挂在 Note 下（`OwnedNote { id, course_id }`），职能是捆绑 ContentGroup/Item ——它是容器，不是生成参数。**

**评审结论：**

| 提案要点 | 判定 | 说明 |
|---|---|---|
| 投影参数化 `project(source)` → `project(source, purpose)` | ✅ **是结构性进步** | 一源多笔记，属新能力 |
| 「目的应该来自于引用源」 | ❌ **此步会伤分层** | 见下 |
| 重跑安全 | ➖ **不是新问题，是已解问题的推广** | 现有策略泛化即可 |

**必须修正的一处（Claude 判断，待 Henry 复核）：**

> **一份教材没有「备考」这个属性；有这个目的的是用户。源是目的中立的。**
> **目的既不属于源，也不属于笔记——它是投影这个操作的参数。源保持中立，笔记记录「我由哪个目的投影而来」（溯源），目的独立存在。**
> **一句话：目的不「来自」引用源，目的「作用于」引用源。** 把目的写进源层直接违反 separation-of-truths（目的不是关于源的事实）。

## 十三、由提案暴露的两个风险

**① ⚠️ 撞名风险（现在改成本近零，晚改很贵）**

| | 现有 `Purpose` | 提案中的「目的」 |
|---|---|---|
| 角色 | **容器**（聚合已有 CG/Item） | **函数参数**（塑形生成） |
| 数据流向 | Purpose ← 聚合 ← 材料 | Purpose → 塑形 → 生成 |
| 存在时机 | 材料已在 | 材料未生成 |

**建议的统一（不新增概念、现有语义零改动）**：让 **Purpose 从「收集者」升级为「订货方」**——它既可收纳已有成员，也可**委托投影生成新笔记，生成物自动成为其成员并携带目的溯源**。
> **Henry 那句「每篇笔记是一个目的的投影」完全成立——只是那个目的是订货方，不是产地。**

**② 真缺口：投影笔记缺少第三态**

现策略为二元（`contentReadOnly: isSourceProjection`）。而目的投影出来的笔记**用户一定会想直接改**（那就是他的学习笔记），当前既无中间态也无「接管/分叉」路径。

> **需要第三态：派生 → 用户接管 → 从此钉版；重跑只产生新候选，不覆盖。**
> 07-20 卷已把此方向记在**解析层**；本提案把同一需求提到了**笔记层**。

## 十八、目的的三重身份:选择函数 / 意图层 / 注意力分配器与终止条件（Henry 三问 × Claude 梳理,2026-08-04)

## 十九、联动困局的消解:收据不门禁、沉降不删除（Henry 困局 × Claude 三定律,2026-08-04)

- **Henry 的困局**:三者(purpose/source/note)全独立→连开发者本人都懒得归档;日记/吐槽/思想大爆发型笔记无目的却可能引用源——若"建立源联系必须带目的"则此类全崩;但完全不联动→经典死法(无目的堆积→浏览负担→发掘找回成本爆炸→用户对整个 project 失去兴趣)。到底要不要在 source/note/item/relation/purpose 之间设机制?另判断:item/relation 是 dependent variable,不宜独立。
- **Claude 破题:假两难——预设了"联动=用户劳动"。改为"联动=动作副产品",两角同消。** "要目的才许引用"是门禁,向"正在写作"这个不可打断过程收费,与标签向"正在理解"收费同罪(§三)。
- **三定律**:①**收据不门禁**——一切联动作为动作副产品自动记录,永不作为前置条件;②**目的是特权层不是义务层**——出生证/会员卡可后补永不强制,无目的笔记是一等公民;③**沉降不删除**——检索靠收据、浏览靠分层,不活跃/不产资产/未被收编者自然下沉但永远可循收据找回。
- **日记案例三种未来皆合法且零写入时决策**:目的后来结晶→补会员卡一键收编;永不结晶但铸过 Item→资产证明,不沉;永不结晶不产卡→沉入档案,循引用收据仍可浮出。
- **积累死法的真正机理**:非"无目的笔记存在",而是**浏览面一视同仁**(书桌仓库同屋)。解法=分层浏览:工作台(最近动过/活跃目的在用)/书架(各目的名下)/档案(沉积层,不删不展示可检索)。沉降判据全部由已有收据读时推导(最近触碰/产 Item 否/被收编否),零手动归档——机械新鲜度哲学用于组织。
- **对"item/relation 是 dependent variable"的修正**:操作层对、数据层错且数据层是 Henry 自己在 V11 拍的——整场生命周期战役即为让卡与关系**不陪葬**。正确表述:**数据层独立(资产不随容器死)/操作层从属(永远在语境中被触碰)/全局层可寻(11.6 用户级搜索)**,三层各立不互吃。
- **三对关系联动表**:Note↔Source=引用即收据(自动,零成本);Note↔Purpose=出生证/会员卡(自愿一键可后补);Purpose↔Source=间接经收据链,直接仅在委托投影(订单收据)。**自由写作毫发无伤,检索靠收据网兜底,目的作为特权层收编精品。**

## 二十一、订单规格:目的的表单(Henry 提案 × Claude 定形;概念起头,Agent 版细做)

  2. **真相分层**:**规格(结构化+自由尾巴)是存储真相;表单=给人的投影,prompt=生成时给模型的编译产物**——prompt 血团不可 diff/验证/批改/还原,规格可双向投影、重跑安全(派生物可重跑老语法)。Henry"本质是 prompt"哲学成立(最终消费形态),存储形态按此分层。
  3. **三层槽位(初步例,细化归 Agent 版)**:必填封闭枚举仅三项、全部来自七轴(目的形状/理解时序→默认折叠/读者);可选预设范围(结构组件取舍:表格保结构-转图-略、图片全收-仅被引-不收、公式 LaTeX-图;密度滑杆完整讲解↔骨架索引;**教学装置保留度=§八红线的执行参数**;语言中英混排;排版基调行距-标题深度);开放槽(自由尾巴原文直通 + **样例引用槽升格为一等槽位**:指向现有笔记作 style exemplar 的指针,带风格出处收据——对 Agent,show 强于 tell)。
  4. **AI 填表纪律**:必填全填、相关可选挑着填、剩余进尾巴("灵性"填法);**字段级 provenance(谁填的)**——AI 重推永不静默覆盖人改过的字段,人碰过即钉死。**第三态定律第三次现身:解析层/笔记层/字段层,同一条律三个尺度,分形**。表单同时是 **AI 对用户意图解释的收据**(意图/解释/产物三层不混;外部管家的翻译在应用侧的落地物,可审计)。
  5. **固定部分的成长机制**:字段靠**晋升**不靠预设——自由尾巴中反复出现的需求才有资格晋升为固定槽位;表单从真实使用里长出("让缺口自己报名"用于表单)。**防膨胀警戒**:手动面保持七轴级小;凡不能从 description+材料推导的字段,先质疑其存在;每多一个必填项=背叛一次零仪式。
  6. **既定教义继承**:重新生成产新候选、永不覆盖已接管笔记(第三态);批量=多行订单,每行行级细参、每篇出生证;基调→行级**两级 cascade 封顶,不造 CSS**。
  7. **时序与依赖**:Agent 版细做;前置=窄腰类型化组件(**表单点的菜必须先存在于菜单上**),现有排期不动。Purpose 2.0 由此成五件套:订货方/作用域上移/出生证会员卡/联动三定律/**订单规格**。

## 二十二、思路转型:模型全面云化,数据主权不动(Henry 拍定方向,2026-08-07 补记)

- **Henry 拍定**:**基本完全放弃本地模型路线**(设备与资本不现实,尤其高智能模型);Agent 跑云服务器平台;模型全线上,**OCR/vision 从一开始就用最贵一档**。理由:各领域处于边际收益曲线的不同位置,OCR/VLM 远未触顶——今天的最好=未来的平庸,故永远用当前最好;实证=手写标本在另一会话被现有 OCR 工具折磨(跨语言/多模式/稍复杂布局即严重失准)。成本不敏感:测试预算 $10k ≈ 近 9000 份文档的 token 费。
- **Claude 定性:转的是"缝后面站谁",不是架构**——**数据的家(原件库/收据/真相层/自有服务器)一寸不动;智能的来源全面租前沿**。解析层本就是 HTTP 缝后可重跑派生层,本转型架构改动为零(缝教义首次全额兑付)。经济学两根梁:①本地模型运维=基建形态的"智能补丁",贬值最快,租曲线不买设备;②**可重跑派生层使"用最贵的"可负担**——按摄入一次性付费+升级重跑,非按阅读付费。**连带作废**:07-18 工具调研中"手写识别走本地 sidecar(Pix2Text 族)"建议——同缝改走前沿 VLM;06-28 "PaddleOCR-VL 本地默认"教义由本节取代。
- **三条随行纪律**:①**转默认留期权**——本地降为缝后备选不删除(今日前沿=明年 3B 本地,够好时重跑白拿);留**隐私分级路由**口子(按源路由:敏感走本地档/不解析,普通走前沿);②**"多记坐标"不松**——前沿 VLM 强于版面理解、**弱于精确坐标与逐字确定性**,锚质量仍是解析线验收标准,预期混合管线(VLM 定结构阅读序+确定性 OCR 定精确坐标);③**红线照旧**——云上 Agent 仍走与人类同一套 API 门,门禁与收据一件不少。

## 二十二之二、"为什么用 Canvas 而不是网站引擎?"——假二选一的澄清(Henry 之问,08-07 后补记)

- **缘起**:Henry 看到 Claude(另一会话)为其期末复习做的静态网站,问:能否放弃 Canvas 思路,改用"网站引擎"——笔记上一切元素都是网页的一部分,造一个引擎编辑它们?更复杂还是更简单?
- **澄清第一层:本产品的 Canvas 从来就是 DOM,不是像素画布**——与 Figma/Excalidraw(WebGL/像素)不同,Canvas Engine 的每个对象都是真实 HTML 元素(React 渲染+CSS 排版+runtime 模型管位置),"画布"只是 CSS transform 容器上的一层空间布局策略。**Henry 的提议=ADR-0001 已建成的自研混合引擎本身**;kind-general 管线即"编辑一切元素的引擎"。DOM 选择=白拿浏览器三十年家底(排版/选区/无障碍树〔AI-readable tree 之基〕/中文渲染),代价诚实在案(节点数天花板+ADR-0001 的 transform 内编辑风险,笔记量级下可承受)。
- **澄清第二层(Henry 的真发现):复习网站 vs Canvas 的差异是布局策略不是技术栈**——流式布局(读)vs 自由空间布局(摆)。恰与 07-20 §五拍定的"引用源投影页=画布引擎加流式布局策略"再次独立收敛。真答案:`DOM 底座(唯一引擎)→ 自由布局策略=画布 register + 流式布局策略=文档 register`。
- **附赠推论**:笔记本体即 DOM ⇒ "笔记→静态网页"导出=一次便宜投影;复习网站预演了订单规格未来的一种产物形态("把这个 Purpose 编成复习站")。

## 二十二之三、⭐ 总账第 0 号:开发者本人每天不想用(Henry 自白,08-07 后;全项目最重 UX 数据)

- **Henry 原话要义**:目前最大的体验问题=**"让我每天都不想用它"**——格式不厉害、调起来不方便;自建 Canvas 引擎在体感上"制造的问题比带来的好处多",难以完美;求解:怎么变容易?成熟的做笔记/生成笔记体验 = 下个版本最重要的点之一。
- **Claude 接收与拆分**:此条**直接进问题总账第 0 号**。诊断=**账单到期,非设计破产**——foundation 分诊有意签下的友好度债(粗糙行为"故意允许"在案)如期到账,V12 体验弧本为还账而设。诚实拆两半:**底座无罪**(DOM 引擎/真相层/锚/AI-tree 皆赖自研,§二十二之二刚验证;翻案=重付 90% 成本回到同一个 10% 缺口)/**表层确实薄**(被排期排薄,非造不好)。

## 二十三、第三时代:量化运维与管理驾驶舱(Henry 提出,roadmap 补完;2026-08-07)

- **Henry 提出**:BN 时代之后是 Agent 时代;Agent 之后出现新方向(暂无名)——**把整个应用系统量化**:随模型/智能更迭做测试,依据证据增减现有功能。现状:增减的依据除直觉外一无所有(产品成功率/录入效率/录入准确率等数据全无,因施工到一半未达该阶段)。时序预估:BN 收尾做小部分展望,Agent 收尾做大部分。诉求:作为开发者与未来管理者,需要**管理工具+指标参数+证据链**,说明产品现状/成果质量/策略与模型选用,以及**时代更迭中哪里成了累赘、哪里从不可能变成可能**——即软件的事后运维阶段。
- **Claude 定形**:业界三分(observability/product analytics/evals),单人产品三合一。命名候选(待拍):时代=**量化运维时代(观测台时代)**,工具=**管理驾驶舱**。roadmap 三段式:BN(建真相层)→ Agent(装手)→ 量化运维(给管理者装眼睛)。
- **结构性事实:收据网即指标原料库**——所需指标全部是对已有收据的聚合:录入准确率←解析置信度+**用户修正层(每次人工修正=一条免费标注,真相分离层兼评测数据生成器,"决策副产品"定律再兑现)**;录入效率←摄入收据;产品成功率←旅程分数+采收几步;累赘识别←操作收据聚合;新可能识别←评测曲线。
- **模型换代管理=evals**:固定基准集(真实材料+手写标本〔自带 ground truth,第一号考题〕)每逢新模型重跑→准确率/成本/延迟三曲线→换不换看图说话;可重跑派生层使其天然便宜($10k 测试预算的用途);**"模型十倍测试"由哲学问题变为例行跑分**。
- **时序修正(关键)**:表盘可晚装,**电线必须现在埋**——指标只能聚合存在的收据,回头补记不可能("多记坐标"逻辑升到管线级)。两根先埋的线:①窄腰契约写死**摄入收据**(每次解析一条 run receipt:模型/版本/成本/耗时/置信度分布/事后修正数);②磨合期旅程分数+问题总账=驾驶舱 UX 轴首批数据(V12 白送)。
