## 二、原始文档格式对溯源质量的影响（Henry 之问 + Claude 分析,待消化）

### Henry 的担忧(原样记录)

- PDF 与 Word 是承载知识最基础常见的两种格式;markdown 现实中很少承载教学性文件,多为 AI 采集/导出物,JSON 同理。
- 上传原始文档 → 整理为引用源 → 归档的全程中,原文档格式影响到底多大?具体忧虑:Word 的字体可能"超标"(我们只能还原字号,字体系统无法保证);行距/缩进无法保证;插图后图文排列顺序。图文组合反而是我们最好模拟的(本质是 canvas,比 Word 更自由)。
- **担忧的根源**:目标是笔记中从原文档提取的每一块内容都有准确溯源,**最好到每一句**;这要求页码排序正常、不与原文档错位——错位直接伤溯源的质量与效率。

### Claude 的分析

**核心拆解:两种保真,溯源只需要第二种。**

1. **视觉复现保真**(字体/行距/缩进像不像原 Word)——**对溯源零影响,且明确非目标**。投影层用我们自己的排版(TextFlow 规矩),"看原样"的收据 = 打开原件——原件逐字节保存 + SHA-256,这是 V10 已落的证据层。不要在磨合期为"像 Word"花一分钱。
2. **寻址保真**(每句话能映射回原文档的稳定坐标)——这才是溯源的命脉,而它**完全不依赖视觉像不像**。

**格式对寻址保真的真实影响排序**(与直觉相反,Word 是好学生):

| 格式 | 寻址风险 | 真实雷区 |
|---|---|---|
| DOCX | **低**——XML 显式文档序,Henry 担心的"顺序错位"在主文字流基本不存在 | 流外内容:浮动文本框/形状、页眉页脚、修订记录、嵌入对象——须当"带锚附件"处理,不硬塞文字流 |
| 文字型 PDF | **中**——PDF 是打印格式,存的是**定位字形不是阅读序**;阅读序靠推断 | **多栏、页眉脚混入、脚注插队、公式碎裂**——"页码排序错位"担忧的真正来源在这,不在 Word |
| 扫描 PDF | **高**——无文字层,先 OCR(PaddleOCR-VL 本地方向,06-28 设计) | OCR 错字 + 版面分析双重不确定 |
| md / txt | 平凡——字符偏移即坐标 | 无 |

**一个"意想不到"级的陷阱,点名记录:PDF 物理页序号 ≠ 印刷页码。** 前言罗马数字、偏移装订都会造成"引用写第 iii 页、阅读器显示第 7 页"。锚必须**同时记物理页索引与页标签**。

**图文顺序**:DOCX 行内图有明确流内位置(无忧);浮动图属流外(同上,带锚附件);PDF 图文关联本来就是启发式。画布自由帮的是**展示**,不帮溯源——图的溯源坐标 = 页/区域锚,不是文字偏移。

**现状诚实声明**:今天的地板是**页级锚 + 扁平文本**(source-reconstruction 已记档的现状);句级溯源是 06-28 三层设计的方向,不是现状。Henry 的期望("最好到每一句")= 方向正确,但需知起点。

**真正必须从第一天就做对的一件事:锚的坐标 schema——"多记坐标"原则。** 解析质量可以迭代(Henry"出了问题就知道怎么修"成立);但**锚写入时少记的坐标,事后补不回来**(数据债不可逆)。每个锚应记:物理页索引 + 页标签 + 提取文本字符偏移 + **摘录副本**(V11 锚已有 excerpt 永不清扫先例)。摘录是终极保险:即使解析序出错,excerpt+页号足以人工或重解析时重定位。写时便宜,后补无门。

### 对测试材料的推论

中英文双类型材料应**故意包含恶性样本**:多栏排版 PDF、罗马数字前言的书籍章节、扫描件、带浮动文本框的 DOCX——让格式战场在磨合期主动现身,而非上线后。

## 三、还原目标与版面理解 Agent（本卷后半;Henry 拍"多记坐标"照办)

- **Henry 拍定**:"多记坐标"原则照 Claude 推荐执行(物理页索引+页标签+字符偏移+摘录副本)。
- **Henry 直觉两条(Claude 判定均正确)**:①Word/扫描 PDF 的通用解法=视觉 AI 分析版面布局——与 06-28 记档方向(PaddleOCR-VL 本地默认)同一条,业界收敛点;②"把原始文档彻底还原格式成我们的笔记"是事倍功半——预感成立,且是教义推论:**原件版面是原件的真相(blob 层永存可看),投影的真相是用我们排版好读;"彻底还原"造出的第三物无任何真相可守**。准确率叠层之忧同样成立:每多还原一个视觉维度多一个出错面,且还原层错误在用户眼里与内容错误无异,腐蚀投影信任。
- **分界线(Claude,一句话判据)**:**改变含义的格式留,只改变外观的格式弃**——重排后理解会不会变?留:标题层级/列表/表格结构/公式/图-题注关联/强调;弃:字体/行距/缩进/分栏。表格与公式是该线上最贵的两件,值得投入。
- **第一个 Agent 的定位**:版面理解 agent(Henry:"我们最先建立的一个 Agent")——好第一棒的三个理由:自包含、可测(原件即 ground truth)、不碰知识真相(只喂 Source 层,犯错炸不到用户心血)。**输出契约=阅读序的类型化块+源坐标,不是"长得像原文的页面"**。时序:真相级施工,走 escape valve 老流程(概念稿→拍板→plan),不进 12.x 修复批。
- **准确率的架构解药**:解析=可重跑的派生层。原件永存+多记坐标+摘录副本 ⇒ 解析器升级即重跑投影,旧锚靠摘录+页号重对位——准确率从一锤子买卖变为迭代变量。锚 schema 是不可逆地基,解析质量是可重跑机器,投资优先级由此定。

## 四、组件化还原提案:窄腰架构（Henry 提案 + Claude 判定与补充)

- **Henry 提案**:还原的目的是让外部文档变成"我们自己的笔记"以享受全部系统效率红利(实时复用/简单复用);格式混杂+时代变化导致返工是最严重问题。解法:不复刻整篇——**提取全部结构组件**:文字与 inline 结构"能还原就还原";**表格/图片/diagram/graph 单拎出来成为组件**;用户可在引用源层面自行修正解析错误。所需只是"组件的位置与内容"。
- **Claude 判定:正确,即业界收敛方案,正式名=窄腰(narrow waist)架构**。复刻=O(格式数×保真维度)且时代一变全返工;窄腰=任何格式→映射到小而稳定的内部组件契约(类型化块+阅读序+源坐标)→下游只认契约;新格式只加一个前端映射,腰下零返工(Pandoc/Docling 同构)。**该契约同时就是 §三版面理解 Agent 的输出契约——两轮讨论会合于同一点。**
- **库存盘点(腰下已建成,是组装不是发明)**:TextFlow inline 结构(行内公式/代码/链接,V8)、**table.v1 结构化对象(8.11.8,表格已是一等公民)**、图片 canvas object、公式 inline 承载。组件拎出即自动继承可锚/可铸卡/可复用/AI 可读——复刻路线的表格是死像素,本路线的表格生而为活组件。效率差是量级差。
- **Claude 三条补充**:
  1. **位置的真相=顺序+锚,不是 x/y**——投影内位置=阅读序位次;源坐标(页+区域)记锚供溯源;不复刻版面坐标。
  2. **每类组件必有降级路径,终点=原件区域截图+锚**——解析没把握不硬造结构(编错的表格比图片版表格伤信任百倍);宁诚实降级,不自信编造。化解准确率叠层之忧。
  3. **用户修正层的真相分离(本提案唯一需认真设计处)**——投影=机器派生可重跑;用户修正=人类真相;两者不得同层,否则重跑解析洗掉修正(与 origin_purpose_id 同类雷)。方向:独立修正层盖在派生投影上,或用户一动手即"人类接管"钉版、重解析只产生新候选。红线:**机器重跑不得销毁人类修正,人类修正不得堵死机器重跑**。待概念稿定形。

## 五、引用源的定位钉死与笔记页面的改动（Henry 收束 + Claude 四点)

- **Henry 收束**:"彻底还原格式"降级为纯视觉需求、可后置;**真正重要的产出是用户后续的笔记**;建引用源这步最重要的是保真(寻址/内容保真);双结构(流+组件库)也能一目了然、位置有稳定保障;但它需要对笔记页面做出一定修改。
- **Claude 钉句**:**引用源不是产品,是矿场;真正的产品是用户后来的笔记。**
- **四点看法**:
  1. **KPI 换轴**:引用源页面的指标不是"像不像原文",是**"从打开到铸出第一张好卡要几步"**(采收效率)——即"材料进门/从读到卡"旅程段的体验打分标准,打眼审查的依据。
  2. **双结构=一个页面两条通路**:组件默认嵌阅读流原位(线性阅读通路,保"一目了然");同一批组件可按清单视角索引("本文档全部表格",采收通路)。一份数据两个视图;位置稳定=阅读序位次+源坐标锚。
  3. **笔记页面的真缺口只有一个:"流内嵌对象"**——对象作为阅读流成员按序排布。不发明新页面类型,给画布引擎加**流式布局策略**(同一套对象机器,布局从自由摆放切垂直流+自动定位)。一个布局策略,不是一个新真相。现状细节待 Codex 盘。
  4. **警示牌(设计红线候选)**:**引用源页面不许长成第二个笔记编辑器**——双结构页面像笔记,用户会忍不住在里面写想法,派生层被创作污染后"机器重跑不销毁人类修正"红线即失效(分不清修正与创作)。页面须在体感上分 register:引用源=矿场(采收动作最顺手,编辑藏在显式修正模式后、修正只改错带收据);笔记=花园(创作自由)。想法永远去笔记和卡,不去矿场。
- **时序**:窄腰契约+流式布局策略+双 register 页面=成套真相级+界面级施工,escape valve 老流程,大概率是磨合期后**第一个大版本**主菜。磨合期以现版引用源页面实测"采收几步"的真实摩擦,喂其概念稿。
