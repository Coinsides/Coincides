# 2026-09-04 Coincides：认知工作台、统一文档与思考痕迹

> 本记录从“Coincides 是可替换模型之上的个人认知工作台与长期知识载体”这一认识开始。此前围绕 GPT-6 Astra 发布时间、Computer Use 与开源替代品的好奇讨论不纳入正文。

## 一、讨论起点：Coincides 不与模型竞争智能

随着通用模型与 Agent 持续增强，Coincides 中由某一代模型完成的具体能力，例如 OCR、总结、聚类、笔记生成、关系建议、网页搜索与任务调度，都会快速商品化，也应当允许替换。

Coincides 不应把自身身份绑定在这些能力上。它长期承载的是：

- 模型工作的上下文、证据与目的；
- 人与 AI 共同形成的知识对象和结构；
- 用户接受、修改、否定与保留过什么；
- 这些认识在长期使用中的变化轨迹；
- 一套属于用户、不会随模型会话结束而消失的数据与操作环境。

因此，更准确的定位不是“能力集合”或单纯的“展示平台”，而是：

> **Coincides 是一个由用户拥有的认知工作台与长期知识操作环境；模型和 Agent 是可替换的认知引擎与执行者。**

模型越强，越能提高初稿、提取、整理和推断的质量；Coincides 则负责把这些短暂能力的产出沉淀为可继续工作的长期状态。两者是相互放大，而不是简单替代。

## 二、Coincides 集中的不是模型智能，而是工作结果与连续性

“把模型能力集中到 Coincides”需要进一步校准。Coincides 不必拥有或复制模型本身的智能，而应统一承接不同模型工作的：

- 输入材料与 Source 依据；
- 明确的 Purpose 与任务语境；
- 外显的结论、解释、假设和结构；
- Proposal、用户修订与接受结果；
- 对象身份、版本、关系和来源收据；
- 可供未来重新阅读、编辑和调用的稳定状态。

模型可以随时更换，模型产生的结果进入 Coincides 后才成为用户的长期资产。对个人而言，Coincides 的不可替代性主要来自数据主权、结构连续性与多年累积，而不是某项功能在技术上无人能够复现。

## 三、从输出格式到可操作的思考中间语言

TextFlow、Canvas、Item、ContentGroup、Purpose、Relation 与 Proposal 不只是帮助模型“想得更好”的工具。它们首先共同构成一套人和 AI 都能使用、都能修改的表达语言。

- **TextFlow**：承载可继续编辑的语言表达，而不是一次性文本输出。
- **Canvas**：承载空间表达、排列、圈选与整体视野。
- **Item**：承载具有稳定身份、可独立处理的知识单元。
- **ContentGroup**：组织和捆绑 Item，而不取代 Item 的知识身份。
- **Purpose**：赋予判断成立所需的任务语境和方向。
- **Relation**：把 Purpose 下的显式判断连接成可查询、可修订的结构。
- **Proposal**：成为 AI 行为与用户主权之间的交接面。

HTML 或 PDF 往往作为一次生成后的成品出现。HTML 在技术上可以编辑，但临时生成的页面通常要求用户穿过代码和页面结构才能修改；PDF 更接近终稿。Coincides 要交付的则是一组仍然“活着”的对象：每个对象有稳定身份、语义边界和编辑入口，可以被选择、移动、拆分、改写、重组或再次交给 Agent 处理。

因此可以形成如下闭环：

```text
人类提供材料、Purpose 与要求
  → AI 生成结构化初稿或 Proposal
  → 初稿落成 TextFlow / Item / Relation / Canvas 对象
  → 用户直接修改，或圈选明确范围要求 Agent 修改
  → Agent 读取修改后的同一份状态继续工作
  → 用户接受的结果沉淀为长期知识资产
```

这不是让 AI 交付一张“思考截图”，而是让 AI 交付一份人类可以接手的可操作结构。

## 四、模型思考的记录边界

Coincides 不需要也不应试图保存模型不可见的内部思维链。值得沉淀的是模型明确交付给人的外显思考产物，例如：

- 结论与主张；
- 证据和 Source 锚；
- 假设与不确定性；
- 分类、关系和结构；
- 可审阅的解释；
- Proposal、修改与最终决定。

这些内容既能由人检查，也能成为下一轮人机协作的输入。

## 五、从个人图书馆到带有思考痕迹的知识系统

Coincides 可以承担个人知识数据库或个人图书馆的角色，但它比传统图书馆多保存一层：用户如何重新理解、组织和连接这些材料。

传统图书馆主要保存材料；Coincides 还希望保存：

- 哪些材料曾进入用户的注意；
- 用户或 AI 在什么 Purpose 下发现了联系；
- 哪些联系被接受、修改、否定或取代；
- 当前认识如何从此前认识生长出来。

因此它也接近一本长期研究日志：既有藏书，也有围绕藏书形成的认识地图。

## 六、Source 驱动之外，还有思考驱动

此前最熟悉的路径是：

```text
Source → 提取与整理 → Item → Relation → 笔记
```

日记、述职、工作报告与学习反思揭示了另一条路径：

```text
自由口述或写作
  → TextFlow 忠实接住
  → 笔记完成
  → AI 事后阅读
  → 发现隐含关系
  → 提出 Item 与 Relation Proposal
  → 用户确认或修正
```

没有外部 Source，不等于没有来源。带有作者、时间与版本的用户笔记，本身能够证明“用户当时这样表达和判断过”，但不能自动证明其中观点在客观世界中为真。

AI 可以先定位相关段落，再提出“这里可能存在一条关系”的 Proposal。用户确认后，才把真正值得长期保留的内容铸成 Item 并建立 Relation。这样自由表达不会被知识工程打断，图谱也不会被每一句随口的话淹没。

更长期的价值来自纵向回看：今天的学习报告可能认为甲导致乙，半年后的笔记则修正了判断。系统不应简单覆盖旧关系，而应允许用户看见认识如何发生变化。

## 七、统一文档哲学

Source 不是某类文档与生俱来的固定身份，而是一个文档在某次工作中扮演的角色。

一本教材在第一次整理里是 Source，整理出的笔记是产物；半年后，当用户用这篇笔记写报告时，它又成为新任务的 Source。日记写下时是用户原创内容，后来复盘自己的思想变化时，它也会成为一份第一手材料。

当前形成的统一认识是：

> **所有笔记都可以成为引用源；所有引用源都可以拥有与笔记同构的文档表面。**

外部 HTML、教材、用户日记、AI 整理稿与 Coincides 内部笔记，可以共用 TextFlow、组件流、Content Range、Anchor、Item 铸造与 Relation 能力。

统一的是文档能力，不是出生事实和生命周期纪律。更宽泛的共同地基可以理解为 Document Artifact：

- 外部引用源的内部重建件仍应忠于原件；
- 用户原创笔记天然可以继续编辑；
- 派生笔记保留它所依赖的上游来源；
- 可变笔记被再次引用时，应锚定当时版本和具体范围；
- 系统不负责裁判材料是否合法，但不抹除其来路、时间与原始收据。

可以暂时概括为：

> **Sourcehood 是上下文角色，provenance 是出生身份，evidence suitability 是另一次判断。**

系统里没有永远只能当原料的文档，也没有永远只能当成品的笔记。任何 Document Artifact 都可以进入下一轮思考，但它从哪里来、何时被引用、当时是哪一版，始终可追。

## 八、Relation 与思考痕迹的第一次分层

Relation 很重要，但 Relation 本身主要表达一个当前判断的结果，例如支持、反对、因果、类比或依赖。它不能独自承担从疑问走到判断的全部过程。

本次讨论形成的初步分层是：

> **Relation 保存当前认识；判断履历保存认识的形成与变化。**

### 8.1 最小判断收据

用户手动建立 Relation 时，系统可以自动留下一个很薄的判断收据，至少包括：

- 行为发起者是用户还是 AI；
- Relation 所属的 Purpose；
- 被连接的对象；
- 当时是候选、怀疑、确认还是其他状态；
- 可选的 Source / Anchor 依据；
- 后续是否被修改、否定或取代。

直接连线本身就应形成最低限度的痕迹，不应强迫用户每次填写一张复杂表单。用户愿意时，可以再补一句“为什么”或添加证据。

### 8.2 探索会话

当用户进行一段持续推理时，可以考虑把连续建立、删除、修改和比较的若干 Relation 聚合为一次“探索会话”或“判断会话”。它不保存鼠标录像和每次犹豫，而保存真正改变知识结构的语义节点：

- 最初关注了哪些对象；
- 提出过哪些候选联系；
- 哪些候选被舍弃；
- 最终保留了哪些判断；
- 判断后来如何演化。

这更接近实验记录，而不是完整思想转录。

### 8.3 当前图与历史账分离

为避免十年使用后 Relation 历史成为 Agent 的巨大噪声：

- 日常 GraphRAG 与 Reading View 默认读取当前有效关系；
- 判断履历、被否定关系和历史版本进入独立的按需读取面；
- 只有在用户或 Agent 追问“为什么存在”“如何变化”时，才水合相应历史。

AI 推出的 Relation 表示“模型发现了可能联系”；用户亲手建立的 Relation 则是更强的注意与判断信号。即使后来被推翻，“它曾进入过用户的判断”这一事实仍有保留价值。

## 九、百万级资料库的真正难题

当笔记和引用源增长到百万级时，真正稀缺的不再是信息，而是模型上下文与人的注意力。

问题不只是 RAG，而是：

> **在当前任务中，如何判断哪几十个对象和具体范围最值得被看见？**

这是一套注意力分配系统。普通向量检索只是其中一个部件。

当前形成的分工是：

- 标签描述“材料是什么”；
- Purpose 描述“用户现在为什么做”；
- 检索系统判断两者此刻在哪里相交；
- Relation 与 GraphRAG 扩展已经显式连接的邻近知识；
- embedding 发现尚未显式连接的潜在相似；
- 全文检索保证专名、年代与术语的精确命中；
- Reading View 把最终选中的范围编译成模型可读上下文。

Purpose 不应成为硬边界，否则跨学科联想会被提前消灭。它更适合影响排序与解释“为什么现在相关”。

标签也应区分：

- **描述性标签**：领域、年代、地域、文档类型和主题；
- **评价性标签或收据**：用户是否读过、核验过、接受过、反复引用过，材料是否可能过时，以及它适合导航还是适合承担证据。

检索相关性与证据适用性不能混为一个分数：

> 一份材料值不值得被模型看见？

与：

> 一份材料值不值得被模型相信和引用？

这是两个不同的问题。

同一观点可能经过摘抄、总结与再总结，出现在大量文档中。系统不能因为重复次数多，就把它误判为多份独立证据。Source lineage 与版本链应帮助检索折叠派生重复，并在需要时回到根来源。

系统也可以保留少量明确标注的探索预算，从较远学科与旧笔记中发现结构类比，避免个人知识库变成只会重复既有分类的封闭回音室。

## 十、Harness、模型与 Agent 的分工

这部分不适合由一个 Agent 从头包办。

- **Harness 管秩序**：元数据、去重、版本链、用户标签、全文索引、embedding、候选召回、预算、权限与收据。
- **模型管语义**：建议标签、概括内容、评估当前相关性、判断证据适用性与重新排序候选。
- **Agent 管过程**：多轮检索、发现缺口、改写查询、回查来源、比较冲突、决定是否继续以及何时停止。

百万级资料库中，Harness 先把范围从百万缩到几千，检索与标签再缩到几百，模型重排到几十，Agent 只围绕真正有价值的材料深入工作。

模型生成的标签、可信度判断与 Relation，都应先作为评估或 Proposal，而不是静默成为永久真相。

> **Harness 管秩序，模型管语义，Agent 管过程。**

## 十一、库内材料与开放网络的选择

这不是“私人库或互联网”的一次性二选一，而是一套证据获取策略。

当前最有价值的默认方向是：

> **库内优先，先检查充分性，再针对明确缺口联网。**

Agent 先把任务拆成需要覆盖的子问题，再检索库内材料，形成覆盖情况：

- 哪些部分证据充分；
- 哪些只有单一来源；
- 哪些互相冲突；
- 哪些已经过时；
- 哪些完全缺失。

只有薄弱、冲突或缺失的部分，才触发外部检索。联网不再来自模型模糊的“感觉不够”，而来自可检查的证据缺口。

不同任务应有独立于 Purpose 的 Evidence Policy 或 Research Scope：

- 用户明确限定材料时，执行封闭语料任务；
- 用户要求完整调查或最新信息时，执行开放世界任务；
- 一般请求默认库内优先、按缺口补充。

模型自身的参数知识可以帮助拆题、提出关键词与发现可能缺口，但不应在正式笔记中悄悄冒充证据。

只要外部网页真正支撑了笔记内容，就应连同网址、抓取时间、快照与具体引用范围进入 Source 系统。每一次联网调查因此也会反过来充实个人资料库。

总体协调者负责判断任务边界、检查覆盖缺口、分配预算与留下收据；大量网页搜索与比较可以交给专门的调查执行者，避免协调上下文被网页正文淹没。

因此，核心选择规则可以压缩为：

> **先问库里有什么，再问是否足以完成当前任务；只有答案是否定的，才去开放世界补缺，而且只补缺口，不推翻用户已经积累的整个知识环境。**

Coincides 的资料库既不是封闭孤岛，也不会因为互联网无限大而失去存在意义。它是用户的认知主场，网络是按需进入的外部补给线。

## 十二、当前形成的总体认识

Coincides 正逐渐显露出三重身份：

1. **个人知识载体**：保存 Source、笔记、对象与长期知识结构。
2. **人机共用的认知工作台**：让 AI 产出可由人直接接手，让人的修改成为 AI 的下一轮上下文。
3. **认识演化的收据系统**：不追求保存全部思考过程，而保存真正改变知识结构的语义时刻。

可以暂时用一句话概括：

> **Coincides 把不同模型和人类产生的外显思考，转化为可操作、可审阅、可追溯、可长期生长的共同知识状态。**

## 十三、后续开放问题

1. Note、Reference Source 与更上层 Document Artifact 的边界如何正式定义？
2. 人工建立 Relation 时，最低限度必须记录哪些字段，才能既有价值又不增加操作负担？
3. AI 提议、用户手动建立、用户接受 AI 提议三种 Relation，在来源与权重上应如何区分？
4. “候选 / 怀疑 / 当前采纳 / 被取代 / 被否定”应属于 Relation 状态，还是判断履历中的事件？
5. 什么情况下应自动把连续操作归并为一次探索会话？用户是否需要显式开启推理模式？
6. 当前有效图与历史判断账应如何分别提供给 GraphRAG 和 Agent？
7. 描述性标签、用户评价收据和模型评估如何分层，避免标签爆炸？
8. 如何定义任务的资料充分性，而不让 Agent 凭感觉决定联网？
9. Evidence Policy 应提供哪些用户可理解的模式？
10. 如何折叠“总结的总结”，避免派生内容被误当成多份独立证据？
11. 如何为跨领域偶然发现保留空间，同时不污染高相关性检索？
12. 这套“认知工作台”定位最终应回填到哪份权威产品文档？
