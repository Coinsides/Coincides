# 2026-08-08 Better Notebook:对照实验全程摩擦记录(应用内重建 ECON 讲稿)

> Henry 发起对照实验:把 Claude(另一会话)制作的 ECON 复习网站,在应用里以真实用户方式重建同一份笔记,对比两版。本卷按 Henry 要求**记录制作过程中遇到的全部问题**,按遭遇顺序逐条,含复现路径与逃生路径。
> 方法申明:Claude 以内置浏览器鼠标+键盘操作,不走 API;JS 探针仅作"眼睛"(验证状态),从未作"手"(执行操作)。素材:July 8《跨时期价格歧视》讲稿(七节+附录,原网页含分数/SVG 图/表格/三类卡片)。

## 一、顺利的部分(先记好处,按 07-15 卷记录纪律:好坏都记)

1. 登录→Projects→新建项目(ECON 201)→进入项目→New Note:全程顺畅,表单直给,无多余弹窗;
2. 笔记直接开页,标题内联可编辑,自动保存(标题在刷新后留存);
3. **连续打字管线稳定**:约 1800 字符分四段连续键入,零丢字、零卡顿,自动跟随光标滚动;
4. Unicode 数学记号(½ ¼ δ ε π ⟺ ∈ −)渲染良好;
5. 画布缩放控件工作正常,60% 可整篇一屏。

## 二、问题全记录(按遭遇顺序)

### 问题 1:主页与项目侧栏大量按钮无 accessible name
- **现象**:登录后 read_page(无障碍树)显示整排空 `button`(侧栏项目条目、主页若干控件、新建项目表单的颜色/图标选择器全部无名)。
- **影响**:屏幕阅读器用户与 agent 均无法辨认按钮职能;我只能靠父子结构猜测。
- **建议严重度**:🅱。

### 问题 2:写作入口只认双击,单击静默无反应
- **复现**:新笔记页,对"Double-click to start writing"占位按钮单击→无任何反馈。
- **影响**:新手第一反应是单击;点了没动静的第一印象是"坏了"。按钮自己的文案都在为这个交互道歉。
- **建议严重度**:🅱(与总账第 0 号直接相关)。

### 问题 3:双击开写后,焦点不移交写作面(🅰)
- **复现**:填完标题→双击占位按钮(按钮消失)→直接打字→**32 个字符全部追加进了标题输入框**,标题被污染为"完整讲稿(应用版)ECON 201 · July 8 lecture…"。
- **影响**:用户以为在写正文,实际在毁标题;真实场景丢失整句输入+需要手工修复标题。
- **逃生**:手工改回标题。
- **建议严重度**:🅰。

### 问题 4:画布正文对文本抽取与无障碍树双盲(🅰,基建级)
- **现象**:`main` 的 innerText 与 a11y 树中,画布正文**一个字都不存在**(只余"Project / Page / Preview / Layout"等 chrome 词)。全程如此,包括最终 1800 字全部落地之后。
- **影响**:三路同伤——无障碍(屏幕阅读器读不到笔记)、agent 可操作性(机器看不见正文,本次实验被迫用 JS 探针当眼睛)、未来全文检索与"笔记→网页导出"路径。
- **定位**:canvas 自建检查线(08-04 卷观察位二)的最强依据;AI-readable tree 与 DOM 呈现的对齐问题。
- **建议严重度**:🅰(基建级)。

### 问题 5:空画布状态下,"纸"本身无任何可寻址交互表示
- **现象**:占位按钮之外,页面本体在交互树中不存在;占位按钮消失后交互树里再无任何写作入口。
- **影响**:与问题 4 同族;ref 式(非坐标)操作完全无法触达纸面。
- **建议严重度**:🅱。

### 问题 6:Page 模式死胡同——占位按钮消费后,空笔记永久无法开写(🅰)
- **复现**:占位按钮被一次双击消费(未产生任何内容)→此后对纸面任意位置单击/双击/先单后双全部无反应(JS 确认点位正确命中 writingSurface/blockList)→ **F5 刷新后占位按钮不回来,依旧无法开写**。
- **影响**:空笔记进入不可恢复的死锁状态;真实用户此刻只能弃笔记重建。
- **逃生**:切换到 Canvas 模式(开放画布)→双击立即正常创建段落块。**死结为 Page 模式专属**。
- **建议严重度**:🅰。

### 问题 7:斜杠菜单键盘流全断(🅰~🅱)
- **复现三连**:①行首输入"/"→菜单在 DOM 中打开(Text/Heading/Quote/Bullet/Numbered/Todo/Toggle/Code line 八项)→键入"hea"过滤到 Heading→**Enter 不选中**,反而把"/hea"留在正文并换行;②重开菜单→**Down 方向键直接关闭菜单**(无高亮移动);③关闭后"/"字符残留正文。
- **影响**:斜杠菜单实际只能鼠标点选;键盘用户(写作场景的主姿态!)全程不可用;失败还污染正文。
- **建议严重度**:🅰~🅱(功能在,键盘通道断)。

### 问题 8:斜杠菜单打开时,截图中不可见(待复核 🅲)
- **现象**:JS 确认菜单在 DOM 中(位置 844,164,尺寸 420×360,内容齐全),同刻截图中肉眼不可见。
- **可能**:渲染层遮挡/透明度/截图时序。留待复核,若为真遮挡则升级。

### 问题 9:编辑态可见反馈弱,错位操作悄悄污染正文(🅰)
- **现象**:斜杠失败残留、重复字符("现象//")累积在正文,而当前"哪个单元在接键"没有清晰的视觉指示;我方多次操作后正文状态与预期漂移却无告警。
- **影响**:用户在无感知情况下积累文本损伤;配合问题 10 形成"看见的改不了、改的看不见"。
- **建议严重度**:🅰。

### 问题 10:所见文本与可编辑面错位——ADR-0001 风险首个活体样本(🅰,分量最重)
- **复现**:对可见文本行(渲染 overlay)单击→焦点落在**空的** textarea(selStart=0,value="");三连击同点→仍是空 textarea;在该空单元按 Backspace→**不发生向前合并**,前一行内容纹丝不动。点击可见文字与命中可编辑单元之间失去对应。
- **影响**:定位编辑(改错字、删残留)在该状态下完全不可能;这正是 ADR-0001 挂账两个月的"TextFlow 在 transform 画布内的编辑稳定性"开放风险的第一次实测证实。
- **逃生**:放弃定位编辑,整块删除重打("只进不退"策略)。
- **建议严重度**:🅰;**并案建议:问题 3/6/9/10 疑似同一个焦点/坐标管理 root cause 的四种症状,建议 Codex 并为一案查**。

### 问题 11:整块删除无确认(🅱,双刃)
- **现象**:选中块→点垃圾桶→整块(含全部正文)即刻消失,无确认、无 undo 提示。
- **双刃**:本次是我的救命逃生门;误触场景则是数据危险(心爱之物可凭空消失半步之遥——依赖后续 undo 体系兜底,但当场无任何反馈)。
- **建议严重度**:🅱。

### 问题 12:新块落点=双击原位,长内容伸出视野(🅱)
- **现象**:双击点即块左上角,长行向右越过视野边界(首个块在页面右缘创建,三行字直接出屏)。
- **影响**:配合问题 4(读不到)与问题 10(点不中),出屏内容的找回成本高。
- **建议严重度**:🅱。

### 问题 13(实验方法侧,非应用问题,如实记):
- 内置浏览器截图需面板显示(中途请 Henry 开面板);坐标点击需先截图缓存;get_page_text/read_page 因问题 4 全程对正文失效——**agent 侧测试的可行性本身就依赖问题 4 的修复**,本次全靠 JS 探针+截图混合导航完成。

### 问题 14(Henry 观察,事后补记):整篇内容糊进单一容器——Agent 行为的预演(🅱,系统性)
- **现象**:最终成品为**一个段落块**装下全部七节+附录(约 1800 字;块内虽有逐行 text unit,块级仍是单体巨石)。网页版的八个 section 结构在应用版中没有对应的块级结构。
- **Henry 的关键定性**:Claude 从头建笔记=**模拟未来 Agent 建笔记**——这个"糊一坨"不健康。
- **成因申明(诚实)**:结构化输入通道全断(斜杠键盘流断/角色不可达/定位编辑失效)后,"只进不退"连续打字进单块是唯一可靠路径——**是 UI 的摩擦教会了我不健康的模式**。斜率定律:当结构化的成本高于糊坨,智能体(人或 AI)必然滑向糊坨;健康结构必须是最低阻力路径。
- **下游代价**:锚粒度粗(溯源只能指向巨石)、铸卡/CG 收编无从按节下手、骨架层折叠(08-04 卷 §九)无结构可折、重排/流式布局无块可排——**单体巨石掐断整条下游价值链**。
- **两条设计推论**:①**Agent 时代硬约束:生成笔记必须生而结构化**(每节一块、角色就位)——订单规格的产物走同一对象模型,窄腰的类型化块直通块结构;②**输入侧机制候选**:长文本粘贴/连打自动按空行成块、结构健康度的安静提示。
- **建议严重度**:🅱(系统性;与总账第 0 号、12.2 日常书写段直接相关)。

## 三、结论(与交互报告一致,此处存叙事版)

1. **内容真相层完好,表现层与交互层欠账集中**——1800 字一次成型证明管线底子好;但"格式的成熟感来自默认值"被对照直观量化:同一内容,网页版与应用版的观感差一个量级。
2. **一条 root cause 主线贯穿四个 🅰**(3/6/9/10):编辑焦点/坐标管理与可见渲染的对位脆弱。修一处,可能四症全消。
3. **问题 4 是基建级**:它同时决定 a11y、agent 可操作性、全文检索与磨合期自动化测试的可行性——canvas 自建检查线应以它为第一目标。
4. 12.2"日常书写段"的最小交付清单由此实验自然生成:排版预设、修通至少一条键盘格式通道、Page 模式死胡同、焦点对位并案。

## 三之二、独立议题:OpenClaw(小龙虾)改装为管家层(Henry 提案 × Claude 落点修正;停车场,Agent 版概念稿素材)

- **Henry 提案**:Agent 版可否直接把 OpenClaw(MIT,Henry 已验许可,含现成 harness 与其自建记忆系统)修修改改放进来?功能过全→裁剪,专精靠 skill;OCR 等工具配套配齐。
- **Claude 判定:成立,落点修正半步**——小龙虾的本体是编排 harness(会话循环/记忆/skill/工具调度/网关),**恰好是 08-04 拍定两层结构中"外部管家"的现成身体**(Henry 原计划自造的那层,从自造变改装);应用内 Agent 层的本体则收敛为**工具面**:应用操作暴露为工具(天然形态=MCP server)+红线守卫+收据——领域逻辑不可替代但恰恰最小。**Agent 版工程量假设由此改写:编排层改装、应用层缩为工具面。**
- **教义兼容性**:"应用不被任何 LLM 绑架"毫发无伤(管家可换,工具面不动);缝而不焊原样适用——**小龙虾=sidecar 服务,永远在 HTTP 缝另一侧,不进应用进程/不碰 DB/不碰文件,与人类同门同钥**。
- **三条边界纪律(预钉)**:①记忆分家——管家记忆管操作,知识真相只在应用收据层,管家读知识走 API,不建第二份真相;②OCR 等解析工具配应用侧(Source 管线,云 VLM 已拍),管家只下订单,不旁路管线;③fork 纪律——pin 版本、最小 diff、skill 优先于核心手术(Henry"专精靠 skill"直觉即此,附带上游升级不撕裂红利)。
- **时序**:Agent 版概念稿素材,escape valve 老规矩,记录不动工。
- **Henry 升级(同日续,拍定方向):外骨骼模型——不被任何 harness 绑架**。应用=机械外骨骼,末端执行器(锚/铸卡/捆组/投影等工具)是我们的形状、专为经营笔记而造;**穿戴者(小龙虾或任何 harness)可换**,接入只是简单拼装;甚至可同时接入多个 harness 分别调查效率与成品质量。Claude 钉三点:①拼装环节的标准名=**MCP**(工具面做成 MCP server,接入=一行配置,业界已收敛的即插标准);②**harness 跑分成为驾驶舱第三评测轴**(模型/解析器/harness 三个可租层同仪器量;同门同钥免费提供评测公平性——各 harness 同工具同权限同收据义务,差异零污染;订单规格=现成标准考题,同单各交一份盲评);③**纪律:外骨骼不许为任何穿戴者整容**——工具形状只由笔记语义决定,不为特定 harness 开特例("改锥的形状由螺丝决定,不由手决定"),否则缝焊死、评测被污染。**三层互不绑架至此补完:大脑(模型,08-07)/穿戴者(harness,本节)/外骨骼(应用,不换)。深层含义:Agent 时代核心资产=末端执行器的设计(工具粒度/描述/守卫/收据)——智能全是租的,手是自己的。**

## 三之三、独立议题:HTML 成品笔记与画布引擎的关系(Henry 之问:冲突吗?答:不冲突,第三次收敛)

- **Henry 的想法**:他会话里 Claude Code(Fable)产出的 HTML 复习网站"立马能看立马能用"且漂亮(为数学公式显示优先选 HTML);Agent 版若要交付成品笔记,HTML 很有意思;缺点=HTML 修改不如画布自然(调高度/大小,item 风格更方便);问:网页能否也模块化、用户自由调节后"保存为一个网站"?似 Lovable 而 Lovable 做不到;与画布引擎冲突吗?
- **Claude 判定:HTML 是投影格式,不是真相格式**——三层分工:真相层=对象模型(Agent 生成落点,即发现 14"生而结构化"的另一面)/编辑层=画布引擎(随手改的承担者)/投影层=编译出静态 HTML 站(交付形态)。**生成 HTML 血团=Lovable 困境(真相是代码,改=重 prompt);生成对象=我们的路(真相是类型化块,改=直接上手,HTML 随时重编译)。"真相存对象,投影出 HTML"与"规格是真相,prompt 是编译产物"同一条语法。**
- **复习网站的美貌来源**=排版决定被设计系统提前做完(杠杆一);Agent 版正确做法=**把设计系统装进导出编译器**,而非让模型每次自由发挥 HTML(好看但不可编辑/不一致/不可锚)——模型审美收编进编译器。
- **与画布引擎:恰是画布第三次被证明必要**(①§二十二之二 画布即 DOM+编辑引擎;②同节"导出=便宜投影";③本节:HTML 成品可编辑化的唯一解=编辑发生在对象层)。**导出地位升级:订单规格新增正式输出轴(应用内笔记/静态 HTML 站/两者)。**
- **诚实边界**:超出组件词汇的生成需求,优先沿"表示变换"轴添 kind(折叠问答=toggle 角色现成,接手写标本"纸盖不住答案");**"内嵌 HTML 对象"沙盒逃生舱=最后手段**(血团不可锚不可铸,内容退出真相层)。

## 三之四、独立议题:笔记工厂愿景与三层分速(Henry 两案合流 × Claude 冷水与定形)

- **Henry 合流**:小龙虾案(工程能力 harness,可多家互补如 OpenCode)× HTML 成品案 → 愿景:harness 的工程能力可为用户改样式(如毛玻璃 glassmorphism,agent 带 browser use 自行网上调研风格)、造新组件;用户可手编组件也可令 agent 代编;**不必把全部笔记内容搭在画布白板上——用户要的不是完全自由,是快速出可用好用的成品**;第一优先级=画布摆组件位→导出成品网站,HTML 随时可打散回画布重排;text block 也是组件之一("没必要像现在一样别扭地放画布上");精细字体字号调节可倚赖网页现成参数标准;软件主体性占比不必在意——主体性=自己,harness 是搭配。
- **Claude 冷水(先记)**:愿景里藏两个产品——**笔记工厂**(装配→编译成品,Agent 时代正确形态)与**笔记本**(花园,总账第 0 号的痛处)。手写标本教义:工厂产物服务理解之前,花园产出(Guess 层/卡)服务理解之后且是工厂的原料。**"不需要完全自由"仅在装配 register 成立,书写 register 不成立;12.2 日常书写段优先级不因工厂愿景后移——否则工厂没有原料。**
- **定形四点**:①text block 本就是 kind,"别扭"源于默认面是自由白板——解=**流式布局策略升级为默认装配面**,自由白板降为可选视图(与实验发现互证:自由摆放=摩擦重灾区);②CSS 标准对一半——标准是单位不是决定,排版预设/token 仍需自建(标准免造尺,预设免量尺);③主体性底线表述:**主体性=真相层+红线+末端执行器,交付面百花齐放**;④**三层分速**(防 Lovable 困境回流):**样式层快**(风格=token 包+主题,是数据不是代码,agent 调研→产包→即刻生效)/**组件层慢**(新 kind=代码=kind-general 注册,走工程 agent+审查慢道,不在用户运行时)/**内容层即时**(永远是类型化对象,永远可打散回画布——真相从未离开对象层,故成品站永远可拆)。
