## 一 · 四堵墙(Henry 已拍:"是 OK 的,也就这么多了")

工具注册表式 Agent 的可达空间=既有原语的组合;四类需求结构性撞墙:

1. **表现力墙**:用户要新表现形式(时间轴/新卡面/小游戏),应用没有该原语则动词无用。Henry 早有测量仪:验收北极星的 Artifact 对照组(差距=表达力缺口清单);
2. **主动性墙**:每个动作 Agent 都会做,但「没人说话它也做」需要触发器/调度运行时——今天不存在;它是独立权力形态(规则在人睡时跑),需自己的门、注册表、总闸;
3. **外界墙**:每个外部连接(网页/视频字幕/发送分享)=一份代码,集合无界;
4. **智能墙**:失败不因缺工具而因模型不够聪明;任何权限治不了,归调教环。

越墙总原则(Fable 提,Henry 未反对):**把「改代码的事」降级成「改数据的事」**——可解释模板(墙一)、规则即数据+独立门(墙二)、连接器协议(墙三)。V2 现物种子:部件注册表/composition templates/皮肤套件/组件块第四族。

## 二 · 三层分权与挂靠(Henry 提案)

Henry:应用可独立存在;要具备"动源码"级的生长能力,不必内置,而是**挂靠外部 Agent**。Fable 与 Codex 即是活例——独立于应用的工程 Agent,不参与软件治理,由 Henry 发现问题→提工程需求→指挥施工。主动性与外界是两大重灾区:每种主动性动作=一套脚本,一套脚本盖一族相似问题,跨域即需第二套/改第一套;外界能力与其自己写,不如挂靠综合性 Agent。挂靠对象点名 **deepseek-harness**(开源,可动其源码,可着重强化其检索技能)。核心判据:**离开外部 Agent,核心功能不变,人能用**——此点今天已做到。

## 三 · deepseek-harness 核查(2026-09-16,Fable 实查)

**仓库:<https://github.com/deepseek-ai/deepseek-harness>**(⚠️ 该项目发布于 Fable 知识截止之后,库内无先验印象——凡涉 dsh 事实以实查为准,本节即首次实查记录)

- **身份**:DeepSeek 官方开源 agent harness(`dsh`),MIT,「一切皆插件」(Cordis 框架),`npx @deepseek-ai/dsh web` 本地起 Web UI(127.0.0.1:3080);开发者预览期,官方声明会有破坏性变更;实查时 226k stars,前一日仍在推送;
- **MCP 客户端:实锤**。`packages/mcp/` 包组:连接外部 MCP 服务器、调用其工具、读取其资源;服务器限定命名/环境变量清洗/每服务器指令。与我们在役的 MCP 服务面两头同协议,零胶水对插;
- **模型面:供应商中立**。`llm-deepseek`(官方)+`llm-pi-ai`(其他供应商/自定义网关);
- **主动性(墙二)**:`schedule` 包=会话内持久提醒(延时/定点/间隔,重启不丢,到点以消息唤醒 agent——已是一个主动性原语),但明确不出会话;跨会话常驻规则要靠其 `webhook`/`jobs` 包或**自写 dsh-plugin**(全插件化+MIT 在此兑现价值,官方设 `dsh-plugin` topic 供生态发现);
- **检索强化的更优路**:dsh 的记忆方案本身走 MCP(官方"第三方 memory MCP 指南")——**不必 fork 强化它,把我们的应用变成它挂载的检索源**(材料库/源库/imprint 检索以 MCP 资源喂给它),方向反转;fork 权留作后手;
- **安全与文化**:自带 `guard`/`sandbox`/`credentials`/SAFETY.md;仓库内有 AGENTS.md/CLAUDE.md/.agents 设计笔记——同样以 agent 纪律造 agent,文化兼容;
- **风险**:预览期破坏性变更(缝=标准 MCP 可隔离大半;真挂时钉版本);真接线前需专门安全审一轮。
