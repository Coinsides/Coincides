# 2026-06-28 Better Notebook：ContentGroup / Relation 哲学深化 + 文档上传与源重建会议记录

> 与 `会议记录/` 下其它记录平行。本次从产品哲学一路谈到文档上传管线。Henry × Claude。
> 注：本次也涉及大量 Henry 的个人人生哲学/学习经历（应试 vs 加拿大教育、CS/LoL 经历、对苦难/自由/价值的看法、对 AI 的态度等）——它们是这些设计的**灵感来源**，但属个人范畴，未誊入本产品记录；只蒸馏出与产品/设计相关的原则。

## 一、产品哲学深化：一条结构铁律 + 态度 vs 状态

**结构铁律（separation-of-truths 的锐化）：凡是"相对于某上下文/目的"的属性，都不许焊死在"内在身份"上。** 一焊：复用就坏、跨上下文就串味、相对就僭越成绝对。本次一晚撞见三次同一形状：

1. **block 身份焊成 `block_id`**（8.11.1 那颗雷）：block 的 per-note 画布身份焊到了内容 id 上 → 跨 note 复用即串。修=per-placement 合成对象 id。
2. **per-purpose 角色**：ContentGroup"在某目的下的角色"（学习=definition / 复习=考点）必须待在 per-purpose placement 上，不能焊到 ContentGroup（其**本相角色**留在 ContentGroup 上是合理的，这是另一回事）。
3. **fitness-state**："为复习目的不可用"必须锁在该目的内，绝不能漏成对 ContentGroup 本身的"无用、删了"绝对裁决。

**这条铁律 = Henry 的世界观的数据模型版**：一个东西进框之前没有好坏，是画了框才有；"东西"本身无框，所有判断都活在框里（placement / 目的 / 视图）。

**态度 vs 状态（被 Henry 修正过的产品原则）**：
- **避免**绝对的、带态度的裁决（好/坏、对/错、accepted/rejected 当判决）。
- **保留**目的相对的 fitness-**状态**（可用/不可用-for-this-purpose，一个状态机，陈述贴合度，不否认价值）。这是**必须有的**——否则什么都被选进来、Agent 负荷爆炸；有限资源逼着做取舍（以后甚至要 importance-scoring，不理想但没办法）。
- **两套视图，别串味**：**过程视图**（无框、不评判、忠实保存——看自己的思考/弯路，全是材料）vs **目的视图**（有框、有状态、分配资源）。
- Claude 一度过度主张"产品该完全无框/像自然不强加框"，被 Henry 纠正：**框就是目的本身**；在目的下操作必然有参照→标准→对比，且需要它。"大家都是框里的人。"
- **拟进 PRODUCT.md 的总原则**：不是"无框"，是 **"状态带目的，相对不焊绝对"**。

**AI 协作的一句脚注**：AI 帮组织/提议时，要锚定在"用户已有的、特别的组织方式"上去长，而非从通用知识凭空生成——保住用户指纹，别把用户洗成平均值（homogenization 比 coerce 更隐蔽）。

## 二、ContentGroup 是什么（深化）

**ContentGroup = "从洪水里蒸馏出的精华"，是一个理解的单元，不是装碎片的盒子。** 人学东西要读海量，但留得下/想留下的只有重点——ContentGroup 就是那个被留下的重点（从 content member 里只挑最精华的）。
- 对**写笔记**不是必需（直接写就行）；它是**学习/理解那一层**——"读完这一堆，我要留下什么、按什么角色留"。
- **Petal** = 给这份精华上**内部结构/子角色**（definition 里的 concept_name / description / example）。
- **角色是分层的**：目的层（folder）→ ContentGroup 层 → Petal 层，每层在自己的粒度上答"你扮什么"。purpose 套 ContentGroup 套 Petal，是个角色的分形。
- **不是所有 ContentGroup 都有意义**（用户乱建/AI 建错）；被接受/有分量的才进知识图。
- 一个对象，**既是人要留住的精华、又是 AI 能读的结构化单元**（这就是"ContentGroup 是 AI 的那一半"和"它辅助人类"不矛盾的原因）。

## 三、Relation 是什么（深化）

**Relation = 两个知识单元之间的联系 = 理解真正住的地方**（一堆没连起来的事实是记忆，连成网才是理解）。
- 它**既是人的知识图谱、也是 AI 的**；进图数据库、AI 可检索（GraphRAG 是它的一种实现形式，不是它的语义本身）。
- **endpoint 只能是 ContentGroup / Petal**（合格的、带角色的知识节点），**不是**任意 canvas object。
- **线 ≠ Relation**：视觉连接线连任意对象、属空间真相、不可命名、不进图、`visual_only`；Relation 连知识节点、属语义真相、进图。**根本隔离是"endpoint 资格"，不是命名**。连接线最多是一个"可被 AI 提议升级"的草稿，升级永远经 RelationProposal、人点头，线本身永不自动变 Relation。

## 四、目的驱动的组织（对 GraphRAG 的态度）

**不用有限的方式去丈量无限的知识用法。** GraphRAG 想一次性把"那张客观图"从 LLM 里穷举压榨出来——范畴错误（知识结构随目的而变）。Coincides 反过来：
- **同一份源 → 无限多组 purpose-organization**；ContentGroup/relation 都随目的换一套，且可跨目的复用（同节点重投角色）。
- 那张图**不是被抽取的，是被"长"出来的**——人策展、随用而长的沉积物（抽取在前 vs 生长在用，是和 GraphRAG 最根本的分别）。
- **保留 GraphRAG 唯一值钱的那个功能**（浮现你想不到的联系）：AI 仍去浮现非显然关系，但在**已蒸馏的 ContentGroup 节点之上**推理，不在 raw text 上穷举——留住惊喜、丢掉噪声。
- **初学者补丁**：用户没目的时，AI 提议目的/组织当脚手架，但永远人点头。

## 五、产品的 telos

**它是"思考的义肢"，存的不是知识，是"你当年怎么想的"。**
- 深度精通靠"用"（反复练习碾进肌肉记忆），工具碰不着也不需要碰；只touched过、没常用的，本来就会淡——**那才是工具替你存的**。脑子管深度、工具管广度，按"用的频率"分工，不冲突。
- 一条 Relation = "当年的我是这么把 A 和 B 连起来的"——所以那张图有一半是**思维的自画像**；多年后回看，是一条**通回过去那个头脑的线**（不是把知识还给你）。
- 人记忆有限会淡，AI 上下文也有限装不下——**外化的 ContentGroup+Relation 同时熬过两者**，是人和 AI 共有的、比谁都长的外部记忆。
- 灵感源于剖析自己怎么学习；最高效的学习是**问题先行、自下而上**（遇到问题→想方案→融合→系统化），产品该擅长支持这个，而非"对着课本从上往下抄笔记"。

## 六、文档上传与源重建（核心工程设计）

**问题**：原始文档（如 100 页 PDF）上传后，到做成笔记/ContentGroup/Relation，中间发生什么？该不该上传即转成"我们的 block"？

**结论：不要 eager 转成 NoteBlock。源就让它当源，按目的、按需往外蒸馏。** eager 全转会同时踩三条原则：毁了证据根、把洪水换格式而非蒸馏、把一种组织焊死在无框的源上（=本次铁律）。

**三层模型（关键：别塌成一层）**：

```
① 原始字节        逐字保存的 PDF/图。证据根，永不动。
        ↓  OCR / 结构化（Mistral OCR 4 / MinerU 在这一步）
② SourceArtifact  原件的"忠实、结构化、可寻址"版：typed blocks + bbox + 阅读序。
                  【仍是源】，可浏览/引用/锚定，不是你的内容。
        ↓  按用户目的、按需，蒸馏
③ 蒸馏内容        ContentGroup / TextFlow：精华+角色+Petal，
                  每个 member 用 bbox 锚回 ② 的某区域。这才是你的内容。
```
锚点串三层：ContentGroup member → SourceArtifact 区域 → 原始字节位置（= PRODUCT.md 的"证据链：外部源是根、内部派生"）。

**关键坑**：OCR 的 "block"（②，源的可寻址区域=锚点靶子）≠ 你的 "NoteBlock"（③，蒸馏出的内容=锚点发出端）。同名，不在一层。**别把 OCR 的 block 自动变成 NoteBlock**。

**eager vs lazy 的调度**：
- **② 源结构化：可 eager**（无框、便宜、忠实，只让源可寻址，不强加解读；"这块是表格"是描述源本身）。也可 lazy（按页 OCR 省钱）。低风险。
- **③ 蒸馏成 ContentGroup：必须 lazy、必须按目的**（有框；eager 全做=GraphRAG 那个穷举错误）。
- 一句话：**源结构化可以急，知识蒸馏必须等。**

## 七、两个 OCR 工具：Mistral OCR 4 + MinerU

两者都是 **② SourceArtifact 的生产者**，且输出形状几乎一致（typed blocks + bbox + 阅读序 + markdown + 公式→LaTeX + 表格）。

- **Mistral OCR 4**（2026-06-23 发布）：商用 API（也可自托管单容器），SOTA、低延迟、bbox+分类+置信度，CJK 强，$2–4/千页。managed、省心。
- **MinerU**（OpenDataLab，开源）：免费、Apache-2.0 系许可、可自托管（含 CPU / Mac MPS / GPU），**CJK 与科学文献/公式/表格强**（最强表格图表抽取），但延迟/算力更重。MinerU2.5 = 1.2B VLM，SOTA。

**怎么用——不是二选一，是"契约优先、解析器可换"**：
- 定义 **SourceArtifact / SourceAnchor 契约**（typed blocks + bbox + 阅读序 + 类型 + LaTeX + 表格——两个工具天然都吐这个形状，所以契约好定、且未来新工具也会吐同样形状）。
- 解析器是**可换后端**，按文档/用户偏好选，不在产品层锁死。
- 对本产品（本地优先 / 个人 / 中文 / STEM / 无云）：**MinerU 是天然默认**（免费、自托管、中文+公式强、合"本地优先无云"），代价是延迟/算力（单用户场景可接受）；**Mistral 是 premium / 兜底**（要低延迟/省心/MinerU 啃不动时）；外加一个**便宜的 born-digital 文本抽取**给干净 PDF（别 OCR 干净 PDF）。

## 九、路线盲点清单（2026-06-28 盘路线时发现）

> 来源：一次 6-lens 对抗式"完整性批判"（扫真 schema + PRODUCT.md + 今日入库设计）。**这些是最尖锐的几组，非穷尽**（Henry 相信还有更多）。状态 = **待解（认知债）**：主线不在此，**不现在做**，但既已看见、必记下，免得淡掉。少数标 🔴 的是"接缝决定"——在浇入库混凝土前值得先拍形状；其余 design-later。
>
> **元观察**：好几颗是同一个形状——① 又是"相对的别焊死在绝对的上"（铁律复发）；② **时间**是 frame 缺的那根轴；③ **导出**是入库的镜像。一句话：**"此刻/单项目/进得来"设计得很美，缺的是"跨年/跨项目/出得去"。**

### A. 源 / 溯源 / 引用链
- [ ] 🔴 **信任不随链路复合**：raw-源引用 vs 笔记-源引用是同一 primitive，但信任语义相反；无"有效溯源强度"计算，诠释损耗逐跳累积却不可见（溯源 ≠ 溯源强度）。
- [ ] 🔴 **bbox 锚 vs "内部引用只到 NoteBlock"撞车**：外部 bbox 锚行级精确，但契约把内部 note→note 引用钉在整块、丢 offset → **笔记一旦成为另一篇的源，页/行溯源当场蒸发**（正是 note-from-note 场景）。
- [ ] 🔴 **re-OCR 的隐形版本漂移**：②层可重生（换 backend / 重 OCR / 修表格），③层锚静默错指，无 edit 事件可归咎。SourceArtifact（②）需自己的版本身份 + 重锚故事。
- [ ] **删中间节点不愈合链**：删掉 C→B→A 的 B，C 悬在墓碑上、与仍活的根 A 断联（链须可向上 re-parent，非平铺直接引用）。
- [ ] **多源主张无聚合/冲突模型**：印证 / 沾边 / 互相矛盾全渲染成"已溯源"；两源同根=一源重复计数，无检测。
- [ ] **缺"溯源模式"字段**（直引|转述|蒸馏|推断）：蒸馏本是有损诠释，没此字段，节点被再引时**诠释被洗成证据**。

### B. 时间 / 生命周期 / 遗忘（telos 是"跨年记忆"，设计却是"快照"）
- [ ] **purpose-frame 没有生日/死亡/衰减**：两年前与今天的组织一模一样；frame 是**时间容器**，解决了"purpose 放哪"，没解决"它何时、是否还成立"。
- [ ] **没有"再入"凭据**：只存结论，从不给自己的整理铸 reasoning-state（"当时想搞清什么、什么没解决"）→ 一年后面对"删了问题的答案"。
- [ ] **自我洞见演化存不下**：有共时"矛盾"，缺历时"我现在这版**取代**从前那版"；旧想法等权威并存，污染你和 AI 的上下文。
- [ ] **源更新标错层**：SourceVersion 护住引用完整，却说不出你的**理解**已过时；staleness 该爬三层（②→ContentGroup→Relation/frame），现在停在①。
- [ ] **没有墓地防御**：图随用而长=单调累积；几年后主体是过期目的 → 导航淹没、AI 检索越用越差、画布成囤积室。需 frame 的"优雅降级/归档不丢"。

### C. 跨文档 / 跨笔记 / 跨项目（被 `course_id NOT NULL` 锁死）
- [ ] 🔴 **源无全局身份**：同一 PDF 进两项目=两个无关证据根（无 file-hash）；"全局 Source Library"是每项目各自的幻觉。
- [ ] 🔴 **多源 ContentGroup 抹掉血统**：成员盖 group 的 course_id 而非成员真实来源项目 → 跨项目综合节点写入即丢一半血统（静默损坏）。
- [ ] **跨项目复用逼出 fork-vs-reference**（最关键语义决定，非 UI）：且 identity_role 现焊在 content_groups 上，违铁律 → 同 group 两项目要两角色、只有一列。
- [ ] **Relation 不能跨项目**：最值钱、最会淡的跨域连接（"ML 这想法=拓扑那证明的结构"）存不下；"local"该是视图 scope，非存储边界。
- [ ] **GroupFolder 只给"看得到"不给"活得久"**：workspace 折叠夹收集跨项目 group，但 group 随源项目 cascade 而亡 → 删无关项目则静默掉条目（违 Principle 5）。
- [ ] **无"同知识两目的"去重信号**：同一源区域在两项目各蒸一次=两个无关 ContentGroup，无全局 join key 识别"你别处已懂过"。

### D. Agent / AI 交互 / 操舵
- [ ] **proposal 没有 diff** = 盖章不是协作：重组 30 块/12 组/40 边没法 diff/分块接受/撤销 → "协作而非接管"塌成同意复选框。
- [ ] **proposal 粒度/原子性未定**：整篇=不可审；逐条=千次确认 + 部分接受造无规则的不一致态（需 proposal 依赖语义）。
- [ ] 🔴 **没有"目的捕获"界面**：整架构 purpose-relative，却无旋钮设目的；捕获弱→懒蒸馏没有可相对的东西→静默退回无目的通用蒸馏（doctrine 禁止的）。
- [ ] **目的会漂移/叠加**：一篇笔记多年服务多目的；无"用新目的重蒸而不毁旧蒸"的模型 → 第二次来=丢一条思考痕迹。
- [ ] **学你的风格无机制/无 scope/不可审**：隐式 accept/reject 学习本身是看不见、不可审、scope 不明的行为突变（产品别处禁止的那种）。
- [ ] **PageFrame-vs-Canvas 其实是用户的目的信号**（doctrine：尊重所选 frame 除非另请），非 Agent 自由选；AI 有时须**提议换模式**——没设计，且撞"禁止破坏式 Page↔Canvas 转换"。
- [ ] **Q&A 无 grounded 答案 + 无"答案→结构"晋升**：否则次要目的悄悄变成被禁的通用聊天框。

### E. 画布 / Relation 可视化（"画布即图"那条路）
- [ ] 🔴 **节点 ≠ tile（1对多、还对零）**：边须绑 ContentGroup 身份、渲染时解析到本画布投影；绑 CanvasObject=又把语义焊到投影上（铁律复发）。
- [ ] **off-canvas 端点**：节点真正的邻居多不在本画布 → "画布即图"展示被布局裁剪的半截图，需"幽灵节点/传送门"。
- [ ] **布局画布 vs 视图画布是两种相反真相**：手摆(位置=真相) vs 图生成(位置=可弃)；同像素相反真值，需 canvas-kind 标记；这是 PageFrame-vs-Canvas 之外的第三根轴。
- [ ] **语义缩放需"节点远景脸"契约**：缩成一点时显示什么一句话——且这"脸"purpose-relative，和 per-purpose-role 铁律撞上。
- [ ] **三态视觉 + lens 关闭≠删除**：手画线 / Relation 边 / 画在两个 CG 之间但没升级的线（看着一样、图里却空）；lens 关掉真边消失会被读成数据丢。
- [ ] **边的路由需"端点契约之上"的解析层**：cluster 字形 / off-canvas 传送门 / 同节点多 tile——"画布即图"真正的工程核心，没在任何地方预留。

### F. 输出（报告/导出）+ 输入多样性
- [ ] **导出只有分类器、无发射器**："report"无任何输出路径；2D 自由画布压平成线性 PDF 是真排版引擎问题，非水管活。
- [ ] **导出 NoteBlock-only，丢 pillar 2/4**：ContentGroup/Petal/Relation/源锚全蒸发；需**双层导出**（人读 PDF/HTML + 随行结构化 sidecar），镜像三层入库。
- [ ] **冻结报告里 Relation/锚无静态渲染语法**：footnote / 引用附录 / 关系图例——"画布上的边"问题的静态孪生（分享给冷读者时最需要它）。
- [ ] **奠基输入（AI 聊天记录）传不进来**：入库是 bbox/页/阅读序（为 OCR 纸做的）；聊天已数字化/无页/有原生结构 → 需**第二种锚（结构/文本锚）**；accept-list 连 .json/.jsonl 都没有。
- [ ] **一段聊天里 证据/诠释/推理态 逐轮交织**：三分法须挂 segment 不挂文档，否则从聊天蒸的每个 ContentGroup 继承错的认识论标签，"区分源证据 vs AI 浓缩"失效。
- [ ] **往返断链**：导出→再导入结构全丢 → 递归源模型 + 未来协作在"分享并基于它建"那刻断链；结构化 sidecar 因此是承重需求，非锦上添花。

## 十、主线捋定（2026-06-28 夜 → 06-29 凌晨；Henry × Claude；待 Henry 重新归置到 PRODUCT / 总 plan）

### 10.1 四根叉的落定

**Fork 1 — 思考 vs 思考的产物 / 痕迹**
- **是思维义肢，但分阶段**：今天是知识库（TextFlow+ContentGroup+Canvas）；**痕迹层落地那刻，毕业成义肢**。幼虫→成虫。
- **痕迹 = 你不愿重新推导的那部分** = 结构对时间的导数，滤成拐点（问题 / 转向 / 带因否决 / 取代 / 连接）。**转向不是可捕获的时刻，是记录之间的"偏差" + 语言里的"疤"**（8.6 标题序列里 `Legacy-Retreat` 那种；只读文件名就能重建整部思想史）。转向用"反悔语气"宣告自己（Retreat/Rebuild/Reset/Question）。
- **该存多少（记录时不判断）**：笨而全地留 **WHAT-流（冷证据）**，把"判断/蒸馏"挪到蒸馏时、甚至永不。**两层**：冷证据全留（永不加载）+ 活记忆只提升 **奇点 + 差分**。噪音永远待在冷库、不进活记忆。
- **奇点模型（Henry 记忆压缩自剖）**：同质跨度塌成节点；奇点（转折 + 并行冲击：骨折/恋爱/破产/顿悟）整存、永不忘；记的是"区别"不是细节；从奇点有损重展开。奇点 = 不连续（可检测）+ 内部奇点（顿悟，无外部签名）靠**用户标星**；**奇点天生跨项目**。
- **痕迹是不是一等公民**：**野心上一等、机制上多为派生、时机上推迟**。= 薄的一等锚（**标星** + **"这取代那"**；事后不可恢复、且 frame-bound）+ 厚的派生重讲（从冷证据按需重讲，**源可溯、不许编故事**）。
- 一句话：**痕迹 = 把"源重建三层"套到你自己跨时间的思考上**（证据=状态+对话；结构=检测到的落差/疤；叙述=源可溯地重讲）。

**Fork 2 — 单位 / scope（拆墙）**
- **"原子单位"是 frame-relative 的三根轴**：寻址=**ContentRange**；承载意义/关系=**ContentGroup/Petal**（需经 Member 升级才够格当 relation 端点）；归属/scope=笔记/项目/目的-框。
- `course_id` = **"相对（焦点/镜头）焊死在绝对（身份/家）上"——铁律第四例**（前三：block-id、per-purpose 角色、fitness-state）。
- **三种关系拆开**：**出身**（事实，永留）/ **绑定**（墙，删）/ **包含**（GroupFolder 式收纳，非独占、删容器不致命）。course_id 把三样压成一列 = 病根。
- **文件夹 → 歌单**：家 = 一个**无墙空间**；course = 一盏**镜头**（可 0/1/多、可重叠、删镜头不删歌）。且**无损**：单 course = 多成员资格的退化特例。
- **拆墙无迁移成本**（数据全是测试数据，可直接删重建）；真活在**代码**（re-scope 每个 course_id 查询 → 用户/空间 + 歌单/成员模型 + 生命周期规则"删镜头≠删节点"）。
- **拆墙插队**：排在 **8.11 之后、8.12 之前**——因为 8.12 的 Reference/Duplicate/Fork/Materialize 复用动词，结构上需要无墙。

**Fork 3 — 时间轴**：被 Fork 1 预答——**非建不可**（没时间维就没导数），但分阶段；**空间（拆墙）与时间（痕迹）正交**，先拆墙、时间轴晚。

**Fork 4 — "用出来的图"**：被 ContentRange 那轮白送——**图随"提起来 + 连起来"而长**：把 ContentRange 提成 ContentGroup（授语义身份）、再连 ContentGroup/Petal。**只有有语义身份的单位进图**（= 反 GraphRAG 的闸门）。

### 10.3 高度视角：零部件栈 + 路线
- **五真相**（TextFlow / ContentGroup / Canvas / Source / Relation）+ **容器**（一个无墙空间 + 出身 + 包含）+ **时间维**（痕迹）+ **行动者/进出口**（人 / Agent / 入=OCR重建 / 出=忠实导出）。其余（Concept、Structure Studio、模板）是某件的**天花板加高**，非新件。
- **顺序是依赖拓扑逼出来的，不是选的**；**Agent 站在"完整 + AI 可读"的基底背后**（roadmap 原则 3.5）。
- **地板 vs 天花板**：按依赖序把每件做到**地板**（够撑上一层），**天花板随用加高**。"至少要做哪些" = **每件的地板**。（8.12 做完 canvas 没"完"，但到地板了，够往下走。）
- **两时代**：① **把基底建满到地板**——`TextFlow✅ → ContentGroup✅ → Canvas 收口(8.12) → 拆墙 → Source 地基 → Relation` = 成熟 Better Notebook = **知识库**。★ **基底完整 + AI 可读 = Agent 闸门**。② **Agent 站到背后 + 痕迹 + 进 + 出** = **义肢毕业**。
- **canvas 收口闸门** = ContentGroup 能投影上画布 + 复用 + AI 可读 + 不把成员内容误当源真相（= 8.12 收口）。

### 10.4 Source vs Agent + "人机件怎么建"（化迷茫）
- **Source 劈两段**：**溯源地基**（roadmap Phase A9a：源库 + 锚模型，人可手动引用）靠前；**重重建**（OCR/VLM→笔记）= **Phase G，和 "AI Note Assembly" 焊在一个 Phase**。"Source 和 Agent 分不开"只对**重活那半**成立。PI-048 双闸门（Contract Intake 早定形状 / Full Research 晚建管线）已编码这条纪律。
- **人机件 = 底座（真相模型，人现在能建能用、AI 可读缝）+ 操作者（用它的 AI，Agent 时代）。** 判据：**底座有独立的"人用"价值吗？** 有就建（Relation/Source/痕迹底座）；纯操作者（RAG / 自动蒸馏 / 笔记组装）**整段推迟**。
- **Relation ≠ 图 ≠ GraphRAG**（三层）：Relation=人手动创建的 typed 真相（**现在能建，不碰 RAG**）；图=relation 遍历出的局部视图；GraphRAG=**Agent 时代、可重建的 sidecar**（PI-049：Coincides 拥有真相，索引可重建）。**建 Relation ≠ 建 RAG。**
- **安心话**：**建底座 = 建"可靠 Agent"的地基**——可靠 Agent 在烂底座上不可能，在干净/分离/源可溯的底座上才可能。**底座质量 = Agent 可靠度上限。** 不是盲建。
- **去险**：不确定底座服不服 AI 时，做一次性 **spike**——**Claude 可以就是那个 spike-Agent**（读 relation/source 底座、试提议/引用、报告缺什么），**验证而不建生产 Agent**。
- **"闭门造车"翻案**：底座该闭门建（良定义真相）；真正需要开门/真实反馈的是**操作者**（AI 协助 UX、学指纹）——本就推迟。AI 可读缝便宜、是通往 Agent 的桥，**留着当保险**。
