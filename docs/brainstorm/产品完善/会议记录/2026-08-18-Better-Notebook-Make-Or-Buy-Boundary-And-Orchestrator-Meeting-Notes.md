## 二、三个点名问题的判定(Claude)

1. **单文件 vs 工程包:两种导出口味,同一编译器**——交付件=单文件 HTML(自足,出生证内嵌数据块,可回家);工程包=index.html+manifest 出生证+objects.json 全保真+assets(逆向/迁移/备份交换格式)。成本≈零。Open Design 的 151 个 design-system 包=工程包格式判例(登记册已挂研读)。
2. **外来 HTML 逆向的代价:合并进窄腰——外来 HTML 就是又一种 Source 格式**(与 PDF/DOCX 并排,不建专门导入器);增量成本=一个前端映射;保真尽力、降级=区域截图+锚;**安全红线(今日钉):外来 JS 永不执行,拆解只取结构与样式**。自产件走出生证,近零成本。Henry"这决定引用源怎么做"的直觉确认:决定方式=统一,不是分叉。
3. **意图路由器(orchestrator)**:快速意图路由(小快模型毫秒级)把混合话语拆成意图清单,**每条绑定红圈锚(锚=共同指涉物)**,分道:挪位置→快车道(直接工具调用即时生效)/重设计→设计道(样式快/组件慢道)/重生成→订单道(重投影出候选不覆盖,第三态)/学术问答→对话道。三关键件:①**封闭世界路由**(目标词汇=末端执行器分类,非开放意图识别,难度骤降);②**拆解结果给用户看**("拆成了四件事"小收据,可纠正——解释的收据教义第三次适用);③**分级放行**(即时/出候选/需确认的意图级权限表=大动作收据教义细则化)。

## 六、成稿前三问(Henry × Claude;三答皆已在案=成稿信号再证)

- **Q1:Open Design(近乎 Lovable 自由平替的完整产品)做的笔记怎么放上画布调节?——答:上不去,所以不许它做笔记。** 血团无对象身份,画布编辑的是对象——本体不匹配,非技术缺口。正确分工:agent 经 MCP **点菜我们的组件→笔记生为对象→画布天然可调→我们的编译器出 HTML**;Open Design=工坊(token 包/组件设计提案走慢道)——**生产菜谱和食材,不生产菜**。外来 HTML 仅两通道:窄腰当 Source(阅读采收,非往返编辑)/沙盒黑箱瓷砖逃生舱。本问=「点菜不下厨」规矩的第一道试金石,扛住。
- **Q2:从零写笔记的场景在无限画布吗?——不在,在流式装配面**(§七 已拍:写和装归流面,摆和圈归画布;08-08 实验=自由画布当写作入口的反面证据)。"未脱离网页设计范畴"=选择而非缺陷(DOM 底座教义)。

## 七、Henry 的经济学反击与「点菜不下厨 v2」:组件成长路径(重要升级)

- **Henry 反击(成立)**:只把 Open Design 当排版师=浪费其核心能力(**现搓组件**/微调既有/素材攒装——与我们高度重合的能力);且产品判断:**组件库长于使用、永不完整**(用户要什么样的东西不可预制;真组件库在使用中逐渐建立)——需求场景:笔记建设中现场要选择题组件(题库从引用源生成、四选项、可打勾;现实还有画图/填空/推理/图片排序/图上标记题),agent 须现搓、且成果留存为模板/素材库/案例库。solo 无商业化,license 不讲究,统一安装取部分功能可行。三层分速的"组件层慢道"在此有真空档——怎么办?
- **Claude 升级:「点菜不下厨」v2=可以下厨,在沙盒厨房,菜谱和锅分开放。组件成长路径三级**:①**产房**(即时:Open Design 当产房引擎现搓交互壳,以沙盒组件落地,同场对话可用);②**案例库**(留存为模板/素材,跨笔记复用,积使用收据);③**转正**(凭使用收据晋升慢道,硬化为正式 kind,获完整真相层待遇)。**晋升凭使用收据**——与字段晋升/沉降同律,第三次适用。
- **⭐ 关键刀:内容与壳分离**——题目内容(题干/选项/答案)=结构化数据**走真相层,从引用源生成故每题带源锚**(第一天即可溯源可采收,将来可铸卡);交互壳(打勾/判分)=模板+沙盒 JS 走产房。**转正只升级壳,内容从未流浪。**全题型同构。
- **三条配套**:①安全修正案——"外来 JS 永不执行"细分:外来**导入**照旧永不执行;agent **应约现搓**的 JS 允许执行但仅限**无特权沙盒**(iframe 隔离/默认无网/碰不到应用状态/整块锚)——请求出身不同待遇不同;②Open Design 角色升格:工坊→**产房引擎**(现搓能力用在刀刃,仍是 sidecar,产出经沙盒纪律落地;Apache-2.0 无许可虞);③**首发组件集缩小**:预制只需地板组件(TextFlow/基础卡/表格/公式图)+产房机制本身,其余让使用长出来。

## 八、组件打磨机制与 AI 阅卷的读法(Henry 两问 × Claude 定形)

- **Q1 打磨微调**:Henry 三例分家——"框改红"=样式层(token);"勾选改涂鸦填满"=壳的皮肤(同 schema 换渲染);"点选变绿+单选互斥/多选切换"=壳的行为(逻辑)。**三例皆不碰数据层** ⇒ 打磨本体=**壳的版本演进**,三档机制:①实例级覆盖(只改这一个,即时);②库级变体(存回案例库成新皮肤/行为变体);③默认晋升("以后都这样"→组件默认,**既有实例不静默改**——第三态再适用:旧实例钉版,愿迁批量迁)。两纪律:**颜色永远进 token 不许内联硬编码**(否则风格统一死——Henry artifact 画廊的统一感即 token 之功);**每次微调留收据**(改哪层/从何到何)——意图路由器先判层再分道("改红"=token 活 or 皮肤活 or 行为活)。
- **Q2 AI 阅卷读什么:假二选一——阅卷读收据,不读画面**(内容与壳分离的第二次红利:答案从未被困在 HTML 里)。四档:客观题(选择/多选/排序/精确填空)=**机械判分零 token 不用 AI**;主观文字/过程题=AI 读结构化数据(题+作答+**源锚拉原文上下文**);视觉作答题(画图/图上标记)=唯一必须读截图处(作答即图像);错题讲解诊断=AI 读数据+顺源锚引原文(最值钱档)。读 HTML 工程文件严格劣于读数据(壳噪音耗 token);截图对文字题有损且贵。**附赠闭环**:判分数据=错题史=credence 层原料——"使用态回流"问题(§三.1)的管线自动衔接。

## 九、选区系统:一切手势归一为选区收据(Henry 推广之问 × Claude 定形)

- **Henry 推广**:人机互动不只判卷不只红圈——页面/画布双模式下有多种选择方式(Ctrl 单点多选如资源管理器/框选/文字指代"你看我这个开头/标题");若全走 OCR/图像理解,效率太低——业界到底怎么捕捉用户选中的区域?
- **总法则:选择在客户端解析成对象身份,AI 读身份换来的结构化上下文;视觉只是身份缺失时的兜底。** 手势拆解:Ctrl 多选=命中测试→ID 集(对象位置是我们摆的,不需认);框选=矩形∩包围盒几何求交;文字选区=block+字符偏移(天生结构化);红笔圈=笔迹多边形几何包含测试→ID 集(笔迹留作锚几何,识别"圈住谁"零视觉);文字指代=对着**对象树**解析(开头=首块,标题=heading 角色)+解析结果高亮回显供确认(解释收据再适用)。**零 OCR 原理:用户点的像素是我们自己渲染的对象——不需要用眼睛认自己亲手画的东西。** 视觉仅两种出场:圈中无身份像素(位图内部/层1 未解析原件)=区域截图喂 VLM 兜底;议题=外观本身(截图是内容非坐标)。
- **归一物:选区收据** `{对象 IDs,文字范围,几何,时刻}`——四手势两模式全部归一;AI 收到的是其**水合后的结构化上下文**(选中块文字/角色/源锚/邻块,纯文本便宜精确)。业界同型(Cursor/Notion AI 皆选区→结构化范围,无人传截图)。
- **漂亮收尾:选区收据=还没保存的锚**——同一坐标+范围+摘录结构,一个活在瞬间(喂 AI/批量操作)一个活成永久(锚);"圈选即造锚"推广为**一切手势归一为选区收据,选区收据可升格为锚**。选区系统=锚系统的前半生,非新子系统。交互捕捉毫秒级零 token,AI 的钱只花在理解问题与内容上。
