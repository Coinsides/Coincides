# R13 - v2.5 Graph-Native Migration Evidence Summary

**Created**: 2026-05-23
**Status**: Research closure draft
**Scope**: v2.5 template/package/editor research -> v3.x Neo4j / graph-native migration evidence

---

## 1. 这份总结要解决什么

R13 不决定 v3.x 是否立刻切换到 Neo4j，也不把 v2.5 的 SQLite 设计改成图数据库。

它只做一件事：

```text
把 v2.5 调研得到的对象、关系、包、迁移、编辑器 adapter 证据，
整理成未来 graph-native 重建可以直接使用的判断材料。
```

换句话说，v2.5 仍然是 SQLite-first / graph-ready 阶段。v3.x 才是 graph-native 架构候选阶段。

R13 的价值是防止未来 v3.x 重建时只能从代码和聊天记忆里反推：

```text
什么应该成为节点？
什么应该成为边？
什么只是属性？
什么只是投影或缓存？
什么必须保留 provenance？
什么可以从 canonical truth 重建？
```

## 3. 总体结论

v2.5 的模板系统不只是 UI 配置系统。

它正在形成一层未来 graph-native 架构非常需要的中间结构：

```text
TemplateDefinition
  -> defines content capability

CompositionTemplate
  -> defines reusable multi-object structure

DomainBlockSet
  -> organizes template capability by domain graph, not rigid tree

TemplateProposal / TemplateMigrationProposal
  -> records reviewed change and migration intent

PackageManifest / .coincides package
  -> defines portable workspace boundary

EditorAdapter
  -> interaction layer only, not truth
```

这些对象会帮助 v3.x 回答一个关键问题：

```text
Coincides 的 graph-native 版本到底是把什么连起来？
```

目前最稳的判断是：

```text
NoteBlock remains the strongest v2.x knowledge node candidate.
ObjectRelation remains the strongest semantic edge candidate.
TemplateDefinition and CompositionTemplate are graph-adjacent capability nodes.
DomainBlockSet is a domain capability graph, not a simple folder tree.
PackageManifest is a portability and recovery boundary.
EditorAdapter state is cache/projection/operation metadata, not graph truth.
```

## 4. v2.5 对象分类

### 4.1 强 graph node 候选

这些对象很可能在 v3.x 中成为图节点，或者至少成为可寻址的 graph-adjacent node。

```text
NoteBlock
TemplateDefinition
CompositionTemplate
CompositionInstance
DomainBlockSet
PackageManifest
Proposal
TemplateProposal
TemplateMigrationProposal
DomainRefinementProposal
PackageImport
PackageExport
OperationBatch
```

判断理由：

- 它们有稳定身份；
- 它们可以被其他对象引用；
- 它们拥有生命周期；
- 它们影响 AI 如何读取、生成、迁移或恢复内容；
- 它们需要被 package/export/import 保留。

其中优先级最高的是：

```text
NoteBlock
TemplateDefinition
CompositionTemplate
DomainBlockSet
PackageManifest
Proposal / OperationBatch
```

`Proposal` 是否作为 graph node 仍需谨慎。它不是知识本体，但它是系统演化历史和可审阅 mutation 的核心证据。

### 4.2 强 graph edge 候选

这些关系很可能成为 v3.x graph edges，或至少成为 edge-like records：

```text
(:NoteBlock)-[:USES_TEMPLATE]->(:TemplateDefinition)
(:NoteBlock)-[:PART_OF_COMPOSITION]->(:CompositionInstance)
(:CompositionTemplate)-[:USES_TEMPLATE]->(:TemplateDefinition)
(:CompositionInstance)-[:FILLS_SLOT_WITH]->(:NoteBlock)
(:DomainBlockSet)-[:INCLUDES_TEMPLATE]->(:TemplateDefinition)
(:DomainBlockSet)-[:INCLUDES_COMPOSITION]->(:CompositionTemplate)
(:DomainBlockSet)-[:RELATED_TO]->(:DomainBlockSet)
(:DomainBlockSet)-[:BORROWS_FROM]->(:DomainBlockSet)
(:DomainBlockSet)-[:FORKED_FROM]->(:DomainBlockSet)
(:TemplateDefinition)-[:ALLOWS_RELATION_TYPE]->(:RelationType)
(:TemplateMigrationProposal)-[:AFFECTS]->(:NoteBlock)
(:DomainRefinementProposal)-[:RECLASSIFIES]->(:TemplateDefinition)
(:PackageManifest)-[:CONTAINS]->(:TemplateDefinition)
(:PackageManifest)-[:CONTAINS]->(:CompositionTemplate)
(:PackageImport)-[:CREATED]->(:OperationBatch)
(:AgentOperation)-[:USED_TEMPLATE_GUIDANCE]->(:TemplateDefinition)
```

最重要的原则：

```text
relation_behavior 不是 graph edge。
relation_blueprint 不是 graph edge。
confirmed ObjectRelation 才是 graph edge 候选。
```

也就是说，模板可以说“这种关系是允许的”，composition 可以说“这里可能需要这个关系”，但只有被用户或 proposal apply 明确确认后的关系，才接近 graph truth。

### 4.3 graph property / nested config 候选

这些对象或字段更适合作为节点属性、嵌套 JSON、配置片段或 schema，而不应默认升级成独立节点：

```text
field_schema
default_content
render_hints
source_behavior
relation_behavior
proposal_behavior
summary_for_agent
legacy_block_type
compatibility_state
template_resolution_status
template_version
domain facets
package compatibility metadata
editor adapter metadata
```

原因：

- 它们主要描述对象能力；
- 它们不是已发生的知识事实；
- 过早建成节点会让图过密、过杂；
- 它们可以随版本迁移；
- 它们通常可以从 `TemplateDefinition` / `PackageManifest` / `Proposal` 中恢复。

例外是：如果未来某些字段被大量复用、独立查询、独立迁移，才考虑升格为节点。

### 4.4 projection / cache / sidecar 候选

这些不应该成为知识图谱真相：

```text
CanvasNode layout
CanvasFrame layout
Viewport state
Render hint final CSS
EditorAdapter state
EditorSnapshot
tldraw snapshot
rich editor internal document JSON
UI selection state
ToolMode
InputBinding
Canvas layout proposal preview overlay
```

它们可以被保存，但语义上属于：

```text
view state
interaction state
adapter cache
sidecar data
recoverable projection
```

v3.x 可以存它们，但不应把它们当知识真相。

关键规则：

```text
If it can be rebuilt from Coincides canonical objects, it is not graph truth.
```

### 4.5 relational side table 候选

即使进入 graph-native，部分数据仍可能留在 SQL 或类似结构中：

```text
auth/session/user settings
raw import logs
large package validation reports
operation audit details
large editor snapshots
binary/source inclusion manifests
temporary import preview rows
compatibility report cache
build/test/runtime cache
```

原因：

- 它们适合批量读写；
- 它们不需要 graph traversal；
- 它们可能很大；
- 它们更偏审计、缓存或操作记录；
- 它们不是用户主要查询的知识结构。

## 5. v2.5 小版本应回答的 graph-native 问题

每个 v2.5 小版本完成时，都应该回答以下问题。

### v2.5.0 Template Definition Runtime

必须记录：

- `TemplateDefinition` 是否具备稳定身份；
- 哪些 seed templates 被真实 NoteBlocks 使用；
- 哪些 legacy blocks 只能 infer，不能确定迁移；
- 哪些 fields 被真实填充；
- 哪些 fields 应该保持 JSON，不拆成节点；
- 哪些模板行为会影响 source / relation / proposal；
- 哪些模板变更必须 proposal-first；
- compatibility report 暴露了哪些未来迁移风险。

初步 graph 判断：

```text
TemplateDefinition = graph-adjacent capability node candidate
field_schema = TemplateDefinition property / nested config
render_hints = projection metadata
legacy_block_type = compatibility property
```

### v2.5.1 User-facing Template Editor Seed

必须记录：

- 用户实际改了哪些 template fields；
- 哪些改动 direct-safe；
- 哪些改动触发 proposal；
- 哪些模板被复制、fork、deprecated；
- system template 与 user template 如何保持身份边界；
- template lifecycle 如何表达为 graph 状态。

初步 graph 判断：

```text
User-created TemplateDefinition = graph-adjacent node candidate
Template lifecycle = node status / proposal history
Template edit history = proposal / operation history
```

### v2.5.2 Composition / Section Template Seed

必须记录：

- CompositionTemplate 是否需要独立稳定身份；
- slot schema 如何引用 TemplateDefinition；
- apply 后是否产生 CompositionInstance；
- slot 是否被填充、跳过、重复；
- relation blueprint 是否只停留在 suggested relation；
- suggested relation 最终有多少变成 ObjectRelation；
- composition 与 CanvasFrame / CanvasNode 的边界。

初步 graph 判断：

```text
CompositionTemplate = graph node candidate
CompositionInstance = graph node candidate if real usage proves needed
Slot usage = edge or edge-like property
relation_blueprint = proposal/design intent, not graph truth
confirmed ObjectRelation = graph edge candidate
```

### v2.5.3 Domain Block Set + Package Manifest

必须记录：

- DomainBlockSet 是否是单树、DAG、还是多维 domain graph；
- domain path 与 stable id 是否分离；
- aliases / parent domains / related domains 是否足够；
- 哪些模板属于多个 domain；
- 哪些模板从相邻 domain 借用；
- package manifest 如何保留 domain membership；
- Domain Fit Check / Template Coverage Check 是否需要进入后续计划。

初步 graph 判断：

```text
DomainBlockSet = domain capability graph node candidate
domain_key = current path, not identity
stable_id = identity
aliases = compatibility layer
parent/related/fork/borrow = graph edge candidates
```

### v2.5.4 Template Proposal + Migration Proposal

必须记录：

- proposal 影响哪些 NoteBlocks / Templates / Domains / Packages；
- migration 是 alias、soft migration 还是 hard cascade；
- affected object count；
- before/after mapping；
- recovery evidence；
- proposal 被 rejected / accepted / deferred 的原因；
- migration 是否改变 current classification；
- created_with 与 current classification 是否分层保存。

初步 graph 判断：

```text
TemplateProposal = change-intent node candidate
TemplateMigrationProposal = migration-intent node candidate
DomainRefinementProposal = future graph/domain restructuring node candidate
Migration affected object links = graph edge candidates or audit edges
```

### v2.5.5 Package Studio Lite / Export-Import Foundation

必须记录：

- `.coincides` package 中哪些对象是完整 truth；
- 哪些只是 reference；
- 哪些是 snapshot；
- 哪些是 omitted；
- import 后哪些关系 degraded；
- broken CanvasEdge / stale ObjectRelation / missing source 如何报告；
- package 是否能恢复 TemplateDefinition / CompositionTemplate / DomainBlockSet identity；
- package 是否能导出未来 graph reconstruction hints。

初步 graph 判断：

```text
PackageManifest = portability boundary node candidate
PackageImport / PackageExport = operation node candidates
Package membership = contains/imported/created edges
Import preview = side table or operation metadata
```

### v2.5.6 Rich Editor Adapter Spike

必须记录：

- editor internal node 如何映射 NoteBlock；
- editor marks 如何映射 source markers；
- editor snapshot 删除后内容能否重建；
- editor 是否污染 `content_json`；
- editor 是否能保留 template metadata；
- editor 是否绕过 proposal-first；
- editor state 是不是只作为 cache/sidecar。

初步 graph 判断：

```text
EditorAdapter = adapter/config/operation metadata
EditorSnapshot = cache/sidecar
Editor internal node = not graph truth
NoteBlock identity = graph candidate
```

## 6. v2.5 需要保留的 provenance

v2.5 的关键不是把所有东西都做成节点，而是保留未来判断所需的 provenance。

每个关键对象至少应该能回答：

```text
created_with
current_classification
classification_history
source_package
source_template
source_domain
proposal_history
operation_batch
import/export history
```

### 6.1 TemplateDefinition provenance

建议保留：

- seed source；
- copied_from；
- forked_from；
- package source；
- created_by user / agent / system；
- lifecycle；
- version；
- migration history；
- compatibility status。

### 6.2 NoteBlock provenance

建议保留：

- created_with_template；
- current_template；
- template_resolution_status；
- created_with_domain；
- current_domain；
- source anchors / source references；
- proposal source；
- package import source；
- migration history。

### 6.3 Composition provenance

建议保留：

- composition_template_id；
- slot fills；
- skipped slots；
- repeated slots；
- generated NoteBlocks；
- generated CanvasNodes；
- suggested ObjectRelations；
- accepted ObjectRelations。

### 6.4 Domain provenance

建议保留：

- stable domain id；
- current domain key；
- aliases；
- parent/related/fork/borrow relationships；
- migration/refinement proposal history；
- current recommended classification；
- historical classification。

### 6.5 Package provenance

建议保留：

- package id；
- package version；
- export mode；
- source inclusion mode；
- imported object mappings；
- degraded relations；
- missing source warnings；
- recovery records；
- operation batch。

## 7. v2.5 应避免的 graph-native 误判

### 7.1 不要把字段都拆成节点

`field_schema`、`render_hints`、`summary_for_agent` 很重要，但默认不是图节点。

它们更像：

```text
capability description
policy
schema
view metadata
agent instruction
```

只有当某些字段被跨模板大量复用并需要独立生命周期时，才考虑升格。

### 7.2 不要把设计意图当成已发生事实

以下都不是 graph truth：

```text
relation_behavior
relation_blueprint
summary_for_agent recommended_relation
AI suggested relation
template allows relation type
```

它们可以生成 proposal，但不能直接变成 accepted semantic edge。

### 7.3 不要把 editor 文档模型当 Coincides 模型

Tiptap、Lexical、BlockNote、BlockSuite 都可以帮编辑体验。

但 editor node 不等于 NoteBlock。

编辑器状态必须可以丢失、降级或重建，而不损坏：

```text
NoteBlock identity
template metadata
source references
ObjectRelations
proposal history
package identity
```

### 7.4 不要把 domain 当死目录

领域不应该只是：

```text
academic.math.probability.biology.xxx
```

而应该是：

```text
stable domain object
  -> aliases
  -> parent domains
  -> related domains
  -> facets
  -> package memberships
  -> migration history
```

真实知识结构会犯错、修正、提升、拆分、合并。graph-native 版本必须承认这种演化。

### 7.5 不要把 package 当普通 zip

`.coincides` package 不是简单文件夹。

它应该是未来 graph-native import/export 的练兵场：

```text
identity mapping
object membership
source inclusion mode
degraded relation reporting
proposal history
operation recovery
graph reconstruction hints
```

## 8. v3.x 可能的图结构草案

这不是最终设计，只是 v2.5 调研后的 working hypothesis。

```text
(:NoteBlock)
(:TemplateDefinition)
(:CompositionTemplate)
(:CompositionInstance)
(:DomainBlockSet)
(:PackageManifest)
(:Proposal)
(:OperationBatch)
(:ObjectRelation)
(:RelationType)
(:SourceAnchor)
(:EvidenceSet)
```

可能的核心关系：

```text
(:NoteBlock)-[:USES_TEMPLATE]->(:TemplateDefinition)
(:NoteBlock)-[:HAS_SOURCE]->(:SourceAnchor)
(:NoteBlock)-[:PART_OF]->(:CompositionInstance)
(:CompositionInstance)-[:BASED_ON]->(:CompositionTemplate)
(:CompositionInstance)-[:FILLS_SLOT_WITH]->(:NoteBlock)
(:CompositionTemplate)-[:USES_TEMPLATE]->(:TemplateDefinition)
(:DomainBlockSet)-[:INCLUDES_TEMPLATE]->(:TemplateDefinition)
(:DomainBlockSet)-[:INCLUDES_COMPOSITION]->(:CompositionTemplate)
(:DomainBlockSet)-[:RELATED_TO]->(:DomainBlockSet)
(:PackageManifest)-[:CONTAINS]->(:TemplateDefinition)
(:PackageManifest)-[:CONTAINS]->(:CompositionTemplate)
(:Proposal)-[:AFFECTS]->(:NoteBlock)
(:Proposal)-[:AFFECTS]->(:TemplateDefinition)
(:OperationBatch)-[:APPLIED]->(:Proposal)
(:ObjectRelation)-[:RELATES_SOURCE]->(:NoteBlock)
(:ObjectRelation)-[:RELATES_TARGET]->(:NoteBlock)
```

其中 `ObjectRelation` 在 graph-native 中有两种可能：

1. 作为真正的 edge；
2. 作为 reified relation node，再连接 source/target。

第二种更重，但能保存更多 metadata：

```text
confidence
layer
status
source evidence
proposal history
created_by
reviewed_by
visible/hidden/AI-only
```

v3.x 设计时应专门比较这两种模型。

## 9. v2.5 到 v3.x 的过渡建议

R13 建议 v2.5 继续按以下路线收集证据：

```text
v2.5.0
  -> prove TemplateDefinition identity and compatibility report

v2.5.1
  -> prove user-edited template lifecycle and safe/unsafe edits

v2.5.2
  -> prove CompositionTemplate and slot usage model

v2.5.3
  -> prove DomainBlockSet as domain graph, not folder tree

v2.5.4
  -> prove migration proposal / refinement proposal evidence

v2.5.5
  -> prove package import/export and degraded relation recovery

v2.5.6
  -> only if needed, prove rich editor adapter can stay replaceable
```

然后在 v2.x closeout 或 v3.x pre-planning 前，建立正式图迁移包：

```text
Graph-native rebuild research package
  -> v2.x object inventory
  -> node/edge/property/side-table classification
  -> Neo4j candidate schema
  -> import/export mapping
  -> package recovery model
  -> local service setup plan
  -> graph mirror / export spike plan
```

## 10. R13 对后续 plan 的要求

从 v2.5.0 开始，每个小版本 plan 和 review 都应该新增一个短段：

```text
Graph-Native Migration Evidence
```

它至少回答：

- 本版本新增对象是否是 future graph node？
- 本版本新增关系是否是 future graph edge？
- 哪些字段只是属性或 config？
- 哪些记录只是 projection/cache？
- 哪些 provenance 必须保留？
- 哪些东西可以从 canonical truth 重建？
- 如果导入 `.coincides` package 后缺失这个对象，会坏在哪里？

这不需要写得很长，但必须每个版本都写。

否则 v3.x 迁移时会再次依赖人的记忆。

---

## 11. R13 结论

R13 的最终结论可以压缩成一句话：

```text
v2.5 的模板与包系统，是 v3.x graph-native 重建前最重要的一层语义证据收集器。
```

v2.5 不应该急着换数据库。

但 v2.5 必须非常认真地记录：

```text
identity
provenance
template usage
composition usage
domain membership
proposal history
package membership
rebuildability
projection-vs-truth boundary
```

这样 v3.x 才不是“把 SQLite 表搬到 Neo4j”，而是把 Coincides 重建成真正的：

```text
source-grounded
proposal-reviewed
AI-readable
graph-native
information workspace
```
