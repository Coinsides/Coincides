# v2.x Source Viewer / Source Board 调研

**创建日期**: 2026-05-21
**状态**: 调研草稿
**范围**: Source Snapshot Viewer、Source Board、引用锚点、范围选择、源材料到 NoteBlock 的跳转

这份文件是 post-v2.1.1 产品/架构调研的一部分。它回答：

> Coincides v2.3 的 Source Snapshot Viewer / Source Board 应该怎么做，才能既服务学习系统，又不把未来画布和展示层做死？

结论先行：

```text
v2.3 不应该直接做完整自由画布。
v2.3 应该做 Source Snapshot Viewer + Source Board seed。

Source Viewer 解决“我相信这个来源吗、这个笔记从哪里来？”
Source Board 解决“我正在选哪些来源范围、这些来源如何生成 NoteBlocks？”
```

---

## 1. 你提出的新判断：它未来不只服务学习

随着 NoteBlock、Source Board、Canvas 逐步成形，Coincides 很可能长出一个更通用的“结构化展示层”。

它未来可以用于：

- 学习材料整理；
- 论文/教材阅读；
- 侦探游戏式线索板；
- 项目研究证据板；
- AI agent 工作成果展示；
- 多个 AI 工具输出的可视化汇总；
- 面向演示或复盘的 story board。

这个判断非常重要，但当前不应该改变 v2.3 的边界。

我们应该这样处理：

```text
长期方向:
  Coincides Canvas / Board 可以成为 AI 生态的成果展示面板。

当前 v2.3:
  先把 source trust、source anchor、scope selection、note/source 跳转做好。
```

否则很容易为了“未来都能做”而把 v2.3 做成过重版本。

---

## 2. 调研问题

Source Viewer / Source Board 需要回答：

- 源材料如何被稳定引用？
- 高亮、摘录、注释、source range 应该存在哪里？
- 用户如何从 NoteBlock 跳回原始来源？
- 用户如何从源材料选择范围，生成 proposal？
- Source Board 是列表、侧栏、空间板，还是完整 canvas？
- 多个来源之间的关系如何展示？
- 它和 v2.4 Learning Canvas 的边界在哪里？

## 3. 参考对象

### Zotero PDF Reader

重点参考：

- PDF reader 和 note editor 结合。
- annotation 可以添加到 note。
- note 里的 annotation 可以跳回 PDF 原页。
- annotation 存在数据库里，而不是只写进 PDF 文件。
- 同时保留导出能力，避免数据锁死。

Zotero 给 Coincides 的关键启发：

```text
source annotation / source range 应该是数据库里的结构化对象。
PDF 文件本身不是唯一事实源。
```

### Readwise Reader

重点参考：

- 阅读体验围绕 highlight、tag、note、document note。
- 同一文档里的 highlights 可以被聚合、导出、同步到其他 note app。
- PDF 可以切换增强文本模式，但并不强调直接编辑 PDF 本体。

启发：

```text
source interaction 的核心不是编辑源文件，而是把可引用的阅读行为结构化。
```

### LiquidText

重点参考：

- 文档旁边有 workspace。
- 用户可以把关键事实从文档中拉出来，在旁边组织想法。
- 摘录可以跨页连接，且可以回到原始上下文。
- workspace 和 document 并排，阅读与组织同时发生。

启发：

```text
Source Board 应该贴着 source viewer 生长，而不是远离源材料另开一个空白画布。
```

### MarginNote

重点参考：

- PDF/EPUB/video 等源材料可以被摘录。
- excerpt 和 annotation 是核心系统。
- mind map、card、PDF highlight 可以同时呈现同一个概念。
- 搜索可以区分 document search 和 mindmap excerpt search。
- 学习场景里，摘录可以进入卡片和复习系统。

启发：

```text
源材料、摘录、卡片/NoteBlock、mind map/board 可以是同一学习对象的不同表面。
```

### Heptabase

重点参考：

- note cards、whiteboards、sections、text elements、mindmaps 可以组成可视化工作区。
- AI 可以搜索 whiteboards，读取 whiteboard 上对象的组织关系。
- card 内容和 whiteboard layout 的版本历史分开。

启发：

```text
Board layout 和 card/NoteBlock content 应该分开。
AI 需要能读取 board structure，但不能把 board 当作唯一内容来源。
```

## 4. 他们大概怎么做

### 4.1 Zotero：annotation 是结构化数据，可以跳回 PDF

Zotero 的成熟点在于：

- 用户在 PDF 上做高亮/注释；
- annotation 被系统管理；
- annotation 可以进入 note；
- note 中的 annotation/citation 能跳回原文页；
- annotation 不完全依赖 PDF 内嵌数据。

这说明 Source Viewer 的基础不是“显示 PDF”，而是：

```text
SourceDocument
  -> SourceAnchor
  -> Annotation / Excerpt
  -> Note / NoteBlock
  -> Jump back to source context
```

### 4.2 LiquidText：文档旁边的思考空间

LiquidText 的关键不是无限画布，而是“parallel workspace”。

用户一边读文档，一边把摘录拉到旁边，建立关系。

这非常适合 Coincides v2.3：

```text
左侧/主区:
  Source Snapshot Viewer

右侧/旁边:
  Source Board seed
  Selected ranges
  Candidate segments
  Proposed NoteBlocks
```

v2.3 的 Source Board 应该靠近 source viewer，而不是做成完整 edgeless canvas。

### 4.3 MarginNote：摘录成为学习对象

MarginNote 的强点是把 PDF 摘录直接变成 mind map/card/复习对象。

Coincides 可以学它的“摘录轴”：

```text
Source excerpt
  -> candidate NoteBlock
  -> board node
  -> review projection
```

但 Coincides 要保留 proposal-first：

```text
Source excerpt
  -> proposal
  -> reviewed NoteBlock
```

### 4.4 Heptabase：board 可以被 AI 读取

Heptabase 的 AI 文档显示：AI 不只是读单张 card，也可以读取 whiteboard 上对象的组织关系。

这对 Coincides 的长期价值很大：

```text
Source Board / Learning Canvas
  -> AI can inspect structure
  -> AI can propose reorganization
  -> user reviews before apply
```

这正好呼应你刚才说的“AI 生态成果展示面板”。

## 5. Coincides 应该学什么

### 5.1 Source Anchor 是 v2.3 的核心

v2.3 最重要的对象不是 PDF viewer UI，而是稳定 anchor。

建议模型：

```text
SourceSnapshot
  source_material_id
  normalized representation
  pages / text layer / images

SourceAnchor
  source_snapshot_id
  page_start
  page_end
  char_start?
  char_end?
  bbox?
  excerpt_text
  anchor_confidence

SourceSelection
  selected anchors
  purpose
  status

SourceBoardNode
  target_type = source_anchor / material_segment / note_block / proposal
  target_id
  layout metadata
```

v2.3 可以不做 bbox 精准区域选择，但要预留字段和概念。

### 5.2 Source Board seed 应该是“选择和信任工具”

v2.3 的 Source Board 不应该急着做自由布局。

它应该先回答：

- 这门课有哪些 source？
- 哪些 source 被解析了？
- 哪些 page/chunk/segment 被选中了？
- 这些 selected ranges 会生成什么 proposal？
- 这些 NoteBlocks 来自哪些 ranges？
- 哪些 source ranges 已经被使用、被排除、待 review？

### 5.3 Source Viewer 和 NoteBlock 要双向跳转

最低要求：

```text
NoteBlock -> Show Source
Source Range -> Show Generated Blocks
Proposal Block -> Show Evidence
Source Selection -> Create Proposal
```

如果只能从笔记看到来源，不能从来源看到笔记，用户仍然不会真正信任系统。

### 5.4 Annotation / Excerpt / NoteBlock 需要分层

不要把它们混成一个东西。

建议：

```text
Annotation:
  用户在来源上的标记或评论。

Excerpt:
  从来源抽出的可引用片段。

NoteBlock:
  经过整理、可编辑、可复用的学习块。
```

一个 excerpt 可以生成一个或多个 NoteBlock；一个 NoteBlock 可以引用多个 excerpt。

### 5.5 Source Board 是未来展示层的第一块地基

你提出的侦探线索板 / AI 展示板，本质上需要：

- 节点；
- 关系；
- 来源；
- 证据；
- 时间线；
- proposal history；
- 可视化布局；
- 导出/演示。

这些能力和学习系统高度重合。

所以 v2.3 不要只做“PDF reader”，要做“source-grounded board seed”。

## 6. 对 Roadmap 的影响

### v2.2 Material Reconciliation

建议：**小幅修改。**

v2.2 仍然主攻 reconciliation，不做 viewer。

但 v2.2 需要给 v2.3 留好这些输出：

- material segments 要能映射到 source anchors；
- reconciliation proposal 要能说明使用了哪些 source ranges；
- excluded/restored scope 要能在 Source Board 里显示；
- canonical block 要保留 evidence set。

### v2.3 Source Snapshot Viewer + Scope Selection

建议：**明显修改。**

把 v2.3 明确升级为：

```text
Source Snapshot Viewer
  + Source Anchor
  + Scope Selection
  + Source Board seed
```

v2.3 的重点：

- source viewer；
- page/page-range/chunk/segment selection；
- source anchor；
- source-to-NoteBlock 双向跳转；
- selected scope；
- proposal creation from selected source scope；
- used / unused / excluded / failed / needs review 状态。

v2.3 不做：

- 完整自由画布；
- 复杂 graph layout；
- 多人协作；
- 完整 PDF 编辑；
- 高级 bbox 标注；
- AI 自动生成大规模关系图。

### v2.4 Learning Canvas

建议：**保持方向，但明确继承 v2.3。**

v2.4 的 Learning Canvas 应该建立在 v2.3 的 Source Board seed 上：

```text
Source Board:
  source ranges / evidence / selected scope

Learning Canvas:
  concepts / note blocks / projections / source evidence / learning paths
```

Canvas 可以扩展成：

- 概念图；
- 线索图；
- 学习路径图；
- review plan；
- AI 工作成果展示板。

但所有正式节点都应该能回到源对象。

### v2.4.x / v2.5 Template Engine

建议：**暂不修改，但增加未来接口意识。**

模板未来可能影响 Source Board：

- source.quote template；
- evidence card template；
- clue card template；
- formula evidence template；
- exercise-from-source template。

但这些不进入 v2.3。

## 7. 推荐的 v2.3 产品形态

### 7.1 最小可用 Source Viewer

功能：

- 打开一个 source material；
- 显示 page/chunk/segment；
- 支持跳到 page/page range；
- 显示解析状态和 warnings；
- 显示该 source 已生成的 NoteBlocks；
- 从 NoteBlock 跳回 source range。

### 7.2 最小可用 Source Board seed

功能：

- 显示 selected source ranges；
- 显示候选 material segments；
- 显示 generated/proposed NoteBlocks；
- 显示 used / unused / excluded / needs review；
- 允许用户从 selected scope 创建 proposal；
- 支持轻量 reorder/group，但不做自由画布。

### 7.3 最小可用 Source Anchor

字段草案：

```text
source_material_id
source_snapshot_id?
document_chunk_id?
page_start
page_end
char_start?
char_end?
bbox_json?
excerpt_text
anchor_confidence
metadata
```

### 7.4 最小可用跳转

```text
NoteBlock source badge -> Source Viewer at anchor
Source Anchor -> Related NoteBlocks
Proposal block -> Evidence list
Selected Source Scope -> Proposal creation
```

## 8. 长期展示层方向

这部分不进入 v2.3，但应该进入 brainstorm/continuity 视野。

Coincides 的 Board/Canvas 未来可以成为：

```text
Evidence Board
Clue Board
Research Board
Learning Canvas
AI Result Board
Presentation Board
```

共同底层：

```text
Node
Edge
Source
Evidence
Annotation
Proposal History
Version / Snapshot
```

这说明 Coincides 不是只能做学习笔记。它可能成为“把 AI 和人类整理出的结构化成果展示出来”的通用界面。

但是产品顺序仍然应该是：

```text
先学习 source grounding
再 Source Board
再 Learning Canvas
再通用展示层
```

## 9. 风险

### 风险 1：把 v2.3 做成完整 PDF 编辑器

会拖垮版本边界。

应对：只做 viewer、anchor、selection、jump、proposal。

### 风险 2：Source Board 过早变成自由画布

会抢 v2.4 的工作。

应对：v2.3 只做轻量 board seed。

### 风险 3：source anchor 不稳定

如果 PDF 页面变动、OCR 重跑、source 替换，引用可能错位。

应对：anchor 要同时存 page、chunk、excerpt、confidence、metadata；未来再做 bbox/char offset。

### 风险 4：AI 展示板诱惑太强

未来空间很大，但当前会扰乱 v2.3。

应对：记录长期方向，不提前实现。

---

## 10. 当前结论

Source Viewer / Source Board 是 v2.x 的关键转折点。

它把 Coincides 从：

```text
AI 生成笔记
```

推进到：

```text
用户可以检查来源、选择范围、验证证据、组织 source-grounded learning objects。
```

推荐 roadmap 调整：

- v2.2: 保持 Material Reconciliation 主线，但让 reconciliation 输出 source-anchor-ready。
- v2.3: 明确改成 Source Snapshot Viewer + Source Board seed。
- v2.4: Learning Canvas 继承 Source Board，不另建第二套知识对象。
- 长期: 记录 Board/Canvas 作为 AI 生态成果展示层的潜力。
