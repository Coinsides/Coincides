# v2.x Roadmap 修改建议总报告

**创建日期**: 2026-05-21
**状态**: Roadmap 修改建议草案
**来源**: post-v2.1.1 七轮产品与架构调研

这份文件不是正式 roadmap。它用于把七轮调研压缩成一份可讨论的版本重排建议。等 Henry 确认后，再把成熟部分写入 `docs/Coincides-Roadmap.md`，并在进入具体小版本前创建对应 version plan。

---

## 1. 总体判断

v2.x 的方向需要从：

```text
v2.2 Material Reconciliation
v2.3 Source Snapshot Viewer
v2.4 Larger Learning Material OS
```

拆成更清晰的渐进路线：

```text
v2.2.x:
  Material Reconciliation
  多来源材料 -> evidence set -> canonical learning objects

v2.3.x:
  Source Snapshot / Source Anchor / Source Board seed
  用户能检查来源、选择范围、跳回证据

v2.4.x:
  Learning Canvas / Board / Interaction layer
  同一批学习对象的空间化 projection

v2.5.x:
  Template Engine / Composition Template / Domain Block Set / Package Studio seed
  用户和 agent 可以安全地扩展组织方式
```

核心原则：

```text
宁可多拆小版本，不把一个小版本塞成巨型工程。
```

## 2. 七轮调研压缩结论

### 2.1 Block Architecture

结论：

- 学 BlockSuite/AFFiNE 的架构分层，不引入依赖。
- NoteBlock 不应永远是平铺列表；未来要支持 hierarchy / composition。
- Canvas 是 projection surface，不是第二套知识本体。

Roadmap 影响：

- v2.2 开始避免把 reconciliation 写死成单 block 合并。
- v2.4 Learning Canvas 必须引用 NoteBlock / MaterialSegment / SourceRange。

### 2.2 Document / Canvas 双模式

结论：

```text
Document mode = 阅读和编辑顺序。
Canvas mode = 空间理解和关系组织。
两者共享学习对象，但不共享布局规则。
```

Roadmap 影响：

- v2.3 可以先做 Source Board seed。
- v2.4 再做 Learning Canvas。
- 画布坐标和文档顺序要分离。

### 2.3 Source Viewer / Source Board

结论：

```text
v2.3 不应该只是 PDF reader。
v2.3 应该是 Source Snapshot Viewer + Source Anchor + Scope Selection + Source Board seed。
```

Roadmap 影响：

- v2.3 要明确 source anchor 是核心对象。
- Source Board 是轻量选择/信任工具，不是完整自由画布。

### 2.4 Material Reconciliation

结论：

```text
Material Reconciliation 不只是去重。
它是从来源碎片到可信知识对象的审阅式合并流程。
```

Roadmap 影响：

- v2.2 要拆清 duplicate / overlap / same-concept evidence / conflict。
- 必须 proposal-first，可恢复，不静默删除 source evidence。

### 2.5 Learning-Specific Blocks

结论：

- Learning-specific blocks 是第一个 Domain Block Set 样本。
- ReviewCard、FormulaSheet、ProofList、ExerciseSet、Briefing/Report 都应该是 projection。
- 应加入 BlockRelation 的长期概念。

Roadmap 影响：

- v2.2 reconciliation 需要识别 learning role candidate。
- v2.4 canvas 需要支持学习关系边。
- v2.5 template engine 需要支持 Domain Block Set。

### 2.6 Template Engine / Package Studio

结论：

```text
开放 template variant。
开放 composition template。
开放 domain block set。
不轻易开放底层 system block type。
不开放任意代码插件。
```

Roadmap 影响：

- v2.4.x 或 v2.5 应新增明确 Template Engine / Package Studio seed。
- Composition Template 是非常重要的中间层，应该早建模、晚开放完整 UI。

### 2.7 AI Proposal UX

结论：

```text
AI UX 核心不是 Chat。
核心是 Proposal -> Review -> Apply -> Evidence -> Recovery。
```

Roadmap 影响：

- v2.2-v2.5 所有 AI 结构变化都必须 proposal-first。
- Proposal 需要 type、scope、evidence、diff、warnings、apply plan、operation batch。

## 3. 建议的新版本摊开

下面是建议拆分，不是最终锁定版。进入每个版本前仍需单独写 version plan 和 engineering spec。

## 4. v2.2.x: Material Reconciliation Track

### v2.2.0: Reconciliation Data Model + Proposal Shell

目标：

- 建立 Material Reconciliation 的最小数据和 proposal 框架。
- 不做复杂 UI，不做全自动 merge。

主要内容：

- `MaterialReconciliationProposal`
- `ReconciliationCandidateGroup`
- group kind:
  - `DUPLICATE`
  - `OVERLAP`
  - `SAME_CONCEPT_EVIDENCE`
  - `CONFLICT`
- proposal evidence summary
- confidence / warnings
- operation batch hooks

不做：

- full source viewer；
- free canvas；
- auto canonical truth；
- cross-course reconciliation。

### v2.2.1: Evidence Set + Conservative Merge Apply

目标：

- 让用户 apply reconciliation proposal，并保留 evidence set。

主要内容：

- `EvidenceSet`
- `MergedSourceEvidence`
- accept / keep separate / defer
- canonical block candidate
- preserve source evidence
- no silent delete

### v2.2.2: Exclusion / Conflict / Recovery

目标：

- 处理排除、冲突、恢复。

主要内容：

- `ExcludedMaterialScope`
- `ConflictReviewItem`
- restore excluded scope
- unmerge / split group path
- operation batch before/after snapshot

### v2.2.3: Role-aware Reconciliation

目标：

- reconciliation proposal 能识别学习角色候选。

主要内容：

- definition / theorem / formula / example / exercise candidate
- exercise-answer pair candidate
- source excerpt -> role suggestion
- template metadata preserved

备注：

- 不做完整 Learning Template Editor。
- 只为后续 v2.3/v2.5 准备。

---

## 5. v2.3.x: Source Viewer / Source Board Track

### v2.3.0: Source Snapshot Foundation

目标：

- 建立 source snapshot 的最小可用基础。

主要内容：

- `SourceSnapshot`
- `SourceSnapshotPage`
- normalized page/text representation
- parser warnings
- source status
- lazy snapshot generation strategy

候选工具评估：

- `EmbedPDF`
  - 用途: PDF viewer / annotation / search / zoom / plugin-based UI。
  - 初步价值: 可作为 v2.3 PDF Source Snapshot Viewer 的首选候选。
  - 风险: 需要验证渲染稳定性、bundle 体积、Windows 本地开发体验、annotation 与自定义 SourceAnchor 的整合难度。
- `PDF.js`
  - 用途: 更底层的 PDF 渲染。
  - 初步价值: 稳定后备方案，适合自定义 viewer。
  - 风险: annotation、search、jump、UI 需要更多自建。

不做：

- full PDF editor；
- bbox annotation；
- video/audio snapshot；
- free canvas。

### v2.3.1: Source Anchor + Jump Back

目标：

- NoteBlock / proposal / source range 能互相跳转。

主要内容：

- `SourceAnchor`
- page range / chunk / excerpt anchor
- NoteBlock source badge -> source viewer
- source anchor -> related NoteBlocks/proposals
- weak anchor warnings

候选工具评估：

- `EmbedPDF` / `PDF.js`
  - 用途: page jump、page rendering、text layer extraction、highlight overlay。
  - 关键判断: 工具只负责渲染和交互层；`SourceAnchor`、`SourceReference`、jump-back 关系仍由 Coincides 定义。

### v2.3.2: Scope Selection

目标：

- 用户可以选择 source scope，用于 proposal 和后续整理。

主要内容：

- `SelectedMaterialScope`
- page/page-range/chunk/segment selection
- selected / excluded / used / unused 状态
- create proposal from selected scope

### v2.3.3: Source Board Seed

目标：

- 做轻量 Source Board，不做完整 canvas。

主要内容：

- selected ranges list/board
- related NoteBlocks
- reconciliation states
- evidence groups
- proposal entry points
- simple grouping/reorder if needed

不做：

- full edgeless workspace；
- arbitrary graph layout；
- relationship graph editing。

### v2.3.4: Source Annotation / Media Snapshot Planning Patch

目标：

- 如果需要，为 source annotation 和 media snapshot 做小补丁规划。

主要内容：

- annotation vs excerpt vs NoteBlock distinction
- web snapshot / PDF snapshot priority
- video/audio anchor 只进入设计，不要求实现

候选工具评估：

- `Mozilla Readability`
  - 用途: Web source 正文抽取。
  - 初步价值: 适合 `WebSnapshot` pipeline 的正文层。
  - 注意: 需要配合 sanitizer，不能直接信任网页 HTML。
- `DOMPurify`
  - 用途: 清洗不可信 HTML。
  - 初步价值: Web Snapshot 安全边界。
- `Playwright`
  - 用途: 网页截图、PDF capture、视觉快照、动态网页加载。
  - 初步价值: 可作为 Web Snapshot 的 screenshot/PDF capture 层。
  - 风险: 浏览器运行成本、动态页面稳定性、离线/本地模式支持。
- `SingleFile`
  - 用途: 保存完整网页为单 HTML。
  - 初步价值: 可作为完整网页归档能力参考或候选。
  - 注意: license 和集成复杂度需要版本期再评估。

## 6. v2.4.x: Canvas / Board / Interaction Track

### v2.4.0: Learning Canvas Data Model

目标：

- 建立 canvas 是 projection surface 的数据基础。

主要内容：

- `LearningCanvas`
- `CanvasNode`
- `CanvasEdge`
- `CanvasFrame`
- `CanvasSessionState`
- node references NoteBlock / MaterialSegment / SourceAnchor / Projection

原则：

- canvas 不创建第二套学习内容本体；
- layout state 和 content state 分离；
- session state 不污染 learning data。

候选工具评估：

- `Excalidraw`
  - 用途: 快速验证无限画布、箭头、图片、手绘风格、导出 JSON。
  - 初步价值: 很适合做 v2.4 之前的 canvas prototype 或轻量 board。
  - 风险: `.excalidraw` 数据模型不是 Coincides domain model，不能作为学习对象事实源。
- `tldraw`
  - 用途: 更完整的 infinite canvas SDK、tool mode、shape/store/session 思路。
  - 初步价值: 很适合做 Learning Canvas 实现层候选或架构参考。
  - 风险: SDK license/production behavior 需要版本期确认；不要把 Coincides 核心模型绑定到 tldraw store。

原则:

```text
Canvas tool can render and manipulate.
Coincides owns CanvasNode / CanvasEdge / CanvasFrame.
```

### v2.4.1: Canvas Viewer + Basic Layout

目标：

- 用户可以在 canvas 上查看和整理已有对象。

主要内容：

- pan / zoom
- select / move
- simple frames/groups
- open target object
- add existing block/source/projection to canvas

候选工具评估：

- `Excalidraw`
  - 可用于快速做 board interaction spike。
  - 适合验证箭头、frame/group、图片、export。
- `tldraw`
  - 可用于验证 command/tool mode、shape binding、session state、custom shape。
  - 如果选用，必须定义 adapter:
    - Coincides object -> canvas shape；
    - canvas shape -> Coincides node reference；
    - tool state -> Command & Interaction layer。

### v2.4.2: Canvas Proposal UX

目标：

- AI 可以提出 canvas nodes / edges / layout，但必须 review/apply。

主要内容：

- `CanvasLayoutProposal`
- proposed nodes
- proposed edges
- proposed frames
- relation confidence
- warnings
- apply operation batch

### v2.4.3: BlockRelation Seed

目标：

- 建立轻量关系层，服务 learning canvas 和 review projection。

主要内容：

- `BlockRelation`
- relation kinds:
  - `proves`
  - `uses_definition`
  - `uses_formula`
  - `example_of`
  - `answers`
  - `supports`
  - `contradicts`
- proposal-first relation creation

### v2.4.4: Command & Interaction System Seed

目标：

- 不做完整快捷键系统，先建立 command/action registry。

主要内容：

- `Command`
- `ToolMode`
- `InputBinding`
- `Context`
- command palette seed if useful
- future desktop / projector / gesture ready

备注：

- 快捷键只是 input binding 的一种。
- 这个版本应该靠近 Canvas 工作，不要太早做。

候选工具评估：

- `tldraw`
  - 可借鉴 tool mode / editor API / shape store 的交互模型。
- `Excalidraw`
  - 可借鉴固定工具、箭头、binding、快捷操作的轻量体验。

注意:

- 不应先从 keyboard shortcuts 设计；
- 应从 Command / ToolMode / InputBinding / Context 设计；
- 键盘只是其中一种 binding。

### v2.4.5: Composition Template Seed

目标：

- 如果 organized note / briefing / formula sheet 需求变强，先做 composition template seed。

主要内容：

- built-in composition templates
- formula sheet section
- side note section
- evidence table section
- proposal can reference composition template
- no full user editor yet

## 7. v2.5.x: Template Engine / Package Studio Track

### v2.5.0: Template Definition Runtime

目标：

- 把 v2.1.1 静态 registry 升级为可持久化 template definition。

主要内容：

- `TemplateDefinition`
- system type remains closed
- semantic role
- template variant
- source behavior
- proposal behavior
- projection behavior
- versioning

候选工具评估：

- `BlockNote`
  - 用途: block-based React editor，内置 slash menu、drag/drop、nested blocks、多媒体、自定义 blocks。
  - 初步价值: 未来 Note editor 体验升级候选。
  - 风险: 不要让 BlockNote block schema 取代 Coincides NoteBlock domain model。
- `Lexical`
  - 用途: Meta 的可扩展 rich text framework。
  - 初步价值: 更底层、更可控，适合长期自研 editor substrate。
  - 风险: 需要更多 editor 工程。
- `ProseMirror` / `Tiptap`
  - 用途: 结构化 rich text schema、collaboration、custom node。
  - 初步价值: 成熟、可控，适合复杂编辑器。
  - 风险: 学习成本和集成成本较高。
- `Milkdown`
  - 用途: Markdown-first WYSIWYG framework。
  - 初步价值: 如果需要 Markdown-friendly editor/export，值得评估。
  - 风险: Coincides 内部对象图不应退化成 Markdown。

建议:

- v2.5 前不要急着更换 Note editor substrate；
- 先做 editor substrate spike，再决定是否迁移。

### v2.5.4: Template Proposal + Migration Proposal

主要内容：

主要内容：

## 10.1 开源和外部工具取向

Henry 当前的产品取向是：

```text
Coincides 首先服务个人使用和开源协作。
如果未来开放给他人使用，也倾向于直接开源和免费提供，而不是闭源商业售卖。
```

因此，调研外部工具时可以比商业闭源产品更开放地评估：

- GPL / AGPL 工具；
- open-core 工具；
- 生产环境需要 license key 的 SDK；
- 可以自托管或本地使用的社区工具。

这会影响外部工具策略：

- 不必因为非 MIT/Apache 就直接排除；
- 但必须记录 license / runtime restriction / production requirement；
- 如果未来有人基于 Coincides 做商业化或生产环境分发，应由他们自行处理对应工具的授权；
- Coincides 自己仍应尽量保持核心对象模型独立，避免被任何外部工具的数据结构锁死。

建议原则：

```text
External tools can power UI/rendering/prototyping.
Coincides owns the domain model, source evidence, proposals, templates, and operation history.
```

这意味着：

- tldraw / Excalidraw 可以作为 Learning Canvas 或 Source Board 的候选实现层；
- EmbedPDF / PDF.js 可以作为 Source Snapshot Viewer 的候选实现层；
- Readability / Playwright / DOMPurify 可以进入 Web Snapshot pipeline；
- BlockNote / Lexical / ProseMirror / Milkdown 可以作为未来 Note editor substrate spike；
- 但 NoteBlock、SourceAnchor、EvidenceSet、TypedProposal、CompositionTemplate、DomainBlockSet 仍应由 Coincides 自己定义。

## 10.2 外部工具候选总览

这些不是立即采用决定。它们是后续版本进入 plan/spec 前需要重点评估的候选。

### Source Viewer / Snapshot

- `EmbedPDF`
  - 类型: PDF viewer SDK。
  - 候选版本: v2.3.0 / v2.3.1。
  - 可能用途: PDF rendering、annotation、search、zoom、print、viewer UI。
  - 当前判断: Source Snapshot Viewer 首选候选之一。
- `PDF.js`
  - 类型: PDF rendering library。
  - 候选版本: v2.3.0 / v2.3.1。
  - 可能用途: 自建 PDF viewer 的底层渲染。
  - 当前判断: 稳定后备方案。
- `Mozilla Readability`
  - 类型: Web article extraction。
  - 候选版本: v2.3.4 或 Web Snapshot patch。
  - 可能用途: WebSnapshot 正文抽取。
- `DOMPurify`
  - 类型: HTML sanitizer。
  - 候选版本: Web Snapshot pipeline。
  - 可能用途: 清洗 Readability / webpage HTML。
- `Playwright`
  - 类型: browser automation。
  - 候选版本: Web Snapshot pipeline。
  - 可能用途: 网页 screenshot、PDF capture、dynamic page capture。
- `SingleFile`
  - 类型: complete web page archive。
  - 候选版本: Web Snapshot later patch。
  - 可能用途: 完整网页归档参考或候选。

### Canvas / Board

- `Excalidraw`
  - 类型: embeddable infinite whiteboard。
  - 候选版本: v2.4.0-v2.4.1 spike。
  - 可能用途: canvas prototype、arrow/frame/group、image board。
  - 当前判断: 很适合快速验证，但不能成为 Coincides domain model。
- `tldraw`
  - 类型: infinite canvas SDK。
  - 候选版本: v2.4.0-v2.4.4 spike。
  - 可能用途: custom shapes、tool mode、store/session、interaction system。
  - 当前判断: 强候选/强参考；license 与 production 行为在版本期确认。

### Note Editor / Block Editor

- `BlockNote`
  - 类型: React block editor。
  - 候选版本: v2.5 editor substrate spike。
  - 可能用途: slash menu、drag/drop、nested blocks、多媒体、自定义 block。
  - 当前判断: 快速提升 Note editor 的候选，但不能接管 domain model。
- `Lexical`
  - 类型: rich text framework。
  - 候选版本: v2.5+。
  - 可能用途: 更底层可控 editor substrate。
- `ProseMirror` / `Tiptap`
  - 类型: structured rich text editor framework。
  - 候选版本: v2.5+。
  - 可能用途: schema-based editing、custom node、collaboration。
- `Milkdown`
  - 类型: Markdown-first WYSIWYG editor。
  - 候选版本: v2.5+ export/editor spike。
  - 可能用途: Markdown-friendly editing/export。

### Architecture Reference / Possible Future Spike

- `BlockSuite`
  - 类型: block editor architecture / editor runtime。
  - 候选版本: future technical spike。
  - 可能用途: schema / service / view / widgets 分层参考。
  - 当前判断: 暂不直接引入，继续作为架构参考。

### 统一评估清单

- 能否通过 adapter 接入？
- 导出/备份/迁移是否可控？

## 12. 最终一句话

v2.x 不应该被压成三四个巨型版本。

更合理的是：

```text
v2.2 解决多来源材料如何被审阅式合并。
v2.3 解决用户如何检查来源、选择范围、信任证据。
v2.4 解决同一批学习对象如何被空间化组织。
v2.5 解决用户和 agent 如何安全扩展模板、组合和领域包。
```

这样 Coincides 才能从学习系统稳定成长为更大的 source-grounded knowledge workspace，而不是在某个版本里一次性失控。
