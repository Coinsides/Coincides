## EI-001: Coincides 可能成长为个人知识处理中台

**来源**: 2026-05-21 Henry 讨论

Coincides 当前以学习系统为起点，但底层能力可能扩展到更通用的个人知识处理中台：

```text
收集信息
-> 保留来源
-> 切分成结构化片段
-> 生成可审阅的组织方案
-> 变成 NoteBlock / Source Board / Canvas
-> 输出成笔记、简报、报告、复盘、线索图
```

潜在输出：

- learning note；
- briefing；
- report；
- evidence board；
- investigation board；
- research dossier；
- knowledge map；
- decision memo；
- AI result board。

暂时处理：

- 不扩大 v2.2/v2.3 范围；
- 在 v2.4+ Learning Canvas / Package Studio / Report Projection 规划时重新评估。

- evidence；
- node；
- relation；

- export/presentation。

暂时处理：

- 记录为长期方向；
- v2.3 仍只做 Source Board seed；
- v2.4 再进入 Learning Canvas。

## EI-003: Note / Canvas 在导出前不是文件，而是对象图

**来源**: 2026-05-21 Henry 讨论

导出前，一篇 note 或 canvas 不应该先被理解成 Markdown、JSONL 或 PDF 文件，而应该是系统内部的对象图：

```text
Note
  -> NoteBlock placements
  -> NoteBlocks
  -> SourceReferences
  -> ProjectionSnapshot
  -> CanvasLayout
```

导出时才转换成：

- Markdown；
- HTML；
- PDF；
- JSONL；
- zip/package；
- future report/briefing format。

暂时处理：

- 作为 export/package planning 的前置原则；
- 不影响当前 v2.2/v2.3。

## EI-004: Media / Video Block 与 Source Snapshot

**来源**: 2026-05-21 Henry 讨论

未来 block 可以包含 video/audio/media，但不同视图和导出方式能力不同：

```text
应用内:
  video block 可以播放、跳时间戳、关联 source anchor。

PDF/静态导出:
  video block 只能降级为封面图、标题、时间戳、链接、QR code、transcript excerpt。
```

Source Snapshot 不应只覆盖 PDF/webpage，也应长期考虑：

```text
PDF Snapshot
Web Snapshot
Image Snapshot
Video Snapshot
Audio Snapshot
```

视频的 anchor 不是 page，而是：

```text
timestamp_start
timestamp_end
thumbnail
transcript_excerpt?
local_asset_id or video_url
```

暂时处理：

- v2.3 优先 PDF/web/source snapshot；
- video/audio snapshot 作为后续 media source extension；
- AI 没有 transcript 时不能假装理解视频内容。

## EI-005: Domain Block Set 是未来特种 block 的组织方式

**来源**: 2026-05-21 Henry 讨论

未来不应该把每个领域都做成新的底层 block type。更稳的模型是：

```text
System Block Type
  text / latex / code / media / table / task / source_quote

Semantic Role
  concept / definition / clue / evidence / claim / event

Template Variant
  paragraph.poetry / formula.math / evidence.webpage / clue.game

Domain Block Set
  Learning Block Set
  Literature Block Set
  Investigation Block Set
  Information Collection Block Set
```

暂时处理：

- 已补入 `v2.x-learning-blocks-reference.md`；
- 下一步 Template Engine / Package Studio 调研要以 Domain Block Set 为核心概念。

## EI-006: Command & Interaction System beyond keyboard shortcuts

**来源**: 2026-05-21 Henry 讨论

快捷键不应该被理解成单独的 UI 小功能。它代表的是更大的交互层：

```text
用户如何高频操控结构化对象。
```

未来 Coincides 的输入方式可能包括：

- keyboard shortcuts；
- mouse drag；
- toolbar tool mode；
- right-click/context menu；
- touch gestures；
- pen input；
- large screen / projector gestures；
- agent command；
- voice or multimodal command。

所以更稳的模型不是先做快捷键，而是先定义：

```text
Command
  真实动作，例如 create edge / group nodes / apply proposal。

Tool Mode
  当前工具状态，例如 arrow mode / source select mode / pan mode。

Input Binding
  键盘、鼠标、触控、手势、笔、agent command。

Context
  Note editor / Source Board / Learning Canvas / Presentation wall。
```

例子：

```text
用户先选择一种 arrow style / relation type。
进入 arrow mode，或按住某个 modifier。
从 block A 拖到 block B。
系统创建固定样式的 edge。
```

这看起来像快捷键，但本质是：

```text
Command + Tool Mode + Gesture + Context
```

暂时处理：

- 现在不做快捷键实现；
- v2.4 Learning Canvas 前后再正式设计 Command & Interaction System；
- 未来桌面 app、大屏、投影墙、手势操作会让这个系统变得非常重要；
- 这个方向应该和 Learning Canvas / Source Board / Presentation Board 一起考虑。

## EI-007: AFFiNE-like entity interface with customizable canvas background

**来源**: 2026-05-21 Henry screenshot feedback

Henry 想要的最终界面不是单纯的 Notion-like 文档页，也不是单纯的白板，而是类似 AFFiNE 的实体界面：

```text
普通文档模式
  -> 接近 Notion 的线性文档 / block editor

自由画布模式
  -> 同一份内容可以被投射到可缩放、可拖动、可连线的 canvas
```

但 Coincides 的需求还要更进一步：

```text
Canvas background must be user-customizable
```

这里的 background 不只是暗色网格或默认点阵，而应该长期支持用户自由更改，例如：

- grid / dotted / blank / lined background;
- custom image background;
- subject-specific background, such as map, diagram, timeline, room board, investigation wall;
- future generated or template-based canvas background;
- background as part of a canvas template or presentation board.

This should expand into a broader user-defined visual language system, not only background customization:

- arrow / connector styles should be user-customizable;
- shape styles should be user-customizable;
- dialog / speech bubble styles should be user-customizable;
- table border and table visual styles should be user-customizable;
- meme / sticker / expressive visual elements should be supported as reusable assets;
- flowchart default styles should be user-customizable;
- canvas templates and flowchart templates should carry intended application scenarios.

Agent implication:

The future agent should eventually be able to use these user-defined styles and templates when designing notes, boards, reports, or canvas layouts.

This raises a later design question:

```text
How does the agent know when a user-defined flowchart template, connector style,
dialog style, table style, or canvas background is appropriate?
```

Possible future answer:

- each visual style/template may need a short summary;
- each template may need intended use cases;
- templates may need tags, domain metadata, examples, and constraints;
- agent selection should happen through a style/template registry rather than free guessing.

产品含义：

- Coincides 的文档模式可以借鉴 AFFiNE / Notion 的 block document experience；
- Coincides 的 canvas 模式要成为可自由创作、整理、展示和推理的空间；
- 背景本身也是表达结构的一部分，不只是装饰；
- 这会影响 v2.4 Learning Canvas / Source Board / Presentation Board 的设计。

暂时处理：

- 不进入 v2.2 / v2.3 范围；
- 在 v2.4 Learning Canvas planning 时正式评估；
- 和 Command & Interaction System、Source Board、Presentation Board 一起考虑；
- 不要求当前 Note editor 做视觉重构。
