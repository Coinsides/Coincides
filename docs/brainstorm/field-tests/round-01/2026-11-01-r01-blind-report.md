## 四、问题清单 · 🅰 正确性

格式：现象 / 复现 / 证据（截图编号或接口）/ 建议判级理由。

### A-01 「上传 → 项目材料」没有界面路径，Agent 的写入因此全部失败
- **现象**：三份 Source 都 Ready，Project Material 始终 0、「No parsed project materials yet」。Material Map、Note Proposal、Reconcile 三个按钮均为禁用，悬停也没有任何说明。Source 详情里没有「转为项目材料」之类的动作；对大文件点「Rebuild projection」重建后，Project Material 仍为 0。让 Agent 把自测题存成笔记，回执「✗ create_proposal」，原始报错「No material segments found for the selected scope」。
- **复现**：上传材料 → 看 Project Material 区块 → 在笔记里打开 Agent，请它把内容存成新笔记。
- **证据**：13、46、47、65、66、43。
- **理由**：测试令里的「转换」一步在界面上不存在；Agent 建笔记依赖它，所以对新用户整体不可用。

### A-02 从首页问 Agent，读不到用户上传的材料
- **现象**：在首页问已上传讲义的内容，Agent 答「在材料库（documents）里检索了两次……Source Library 的内容我检索不到，这是能力边界」，并建议「经材料库上传」，但界面上没有这个入口。
- **补测**：源文档阅读视图里拖选文字后，底部工具栏有「问 Agent」（69）。在笔记里带上下文问时，Agent 能读到笔记内容（42），所以从源文档里问很可能能读到。本轮没有为此再发消息，留第二轮验证。
- **复现**：项目里上传 PDF 至 Ready → 首页 Chat with Agent → 问该讲义讲了什么。
- **证据**：38、69。
- **理由**：首页是 Agent 最显眼的入口，「传上去问 AI」是学习主干；入口能问、却读不到，而且指引照做不了。

### A-03 新账号的 Agent 默认选了用不了的提供方，报错还误导
- **现象**：新账号默认 Agent 提供方 Anthropic、模型 claude-sonnet-4-20250514，设置页向量栏默认高亮 Voyage AI。第一条消息就报「No API key configured. Go to Settings to add one.」，而设置页同时显示「AI Provider 凭据（2 已配置）」。这句报错的真实意思是「你选的提供方没有钥匙」，用户读到的却是「整个应用没配钥匙」。报错里没有去设置页的链接，消息下还挂一个空气泡。
- **复现**：新注册 → 首页 Chat with Agent → 发任意消息。
- **证据**：33、34；接口返回 SSE `event: error`。把本账号提供方切到 DeepSeek 后正常（36），核对 `/api/auth/me` 确认只改了本账号设置。
- **理由**：岛上每个新账号的 Agent 开箱即坏；用户也无从知道「钥匙其实在，只是默认选错了家」。证据只来自一个新账号，第二轮用另一个新账号复核。

### A-04 新笔记第一段刚打完就回车，后续输入被吞
- **现象**：新建笔记 → 双击开始写 → 打第一段 → 立刻回车 → 接着打第二段：回车不新建段落，第二段文字整段消失（也没追加到第一段）。打完第一段停 1 秒再回车，一切正常。
- **复现**：同上。停 0 秒复现 3/3（含首次偶遇）；停 1 秒、停 3 秒均不复现；已存好的段落末尾回车也不复现。
- **证据**：18、53；Agent 读笔记时也指出「标题提到端口，但正文没有任何关于端口的内容」，丢的正是那段（42）。
- **理由**：静默丢失用户输入，无任何提示。窗口不到 1 秒，但「打完一句马上回车」正是常见节奏；中文输入法上屏后再回车的情形没测。

### A-05 新建之后列表不刷新（目标、卡片组、上传生成的笔记）
- **现象**：提示「Goal created」「Deck created」，对应区块仍显示 0 和空态，整页刷新后才出现。上传三份新材料后，接口里项目已有 7 篇笔记，项目页 Notes 仍显示 4 篇，离开再回来也不更新；删除 Source 时列表倒是会减少。
- **复现**：项目页 → Add Goal（或 Add Deck）→ 创建；或上传新文件后看 Notes 计数。
- **证据**：12、60、66；接口 POST /api/goals、/api/tasks/batch 均 201，之后没有重新拉取列表。
- **理由**：用户会以为没存上而重复创建；同一根因出现在三个地方。

### A-06 编辑目标的对话框写着「Create Goal」，已有任务不显示
- **现象**：在项目页点目标标题，打开的是「Edit Goal」，但底部按钮是「Create Goal」；这个目标已有的一条任务在对话框里不显示，任务区是空的。
- **复现**：项目页 → 点目标标题。
- **证据**：70。我没有点「Create Goal」，所以不确定会不会复制出第二个目标或清掉任务。
- **理由**：按钮文案与动作不符，叠加任务不显示，有误改或重复数据的风险。待施工方确认按下后的实际行为。

### A-07 手机尺寸基本不可用
- **现象**：375 宽下导航按桌面宽度展开，占约七成屏幕，项目标题一个字一行；没有自动收起或汉堡菜单。手动收起后项目页可读。笔记页把整张纸等比缩小，正文小到读不出，「Groups」「Staging」浮钮反而很大并盖在纸上。卡片上的「添加封面」在触屏上常驻，挤掉标题。
- **复现**：视口 375×812 打开项目页、笔记页。
- **证据**：56、57、58。
- **理由**：按决策记录，Henry 在大陆期间用手机访问是硬需求；目前这条路走不通。是否算正确性由设计方终审，我建议按 🅰 处理。

### A-08 （已知 P3，记现象）任何注册账号都能看到并清除全站共用的 AI 钥匙
- **现象**：设置页「AI Provider 凭据」显示的是全站共用的钥匙（DeepSeek、百炼已配，显示末四位），任何新注册账号都看得到，并且有「Save key」「Clear」按钮。文案「Keys stay on this machine」对服务器部署也不准确。
- **证据**：35（截图只含无钥匙的一格）。只观察，未点任何按钮。
- **理由**：对应档案里已暂缓的 P3「钥匙按人分开」。列在这里是因为它已经能从普通用户界面直接碰到。

### A-09 （出现一次，未能复现）离开笔记时误报「保存失败」
- **现象**：笔记里某段处于编辑态、在 Agent 面板里发过消息后，离开笔记，下一页弹红框「Changes could not be saved. Please retry before leaving the note.」。网络里没有任何失败请求，回到笔记内容完整。
- **补测**：「有改动立刻离开」「编辑态不改就离开」「编辑态开关 Agent 面板（不发消息）再离开」三种路径均未复现。合计 1/4。
- **证据**：44、45。
- **理由**：数据安全类误报会让用户不再信任保存提示。目前只能确认出现过一次，请施工方结合当时的前端日志判断。

## 七、设计走查主题（「施工现场」的成因）

1. **两套语言叠在一起**：英文骨架加零散中文，切换语言也只翻了一小部分。
2. **开发者视角外露**：内部标识、工具名、管线术语直接出现在界面、确认框和 Agent 回复里。
3. **引导描述的是另一个产品**：Course、Calendar、flashcards、study plans 与现在的 Project、画布、笔记对不上。
4. **死区块不解释**：Project Material 三按钮全禁用、插入菜单灰项，原因要么只在悬停提示里，要么没有。
5. **浮层抢位置**：工具条、浮条、链接面板、浮钮压住导航和正文。
6. **反馈不可信**：成功了不刷新，按钮写的和做的不一样，报错指错方向。

## 十二、复测相位 · F2 Source 删除流（版本 9d8858fe）

按 Main_Designer 部署通知，硬刷新后复测三条。本节与盲测发现分开记。

| 项 | 结果 | 说明 |
|---|---|---|
| ① 项目视图删除一条测试 Source，读确认框 | ✅ 通过，文案有一半不说人话 | 详见下方 |
| ② 删后重传同一文件，应为全新记录 | ✅ 通过 | 新 Source 编号与被删的不同，生成了新的投影笔记，几秒内 Ready，没有被当成重复拦下 |
| ③ 物化进行中的 Source 删除应被禁且有解释 | ⏸ 未能触发 | 物化在界面上没有可见窗口，抓不到进行中的状态 |

**① 细节**
- 项目视图 Source 详情右上角的删除键可用，点开是确认框「Delete What-Is-a-Server.pdf permanently?」。（62）
- **说人话的部分**：第一段「This cannot be undone. The original file and its extracted note… are deleted, and the Source is removed from every Project…」清楚；下面三行计数（1 个项目、1 篇提取笔记、0 处引用）直观。
- **不说人话的部分**：后两段「Library purposes and boards keep their identities. Project tags are weak associations…」「Some older purposes still belong to the extracted note. An unboarded legacy purpose is deleted…」是内部术语，新手读不懂；整框只有英文。
- 确认框叠在详情框上面，背后还有项目级的「Delete」按钮，误点风险存在但未发生。
- 删除后：接口 DELETE 返回 200；Source 列表立刻减为 2 条；投影笔记再查返回 404，确认连带删除。提示语「Source permanently deleted; historical receipts were retained」里的「historical receipts」是术语。（63）

**② 细节**
- 重传后得到新的 Source 编号和新的投影笔记编号，与被删记录都不同；状态 Ready。（64）

**③ 细节**
- 上传 160 页（约 510KB）和 700 页（约 2.2MB）的大 PDF，都在约 3 秒内 Ready。处理期间项目页列表里不出现这一行，Source Library 刷新时已经是 Ready。
- 改用「Rebuild projection」让它重新物化：接口是同步完成的（返回 200 即结束），同样没有可见的进行中状态。
- 结论：在用户能走到的路径上，这条无法触发。若要验证禁用逻辑，需要施工方提供能拉长物化时间的办法（例如测试开关或更慢的解析器）。
