## 六、新发现 · 🅰 正确性（建议判级）

### A-17 标题回车后失焦，整篇笔记静默卡在只读；期间在空块里打「# 文字」会丢字（9f291e6d 干净重验）
- **复现**（笔记 63f427aa，10:50 – 10:53）：
  1. 一个两行块，用拖柄 Turn into 把第二行「段落乙」转成标题。
  2. 在标题末尾 End、回车，**不打字**，直接让输入框失焦。重复两次，得到两个独立空块。
  3. 双击其中一个空块，快速打「# 节三」；另一个打「# 节四」。
  4. 再在标题末尾回车并失焦，造第三个空块。
- **现象一（丢字，2/2）**：「节三」「节四」两块都变成了空标题，服务器上 heading_1 的文字为空，字永久丢失。辅助功能树里却出现「Collapse chapter: 节三」「Collapse chapter: 节四」：客户端的章节结构记着标题名，文本那一半是空的。
- **现象二（卡死只读）**：
  - 第 4 步之后，还没打字，整篇 5 个输入框就全部 `readOnly`，持续超过 10 秒。
  - 因为 F8 改了锁标签，底栏不再显示「Source locked」，Layout 和装订也没有变灰。现在用户**完全看不出**笔记被锁了，打的字没有反应。
  - 双击进某个块之后只读解除。之后在那个块里打「# 」、停 1.2 秒、再打「节六」，「# 」快捷方式没生效，这一行被原样存成「# 节六」字样。
- **对照**：
  - 在段落里回车得到的新行（同一块内）打「# 节五」，完整保留。
  - 只走「回车后立刻打字」这条正常路径时，从未出现只读。
- **混杂期的同类现象**（b6515942，10:39 – 10:43，仅作线索）：
  - 现象一同样 2/2。
  - 卡死更重：双击后仍然只读，底栏「Source locked」常亮，直到整页刷新。
  - 刷新后，被扣在队列里的「节六」才在刷新那一刻（10:43:12）写入服务器，顶部出现恢复条「A block edit is waiting for recovery · 节六 · Apply / Dismiss」，我没有点。
- **推断**：
  - F7 的结构提交要等「焦点送达新段落」才算完成（见 F7 回执）。用户回车后不打字就失焦，这次提交就一直挂着，`headingStructure.busy` 不释放。
  - 而 `contentReadOnly` 是包括这个忙态在内的并集，于是整篇只读。
  - 此时在别的空块里用「# 」，转换照样执行，排队的按键却没有新段落可接，被丢弃。
- **建议判级**：🅰（静默丢字，加上编辑器整体被锁且无提示）。夹具：63f427aa（干净）、b6515942（混杂期）。
- **施工方确认（Main_Designer 转告）**：builder 在干净的本地实例上确定性复现了 A-17，版本污染疑云解除，F9 修二已放行。根因有两头：
  - 「# 」转换只发布了 flow 那一半，文本那一半没写进权威，这正是「章节树记着节三、块里是空」的成因。
  - `commitStructure` 依赖 requestAnimationFrame，在被节流的标签页里永远不回调，于是 busy 永久锁住。
- **环境说明**：我用的内置浏览器面板在被遮挡或处于后台时可能被节流。所以本报告里「卡死 10 秒以上」的时长可能被测试环境放大。但只要用户在结构提交途中切走标签页，就会碰到同样的锁死，问题本身成立。

### A-14 设置页整页加载显示错误提供方 → F8 已修，复测通过
- **初始化**：`client/src/pages/Settings/Settings.tsx:58–62` 用 useState 初始化器从 `user?.settings || {}` 取值，取不到就落回硬编码的 anthropic 和 claude-sonnet-4-20250514（`:21`、`:60–61`）。
- **为什么只在站内跳转时生效**：
  - F4-1 的 default_chat_provider 拉取在 `:104–116`，它只在 `settings.active_provider` 为空时发出（`:105`）。
  - 整页加载时，ProtectedRoute 只看令牌（`App.tsx:39`），AppLayout 立刻渲染子页面。设置页在 `/auth/me` 返回之前就挂载了，`user` 还是 null，初始化器把默认值锁死，同时发出 providers 请求。

### A-15 Agent 断言「项目里没有笔记」 → F8 已修，复测通过
- **工具清单**：聊天 Agent 拿到的是 `toolDefinitions`（`orchestrator.ts:231`），共 43 个工具，其中没有一个能按项目或标题列出、搜索用户笔记。`read_note` 必须先有 note_id（`registry.ts:826–828`）。
- **现成工具没开放**：`list_notes`、`get_note`、`list_note_blocks` 已在 `TOOL_REGISTRY` 里，但只以 public 身份开放给 MCP（`registry.ts:925`、`:935`；`mcp/manifest.ts:37`），没有进入聊天工具清单（`definitions.ts:11` 只展开三组 agent 工具）。另外 `listNotes`（`services/notes.ts:118–135`）不区分 Source 投影笔记和用户自写笔记，也没有标题过滤。F8 的 list_notes 已按自写与投影分开列。
- **为什么选择断言而不是声明边界**（提示词层）：
  - `system-prompt.ts:35–38` 把 documents 和 Source 称为「两座内容库」，并说 search_documents「一次检索两者」，暗示这是全部内容。
  - 唯一的找不到规则是「都找不到时如实说明」，只要求如实，不要求说清搜索范围。
  - 「宣称纪律」（`:48–54`）只管写动作和报错，不管「某物不存在」这类断言。
  - search_documents 的工具描述（`definitions.ts:228`）没说用户笔记不在范围内，也没说条数上限（文档 10 条、Source 5 份）；返回里的 `total`（`executor.ts:721`）读起来像库存总数。

### R2 遗留：「Source 路只认 1/6」是检索词没命中，不是枚举缺损
