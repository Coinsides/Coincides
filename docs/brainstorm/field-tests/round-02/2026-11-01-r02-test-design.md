## 三、复测项（对应 R1 的 🅰）

每项格式：步骤 / 期望 / 要截的证据。结果填「通过 / 部分 / 未通过 / 未能触发」。

### R2-01 Source 进入项目材料（R1 A-01，F3）
- **步骤**：账号甲的项目里看 Project Material 计数 → 上传一份新 md → 等 Ready → 刷新项目页。再看三个按钮（Material Map、Note Proposal、Reconcile）是否可用，禁用时是否有原因说明。
- **期望**：旧 Source 与新 Source 都能进入项目材料（或有一个明确、可发现的动作把它们放进去）；按钮可用或禁用有说明。
- **证据**：前后两张项目页截图、按钮状态、相关接口返回码。

### R2-02 Agent 读材料（R1 A-02 / C-02，F3）
- **步骤**：①首页 Chat with Agent 问一份已上传讲义讲了什么；②在该讲义的源文档阅读视图里拖选一句，点「问 Agent」问同一问题。
- **期望**：至少②能答出讲义内容；①若仍读不到，回复里不再出现「documents」「经材料库上传」这类无法照做的指引。
- **证据**：两条回复的原文片段、面板上下文标签。计 2 条。

### R2-03 Agent 建笔记（R1 A-01 / C-04，F3）
- **步骤**：在源文档或项目上下文里请 Agent 把「三道自测题」存成新笔记 → 去提案收件箱（或 Tool Receipts）采纳 → 回项目页看新笔记。
- **期望**：提案登记成功；采纳入口能被新手找到；采纳后笔记出现在项目里，且不需要整页刷新。
- **证据**：回执、收件箱截图、项目页笔记列表。计 1–2 条。

### R2-04 Agent 找笔记（R1 C-03）
- **步骤**：首页问「列出我这个项目里的笔记」，再问「读一下《我的笔记：公网、内网和端口》」。
- **期望**：能列出或按标题找到；若设计上仍要求 ID，回复应告诉用户在界面哪里能拿到，而不是让用户报内部编号。
- **证据**：回复原文片段。计 2 条。

### R2-05 新账号默认提供方（R1 A-03，F4）
- **步骤**：账号乙注册后不进设置，直接首页发一条消息；再看设置页 Agent 与向量两栏的显示，并与 `/api/embedding/status` 对照。
- **期望**：开箱可用（默认 DeepSeek 或等效）；若仍失败，报错说清「当前选的提供方没有钥匙，去设置改」并带链接；设置页向量栏显示与服务器实际一致（R1 B-38）。
- **证据**：首条回复、设置页截图、接口返回。计 1 条。

### R2-06 回车吞字（R1 A-04，F4）
- **步骤**：新笔记 → 双击 → 打一句 → 分别在停 0 秒、约 0.3 秒后回车并立刻继续打字，各 3 次；再用中文输入法打一句、上屏后立刻回车（若浏览器面板支持输入法则测，否则标未测）。
- **期望**：0/6 丢字；刷新后服务器上的内容与屏幕一致。
- **证据**：每次的段落内容（页面读取）与刷新后对照。

### R2-07 新建后列表刷新（R1 A-05，F4）
- **步骤**：项目页分别新建目标、卡片组；上传一份新文件；Agent 采纳一条笔记提案（接 R2-03）。每次都不刷新，直接看对应区块。
- **期望**：四处都即时出现；Notes 计数与接口一致。
- **证据**：每次操作后的区块截图与接口计数。

### R2-08 编辑目标（R1 A-06，F4）
- **步骤**：点目标标题打开编辑框 → 看按钮文案与已有任务是否显示 → 改标题后保存 → 回项目页与日历核对。
- **期望**：按钮写「保存」类文案；已有任务可见可改；保存后不产生第二个目标、不丢任务。
- **证据**：编辑框截图、保存前后的目标与任务列表（页面与接口）。

### R2-09 误报保存失败（R1 A-09，F4 搭车侦察）
- **步骤**：按 R1 唯一出现过的路径重走：笔记里某段进入编辑态 → 打开「问 Agent」并**发一条消息**（计 1 条）→ 关面板 → 用左侧导航离开。另走 R1 已排除的三条路径各一次作对照。
- **期望**：0/4 误报；若出现，同时抓控制台与网络记录交给施工方。
- **证据**：每次离开后的截图、控制台错误、网络失败请求。

### R2-10 F2 第三条（R1 第十二节 ③）
- **前提**：只有施工方提供「拉长物化」的测试手段时才测；否则沿用「未能触发」，不另找办法。
