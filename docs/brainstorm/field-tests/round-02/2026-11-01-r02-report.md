## 五、新发现 · 🅰 正确性（建议判级，编号接 R1）

### A-10 Reconcile 30 组候选全部误报（F3 桥接触发）
- **现象**：24 组「Possible overlap」配对的是两份不同 PDF，比如中文网络讲义和英文 What-Is-a-Server，理由却写「page ranges overlap within the same source document」。另 6 组「Same concept evidence」是同一份 md、同一 segment 的标题片段配它自己的正文。
- **原因线索**：证据里 `document_id` 全为 null。`materialReconciliationProposals.ts` 约 424 行的 `left.document_id !== right.document_id` 遇到 null 等于 null 就放行，任何页码重叠的跨源片段都被当成同文档。输出 `slice(0,30)` 截断，真重叠会被噪声挤掉。
- **复现**：有多份桥接材料的项目 → Reconcile。
- **影响**：只产出噪声提案，不改数据。另外界面露开发文案，见 B-43。
- **证据**：05、06；提案接口原始数据已核。

### A-11 Note Proposal 引用错配，AI 路径喂的是截断摘录
- **现象一**：项目页 Note Proposal 生成 23 块，`source_references` 只有一组，所有块都挂「网络基础入门 p.1、p.2 + SSH docx」。英文 What-Is-a-Server 那一块也引用中文 PDF。Agent 走 organized_note 建的笔记同样如此，8 块同一组引用。
- **现象二**：模型给出的警告称「原文第 2 页截断、第 3 节标题缺失」「SSH 讲义仅见标题」，而源文件是完整的。AI 路径用的是每段 500 字的引用摘录加总 12000 字上限，确定性回退路径的注释明说要用全文片段。
- **原因线索**：`organizedNoteProposals.ts` 的 `tryGenerateAiBlocks` 给每块挂 `fallbackRefs`，即全体 segment 的前 3 个引用；喂料用 `ref.source_excerpt`。
- **影响**：溯源是本产品的骨干。引用错配会让用户点「Source」跳到错误出处，模型警告也会让用户误以为原文损坏。
- **证据**：07、08、13、15。

### A-12 标题末尾回车吞字，5/5（A-04 族新入口）
- **现象**：在标题末尾按 End、Enter，新建了一个空行，但焦点不进去，接着打的字全部静默丢失。
- **复现**：拖柄菜单 Turn into → Heading 建的标题 4 次全丢，其中 3 次立刻打、1 次停 1 秒；行首 `# ` 建的标题 1 次也丢。
- **观察**：每回车一次留一个空 paragraph，服务器上可见。手动点进空行再打则正常。转标题的瞬间底栏闪现约 1 秒「Source locked」，Layout 和装订变灰，而这是用户自己的笔记。
- **对照**：普通段落回车 7/7 正常（R2-06），说明「唯一真相源」修好了段落路径，标题路径没覆盖到。
- **证据**：39、40；笔记 de003655 的服务器块序。

### A-13 空卡组无法加第一张卡，Agent 却能（触红线）
- **现象**：New Card 必选 Section，对话框里写「No sections in this deck. Create a section first.」，却没有建分区的入口。卡组页的「Add section」是无文字图标，按下去变亮但页面无任何变化。点 Create Card 无请求、无报错。Ctrl+K 弹出的是同一个对话框。
- **原因线索**：`DeckDetail.tsx` 约 201 行在 `cards.length===0` 时只渲染空态，不渲染 `SectionList`，而建分区的输入框在 `SectionList` 里。
- **对照**：让 Agent 加卡，它用 `create_section` 直接建了分区（不走提案），再登记两张卡的提案，采纳后可复习。
- **影响**：项目红线「Agent 能编辑的，人类必须 100% 都能编辑」被反向打破。新用户永远加不进第一张卡；手册写「卡创建唯一通道=提案」，与界面上的 Add Card 按钮矛盾。
- **证据**：23–25。

### A-14 设置页整页加载时显示错误的提供方（潜在误写）
- **现象**：甲账号的实际设置是 `active_provider=deepseek`、模型 deepseek-flash，服务端 `default_chat_provider=deepseek`，Anthropic 无钥匙。直接在 `#/settings` 整页刷新，Provider 下拉显示 Anthropic，Model 显示 claude-sonnet-4-20250514，2/2 复现。从首页站内点进设置则显示正确。
- **推断**：表单在用户设置加载前用默认值初始化了。
- **影响**：此时若点「Save Provider Settings」，会把 Anthropic 写回，未验证、未点。F4「设置页显示生效提供方」只在站内跳转路径上成立。
- **证据**：56；接口返回已核。

### A-15 Agent 断言用户的笔记不存在（C-03 的升级形态）
- **现象**：见 R2-04。R1 时 Agent 老实说「我列不出、需要 ID」，这轮改为断言「没有笔记」，并在下一轮引用这个错误结论。
- **原因线索**：工具链只搜材料，没有笔记的列举或搜索工具。F5 修好了 Source 路，用户自写的笔记仍不在 Agent 的视野里。
- **影响**：错误地否认用户数据存在，比「做不到」更伤信任。
- **证据**：16；会话工具链已核。

## 八、测试手段与证据边界（不算产品问题）

- **上传**：内置浏览器没有文件上传工具，用本地只绑 127.0.0.1 的小服务加页面脚本，把自造文件塞进上传控件，之后的链路全是真实的。材料全部自造。
- **150% 放大**：面板不支持 Ctrl+加号，视口缩到 683 宽会触发手机模拟。所以用根元素 CSS zoom 1.5 近似，媒体查询宽度仍是 1024，与真实浏览器 150% 不完全相同。
- **中文输入法**：面板无法驱动，N-09 和 R2-06 的输入法部分未测。
- **「?」快捷键面板**：三次按键没能确认弹出，可能是输入方式所致，不作为发现。
- **部分点击用了脚本定位**：滚动到元素、读坐标。结论只采信真实点击和按键的结果。有两处用脚本直接聚焦按钮再按 Enter，是 N-07 键盘路径的起点，等价于用户 Tab 到那里。
- **账号切换**：甲、乙之间是暂存登录令牌后互换，没有反复输密码。测试结束已清除暂存。

- **服务器**：只做只读取证（HEAD、journal、dist 文件时间）。
- **截图**：截图比例 800×600，视口 1024×768。存进本目录的截图都不含测试账号邮箱。
