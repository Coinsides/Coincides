# V2.BN.10.4 + 10.5 Source Experience / Lifecycle 联合浏览器验收

## 目的

验收当前工作区的完整 Source Floor，而不是分别验收已经过时的 10.4 和当前 10.5 快照。重点判断用户是否能理解 Source、Project 镜头、提取投影和历史收据的区别，并在删除前准确预期后果。

本交接取代未执行的 `2026-07-11-v2bn10.4-source-experience-browser-smoke.md`。旧 handoff 没有取得 PASS，其中“删除入口禁用”已不再是当前预期。

```text

```

使用仓库 `.env` 的测试账号，不把账号或密钥写入回执。准备三个普通 Project：A、B、C。打开 DevTools Console 和 Network。

## A. 10.4 基线回归

1. 从 Source Library 上传 TXT、PDF、DOCX、MD、PNG，确认可解析格式进入 Ready 并能打开提取阅读视图。
2. 上传 CSV/XLSX，确认显示 Original only 且原件可查看/下载，不进入空路由。
3. 上传损坏 DOCX，确认原件保留、失败原因稳定、Retry 与 `retryable` 一致。
4. 验证名称/类型/状态筛选、active-only polling、认证 Blob 双开和原始文件名下载。
5. 在 Project A 上传一个 PDF，再在 Project B 上传同一文件；B 应立即获得同一 Source placement，Library 中只存在一个 Source identity，Origin 不被 B 改写。
6. 打开 Ready 投影，确认 title、TextFlow、Block/Object、Layout/PageStack 和 document typography 写操作在请求前被锁；Page/Canvas 切换、选择、Annotation、ContentGroup 与允许的解释组织入口仍可用。

## B. Project 删除：纯投影默认

1. 在 Project A 新上传一个未在其他 Project 出现的 Source，等待 Ready；不要在投影上创建用户劳动。
2. 打开删除 Project 对话。推荐行为应为 `delete_projection`，并说明 Source 原件仍留在全局 Library。
3. 确认删除后：Project A 消失；Source record 和原件仍能从 Library 找到/打开；旧投影不再可达；不得删除事实 blob。
4. Library 若呈现 Projection missing，主动作必须降级到详情/原件，不得死点击。

## C. Project 删除：保护劳动与其他 placement

1. 使用在 Project B/C 均有 placement 的同一 Source，或在 B 的 SourceProjection 上建立 Annotation / ContentGroup / Purpose 中至少一种用户劳动。
2. 删除 Project B 时，推荐行为应自动变为 `move_to_home`；前端默认必须来自 impact API，而非固定写死。
3. 确认删除后 Source、原件、Home placement 和迁移后的投影仍在。
4. 若创建过用户劳动，确认 Annotation / ContentGroup / Purpose 仍可找到；Canvas/PageFrame/图片等可见布局不得因 Project 删除蒸发。
5. 再建一个隔离样本，显式把推荐值改为 `delete_projection`，确认对话清楚表达会删除投影及其 Project-local 劳动，但仍不会删除 Source identity/blob。

## D. Source hard delete

1. 从全局 Library 选择一个隔离 Source，打开删除对话。
2. 对话应显示 placement、projection、receipt、用户劳动影响，明确不可恢复，并说明历史 receipt 会降级而非消失。
3. 确认删除后：Library 与所有 Project Sources 中条目消失；投影不再可达；原件预览/下载接口不再返回 blob；页面无崩溃或无限 polling。
4. 若当前 UI 能建立外部 Source receipt，先建立一条再删除，确认引用仍显示 excerpt/locator 的历史证据且活跳转明确失效。若该入口尚未产品化，在回执中注明“receipt survival 仅由 10.5 integration test 证明”，不要伪造浏览器 PASS。
5. 尝试在 materialization active 时删除较大样本；若状态推进过快无法稳定复现，记录为未覆盖。稳定命中时必须被阻止，且不能留下删除一半或稍后复活的 Source。

## E. Home 与入口边界

1. Home 不应出现在普通可删除 Project 列表或允许被重命名/删除。
2. Project Sources 只能移除/管理镜头，不得出现“顺便删除 Source identity”的含混操作。
3. Source hard delete 只从全局 Source Library 发起。
4. legacy Documents Upload / Manage 不得重新成为正常摄入入口。

## F. UI、Console 与 Network

1. 桌面宽屏和窄窗口各走一次 Project/Source 删除对话，长文件名、统计、单选项和危险按钮不得重叠或溢出。
2. 删除中按钮应防重复提交；成功后列表和详情状态同步，不保留幽灵 modal。
3. Console 无未捕获异常、React key/controlled-input 警告或 Promise rejection。
4. Network 无裸 blob 401、重复整文件上传、无限 polling、重复 DELETE 或正常点击触发的意外 409/500。
5. Vite dynamic-import 与 chunk-size warning 是既有构建风险，不计为本轮浏览器失败。
