# V2.BN.12 修正单 05.6:恢复载体归家 + 副作用重绑(第二次设计介入)

## 设计裁决(Fable)

05.5 复核 FAIL(3H+共享树 gate blocker)。三 HIGH 的共同病根:**05.5 新造了 in-memory 恢复载体与调用时绑定的对账 fence——平行机关,不走正门**。而 03 链已有一套被四轮复核打磨过的 **sessionStorage 恢复收据系统**(versioned 校验/blocked 队列/可观察提示/remember-forget 纪律)。裁决:

1. **恢复载体归家**:废除 05.5 的 in-memory carrier;跨 note/跨 generation 的未决编辑,唯一恢复载体=**既有 note-scoped sessionStorage recovery receipt 系统**。载体天然在用户可见队列里、天然扛 hydration、清理天然走 receipt 纪律(只在显式 apply/dismiss 时清)——HIGH-2/HIGH-3 随平行机关死亡而消解。
2. **副作用重绑**:reconciliation 及一切写回副作用,创建时绑定不可变 `{requestedNoteId, creationGeneration}`;不满足绑定的 GET/settle 对**任何**当前 note 零 UI 写入。离开 note 后未决 save 的唯一合法副作用=写该 note 的 recovery receipt(HIGH-1 的修法)。
3. **申报诚实收窄**:同-note 并发再 hydration 的完整 OCC 支持**不申报**——生产今日无该触发器(05.4 复核已确认);epoch fence 保留为安全网(stale_epoch 结局+落 receipt),但回执只申报「安全网+恢复载体」,不申报「支持并发再 hydration」。客户端 OCC 极限并入 TD-6 注记。

## 修正要求

- R1 副作用重绑(上述 2)+复核官 HIGH-1 场景(A settle 于 B 可见时→B 零污染+A 编辑可于回 A 时寻回)落常驻 killer。
- R2 载体归家(上述 1)+复核官 HIGH-2/3 场景落常驻 killer(旧 generation 编辑可寻回/可放弃、过期 GET 不删新 intent 载体)。
- R3 申报收窄(上述 3)+TD-6 注记。
