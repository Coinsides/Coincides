# Stage-4 收尾：null-offset range 也走 renderable 门（封 -02 家族最后一个触发）

> **背景**：Stage-4 红线 BLOCKER（CR-8.11.15-01 pending 焊死）已由上一份修正单**真封死**（Claude 亲验 + 活探证实 fail-before）。但对抗核查第 4 维挖出**同族最后一个触发 CR-8.11.15-07（HIGH）**：overlap 失效的 **null-offset range 在健康块上不算 pending**，而 F2 的消费者门只挡 `pending`、放过它 → 漏进 badge/marker/AI、画在坐标 0 + stale 文本。本单收掉它 + 两条连带（-08/-09），Stage-4 完全 done。
> **一件事**：让所有"会把 range 画出来或喂给 AI"的消费者都按 **`annotationRangeIsRenderable`**（既排 pending、又排 null-offset）判定，而非只排 pending。
> **过程说明**：根因已由 Claude 逐行亲验（`annotationRangeIsRenderable` @annotationDisplayService.ts:56-62 **已正确排除 null-offset**，消费者只是没用它）。**验收测试是硬闸**；Claude 落地后重跑对抗核查。

## 根因（亲验·先读）

- `annotationRangeIsPending`（annotationDisplayService.ts:51-54）：仅 `anchor_status==='pending'|'invalid'` 为真。
- `deriveRangeMetadata`（annotationTruths.ts:262-279）：只对 **offset 是 number** 的越界标 pending。overlap 失效后 offset=**null** → OOB 检查被跳过（`typeof===number` 为假）→ 健康块返回**非 pending**。
- `annotationRangeIsRenderable`（annotationDisplayService.ts:56-62）：`isPending → false`；text_span **额外要求 start/end offset 是 number** → **null-offset range 正确判不可渲染**。**这个函数已经对了。**
- **坑 = 消费者门用 `!annotationRangeIsPending` 而非 `annotationRangeIsRenderable`** → null-offset range 溜过。

## 修

### F1 · 消费门 `!isPending` → `isRenderable`（收 CR-8.11.15-07 · HIGH）

**做法**：grep 全仓 `annotationRangeIsPending` 的**每一处消费用途**，凡是"渲染/命中测试/badge/marker/preview/喂 AI/导出/复制文本"的门，**换成 `annotationRangeIsRenderable`**（strictly 更强：排 pending + 排 null-offset text_span，其它 target_kind 不变）。已知需覆盖（以现状 grep 为准，行号可能漂）：
- `TextBlockProjection.tsx`：`rangeContainsTextOffset`、`annotationRangesForTextUnit`、`annotationStartOffsetInTextUnit`、`unitAnnotations`、`previewFromRanges`（badge/marker/高亮/preview/hit-test）。
- ContentGroup Rail preview / member projection（contentGroupRailShellModel.ts / contentGroupService.ts 的 rangePreview/annotationPreview）。
- ReadingInterpretation / AI-readable 投影（readingInterpretationService.ts 的 annotationPreview / projectAnnotationsForReading）。
- **复制动作**（NoteWritingSurfaceLayer.tsx:2305-2311 handleAnnotationHighlightContextAction）：复制 range_text_cache 前 `.filter(annotationRangeIsRenderable)`（别复制 stale/未锚定）。

**例外·不隐藏**：
- **AnnotationInspectorPanel.tsx:288-292**：inspector 是用户**重锚的地方**，**不要隐藏**未锚定 range → 保留显示，但加"未锚定/needs-review"标（可用 `!annotationRangeIsRenderable` 判定加 badge，不 filter 掉）。

**⚠ 不过度抑制**（回归必守）：健康 + offset 是 number 的 range **必须照常渲染**（`isRenderable` 为真）——只多挡 null-offset + pending。别误伤有效 range。

**验收**（修前 fail / 修后 pass）：
- 造一个 overlap-失效（offset=null）、块健康的 range → 断言**不产 badge/marker、不进 AI 投影、复制不含其 stale cache**；对比修前它在坐标 0 出现 / 进 AI。
- **不过度抑制正控**：一个健康 + 有效 offset 的 range → 断言**照常**产 badge + 进 AI（防 isRenderable 误杀）。
- inspector：未锚定 range **仍列出**、带未锚定标。

## 明确采用的判断（Claude 定）

- **渲染/AI/导出/复制门一律 `annotationRangeIsRenderable`**（排 pending + null-offset）；**inspector 例外**（显示 + 标未锚定，因它是重锚入口）。
- **不过度抑制**：有效 offset 的健康 range 照常渲染——正控测试必带。
- **读侧 strip 是兼容存量污染的兜底**，须有独立测试锁（写剥恒净会掩盖它）。
- 不改红线机制（上一单已封）；不建自动 re-anchor 引擎（仍留后续）。
