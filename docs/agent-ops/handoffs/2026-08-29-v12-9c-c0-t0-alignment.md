### 1.3 ⭐ 复核方实测:**现有的「折叠版」不够用,必须是「剥离版」**

fixture:`ref = "第一段文字。\n\n第二段文字。"`,碎片 `["第一段文字。","第二段文字。"]`(段间空行已被 `splitParagraphs` 丢弃)。

| canon | `canon(join)` vs `canon(ref)` | 结论 |
|---|---|---|
| **折叠版** `\s+ → ' '` | `"…。第二…"` vs `"…。 第二…"` | ⛔ **不相等** —— 段间空白丢失导致失配 |
| ⭐ **剥离版** `\s+ → ''` | 相等 | ✅ **可用** |

**并且剥离版同时满足**:元不变式 `nonWS(canon(x)) === nonWS(x)` ✅ · **丢一个非空白字节仍会失配** ✅
⇒ ⭐ **`whitespace` 类的 canonicalizer 定为【剥离全部空白】。**

#### ⚠️ 1.3a 剥离版的**射程限制,必须如实记**(v0.6.1)

**剥离把宽恕窗开到【全部空白编辑】** —— ⚠️ **词间空格被吞(`ab cd` → `abcd`)在此类下 K-1 【看不见】。**
📌 **这不是否决理由**:类名就叫 `whitespace`,**它的保证本就是【非空白字节序列保全】**,不多不少。
⛔⛔ **但绿的含义止步于此**:
> **⛔ 谁引 K-1 的绿去断言「空白也对 / 文本完全一致」,即为越界。**
⚠️ **⇒ 回执措辞硬要求**:**K-2 的绿只能写成「非空白字节序列一致」**,**⛔ 不得写成「文本完全一致」/「逐字相同」**。**复核方按此条打回措辞。**
📌 **这是「绿有两种含义」的又一分身** —— 演进触发器同 `detail`:**将来若有消费者需要词界保全,另立更细的类。**
📌 **它此刻零生产者**(c-0 是第一个申报 `whitespace` 的),**故现在改语义是免费的** —— ⛔ 以后就不是了。

### 为什么没有越权把 K-1 做绿

施工核对发现，工单的允许面与现役生产接点/锚契约存在四个不能靠「纯映射」消掉的硬冲突；若只为特制 fixture 在 intake 重跑 parser，会留下生产错误：

1. **同一份 artifact 的唯一合法接点在禁区外**：`sourceMaterialization.ts:201-210` 首次同时持有 owned source file、DB/user 身份与 `parseSourceArtifact` 返回值，随后 `:221-225` 发布投影。`sourceFileIntake.ts` 的 text-fallback 先例在 intake 当场已有 `fallback_text`；它拿不到后续 artifact。生产路由也没有传 `afterParse` hook。最小接线需在 `sourceMaterialization.ts:210` 后调用一个复用 text-fallback 形状的幂等 mapper，但该文件不在本单允许面。
2. **不能在 intake 偷跑第二次解析**：那会把「征用时拓印」前移为入库即拓印，并让同一文件在 intake 与 materialization 各解析一次。坏 PDF / resource-limit 会让 blob 已入库但 API 返回失败，撞上既有「入库永不拒收」killer；若 catch，则本次失败无出生证、后续 materialization 成功也不补，形成两套真相。
3. **页锚并非所有 block 都可诚实映射**：PDF block 有数值 `page_index`；DOCX/TXT/Markdown block 的 `page_index` 是 `null`。`PageAnchor.page` 又必须是 `>=1` 整数。把 null 伪成 1/seq 是假页码，改 flow/section 则违反本单钉死的 `anchor_fidelity:'page'`。
4. **同页多 block 无合法唯一页锚**：PDF parser 对每页 `flatMap(splitParagraphs)`，常会同页多 block；page anchor 在本期只有 `{family,page,bbox?}`，而校验器拒绝重复 exact anchor，且 page fidelity 禁止 bbox。合并整页会丢 `block → role/seq` 一一映射；伪 bbox/假页码/放宽唯一性都超出允许面。
