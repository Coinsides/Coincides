# 12.9d · 检索地基 —— 规格骨架

## 〇 · 定位:它就是那个「读者」

12.9c 的判词是「碎片写得进,没人读得出」。**12.9d 的使命 = 给碎片第一个生产读者**:检索结果水合时调用 `getImprintFragmentsByAnchor` ⇒ 它落地之日即 **c-3 触发器开门之时**(c-3 排在 12.9d 之后,已裁;c-3 的 TD-37 前置已清,⛔ 不再等 Henry)。嵌入**终选**收据(真实检索采纳,≥50 组标注集)仍延 V14——本段一切选型按**工作假设**申报,⛔ 不冒充终选。

## 一 · 三件交付物

1. **嵌入工序**:imprint_fragments → BGE-M3 向量(工作假设)。批量回填存量 + 增量钩子(新碎片入库后可嵌;触发形态 K-0 侦察后定,倾向显式跑批起步,⛔ 不上后台常驻)。
2. **向量存储**:倾向 SQLite 内表 + 暴力余弦(我们的规模是千级碎片,⛔ 不为此引向量库重依赖)——K-0 实测规模后可推翻,推翻须附数字。
3. **最小检索 API**(server route):query → 嵌入 → top-k → **经 `getImprintFragmentsByAnchor` 水合出带锚碎片**(出处链完整:碎片 id/指纹/锚/来源件)。⛔ 本段不做 UI,消费面是 API 本身 + 一个走查用的最小调用脚本。

## 二 · 法度(判据拆单时按「写动作」文法展开)

- **嵌入也是转写器**:每向量行记 fragment 指纹 + 模型标识 + 维度 + 归一化参数——「转写器身份=lockfile 指纹」同族适用;模型换版 = 新身份,⛔ 不许原地覆写;
- **分母义务**:嵌入覆盖率申报(总碎片/已嵌/跳过及其原因,分卷);
- **条款触发申报**:哪些设计条款本轮未走到,如实列;
- **运行时**:BGE-M3 本地推理;若需 sidecar,复用 MinerU sidecar 模式(并发闸/杀进程树先例);⛔ 云嵌入 API 不做默认(key 零出境红线);
- **锚可复放判据**:检索返回的每条碎片,其锚经水合能定位回源(排他半边配套);
- 门禁照旧:tsc/test:v2/docs:check/tech-debt 闸零新增。
