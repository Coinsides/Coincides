# 带锚碎片流(Anchored Fragment Stream)规格 v0

## §1 它是什么

拓印工序的**唯一合法产物**;一切转写器(无论哪家、哪族)的输出都必须对齐到本格式。存储真相;markdown/HTML 渲染一律是它的读时投影。⛔ 本格式不承载语义判断(「这是定义」之类归理解轨的候选,不进碎片流)。

## §2 碎片记录(JSONL,一行一碎片)

```
{
  "seq": 42,                      // 拓印内全序,顺序保真
  "text": "…",                    // 忠实文本,零消毒零改写
  "role": "para",                 // 结构角色(封闭枚举):heading|para|list_item|table_row|cell|slide_shape|caption|code_line|footnote|blank
  "anchor": { … },                // §3,必填
  "style": { … }?,                // 可选样式提示(加粗/级别),渲染用,不承重
  "lang": "en"?                   // 可选,检测值,候选性质
}
```

**不变式**:①`anchor` 必填(允许粒度降级但须在拓印件出生证申报 fidelity);②`seq` 连续且与原件阅读序一致;③`text` 与原件逐字,**或与原件逐字模一类已申报的归一化**(出生证 `text_normalization`;v0.1 修定,据 12.9a 第 1 场实证:Docling 归一标点)——⛔ 未申报的偏离一律违法(转写器的忠实性由回程票考卷验);④role 是**结构**描述,永不是语义描述。

## §3 锚(五族,封闭)

```
页面族   {"family":"page","page":7,"bbox":[x0,y0,x1,y1]?}          // bbox 单位:页宽高归一化 0-1
流式族   {"family":"flow","path":"h1[2]/h2[1]/p[4]","char":[120,180]?}  // path=结构路径;代码用 {"path":"file.py","line":[10,14]}
表格族   {"family":"table","sheet":"Sheet1","cell":"B7"}            // csv 用 {"row":7,"col":2}
幻灯族   {"family":"slide","slide":12,"shape":"shape_3"}
时间轴族 {"family":"time","ms":[61200,64800]}                       // 🅿 本期无生产者,形状预钉但不实现写入端
```

**fidelity 阶梯**(出生证申报):`region > block > page`(页面族)/ `char > element > section`(流式)/ cell(表格天然满格)。**低保真合法,伪造高保真违法**——没有 bbox 就不写 bbox,⛔ 不许编。

## §4 拓印件出生证

```
{ "source_id": …, "transcriber": {"name":"docling","version":"x.y.z","lockfile":"tools/…"},
  "anchor_fidelity": "block", "text_normalization": "none|punctuation|whitespace", "fragment_count": 812, "created_at": …, "warnings": [{"code":…,"anchor":{族锚,机械可扣},"detail"?:…}], "status":"accepted|rejected", "rejection_reasons"?: […] }
```

用途:换工具重拓可比对择优;锚粒度消费方可见;`warnings` 如实记(乱码页/空页/解析失败段——**残缺如实申报,⛔ 不静默跳过**)。

## §5 与既有体系的接线

- 存储:拓印件 = 层0 原件的派生物,挂 source_id;碎片流落库形态(单表 or 文件)由拆单时按现役 sourceArtifact 家族现物定——**先核现物再定表,不在本稿凭记忆点名机关**。
- 查重指纹:原件 sha256(入库即算)+ 碎片流内容指纹(拓印时算)。
- 收据:拓印是一次动作,留拓印收据(谁触发/哪个转写器/耗时)。
- T0 存量(现役 pdf/docx/xlsx 解析)**对齐本格式 = 12.9c 首单**,⛔ 不在 12.9b 顺手做。

## §6 Killer 方向(拆单时具体化)

K-1 逐字保真(v0.2):对参照全文**扣除已申报残缺区间后**施加**同一申报类**归一化后逐字节比对(机械非模糊;页面族允许布局重排申报);申报 none 而实测有归一 ⇒ 必红(伪高保真同条)。K-2 锚真实性:抽样碎片按锚回原件取文本,须命中(fidelity 相应粒度)。K-3 伪高保真必红:出生证申报 page 级而碎片带 bbox ⇒ 校验器拒。K-4 顺序保真:seq 乱序注入 ⇒ 必红。K-5 残缺申报:人为坏页 ⇒ warnings 非空且对应碎片缺席,⛔ 不得以空 text 碎片顶位。

**v0.1(2026-08-28)**:归一化纳入保真阶梯——与 anchor_fidelity 同形(低保真合法,不申报违法)。待探:转写器能否另给原始 glyph 文本(能则取更高保真,不阻塞)。

**v0.1 补(2026-08-28,2b 实证)**:**引用校验闸**——理解轨产物以碎片 id 作出处时,入库前机械校验 `id ∈ 该拓印件碎片集`,违者拒收。依据:引用制不消灭幻觉,**把幻觉从「坐标不准」(需裁图人眼判)变成「引用不存在的 id」(一行 in 判掉)——错误可判定性的差别,不是能力的差别**;2b 实测 2/9 虚构 id ⇒ 查的义务在门,⛔ 不靠模型自觉。副证:删掉坐标字段后 JSON 残缺同步消失——**让模型少造一样东西,连格式都稳**。

**v0.2(2026-08-28 夜,b-1 二停实证两洞,修宪)**:
1. **K-1/K-5 互斥解消——分工定义**:K-1 守**忠实性**(凡交付的文本必须逐字),K-5 守**申报性**(凡未交付的区间必须申报)。总不变式:**碎片拼接 ⊎ 已申报残缺区间 = 原件全文的分割**——K-1 比对范围=原件减已申报区间;**未申报的缺失仍 K-1 必红**(丢文本不申报=藏不住)。
2. **warnings 元素升结构化**:`{code, anchor, detail?}`——anchor 用**与碎片同族的锰形状**(机械可扣,才扣得动 K-1);原 `anchor_hint` 字符串降为 detail。**申报与碎片说同一种地址语言。**
3. **拒收与申报分族(修订此前「拒收留痕走 warnings 族」之裁——它欠定义)**:warnings=**已收之件的自我申报**(残缺类闭集,随件走);拒收=**未收之件的审判记录**——落在**出生证本身**:出生证得 `status: accepted|rejected`,rejected 时带 `rejection_reasons`(**validation 族新闭集**:fidelity_mismatch / anchor_invalid / fidelity_overclaim / order_violation …),**碎片不落库**。出生证就是那次拓印尝试的收据——拒收也有收据,但两族 code ⛔ 永不混用(把未发生的解码失败写进申报=伪造申报)。

**v0.3(2026-08-29 凌晨,b-2 一停实证,修宪)**:
1. **申报住所总原则(统一三处落点)**:**申报住在被申报物身上**——描述拓印产物的申报住出生证 warnings(残缺族);描述拓印尝试被拒的住出生证 rejection_reasons(validation 族);**描述文件本身的住**文件层 `source_files`**(intake 申报族,新闭集;v0.3.1 精确化——后缀/魔数/编码描述的是文件非整条记录,落文件层才真叫住在被申报物身上)。
2. **二进制兜底采 (C)「只存不拓」字面义**:不产拓印件⇒无出生证无 warnings——intake 申报落 source 记录层。此前「拒收留痕走 warnings 族」之裁**限缩为拓印件层适用**(第三次修订自裁,就地记)。⛔ 锚族不加 whole_file(为从未出生之物造出生证=假身份);⛔ 锚不许置空(毁机械可扣性)。
3. **intake 申报族闭集 v1**:`unknown_extension` · `signature_mismatch` · `non_utf8_text` · `nul_bytes` · `binary_unparsed`——三套闭集(intake/残缺/validation)各守各层,永不互串。
4. **mime_extension_mismatch 在永不拒收射程内**:改判为收下+申报;**归族以魔数为准,后缀是自称**——字节是事实,名字是主张;不符即按魔数归族并申报 `signature_mismatch`。

**v0.4(2026-08-29 凌晨,b-2b 重对现物实证,修宪)——容器条目申报四裁**:
1. **住所**:容器条目按结局分两类,各归各家——**成为了件的**,条目即子件,其申报(解码回退等)住**子件自己的** `intake_declarations`,与顶层文件同闭集同形状,⛔ 无特殊化;**没能成为件的**(上跳被拒 / 解压失败 / CRC 坏 / 加密不可读),无件可挂,申报住**容器件自己的** `intake_declarations`。依据有二:(a) 该观察是**容器的性质**(坏 CRC 条目 = 坏 zip,上跳条目名 = 畸形 zip),且正是在容器自己的入库-展开过程中被观察到——住被申报物身上,一条原则推到底;(b) 永不拒收下**容器 blob 全量在库,失败条目的字节并未失去监护**——它们还躺在容器原件里。申报是诚实标记,⛔ 不是监护替身。
2. **intake 闭集 v1 → v2:只加一码** `container_expansion_incomplete`(部分条目未成件,或整包不可开=全部未成件)。⛔ 不设 `container_entry_*` 按因分码——闭集是**文件性质词表**,按失败原因增殖会让它随每种容器格式膨胀;**原因粒度是 detail 不是 code**。空包 ≠ incomplete(空是完整的空,零申报)。
3. **账目机械可查靠推导,⛔ 不建失败条目台账**:失败条目集 = **容器蓝图**(zip central directory,就住在已存 blob 里)**− 成功子件集**——内容可从已存原件推导之物,建表存它 = 形状先于能力(与「只存不拓」同构:不为可推导物造第二存储)。code 的作用是**免开包触发器**:无此码的容器,「子件 = 全部内容」可信;有此码的,对账须开包。
4. **对施工的硬前提(集合差可算的代价)**:子件必须带出处二元组 `(container_file_id, entry_path)`;重名条目以 entry_index 区分,⛔ 不得合并——否则蓝图减子件的集合差不可算,第 3 条的机械可查性塌掉。**(⚠️ 本条为 v0.5-1 所修订——它把出处误当身份,见下。)**

**v0.5(2026-08-29,b-2b 一停实证,修宪)——去重与出处相撞案两裁**:
1. **件/出处分层(修订 v0.4 ④,自裁记档)**:b-2b 一停暴露 `UNIQUE(user_id, content_hash)` 与「重复条目⛔不得合并」正面相撞。**病根在 v0.4 ④ 是我把【出处】写成了【身份】**:「同字节=同件」是**内容身份**(b-2 已落之法,⛔ 不动,UNIQUE 保持);「条目→件」是**出处关系**(多对一:zip 里两份同字节讲义 = **一个件,两笔出处**)。⇒ **对账等式移到条目层**:∀条目 ∈ 蓝图:(提取→hash→命中件 ∧ 可归为成功)⊎(归为已申报失败);容器带码 ⟺ 失败集非空。件层数目**不参与**等式(N 条目 1 坏 2 同字节 ⇒ 件 +2 **非** +3,而账仍全平)。**出处关系与失败集同律:皆可从已存 blob 重推导,⛔ 皆不建表**——蓝图本身就在 blob 里,查账必开包,开包即得全部出处;为可推导物建出处台账 = 违反本宪 v0.4 ③。原 K-6「合并即红」**撤销**,代之以**同字节双条目 fixture**:钉住条目层语义(3 成功条目 → 2 件,账平;且件数断言 +2,**去重被破坏反而必红**——裁定的反例)。子件⛔不加 container 出处列(推导可得;第一个需要反查「此件来自哪些容器」的消费者单,自带索引与其守缝之刀)。
2. **detail 缓期(v0.4 ② 精确化)**:「原因粒度是 detail 不是 code」是**住址裁定,不是存在裁定**——它说的是原因**若被记录**该住哪,⛔ 不是命令现在就记。载体保持 `string[]` 不动;失败原因可从 blob 重推导(同一确定性解包器,同因重现),**有消费者前不持久化**。演进触发器:第一个要向人/Agent 展示失败原因的单,届时载体演进为兼容旧字符串的 `{code, detail?}`,并自带迁移与守缝之刀。
3. **附记**:闭集第六码不需迁移(码是字符串值,列已存在);b-2 五码精确断言随扩集显式改动(那道摩擦是设计意图,扩允许面即可)。**容器删除时子件的生死是悬案**,⛔ 本段不裁——记 12.9c 库治理开题。

**v0.5.1(2026-08-29,b-2b 复核假申报案,精确化)——条目名解码回退不是申报事项**:
1. **⛔ 给内容寻址物挂出处域事实**:子件由内容寻址(同字节=同件),条目名及其编码是**出处域**事实——挂子件则同内容经「净名条目」与「CP437 名条目」两路到达时,码之有无取决于到达顺序 ⇒ **申报不可判定**。此为不可救药的类型错(码挂容器则可判定但可推导,见下)。
2. **申报义务的判定标准(通例,两问)**:**证据会被消化吗?决策依赖它吗?** 条目名原始字节与 UTF-8 标志位就躺在已存容器 blob 里,回退解码是**读时投影**,确定性可重推导——证据未消化;且无任何收/拒决策依赖它。两问皆否 ⇒ **无申报义务**(jszip 案两问皆是:失败集分类【决策】依赖被静默改写【消化】的条目名——故彼案否走此案行,同一标准两个答案)。⛔ 不加第七码,⛔ 不动 `non_utf8_text` 语义(它仍且仅指**文件内容**非 UTF-8)。
3. **K-4 反转为反例刀**:暴露假申报的那个 fixture(CP437 名条目 + 完美 UTF-8 内容)自己变成禁止假申报的刀——断言子件申报**必须不含** `non_utf8_text`;行为面保留(回退解码确定性、子件照建、内容无损)。**名字是礼貌标签,字节是事实**——v0.3 ④ 的老法,在条目名上再次适用。

**v0.6(2026-08-29,c-0 重对现物「两不变式相撞」案,修宪)——归一化从标签升格为可重放函数**:
1. **先正法源**:§6 K-1 自 v0.2 起基准即为「参照全文扣除已申报残缺区间后,**施加同一申报类归一化**,逐字节比对」——申报归一化投影作基准**本来就是法**;b-1 的 `join('')` 裸比对是 `none` 类的特例实现,⛔ 不是法的全部。两不变式(③逐字/④角色)不冲突:**③ 的「逐字」从来允许「或已申报的归一化」**。
2. **申报的不是标签,是可重放函数**:`text_normalization` 的每个类必须存在**确定性、可重放、与校验器共享、版本钉死**的规范化函数(canonicalizer;版本随转写器身份 lockfile 钉入出生证)。校验器执行 `join(碎片) === canon(参照 ∖ 已申报残缺)`。⛔ 校验器不得重放转写器的**分段/角色**逻辑——只重放文本规范化;吞段发生在分段层,故重放规范化不构成自我印证。
3. **白空间保全元不变式(吞段可抓性的承重梁)**:`whitespace` 类合法的充要条件 = 机械可证**仅动空白**:`nonWS(canon(x)) === nonWS(x)` 为常驻元检(配自己的 killer:令 canon 吞一个字母 ⇒ 元检必红)。由此定理:**碎片丢失任何非空白字节必被 K-1 抓住**——吞段可抓性由元不变式保证,⛔ 不靠归一化函数的自觉。**v0.6.1 补(c-0 拆单实测)**:canon 定为**剥离全部空白**(折叠为单空格救不了段间空行被丢的合法场景,c-0 实测);⚠️ **类保证如实记**:`whitespace` 类保证的是**非空白字节序列保全**,**词界不在保证内**(词间空格被吞在此类下 K-1 不可见)——绿的含义止步于此,⛔ 谁引 K-1 的绿断言「空白也对」即越界;若将来有消费者需要词界保全,另立更细类(演进触发器同 detail)。
4. **c-0 采 (A)(复用 `sourceArtifact`:结构角色 + 页锚,申报 `whitespace` + `anchor_fidelity: 'page'`)**;(B) 否——扔掉角色与页锚去保段间空行,是买没有消费者的保真;(C) 否——**原件在库,逐字真相永可重推导**,为可推导物另建保真链 = 形状先于能力(v0.4 ③ 推到底)。**校验器的 `whitespace` 类支持与第一个申报它的生产者(c-0)同单落地**——闸与生产者同生,第三次适用。

**v0.7(2026-08-29,c-0 一停四冲突案,修宪)**:
1. **page 族锚形状扩为 `{page_index, block_index}`**:block_index = **分段器给出的同页内序数**(确定性、可重放),仅作同页消歧;**fidelity 仍是 `page`**,⛔ block_index 不声称任何几何精度(声称即伪高保真,K-3 同罪)。锚唯一性法(:422)在二元组上成立。一页一碎片方案否(丢 role/seq 一一映射 = 丢 c-0 的价值);PDF 退 flow 方案否(丢页码 = 丢 PDF 的价值)。
2. **每格式一拓印件,单锚族法(:437)保持**:PDF → `page` 族;DOCX/TXT/MD(page_index 全 null)→ `flow` 族(locator 自带 block_index)。锚族随格式的**真实定位能力**走,⛔ 不迁就统一形状。
3. **page 类 K-1 参照物 = 分段层上游的整页原始文本**(解析器在 split 之前持有的 per-page 文本,连接后经申报类 canon 与 `join(碎片)` 比对)。**自我印证边界精确化(承 v0.6-2)**:参照必须取自分段层**上游**,⛔ 不得由碎片回造(join(blocks) 回造 = 自证,明禁);K-1 守的正是分段层的吞段。**库级共盲**(解析器本身漏字)如实申报为此参照的极限——⛔ 不冒充已验,其对手是 c-2 双拓互证(债的落点认第一个生产者)。
4. **接点裁定(教义执行面)**:拓印写入住 `sourceMaterialization` **工序本体**——「拓印属征用工序」由工序自己保证,⛔ 不靠每个调用方记得传 `afterParse` 钩子(调用方必须记得 = 会被忘的文档,门不会忘);钩子留作仪表/测试位。⛔ intake 接点明禁(入库即拓印 = 工序前移,教义级违反)。

**v0.7.1(2026-08-29,c-1a 两半刀实证,措辞钉死)——转写器的身份是 lockfile,不是版本号**:实测 `uv lock --upgrade` 后顶层包版本纹丝不动(mineru 3.4.5)而五个传递依赖已漂——**出生证如实写 `transcriber_version` 也标识不了环境:版本号没有说谎,它只是不足以标识**(同名不同物)。⇒ 身份三元组的**承重者是 lockfile 指纹**(内容 hash,机械可比对);`name`/`version` 降为**礼貌标签**(检索与人读用)。**「名字是礼貌标签,字节是事实」第三次适用**——后缀自称(v0.3④)、条目名(v0.5.1)、版本号(本条),一条法理三处落点。校验两转写产物「同一转写器」⇔ lockfile 指纹相等,⛔ 版本号相等不构成同一性证明。

**v0.7.2(2026-08-29,TD-36 两问裁定)——指纹承重件的形制**:
1. **指纹算法 = 原始字节 sha256,⛔ 无任何归一化**:格式化/行尾改动导致指纹不同 = **保守判「未证同一」**,方向安全(错也错在不轻信);解析包集合方案否——为买不需要的宽容引入两个解析器(uv.lock TOML / package-lock JSON),每个都是新的出错面。配套:pin 文件在 `.gitattributes` 标 `-text` 钉住字节(防 autocrlf 搅动指纹)。**落点更正(48 实测纠偏,+2616 字节 checkout 实证)**:此条⛔不得晚于 pin 三件入库——伤害发生在提交那一刻(checkout 往返即污染),故 `.gitattributes` 与 pin 同批提交,且 K-2 须走 **checkout 往返后重验**(「逐字节一致」两义:此刻一致 ≠ 活过 git 往返)。
2. **既有行⛔不回填**:今日指纹 ≠ 落库当时的,且当时工作树状态不可考——按 commit 取回是**看起来对的错答案**(行的写入时刻与树的状态无法逐行对应)。既有行 hash 置 NULL = **「前指纹时代」的如实申报**;新写入自 c-1b 起服务层强制非空(常驻测试:无 hash 的新拓印必拒)。**空得诚实,胜过填得体面**——与「⛔ 不许假装能回填」同判。**运行时语义(c-1b-0 落地注)**:`NULL` 指纹**不判同也不判异,是「未证」**——判同要求两侧皆为合法指纹;未证按不轻信处理。**v0.7.3(c-1b-1 一停实证)**:**身份⛔不得有共享默认值**——每个转写器**显式申报**自己的 lockfile 与指纹;未申报者**拒写出生证**并落 failed,⛔ 不回退到任何公共 lockfile(共享默认 ⇒ 不同转写器同指纹 ⇒ 「身份=指纹」被默认值从内部绕过;**一个错得合理的默认值比没有默认值危险——它让「忘了申报」看起来像正常工作**)。

**v0.7.4(2026-08-29,c-1b-2 拆单前置侦察,修宪)——表格锚的族界**:**锚答「在哪」,角色答「是什么」**。PDF 表格单元格的诚实地址是几何的(该页该矩形)⇒ **住 page 族,region 保真 + 归一化 bbox,每单元格一碎片**,同页消歧沿用 block_index;其「表格性」由 role 表达,⛔ 不由锚族表达。`table` 族限于**以表为原生坐标系的格式**(sheet/row/col 是其真实定位能力;`sheet` 字段必需即其证据)——xlsx/csv 归它,PDF ⛔ 不归。TD-30「单元格可寻址」判据不变且仍用寻址动作验(按 bbox 回原件取矩形内文本命中);「table 族锚现身 page 族拓印件必拒」保留为本条的常驻证明。**归一化基准:⛔ 只许用转写器自报的 page_size**,与媒体框的比例偏差如实申报(1.0005/1.0011 在案)——**拿别的尺寸凑 = 在坐标系上撒谎**。附:巨表的每单元格一碎片粒度若成负担,粒度演进随第一个受害消费者单走,⛔ 本段不预设。**自证边界的几何维(c-1b-2 拆单实证)**:**锚真实性的验证源必须独立于锚的生产者**——⛔ 不得拿 MinerU 的 span 证 MinerU 的 bbox(v0.6-3「不重放分段逻辑」在几何维的同形);region 寻址验证以独立文本层读取器(pypdfium2)为源,故 K-1 fixture 必须用**有文本层**的真件(image-only 件上无独立源可用——**两张单要的 fixture 性质正好相反**)。归一化越界必须被 `anchor_invalid` 拒,⛔ 不许 clamp 掩盖——clamp 把越界变成看起来合法的坐标,是坐标系上的另一种谎。

**v0.7.5(2026-08-29,c-1b-2 builder 停线实证,修宪)——单元格几何不可达案三裁**:
1. **锚真实性判据补排他半边**:按锚取回须**命中该碎片文本 ∧ ⛔ 不得包含同拓印件其它碎片的独有文本**——「包含」型验证天然被更大范围平凡满足(整表 bbox 让每个 cell 的命中断言平凡通过);**凡验定位,必配排他,否则验的是「在不在里面」不是「在哪」**。
2. **MinerU 单元格几何记「本转写器不可达」,采「做得少」拒「说得假」**:实证 cell bbox 在 MinerU 内部算出、落盘前被丢(`batch_analyze.py:684` 仅取 `.html`)。①共享整表 bbox 给 cell = 伪高保真(K-3 同罪)⛔;②静默补丁保字段 = **打补丁的运行时不再是 lockfile 所描述的转写器,身份指纹说谎**(违 v0.7.2)⛔;采 ③:**表级碎片带真实整表 region 锚 + 结构化 cell 文本**,单元格级几何寻址**如实申报不可达**。**「做得少」可以如实申报,「说得假」不能——保真阶梯的全部意义就在这一句。**
3. **TD-30 诚实拆分**:表级可寻址(本单交付)⊕ 单元格级几何寻址(不可达,挂触发器)。触发器三出口:换用给 cell 几何的转写器 / MinerU 上游把 `cell_bboxes` 纳入标准输出 / **补丁版以独立转写器身份申报**(自带 name+补丁指纹入 lockfile——② 的唯一合法形态,⛔ 静默补丁永禁)。债的移动不是失败——**债跟着真实生产者的真实能力走**。
3. **列名处置**:加 `transcriber_lockfile_hash` 承重;既有 `transcriber_lockfile` 路径列**不改名**(SQLite 改名 = 重建表,为正名付重建不值),**在法上降为定位用礼貌标签**,本条即其正名记录。**字段名自称 = 「名字是礼貌标签,字节是事实」第四处落点**(后缀/条目名/版本号/字段名)——本次是法理回咬立法者自己的 schema,收录。
