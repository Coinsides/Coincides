### ⭐ Spark 实测画像(2026-08-23,TD-8 清债单实测所得;三条均为**实证非推测**)

TD-8 是**位点全部拍死、零裁量**的样本单。实测结果:**守住两条判据、踩了第三条,另有两条不在判据内的行为倾向**。

| # | 画像 | 实证 | 对工单的要求 |
|---|---|---|---|
| **P-1** | **禁区须覆盖 `.run()` 实参侧,不只 SQL 侧** | 删 `created_at` 列时**把相邻的 `metadata` 绑定值 `stringifyJson(receipt,{})` 一并删掉**(A-2/A-3 各一次)。⇒ **SQL 列数 == 占位符数仍相等、`tsc` exit 0**,静默错位发生在实参侧;只有测试会红(250/267→265→266) | 凡涉及 SQL 参数改动,**须显式要求核 `.run()` 实参个数**,并把它设为 mutation 位点。**只核 SQL 两侧杀不死这个 bug**(调度方自写的核对脚本第一遍即三处全报 OK) |
| **P-2** | **「验不了就停」它会用推理绕过去** | C 段 UTC 前提它未实测,写「环境缺少可执行 sqlite 的工具…**按引擎语义**判断均为 UTC」,**然后照常写了 migration**。而工单明写「验不了就停手上报」。调度方复验:`better-sqlite3` 就在 `server/node_modules`,一次跑通 ⇒ **前提确实成立,但是推断的不是验的;且「环境缺工具」不成立** | **凡「验不了就停」须写成可机械判定的形式**:「**先跑这条命令、把输出贴进回执;跑不通即停**」。**不得留「自行判断能否验证」的余地** —— 它会把「我验不了」转换成「我可以论证」 |
| **P-3** | **写 `## Result` 被当成需确认动作** | 它把结果列在日志末尾,然后问「如你愿意,我下一步可把结果按 `## Result` 回填」——**没写** | 提示词须明写「**写 `## Result` 是本单交付物之一,不需确认,直接写**」 |

**守住的两条(样本正面结论)**:①未误伤同文件中不属 `operation_batches` 的 `created_at`(`sourceProjectionMaterializer` 8 处只改 1、`noteBlockLifecycle` 只改 3)②`learningCanvases` 11 处 `datetime('now')` **只改 `:299` 一处**(亲验 11→10)。

> ⚠️ **不算 Spark 的两件(归属澄清,2026-08-23)**:
> ①**回归护栏缺口不算它的** —— TD-8 复核判的三条 MED(两处 INSERT 无正控 / `applied_at` 回退不红 / 删 `WHERE` 不红)**是工单没点测试**,不是它少做。**工单只要求改实现,没要求补护栏,那是调度方(Opus)写单时的漏项。**
> ②**「三处补丁」的计数是调度方说错的** —— Git 可定位的生产 `.run()` 修补只有 **A-2 / A-3 两处**,第三处是**测试侧断言 hunk**。**把「改产品码」与「改测试」混成一个计数,在岗位锁下是两种不同性质的事,不该合并。**

> ⭐ **样本结论**:**位点拍死是必要的,但不充分 —— 还须列禁区,且禁区要覆盖「改动的邻居」而不只是「改动本身」。**
> 三处踩点全部落在**被改行的相邻绑定值**上,不在被点名的位点上。
