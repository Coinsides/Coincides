# V12.9b 段计划:腰与底盘

**段目标**:带锚碎片流从规格变成库里的真东西——一切插头的插座,先于所有插头。**⛔ 本段零转写器接入**(那是 12.9c),本段只造「接住任何转写器产物」的地基。

## 单序(串行,b-0 先行)

- **b-0 现物核实单(只读,派 Opus 或自做)**:①现役 `sourceArtifact`/`documentParser` 家族的存储形态与消费者清点(碎片流落库选表还是文件,**按现物定,⛔ 本计划不预设**);②`source_id` 身份链现状;③查重指纹现状(有无 sha256 落库);④出参形状被谁消费。产出:b-1 的落库形态裁定材料。
- **b-1 碎片流 schema 落地 + 拓印件出生证**:按规格 v0.1 建碎片流存储 + 出生证(transcriber/version/anchor_fidelity/text_normalization/warnings);killer 按规格 §6 K-1~K-5 具体化(K-1 逐字保真模申报类、K-3 伪高保真必红、K-5 残缺申报)。
- **b-2 入库永不拒收 + 两兜底**(⚠️ **2026-08-28 瘦身:容器策略已拆出为 b-2b**;单 `handoffs/2026-08-28-v12-9b-b2-never-reject.md`):任意字节可入散沙层(存原件+sha256+按名可发现);文本兜底(未知后缀可判文本 ⇒ 纯文本碎片,行锚)/ 二进制兜底(只存不拓)。
  - ⭐ **开头钉句(Fable)**:**⛔「永不拒收」≠ 删掉那三道 `throw`;是改判不是拆闸 —— 拒收改为「降级收下 + 如实申报」。三道闸的原拒收理由必须保留为申报字段:降级的证据链就是那些原拒收理由。**
  - ⭐ **工作量如实缩水(b-2 预读实测)**:三道拒收闸全在 `sourceFileIntake.ts`(`:279` 后缀白名单 / `:295` 签名比对 / `:305` 文本编码);**两条兜底都有现成判定器可复用** —— 文本判定用现成的 `TextDecoder('utf-8',{fatal:true})` + NUL 检测,二进制判定用现成魔数嗅探与流式 `hashFile`。**主要动作是「把判真伪的判定器改用为判归类」,不是从零写。**
  - **killer 五条**,其中 ⭐ **K-5 回归锁最重**:12 种已知后缀的既有行为逐一不变,**expected 须为改动前捕获的死值**(改判最容易的事故是把已知路径弄坏)。
- **b-2b 容器策略(zip / 文件夹)**(⚠️ **2026-08-28 从 b-2 拆出**,因为它含一个**采购决策**,混在施工单里会卡住整单;单 `handoffs/2026-08-28-v12-9b-b2b-container.md`):解包 + **目录作出生语境逐件归族**。
  - **采购裁定(Fable,证据 `analysis/2026-08-28-v12-9b-b2b-zip-probe.md`)**:**`yauzl@3.4.0` + `decodeStrings: false` 档**。
  - ⭐ **jszip 被教义一票否**:它把上跳条目名**静默改写**(`..` 那条目被拆成根目录条目 + 去掉上跳的文件名)⇒ **应用层拿不到「该条目试图上跳」这条事实,无法申报**。**「不炸,但投毒无痕」比响亮的崩溃更差。**
  - ⭐ **「坏 zip 不炸整批」的完整形态 = 把永不拒收施加到容器内部**:**每个条目独立受审**,好条目照收、坏条目降级 + 申报,**申报的证据 = 原始条目名原样在案**。
- **b-3 引用校验闸：⚠️ 已移出本段(2026-08-28 裁,理由见下)**：无生产者(引用碎片的理解轨产物一个不存在;现役提案引旧链)——**给没人走的门装锁=形状跑在能力前**;与 K-2 裁定同理(验证者需要真对手)、与 get_relation 退列同形。⛔ 也不留预留接口(预留位禁令)——**法住在规格里**(spec v0.1 引用校验闸条款不动)，**闸与第一个生产者同单落地**(12.9c/d 入场条件：谁先引用碎片，谁的单里带这道闸)。
- **b-4(文档面)**:词典「转写/碎片/拓印」现状栏更新;程序表 §2 状态刷新。
