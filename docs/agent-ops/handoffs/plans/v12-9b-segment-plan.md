# V12.9b 段计划:腰与底盘

**段目标**:带锚碎片流从规格变成库里的真东西——一切插头的插座,先于所有插头。**⛔ 本段零转写器接入**(那是 12.9c),本段只造「接住任何转写器产物」的地基。

## 单序(串行,b-0 先行)

- **b-0 现物核实单(只读,派 Opus 或自做)**:①现役 `sourceArtifact`/`documentParser` 家族的存储形态与消费者清点(碎片流落库选表还是文件,**按现物定,⛔ 本计划不预设**);②`source_id` 身份链现状;③查重指纹现状(有无 sha256 落库);④出参形状被谁消费。产出:b-1 的落库形态裁定材料。
- **b-1 碎片流 schema 落地 + 拓印件出生证**:按规格 v0.1 建碎片流存储 + 出生证(transcriber/version/anchor_fidelity/text_normalization/warnings);killer 按规格 §6 K-1~K-5 具体化(K-1 逐字保真模申报类、K-3 伪高保真必红、K-5 残缺申报)。
- **b-2 入库永不拒收 + 两兜底 + 容器策略**:任意字节可入散沙层(存原件+sha256+按名可发现);文本兜底(未知后缀可判文本⇒纯文本碎片,行锚)/二进制兜底(只存不拓);zip/文件夹解包=目录作出生语境逐件归族。killer:未知二进制入库成功且不产碎片;坏 zip 不炸整批。
- **b-3 引用校验闸**:理解轨产物引用碎片 id 的入库校验(`id ∈ 该拓印件碎片集`,违者拒收留痕)——2b 实证的那道门。killer:虚构 id 必拒且拒收有收据。
- **b-4(文档面)**:词典「转写/碎片/拓印」现状栏更新;程序表 §2 状态刷新。

## 边界

⛔ 不碰 MCP 工具面(读碎片的 Agent 门归 12.9d 检索地基一并裁);⛔ 不动现役 parser 行为(T0 对齐归 12.9c,TD-29/30 落点在彼);⛔ 不接任何真转写器。**本段全绿判据:一份手造碎片流(fixture)走完 存→出生证→校验→按锚取回 全环。**
