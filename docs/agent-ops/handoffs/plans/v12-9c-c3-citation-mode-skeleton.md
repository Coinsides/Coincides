# c-3 · 识别器引用模式 —— 规格骨架(含归域裁定)

## 〇 · 定位:三级火箭第 3 级

识别器(qwen-vl-max @ dashscope-intl,同一把 116 位 key)从「转写者」转为**「引用者」**:对文档内容的表述**引用既有碎片**(fragment id + 锚),⛔ 不重新转写正文。门已开:检索水合是第一个生产读者,识别器引用是第二个——两者共用同一条锚复放链。

## 一 · 归域裁定(c-2 挂起项,今裁)

c-2 三域资产的消费方式,按「点射预算只烧真分歧」原则:

1. **存在性差异(175 张收据)→ 按尺子域处置,零点射预算**——本体多为页眉页脚整条带、方向均衡(101:74),属转写器收录约定差异。**但带一条例外闸**:引用校验闸遇到被引碎片落在存在域收据集合(单边碎片)时,**标注「单证」(uncorroborated)**——只标不拒,标注随引用结果透传给消费者。廉价的注解,不是预算黑洞;
2. **分类学差异(211 条,92% 为 text×list)→ 尺子域,零预算**——角色分歧不影响引用有效性(引用认锚+文本,不认角色);角色对频次矩阵留作将来转写器选型资产,⛔ 本段不消费;
3. **真实指错(④类)→ 置信域,点射预算唯一去处**——基数从 v3 census JSON 读出④类实际条数(拆单 K-0 必做),点射复核只对着它设计。
4. 附:**c-2 持久层解锁条件更新**——c-3 收口时须申报「点射消费形态」(置信度 per-fragment 还是 per-imprint、谁读它),持久层据此开单;⛔ c-3 本段不建持久字段。

## 二 · 三件交付物

1. **引用模式契约**:识别器的输入=页范围碎片清单(id/锚/文本),输出=引用式表述(每条断言附 fragment 引用);prompt 契约冻结(口径冻结早于实现);
2. **引用校验闸(与引用者同单,b-3 遗训)**:机械三验——被引 fragment 存在于**现役 lockfile**(⛔ 跨转写器引用)→ 锚可复放(复用 d-2 水合链)→ 存在域单证标注;违约=该条引用判废并入台账,⛔ 静默放行;
3. **实验层验证**:四卷各抽页实跑(预算硬闸:调用数/字符数上限随单冻结+预检),产出引用质量台账(有效引用率/判废清单/单证率,分卷申报)。
