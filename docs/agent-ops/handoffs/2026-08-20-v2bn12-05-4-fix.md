#### 05.4-HIGH-1 — response fence 被当作 OCC，合法编辑可静默丢失

`useNoteCanvasDataAdapter.ts:479-503` 在成功 hydration 时推进 epoch、换入hydrated blocks并清空 plain/TextFlow/field drafts。`saveBlock` 在 `:1194-1205` 冻结 epoch，但 PUT 已在 `:1227-1230` 发出；跨 epoch 后：

- 成功响应在 `:1231` 直接 `return null`，不收敛本地block/draft；
- pre-commit reject在 `:1246` 同样先 `return null`，跳过 `:1247-1248` 的error/toast；
- `finally` 在 `:1251` 因“不再current”不清 `savingBlockId`。

普通 Text/Code/Formula 保存经 `NoteWritingSurfaceLayer.tsx:3720-3727` 与各projection/`BlockEditorLayer` 把 `onSave` 当作 `void` 使用，既不await也不解释 `null`。因此 `null` 只在少数显式await的内部调用者可见，对正常打字用户不可观察。

Reviewer在隔离clone构造：用户正常编辑→blur触发并hold block PUT→成功同-note hydration返回server旧block→held PUT pre-commit reject。实际稳定为：

- receipt=`null`；
- durable仍为`server old`，UI也已换回`server old`；
- plain/TextFlow/field drafts已清，合法`user edit`无恢复载体；
- `console.error`、error toast均为0；
- `savingBlockId`仍为该block。

最终恢复/可观察性合取 `durablePreserved || localDraftPreserved || userObservedReject` 为 `false`，reviewer probe在唯一承重断言精确红。若held PUT成功，server路由又没有revision/`If-Match`，客户端仍会静默 `null`，形成durable/UI分叉，并不能阻止旧body覆盖hydration看到的新truth。

当前production没有周期性same-note refresh入口；现有常驻case通过load dependency identity触发第二次hydration。但“成功同-note hydration”正是05.4明确申报并要求支持的状态转移，本轮按该验收模型判定，不外推为当前已有定时刷新。

修复不能只把 `null` 改名。至少需要让普通编辑面可消费discriminated outcome，跨hydration时保留pending edit/recovery receipt，失败可观察且operation-local saving token必须收束；已发出的PUT还需要read-after-outcome/conflict reconciliation。若要称durable OCC，则需server revision条件写，而非只有client response fence。

### 4. R2 durable rollback与failure-order语义

`useSlashBlockRollbackController.ts:133-142` 先启动普通annotation/TextFlow persistence，同一调用栈在 `:144-183` 独立启动block save；两条promise各自catch，block路径不等待annotation promise。`durableOutcome` 只描述block正门：

- block receipt=`null`或promise reject：均报 `durableOutcome: unknown`；
- block不存在：block PUT=`0`并报 `durableOutcome: not_attempted`，但此前启动的annotation promise仍继续；
- annotation reject：独立报 `annotation_save_failed`，不取消或阻塞block save。

Reviewer-only乱序probes亲跑 **3/3 GREEN**：

1. annotation先reject，block promise held；先收到精确annotation error，随后释放block成功，block未被取消；
2. block先reject，annotation promise held；先收到精确block `unknown`，随后释放annotation成功，annotation未被取消；
3. missing block：精确 `block_unavailable / not_attempted`、block save=0，但annotation save=1。

这与 `tech-debt.md` TD-6 的普通编辑双资源非原子基线一致，不把已知半提交重新判成05.4新HIGH。缺口是常驻13-test suite只承重“不等待”、block null/reject；没有上述annotation failure与双向完成序，也没有精确锁住`not_attempted`只指block，故列MED-1。
