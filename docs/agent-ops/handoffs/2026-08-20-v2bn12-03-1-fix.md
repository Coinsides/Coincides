### 1. Findings（按严重度）

#### MED-1 — R4 的 session canonicalizer 在多 PageFrame/旧 receipt 状态下仍会选错 owner [技术缺陷][恢复路径][D1×D2][状态转移后]

但 production owner resolver 的更宽状态没有闭合。隔离 reviewer probe 只为调用私有 resolver 临时加了一个 `export`，未改逻辑，三个负例均稳定转红：

1. **Canvas 选过 secondary 后切 Page。** Page viewport 与可交互 DOM 实际绑定 primary（`useNoteCanvasLayoutModel.ts:174-208`；`NoteWritingSurfaceLayer.tsx:3275-3330`），surface toggle 不重置 PageFrame selection（`useSurfaceModeController.ts:25-31`）。但 `findPageFrameForLayout` 按 `layout.frame_id → authority.frameId → selectedFrameId → primary` 取 owner（`useRuntimeNaturalWritingController.ts:45-56`）。probe 的 visible owner 为 `visible-primary`，当前 captured/receipt owner 却均为 `canvas-selected-secondary`。
2. **PageStack move/append。** `createDraftLayoutAtFrameStart` 只改 `x/y/width`，没有把 plan 的 `targetFrameId` 写进 layout/authority（`pageStackContentFlowService.ts:62-73,134-153`）。runtime 先请求 focus/save 新 frame，随后在同一旧 render closure 里立即 `activateDraft(plan.targetLayout)`（`useRuntimeNaturalWritingController.ts:234-256`）。已有 F2 的 move probe 期望 receipt owner=`target-frame-b`，实际 `targetLayout.frame_id=null`、captured/receipt owner 都是旧 `owner-frame-a`；append 新 frame 时旧 collection 甚至不含新 frame，风险更确定。
3. **修复前已经排队的 raw v1 receipt。** storage key 与 receipt 仍是 v1，`listDraftRecoveryReceipts` 仅 blind cast，没有 shape/version upgrade（`draftBlockPersistence.ts:13-48`）；mount replay 直接进 adapter base finalizer（`useNoteCanvasDataAdapter.ts:932-989`），不经过 runtime canonicalizer。probe 经真实 `finalizeDraftRecoveryReceipt → buildLayoutPayload` 后，期望 `x=72/canvas_world/frame=visible-primary`，实际仍为 `x=0/page_frame_local/frame absent`。
