# 走查修六 · F11-B + F12

## F11-B · 陈旧/死 frame_id 的保存期重落籍

**症状**:修五(写时自愈)落地后,Henry 真机直接拖块**仍**报 "Failed to save block layout";绕 Staging 一趟仍能逐块治愈。

**根因假设(HQ,builder 须先合成复现红,⛔碰真库)**:笔记**有**持久化页框集合,但块的存量布局(或据其生成的拖拽草稿)携带的 `frame_id` 指向**集合里已不存在的帧**(历史上集合被替换/重建)。`normalizeBlockLayoutForSave` 的早退分支(frame_id 为真)→ `requireStoredLayout` → frames 里找不到该 id → 抛 "A resolved page frame is required..."。修五只治"没集合",不治"错帧章"。旁证严丝合缝:tray-out 会给块盖**现行有效**的帧章,故绕道逐块治愈;渲染端 `selectPlacementFrame` 找不到帧时按 frameless 渲染,所以屏上一切正常、保存必炸。

**修法(HQ 已裁,⛔复议)**:

1. 保存边界(v2):`layout.frame_id` 不在现行 frames 中 → **剥掉死 id,走既有几何落籍路径**(最大重叠 → primary 兜底 → **新增:首帧最后兜底**——primary/stack 指针悬空时不再无帧可落);修正后的 frame_id 随本次保存写回=逐块永久治愈;
2. **零跳变铁律**:渲染端对死 id 本就按 frameless 处理,故落籍以当前屏幕矩形重算即天然零跳变——逐像素断言之;
3. ⛔ 对**有效** frame_id 的布局零行为变化(payload 逐字节不变);⛔ 松动 v2 契约(落籍后仍无帧=照抛;修五自愈在前,本修在后,两级串联);
4. primary/stack 悬空兜底加固随本条,⛔ 另开分支体系。

**冒烟五条**:①合成"集合在+块布局挂死 frame_id"笔记→修前拖块断言红(现状)→修后同路径绿,frame_id 重写为现行帧,零跳变逐像素;②健康笔记(有效 frame_id)保存 payload 逐字节不变;③frameless 块落籍回归(修一路径)不破;④修五半成品自愈回归不破(两级串联次序验证:先自愈铸集合,再重落籍);⑤tray 往返回归不破。

## F12 · 页框边线与页面错位

**症状(Henry 截图,全页 NoteDetail)**:纸顶部淡灰线(页框边界)与页面内容整体不对齐(起点横向偏移/观感歪斜)。

**侦察线索(HQ 静态,builder 确权)**:`NoteWritingSurfaceLayer` 的 `formalPageBoundary` 定位直接用 `pageFrame.x/y`(世界账);块屏幕位 = `layout.x + pageOffsetX`(偏移账)。两账对齐的前提=pageOffsetX 与帧内容原点同源;若 pageOffsetX 独立推导(如居中计算)而集合中 frame.x 来自另一来源(仪式端点/种子/历史),即错位。修五自愈铸帧=渲染同源不背锅;历史集合可能背。

**要求**:builder 合成"frame.x 与渲染偏移不一致"的集合先量化复现错位(修前红),再裁修法申报——**对齐规则只能有一本账**(边线与块共用同一坐标推导);⛔ 硬调像素;若勘定与 F11-B 同根(帧几何账 vs 偏移账),申报合并修。

**冒烟四条**:①错位集合修前红(可量化)→修后边线与块列逐像素对齐;②正常集合回归;③打印/统揽的页边渲染不破;④Fit width/缩放各档位对齐保持。
