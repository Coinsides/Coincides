### 根因与实现

**F14：同参红成立，但应更正“offset 丢失”的推断。** 按单内参数使用三段文字，首段 `We are the Champions of the world`，锚点 `(tu-1, 21)`（`of` 前），Shift+↓×2。修前真实 `NoteWritingSurfaceLayer` 中，第一次原生段内延伸发布 annotation draft，第二次跨 unit 转交逻辑选区时没有清掉旧 draft；`.textUnitDraftRange` 又给整个 unit 行涂底色，所以锚点前的文字也显得被选中。修前浏览器复制已经是 `of the world\nSecond p`，不能据截图声称实际复制 offset 归零。修复在捕获锚焦端点后、跨 unit/block 选区接管时清掉旧 draft，并去掉该 class 的整行底色；准确的文本范围高亮保留。没有重写 anchor、历史栈或保存语义。

**第二条独立根因申报：Layout 摆放序与 `visibleBlocks` 数组序不一致。** 数据适配器按 `order_index` 排序，拖动 placement 只改坐标；旧导航直接按数组邻居找下一块，旧合成夹具又把数组顺序手工排成屏幕顺序，因而漏检。真实布局夹具将 `lower(order=0,y=220)` 放在 `upper(order=1,y=0)` 下面，修前从 upper Shift+↓ 无下一邻居，红断言成立。手势/provider 链已接通，非 F14 连带，也不是 Layout 模式开关失效。

导航和文档选区现共用 placement 阅读序：同渲染坐标契约解析 frame / pageOffsetX，按 y、x、原顺序稳定排列；不改持久化 `order_index`。文档复制/编辑也使用这份序列，避免“焦点走对、范围按旧数组切错”。另将真实画布 image/table placements 加入同一序列：它们并非 `visibleBlocks` 中的 NoteBlock，必须显式作为导航目标和文字选区障碍。

**导航改判：** 普通方向键在非文本邻居停止并调用既有选中态，图片/表格使用既有 canvas object 选中样式，item/投影使用既有 block 选中样式；shell 获得焦点后 ↑/↓ 可继续离开。落图表时通过既有 `clearBlockSelection` 清除上一个文本块选中态，回到文本时清掉 canvas object 选中态。Shift 箭头和跨障碍 Shift+Click 都停止；shell 只处理自身的 ↑/↓，Enter、字符、表格内部输入、组合输入保持原路径。
