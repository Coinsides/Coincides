### 实施结果（不作放行判断）

- **R1**：rollback 路径已删除对共享 `draftTextRef` 的预写，只经真实 `setDraftText` 更新 ref/TextFlow/revision。production integration 由真实 `useRuntimeNaturalWritingController → useDraftBlockController` authority 驱动，覆盖 held create → `/hea` → Escape → stale create receipt；rollback revision 递增后，latest-save loop 发出纠正 `saveBlock`，并收到纠正文案的 durable reconciliation receipt。
- **R2**：采用**方案 A**。理由是 annotation 的本地状态与 durable PUT 已集中在 data adapter authority，可在不引入服务端 version/CAS 协议与 schema 变化的前提下建立 session fence。首个 `/` 的同-event TextFlow receipt 会同步建立 fence；Slash forward rebase 与 fence 内普通 full-resource annotation mutation只更新本地 overlay、零中间 PUT；commit、rollback 或 retain-current terminal 串在既有 durable tail 后发布最新 coherent snapshot 一次。guard reject 使用 fail-closed terminal disposition，并以 `abandon` 只解除 fence、不回退仍与正文/TextFlow 一致的本地 annotation overlay；下一次真实 edit 才重建新 fence。
- **R2 认识论**：Promise rejection 只证明 client 观察到失败；在 read-after-error receipt 返回前，durable outcome 是 unknown。本地保持目标 terminal snapshot 并 toast；GET 若读到目标态，判为 server commit + response loss、不得重复 PUT；GET 若读到非目标态，串行发一次 reconciliation PUT。两条 failure-boundary 测试均已落户，另有 queued tail、same-array stage/terminal、reject 后再编辑 coherence killer。
- **R2 事件边界**：block/shape blur、unmount、toolbar、gutter、selection toolbar、canvas object、page/surface/context-menu 等会释放 owner 或触发正文/annotation durable mutation的入口，统一在 mutation 前执行 terminal boundary；false 时阻断后续 mutation。accepted path 保持菜单、原生 Tag drag、普通 Save 的 exactly-once 行为；右键 physical sequence 与 primary-button 分流已有测试。
- **R3**：新增三份 draft 的唯一 enqueue-time authority；functional update 在入队时只求值一次，同步 merge 到单一 `snapshotRef`，再把 concrete state 交给 React。rollback 在 plan 前读取一次 coherent snapshot，旧的嵌套 no-op setter/`flushSync` drain 已删除。shared positive 同一 `act` 排队 plain/TextFlow/Formula 后立即 rollback，要求 `applied=true`、三份均保留 suffix；删除任一同步 snapshot 写入会命中该 oracle。
- **R4**：三条 killer 已落户：同 block/unit 但非 canonical TextFlow identity 时拒绝且零写；owner 漂移后 Escape 不增加 interaction write（call count 保持 1）；duplicate 正控让 aggregate range 与 owner-local caret 同指第二处，只删除第二处并保持第一处原样。既有 wrong-occurrence 负控继续保留。

#### HIGH-1 — terminal annotation 与正文 durable save 未闭合

确定因果链：

1. `external_clear` 固定选择 `retain_current`（`useSlashCommandController.ts:218-270`），terminal controller 在 `useBlockSlashAnnotationTerminalController.ts:135-139` 以 fire-and-forget `void saveAnnotationTruths(...)` 发布 annotation。
2. Block unmount cleanup 只做 terminal + release（`BlockEditorLayer.tsx:220-225`），shipped test `BlockEditorLayer.test.tsx:385-395` 还明确断言 `onSave=0`；与此同时 terminal test `useBlockSlashAnnotationTerminalController.test.tsx:126-141` 明确断言 retain-current durable annotation 恰好 1 次。两条各自绿，交叉后正是 body/offset 分叉。
3. Reviewer 在隔离副本补 invariant：正文为 `alpha /hea beta` 的 focused block unmount 后，接受 terminal 必须伴随匹配 body save。实际 `onClearSlashTarget=1`、`onSave=0`，exit 1，红在 `expected onSave 1, got 0`。
4. move/resize 更硬：`BlockEditorLayer.tsx:313-330` 先 terminal；`useBlockPlacementInteractions.ts:82-137,157-203` preventDefault 并只持久化 layout，不触发 textarea blur/body save。因此 annotation 可以按带 `/query` 的本地 body durable forward，而 durable block 仍是旧正文。
5. 即使是 blur，capture phase terminal 先 fire-and-forget annotation，bubble phase `TextBlockProjection.tsx:1212` 才启动 body save；两请求无共同 receipt。terminal 后立即 reload / 网络中断可只提交其中一个。

建议修法：terminal transaction 必须携带同一 authoritative block snapshot，并让 body 与 annotation 经过一个可恢复、可判定完成的 durable operation。若暂不做服务端原子 endpoint，至少要先取得 body durable receipt，再发布 annotation，并用 operation id / read-after-error reconciliation 补偿两边；unmount、move、resize、selection、context 与 reload fault 都要有 killer。只在 cleanup 随手再发一个独立 `saveBlock` 仍有半提交窗口，不足。

#### HIGH-2 — note switch 可确定地产生旧 note 半发布

`SlashSession` 只有 target/owner/trigger/slice/caret，没有 note 身份（`slashCommandReducer.ts:30-36`）；`NoteDetail.tsx:5-11` 的 provider/runtime 也没有以 `noteId` key remount。route 在 render 立即写入 B（`useNoteCanvasDataAdapter.ts:367`），旧 `noteRef` / block editor 则仍可能是 A；loading 会卸载旧 runtime（`NoteCanvasRuntime.tsx:23-29`）。

两条写路径随后不对称：

- annotation terminal 从 `noteRef` 取 `currentNote=A` 并 PUT A（adapter `:542-573`），没有 route-generation guard；
- block save 在 `routeNoteIdRef=B`、`noteRef=A` 时于 `:1133-1140` 直接返回 `null`。

Reviewer adapter probe：load A → stage forward → rerender B 并 hold B hydration → flush旧 terminal → 尝试保存旧 A body。预期不允许旧 note 只发布一半；实际 `savedBlock=null`、block PUT=0、annotation PUT=1，exit 1。若 B hydration/旧 cleanup 被批处理为另一 interleaving，旧 A terminal会因 B blocks 不含 owner而 reject；`rejectedTerminalRef` 在 `useSlashCommandController.ts:257,269` 持续让 B 的无-session gate返回 false，直到下一次 text edit 才于 `:303` 重置。

建议修法：session、fence、save tail 与 reject latch全部 note-scoped + generation-scoped；route generation 翻转前收口 A，或把 A 的 body+annotation 放入统一可恢复队列。B hydration 必须只重置 B 的状态，旧 A receipt不得覆盖 B。仅给 annotation PUT 补与 block 相同的 route guard只能把“分叉”改成“静默丢编辑”，仍不合格。补 A active Slash → rerender B → 分别 hold/先完成 B hydration → 旧 cleanup → reload A/B，并断 B 首次交互不被 latch 毒死。

#### HIGH-3 — boolean fence 不承载 pending durable intent

stage forward后，adapter把所有 full-resource annotation save统一改成 local-only（`useNoteCanvasDataAdapter.ts:550-561`）。这能满足“fence内零中间 PUT”，但没有记录哪部分是 ordinary durable intent。`NoteWritingSurfaceLayer.tsx:898-917` 的 draft-owner reconciliation不经过UI terminal gate，会直接调用 `onSaveAnnotationTruths(reconciledAnnotations)`，因此可在任意活跃 Slash fence内命中这条 suppression。

随后若 owner/aggregate guard reject，terminal controller走 `abandon`；`abandonAnnotationSlashTransient` 在 adapter `:630-633` 只清 boolean，没有 pending journal或drain。Reviewer sequence为：stage forward → fence内加入另一 block 的 ordinary durable annotation → abandon。结果本地overlay含两者，但模拟durable store仍只有Slash前旧annotation；期望durable包含unrelated id，实际缺失，exit 1。若用户此时reload，已经发出过的reconciliation intent静默丢失。

同一 authority还有并发快照风险：terminal controller的 `annotationTruthsRef` 只在render同步；同 turn enqueue concurrent annotation后立刻terminal，payload仍用旧数组。Reviewer probe期望terminal array同时包含owner forward + concurrent annotation，实际只含owner，exit 1。这条作为并发边界佐证；HIGH判定本身由前述可达的reconciliation→abandon→reload链承重。

建议修法：fence内 ordinary mutations要有独立journal/delta，并在terminal或abandon时drain/reconcile，不能靠“最新full array”猜来源；annotation authority也要像R3 draft authority一样在enqueue时同步维护coherent snapshot。补 draft-owner reconciliation during fence → guard reject/abandon → reload，以及 concurrent set+terminal 两条集成 killer。

#### HIGH-4 — preserved-focus menu只验打开时，不验action时

`TextBlockProjection.tsx:700-705,1091-1094` 在physical right-click / gutter open-menu时调用一次 `onBeforePreservedFocusAction`，但 `ContextMenuLayer.tsx:137-164,215-225` 只在outside/Escape关闭菜单、以mousedown保留textarea focus，并在点击时直接执行action。用户随后输入新的 `/query` 会建立新session；旧菜单的 `handleTextUnitMenuAction` 在 `:794-804` 直接执行 `handleSetRole` / annotation action，没有再次terminal。九类菜单在 `NoteWritingSurfaceLayer.tsx:3928-3979` 都直接接action handlers；block actions `:2440-2478` 可Save、label、切policy或trash，canvas actions `:2864-2931` 可duplicate、切placement persistence或delete，所以这不是只影响菜单视觉状态的轻微缺口。

方案A本身允许在真正“释放owner或触发durable mutation”前建立terminal boundary；问题是本轮把“切selection或打开竞争菜单”也等同于该谓词。`ImageObjectLayer`、`ShapeObjectLayer`、`TableObjectLayer` 的非layout primary path会被parent `preventDefault` 保持焦点，主要只换selection；gutter row selection同样不必然释放文本owner或durable写；`VisualConnectorLayer.tsx:88-95` 更只打开context menu并显式保焦。此时提前terminal既不是action-time validation，也不保证matching body save，反而改变用户仍在编辑时的Slash lifecycle并放大HIGH-1。
