## 请重点对抗复验

### A. 四态机械新鲜度

- 新建 Relation 是否 `fresh`；只改 from、只改 to、两端都改是否准确进入三种 changed 状态；
- 只改 `body_json` 表达、type、topic、metadata 而 canonical `plain_text` 不变时是否始终 fresh；
- reaffirm 是否刷新双 Snapshot 并立即返回 fresh；
- freshness 是否只在读取时派生，schema 中是否确实没有 freshness / stale / sync 列。

### B. Assessment checkpoint 非权威

- latest assessment 是否按最近记录读取并贡献 `inspection_checkpoint_at`；
- 晚于 affirmed 的 `still_holds` / `questionable` 是否都不能覆盖 hash changed 事实；
- 是否不存在 assessment invalidation flag、模型执行器或伪装成人工 judgment 的新写路径。

### C. Item 搜索与用户隔离

- 搜索是否覆盖 plain text、type 与 topic；
- active 默认、limit 上限与 SQL wildcard escaping 是否可靠；
- 同用户跨 Project / Note / ContentGroup / Purpose 的 Item 是否可见；
- 另一用户的 Item 是否绝不可见。

### D. Inspector 行为

- active Relation 是否正确解释相对方向、对端、type、note 与 relative freshness；
- directed create 是否能明确反转方向，undirected 是否不伪造方向；
- retired endpoint 是否可读、可 revoke、不可 reaffirm；
- revoked、Snapshot 全文、diff 与 assessment history 是否默认隐藏；
- create / reaffirm / revoke 错误是否只留在 Inspector 局部，不发 freshness 全局通知。

### E. absence boundary

- 全 active Relation 代码是否没有 timer、sweep、queue、batch freshness route 或 RelationGraph；
- 是否没有提前建设图谱工作台、AI assessment、proposal 或自定义 RelationType 实体；
- 11.5 LOW 的 directed 同向 duplicate 409 是否已有专项断言并返回既有 Relation ID。
