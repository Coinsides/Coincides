# V2.BN.10.4 Source Experience 浏览器与对抗验收

## 任务

对 V2.BN.10.4 的 Source Library、Project Sources、状态感知打开矩阵和 SourceProjection 显式锁定做真实浏览器 Smoke / adversarial review。Codex 已完成代码和非浏览器验证，但按 Henry 的决定没有执行本轮浏览器验收。

请不要把“页面能加载”当作 PASS。重点判断：用户是否始终知道 Source 在哪里、当前发生了什么、现在能做什么，以及为什么正文操作不可用。

## 前置检查

1. 浏览器登录后左导航存在 Source Library。
2. 建立或选用两个普通 Project，记为 Project A / Project B。
3. 打开 DevTools Network 与 Console，清空历史错误。
4. 确认 legacy Documents 的 Upload / Manage 不再是 Project 正常入口。

## 验收矩阵

### A. Source Library 与状态机

1. 在 Source Library 上传 `source-smoke.txt`。
2. 观察 Network 顺序应包含 precheck、upload、materialize 和按需 list polling。
3. 条目最终进入 Ready；点击条目打开提取阅读视图，不进入空路由。
4. 返回 Library，分别验证名称搜索、TXT 类型筛选、Ready 状态筛选。
5. 上传 `source-smoke.xlsx` 和 `source-smoke.csv`：状态必须是 Original only，不显示误导性 Retry，条目点击进入详情而非空阅读视图。
6. 上传 `source-smoke-corrupt.docx`：原件必须保留；详情显示稳定失败原因；不可重试错误不显示 Retry。若 parser 将该样本分类为可重试错误，记录实际 error_code 并核对按钮与 `retryable` 一致。

预期：小样本可能在第一次轮询前跳过肉眼可见的 received/parsing/publishing，但不得出现永久转圈、空投影或 Console 未处理异常。

### B. 双开原件

对至少一个 Ready Source 和一个 Original-only Source：

1. 点击 View original，应通过认证请求后在新标签页打开 Blob；Network 不得出现裸 `/api/sources/:id/blob` 新标签 401。
2. 点击 Download，应得到原始文件名与完整文件。
3. 原件缺失时按钮必须禁用；不要为了测试此状态破坏共享 dev DB。

### C. Project Sources 与跨 Project 去重

1. 在 Project A 的 Sources 区上传 `source-smoke.pdf`。
2. 条目应立即出现在 Project A，并同时能在全局 Library 找到。
3. 查看详情：Origin 显示 Project A 收据，Placements 显示当前 Project；文案不得暗示 Project 拥有 Source identity。
4. 在 Project B 上传同一文件。
5. 应出现“既有 Source 已添加到当前 Project”语义的反馈，不应再次上传整份文件或建立第二个 Source identity。
6. Project B 列表立即出现该 Source；Library detail 的 placement 数增加，Origin 仍保持首次收据。
7. Project 卡片上的 Sources 按钮应滚动到 Project Sources，不得打开 legacy DocumentManager。

### D. 格式旅程

至少逐一上传并打开：

- `source-smoke.pdf`
- `source-smoke.docx`
- `source-smoke.txt`
- `source-smoke.md`
- `source-smoke.png`

预期：前四种形成可读文本投影；PNG 形成可查看图片投影；所有格式原件仍可独立打开/下载。

### E. SourceProjection 显式锁

打开任一 Ready 文本投影：

1. 展开和折叠 Chrome 均能看见 `Source locked`。
2. 标题可选择但不可修改。
3. paragraph / formula / code 正文可选择文本但不可改写。
4. Block 移动、缩放、保存、删除按钮不可用；双击空白处不能创建 Block。
5. Layout 与 New PageStack 不可用；PageFrame/PageStack 修改与 document typography 控件不可用。
6. Canvas shape/image/table/connector 不应出现可变 context menu 或 Object Inspector；shape text 与 table cell 不可编辑。
7. Page / Canvas 切换、Canvas 平移缩放仍可用。
8. 文本选择后 Annotation 创建应可用；ContentGroup 收集/组织路径应可用。若 Purpose 没有直接 UI 入口，核对其现有入口没有因 read-only policy 被隐藏或拒绝。
9. Network 不应因正常点击产生 SourceProjection content-write `409`；若出现，记录具体控件和请求路径。

### F. 详情与失败降级

1. active / failed / original-only 条目点击均打开可理解的详情，不是无响应按钮。
2. detail 显示文件事实、parser/version/attempt、Origin 与 Placements。
3. 删除图标处于禁用状态；本轮不得把它计为已实现删除。
4. `projection_missing / original_missing` 的纯状态行为已由 `npm run check:source-experience` 覆盖；除非使用隔离测试 DB，不要手工破坏 FK 或事实 blob。

### G. UI 与运行质量

1. 桌面宽度与窄窗口各检查一次；文件名、状态和操作按钮不得重叠或溢出。
2. 上传中进度条不应改变列表布局。
3. active 项完成后轮询应停止；页面隐藏时应暂停轮询。
4. Console 无 React key、受控输入、未捕获 Promise 或无障碍严重警告。
5. Network 无重复整文件上传、无限 polling、401 blob 请求或正常操作触发的 409。
