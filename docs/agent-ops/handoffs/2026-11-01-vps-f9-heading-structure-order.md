## 二 · 修二(A-17):空块快打「# 」→ 丢字+章节树分叉+整篇只读卡死

- **现象**(2/2):「标题回车不打字失焦」造出的独立空块里快速打「# 节三」→ 文字丢失;服务器上是**空标题**而章节树记着「节三」(两真相分叉);随后整篇 10 个 textarea 全部 readOnly、「Source locked」常亮(3cc2a0e4 上的标签表现;F8 修四后标签不亮但**只读卡死照旧**,病根未除),打字不显示,直到刷新;刷新后 F7 队列里的「节六」落盘并出现恢复条——安全网接住了,但门锁死了。
- **判读三头**:
  1. **忙态释放保证**:headingStructure.busy 在「空块内『# 』转换、无后继新段落」路径上未释放——commitStructure 的所有出口(成功/失败/无事可做)必须释放忙态,这是不变量;
  2. **队列出口保证**:F7 的键入队列靠「焦点送达新块」触发重放;此路径无新块产生,队列无出口——转换无后继块时,队列须改投当前块重放或可见地失败,⛔静默滞留;
  3. **章节树与块文本分叉**:树上有「节三」而块为空——查树的派生时机(疑在提交前取了乐观值),修到树恒从已落盘块文本派生,或提交失败即回滚树。
- **测试**:①死锁场景确定性复现→修后文字保留、页面不锁;②忙态不变量用例(所有 commitStructure 出口后 busy=false);③树与块一致性断言;④杀手级:任何路径不得让编辑器停留在永久 readOnly(超时兜底也算出口,但首选结构性出口)。

### 修二(A-17):两个根因,均在临时实例确定性复现后修

1. **丢字 + 章节树分叉 = 漏发 text 半边**(F4-2/F7 恒定律同族):
   - 「# 」转换不走编辑器自己的发布器(普通键入经 `onTextChange` + `onTextFlowChange` 两半都发),而走 `commitStructure` 的 `applyEdit`,只发 flow 半边。
   - 临时库探针实证:flow 变成 heading「Sec4」,text 半边仍是 ""。`alignFlowWithText` 以旧 text 为准,编辑器显示空;章节树从 flow 派生,显示「Sec4」。用户在「空」块再打字,就把「Sec4」覆盖掉:临时库该块落成「x」,这就是 Tester 所见「服务器空标题」。
   - **修**:结构编辑一落地就从同一份 flow 发布 text 半边;失败或看门狗出口按 live flow 回写所有触及块的 text。章节树与块文本从此同源。
2. **整篇只读卡死 = 结构提交挂在动画帧上**:
   - `commitStructure` 的每一步都 `await requestAnimationFrame`,排队按键的重放也挂在 rAF 上。后台、被遮挡或被节流的标签页里帧不来,run 就到不了 `finally`:busy 不释放(contentReadOnly 是并集,所以整篇只读),全局按键捕获也不卸载,继续吞键。
   - 复现:截停 rAF 后打「# Sec7」,6 个编辑框全部 readOnly、Sec7 被吞;恢复 rAF 后仍锁死,只有刷新能解。这与 Tester 环境说明(内置浏览器面板被遮挡时会节流)吻合。
   - **修**(结构性出口优先,超时兜底):
     - 所有「等一帧」改为 `afterFrame`,rAF 与 100ms 计时器先到者为准;
     - 新增 10s 看门狗作为最后出口:作废 run(后续步骤见 `current()` 为假即停)、释放 busy、回写两半、走失败 toast、交出排队按键;
     - 成功、失败、抛错、看门狗四个出口都释放 busy,也都给队列一个出口:成功回放到新光标,其余回放到当时打字的位置。焦点单元若被半途移进新块,就跟到新块;若不存在,就放进该块最后一个活单元。
   - **申报**:若失败本身是保存失败,笔记按既有恢复纪律进入「Retry/Undo」状态,所有打字(包括回放)都被同一道门拒收,此时失败 toast 就是可见出口。我没有加重试:晚到的重放基于旧快照,会覆盖用户新打的字。
