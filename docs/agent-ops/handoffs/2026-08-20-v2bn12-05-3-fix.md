#### 05.3-HIGH-1 — receipt 没有冻结 hydration/snapshot epoch

`useNoteCanvasDataAdapter.ts:389-395` 的 `annotationSaveRouteReceipt` 只有 `{noteId, route generation}`。但 `routeRequestGeneration.ts:6-12` 在 noteId 不变时原样返回 generation；同 note refresh 实际推进的是另一套 `noteLoadGenerationRef` (`useNoteCanvasDataAdapter.ts:442-447`)，成功 hydration 又在 `:479-480` 推进 annotation snapshot generation并替换 snapshot。旧 callback不携带这两个 epoch。

Reviewer sequence：hydrate A=`initialA`并捕获 callback → 改变同-note load dependency触发第二次 A hydration=`newerA` → 调旧 callback(`staleA`)。期望 enqueue reject、零 PUT、snapshot/durable仍为 `newerA`；实际向 `/annotation-truths/by-note/A` 发出一笔 `staleA` PUT并把 snapshot改回 stale，测试 exit 1。该调用在 `:574-580` 通过，因为 note id与route generation都未变；随后 `:594-620` 反而把 stale operation立为新的 snapshot generation。因为它被误认成 current，实际 warn=0。

真实 range-edit continuation也不能兜底：writing surface只检查 block save返回非空且 block id相同；adapter的 block save同样只用 route note/generation核验。同 note hydration期间 held旧 continuation仍可通过并调用旧 annotation callback。

修复需要把**成功 hydration/render epoch**（或等价 OCC token）纳入不可变 callback receipt，并与“同一 epoch内多笔 save的 response ordering sequence”分离；不能直接复用同一个 snapshot counter后让每笔保存自增，否则正常串行 save会自我判 stale。应把本轮 reviewer同-note probe落为常驻 killer，断零 annotation PUT、当前 snapshot与durable不变、精确可观察 reject。

#### 05.3-HIGH-2 — migrated Escape 只改本地，不改 durable block

`useSlashCommandController.ts:569-589` 的 block Escape只调用 `exitSlashSession('escape', text)`。后者在 `:235-275` 对 block owner调用 `rollbackBlockSlashSession`，但没有调用已经注入controller的 `saveBlock`。`useSlashBlockRollbackController.ts:98-132` 只 `setBlockTextDrafts`并 `void applyBlockTextFlowEdit`；`useBlockTextFlowEditController.ts:49-78` 又只更新本地 TextFlow draft和保存 annotation，完全没有 block PUT。

所以现有 `useRuntimeNaturalWritingController.test.tsx` 的“durable TextFlow”断言实际上只读本地 `blockTextFlowDrafts`。Reviewer在同一真实 runtime helper中接入 durable `saveBlock` spy后：Escape `preventDefault=true`、session关闭、本地 plain/TextFlow 均变为 `draft `，但等待后 durable仍为 `draft /hea`，`saveBlock`实际0次，测试 exit 1。若存在 annotation，当前路径甚至可能持久化annotation inverse而不持久化对应block正文，再次形成跨真值半提交。

修复需让 block-owner rollback通过现有 block持久化正门提交同一 rollback TextFlow/plain truth，并以失败/route stale语义明确处理；常驻 probe必须同时断 prevent、local inverse、block PUT/receipt以及重读后的 durable无 `/query`，不能只断本地map。
