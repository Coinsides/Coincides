### R1 — mount identity 与旧 continuation 失效

- `BlockEditRecoveryReceipt` 与 `recoveryKey` 现强制携带每次 adapter mount 唯一的 `mountNonce`；validator 会重算含 nonce 的完整 key。新旧 mount 即使同为 `generation=0 / operation=1` 也不再共享持久身份。
- adapter unmount cleanup 会令该 mount 的 route receipt 失效；旧 save/reconciliation/conversion continuation 不再写当前 UI、toast 或 `savingBlockId`。hydration 只有在 `mountNonce + creationGeneration` 同时属于本 visit 时才自动灌入 draft，旧 visit receipt 仅留在显式 Apply/Dismiss 队列。

### R2 — focused editor 的物理事件序

- Apply 与 Dismiss 两按钮均在 `mousedown` 同时执行 `preventDefault()` 与 `stopPropagation()`，避免浏览器默认把焦点从 editor 移到按钮。
