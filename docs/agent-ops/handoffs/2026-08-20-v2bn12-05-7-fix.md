**这句话把缺失能力的位置点名在服务端。** 而 05.1 造的是一道**客户端围栏**，试图提供服务端并不提供的跨资源保证。

**这不是事后诸葛：** 「**局部子系统无法制造它所依附的基线不提供的保证，否则它就成了第二个真相源**」是结构性判断，不需要先建出来才能推出。05.2 最终的结论（「正解需要服务端支持：operation receipt / 原子端点」）**正是 05 Review 那句话的直接推论** —— 05.1 那一轮，是没有把两者连起来的成本。

**⇒ 裁定本身正确，时点晚一轮。** 若 05.1 的方案短笺阶段问一句「这道围栏想给斜杠回滚一个普通打字都没有的保证，凭什么？」，这一轮可省。

#### 05.6（载体归家）：裁决正确，但它**重新发现了 05.2 已经用过的那条规则**

- **05.1 的病**：斜杠专属 durable 机关，平行于普通编辑正门 → **撤除，回滚走正门**。
- **05.5 的病**：in-memory 恢复载体，平行于既有 sessionStorage 收据系统 → **归家，走既有系统**。

**这是同一个错误的两次发作，而且两次的解法字面相同（走正门 / 归家）。**

Fable 在 05.6 首次把它命名为「**平行机关，不走正门**」并判为系统性倾向 —— **判定成立**。但：

> ⭐ **05.2 修的是一个实例，没有提取出规则；05.6 不得不把同一条规则重新发现一次。**

**⇒ 我的核心建议**：立案的「平行机关」纪律**不应只约束 builder**。05.1 与 05.5 两个方案都是经过短笺进来的 —— **它同样要成为裁定方在方案短笺阶段的必问项**：

> **本方案是否在既有正门之外另造了一套承载同类职责的机关？若是，为什么正门不够？**

**理由**：builder 提方案时正在解一个局部问题，看不见全局重复；**看得见的是裁定方**。把这条只挂在 builder 侧，等于把检测责任放在最看不见它的位置。

### ③ 止损承诺机制：**值得制度化，但要带触发条件而不是临场宣布**

05.7 的机制：**预告本轮为最后一轮 + 预置降级方案**（若再 FAIL，Apply/Dismiss UI 降级为只读队列，**收据保全能力保留**，交互入口进债表）。

**它好在三点**：
1. **在情绪时刻之前**把退路定死 —— 「防自己心软」是 Fable 的原话，也是这机制的真正功能；
2. 降级方案**保留承重能力、只砍交互面** —— 是范围收缩，不是投降；
3. 它把开放式乒乓变成**有界承诺**。

**但它在第 7 轮才出现。** 止损的价值与设定时点成反比 —— **第 7 轮设的止损最多省 2 轮；第 3 轮设的会逼出设计问题**。

**⇒ 建议制度化的形式是触发式，不是自觉式**：

> **任一修理链到达第 N 轮（建议 N=3）时，裁定方必须二选一：**
> **①宣布止损承诺（含预置降级方案），或 ②记录为什么这条链值得继续无界乒乓。**
>
> 关键是**不允许沉默地继续** —— 沉默继续正是「心软」的形态。

### ④ 「预点次态刀」在 05.4→05.5：**有实效，且它的有效性有结构性原因**

机制：把上一轮的**新防御**指为下一轮的头号嫌疑。

**实效已验**：05.5 的 FAIL 正来自 05.4 新造的 epoch fence / pending map —— 复核发现它的 UI 写入 fence 与 pending map 读取匹配删除「**完全没有复用 `reconciliationReadIsCurrent()`**」（05.5 Review `:122`）。

> ⭐ **它为什么有效，值得点破**：**新防御正是平行机关的产房。**
> 一个新加的防御，天然倾向于自带一套自己的判定，而不是复用既有那套 —— 因为「加一层」比「接进去」容易。所以「预点上轮新防御」在结构上就等价于「自动扫描平行机关」。
>
> **这条与 ② 是同一个发现的两面。** 建议把「预点次态刀」的理由写成这一句，而不只是经验法则 —— **有理由的规则才扛得住被简化掉。**

### ⑤ 边际信息量曲线 →「何时该停乒乓」的可操作判据

按 5-7 成本视角看九轮，**信息量不随轮次衰减，而是集中在两个尖峰**（05.1 与 05.5），而两个尖峰的共同特征是：**该轮的 finding 是设计级的，不是机械级的**。

| 轮 | findings 性质 | 该做什么 |
|---|---|---|
| 05.1（4H1M） | **设计级** —— 4 HIGH 全住在本轮新造的子系统内；MED-1 判扫面谓词本身不成立 | ⇒ 设计介入（做了，晚一轮） |
| 05.5（3H） | **设计级** —— 新造平行载体 | ⇒ 设计介入（做了） |
| 05.3 / 05.4 / 05.6 / 05.7 | **机械级** —— 事件次序、key 碰撞、kind 分派、措辞收窄 | ⇒ 乒乓有效，继续（确实收敛了） |

**⇒ 判据（建议进角色卡 / 工单纪律）：**

> **停乒乓的信号不是「FAIL 数下降」，是 findings 的性质。**
>
> - **机械级 finding**（次序 / 身份 / 分派 / 措辞）：乒乓有效，继续。**连续两轮全为机械级 ⇒ 收敛在望。**
> - **设计级 finding**（新缺陷住在本轮新造的机关里 / 扫面谓词不成立 / 平行机关 / 局部超越基线）：**立即停乒乓做设计介入，不要用下一张修正单去补。**
>
> 判定「设计级」的机械问法：**这些 finding 是不是大多住在本轮新加的东西里？** 是 ⇒ 设计级。

**⇒ 若该判据当时存在**：05.1 与 05.5 两个方向本应在**短笺阶段**被拦（依据分别是 ② 的两条），**九轮可收敛为七轮**。这是我能给出的最具体的成本答案。

### ⑥ 反向校准：**九轮无一过严；但 05.2 暴露了判定词汇的表达力缺口**

逐轮核过，**没有一轮的 FAIL 定级偏严**（对比我在 03 链给出的「03.3 说重了」，本链无同类）。相反：

**05.2 是一处词汇缺口，不是过严。** 那一轮的**设计目标（验证撤围栏方向）达成了**，复核也明确写了「架构验证成立」—— 但判定仍是 **FAIL（3H）**，因为代码确实还有 3 个 HIGH。

**二者都对，但二元判定说不出这个区别。** 而这个区别**恰恰是裁定方最需要的信号** —— 它决定的是「继续乒乓」还是「再次设计介入」。

**⇒ 建议：判定允许一个方向注记。**

```text
FAIL（方向成立）  ⇒ 代码未过，但本轮的设计方向被验证 ⇒ 继续乒乓
FAIL（方向不成立）⇒ 缺陷住在本轮新造的机关里       ⇒ 停，做设计介入
```

> **⑤ 与 ⑥ 收敛到同一条建议**：把「设计级 / 机械级」这个区分**做进判定词汇**，它就同时解决了「何时停乒乓」与「FAIL 说不清方向对错」两个问题。**判据不写进判定格式，就只能靠裁定方每轮自己想起来。**

### 给终检 / 铸版的四条

1. **我认同复核侧意见：全链具备 checkpoint 条件。** 九轮收敛是真收敛 —— 每轮的原 witness 都被**原样重放**验证转绿，05.7 还补了用户点名的**反向** probe（旧 receipt 仍可见、可 Apply），并在取证后撤除、交付树复原。
2. **「平行机关」纪律建议双向立案**：除 builder 侧外，**加一条裁定方在方案短笺阶段的必问项**（②）。只挂 builder 侧，等于把检测责任放在最看不见它的位置。
3. **止损机制建议改为触发式**（③）：到第 3 轮必须二选一（宣布止损 / 记录为何继续），**不允许沉默地继续**。
4. **建议把「设计级 / 机械级」做进判定词汇**（⑤⑥）—— 这是本链九轮最可复用的一笔。
