# V2.BN.12 修正单 05.2:设计收缩——撤除围栏子系统,回滚走正门

## 设计裁决(Fable,本单的核心不是修 finding,是换方案)

05.1 的方案 A(布尔围栏+终端边界扫面)被复核证明架构不胜任:4 HIGH 全部住在该子系统内(跨资源半提交/跨 note 半发布/围栏吞无关意图/菜单 TOCTOU),且 MED-1 判定扫面谓词本身不成立。**根因**:正文与 annotation 两个 PUT 无跨资源事务是**全应用既有契约**(普通打字同样如此,复核 05 轮已指出),斜杠专属围栏试图在局部超越基线,反而制造了基线没有的新缺陷面。

**裁决:**
1. **回滚是一次普通编辑**——rollback 的文本 splice 与 annotation 逆向 rebase 走**普通编辑同一路径**(与人类击键同门,机件也同门同钥),继承基线的 rebase+保存语义与失败语义。不再有斜杠专属的 durable 发布机关。
2. **跨资源事务是全应用债,不在斜杠角落修**——立 **TD-6**:正文+annotation 双 PUT 可半提交,适用一切编辑;正解需要服务端支持(operation receipt/原子端点),另立设计单。客户端围栏不是解。

## 修正要求

1. **R1 撤除围栏/终端子系统**:以复核 §3 逐文件裁决表为回滚地图——11 个层文件+pointer hook 的 terminal boundary 接线、fence(stage/abandon/terminal publisher)、reject latch 全部撤除,恢复 05.1 前行为(external clear/Ctrl+Enter 只关闭不回滚照旧)。随子系统死亡的测试一并移除,不留孤儿红。
2. **R2 保留已验实修(不许连坐回滚)**:①05.1 的 R1(禁预写 ref/revision 递增/纠正 save+集成测试);②R3(enqueue-time snapshot authority+coherent positive);③R4 三 killer 与 owner/range/duplicate guards;④D3 矩阵/D4 门接线;⑤**adapter 通用加固保留且去斜杠门控**:durable-semantic comparator(metadata hydration 归一)与 read-after-error reconciliation(GET 目标态不重 PUT/非目标态一次修复 PUT)成为**一切** annotation 保存失败的通用路径——它们修的是真缺陷(rejection≠未落盘),与围栏无关。
3. **R3 一处真不对称修复**(05.1 HIGH-2 暴露的既有缺陷,与围栏无关):annotation PUT 补与 block PUT 相同的 route/note guard(adapter :542-573 对齐 :1133-1140)——切 note 后旧 note 的 annotation 不得再发布。补 A→B 切换负控。
4. **R4 rollback 经正门的验收**:Escape/disabled/annotation/missing 各路径回滚后,annotation 偏移经普通路径 rebase+保存;失败走 R2⑤ 的通用 reconciliation。原 05 的 guard 语义(owner/range exact/漂移不回滚)不变。
5. **R5 TD-6 入账**:tech-debt.md 新行——跨资源(正文+annotation)durable 耦合缺失,全应用级,承接=专项设计单(服务端 operation receipt/原子端点方向),排期 V12 必修后。
