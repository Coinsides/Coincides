## ⚠️ 调度方复核 Fable 四条预裁时发现的一处缺口(**已按下述补齐,施工按本节**)

**Fable 预裁①只覆盖了 `confirm:true` / `confirm:false` 两种回答,没覆盖「用户 decline / cancel」。** 这不是文书疏漏,是有牙的坑:

> **SDK 官方示例用的是 `acceptedContent(...)`,而 `acceptedContent` 对「没问过」和「问了但被拒/被取消」一律返回 `undefined`。**
> 照抄官方那句 `if (!confirmed) return inputRequired({...})` ⇒ **用户每拒绝一次就被再问一次**,直到客户端 `inputRequired.maxRounds` 耗尽,报 `INPUT_REQUIRED_ROUNDS_EXCEEDED`。
> 对一个**删除类**工具,这是「拒绝无效、反复逼问」—— **红线级**的交互。

**⇒ 分支判定必须走 `inputResponse()`(判别式视图;SDK 自陈它「covers decline/cancel detection and the non-elicitation response kinds that `acceptedContent` does not surface」),⛔ 不得用 `acceptedContent` 判断「是否已问过」。**

`acceptedContent` 仍可用于**取值并按 schema 校验**(它有 schema 重载),但**分支判定归 `inputResponse`**。

**confirm 档状态表(⛔ 逐行照做,不合并分支)**:

| `inputResponse(responses,'confirm')` | 执行 | 收据 | 返回 |
|---|---|---|---|
| `kind:'missing'`(**首呼**) | ❌ | ⛔ **零行** | `inputRequired({ inputRequests: { confirm: inputRequired.elicit({…}) } })` |

| `kind:'elicit'`, `action:'decline'` | ❌ | ⛔ **不写** | **拒绝形状**,`decision: 'declined'` |

| `kind:'sampling'` / `'roots'`(不该出现) | ❌ | ⛔ **不写** | 视同 missing,重问**一次**即可;⛔ 不得执行 |

### 「拒绝形状」定义(Fable 2026-08-23 裁定,三者**同一处理路径**)

**拒绝不是错误。** 三种情形(`rejected` / `declined` / `cancelled`)走同一段代码,只有 `decision` 取值不同:

| 面 | 值 |
|---|---|
| `isError` | **`false`**(⛔ 不得设 true,⛔ 不得走 `appErrorResult`) |
| `resultType` | **`complete`**(⛔ 不得再回 `input_required`) |
| `structuredContent` | **`{ results: [] }`** —— 合法且**已有绿测在跑**(实况 10) |
| `_meta['io.coincides/toolFaceDecision']` | **`{ decision: 'rejected' \| 'declined' \| 'cancelled' }`** |
| `content` | 文字说明「已按用户选择取消,未执行任何删除」 |

⛔ **`_meta` 里不得带收据键** —— 拒绝路径**没有收据**,塞一个 `io.coincides/toolFaceReceipt` 就意味着编造 id,是**最像绿的假绿**。拒绝路径的 `_meta` **只有 decision 一个键**。
⛔ **不得为 `decision` 改 `output_schema`** —— 顶层 `additionalProperties: false`,塞进 `structuredContent` 会被拒(实况 10b)。

**表单内容(预裁①)**:`requestedSchema` 为 `{ type:'object', properties:{ confirm:{ type:'boolean' } }, required:['confirm'] }`;**`message` 须含受影响条目数与 id 摘要**(K-c9 验)。

**`droppedInputResponseKeys`**:SDK 会丢弃非 bare 形状(如 `{method,result}` 包装)的条目并把 key 记在此处 —— 那种情况读作 `missing` ⇒ 重问。**这是 SDK 的既定意图,不是 bug;回执申报即可,⛔ 不要为它加补偿逻辑。**

**零持久(硬闸 H-5)**:`input_required` 那一轮**绝不能写 `operation_batches`**,也不得留任何进程内状态 —— 本服务是**每请求新建 server + `handler.close()`**,重试是**全新请求**,服务端**从客户端重发的原 input 重算计划**(预裁②)。
