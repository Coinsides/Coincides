## 簇 A — 页框 extension 数据丢失（CR-8.11.1-01 + CR-8.11.3.1-01 + CR-8.11.3.1-02）

**根因（一条链）**：migration 035 建 `page_frame_extensions` 时 PK=`frame_id` 单列，backfill 用 `INSERT OR REPLACE`，而默认主框 id 是常量 `'primary-page-frame'`（`engineModel.ts:70`）→ 单事务循环所有 note 时后一篇覆盖前一篇，**塌成每 frame id 一行**；legacy 同事务 strip（035:322-324）→ 不可恢复。039 已把 PK 改 `(note_id, frame_id)`（结构性复发已堵），但**只拷幸存行、救不回已塌的数据**。8.11.3.1 的 LEFT-JOIN 兜底只救几何，`content_inset`/`page_size`/`background`/`template` 退默认，且 **adapter 立即 re-save 把默认烤死（LIVE tail）**。

### A1 — 修 LIVE tail（CR-8.11.3.1-01，先做，止血）
- **文件**：`server/src/services/canvasObjects.ts`（listPageFrameRows / hydratePageFrameCollection，约 1320-1397）、`client/src/pages/Notes/canvasEngine/hooks/useNoteCanvasDataAdapter.ts:542-556`（load 后 re-save）、`savePageFrameCollection`（canvasObjects.ts:1515-1660）。
- **要求**：extension 缺失、走 LEFT-JOIN 兜底恢复出来的 PageFrame，**必须带 `recovered/degraded` 标记**；`savePageFrameCollection` 写 extension 时，**不得用兜底默认覆盖一个已存在的真 extension**，也不得把 `recovered` 帧的默认 `content_inset/page_size/background` 当真值持久化。等价做法二选一（Codex 定）：(a) hydration 前先 repair extension（见 A2），使读出来即真值；(b) 在 frame 上传递 `recovered` flag，save 路径遇 `recovered` 且默认值时跳过覆盖 / 保留现有行。
- **验收**：构造一个"有 page_frame object+placement 但缺 extension、且自定义过 margins"的状态 → load → 不做任何编辑再 save → 断言 `content_inset/page_size` **不被默认值覆盖**。

### A2 — repair migration（CR-8.11.1-01，愈合历史）
- **文件**：新增 `server/src/db/migrations/043_*.ts`（编号接 042；idempotent、事务、`IF NOT EXISTS` 风格对齐 041/042）。
- **要求**：对每个"有 `kind='page_frame'` 的 canvas_object + placement + 在 collection 里、但缺对应 `(note_id, frame_id)` 的 `page_frame_extensions` 行"的帧，**重建 extension 行**：geometry 从 placement 恢复；`page_size/content_inset/background/template/exportable` 从**仍存活的** legacy `canvas_engine_page_frames_v1` blob（note.metadata）恢复，**若 legacy 已被 035 strip 则退默认并在 metadata 标 `recovered:true`**。
- **诚实边界（判断点，见文末）**：pre-cutover 已被 strip 的自定义样式**不可恢复**、只能退默认——这是可接受的（local-dev / pre-release），但 repair 要把"哪些是 recovered 默认"标出来，别假装恢复了真值。
- **验收**：跑一个"两篇 note 都用 'primary-page-frame'、各带不同 margins、经 035 backfill 塌缩"的 fixture → 跑 043 → 断言两篇各自有 extension 行、几何正确、被 strip 的样式退默认且标 recovered。

### A3 — 补回归测试（CR-8.11.3.1-02）
- **文件**：`server/src/__tests__/v2CanvasPersistenceCutover.test.ts`。
- **要求**：① 加"两篇 note 共享 'primary-page-frame' 经 035 backfill"测试——**它在修 043 前必须失败**（暴露塌缩），修后通过；② 扩 extensionless-recovery 测试：断言 recovery 后 `content_inset/page_size` 被保留或显式标 recovered（现测只断言 length/primaryFrameId/x/width，掩盖丢失）。

## 簇 B — AI 可读层污染（CR-8.11.3-01 + CR-8.11.4-01 + CR-8.11.1-05）

**共同性质**：三条都是"**不该进 AI 快照的东西进了 AI 快照**"——AI 半边(ContentGroup/未来 Agent)读的就是这份快照，必须**恰好是 live、可见的真相、每个一次**。

### B1 — 双真相源（CR-8.11.3-01）
- **文件**：`client/src/pages/Notes/canvasEngine/engineModel.ts:388-416`（buildNoteCanvasRuntimeModel 的 merge/dedup）、`useNoteCanvasLayoutModel.ts:224`（genericCanvasObjects 输入）。
- **根**：持久化 block/page_frame object 用合成 id（`canvas-object:{note}:…`，8.11.1.1 方案），runtime builder 用裸 `block.id`/`pageFrame.id`；dedup 的 `builtObjectIds` 按裸 id → 合成 id 对象**永不被 dedup**、泄成重复。
- **修**：把持久化 generic 数组**按 kind 过滤**——merge 前从 `genericCanvasObjects` **剔除 `page_frame` 与 `paragraph_block_projection`**（它们已由 pageFrames/blockPlacements 重建）。加 boundary 断言"generic 对象不得含这两 kind"。
- **验收**：新增 client 回归（`canvasEngineModelContractCheck.ts`）：喂一个**合成 id 的 page_frame + paragraph_block_projection** 进 genericCanvasObjects，断言 `canvasObjects` 与 `canvasAIReadableSnapshot` 里每个逻辑块/帧**恰一个节点**。此测试**在修前必须失败**。

### B2 — 隐藏 backing 块泄进 AI 快照（CR-8.11.4-01）
- **文件**：`server/src/routes/projections.ts:59-79`（buildSnapshotFromNote）+ 任何喂 AI/导出的 server 块列表。
- **修**：把隐藏规则**下沉数据层**——server 选块时加过滤 `json_extract(metadata,'$.render_scope') != 'canvas_object_backing'`（现规则只活在 client filter）。
- **验收**：构造一个 block-backed shape（backing 块 render_scope=canvas_object_backing）→ 调 buildSnapshotFromNote → 断言快照里**没有**那个 backing 块作为独立顶层块。

### B3 — trash 块留 ghost 投影漏进 AI 快照（CR-8.11.1-05，与 B2 连续）
- **文件**：`server/src/routes/noteBlocks.ts:107-115`（trash）、`server/src/services/canvasObjects.ts:1464-1479`（blockRows 读路径）、canvasObjects.ts:1406-1411（canvasObjects 读）。
- **根**：DELETE 只置 `note_blocks.status='trashed'`、不级联 projection/placement/mount；读路径只 `co.status='active'`、从不 join `note_blocks.status` → trashed 块的投影（stale mount 指向死块）持续被返回、当 ghost 漏进快照、无界累积。
- **修**（二选一，Codex 定；**倾向 read 派生、不焊**）：(a) **读路径 join `note_blocks`**，排除 backing 块非 active 的 paragraph_block_projection（在 read 时派生 liveness，符合相对不焊）；或 (b) block trash 时**级联 trash** 其 projection object + placement + content_mount。
- **验收**：trash 一个 block-backed 对象的 backing 块 → 断言 getNoteCanvasPersistence / AI 快照**不再**含该 projection ghost。

## 通用约束
- **相对不焊绝对**：liveness / render_scope 这类"目的相对"属性，**读时派生**，别焊进身份行（B3 倾向 read-join 而非只靠 cascade-mutate；A1 的 `recovered` 是标记不是新真相）。
- **不破坏现有测试**：`cd server; npm run test:v2` + `npm run verify:v2-bn8-runtime` 必须仍绿；每个新修都应带一个"修前失败、修后通过"的断言。
- **单一真相源**：B1 过滤后，page_frame/block 投影只有 runtime 一份；A2 后 extension 只有 note-scoped 一份。

## 判断点（供 Henry 复核，翻牌 ready 前看一眼）
1. **A2 repair 的"不可恢复→退默认"可接受吗**：pre-cutover 已被 035 strip 的自定义页样式救不回、只能退默认（标 recovered）。这是 local-dev/pre-release 的现实，但意味着**若你本地有自定义过 margins/纸张的老 note，043 后它们会变默认**。若你想在跑 043 前先手动导出/备份那些 note，跟我说。
2. **B1 修法选"kind 过滤"而非"runtime id 归一到合成 id"**：两者都能根治双源；我选 kind 过滤（改动小、语义清）。若你更想让 runtime id 与持久化 id 归一（结构更自洽但改动大），可让 Codex 走那条。
3. **B3 选 read-join 还是 cascade-trash**：我倾向 read-join（相对不焊、liveness 读时派生）；cascade-trash 更彻底但把清理焊进 trash 动作。留给 Codex 依代码现状定，但请守住"别把 liveness 焊进 mount 身份"。
