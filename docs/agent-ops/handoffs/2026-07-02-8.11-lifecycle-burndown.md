## 脊椎原则（先读，决定所有修法的形状）

**backing 块的身份是「读时从 live shape 拥有关系派生」，不是「焊在块上的 render_scope」。**（相对不焊绝对）

- 一个 note_block **是** backing 块 ⟺ **有一个 live canvas shape**（`backing='note_block'`）经 content_mount 拥有它。
- `metadata.render_scope='canvas_object_backing'` 只是**提示/缓存**，**不是真相**。真相 = live 拥有关系。
- 由此，所有生命周期动作都从这条派生，而非各自读焊死的 render_scope：
  - shape 还在、块死了 → shape 退成**无文本图形**（不消失）。
  - 块还在、没有 live shape 拥有 → 它**不是** backing 块 → 可见、可编辑（不再是 zombie）。
  - 「独立 trash 一个仍被 live shape 拥有的块」→ 拒绝（生命周期归 shape）。

这条脊椎一次性收掉 CR-8.11.12-01 / CR-8.11.4-03 / -06 / -08，并让 -02 / -04 / -05 自洽。

## 簇 C — 服务端权威：生命周期脊椎（read-derived）

### C1 · 守卫 note-block 独立生命周期操作（收 CR-8.11.12-01 主 + CR-8.11.4-04 权威）

**问题**：`DELETE /api/note-blocks/:id`（server/src/routes/noteBlocks.ts:107-115）与 `PUT /api/note-blocks/:id`（同文件，status 改写）**零守卫**软 trash/改任意块。加上 Stage-1 的 liveness 过滤按 `co.backing='note_block'` 罩住 block-backed shape（canvasObjects.ts:1426-1445）→ **独立 trash 一个被 live shape 拥有的块，会让整个用户画的图形消失**（CR-8.11.12-01）。

**修**：在 DELETE 和 PUT-status(→ 非 active) 路由加守卫——**若该块当前被一个 live shape 拥有**（存在 `content_mounts` 行 target_kind='note_block'、projection_mode='owned'，且其 object 是 `backing='note_block'` 的 active shape）→ **拒绝**（400，指引「经图形 remove-text/删除」）。
- **必须按「live 拥有」判定，不是按 render_scope 判定**（相对不焊）。这自动放行两类合法 trash：① demote 的 trash（demoteShapeText 已先 persist `backing='none'`+清 mount，到 trash 时块已无 live 拥有者）；② persist 失败回滚（1440/1535 的 `onTrashBlock`，此时 shape 根本没存成、无 live 拥有者）。
- **CR-8.11.4-04 权威**：`deleteCanvasObjectWithBacking`（NoteWritingSurfaceLayer.tsx:2582-2595）现在 server delete cleanup（690-727）软 trash 块**之后** client 又 `onTrashBlock` 一次（2589）。改为 **server 单一权威**：删 shape 时 server cleanup 负责 backing 块，client **不再**二次 trash（删 2589），从响应 reconcile。

**验收**：
- 修前 fail / 修后 pass：`DELETE /note-blocks/:id` 一个被 live shape 拥有的 backing 块 → 断言 400 且图形仍在（对象+placement+mount 未被隐藏）。
- 断言 demote 路径**不被**守卫误伤（demote 后块成功 trash、shape 成 pure）。
- 断言 persist 失败回滚路径**不被**误伤。
- 断言删 shape 只经 server 一次 trash（client 无二次 DELETE；用请求计数或 mock 断言）。

### C2 · 读路径：dead-block 退成无文本图形 + orphan 块不再隐藏（收 CR-8.11.12-01 纵深 + CR-8.11.4-03 根）

**问题**：liveness 过滤（canvasObjects.ts:1426-1445）现按 `co.backing='note_block'` 一刀切——block-backed shape 的 backing 块一死，**整个 shape 被隐藏**。反过来，一个 backing 块若其 shape 已不在，它仍因焊死的 render_scope 被当 backing 隐藏（CR-8.11.4-03 的服务端半边）。

**修**（两半，都 read-derived）：
1. **shape 不随文本死而消失**：liveness 过滤对 **kind='paragraph_block_projection'**（纯文本投影，对象即文本）保持「块死→整体隐藏」；对 **block-backed shape**（kind='shape' 且 backing='note_block'）改为**只隐藏其文本 mount，保留 shape 对象+placement**（退成无文本图形）。即过滤要 **kind-aware**，不再无差别按 backing 罩。
2. **orphan 块可见**：读路径判定「块是否 backing」时按 **live shape 拥有**派生，而非读 render_scope。没有 live shape 拥有的 render_scope 块 = 普通块，正常返回（不隐藏、不进 backing 逻辑）。

**验收**：
- 修前 fail / 修后 pass：一个 block-backed shape 的 backing 块被 trash（绕过 C1 直接造态，或用 fixture）→ 断言 **shape 对象+placement 仍返回**（geometry 在）、只是无文本；对比 paragraph_block_projection 的块死→整体不返回（保持 Stage-1 行为）。
- 断言一个带 render_scope 但无 live shape 拥有的 active 块 → 出现在正常读结果里、非隐藏。

### C3 · cascade：trash backing 块连带清 placement + mount（收 CR-8.11.4-02）

**问题**：server cleanup（canvasObjects.ts:690-727）trash backing 块时**只软 trash 块本身**，`note_block_placements` + `content_mounts` 行**从不清**（demote/delete 都如此）→ 孤儿累积、吃 order_index 槽。noteBlocks.ts:112 的软 trash 同理不级联。

**修**：backing 块被 trash（经 shape demote/delete）时，**同事务级联软 trash / 清其 note_block_placements 行 + content_mount 行**。
- **关键约束（与 C2/D2 的张力解）**：**软 trash（status），绝不 hard-delete**。因为 D2（re-promote 复用）要能 restore 回来。hard-delete 会让复用失效、且违「可恢复非数据丢失」。
- 与 Stage-1 liveness 过滤的关系：liveness 是**读时派生**（不写），C3 是**写时级联清 placement/mount**。二者不冲突——liveness 保证「即便 C3 没跑干净，读时也不漏 ghost」（纵深），C3 保证「底层不累积孤儿」（根治）。**读时派生仍是权威可见性**；C3 只清物理孤儿，不改可见性真相来源。

**验收**：修前 fail / 修后 pass：demote 一个 block-backed shape → 断言其 note_block_placements 行 status=trashed（或删）、content_mount 清；对比修前该行残留 active。

## 簇 D — 客户端生命周期

### D1 · demote 非破坏 + 非空确认（收 CR-8.11.4-06 · 产品红线）

**问题**：`demoteShapeText`（NoteWritingSurfaceLayer.tsx:1581-1602）静默软 trash 承载文本的块，只 toast、无确认、无「留成笔记」——用户写的内容静默进回收站，且恢复出来是 zombie（CR-8.11.4-03）。

**修**：按判断点 1 的裁决实现 = **(B) 确认后丢弃（Henry 2026-07-02 定）**：
- demote 前判断 backing 块文本**是否非空**（trim 后有内容）；非空 → 弹确认对话框（「此图形含文本，移除？文本将移入回收站，可从回收站恢复为普通笔记块」）。空 → 直接走（无确认）。
- trash 走 C1 放行的路径（demote 先 persist backing='none' 再 trash，天然合规）。
- 依赖 CR-8.11.4-03（D4）：确保回收站恢复出来可用。

**验收**：修前 fail / 修后 pass：demote 一个非空文本 shape → 断言弹确认；取消 → 块仍 active、shape 仍 backing；确认 → 块 trashed 且可 restore 成普通块。空文本 demote → 无确认直接成 pure。

### D2 · re-promote 复用/恢复 trashed backing 块（收 CR-8.11.4-05）

**问题**：`promoteShapeToBlockBacked`（NoteWritingSurfaceLayer.tsx:1504-1539）用 `findBackingBlockForShape(objectId, contentMounts, allBlocks)`（1509）找已有块，**看不见 trashed 块** → remove-text 再 add-text 每轮**新建**一个 backing 块，无界累积。

**修**：re-promote 时，先查该 shape 是否有 **trashed** 的历史 backing 块（按 shape_object_id）；有 → **restore 它并重连**（而非新建）。依赖 C3 的软 trash（没 hard-delete 才能 restore）。
- `findBackingBlockForShape` 或其上游需能感知 trashed 态；restore 走 D4 修好的 restoreBlock（重连时保留 backing 关系，不剥 render_scope——因为有 live shape 拥有）。

**验收**：修前 fail / 修后 pass：对一个 shape 连续 remove-text → add-text → remove-text → add-text，断言 backing 块总数不随轮数增长（复用同一块 id 或至多 GC 后恒定），对比修前每轮 +1。

### D3 · empty-text 自动 demote（收 CR-8.11.4-08）

**问题**：清空 shape 文本不 auto-demote → 留 active 空 backing 块，仍喂 AI 快照/搜索（体验测试 EX-S3-02 经 note-block API 实证 live）。

**修**：文本编辑保存时若结果为空（trim 后无内容）→ 自动走 demote（空文本分支，无确认），移除空 backing 块、shape 退 pure。或至少：空 backing 块不进 AI/搜索投影。**推荐前者**（auto-demote），与 D1 空分支一致。

**验收**：修前 fail / 修后 pass：把 block-backed shape 文本清空并保存 → 断言 backing 块被移除（shape 成 pure）、不再出现在 buildSnapshotFromNote/搜索；对比修前留 active 空块。

### D4 · restore 剥 render_scope 焊（收 CR-8.11.4-03 · 相对不焊绝对）

**问题**：`restoreBlock`（useNoteCanvasDataAdapter.ts:847-883）PUT `{status:'active'}` **原样恢复**、不剥 render_scope → 若其 shape 已不在，恢复出「看不见、删不掉、改不了」的 zombie。

**修**：restore 时按脊椎原则——**若无 live shape 拥有该块**（无 active backing shape 经 mount 指向它）→ **剥掉 render_scope='canvas_object_backing' 焊**（及相关 backing 元数据），使其恢复为普通可见可编辑块。若**有** live shape 拥有（D2 的重连场景）→ 保留 backing 关系。判定按 live 拥有派生，不按存的 render_scope。
- 服务端可提供一个「restore-block」语义端点或在 PUT-status→active 时下沉此判定（更权威，避免 client 绕过）；client restoreBlock 从响应 reconcile。**建议下沉服务端**（PUT-status→active 时判 live 拥有、无拥有则剥焊），与 C1/C2 同层，避免 relative 状态在 client 焊回。

**验收**：修前 fail / 修后 pass：trash 一个 backing 块 → 删除其 shape → 从回收站 restore 该块 → 断言块 active 且**无 render_scope 焊**、出现在正文流、可编辑可删；对比修前恢复出隐藏 zombie。

## 明确采用的判断（Claude 定，留余地给 Codex 依现状调）

- **CR-8.11.12-01 裁决**：不孤立补，并进本簇。主修 = C1 写侧守卫（生命周期归 shape，按 live 拥有判定）+ C2 读侧退化（dead-block→无文本图形）。与 demote（先卸 backing）、restore（D4 剥焊）同源，都是脊椎原则的落点。

  - C3-cascade vs D2-reuse → **C3 只软 trash 绝不 hard-delete**，D2 才能 restore。

## 验收标准（每条必有「修前 fail / 修后 pass」）

- C1：独立 DELETE live-backing 块 → 400 且图形不消失；demote/rollback 不被误伤；删 shape 只一次 server trash。
- C2：block-backed shape 的块死 → shape 保留成无文本图形；paragraph_block_projection 块死 → 整体不返回（保持 Stage-1）；无拥有的 render_scope 块 → 正常可见。

- D1：非空 demote 弹确认、取消不丢、确认可恢复；空 demote 无确认。
- D2：连续 remove/add-text N 轮，backing 块不随轮数增长。
- D3：清空文本 → 空块被移除、不喂 AI/搜索。
- D4：删 shape 后 restore 块 → 无 render_scope 焊、正文可见可编辑。
- E1/E2：extensionless hydrate 断言 inset/pageSize 保留或带 recovered 标记。
- E3：加正常块正控，去掉 COALESCE 即 fail。
