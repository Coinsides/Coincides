**⚠ 校正 register 前提**：CR-8.11.1-03 的 register 描述"没有 rebase"**已过时**。一套完整的 offset-rebase 引擎**已经上线**：`client/src/pages/Notes/canvasEngine/rangeRebaseService.ts`（280 行，`rebaseTextUnitAnnotationRanges` 97-190 处理 shift/contain/replace/overlap + 失效 176-177；`rebaseAnnotationsForTextUnitEdit` 192-236），且**已接进普通文本块打字**（TextBlockProjection.tsx:612 → `handleBlockTextFlowChange` NoteWritingSurfaceLayer.tsx:2086-2115 → rebase）。所以 CR-8.11.1-03 **不是"建 rebaser"，而是"补覆盖洞 + 块删级联"**——远小于 register 暗示的量，**不需要单独 stage**。

**脊椎（相对不焊绝对）**：parent 指针、child 列表、offset、block_id **全是 context-relative**；durable store 必须把 **live 关系当真相**、读/编辑时派生或失效，绝不留焊死的数字。具体：
- **parent 指针 = 唯一真相**；`child_annotation_ids` 是**派生缓存**（服务端每次写重算，client 已如此 173-186）。
- **offset** 是相对块当前文本的；编辑时 rebase 重派生（引擎已有），失效时**读时判定**、不焊 flag。
- **block_id** 是对 live 块的相对引用；块 trash（软删）时 range **读时显示为挂起**、块恢复自动复活——**绝不删 range 行**。

## 判断点（Henry 翻牌 ready 前请裁决）

1. **【必裁·repair vs reject】层级完整性（CR-8.11.1-04）修法**：服务端发现悬空/成环的 parent 指针时——**(A) repair-and-persist**（清掉违规指针、**保留 annotation 行**、可选告警）vs (B) 400 硬拒整个 PUT。**我荐 (A)**：守红线（用户 annotation 行绝不消失），只修指针；合法 UI 本就 client 预规范化、不会触发；(B) 只在裸 API 误用时干净拒绝但会误伤脏 legacy 数据的 backfill。
2. **【必裁·跨 note 层级是否合法】**：annotation 父子层级**能否跨 note**？critique 指出：note-scoped 批次里"重算 child 会丢掉跨 note 的子引用"。**若跨 note 层级合法** → 服务端**保留批次外无法解析的指针 verbatim（别清你看不见的）**；**若严格 intra-note** → 加迁移期断言、按 note-scoped 清理。**我倾向"严格 intra-note"**（annotation 是块上的标注、自然属单 note），但需你确认现有/legacy 数据没有跨 note 层级。
3. **【必裁·backfill 碰撞】036 遇真·跨 note 重复 id（CR-8.11.1-02）**：**(A) throw-and-abort**（回滚、清完脏数据后可重跑）vs (B) 自动补后缀。**我荐 (A)**：自动补后缀=迁移擅自 mint id、违 separation-of-truths（id 是 AnnotationTruth 的身份）。**确认你接受"036 可能在脏 legacy 上 HALT"**（一次性前向迁移、runner 保证只跑一次；HALT 后清数据重试）。
3.5. **【可裁·code/formula/shape 块能否带 offset 标注】（CR-8.11.1-03）**：若产品意图=这些块**不该**带 text_span offset 标注 → 更干净的修法是**创建时禁止**（而非把 rebase 接进每条投影）。但注意（critique）：禁止只挡新的，**已存在的**旧 offset range 仍需一次性 reconcile。**我倾向"接 rebase 覆盖"**（一致、不丢能力），你可选"禁止 + 一次性 reconcile"。
4. **【知会·非阻断】** 本单**不**加 schema 硬 FK（parent 自引用 FK / range.block_id→note_blocks FK）——那会硬拒跨 note/悬空/成环、和 (A) repair 立场冲突、且会 break 脏 legacy 的 backfill。留作**单独硬化 stage**（须排在 repair 迁移之后）。

## 三簇（按序执行）

### 簇 1 · backfill 可重跑、绝不静默吃 note（收 CR-8.11.1-02）· 先落

**问题**：migration 036 的 `insertAnnotation`（117-127）+ `insertRange`（129-141）都是 **INSERT OR REPLACE 进全局 PK**，legacy annotation id 非 note-namespaced 且弱唯一；两 note 同 id → 第二篇静默覆盖第一篇，且 legacy metadata strip（198-200）在**同一 per-note 循环内**跑 → 不可恢复。

**修**（`server/src/db/migrations/036_v2_annotation_truths.ts`）：
1. `insertAnnotation`（117-127）+ `insertRange`（129-141）**INSERT OR REPLACE → 纯 INSERT**（作为一个单元）。
2. `backfillAnnotationTruths`（109-202）：per-note 循环**前**先**预扫**所有 note 的 legacy `canvas_engine_annotations_v1`，发现跨 note 重复 annotation id → **在任何 insert/strip 前 throw、报出两个 note id**（判断点 3=A）。
3. **legacy metadata strip（198-200）移出 per-note 循环**，放到**所有 insert commit 之后的第二遍**——中途 throw 则 legacy（真相源）原样保留、可重跑。
4. **确保整个 `up()` 在单事务内**（runner 应已包裹；若否，本单必须补），使中途 throw **回滚所有 insert**，不留半截行阻塞重试（critique CONCERN #4）。
- **不采** register 备选"backfill 里 note-namespace PK"——偏离运行时 raw-id 方案（replaceNoteAnnotationTruths 用 raw client id, annotationTruths.ts:210）、且把 note 前缀焊进 annotation 身份、违相对不焊。

**验收**：两 note 各带**同 id** 不同内容的 legacy annotation，跑 036 up()。修前：只剩一行（第二覆盖第一）+ 两 note metadata 都被 strip。修后：throw 报两 note id、**两 note 的 legacy metadata 都未 strip**（可重跑）、无半截行。第二用例：两 note 不同 id → 干净 backfill，两行都在、两 metadata 都 strip。

### 簇 2 · 一个服务端完整性闸拥有层级 + range 引用完整性（收 CR-8.11.1-04）

**问题**：`replaceNoteAnnotationTruths`（`server/src/services/annotationTruths.ts` 165-257）DELETE 全 note 行后**逐条 verbatim INSERT**（parent 216、child 列表 217-220）、**零校验** → 悬空/跨 note/成环 parent、parent 与 child 列表不一致全部静默持久化。完整性全在 client（`annotationHierarchyService.ts` normalizeAnnotationHierarchy 131-198 + createsCycle 17-31）——durable store 信任其编辑器 = separation-of-truths 气味。

**修**：加服务端 `normalizeAnnotationTruthsForNote(annotations, batchIds)`（annotationTruths.ts），**逐字节 port** client 规范化的**解析顺序**：
1. **先** legacy child-list→parent 播种（镜像 client 139-155）——**必须最先**，否则 legacy 只有 child 列表的关系被丢（红线）；
2. `parent = parent_annotation_id || legacyParentByChildId`；
3. 清掉不在 batchIds（悬空/跨 note，见判断点 2）、self、成环的 parent——**repair 指针、绝不删 annotation 行**；
4. **重算 `child_annotation_ids` 自校验过的 parent、忽略传入 child 列表**（parent 指针=唯一真相）；
5. 每条 range：target id 对其 target_kind **非空**校验（text_span/text_unit/block 要 block_id；canvas_object 要 canvas_object_id）——同 helper、同事务。
- 在 `replaceNoteAnnotationTruths` 事务内、insert 前 invoke，override parent（216）+ child（217-220）。**簇 1 的 036 backfill 也走同一 helper**，所有 durable writer 收敛到一个闸。
- **⚠ critique 校正**：本 helper 只做 **intra-batch** 校验（非空 + 同批 parent 存在 + 无环）。它**不做**"block_id 是否指向 live 块"的存在性检查（那需 join note_blocks，本写路径不载）——**块级失效归簇 3 的读时派生**，别让簇 3 依赖本簇不提供的能力（修正 design 的 dependsOn 措辞）。

**验收**（裸 PUT 绕过 client）：payload 含 (i) parent 不在批次、(ii) 2-环 A→B→A、(iii) parent 与 child 列表不一致、(iv) 只有 child 项无 parent 指针的 legacy。修前：悬空/环/不一致全 verbatim 持久化。修后：悬空+成环 parent **清空**（行数不变、无删行）、child 重算与 parent 一致、legacy child-only 关系保成 child 上的 parent 指针。**加幂等正控**（critique CONCERN #3）：PUT→GET→原样再 PUT → 第二次产出**相同行**（无 updated_at churn、无 parent 翻转）——锁死 client/server 规范化一致，防加载时互相打架的脏写环。

### 簇 3 · rebase 覆盖每条编辑路径 + 块删读时失效（收 CR-8.11.1-03）· 后落

**问题**：rebase 引擎已存在但有**覆盖洞**——code/formula（BlockEditorLayer.tsx:343/353）、shape-text（NoteWritingSurfaceLayer.tsx:3506-3514）编辑走 `onBlockTextChange`+`onSaveBlock` **不发 `onTextFlowChange`** → 这些块上的 range **从不 rebase**；且 `trashBlock`（useNoteCanvasDataAdapter.ts:816-845）删块**从不碰 annotationTruths` → range 悬空。

**修**（**读时派生失效，不焊 flag**——critique 两个 blocker 的解法）：
1. **补覆盖**：把 code/formula/shape-text 编辑路径接进 `handleBlockTextFlowChange`（2086-2115），或按判断点 3.5 在创建时禁止 offset range（并一次性 reconcile 已存在的）。
2. **🛑 块 trash = 软删可恢复（noteBlocks.ts:133 UPDATE status='trashed' + restoreBlockById 可复活）——绝不删/清 range**。改为 **读时派生失效**：range 有效 ⟺ 其 block_id 解析到一个 **live（status='active')** 块**且** offset 未超当前文本长度。在 `hydrateAnnotationTruth`（annotationTruths.ts:98-130）/ client 渲染处按 live 块集**读时计算** → 块 trashed 时 range 显示为**挂起/needs-review**、**块 restore 时自动复活**（原 offset 还在）。**无新增 schema 列、无焊 flag**。只有块被**永久删除**（回收站清空的 hard-delete，若存在该路径）才 hard-purge range，且优先留"孤儿可见可重连"态而非静默删。
3. **修既存 overlap-cache 陈旧**（critique nit #7）：`rangeRebaseService.ts:176-181` overlap 分支把 range 推进 invalidated **却仍按 oldText 重算 range_text_cache** + 留旧 offset → 焊死的陈旧快照。改：overlap 失效时 **null 掉 offset**（读时派生视为未锚定），别假装有效。

**验收**：
- code/formula 块带 range 编辑文本 → 修前 offset 不变、指向错文本；修后 offset 位移或失效。
- **块 trash/restore 往返**：range 在块 B 上、trash B → **range 不删、显示挂起**；**restore B → range 原 offset 复活**（critique BLOCKER #1 的正确断言，取代 design 里错误的"reload 不复活悬空 range"）。
- overlap 编辑 → 失效 range 的 offset 被 null、不按错坐标渲染。

## 明确采用的判断（Claude 定，含 critique blocker 解法）

- **失效=读时派生、不焊 flag**（相对不焊）：range 有效性从"block_id 是否解析到 live 块 + offset 是否越界"读时算，不加 schema 列。若某场景确需存标记（如 block 仍在的 overlap），放**既有 `annotation_ranges.metadata` JSON**（036:71）当 advisory，别加新列。
- **块软删绝不删 range**（红线）：trash 可恢复 → range 挂起而非删；块恢复自动复活。
- **parent 指针=唯一真相、child 派生**；服务端 helper 与 client 规范化**逐字节一致 + 幂等正控**，防脏写环。
- **簇 2 只 intra-batch 校验、簇 3 管块级读时失效**——两簇不交叉依赖幽灵字段（修 design 的 dependsOn）。
- 顺序：簇 1（backfill）→ 簇 2（服务端闸）→ 簇 3（rebase 覆盖 + 读时失效）。

## 不做什么（本单边界）

- **不加 schema 硬 FK / cycle-guard trigger**（parent 自引用、range.block_id→note_blocks）——冲突 repair 立场 + break 脏 legacy backfill；归**单独硬化 stage**（排在 repair 迁移后）。
- **不删 `child_annotation_ids_json` 列**——本单让它成重算缓存；物理删列 + 纯读时派生是后续（重算稳定后）。
- **不做跨 block 结构性 rebase**（block merge/split/reorder）——本单只单 text-unit 编辑 + 块删；跨块结构 rebase 归后续。
- **不做 retroactive 数据修复**（036 已跑过、旧碰撞的 legacy 已 strip、无从恢复）——本单**预防性**。
- **不建 note clone 端点**（今 POST /notes mint 新 uuid、不 clone）——"clone 重碰撞 id"是未来向量。
- **不擅自改运行时 annotation id namespacing 方案**（createRuntimeId 13-16）——跨层决定，须 replaceNoteAnnotationTruths + createRuntimeId 一起定，标依赖、本单不动。
- 不推进 ContentGroup / Source / Agent / Relation。不整理 dirty workspace。
