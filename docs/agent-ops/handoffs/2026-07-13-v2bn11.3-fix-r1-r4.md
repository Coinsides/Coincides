## R1 · [MED,必修] 净库丢失 `idx_content_group_members_item`

侧修 #1 把索引从 schema.sql 移除后,它只活在 047 `rebuildContentGroupMembers` 的 rebuild 分支里;净库上 schema.sql 已建终形表(含 item_id)→guard `tableHasColumn(item_id)` 早退→**索引永不创建**。升级库有、净库没有=形状漂移,违反 11.2 plan"避免新空库与升级库形状漂移"。

**改动**:
1. 047 `up()` 在 `rebuildContentGroupMembers(db)` 调用之后、**guard 外**,无条件执行 `CREATE INDEX IF NOT EXISTS idx_content_group_members_item ON content_group_members(user_id, item_id);`(升级路径 rebuild 已建则 no-op;净库路径由此补上)。
2. 启动回归测试(`v2Items.test.ts` L103 那条)加**净库**分支断言:fresh `initDb` 后 `PRAGMA index_list(content_group_members)` 含该索引——两条路径都锁死,不再只测升级半边。

## R2 · [MED-LOW,必修] successor 必须 active

父 plan §3.1/§4.3 明文要求,当前 `assertSuccessorChainAcyclic` 只查环与归属。现有 L180-186 的"退役进已退役卡"用例**因环而抛**——错误理由的通过。

**改动**:
1. `retireItem` 对**直接后继**加状态检查:successor 非 active → 400(如 "Item successor must be an active Item");链上更深节点无需查(链中段天然退役)。
2. 专项测试:A→B(B 退役,无环),再 C 退役进 B → 被拒;错误消息断言与环用例区分开。
