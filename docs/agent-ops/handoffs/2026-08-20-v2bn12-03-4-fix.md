- **03 主单 MED-1 的成因**（reviewer 原话）：「现有测试覆盖 left/right outside 与**右侧 crossing**，却**没有左侧 crossing** 的完整 hydrate→normalize→save 链」—— **左右不对称的覆盖缺口，就是这条五轮长链的起点。**
- **03.4 之后的 recovery 矩阵**：persistence 有**左界** canonical crossing；对 `canvasEngine/**` 全扫，`[96,636]`（右界）命中 **0**。

**同一条左右不对称，方向镜像地复发在了 recovery 层。** 起点是「有右无左」，终点是「有左无右」。

**为什么不是活缺陷**：03.4 已把 framed receipt 接到**共享 classifier** 本体（`draftBlockPersistence.ts:157-165`，classifier 内容 SHA 与 03.2 preserved candidate 一致），几何判定不再有第二份实现 —— 所以右界不会因缺测试而算错。reviewer 亲调 classifier 验过两个方向都正确。**LOW 的定级对「当前是否会出错」是准的。**

**但作为回归护栏，它的缺口形状与那个把我们拖了五轮的缺口一模一样。** 建议补回时**不按「补一行 fixture」处理，而按「把 crossing 的左右两向在 recovery 矩阵里做成对称必备项」处理** —— 单补一行，下次换个轴（上/下界、多 frame 边界）还会重演。

> 📌 这条只有跨五轮回看才看得见：reviewer 每轮的累计扫描都在查「旧修复有没有打架」，而这是**新覆盖与最初病因的形状同构**，不在「打架」这个提问范围内。

### 三、反向校准（Fable 点名：体制不能只会挑刺）

逐轮看 FAIL 的定级是否过严 —— **四轮里三轮不过严，一轮的定级理由有缺口。**

| 轮 | 判定 | 我的校准 |
|---|---|---|
| 03 | FAIL 2H3M1L | **不过严，甚至克制。** 两条 HIGH 各有独立 fixture 复现到 durable 后果（用户正文丢失 / 误删并级联删另一 note 的 placement），HIGH 名副其实 |
| 03.1 | FAIL 2M1L | 不过严（三个窄负例在 03.2 被亲验忠实转绿，说明原判点准） |
| 03.2 | FAIL 2M1L | **不过严，偏宽松**。MED-1 是「storage 写失败后清掉唯一 v1 → reload 正文全失」，**后果是数据丢失**，只因触发条件（近 quota）不常见而记 MED。按影响本可 HIGH |
| **03.3** | FAIL 1M | ⚠️ **定级理由有缺口 —— 见下** |

#### 03.3 MED-1：现象证实了，**durable 后果没有被证实**

reviewer 证明了：矛盾 receipt（申报 `inside/frame-a`，几何实为 `outside/null`）通过 validator，`create` 消费了申报的 `crossing`，`placement` 又按权威几何改写成 `outside`。

**但它没有回答一个关键问题：改写之后，durable 行是对的还是错的？**

从它自己给出的证据看，`placement` 阶段是**按权威几何**分类的 —— 也就是说**最终落库的几何是正确的**。那么这条 finding 的实际损害是：①create 与 placement 两阶段之间的瞬时不一致；②recovery 成功后 forget 掉原 queue 证据，事后不可诊断。

这两条都是真的问题，**但它们和「durable 真相被写错」不是一个量级**。而 reviewer 的定级陈述里写的是「owner 漂移」「下一状态不是安全正规化」—— 读起来像后者。

**按 reviewer 自己的 §5-1 标准（能取的收据不取须说明、证人必须承载答案），这条应当附一个 durable-state 收据**：矛盾 receipt 走完全链后，落库的 `(surface, boundary_role, frame_id)` 到底是什么。它有能力取（全链都在内存 witness 里跑），但没取。

**我的结论：FAIL 判定本身我不推翻**（fail-open 于自相矛盾的输入，确实违反 03.3 R2 明文要求的「矛盾 tuple 一律 fail closed」，**违约是实的**）。**但定级陈述超出了它证明的范围** —— 应表述为「违反 fail-closed 契约 + 两阶段不一致 + 证据丢失」，而不是暗示 durable owner 被写错。

> 这与我在 01 单批评 builder 的「未复现 ≠ 已漂移」是同一类：**证明了 A，陈述成了 A+**。四轮里只出现这一次，且方向是「说重了」不是「放过了」——**体制的偏置方向是安全的**，但精确性该守住。

### 四、Fable 点名的另两处

#### ① 取证强度是否过度工程化（诚实的成本问题）

**技术选型本身：每一次升级都是被问题逼出来的，不是炫技。**

- `esbuild` 内存加载生产模块（03.2 起）：因为问题变成了「**当前 production 在 storage 写失败时做什么**」—— 静态阅读答不了，既有测试是 happy-path 也答不了。**这是唯一能承载该答案的证人。**
- live DB 字节级指纹：它回答的是「**我们碰过 live 吗**」—— 那是安全义务不是加分项。
- 504 文件 EOL-normalized union scan：回答「**有没有夹带**」。

**但成本问题是真的，且我能指出它具体贵在哪：**

> **全面取证的开销是「按轮数线性」的，而它所证明的变化量是「按轮数常数」的。**

03.2 / 03.3 / 03.4 三轮各自完整重跑了 D4 readonly 三件指纹 + 504 文件全扫 —— 而这三轮的实际代码差分分别是 12 / 4 / 4 个文件，且 D4 live 三件指纹**三轮完全相同**（DB `2c47907f…`、WAL 空、SHM `fd4c9fda…`）。

**建议协议（不降低强度，只降低重复）**：
- **首轮与终轮**：全面取证（建立基线 + 收口证明）；
- **中间轮**：**增量取证** —— 只对「相对上一轮 clean candidate 的差分面」做全扫，D4 指纹只比对与上轮记录的三个 hash 是否相同（相同即引用上轮结论，不同才展开）；
- **强制**：中间轮必须**显式声明**采用了增量协议及其引用的上轮基线 —— 否则就变成「悄悄少做」。

> 这条与 5-1「能取的收据不取须写明为什么不取」相容：**增量是声明过的范围收缩，不是沉默的省略。**

#### ② 对 builder 自报 RED 历史的处理 —— **我认为这是全链最精准的一处方法论**

03.3 §3.4：builder 自报 `7f/13p → 8f/14p → 3f/22p`，reviewer 判「无独立日志或中间 snapshot，精确历史数字只能记为 **builder receipt**，不能改写为 reviewer 亲证」，**但同一句里保留了「其核心 RED 因果仍成立」** —— 因为它自己在旧 snapshot `df09253` 上重放了两枚原 witness，稳定为红；当前树为绿。

**这个切法是对的，而且切得很细**：

```
承重的部分（RED 因果：旧红新绿）→ 自己亲验 → 记为 reviewer 收据
装饰的部分（中间过程的精确数字）→ 无法独立取证 → 记为 builder receipt，标明出处
```

它既没有**整体拒收**（那是过严：因果本身可验，拒收等于浪费可得的证据），也没有**整体采信**（那是洗白：把他人自述变成自己的收据）。

**建议把它一般化进角色卡**：**对他方自报的证据，按「承重 / 装饰」二分 —— 承重部分必须自验，装饰部分记为对方收据并标明出处。整体采信与整体拒收都是偷懒的两端。**

### 五、制度提案：mutation 判据三要素（Fable 点名，形制已验证有效，随本复盘一并交）

预登记的三要素在本链全部通过，**且通过的方式说明它们各自承重**。提请纳入 reviewer 角色卡（由 Fable 决定）：

> **mutation 判据三要素** —— 凡以「mutation 后主门必红」作为验收判据的工单，须同时满足：
>
> 1. **位点由裁定方或复核方点名**，不得由施工方自选。
>    *（施工方自选有挑「必然被现有断言覆盖」之处的动力：主门确实会红，但不证明护栏覆盖真实风险面。）*
> 2. **由对抗方执行**，施工方自测只作前置自查，不作验收收据。
>    *（自测的动机是「证明我过关」，对抗方的动机是「我要抓你」，方向相反。）*
> 3. **瞄准已证实的漏径**，不得任取一处。
>    *（任取一处只证明「有些改动会被抓到」；打已知漏点才证明「这次补的正是上次漏的」。）*
>
> **附验两条**（三要素全成立 ≠ 判据成立）：
>
> - **probe 必须可证还原**：`git diff --exit-code=0` + status clean，且**险情要披露**（本链有一次删临时文件遗留空行被 diff 抓到并还原的记录，正是该纪律有效的证明）。
> - **必须记录红在哪条断言上**。**形制对了而红在无关断言（如类型检查而非契约断言），判据仍然是空的。** 这是最容易滑过去的一条。
