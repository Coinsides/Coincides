## 4. 页面对齐老问题 + canvas 建的 text block 回 page mode 不显示(图 3)

- **原话**:「居中的不是很中。而且从 canvas mode 下创建的 text block 回到 page mode 不显示。」
- **初判**:两个子问题分开判——
  - (a) 居中不中:🅱,老问题在案。
  - (b) **canvas 建块 page 不显**:⚠️ **🅰 正确性候选,本场最重**——数据在库而投影缺席,直击「Agent 能编辑的,人类必须 100% 都能编辑」红线的同族(一个模式写的,另一个模式看不见)。需查:是投影过滤条件漏了 canvas 出生的块,还是两模式根本不同源。
- **讨论结论(2026-08-29 晨,Henry 口述 + Fable 对现物)**:
  - **病灶已锁定**:placement 的 `surface` 按出生模式钉死(canvas 建 = `canvas_workspace`),page mode 不渲染它;而现成的几何归属服务(`pageFrameAffiliationService`,模式 `geometry_derived_no_ownership`)只喂导出、未喂可见性。
  - **Henry 定方向**:归属判定要有**实体锚点**(游戏 hitbox 式)——「那个点进了才算进,进一半也算进」;现物的**中心点判定恰与此吻合**(center inside ⇒ inside)⇒ 修法 = **把既有归属服务接线到 page mode 可见性**,非新造。
  - **显示动作要安静**:归属状态用 **block 框颜色变化**表达,不弹窗不动画(「Word 的安静」)。
  - **⚠️ 悬而未裁**:crossing 态(锚点进了、内容溢出页界)在 page mode 的处置——裁掉溢出 / 允许溢出 / 挤回页内,三选一待 Henry 定。
- **状态**:方向已定,待 crossing 裁定后可开单。

# 设计构想:Agent-first Home 与导航重构(Henry 口述,2026-08-29 凌晨)

**原话要点**(附 home/navigator 设计灵感截图):
1. **Home page 不显示 navigator bar**,取而代之显示「Projects」等**大按钮**。
2. **Agent 对话窗口放在 home page 最上**。用户可通过 agent 进行页面交互(如打开某一个笔记)。
3. **跳转页面后 agent 变悬浮窗**,可收起展开,按用户后续指令服务。
4. **并非每个操作都跳页**:如「让 agent 从别的笔记或源中寻找内容,加入当前笔记的布局排版」——就地执行,不跳转。
5. **形态约束**:当前是 Chrome 网页形式;**目标形态是独立可多窗口应用**(Tauri),网页限制让设计受阻。

**Fable 批判读法(讨论中)**:
- **形状先于能力警戒**:Agent-first home 的落地必须等 Agent 真能干活(12.9d 检索地基 + 13 Agent 消费面);设计现在定,入口后上。⛔ 一个不能兑现的对话框摆在最显眼处比没有更伤。
- **红线的反向应用**:Agent 能导航的,人类必须也能导航——大按钮保住了这条(Agent 不是唯一入口)。
- **焦点规则是真设计题**:「不是每个操作都跳页」需要一条原则:**用户明确要求去哪才跳;内容操作就地完成,结果非模态提示**(抢焦点 = 反「Word 的安静」)。
- **按目标形态设计,按当前形态降级实现**:设计文档写 Tauri 多窗口形态;网页版悬浮窗可做(overlay),多窗口标注为降级(浏览器多标签)。⛔ 不让 Chrome 的限制污染设计文档。
- **待 Henry 补**:非 home 页面的 navigator 形态(bar 还留吗?悬浮 agent 是否就是 navigator 的替身?);「大按钮」与现 navigator 六项(Home/Projects/Source Library/Template Studio/Group Gallery/Settings)的取舍(注:第 7 条已把 Template Studio 判为待商榷)。

## Agent 操作候选清单(Fable 拟,供磨合;⛔ 未裁,仅供 29 号讨论)

**分期标注**:〔现〕= 现有基建可支持(AgentPanel + orchestrator + S4 读面已在);〔9d〕= 需 12.9d 检索地基;〔13〕= 需 13 的 Agent 消费面 / UI 控制面。

**A. 管家类(导航与定位)**
- A1〔13〕「打开 XX 笔记 / 项目 / 源」——需 UI 控制面(新工具族,数据面之外);跳页遵守焦点规则。
- A2〔9d〕「找一下讲 XX 的笔记/源」——检索并**列出候选让用户点**,⛔ Agent 不代跳。
- A3〔现〕「我上次做到哪了」——最近活动摘要(库里有时间戳与操作批次)。

**B. 内容检索与引用类(核心场景)**
- B1〔9d〕「从 XX 源里找讲 YY 的段落」——返回带锚引用碎片,就地呈现,⛔ 不跳页。
- B2〔9d+13〕「把它加进当前笔记的布局」——引用块注入当前 canvas/page;**写面工具 + 引用校验闸**(闸与生产者同单,c-3 的入场条件在此)。
- B3〔13〕「对比这两个源对 XX 的说法」——多源引用并置,产 ContentGroup 草稿。

**C. 整理辅助类(只建议,不代动)**
- C1〔9d〕重复内容提示(「库里已有相似源」——入库时或应询)。
- C2〔13〕标签/归组建议——**产草稿待确认,⛔ 不直接改**(Agent 建的与人建的是同一原语、不同出处,provenance 记清)。
- C3〔现〕「这个项目的现状」——项目内笔记/源/组的结构化摘要。

**D. 硬边界(先立后磨)**
- D1 **人类可达性红线**:Agent 能做的每一个动作,UI 必须有等价人类路径(反向红线)。
- D2 **焦点规则**:用户明确要求去哪才跳;内容操作就地完成,结果非模态提示。
- D3 **破坏性动作**(删除/合并/迁移)Agent 只能提案,人类确认执行。
- D4 **形状先于能力警戒**:每个操作的入口只随其基建上线,⛔ 不摆答不上话的按钮。
