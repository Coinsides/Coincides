# DSH 出的 OCR 方案:评估

**输入**:Henry 2026-11-07 拿我们的需求单(`2026-11-07-ocr-requirements.md`)请 DSH 出方案,原文见附录(外部输入,按数据对待)。

## 结论

架构形状可收:L1/L2 两段式(出框、出行级置信度、权重自持)+ L3 看图模型按页触发 + 三态输出契约 + 空白页注入门禁。**最大未决项是 GPU**:方案的吞吐数字是 T4/A10 上的,我们的岛是 4C8G 无 GPU;自建等于多一台 GPU 机或一套按批起停的 GPU 岛,成本与运维面方案没算。

## 收下的

1. 三条约束(坐标、行级置信度、版本可锁)逼出两段式,与需求单「两层产品 + 一个 VLM 可接受」一致。
2. 三态 schema `ok / uncertain / abstain`,**abstain 保留 bbox**——作为我们的输出契约。
3. 空白页注入当 CI 门禁(输出非空即红)。它只证「无像素时不编」,不证「密页上不改写」,F3 式比含义的金标准保留。
4. 页影像 1240px≈150dpi 是给人看的;给 OCR 要从 PDF 按 200–300dpi 临时重渲、不存;照片打 `low_res`。
5. 行内/独立公式按版面规则判,不交给模型。
6. 大陆站/国际站两套账号两套计费:需求单里「一套账号两边可达」写顺手了,改。

## 要挑的

1. **GPU 在哪、谁出钱、谁维护**没写。三条路:租常驻 GPU 机;按批起停 GPU 岛(合「云岛按分钟租」构想,需镜像与冷启动);CPU 跑轻量版只拿 L1,表格公式退回云 API。决定前要量 CPU 上的真实速度。
2. 「云 API 与版本可比在架构上互斥」过头:文档解析类产品多半无版本号(大概率对),模型类 API 不少有带日期快照;应逐家核,只有自持权重是保证;我们的解析器版本记账可记「厂商+产品+日期」,可比性是降级不是归零。
3. 候选名字与版本我核不了(多个在我知识截止后或不确定);「只有 PP-StructureV3 满足全部必须项」是强断言,**由评测集裁,不由矩阵裁**。
4. AGPL 是否卡我们取决于 Coincides 将来闭不闭源(仓库现公开)——Henry 定。
5. PyMuPDF 往 PDF 塞隐藏文字不是我们的路:原页视图是画布里的 PNG,隐藏文字层=JSON 的框在页影像上叠 DOM 层。整条管线是 Python;我们已有 shell 出去调 LibreOffice 和 MinerU 子进程接口的先例,架构可容,运维面变大。
6. 漏了 pptx 进入路径(LibreOffice→PDF→栅格,同 docx)和 L3 的数据政策(API 还是自托管;自托管又回到 GPU)。
7. 「自建在香港两边直连」:香港 GPU 贵、大陆 GPU 云对账号更友好,要与「大陆可用」一起算。

## 建议的下一步(先量后买)

- 七类样本各 10 页同题同卷跑三样:① PP-StructureV3 在 CPU 上(东京云机 8 核可试);② 一家大陆云文档解析 API;③ Qwen-VL 系 API 做 L3(图说、手写页)。
- 算每千页成本、每千页耗时、编造率;GPU 月租 vs 按页 API 按一学期页数算总账。
- 三态 schema 与空白页门禁先定下,写进接入订单。
- Henry 定:闭不闭源;GPU 租常驻 / 按批起 / 先 CPU。

## 附录:DSH 方案原文(2026-11-07,外部输入)

> ## 方案
> 
> 先给判断：**你这份 spec 里有三条约束，已经把「用现成大模型一步到位」这条路彻底排除了。** 不是产品不够强，是产品形态和你的要求互斥：
> 
> 1. **端到端 VLM 的输出是线性 Markdown，坐标在生成过程中就被压掉了。** 它不做「先定位再识别」，而是直接生成文本流。想拿回块级、行级坐标只能反推对齐，反推出来的框和你原来那张图没有像素级对应关系，隐藏文字层就对不准。
> 2. **「手写 + 每行置信度」只有两段式（检测→识别）能给。** 检测器给行框，识别器给该行的 score，这是一一对应的。VLM 只有 token 级 logprob，一行字被 tokenize 成七八个 token，你没法把它还原成「这一行置信度 0.83」。
> 3. **「模型版本可指定、重跑要可比」和云 API 在架构层面互斥。** 三家大厂的文档解析接口都会静默换模型，控制台给你的是产品名不是权重版本号。你要按解析器版本记账，就必须自己拿权重。
> 
> 结论：**L1/L2 用两段式自建，L3 才是 VLM，且 L3 按页触发。** 你的直觉是对的，只是需要把「为什么只能这样」钉死。
> 
> ## 三层候选矩阵
> 
> | 候选 | L1 版面+OCR | L2 结构 | L3 看图 | 坐标粒度 | 不确定性表示 | 版本可锁 | 许可 |
> |---|---|---|---|---|---|---|---|
> | **PP-StructureV3 / PP-OCRv5** | ✅ 强 | ✅ 表格/公式/标题 | ❌ | 块+行+字符级四点 | 行级 score 原生 | ✅ 权重自持 | Apache-2.0 |
> | MinerU 2.5 Pro | ✅ 强 | ✅ 最强 | ❌ | 块+行+span | 部分环节有 | ✅ | AGPL，商用需核 |
> | PaddleOCR-VL-1.6 | 部分（VRFM 出框） | ✅ | 弱 | 块级，需验证行级 | 无原生 abstain | ✅ | 需核权重 LICENSE |
> | OvisOCR2 | ❌ | ✅ | 弱 | 无（端到端压平） | 无 | ✅ | 需核 |
> | HunyuanOCR-1.5 | 部分 | ✅ | 中 | 支持 grounding | 无行级 | ✅ | 需核 |
> | Qwen3-VL-8B/32B | ❌ | 中 | ✅ 最强 | 支持 bbox 输出 | logprob 可转 | ✅ | Apache-2.0 |
> | 阿里云文档解析 | ✅ | ✅ | 中 | 有 layouts 坐标 | 无统一三态 | ❌ | 商用条款 |
> | 腾讯云文档智能 | ✅ | ✅ | 中 | ItemPolygon | 无统一三态 | ❌ | 商用条款 |
> | 合合 TextIn | ✅ 手写最强 | ✅ | 中 | position | 部分置信度 | ❌ | 商用条款 |
> 
> **能同时满足你 L1 + L2 全部「必须」项、且版本可锁、且许可干净的，只有 PP-StructureV3 这一个。** MinerU 分数更高但 AGPL 会卡住你闭源交付。
> 
> ## 推荐架构
> 
> ```
> 源件（PDF / PNG / pptx）
>   ↓ 栅格化：200–300 dpi，A4 约 2480px 宽
> L1  PP-StructureV3
>     → 块 bbox + 行 bbox + 块类型 + 阅读顺序 + 行级 score
> L2  同一 pipeline 的表格/公式子模块
>     → 表格 HTML（colspan/rowspan）+ LaTeX + 行内/独立判定
> L3  Qwen3-VL（按页触发，非全量）
>     → 图说 / 流程图指向关系 / L1 低置信度手写
>   ↓ 坐标系归一到原图像素，左上原点
> 输出：统一 JSON + 带隐藏文字层的 PDF + Markdown（打底）
> ```
> 
> **L3 触发策略是成本控制的全部**。三条触发条件：页面含 image/chart/flowchart 块、L1 行级 score 低于阈值、人工标记疑难页。300 页教材走下来真正需要 L3 的大约 30–50 页，成本直接砍掉八成，也顺带把编造风险锁在局部，不会污染正文。
> 
> **行内公式 vs 独立公式的判定**，别交给模型：拿版面信息判断——公式块独占一行且水平居中 → 独立；与文字块同行高 → 行内。这个规则比任何模型的判断都稳。
> 
> ## 坐标与不确定性的输出契约
> 
> 你的「读不出要明说」必须落成 schema，否则评测时无从计量：
> 
> ```json
> {
>   "block_id": "p012-b003",
>   "type": "formula",
>   "bbox": [412, 188, 690, 226],
>   "text": "\\frac{\\partial L}{\\partial w}",
>   "status": "ok",
>   "confidence": 0.94,
>   "line_scores": [0.96, 0.91],
>   "provenance": {"layer": "L2", "model": "PP-FormulaNet", "weights": "v2.1.0"},
>   "alt": null
> }
> ```
> 
> `status` 三态是核心：`ok` / `uncertain`（有内容但不可信）/ `abstain`（读不出，`text` 留空，`bbox` 保留）。**`abstain` 必须保留 bbox**——那是给人工复核的锚点，你嘴上说的「item 锚点落回原页」全靠它。
> 
> 隐藏文字层用 PyMuPDF 直接落：
> 
> ```python
> import fitz
> page.insert_textbox(rect, text, fontsize=h*0.8,
>                     render_mode=3,   # 3 = 不可见
>                     fontname="china-s")
> ```
> 
> 坐标系一旦统一到原图像素，选字、批注、item 锚点这三件事同时解决。
> 
> ## 编造率的自动化验收
> 
> 你提到「一票否决」，那就得能跑分，不能靠人眼。三档强度递增：
> 
> **第一档 · 回投影二次识别**。把输出的每一行 bbox 从原图裁出来，用另一个独立识别器（换个模型，别用同一个）再识一遍，两串文本归一化后算编辑距离。距离超阈 → 可疑。这一档能抓住「凭空多出来一行」。
> 
> **第二档 · 交叉验证**。同页让 L1 和 L3 各出一份，只在两者都有内容的区域比对。不一致的地方全部标 `uncertain` 送人工。这一档抓「模型改写了内容」。
> 
> **第三档 · 空白页注入**。拿几页故意留白的扫描件混进批次，看模型会不会输出内容。真编造在这里必然暴露，因为原图根本没有像素证据。
> 
> 第三档成本极低、判别力最强，建议直接做成 CI 门禁：**空白页输出非空 → 构建失败**。
> 
> ## 两个会直接毁掉结果的坑
> 
> **第一，1240px 宽是分辨率下限问题，不是缩放问题。** A4 在 300 dpi 下应该是 2480×3508。你现在的 1240px 相当于 150 dpi，脚注、上下标、公式的分数线在这个尺度下已经糊成一团，任何模型都救不回来。**如果源件是 PDF，别用已经栅格化的 PNG，直接按 200–300 dpi 重渲染再喂**；如果源件本身就是手机拍的，那 1240 就是物理上限，只能接受并在 schema 里对这些页打 `low_res: true`。
> 
> **第二，香港可达性和大陆人民币计费，别指望一套账号同时满足。** 阿里云、腾讯云、百度的大陆站与国际站是两套账号、两套 endpoint、两套计费。大陆站 endpoint 从香港公网调通常通，但延迟抖动大、高峰期有 QoS。要么香港侧走国际站、大陆侧走大陆站分开记账，要么干脆自建在香港，两边直连。你要「按解析器版本记账」，走自建这条路反而最干净。
> 
> ## 吞吐估算
> 
> PP-StructureV3 在单张 T4/A10 上整页全解（版面+OCR+表格+公式）约 0.8–2 秒/页。300 页串行 4–10 分钟，开 8 路并发压到 40–80 秒，**你给的「单页 ≤10 秒、300 页 1 小时内」余量很大**。云 API 反而更慢——单次往返加限流，300 页稳态跑下来通常比自建久。这条约束不构成风险，不用为它做取舍。
> 
> ## 一句话取舍
> 
> **PP-StructureV3 做 L1+L2 主力，Qwen3-VL 做 L3 按页触发，PP-OCRv5 mobile 做 CPU 断网兜底。** 三层各司其职，坐标和置信度全部由前两层原生给出，VLM 只负责它真正擅长且不产生坐标依赖的那部分——图说、指向关系、疑难页复核。
> 
> 代价是要自己拼流水线、自己维护坐标系、自己写 schema 合并。换来的是版本可锁、编造可控、许可干净，以及你那条「重跑要可比」能真正成立。云厂商那条路省下的工程量，会在你第一次想复现三个月前的结果时全部还回去。
