# b-2b 采购探针:zip 解包候选四维实测

**装在仓外** `v12.9-selection/tools/zip-probe/`。⛔ **采购未决前不让候选在生产依赖树上占位**(与 sqlite-vec 探针同规矩)。

## 0. ⭐ 结论摘要:**这是权衡不是胜负,而且默认值两边都不是我们要的**

| 维 | **jszip@3.10.1** | **yauzl@3.4.0** |
|---|---|---|
| **① 流式与内存** | ⚠️ `loadAsync` **整包进内存**;条目可 `nodeStream` | ⭐ **`lazyEntries` + `openReadStream` 逐条目流,整包不入内存** |
| **② 条目路径规范化** | ⚠️ **静默改名**:`../escaped.txt` 被拆成 `/` 与 `escaped.txt` | ⭐ **默认整档拒收**:`invalid relative path: ../` |
| **③ 维护状态** | 最新 3.10.1,**registry 最后变动 2025-03** | 最新 **3.4.0**,**registry 最后变动 2026-06** |
| **④ 声明状态**(复核方加的维) | ⚠️ **幻影**(TD-35:三处未声明,靠 `mammoth` 传递)| **真新增**(诚实的一次采购) |
| **漏洞** | audit 0 | ⚠️ **3.2.0 有 moderate off-by-one;3.4.0 已清零** |

⚠️ **阳性对照先行**:两库**都能读出正常条目**(yauzl 用干净档验)⇒ 后面的观察归得了因。

## ⭐ 1. 最重要的一条:**jszip 的静默规范化会毁掉我们必须申报的证据**

我们的教义是 **「降级收下 + 如实申报」**,而 **「降级的证据链就是那些原拒收理由」**。

- **jszip**:`../escaped.txt` 进去,出来变成 `/` 和 `escaped.txt` —— **上跳被消解了,但原始名也没了**。
  ⇒ ⚠️ **应用层拿不到「这个条目试图上跳」这条事实,因而无法申报。** **不炸,但投毒无痕。**
- **yauzl 默认**:**响亮拒收整档** —— **有痕,但整档皆失**(与 b-2「坏 zip 不炸整批」冲突)。

⇒ **两边的默认值都不是我们要的形状。**

## ⭐⭐ 2. 但 yauzl 有第三档:`decodeStrings: false`

| yauzl 选项 | 实测行为 |
|---|---|
| 默认 | 读到 `docs/`、`docs/normal.txt` 后 **整档报错** `invalid relative path: ../` |
| `strictFileNames: false` | ⚠️ **无效** —— **仍整档报错**(该旗管的是反斜杠,不是上跳;⚠️ **复核方原以为它是那个开关,试了才知道不是**)|
| ⭐ **`decodeStrings: false`** | ⭐ **原始条目名原样交出**(`../`、`../escaped.txt`)**且不报错** |

⇒ ⭐ **yauzl 能支持「逐条目自判 + 保留原始名作证据」** —— 正是「降级收下 + 如实申报」要的形状。
⚠️ **代价**:名字变成 `Buffer`,**编码解码得我们自己做**(该库不再替我们处理)。

## 3. 四维之外的两条如实记

1. ⚠️ **是我随手挑的版本引入了那个漏洞**:我先装 `yauzl@3.2.0`(有 moderate),**升到最新 3.4.0 后 audit 归零**。
   ⇒ **「候选有漏洞」必须按【你真会采用的那个版本】去查**,⛔ 不能按手边随便装的版本给候选定罪。
2. **两个候选的真实采购成本都不是零**:jszip 看着「已经在树上」,**但它是幻影**(TD-35)⇒ 它的成本同样是**声明 + 接门**两件事。

## 4. ⛔ 不预设赢家 —— 给裁定方的三个问法

1. **「坏 zip 不炸整批」要多严?** 若要求**逐条目降级**,则默认档两边都不合格,**只有 yauzl 的 `decodeStrings:false` 路径够得着**;
2. **「自己解码条目名」这份工作我们接不接?**(那是 `decodeStrings:false` 的价钱)
3. **流式是否是硬要求?** 若入库允许整包进内存(源文件体量有上限),①维的差距就不承重。

**探针脚本**:`zip-probe/probe.mjs`(四维 + 阳性对照)· `probe2.mjs`(yauzl 三档选项对比)。
