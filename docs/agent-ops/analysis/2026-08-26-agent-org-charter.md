# Agent 时代组织总纲(收敛稿)

**一句话**:用户视角里只有一个 Agent;工程与设计的分工是我们内部的实现细节,永不暴露。

## 1. 四层收敛(本文核心)

1. **一个对话窗** —— 永远在 Coincides 里。⛔ 不把应用做成任何 harness 的插件(主客关系反转会撞「流不断」公理,且把产品降格为附件)。
2. **一个统筹者岗位**(Mr. Zero) —— 剧本(怎么接需求/怎么验收/什么算合格)与道具(工具面)**都是我们的**。
3. **演员可换** —— dsh 首选(MIT/TS 同栈/模型可换/声明支持被驱动会话),OpenClaw 备选,将来谁都行。
4. **工程/设计的分工,用户永远看不见**。

⭐ **由此,「harness 配置地狱」被结构消灭**——不是因为配置做得好用,是因为用户根本不需要知道后面有几个人。

## 2. 统筹者的真正职责(不是分派)

接住模糊需求 → **补上用户没说但必须有人想到的**(例:「跟随的变量表」里,表的数据从哪来)→ 分派 → 验收 → **落库**。
分派是次要的;**接缝上的活才是它存在的理由**。

## 3. 剧本在我们这边(核心判据)

统筹逻辑 ⛔ 不住在 harness 里。⇒ 换 harness = 换演员念同一份台词,**不 fork、不改源码、闭源开源皆可**。

> ⭐ **判据**:若发现「必须改 harness 源码才能做成这件事」,**八成是把本该住在我们这边的东西错放进了 harness**。
> 同族先例:来源可靠性判断(哪些站可信、哪些不可)必须收回门里——寄生在 harness 上则换一个就没了。

- **可加工的是资产,不是行为**:把我们的 token 预设做成一套设计系统喂给 open design=合理;改它的运行逻辑=不该有此需要。
- **依赖形态**:锁版本依赖 + 一键安装脚本(`npm run setup:agent`),⛔ 不 vendor 源码(fork=背上合并上游的义务)。

## 4. 岗位收缩(推翻 08-25 会议记录的四岗划分)

| 岗 | 谁 | 干什么 |
|---|---|---|
| **统筹者**(Mr. Zero) | dsh / OpenClaw / 任意 | 接需求、调工具、验收、落库 |
| **采购员**(统筹者的能力之一) | 同上(自带网搜) | ⭐ **零素材起步**场景:用户手里什么都没有,Agent 去外部世界把材料找回来、入库、建引用 |
| ~~工程部 / 设计部~~ | —— | **不是岗位,是统筹者手里的两种工具**;用户不可见 |

- **open design**:降为登记备查(可加工资产,产房时代再议),⛔ 不入日常客工名单。
- **内置薄地板**:应用自带最小对话面(填个模型 key 即可用),保证**开箱不空**;它是地板不是天花板,装 harness 即可增强。

## 5. 组件的三条裁定(重要松绑)

1. ⭐ **组件是数据,不是代码** —— 用户造的组件进他自己的组件库,**不进产品仓库**。⇒ 造组件**不必等产房**,V12 之后即可做(推翻此前「要等产房」的说法)。
2. **组件的出生证有两样**:
   - **旋钮**:我能被怎么调(颜色/尺寸/档位)→ 应用侧通用旋钮面板读它自动渲染
   - ⭐ **食谱**:我需要什么数据才能工作(例:`{符号,含义,备注}` 列表)→ **壳一份,数据各是各的**,同一组件插到数学笔记与财务笔记显示不同内容
3. **三种落位**(组件自己声明):①钉在画布坐标 ②插在页面流 ③**附着整篇**(悬浮/跟随类)

## 6. 设计造壳,工程造插座

- **纯展示组件**(排版/卡片/图表样式)= 全是壳,设计一家做完,零工程介入。
- ⭐ **有状态组件**(限时试卷/清单/打分器)——**它记住的东西去哪?**
  - 存组件肚子里 ⇒ **真相层之外的第二份事实**,违反分离真相原则 ⛔
  - 进真相层 ⇒ 需要**我们提供的、受控的、留收据的**通道
- ⇒ **「地板组件」的真实工作量不在渲染 HTML(几乎白送),在定义那套插座**:能读什么、能写什么、写完留什么痕迹。
- **工程活有限且收敛**(插座+出生证格式,一次性);**设计活无限且随需求生长**。

## 7. 一个对称(12.4 设计输入,未拍)

**Agent 经工具面动真相层;组件经插座动真相层** —— 本质同为「外来者受控地碰真相」。
⇒ 两者是否共用同一套守卫/收据/可撤销约定?**倾向共用**。若成立,12.2 建的这道门顺手也是给组件建的。

## 8. 画布 / 页面 / 导出(解「逻辑绕」)

三者**不是并列模式,是同一份真相的三种呈现**:

| | 是什么 | 性质 |
|---|---|---|
| **画布** | 想的时候 —— 碎片、并置、**位置本身即意义** | 携带空间信息 |
| **页面** | 说出来的样子 —— 有头有尾,能给人看 | 线性流 |
| **导出 HTML** | 把某一刻**凝固**下来带走 | 快照 |

⭐ **绕的根源**:画布→页面必须丢掉空间并发明读序,页面→画布必须凭空造出位置 —— **它们天生不对称,是有损投影,不是对称视图**。
**导出难度**:画布元素自带坐标尺寸 ⇒ 「照片」(交互冻结)几乎白送;「活的」(组件仍可交互)需连带运行环境,贵一档。**建议先做照片。**
