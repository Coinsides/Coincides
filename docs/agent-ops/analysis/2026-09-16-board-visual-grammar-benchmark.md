**跨家共识(≥4 家收敛的做法,可视为行业地板)**:
1. 连线词汇全部**封闭枚举**、拒绝自由贝塞尔(FigJam/Whimsical/tldraw/Miro/Excalidraw)。
2. 箭头=**两端独立属性**,默认「起点无+终点轻箭头」或「双端无」(Miro/FigJam/Obsidian/tldraw/XMind)。
3. 边标签**属于线对象**、锚线中点或沿线参数化、以**遮线**(垫底/擦线/描边)保可读(全部七家中有六家)。
4. 层级不设语义字段,用**少档位离散样式轴**让用户手工表达(FigJam/Excalidraw/tldraw/Miro)。
5. 色板**策展收敛**+派生,不开全量取色器(Excalidraw/tldraw/FigJam/Miro/Whimsical)。

## 二 · 提炼的视觉语法建议

### ① 轻量便签节点件的形态

| 规则 | 内容 | 出处 |
|---|---|---|
| **定宽两档,只纵向长高** | 方形/宽形两档固定宽度,文字溢出只向下生长,字号恒定不随内容缩放 | FigJam sticky(240/416 定宽);反面:Miro Auto 字号致同板字号不一致 |
| **一种卡形,类型靠内容** | 不给便签开形状词汇;便签与笔记引用卡同框同交互,分化点只在内容渲染 | Obsidian Canvas(text/file 卡同形);反面:XMind 31 形状 |
| **默认中性底色** | 新建便签默认无彩色(用 `--bg-elevated` 级 token),颜色永远是用户显式赋予的强调 | JSON Canvas「默认无色=中性」;反面:FigJam 随机派色伪造分类信号 |
| **中等字重保小字可读** | 便签正文直接用 Medium 字重 | FigJam 刻意选 Inter Medium |
| **远景降级标签** | 缩放低于阈值时,便签取**首行/摘要**充当大号远景标题——补掉 Obsidian text 卡缩出变空白的裂缝 | Obsidian 缩放阈值机制+其社区公认痛点 |
| **克隆手势** | 便签边缘拖拽即生成相邻同款便签(连+建一手势) | tldraw clone handle;Miro 蓝点拉线建物件;Whimsical 四侧加号 |

### ② 连线族词汇表(最小集,⛔过度设计)

Coincides 的板上线是纯视觉线,词汇整体落在 XMind「自由关系线」一侧(细、可曲、箭头可选),**永远不需要**结构线/端口/路由器那套。

**v1 最小集(每轴档位刻死)**:

| 轴 | 档位 | 默认 | 出处 |
|---|---|---|---|
| 线型 | **弧线一种**(三点圆弧:两端点+一个 bend 标量) | 微弯弧线 | tldraw arc——曲线优于直线正是为「节点换位后仍不难看」,单 bend 手柄把曲率编辑收敛到一个点;⛔不做肘线路由(tldraw elbow 无 waypoint 是其开放 issue,复杂度不值) |
| 虚实 | 实 / 虚 2 态(v2 可加点线) | 实 | Mermaid 三线型语义、FigJam dashPattern |
| 线重 | **3 档等比阶梯**(细/中/粗) | 细 | Mermaid 常规/粗=主干;反面:Whimsical 两档跨度过大、Miro 1–24 连续档致全板线重不一致 |
| 箭头 | 两端独立,每端 **3 值:none / 箭头 / 圆点** | 起 none + 终 none | JSON Canvas fromEnd/toEnd 模型(一个数据模型覆盖无向/单向/双向,不设"线类型"枚举);**默认双端无**比 Miro 的默认燕尾更贴纯视觉线定位——方向是可选修饰不是默认负担(XMind 规则) |

**端接与跟随(最低机械,没有它挪卡即散架)**:
- 端点拖近节点→节点出**淡色轮廓高亮**预告可绑→松手即绑→节点移动线自动跟随(Excalidraw 绑定三件套,连自由文本不跟线都被其用户当 bug 报)。
- 绑定默认**指节点中心+与卡片圆角矩形轮廓求交**,交点即线终点,带箭头端回退一个小间隙(tldraw 端接,不做端口/锚点枚举)。
- **绑定豁免**:按住修饰键(如 Alt)拖端点=不吸附;已绑线提供显式解绑手势(Excalidraw 误绑是其 top 抱怨、issue 多年 BLOCKED)。
- 样式惯性:新画的线沿用上一条线的样式(Miro 社区高票未实现请求;tldraw last-used、Whimsical 样式继承已证明有效)。

**⛔ v1 明确不做**:肘线正交路由、避障自动布线、waypoint、ERD 端点、自由贝塞尔、逐线自由线宽。

### ③ 线色线重的主次语义方案(token 表达)

借 FigJam「灰承担结构、彩承担区分」+ tldraw「色名→角色派生变体」+ JSON Canvas「数据层存索引、主题层解释色值」三家合成:

**数据层**:线只存 `{ colorIndex | null, weight: 1|2|3, dash: solid|dashed, capStart, capEnd }`。`colorIndex` 指向皮肤色板的强调色槽位(建议 6 槽,XMind/JSON Canvas 均收敛在 6 色一组),`null` = 中性线。**换皮肤不破档**。

**主题层(token 增量,挂进现有 `global.css` 体系)**:

```css
/* 中性线三档 —— 复用现有边框/文字灰阶的秩序,亮暗主题各存一份 */
--board-line-1: var(--border-subtle);    /* 细·默认:比卡描边还退后 */
--board-line-2: var(--text-muted);       /* 中:可辨识 */
--board-line-3: var(--text-secondary);   /* 粗·主干:接近正文重 */

/* 6 个强调色槽,每槽按角色派生(tldraw 色名派生模式) */
--board-accent-1-line: …;      /* 线/描边用:饱和 */
--board-accent-1-fill: …;      /* 卡底用:同色相柔化(≈ 现有 *-bg 的 12–16% alpha 惯例) */
--board-accent-1-text: …;      /* 该底色上的字色 */
/* …-2 至 …-6 同构 */
```

**语义分工**:
- **中性=层级轴**:默认线全走中性三档,主次 = 线重档 × 灰阶档同向联动(1 档线配 `line-1` 色,3 档配 `line-3`),即「粗的也更深」——单通道内两手段同向,任一手段单独看都能读出主次(XMind 多通道同向递减原则的收敛版)。
- **彩色=归属轴,不表层级**:一个 colorIndex 表一簇归属(线与卡共享同一槽位),同簇内换深浅不换色相(XMind「色管归属、宽管深浅」+ Miro「颜色=可机读分组键」)。
- 箭头/端点色**永远随线色**,不单独开轴(Whimsical 色一体)。

现有 token 体系已具备 `*-bg` = 主色 12–16% alpha 的派生惯例(`--accent-primary-bg`、`--success-bg` 等),`-fill` 变体直接沿用该惯例即可,无新发明。

### ④ 边标签排版与避让规则

| 规则 | 内容 | 出处 |
|---|---|---|
| 标签**属于线对象** | 是线的一个文本属性,不是独立节点;随线移动、随绑定节点移动 | 六家共识(tldraw richText prop / Excalidraw containerId / FigJam / Miro caption / Whimsical / Mermaid) |
| 双击线身即建/即编 | 无需先选中再找菜单 | Obsidian / Excalidraw / XMind |
| 锚定=**0–1 沿线标量**,默认 0.5,可拖,拖近中点吸回 | 第一版就要能滑——Excalidraw 死锁中点是其至今未解 issue,勿重演 | tldraw labelPosition + labelCenterSnapDistance |
| **永远水平**,不随线旋转 | "always render it from left to right" | Excalidraw 铁律;⛔不采 Miro aligned 默认(倾斜文字扫读成本高) |
| 可读性=**标签矩形内断线** | 优先 Excalidraw 的擦线方案(标签矩形内不绘线段像素)——任何卡色/板底色/皮肤下都干净,无需维护"标签底色跟画布"的映射;退而求其次才是 Mermaid/FigJam 式不透明 chip 垫底 | Excalidraw clearRect;反面:Miro 无遮罩致社区长期抱怨手动加白底 |
| 字级低于卡内正文一级,字色 `--text-secondary`,可跟随线的 colorIndex 取 `-text` 变体 | 标签是修饰不是正文 | XMind「标签字级低一级」+ tldraw 独立 labelColor 轴 |
| 格式极简:纯文本+换行,至多 bold | | FigJam(仅 bold/删除线) |
| 长标签自动折行(约 120px 宽) | | Mermaid wrappingWidth |
| **跨元素避让 v1 不做**;若未来做自动整理,标签必须是路由的一等避让对象 | | Whimsical 2026.4「其他连线不得压过标签」;反面:Mermaid 只算线不算字致标签互撞顽疾 |

### ⑤ 卡片分级用色用字

**核心采纳:Whimsical「一次选色驱动多档卡重」+ FigJam「成套预设」——用户永远只做两个决策:色槽 × 重量档,禁止分别调边框色/填充色/字色。**

**卡重三档**(单色槽内派生,对应 §③ 的 `-line/-fill/-text` 三变体):

| 档 | 渲染 | 语义(建议约定,不硬编码) |
|---|---|---|
| 重 | 实心填充(`-line` 色作底)+ 反衬字色 | 少数强调/结论卡 |
| 中 | `-fill` 浅底 + `-line` 描边 + `-text` 字 | 已归类内容卡 |
| 轻(默认) | 中性底(`--bg-elevated`)+ `--border-default` 描边 + `--text-primary` | 未整理输入/批量便签 |

- **明度表层级、色相表归属,互不干扰**:同一色槽换档不换色相(FigJam 深底白字/浅底深字两档 + XMind 原则)。
- **饱和度预算**:全饱和渲染只留给重档;批量便签自动落在轻/中档——主次由系统派发,不靠用户自律调色(Whimsical 降饱和分配)。
- 浅色=发散输入、饱和=结论的使用约定写进操作手册而非代码(Miro 的约定层做法)。
- **字级用 T 恤码离散档**(S/M/L,不给任意 px),且尺寸档同时驱动字号——若线也分档,可考虑 tldraw「size 一轴同驱线宽与字号」的联动,但 v1 卡与线各自三档已够。
- 亮暗两套主题各存一份派生结果,卡片只引用 token 不引用 hex(tldraw 主题模式;与现有 `global.css` 亮暗双份结构天然同构)。

## 三 · 反面教材汇总(我们要避开什么)

**词汇过剩类**
1. XMind 31 种主题形状(心形/云朵/引号)——装饰过剩破坏形状语义一致性;形状词汇宁少勿多。
2. Miro 线重 1–24 连续整数档——全板线重语义涣散;档位要少要离散。
3. tldraw 手绘签名风(draw dash/font 为默认)——学习笔记场景显玩具化;可借其闭集纪律,默认取工整一侧。

**默认值错误类**
4. FigJam 便签随机派色——同一人卡片颜色不连贯=伪造分类信号;默认必须中性稳定。
5. XMind Relationship 默认「过度弯曲」且不可改默认——默认曲率要克制,偏好可存为默认。
6. Miro 每画一条线都要重调样式(样式偏好不被记忆)——「沿用上一条」应是默认行为。

**标签半成品类**
7. Miro 边标签无底色挖空,线穿字全靠用户手动救——遮线机制必须内建。
8. Excalidraw 标签死锁中点、肘线上落点诡异且不可动(issue 至今开放)——滑动锚点进第一版。
9. Mermaid 自动路由只算线不算字,标签互撞是多年顽疾——任何自动整理都要把标签当一等避让对象。

**机制半成品类**
10. Excalidraw 邻近自动绑定无豁免开关——密集便签板必然误绑;修饰键豁免+显式解绑进第一版。
11. Obsidian 单一贝塞尔且无粗细/虚实/直线选项(常年高票未实现)——「只有曲线」不是极简美德,虚实+三档线重是纯视觉线也该有的地板。
12. Obsidian text 卡缩出阈值后渲染空白——轻量卡越多远景越像无字白块;远景标题兜底必须做。
13. FigJam shape 文字不随缩放适配 vs Miro Auto 字号失控——两个反向翻车:选「容器随文字长高+字号恒定」这条中道(FigJam sticky 自己做对了的那半)。
14. Whimsical 线重两档跨度过大(thin→thick 从隐形跳粗黑)——三档等比阶梯。
15. FigJam 曲线端箭头不贴切线「歪头」——箭头须按曲线末端切线旋转,短曲线钳制曲率。
16. Excalidraw 粗糙度不随元素尺寸归一化(若未来做任何手绘/噪线风参数,必须按尺寸缩放)。
17. Whimsical 视觉规范大量藏在实现里、官方无档位文档——**我们的视觉升级要把每个轴的档位写进成文规范**(token 表即规范),不重演。

## 四 · 实施分档建议

### v1(便宜可先做:多为数据字段+渲染分支+token 增量,不涉路由算法)

| 项 | 内容 | 便宜的原因 |
|---|---|---|
| 线数据模型 | `{colorIndex\|null, weight 3 档, dash 2 态, capStart/capEnd 各 3 值}` | 纯字段,JSON Canvas 同构模型已验证 |
| 弧线单形态 | 三点圆弧+单 bend 标量,一个中点手柄 | tldraw 已证明一个标量够;避开整套肘线路由 |
| 绑定三件套+豁免 | 轮廓高亮预告/松手即绑/移动跟随;Alt 豁免+解绑手势 | 双向记账两个字段;豁免是一个修饰键判断 |
| 端接求交 | 指中心+圆角矩形轮廓求交+箭头端回退间隙 | 卡片全是圆角矩形,求交是解析几何不是搜索 |
| 线色线重 token | §③ 的 `--board-line-1/2/3` + 6 槽 `-line/-fill/-text` 派生 | 挂进现有 token 文件即可,派生惯例(`*-bg` alpha)已存在 |
| 卡重三档 | 中性默认+同槽三档渲染 | 一个色槽字段+一个档位字段驱动全部样式 |
| 边标签基础 | 双击建、0–1 滑动锚+中点吸回、永远水平、标签矩形断线、折行 | 断线=绘制时跳过一段,比维护底色映射还省 |
| 样式惯性 | 新线/新卡沿用 last-used | 一个记忆变量 |
| **成文规范** | 把上述每轴档位写进 current-state 视觉规范条目 | 写作成本,零代码 |

### v2(要等设计场拍:涉及品味裁量、算法或与既有体系的接轨谈判)

| 项 | 等拍原因 |
|---|---|
| **6 色槽的具体色值与现有皮肤体系接轨** | 现有 token 只有 accent-primary + 语义红黄绿蓝,6 槽强调色是新色彩预算,亮暗两套的具体 hex 是设计裁量;tldraw 教训:封闭 palette 若不与既有内容库色彩接轨会顶墙 |
| 远景降级标签(缩放阈值+首行摘要) | 阈值手感、摘要截取规则、与板整体 LOD 策略耦合 |
| 点线第三态、端点圆点之外的端头扩充 | 等真实使用暴露需求再扩,防词汇通胀 |
| 自动整理/自动避让(若做) | 算法项;且必须一开始就把标签纳入避让(Mermaid/Whimsical 正反两例都在案) |
| 分组容器(半透明底+左上角常驻标签、容器比居民淡一级) | Obsidian/Mermaid 共识形态,但与 Coincides 既有 board 分组概念的关系要先设计裁定 |
| 卡片克隆手势/四侧快速添加 | 交互设计项,与现有板手势体系合并设计 |
| 手绘/语气风格轴 | 与产品气质定位强相关,纯设计场议题 |
