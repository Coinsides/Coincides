> 需求:Coincides 单体应用(Node+Express+SQLite+blob),8–10 并发;大陆+海外(北美现居,未来北美↔大陆,可能日/韩/港/马)都可直连;亚洲优先;要成本/配置/物理位置/大陆直连质量。
> 方法:三路 workflow(香港/日新韩/大陆与跨区),价格尽量对官方定价页核验(2026-08)。

## 〇、决定性事实(主导整个推荐)

**OpenAI 与 Anthropic 双双不支持香港和中国大陆**(OpenAI 对 HK IP 返回 403;Anthropic supported-countries 列表含日/韩/新/马/台,不含 HK/CN)。而模型云化战略(08-04 卷 §二十二)要求服务器直连前沿 AI API——

- **香港节点**:大陆直连最好,但 AI 调用需经中转(东京/美国小机出口)——多一层运维;
- **大陆节点**:双重死结(ICP 个人备案明确不允许登录/交互类应用=灰区可注销 + GFW 阻断 AI API)——**取消资格**;
- **东京节点(软银线路)**:AI 直连合规 + 大陆晚高峰可用 + 北美延迟全场最佳——**唯一零附件满足全部约束的单点**。

## 一之二、需求修订后的重排(08-07 同日,Henry 放宽 NA 延迟至 ≤300ms)

**背景**:Henry 澄清——NA 延迟非最高优先级(北美将来自建本地节点,亚洲服务器只需"能维护"级延迟);**数月后回国度假,届时本人即大陆用户**→大陆体验升为第一优先;计划先建亚洲节点、返美后再议北美节点。

**重排**:①**腾讯云锐驰型 HK(主)+东京小中继(AI 出口),升首选**——大陆体验全场最佳(南方 10-40ms/晚高峰 99%+),中继减分项被多节点计划吸收(€9.95 小机可长成真节点或常任 AI 出口);②V.PS Tokyo 退次席(单机最简,大陆"良"级);③Vultr Tokyo 持平;④**新加坡系新入围但列末**——靠放宽 NA 才及格,大陆直连三地最差;"SG 是马来西亚时代的节点,不是回国度假的节点"。

**⚠️ 架构事实(随重排说破)**:"两地建节点"若指共享同一份数据 = 数据同步问题非采购问题。SQLite 单文件=天然单主库;双活同步=为 10 人应用付分布式税,**明确关掉这条路**。理性模式:**单主库+快照搬家**(主节点永远一台;回美后拍"搬还是留",搬=一次快照,留=忍 110-150ms 完全可用);北美"节点"的真身大概率是**异地备份目标**(持续快照推对象存储,兼得灾备)。

## 一之三、方案 2 基本拍定与两个 AI 消费者的拆分(08-07 同日续)

- **Henry 基本拍定方案 2(V.PS Tokyo 单机)**:35-70ms 对笔记应用无感("又不是玩游戏")。
- **国产模型提案的归位**:Henry 提"东南亚节点用国产模型、北美节点用 Anthropic/OpenAI"——Claude 判定:**单节点方案下该前提消失**(应用 AI 调用是服务器侧发出,用户位置不碰 AI API 线;东京直连 Anthropic 永远畅通)。国产模型(DeepSeek/Qwen 确实能打且便宜)的正确姿势=**按任务切模型不按地理切**:收进既有 provider 缝(server/src/agent/providers/ 抽象)当未来"成本档"候选,上不上由驾驶舱评测跑分说话。按地理切的坏处:同一数据不同质量处理+评测基准×2。
- **回国期间的真问题=开发工具**(Claude Code/Codex 直连 api.anthropic.com,大陆不在支持名单):解法=**远程开发**——人在国内 SSH/VS Code Remote 进东京节点(或北美家中机器),开发环境与 Claude Code 跑在境外,AI 调用从日本发出天然合规;度假期可多开一台小开发盒(生产机跑开发不干净,备选)。
- **远程开发定形(08-07 续,Henry 之忧的完整解)**:**彻底薄客户端**——笔记本=窗,东京=完整工作台(代码/Claude Code/Codex/GitHub 推拉/npm/dev server 全在东京);本地不装不拉不碰 GitHub 与 npm(Henry 原设想"GitHub 中转→本地 npm install"砍掉——它把 GitHub 大陆不稳/npm 慢/本地无 Claude Code 三个问题重新引入)。唯一网络依赖=SSH 到东京(选型时已优化的那条线)。实操三件:**VS Code Remote-SSH**(端口转发,dev server 现于本地 localhost)/**tmux 或 mosh**(断线不死,Claude Code 长任务断网续跑——agent 工作流刚需)/**开发盒与生产盒分离**(度假期 €10 小盒,回程销毁)。诚实边界:需在线(离线时本地模式同样无 Claude Code,净损失零)。部署手册+远程开发指南=回国前两周交付物。
- **冗余方案(08-07 续;Henry 提"3 台同款,2 台闲置备机",Claude 否决并替换)**:同款闲置备机对 Henry 真正怕的故障(跨国线路拥塞)**零作用**(三台同机房同线路,一堵全堵),对硬件故障是虚覆盖(备机无数据,仍需从备份恢复≈现开新机 5 分钟),且闲置机悄悄腐烂(没演练过的备机=没有备机)。**替换方案(€28/月 vs €60/月,三种故障全覆盖)**:主力 V.PS Tokyo + **线路备份**=不同线路不同商的小机(腾讯锐驰 HK 小杯 ¥40-55/月,东京线路堵时走完全不同的路 SSH 进入)+ **数据备份**=自动快照推对象存储(B2/R2,€2-5/月;即"北美节点的真身")。心法:**服务器是牲口不是宠物**——坏了开新的,恢复=备份+恢复脚本 15-30 分钟;真正买安全的纪律=**恢复演练**(部署后真跑一遍从备份拉起全站,计时入手册)。对计划影响零;部署手册多三节(备份自动化/恢复演练/备路配置)。
- **两个澄清 + 工作环境无缝衔接(08-07 续)**:①备路小机**无需任何中转**(中转只属于被否的旧方案 1——香港当主机跑应用才需 AI 出口;现在的备路门不跑应用不调 AI);不想用腾讯可换阿里 HK 同级,甚至可先不买、遇堵再开;②**非实时同步备机**——数据冗余=单向快照推对象存储,实时多机同步维持否决。③Henry 真需求=**换任何机器打开 Claude Code 看到同一个我**。解法=状态外置而非状态同步:git 仓库(代码+CLAUDE.md+agent-ops 全档=工作知识 90%,clone 即得)/记忆目录(唯一手动搬的:`~/.claude/projects/.../memory/`,建议私有 dotfiles 小仓,**不入主仓**——涉私)/会话历史(**不同步也不该同步**:一次一个工作台,耐久产出全落仓)/登录态(每机一次)。**实战已验证**:蓝屏时代两次会话中途崩机、两次无损续工——"重要状态落耐久工件、会话可抛弃"的纪律当时是监督轨迹,现在白捡第二身份=**跨机器交接协议**。钉句:同步大脑的外置部分(仓库+记忆),不同步正在说话的嘴(会话)。
- **闭合形态**:V.PS Tokyo 单主机(应用+AI 全走东京)+ 远程开发习惯 + 北美=异地备份目标。跨国生活架构一台机器闭合。

## 二、明确排除(带理由)

- **大陆机房**(阿里/腾讯轻量 ¥188-199/年,便宜到碾压):①个人 ICP 备案 10-20 工作日+人脸核验+境内实名域名,且**明确不允许登录/交互功能——多用户笔记应用属灰区,抽查可注销**;②出站 AI API 被 GFW 阻断且不在两家支持列表,需商业中转(key 过第三方手)。双闸门,不值。
- **香港超大规模云**(AWS ap-east-1 $43+/Azure $77+/GCP):价格 3-6 倍于阿里腾讯 HK,线路反而是普通国际 transit 晚高峰劣化,egress $0.12-0.23/GB 计费陷阱,且同样被 AI 地理封锁——**花更多钱买更差的路**。
- **CN2 GIA 专线商**(DMIT Pro $160/月 4G、搬瓦工 $90+/月 2G):线路天花板(沿海 28ms 晚高峰稳),但价格是 V.PS 的 8 倍,10 人应用用不上。
- **韩国**:无平价中国优化线路市场,只有你人搬到韩国才值得;**新加坡**:北美延迟差(170-240ms),重心移马来西亚时再议;**DigitalOcean**:根本没有日本机房。
