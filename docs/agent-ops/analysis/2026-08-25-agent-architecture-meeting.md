## 2. Mr. Zero 哲学(Henry 亲述,v1 起源)

- 用户只要**一个可对话的窗口**;不需要知道背后多少 Agent 协同;说出需求,Mr. Zero 在应用里搞定。名字是概念代号,可改。
- v1 的 Mr. Zero 以整理知识卡为主体,已相当称职——手艺继承进「整理/铸卡」角色。
- **Fable 补的第三件**:隐藏的是复杂度,不隐藏的是行为——**每个动作留收据**;「一张脸、一群工、每笔账可查」三件合一才是完整的 Mr. Zero。
- 对称性:产品的 Mr. Zero 结构 = 工程指挥链结构(Henry→Fable→Opus→Codex),同一条设计直觉的分形。

## 3. 客工制度(外部 harness 的位置,四层)

1. **定性**:外部 harness 不是「角色」,是**客工**——用户自己请进门、穿上外骨骼的外来劳力;角色表管驻场剧组,客工制度管外人进后台。
2. **一道门,一部法**:驻场与客场同走 MCP 工具面,同守阈值/收据/撤销。**红线对偶(Fable 拍):第一方 Agent 不得拥有第三方 Agent 没有的暗门**——Mr. Zero 12.4 起只是「第一位常客」(TD-7 退役)。
3. **可见性不对称是对的**:Mr. Zero 隐藏内部剧组(设计);客工由用户自己邀请、无需隐藏;统一点=**收据墙**(所有 Agent 活动的统一可见面,进同一人审队列)。
4. **待补四小件**:①收据记客户端身份(MCP 握手自报,metadata 词汇扩展);②Mr. Zero 搬上工具面(12.4/TD-7);③按客户端分工具曝光(TD-14 家族,将来);④DeepSeek 实验小环(12.2 铸版后第一战,打客场=「第一个外部 Agent 接入」触发器彩排)。

## 4. 小龙虾 = OpenClaw;实验设计

- **小龙虾 = OpenClaw**(用户自托管私人助理,MCP 原生)——客工原型样本;接入=触发器真身(接入前按 deferred-tests 台账批量补安检);连门需长期 token → 与「免密测试入口」方案(dev token 铸造脚本,挂 Henry 待拍)一并做。
- **DeepSeek 实验(Henry 亲定)**:刻意选弱模型(V4-Pro/Flash)压测外骨骼——设计论点=安全性长在骨架不长在模型智能;唯一硬要求=函数调用格式纪律。

## 6. 工具面共演化 · make-or-buy · 场景可行性(2026-08-25 凌晨续)

- **身前身后事(Henry 提)**:每个功能改动要想清「身前」(哪些库/表受影响)与「身后」(如何被外部 harness 用到)。**制度化(Fable 定)**:身后事一半已被门禁机械化(注册表→manifest 重生成→parity 强制人类入口→收据轴自动);剩下的一件=**每个版本计划加常备小节「工具面增量(可为空)」**——「要不要开门」成为规划必答题,即日起入计划模板惯例。工具退役纪律(客工多后改动破坏接入)先登记不先建。
- **Make or buy(Henry 定调)**:买穿戴者,**造了买不到的两样:真相层与门**。接缝维护有界,因为接缝=一个标准协议+一份 manifest,非 N 个适配器;「接口处的特殊东西」=manifest 新鲜度门+parity 门,已建成且机械。好处=harness 如积木随时可换可拆;代价=接缝档案要保鲜(每代表一份兼容性档案+冒烟旅程)。
- **造箭手家规**:Claude Code(及 Fable 参与)可为产房时代的工程 harness;**自家人同走客工法**——收据照留、暗门没有;造门的人从门里走进去=对门的最好检验。
- **open design 定位**:本地优先开源设计平台(2026-05 开源,TS,84.4k 星,72 套设计系统/31 技能,可接驳 ≤15 个编码 agent CLI)——**不是穿戴者,是会指挥厨子的设计总厨** ⇒ 产房时代设计部门候选,不入日常客工名单。
- **场景可行性(Henry 问「重整笔记时无引用源→harness 上网找源→入原始文档库→建引用→生成笔记」)**:**可行,且全部是路线图既有拼图**——S4 读面(检索)+ harness 自带网搜 + **入库工具族(=V12 随行三线「入库收据」的落点,唯一真正的新件)** + 12.5 源梯(引用锚)+ 写工具按阈值规则生长。**一条硬规矩:网络来源文件入库,收据必记出处(URL/抓取时间)**——网货也是源件,身世写进户口。

## 7. 接入台(反「harness 配置地狱」设计,Henry 提出、Fable 定形)

- **铁律(设计原则入档)**:「接入一个 harness 如果需要读我们的源码,那就是产品缺陷。」接入知识必须住在产品里,不住源码/对话里。
- **形态**:Settings → Agent 接入,三部件:①**通行证架**——每 harness 一张具名 token(签发/吊销;名字进收据;岗位=钥匙的权限面:应用管不了用户机器上跑什么 harness,但每把钥匙开哪些门、账记谁头上,由应用管);②**配方生成器**(反地狱核心)——产品替每个代表 harness 生成其侧配置片段(dsh 插件行/OpenClaw MCP 配置/.mcp.json),端点+通行证预填,一次复制粘贴接入;③**岗位一览**——岗位×在用 harness×通行证状态×最近活动。
- **排期**:设计现在定档;最小版(具名 token+配方生成+收据署名)在第一个客工真实接入时建(OpenClaw 实验站);token 签发机关与「免密测试入口」方案同一套,一鱼两吃;按岗分权限面随 TD-14 强制。

## 8. 路由拓扑(Henry 问「小龙虾是不是 orchestrator」;Fable 答:半对,系统级无总调度台)

- **四层路由,各归其位**:①**用户是总路由**(选今天叫谁上门=选 harness;接入台把这层显式化);②**harness 内部路由**(其自身 orchestrator 把自然语言拆成对我们工具的调用——Henry 的 orchestrator 直觉在这一层成立,OpenClaw 对日常任务确实干这个);③**门内机械路由**(transport dispatch+policy 分档,无智能、纯机械);④**Mr. Zero=驻场前台**(将来给不自带员工的用户;Henry 现阶段由 OpenClaw 事实代行前台,是任命不是架构)。
- **系统级拒绝 hub 拓扑**(OpenClaw 指挥其他 harness):传话链损耗上下文、收据署名糊掉(工程活记在管家 token 上)、单点故障;且每个 harness 架构完整——雇了完整的工程师再让他听管家传话是浪费他的脑子。**协作走共享世界,不走科层**:各部门各持通行证直连,通过宅子本身协调(收据墙/队列/笔记=工地交接板)。
- **「光聊天不值得一个 harness」**(Henry)成立,而 OpenClaw 的雇佣理由本来就不是聊天:它是**永远在手边的生活助理**(IM 集成、常驻、跨应用),操作 Coincides 只是它众多能力之一;聊天是它的界面,不是它的岗位。

## 9. Mr. Zero 降格为岗位(已决);应用内指挥的经济账

- **历史订正(Henry 亲述)**:OpenClaw 出现早于 Mr. Zero;当年不是没得买,是尚未意识到 make-or-buy 是选项——且当时 make 恰是最经济解(极简应用配极简自制管家,接大 harness 反而杀鸡用牛刀)。**教义补笔:make-or-buy 不是一次性判决,要定期重问**——v1 答 make、今天答 buy,都对,变的是市场。
- **已决**:①Mr. Zero 降格为**岗位名**(前台名牌),不再是要养的代理运行时;②现阶段由 OpenClaw 受聘坐岗(接入台领"日常助理"钥匙);③v1 自制 harness 零件(orchestrator/providers/agent memory)**光荣退役**:留在当年 branch,标遗产存量停投入,物理清除随清场专项;TD-7「桥接内部代理上工具面」改写为「将来为不自带 harness 的用户造**参考穿戴者**(最小诚实 MCP 客户端,同门同法),非 V12/V13 活」;④**名牌与工牌分开**:聊天窗显示岗位名(Mr. Zero),收据墙记真身(哪个 harness)。
- **新用户开箱流程**:注册 → **配岗**(给 Mr. Zero 的椅子选人)——接入台升格为 onboarding 第二步。
- **应用内指挥经济账(「指挥便宜,陪聊贵」)**:便宜层=委托单(现成笔记/队列原语)+ 无头启动器(每 harness 一条带通行证的命令模板)+ **结果从正门回来**(MCP 写入真相层→原生渲染→预览近乎免费),"天"级投入;贵层=把外部 harness 完整驾驶舱嵌进应用——**明确不做**(适配器地狱调头);中间层=**ACP**(Agent Client Protocol,与 MCP 对称:MCP=它们调我们,ACP=我们驱动它们的会话;dsh 已声明支持),一份客户端投入通吃,"周"级,待真实需求。

## 10. 注意力公理;默认岗语法;设计岗的 ACP 例外

- **产品气质条款(Henry 亲述入宪级)**:**流不断,是第一体验公理**——做笔记/改笔记/造组件全程不切应用、思路不断;这与弃 artifact 的初心(孤儿成果断流)、12.4 流式装配面同源。80 岁老太太原则(陶渊明派):用户只需会说想要什么,在应用里说、在应用里改、在应用里迭代版本。
- **默认岗语法**:「open design 当默认」采,但**焊岗不焊人**——"设计部"升为**默认常设岗**(开箱即有),open design 为**默认任命**(可换:Claude Design 等);乐高原则不许焊死任何积木。
- **默认的两档价签**:现在档(Henry)=接入台预配配方+一键点火(便宜,顺做);老太太档(将来)=产品替用户当 IT 部门(捆绑安装/托管云端设计服务)——真钱,记方向账,产房专项一并设计。
- **设计岗是「陪聊贵」的合法例外**:设计迭代节奏(十几秒一轮微调)即体验本身,委托单模式喂不饱 → 设计岗值得 ACP 级应用内会话回路投入。产房门规不变:沙箱里迭代不留账,**采用那一下才落收据**。

## 11. 组件微调:调节面方案(旋钮级/结构级两层)

- **原则**:组件可微调性不是编辑器问题,是**出生证问题**——产房出生的组件必须申报**调节面**(旋钮清单:名称/类型/取值范围)。应用只造**一个通用旋钮面板**(读出生证自动渲染滑杆色盘,live 预览),一次投入全组件通用;**不造**任意 HTML 可视化编辑器(make 一个买得到的东西+无底洞)。
- **两层微调**:旋钮级(约八成:颜色/尺寸/间距/档位)=应用内拖滑杆,零延迟零 token 离线可用,老太太友好;结构级(改机理)=回设计岗 ACP 对话回路。配眼镜在店里调镜腿,换晶状体进手术室。
- **地基伏笔**:V12 必修⑤ token 预设=旋钮的地基(组件"主色"旋钮默认绑应用 token,用户组件天生与笔记同色系)。
- **成长律接口**:旋钮被拧的频次=组件使用收据(常拧的旋钮=价值证据;从没人碰的=下版赘肉候选)。
- **红线兜底**:组件 HTML 本体永远人手可编辑;老太太不需要知道盖子存在。
