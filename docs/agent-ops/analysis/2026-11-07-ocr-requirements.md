# OCR / 文档理解模型选型:我们的需求

**背景**:影像面已接近「应用一页 = 原件一页」(PDF、docx 走页影像);文字面是大头。文字层的首要读者是 agent 和搜索,其次才是人(目标态:页影像是人的操作面,文字层藏在影像底下)。所以这次选的不是「把图变成字」的工具,而是**把一页纸变成 agent 能用、能对回原页位置的结构化记录**的工具。约束:**大陆可用**(账号、计费、网络);服务端在香港 4C8G,本地跑不动重模型(MinerU 本地 70 秒/页已判不可行);按目的触发、按页计费。

## 一、输入(我们手里有什么)

| 输入 | 来源 | 现状 |
|---|---|---|
| 单页 PNG,宽 1240 | PDF、docx 已逐页栅格化(`source_pages`) | 现成,最主要的输入形式 |
| 整份 PDF | 原件 | 有;有文字层的 PDF 已用 pdf-parse 取文本,但双栏顺序乱、公式是字形碎片 |
| 扫描件 PDF | 原件 | 现有 OCR 通道只认 Anthropic 凭据,岛上没放,等于没有 |
| 照片、截图(手写笔记、黑板、幻灯片拍照) | 图片 Source(A-19 在工) | 没有任何文字层 |
| pptx | 原件 | 整类没开;转页可走 LibreOffice 同一条路,之后就是页 PNG |
| 语言 | — | 中英混排为主,少量公式符号;繁体、日韩偶有 |

## 二、输出(每种结构我们要拿到什么)

按「agent 读 / 搜索 / 对回原页」三个用途倒推。**每一项都要带页内坐标**(块级必须,**行级/字级优先**——块级只能对到段,字级才能对到词;选字与批注锚点的精度上限由此决定):没有坐标就建不了「影像底下的隐藏文字层」,选字、批注、item 锚点都落不回页上。(2026-11-07 修正:评测加「选字对齐」一题)

| # | 结构 | 要的输出 | 用途 | 优先级 |
|---|---|---|---|---|
| 1 | 正文段落 | 文本 + **阅读顺序**正确(双栏、文本框、绕排) + 段落/标题层级标签 | agent 读、切 item、建章节 | **必须** |
| 2 | 公式(印刷) | 行内/独立 **LaTeX**;读不出要明说,不许编 | agent 读、做卡 | **必须**(docx OMML 已有,PDF/图片里的公式还没有) |
| 3 | 表格 | 单元格级结构(行列、合并格、表头),可转 HTML/Markdown | 财务/统计类文档;agent 要知道「哪个数在哪列」 | **必须** |
| 4 | 手写文字 | 文本 + 每行置信度 | 手写笔记照片 | 高 |
| 5 | 图、图表 | 图说(caption)+ 一段描述;图表尽量给出数据点/趋势 | agent 读;人看影像即可 | 中 |
| 6 | 流程图、SmartArt、箭头形状 | 节点文字 + 边(谁指向谁) | 讲义、课件 | 中 |
| 7 | 页眉页脚、页码、脚注、尾注、批注 | **打标签**,与正文分开(可剔除、可挂回) | 正文不被污染 | 高 |
| 8 | 代码块、列表、编号 | 保留缩进与层级 | md/技术类文档 | 低 |
| 9 | 超链接、交叉引用 | 文本即可 | — | 低 |

**诚实优先于完整**:F3 的教训——拍扁成似是而非的假公式比留白更坏。模型对读不出的部分必须能给「不确定/无法识别」的信号(置信度、显式占位),而不是通顺地编。这是硬要求,评测里单列「编造率」。

## 三、非功能要求

| 项 | 要求 | 说明 |
|---|---|---|
| **可用性** | 大陆账号可开、人民币计费;API 从**香港服务器**调用要通 | 岛在香港。**大陆站与国际站多半是两套账号、两套 endpoint、两套计费**,要分开核;香港→大陆站 endpoint 的延迟与失败率要实测(p50/p95/p99)(2026-11-07 修正) |
| **成本** | 按页计价,给出每页估价;一本 300 页教材整本跑完的费用在可接受范围 | 触发时机按目的来(有目的才付钱),但单价仍要低 |
| **延迟与吞吐** | 单页 ≤ 10 秒可接受;后台异步;300 页在 1 小时内跑完 | 我们已有 3+1 槽的并发限流 |
| **并发与限流** | 明确的 QPS/并发上限,429 时可退避 | 别让一本书把队列卡死 |
| **输入形式** | 支持单页图片;最好也支持整份 PDF 直传 | 单页 PNG 是我们现成的 |
| **输出格式** | 结构化 JSON(块类型 + 坐标 + 文本/LaTeX/表格),Markdown 只作次选 | Markdown 丢坐标 |
| **版本记账** | 能指定版本最好;做不到时至少返回里带版本/日期标识,并**每次把原始响应全量落盘**(带厂商、产品、调用时间) | 云 API 普遍不能锁版本(2026-11-07 DSH 核实四家皆否);可比性靠「原始响应 + 固定回归集定期重跑」事后对齐(2026-11-07 修正) |
| **数据政策** | 不用我们的文档训练;保留期短或可删;商用许可明确 | 笔记是私人材料。**按具体产品核,不按公司核**(同一家的模型服务与文档解析产品政策可能不同)(2026-11-07 修正) |
| **本地兜底** | 轻量开源引擎(CPU 可跑)作为敏感文档或断网时的最低档 | 只要「有字 + 有框」,不求结构 |
| **页数上限** | 单次 ≥ 200 页或可分批 | 现有 Anthropic 通道有 200 页上限 |

## 四、选型怎么分层看

需求跨三类产品,大概率不是一个模型包圆:

1. **版面 + OCR 引擎**(字 + 框 + 块类型 + 阅读顺序,便宜、确定性强)→ 做隐藏文字层和搜索的底座。
2. **文档结构解析器**(表格、公式、标题层级 → 结构化输出)→ agent 读的主料;有的产品把 1+2 合在一起。
3. **看图的大模型(VLM)**(图说、图表数据、流程图关系、手写、疑难页)→ 按需、按页、贵;只在前两层给不出或置信度低时调用。

选型时请对每个候选标出它覆盖哪几层、坐标给不给、不确定时怎么表示。两层产品 + 一个 VLM 的组合是可以接受的答案。

## 五、评测口径(选型要过的题)

**样本**(每类 10 页左右,从我们自己的材料里取,不用厂商的演示图):

| 类 | 样本 | 考什么 |
|---|---|---|
| A | 双栏教材 PDF 页(有图有公式) | 阅读顺序、公式 LaTeX、图说分离 |
| B | 扫描的中文讲义页 | 中英混排识别、页眉页脚剔除 |
| C | 手写笔记照片(中英、带箭头) | 手写识别、置信度是否诚实 |
| D | 财务/统计类 docx 页(表格密集,含合并格) | 单元格结构 |
| E | 课件页(SmartArt、流程图、形状) | 节点与边 |
| F | 公式密集页(矩阵、分段函数、上下标嵌套) | 公式语义等价(复用 F3 的「比含义不比字符」金标准法) |
| G | 一页故意模糊/倾斜/低分辨率 | 该说「读不出」时说不说 |

**指标**:

- 正文:字符错误率(CER)、阅读顺序错位数
- 公式:语义等价率(F3 金标准的比法),编造数(输出了原文没有的结构)
- 表格:单元格命中率、合并格是否保留
- 坐标:块级框的有无与大致准确(抽查叠回原页)
- 图/流程图:图说有无、关系对错(人工判)
- 手写:行级 CER + 低置信度标注的召回(真读不出的有没有标出来)
- **编造率**(全类单列):通顺但原页没有的内容条数;这一项一票否决
- 成本与时间:每页实际花费、实际耗时

**对照**:每类同时跑现状(pdf-parse / mammoth 纯文本 / 没有)作基线,看增益;有条件就同时跑两个候选,同题同卷。

## 六、接进我们系统时的落点(供选型时想一步)

- 输入走现成的 `source_pages` 单页 PNG;输出按页存,挂在页记录上,带解析器版本。
- 第一次只做「隐藏文字层 + 公式 + 表格」三样进产品;图说、流程图、手写按目的触发(与 L-009「上传不切、目的来了再花钱」一致)。
- 凭据走设置页的提供方凭据(岛上 `appdata/provider-credentials.json`),不进 env、不进仓库。
- 不要求人能在文字视图里读顺;人读影像,agent 读结构。

## 七、不在本次范围

- 实时/摄像头 OCR;语音;视频帧。
- 把文字层做成人阅读的排版。
- 用 OCR 替代 docx 的 OMML 公式解析(那条已经 0 错,保留)。
