# 三个角色的常设记录体系（设计稿）

**我们不是裸奔，是只有「时间线」、没有「状态卡」。** 台账、订单尾部、短讯、信箱都只能往后追加，所以想知道「此刻是什么样」，只能倒着读完一长串。这份方案只补两样东西：

## 二 · 六条原则

1. **两种墨水**：**时间线只追加**，记「发生过什么」；**状态卡只覆盖**，记「现在是什么」。卡片可以由时间线重建，反过来不行。
2. **正本在文件，短讯只是指针**：一条短讯 = 「去看 X 的第 N 节」加一句为什么。短讯丢了也不丢东西。
3. **一事一处**：每条事实只有一个家，其他地方只放指向它的指针。
4. **公开和私有分开**：仓库是公开的，只放能公开的内容。凭据、服务器地址、本机路径、进程号和端口、账号数据地图，都放仓库外的私有 ops 目录（下文记作 `<ops>`）。每个角色的状态卡**一分为二**：公开的一半在仓库，私有的一半在 `<ops>`。
5. **少而必写**：每份记录都要回答「谁、在什么时候、要知道什么」。答不出来就不建。
6. **门禁优先**：形状和新鲜度由脚本检查，散文只用来解释为什么。门禁本身要过阳性对照：先人为造一个违规，看它是不是真的会报红。

### 3.2 每张单一张「单卡」（改造现物：在订单文件**最上面**加一块，覆盖写）

**位置**：每个订单文件的状态头之后、规格之前的 `## 单卡（现行，覆盖写）`。订单尾部照旧追加 Result 和裁定，作为时间线。
**回答的问题**：

| 谁 | 想知道 |
|---|---|
| builder（包括接班的 builder） | 现在什么有效？改了什么？还欠什么？ |
| Tester | 要验什么、对照哪个基线？ |
| Main_Designer | 这单卡在哪？ |

**分块写，每块只有一个主人**，避免两个会话同时改同一行。只有「阶段 / 持有者 / 下一步」这一行例外：**谁交出，谁改**。builder 交货时改成「待验 · Tester」，Tester 下判语时改成「待裁 · Main_Designer」。所有人都只改共享树里的那份订单文件（⛔ 在副本里改），而且只用 Edit 改自己那块（⛔ 整个文件覆盖写）：

| 块 | 主人 | 内容 |
|---|---|---|
| 状态 | Main_Designer | 阶段、持有者、下一步（都用枚举值，看板就从这里生成）；**现行有效的裁定**：一条写一行，每行一句摘要，加上目标标题的**原文**（不用锚点 slug，中文标题的 slug 规则不好复现）。同时有几条有效就写几条；被推翻的裁定直接删掉（尾部的时间线里还留着）；**已读到**：写这张卡时尾部最后一个 `##` 或 `###` 标题的原文 |
| 已否决的做法 | Main_Designer | 做法名、为什么被否、哪一节否的。防止新会话把被否的做法再提一遍（builder 换班最怕的第 3 条） |
| 改动清单 | builder | 基线 commit；改了哪些文件；哪些文件在冻结清单之外 |
| 自报数字 | builder | 一个数字一行：`数字 · 命令 · 环境/版本 · 证据文件`。**数字没有出处就不许写进来**（a21 的数字对不上就是这个原因） |
| 待办 | builder | 还欠什么 |
| 验收条件 | Tester | 带条件的判语：放行或阻断，加上附带条件。例如：编辑器组 7 项返修、「H 必过」、「阳性对照要红在第 1、2 条」；还有哪些自报数字 Tester 没核 |

后台进程、端口、副本路径、副本里的陷阱（比如 junction）**不写在单卡上**，写在各角色私有状态卡的「在跑的东西」里，单卡只放一句「见私有卡」。

**状态头改成机器可读**（新单起）：`> **状态 (Status)**: active | archived`（只用 docs-index 认识的值，单关闭时改成 archived；阶段只写在单卡里，不在状态头再抄一遍）和 `> **日期 (Updated)**: <日期>`，替换现在这种自由文字的 `**status**: ready,排在…`。新单从此不再计入 INDEX 的「(缺状态头)」。现有 154 行里有 140 行是旧交接单，它们原地冻结，仍会留在 INDEX 里。

**单号**：一张单一个单号，就用订单文件名去掉日期和 `-order.md` 后剩下的那段（比如 `a19-a20-image-pages-and-idle-save`）。审计目录、判语台账、看板都用同一个单号。这样第四节的门禁才能把三处机械地对上。

**尾部标题**（新单起）：每个新追加的 `##` 标题都以 `(<角色> YYYY-MM-DD)` 结尾，日期写**写作日**，不写发现日。

⚠️ 派单前的「第 7 道检查」（`check-handoff-surface.mjs`）会扫描第一个 Result 标题之前的全部文字，单卡就在这个范围里。所以单卡「自报数字」里写的 `npm run …` 必须是真实存在的脚本名，否则重新派单时检查会报红。

## 四 · 门禁（能机械化的都机械化）

新增一个零依赖脚本 `scripts/check-role-records.mjs`，写法照 `check-tech-debt-table.mjs`：中文报错、写明怎么修、遗留问题用一个只许缩短的豁免名单。把它挂进 **`docs:check`**，因为这一组很轻；不挂进重型的 `verify`。检查项：

1. **看板形状**：「阶段」「持有者」只用枚举值；没有关闭的单都要出现在看板上（扫描切换日之后的订单文件）；看板的「在办的单」表要和各单卡的状态块一致（重新生成后没有差异）。
2. **单卡新鲜度**：切换日之后的订单必须有单卡；「现行有效的裁定」里写的每个标题原文都必须在文件里真实存在；**单卡的「已读到」必须等于文件里真正的最后一个 `##` 或 `###` 标题**。按位置比，不按日期比：a19-a20 那张单 11-07 一天就有 5 节裁定，单卡落后几节、日期却一样，按日期查不出来；而且有些旧标题没写日期，有些写的是发现日。
3. **自报数字有出处**：「自报数字」表的「命令」「证据文件」两列不能为空。证据文件必须是仓库内的相对路径（在 `docs/audits/` 下面），并且真实存在。指向会话临时目录或 `<ops>` 的一律报红：前者换班就丢，后者会把本机路径写进公开仓库。
4. **判语台账**：列数固定（照 tech-debt 的做法）；凡是存在 `tester/review.md` 的单，台账里都要有一行。
5. **台账编号**：只查切换后的月文件（`claude-log/\d{4}-\d{2}\.md`），标题按 `^## §(\d+) ` 解析：第一条必须是 §294，此后跨文件严格 +1，不许重复；每条都要有「判断点」。旧的日文件不进扫描，不靠豁免名单。原因：旧日文件每天从 1 重新编号，写法是 `## N —` 或 `## N.`；`2026-09-09.md` 里 24 和 167 各重复了一次。
6. **隐私闸**：只查**改动过和还没跟踪的**文件，取法照 `changedFileSecretScan.mjs` 的 `uniqueChangedFiles`。不做全量扫描，因为 `docs/audits` 有 206MB、2162 个文件，全量扫一次就不轻了。范围是 `docs/agent-ops/records/**`、`docs/audits/**`、`docs/agent-ops/handoffs/**`（单卡里会写证据路径）和 `current-state/board.md`。
   - **`.md` 文件**：以下报红：
     - IPv4 地址，但 `127.0.0.1`、`0.0.0.0` 和 `152.0.0.x` 这类浏览器版本号放行
     - 本机路径：`C:/Users/`、`C:\Users\`、`/c/Users/`、`AppData`、`.claude/ops`
     - 邮箱，但 `example.*`、`*.test`、`*.invalid` 这些保留域放行
   - **原始日志**（`.txt`、`.log`、`.json`）：只查 IPv4 和邮箱，不查本机路径。builder 是在 `AppData` 下的副本里跑命令的，每份原始日志都会带上这个路径；全查的话每次收割都红，最后就没人理它了。
   - 占位写法 `<home>`、`<ops>` 放行。
   - **不并进** `check:changed-file-secrets`：那条只挂在重型的 `verify` 链上，并进去就离开了轻量的 `docs:check`。

**怎么跑**：没有 CI，钩子也没启用，所以把 `docs:check` 直接写进收割用的那一条提交命令里（`node scripts/docs-index.mjs && node scripts/docs-inventory.mjs && npm run docs:check && git add … && git commit …`）：检查一红，提交就不会发生，不靠谁记得去跑。pre-commit 钩子：Henry 已拍「开成真拦」，而且只有 Main_Designer 提交。注意：现有钩子只警告、不阻断（任何失败都 exit 0），整体还有 60 秒超时，所以光启用它不等于有了门禁，钩子本身也要改。具体改法见规矩修改稿 `analysis/2026-11-07-role-records-rule-changes-draft.md` 第六节。
**阳性对照**：脚本上线那一单，必须附 6 个故意违规的样本，证明每一项都会报红。
