## 3. 取证方式(以及它的边界)

| 要证的 | 取证 |
|---|---|
| 收据内容 | 直接读客户端投影产物 / 网络请求体,**不看页面文案** |
| 解析结果 | `read_network_requests` 取 **`/api/mcp` 真实响应体** |
| ⭐ **只读性** | 调用前后 `operation_batches` **行数不变**(只读 DB 副本查) |
| ⭐ **J4 不可区分性** | B 携 A 的 ref 与 B 携**纯不存在**的 ref,**两个响应体逐字节 diff** |
| J3 成因 | 查 DB:block 行是**消失**还是**被标记** |

### ⚠️ 已知取证天花板(**先写明,免得把方法的限制说成产品的结论**)

- ⭐ **DB 取证必须连 `-wal`/`-shm` 一起复制** —— 库是 WAL 模式;只复制 `.db` 会读到旧快照,**得到一个看起来完全正常的空集**(先例:12.2b-4,差一步就判成产品缺陷)。
- 合成 `KeyboardEvent` **不触发浏览器原生默认动作** ⇒ 依赖原生按键手感的部分本轮不产生证据。
- ⭐ **圈选本身**是最可能栽的一步:合成鼠标事件能否产生真实 `Selection` 尚**未验证** —— 若不能,J1 就走不通。**这不是产品缺陷,是取证手段的天花板**,须如实分开写。
- 亚 200ms 竞态排除不了 —— 「没观察到」≠「不存在」。
- ⇒ 凡测不了的,**写「未取证」,不写「通过」**。
