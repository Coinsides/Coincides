## 1. 四步操作化(**实走前冻结;⚠️ 含三处需 Fable 确认的判读**)

| 步 | 预期原文片段 | 操作化(怎样算 **2**) |

### ⚠️ 需 Fable 确认的三处判读(**我不自行拍板,先冻结问题**)

1. **J1「身份齐」的判据** —— 我操作化为「三元组逐字段回参且等于收据值」。**若你的原意只是「返回 `found` 即算齐」,请说**,两者严格性差很多。
2. **J2「改该段文字」的位置** —— 我操作化为**改选区窗口内**的字。⚠️ **若改在选区之前**,offsets 整体推移,按 c-2 语义**同样报 `text_drifted`**,但它验的是**另一件事**(位移而非改写)。**我按「窗口内」走,并把「窗口前」作为附加观察记录,不计分。**
3. **J3 的删法** —— UI 删 block 走的是软删还是硬删?若软删后 block 行仍在、只是标记,`missing` 的成因就与预期设想的不同。**实走时我会取证成因,不只取证态。**

### 【裁定 · Fable 2026-08-24】四件(**冻结前澄清,非事后对齐** —— 裁定原文,⛔ 不得改写)

> ① **J1 判据:采严格版** —— 三元组逐字段回参且等于收据值。理由:恒返 `found` 的空壳在宽松判据下也过,严格版才有鉴别力(第六分则的正向应用)。加一句:`textFlowId` 的回参一致性**同时兼验 C 裁定那道校验没被绕过**。
> ② **J2:采** —— 窗口内改写计分;窗口前推移作附加观察不计分,**位移≠改写,两件事分开记**。
> ③ **J3:采** —— 取证成因不只取证态。补一条:**若 UI 删 block 是软删且 resolve 因「行还在」返回 `found`,那不是取证瑕疵,是真 finding**(resolve 与「什么存在」的权威约定不同源)—— 按缺陷分诊,⛔ 别当观察记完就算。

## 1b. 天花板前验(依裁定⑤,**在打扰 Henry 之前**)

**做法**:在 `:5173` 登录页注入一个探针 `<textarea>`(与产品 TextBlock 同型),用完即删;分别试三条路径。**⭐ 探针自身先证有效**:`document.activeElement === ta` 为 `true`,证明焦点确实落在探针上。

| 路径 | 结果 | 实测证据 |
|---|---|---|
| **键盘选区**(`shift+方向键`) | ❌ **不可用** | `shift+Right` 写在 text 里 ⇒ 光标从 13 走到 22(`13+3+6`,**恰好**),但 `selectionStart === selectionEnd` —— **方向键的原生动作生效了,shift 修饰没被带上**。改用 `modifiers: "shift"` 参数 ⇒ 光标**一动不动**,连移动都没了。另:`Home` 键**无效果**。 |
| **坐标点击 / 拖拽** | ⛔ **本轮不可用** | `left_click_drag` 与坐标版 `double_click` 都**强制要求先截图**,而截图要求 Browser 面板处于显示状态,当前未显示 ⇒ 5s 超时。 |
| ⭐ **按 ref 双击选词** | ✅ **可用** | `double_click(ref)` ⇒ `selectionStart=50 / selectionEnd=55 / selected='india'`;**`startOffset > 0` 且 `selected !== whole`** ⇒ **有鉴别力**。 |

### ⇒ 结论:**J1 不必为"拖选"打扰 Henry**

**合成输入能产生真实 textarea 选区** —— 只是路径不是拖拽,是**双击选词**。⇒ 裁定⑤ 里"若验出走不通就把拖选并进同一次打扰"的**备用分支不必启用**;打扰仍只需 **登 A + 登 B 两个动作**。

### ⚠️ 但仍有一个**未取证**项(⛔ 不得当成已通过)

**本次只证明了「浏览器层能产生选区」,没证明「产品层会捕获它」。** 产品的选区草稿服务监听的是哪个事件(`mouseup` / `selectionchange` / 其它)尚未查证;**若它只认拖拽产生的事件,双击选区可能不进草稿**。
⇒ 这一项**须登录后在真实 note 里当场验**,是 J1 的**第一个动作**,⛔ 不是可以跳过的前提。**若它也不成立**,那时才启用裁定⑤ 的备用分支(请 Henry 拖选一次)。
⭐ **排期见 §2「打扰脚本」第 3 步 —— 它必须在 Henry 离开之前执行**,否则失败时会产生第二次打扰。

📌 **原则边界(裁定 Fable 2026-08-24 ③)**:走查的**记分证据**必须取自产品实证;但**读码用于排期风险预案**(估计要不要备兜底)**不算置换** —— **置换的定义是「顶替证据」,不是「提前了解」**。本例因第 3 步的当场兜底设计已不需要读码。

## 3. 取证方式(以及它的边界)

| 要证的 | 取证 |
|---|---|
| 收据内容 | 直接读客户端投影产物 / 网络请求体,**不看页面文案** |
| 解析结果 | `read_network_requests` 取 **`/api/mcp` 真实响应体** |
| ⭐ **只读性** | 调用前后 `operation_batches` **行数不变**(只读 DB 副本查) |
| ⭐ **J4 不可区分性** | B 携 A 的 ref 与 B 携**纯不存在**的 ref,**两个响应体逐字节 diff** |
| J3 成因 | 查 DB:block 行是**消失**还是**被标记** |

### ⚠️ 已知取证天花板(**先写明,免得把方法的限制说成产品的结论**)

- ⭐ **DB 取证必须连 `-wal`/`-shm` 一起复制** —— 库是 WAL 模式;只复制 `.db` 会读到旧快照,**得到一个看起来完全正常的空集**(先例:12.2b-4,差一步就判成产品缺陷)。
- 合成 `KeyboardEvent` **不触发浏览器原生默认动作** ⇒ 依赖原生按键手感的部分本轮不产生证据。
- ⭐ **圈选本身**是最可能栽的一步:合成鼠标事件能否产生真实 `Selection` 尚**未验证** —— 若不能,J1 就走不通。**这不是产品缺陷,是取证手段的天花板**,须如实分开写。
- 亚 200ms 竞态排除不了 —— 「没观察到」≠「不存在」。
- ⇒ 凡测不了的,**写「未取证」,不写「通过」**。
