# 设计宪章对后续路线的影响清单

## 一 · 总判:无版本需要推倒重设计;一份章程候修订,两个版本候加料

宪章的绝大部分是**法与公约**(零新工程),建造件与既有排队高度重合。逐版本盘点如下。

## 二 · V14(收尾中):零重设计,收尾批加两件小料

1. **既有工程零返工**——恰相反,宪章追认了已建成物的正确性:token/角色体系(皮肤)、component_kind 信封、display_overrides 透传、存为套装、浮卡,全部是宪章插座的现役实例;
2. **收尾批新增候翻两件**:①**出生公约入工单模板**——凡产新元素的单(G1 封面预设/G2 目录块/N 件等)附血统条款(⛔字面 hex⛔硬编码字体,只许 token/角色/节奏引用),零成本;②**图鉴血统检查**——审 99 件现役元素揪硬编码值,小单级;
3. **G6 富块提案管线**(收尾批已列,权重最高)——工单起草时烘入血统条款:Agent 产的块参数化于 token;
4. **E 波验收**(候 Henry 出题)——可选:验收语言采「不违和/讲清楚」二分与眯眼测试,零工程纯措辞;
5. **manifest v0**:可作收尾批候选(纯派生读面,便宜)或滚 V15 头——HQ 倾向 **V15 头**,与契约同批设计口径更省(见三)。

## 三 · V15(未立项):建议维持判定层为脊柱,设计域以两小件随行——此为唯一需 Henry 选路的版本级决定

- 09-19 路线建议的 V15 = 判定层(三色判定/目的树/编年史)。宪章新增候选:设计域三件套(manifest/契约/状态栏纪律层)+呈现语法;
- **HQ 建议的切法**:V15 脊柱不变(判定层);设计域只随行**两小件**——manifest(传感器,先行铁律)+ 契约 v0(浮卡纪律层:风格声明+语义映射+偏离登记簿,机制与判定层同族,可共用「应然/实然/收据/偏差」的机械件);
- **呈现语法⛔入 V15**:V15+ 真系统,单独立项(或归产房专项),防止 V15 膨胀违背基础优先决;
- 备选切法(供翻牌):设计域整体滚 V16,V15 纯判定层——代价是「样子的判定域」与「内容的判定域」错过共建机械件的窗口。

## 四 · 产房专项(排期 V14 尾/V15):唯一候修订的章程

组件产房章程(2026-08-29)第 2 站经济学被宪章第七条改变:**「样子」走呈现语法(数据),仅「行为」出码走三级转正**。修订属文档级(便宜),但影响产房开工的工程形状——**产房开工前须先裁呈现语法立项与否**,二者顺序绑定。OpenDesign 可行性问题卷(draft)新增一问:能否产出 token 参数化资产(而非字面值 HTML)——这决定导入闸的自动化程度。
