# 审查结论：V2.BN.8.11.3（shape）+ V2.BN.8.11.4（block-backed shape）

> 6-agent 对抗审查 + Claude 亲自定案。方法上有一处 agent 互相矛盾的大 finding，由我读真码裁定（见 HIGH-1）。

## 总评
- **都是真活，不是 patch-note 表演**：shape 是真正薄的 registry handler（无新 if-kind 核心分支）；block-backed 生命周期主体可靠；migration 039 正确（probe 验过）；测试 29/29、browser-smoked。
- **判定：CONCERN** —— 两颗**真 HIGH 坑**（都在 AI 可读层）+ 一簇 MED 生命周期坑/功能缺口。**happy-path 无数据腐败**，但拱心石的 AI 层被污染、demote/restore 边路有真缝。

## 一、坑 (pits)

### 🔴 HIGH-1 双真相源：每个 page_frame / 每个画布上的块，在 runtime + AI 快照里出现两次（已亲验）
- 8.11.3 接 generic 持久化数组时**没加 kind 过滤**；`engineModel` dedup 按 objectId（engineModel.ts:393），但 **runtime id ≠ 持久化 id**：`buildBlockCanvasObject` 用 `placement.objectId=block.id`（placementService.ts:242），`buildPageFrameObject` 用 `pageFrame.id`（engineModel.ts:118）；持久化用 `canvas-object:{note}:block-placement|page-frame:...`（037）。`getNoteCanvasPersistence.canvasObjects` 返回所有 kind、无过滤（canvasObjects.ts:1406-1411）。
- 结果：持久化的 page_frame + paragraph_block_projection **泄进 runtimeGenericObjects/Placements/Mounts**，AI 快照对同一实体生成**两个节点**（canvasAiTreeService.ts:317-347），重复 page_frame 还冒成第二个顶层容器。
- **裁定**：3 个 agent 说"dedup 生效、不泄"，但都假设 runtime id == 持久化 id；实测 placementService:242 用 block.id，**泄是真的**。
- **修**：过滤 `persistedCanvasObjects` 只留 generic 该拥有的 kind（shape/image/table/visual_connector），排除 page_frame/paragraph_block_projection，再传 `genericCanvasObjects`；加 boundary 断言"generic 对象不得含这两 kind"。

### 🔴 HIGH-2 隐藏块泄进 AI projections（server 侧无过滤）
- shape 的 backing 块的隐藏规则**只活在 client React filter**（modePolicyService.ts:73）；server `buildSnapshotFromNote`（routes/projections.ts:59-79）选**所有** active note_blocks、**无 render_scope 过滤** → AI"组织笔记"消费的快照里，shape 文本以**脱离 shape 的孤立顶层块**出现。
- **修**：hide 规则下沉数据层——buildSnapshotFromNote（及任何喂 AI/导出的 server 块列表）加 `json_extract(metadata,'$.render_scope') != 'canvas_object_backing'`。

### 🟡 MED 坑群（block-backed 生命周期）
- **孤儿 placement 行**：demote/delete 只把 backing 块 status 置 trashed，**从不删 `note_block_placements` 行**（canvasObjects.ts:710 + noteBlocks.ts:112）→ 累积孤儿、吃 order_index 槽。
- **restore 孤儿（相对不焊绝对 违例）**：trashed backing 块仍带 {render_scope, shape_object_id} 元数据；从回收站 restore 后被永久过滤出文档、但其 shape 已不存在 → **一个看不见、删不掉、改不了的 active 块**。restoreBlock 不 strip 元数据（useNoteCanvasDataAdapter.ts:847-883）。**render_scope 这个目的相对属性焊在块的绝对身份行上，关系没了它还在。**
- **非原子双 trash**：server 已 trash（writeExtension/cleanupOnDelete）+ client 又 onTrashBlock 一次（NoteWritingSurfaceLayer.tsx:1509/2477）→ 部分失败 client/server 发散。
- **re-promote 无界累积**：remove-text 再 add-text，reuse guard 看不见 trashed 块（NoteWritingSurfaceLayer.tsx:1418）→ 每轮新建一个 backing 块。
- **shape_object_id 未复核**：cleanup 仅在 `metadata.shape_object_id===objectId` 才 trash；不匹配就跳过、却仍删 mount/object → 留 active-but-hidden 孤儿（canvasObjects.ts:715-725）。

### 🟢 LOW 坑
- **`__test_probe` 在生产 validator union + KIND_HANDLERS 上线**（validators/index.ts:588-593 / canvasObjects.ts:1216，无 NODE_ENV 守卫）→ 任意用户可经 generic PUT 写 __test_probe 对象。该 test-only 守起来。
- normalizer 静默丢 placement.layout_policy + mount.metadata（对 shape 无害，未来 kind 会丢）。
- backing 块隐藏靠 3 字段元数据三连，任何 metadata 覆写路径（模板重应用）会清掉它、un-hide 块。
- 未知 shape_type 静默渲染成 rectangle。

## 二、要完善 (improve)
- backing 块清理"双源"→ 让 **server 单一权威**，client 从响应 reconcile，去掉冗余 onTrashBlock。
- migration 039 `INSERT OR REPLACE` 理论上静默有损（老 schema 保证无 dup，可接受）；`page_frame_extensions.object_id` 索引非唯一、1:1 靠约定（object_id 已 note-unique，可上 UNIQUE）。
- shape delete-cascade 测试用 existence 而非 `COUNT=0`（block 路径已用 COUNT），对齐即可。
- client filter 用 OR、server validate 用 AND 的 backing 元数据 key 集不一致；两处构造器（shapeProjectionService vs shapeTextMountService）会漂——收成一个。

## 三、功能缺口 (feature-gap) —— 对"成熟"最相关
- **🔴 demote 销毁用户文本**：remove-text 把承载文本的唯一块 trash 掉，只有 generic toast → 用户在 sticky 里写一段、选"去掉文本"，**内容没了**。违"工具+心爱之物 / Agent 能编辑人也能编辑"。**建议：remove-text 给"留成普通块 / 丢弃"二选一 + 显式确认。**
- **shape 文本不进导出**：写在 shape/sticky 里的文本 export preview 看不到（buildExportPreviewModel 喂 visibleBlocks、排除 backing 块）。要么投影进导出，要么 UX 标 canvas-only，别静默死路。
- **空文本残留**：清空 shape 文本不 auto-demote，留 active 空块、仍喂 AI/搜索。定一条规则（自动 demote 或排除空 backing 块）。
- **可发现性差**：shape 和 Add-text 只在右键菜单、只在 canvas mode；无工具栏/快捷键；page mode 看不见 shape。对"成熟=真用户找得到"，至少加一个常驻 Add-text affordance。
- **样式固定 v1**（无色/描边；sticky 仅矩形；preset 仅 block-backed 可换）——证管线够了，diagram/sticky 工作流的表达力缺口，可推迟。
- **resize 脆**：14px 单角手柄、无键盘/max-clamp（smoke 的 CDP Input timeout 就撞这）——能用但脆。

## 四、路由建议
- **建议给 Codex 一份 hardening handoff**，优先级：HIGH-1（双真相源加 kind 过滤）→ HIGH-2（server 隐藏块过滤下沉）→ restore-孤儿（铁律）→ demote-销毁文本（产品红线）。其余 MED/LOW 凑一批。
- 对照"成熟"：功能缺口里 **demote-销毁文本 / shape 文本不进导出 / 可发现性** 是真用户旅程会撞的墙，该排近线。
