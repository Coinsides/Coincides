# 设计会议记录:库治理 · 自由学习 · 三位一体 · 导入窄腰

## 一、为什么有这场会

V12 收版前夜,Henry 判断:能力边界随地基成长首次可见,「用户真正要什么」第一次成为可正经讨论的题目。本场从一个具体担忧(AI 检索加入后库会爆炸成整理地狱)出发,十六轮推到产品自我定义。**多数结论超出单个小版本的容量——这正是设计,记录即保存。**

## 二、库治理(轮 1–5、9)

1. **两层楼**:原始文档库=散沙层(备用候选资格,零门槛零整理零承诺);引用源=**拓印件**(原始文档在我们软件里的忠实复刻,页码样式保真,碎片现成可用)。晋升条件=**一个使用决定**(征用),⛔ 不需要机器猜想——靠「被用」不靠「被理解」。
2. **门口设卡,货架不设卡**:Agent 引入新源必须附查重申报收据(指纹+近似指纹);「找材料」动词强制库内优先;分类不建文件夹,靠出生语境+使用轨迹自动生长;视图是读时投影。
3. **只保工作集,不保全库整洁**:未被再用的源躺着成本为零;简历(多重征用记录)喂检索排序。
4. **概念重复是知识层的原料非文档层的病**:多定义=多证据;收敛=金字塔(概念一个 Item,定义多条带出处证据);⛔ 机器不裁「哪个定义对」。

## 三、折叠的多样性(轮 3–6,canonical 文本在章程第六轮)

一处多候选:默认位放此刻最合身的一个,其余折叠在一步之遥的安静入口;用户四权(换选/自写/令 Agent 熔铸/踢出误入者);系统四义务(候选带出处/换选留收据/默认可逆/不打开不欠债);**三层自相似**(选哪个定义/穿哪件壳/旋钮拧多少)。AI 直接熔铸合法的前提:母本零动、标 AI 铸、占可逆默认位、**下拉本身=常设非阻塞咨询**。设计选项交付=场景默认→选中即旋钮→换壳是一个旋钮。

## 四、检索的边界原则(轮 2,Henry 定)

「够不够」归模型判断;我们只造「看得见、查得快、**对没有也诚实**」的机制(检索结果自带「我怎么找的」)。**尺子:凡「替模型想」的功能不做;凡「让模型看得见/查得快/查得诚实」的机制做。**

## 五、自由学习(轮 10–12)

1. **骨架=用户自生的问题串**(大学学习骨架外来;自由学习骨架不可预制)——产品机会:让问题串显形,疑问是一等公民。
2. **两种学习一条管线,区别只在征用的驱动者**(大纲驱动批量 vs 问题驱动增量;作品即里程碑)。
3. **对自由的默认假设=节奏不是路线**:每段自由学习默认想收口成一件作品;征用多铸造零=堆积信号(收据可见);提醒走 G1。
4. **跨 project 复用零新机制**:拓印整本归全库(灭佛铸 1%,99% 现成留给通史项目);库内优先+简历自动复现。归属:原件/拓印件/条目归全库,作品/征用/问题串归 project;⛔ 永不做项目文件夹式存储隔离。
5. **分支:停放+家谱,不整理**:好奇心的停车场(停放成本趋零);升格开新 project 行李自动继承;组织=血缘+共源算出的图(读时投影);注意力协议=一次一条主线。
6. **好用两标准**:火花到作品的距离;**旧物在新旅程的复现率**(真护城河)。

## 六、三位一体(轮 13–15)

**信息精加工平台 × 个人知识库 × AI 的推理车间。**冶炼厂建在矿山上;飞轮=加工产生库存、库存降低下次加工成本;两把尺子各守一身份。第三身份(AI 借库做超上下文推理,报告身后拖着可拆的车间)=二月 MU 记忆框架的原点回归,**我们自己(agent-ops 工作流)是它的第一个用户**;AI 用库走同一扇门。🅿 停车场首车:**异库辩论**(给辩手各配不同的库=真正两种知识背景)。

## 附录 A(轮 17):文件类型盘点 → 五锚族(选品前置,Henry 判「选品稍早,先盘类型」——采)

**现状地基**:仓内解析家族已活(`sourceArtifact.ts` PARSERS):txt/md/csv/PDF/docx/xlsx,页级锚。

**类型清单**(来源场景 · 锚形状 · 难度):PDF 数字原生(页+位置,已吃)/ PDF 扫描(页+区域,最难,走识别器)/ HTML 存档(标题路径+偏移,正文抽取是关键)/ docx(标题路径+段落,已吃)/ EPUB(=打包的 HTML,章节+路径)/ PPTX(页+形状,大学 lecture 主力)/ xlsx·csv(表+单元格,格子天生是碎片,已吃)/ 图片·板书照(整图+区域,走识别器)/ 纯文本·md(行偏移,已吃)/ 音视频(**时间戳锚**,自由学习的火花源头;V12.9 不选品,🅿 停车场)。

**⭐ 盘点的真正产出:类型十余种,锚只有五族**——①页面族(页+区域)②流式结构族(结构路径+偏移)③表格族(表+单元格)④幻灯族(页+形状)⑤时间轴族(时间戳区间)。**带锚碎片流的锚字段按五族设计**;新格式=新演员,五族=舞台地板。选品考法改判:不考「支持多少格式」,考「**每族里谁的回程票最真**」——一族一冠军,可五工具,腰统一。

**实务两句**:知识产权——库本地私有,格式对产品中立,不设机制;唯一工程事实=DRM 锁的文件解析器打不开(技术障碍非立场)。

## 附录 A 再续(轮 19):迁移件与对话记录的格式实况——三等级 + 「有数据不取渲染」

Henry 问:对话记录/笔记迁移件是不是都是 HTML?**答:分三级,多数比 HTML 好**:
①**结构化数据级(白捡)**:ChatGPT/Claude 导出=zip 内 `conversations.json`(消息/角色/时间戳全显式,附带 HTML 只是查看器)· Anki .apkg=**SQLite**+媒体 · Evernote .enex=XML——转写≈翻译,锚天生是数据;
②**Markdown 原生级**:Obsidian(库本身就是 md 文件夹,零导出)· Notion 选 md 导出(+CSV);
③**HTML 渲染级**:Notion-HTML/论坛存档/第三方微信·Discord 导出——走正文抽取,与存网页同族;OneNote 最糟(无干净导出),微信无官方导出。
**规格级规矩:导出包内数据与渲染并存时,有数据永远取数据不取渲染**——渲染是给人眼的投影,数据是真相(=「markdown 是碎片流投影」裁定在业界的镜像,方向背书)。这批几乎全是 zip ⇒ 容器策略是统一入口。

**轮 20(确认):底层载体 × 产品方言**——Henry 之解「基础类型先做好,Obsidian/Notion 等是衍生」:采,精确化为:底层载体处理器(md/HTML/JSON/SQLite/XML/PDF/图片,对应锚族,重投资先建)+ **方言适配片**(每产品一张薄片:认识其私有约定、翻译进标准碎片流、**保住语义角色**——如 Anki 卡片正反面);方言片按需添,⛔ 不预写没人用的(grow-by-use)。「壳与插座」第四次出现(组件/harness/转写器/方言)——已属产品基本语法。

## 附录 B(轮 21):底层载体处理器清单(后缀 × 锚族 × 优先级)

**前置原则:入库永不拒收**——散沙层收字节,任何后缀可进(存原件+指纹+按名可发现);处理器只决定「能否拓印」不决定「能否进门」;无处理器的类型躺库等处理器到货。
- **T0 已有**:pdf/docx/xlsx/csv/txt/md(现役解析家族,页级锚,待升带锚碎片流)
- **T1 V12.9 必备**:html/htm/mhtml(正文抽取)· epub(=打包 HTML,半价)· pptx(lecture 主力)· srt/vtt(字幕先遣)· png/jpg/jpeg/webp(识别器车道)· json/jsonl(**方言地基**)· zip+文件夹(容器策略)
- **T2 按需**:代码后缀**不枚举**(文本兜底策略覆盖)· ipynb · enex/XML · SQLite 只经方言片(Anki)
- **T3 低优先/停车**:djvu/caj/eml · 旧二进制 Office(转换后入不直啃)· 音视频(🅿 字幕代偿)
- **两条兜底(比清单重要)**:①文本兜底:未知后缀+内容可判文本 ⇒ 纯文本处理器接住(行锚);②二进制兜底:判不了 ⇒ 只存不拓。**⇒ 清单永远不会「漏」,只会「晚」;晚可接受,拒收不可以。**
