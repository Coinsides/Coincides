# 对照实验:同一份 ECON 讲稿,网页版 vs 应用手搓版(2026-08-08)

> Henry 发起:"把你(另一会话)做的复习网站,在我们应用里原样做一遍,看对比。"
> 执行方式:Claude 装成用户,内置浏览器鼠标+键盘操作,不走 API(JS 仅用作"眼睛"验证状态,未用作"手")。
> 素材:July 8《跨时期价格歧视》完整讲稿(7 节+附录;原网页含分数排版/SVG 图/表格/三类卡片)。
> 账号:test@test.com;位置:ECON 201 项目 → 新笔记,Canvas 模式,单段落块。

## 一、结果

**内容层:全量落地。** 题头 3 行 + Section 0–6 + 附录变量速查,约 1800 字符,经"只进不退"连续打字一次成型;Unicode 数学记号(½ ¼ δ ε π ⟺ ∈)渲染正常;自动跟随光标滚动正常;60% 缩放整篇一屏可读。

**形式层:全面落差(预期中,正是实验目的)。** 网页版有:字阶层级/眉标/三类卡片/居中显示公式(真分数)/SVG 图/结构化表格;应用版为:单一字号平文本,层级只靠我手打的【】记号,无卡片无显示公式无图无表。**"格式的成熟感来自默认值"在对照中直观成立——同一内容,排版预设的有无 = 成品观感的量级差。**

## 三、对照结论(供概念稿引用)

1. **内容真相层能力完好,表现层欠账集中**——与"总账第 0 号"(每天不想用)的诊断一致:账单到期,非设计破产。
2. **强默认排版预设的价值被实验直接量化**:同一内容,有预设(网页)与无预设(应用)的观感差 = 用户每天面对的落差。12.2"日常书写段"的核心交付应为排版预设+角色快捷通道(斜杠/markdown/角色下拉三通道至少修通一条键盘流)。
3. **发现 3/6/9/10 构成一条主线**:编辑焦点与可见内容的对位关系脆弱——这不是四个孤立 bug,疑似同一个 runtime 焦点/坐标管理缝的四种症状,建议 Codex 按一个 root cause 查。
4. 发现 4 是 canvas 自建检查线(AI-readable tree 对齐 DOM 呈现)的最强依据。
