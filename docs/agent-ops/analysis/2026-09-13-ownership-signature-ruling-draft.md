# 权威 ownership 签名裁定稿(TD-15 设计步)

**问题**:`getOwned*` 全仓 14 份实现,同一条 SQL、同一个 404,签名各异——ownership 是安全边界,各自演化=加固时会漏改。收敛前提是先定权威签名(台账原文)。

## 裁定稿(三题三答)

1. **收不收 `db`:收**。签名 `getOwnedX(db, userId, xId)`——理由:事务内必须复用同一连接(不收 db 的版本在事务中另开连接=事务外读,一致性洞);显式依赖可组合可测。非事务调用方传默认连接,零负担;
2. **返 void 还是实体:返完整 owned 行**。返 void 的调用方往往紧接着再查一次(双查反模式,现物 organizedNoteProposals 返 {id,name} 即为此妥协);统一返行,调用方自选字段。查无=抛 404 明码(现役语义不变);
3. **参数位序:`(db, userId, xId)`**——连接先、作用域次、目标末,全家统一。

## 附则

- 命名统一 `getOwnedX`;住所维持各资源 service 文件(⛔预设集中巨文件,收敛专项时再裁归所);
- **机械闸**(收敛时同批加):签名契约测试——枚举全部 getOwned* 导出,断言参数形状与返回形状一致,新增第 15 份不合形即红;
- **收敛执行=V14 专项**(连 TD-16 循环依赖一并);在此之前任何单触及其中一份仍⛔顺手统一其他份(TD-15 禁令原文继续有效);
- 本稿转正后,13.x 后续新增资源的 getOwned* **必须按本签名写**(增量止血,存量候收敛)。
