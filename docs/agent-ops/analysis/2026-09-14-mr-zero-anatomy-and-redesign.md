## 六 · 知识跟版体系(Henry 09-14 第二问:"新组件他怎么知道"——草案)

**前提承认:Mr Zero 永远不完整,宅子会一直加房间(小游戏例)。** 故资格闸判据精确化:⛔"认识每个房间"(不可达),**="没有未登记的房间"(已知漂移=0)**。三层跟版:

1. **自动跟版**(机器可导出的能力事实):工具清单/入参 schema/tier/提案型/块型枚举——**从 V2 注册表 manifest 生成 prompt 能力节**(manifest 本就随构建再生+有 parity 闸)——新工具注册→prompt 能力节自动跟;⛔手写工具清单进 prompt(手写必腐);
2. **义务跟版**(机器导不出的世界观:功能为何存在/用户怎么体验/边界真话):住说明书;双保险=①工单申报义务"说明书条目已更新/无涉"(已立)+②新增机械闸 `check:agent-knowledge`:注册表/路由面指纹变动而说明书版本戳未动=门红——**知识欠账挡在 commit 口,⛔靠记性**;
3. **评测跟版**(知道≠会用):**每张交付新面的工单随附 1-2 个评测场景**(如测试随代码)——夜跑评测集自动验证管家真会用新房间;资格清单=活文档,加房间=加行=加场景。

**同源申明**:此体系与文档防腐条款、item 血缘登记是同一条设计公理的三次应用——**凡靠记忆保真的都会腐,凡与"使其失效的变更"物理挂钩的才活**。

**落地序**(候拍):自动跟版=针一收口后的下一小单(prompt 能力节改由 manifest 生成);义务跟版闸=小单;评测跟版=随评测集立起(§五.2)同批。
