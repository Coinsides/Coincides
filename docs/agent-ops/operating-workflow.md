## 1. 三层文档驱动,消息退为指针

| 层 | 文件 | 作者 | 内容 |
|---|---|---|---|
| **Plan** | `handoffs/plans/<version>.md` | Fable | 目标 / DoD(契约门+旅程分数)/ 触及面申报 / 编号步骤(各带 RED 靶)/ 边界 / 步骤状态表 |
| **Order** | `handoffs/<date>-<单号>-order.md` | Main_Designer | 施工单:规格 + 顶部单卡(覆盖写);裁定和 Result 追加在尾部 |
| **Receipt** | 订单尾部 Result;`docs/audits/<日期>-<单号>/{builder,tester}/`;`records/tester/verdicts.md`;`claude-log/` | builder / Tester / Main_Designer | 见各角色卡 |

**消息纪律**:跨会话消息只用于 ①方向变更 ②一行指针(「X 已落盘」)③升级告警。**报告不进消息**。
*理由:文件是权威通道(CLAUDE.md);消息里重述文件=同一事写两遍、两个会话各吃一遍上下文(08-20 实测)。*

## 2. 指挥链(Henry → Main_Designer → Tester / builder;2026-11-07 起)

- **Main_Designer**(固定由主设计会话担任):设计、裁定、派单、收割提交、部署、对 Henry 汇报;维护看板、台账、tech-debt 与生成件。**不做验收,不写产品代码。** 角色卡 `roles/main-designer.md`。
- **Tester**(Claude 会话或 Codex 代理):对抗式复核、冻结快照、下判语、部署后复走、回归。角色卡 `roles/tester.md`;复核纪律承接原 reviewer 角色卡 5-1 到 5-10。
- **builder**(Claude 会话或 Codex 代理):在副本里施工,交 Result 和证据。角色卡 `roles/builder.md`。
- 三者共读看板 `current-state/board.md`;一切指令和交接落在文件里,会话短讯只是指针。
*理由:昨日 Fable 兼任调度员,34 场 codex 会话逐单重读全仓;策略上下文被代码细节挤占。调度下沉后 Fable 上下文回到设计层。*

## 3. 版本纪律

- **结构**:`V2.BN.12.x` 按必修件:12.1 编辑基座(已铸)→ 12.2 MCP 工具面 → 12.3 选区收据 → 12.4 流式装配面+地板 → 12.5 层0/层1 → 12.6 收口(随行三线+契约冻结+旅程总验收)。**一个 12.x = 一份 plan。**
- **铸版动作**(plan 收口时,一次成型):checkpoint commit → **注解 git 标签** `v2.bn.12.x` → ROADMAP §3.5.1 → current-state §1 → claude-log → 迷你复盘(三行:哪里不顺/哪条债/下版带走什么)。
- **补丁版** `12.x.y`:铸版后的修理批(如旅程分数挖出的),Fable 定。
- **大版本收口**(V12→V13):**复盘文档** `analysis/<version>-retrospective.md`——真正使用不便清单 → 优化积压 → 进下一版 plan。
*理由:Henry——「我们目前是没有版本的,需要有记录」;标签让版本成为 git 实体而非路线图里的一行字。*

## 6. 流程精简八条(Henry 2026-11-08 批;起因:「上岛之前我无法参与测试」,上岛快 = Henry 能上手,他的使用就是测试)

1. **验收臂先于施工**:派单时 Tester 先把本单探针写好交 builder;builder 封包前自己跑同一套探针,红不封包。目标:包到 Tester 手里只一轮。
2. **不无据预裁**:Main_Designer 不知道现状的地方只提问,不预裁;预裁只写有证据的。
3. **一处写**:每单一个订单文件(旧文件关闭不再追加);看板与单卡只放一行指针;台账按里程碑(派单 / 裁定 / 收割 / 部署)一条,判断点合并写,不按每封短讯一条。
4. **每单验过即上岛**,不等同阶段其他单(Henry 要尽早上手);岛上对账改轻:哈希脚本对账 + 三到五条代表臂,全套回归留到阶段末。
5. **Tester 必做 / 里程碑分开**:每包必做 = 同源核对、本单验收臂(修后)、只跑本单直接相关的修前阳性对照、改动面周边 ≤10 条定向冒烟、判语 + 台账行 + 证据扫描、有 🅰 疑点时的独立旁证;阶段末一次 = 跨单回归套、server / client 全量、说明书逐句、真人走查 / 触屏 / 其他浏览器、METHOD 整理。确定性场景 1 轮,抖的才 2 轮;修前不跑全套回归(回归比的是说明书「已知」)。
6. **全量由 builder 每包跑一次**(server + client),Tester 不重复;Tester 的同源重建 dist 保留(F9 闸)。
7. **重活锁放宽到两个并行**:各自压 40% 以下、总量仍 <90%、工作流 ≤4、浏览器 ≤3(Henry 红线不动;「一次一个」是 Main_Designer 11-05 自加的保险丝,放宽一档)。
8. **Reviewer 只核碰写入路径 / 数据的单**;纯显示单跳过。

**代价与兜底**:回归红可能到阶段末才出现 → 每包有 builder 全量 + 定向冒烟,包是原子提交,出红按包二分。阶段的起止由 Henry 定;阶段末封版后进 Henry 日用期,使用摩擦是下一阶段唯一订单来源,除 🅰 不部署。
