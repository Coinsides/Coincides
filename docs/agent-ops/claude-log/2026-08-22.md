### 两条 killer 的质量

**H-1**:纯函数可注入,**生产 CLI 与测试 import 同一个导出函数**(不是复制)。fixture 四条 `public / internal / test / __reserved(public)`。

> ⭐ **一处它自己做对的设计**:**`__` 条目故意设为 public** —— 这样 exposure 误过滤与 `__` 误过滤**互不遮蔽**。若 `__` 条目也设成 test,一个过滤就能把另一个的靶子一起吃掉,killer 会假绿。**工单没要求这一点,是它想到的。**

RED = 过滤真删掉 internal/test 两条 ⇒ 基数 `2 !== 4` ⇒ 断言直接红。**不是 API 缺失的红。**

**H-2**:测试 **spawn 同一个生产 npm 入口**(`npm run docs:tool-face-manifest -- --check`),fresh/missing/stale 三态,**每态先取一次 fresh 阳性对照**。RED = 把比较分支改恒假 ⇒ stale 由同一生产入口误报 exit 0 而红。

> ⭐ **另一处它自己做对的**:子测试**先断言无 spawn error、无 signal、status 是数字** —— **防止「进程根本没启动」被 `status !== 0` 判成假绿**。
> **这正是我今天栽了七次的那一族错误(探针没跑成 vs 探针跑出阴性),它在自己的测试里主动防住了。**
