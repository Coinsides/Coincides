# Tester 方法与坑

> 给接班的 Tester，也给想知道「验收会怎么验」的 builder。**追加加修订**，每条写清「怎么做」和「为什么」，事由能指到报告就指过去。
> 私有的东西（凭据、服务器地址、本机路径、端口、账号数据）不写这里，在 `<ops>/roles/tester-state.md`；工具在 `<ops>/tester-kit/`。
> 首版由 Tester(1) 于 2026-11-07 从 11-01 至 11-07 的经验整理。

## 一、版本记账：你测的到底是哪个版本

- **每轮开测、收尾、发小结前，各只读核一次**岛上的 HEAD、服务重启时间、前端包名。部署短讯总比实际部署晚到，不能当版本依据。
- 纯服务端部署不换前端包名，光看前端指纹会漏。部署也可能在测试途中、没有通知就落地。按笔记、源的 `created_at` 切分哪项测在哪个版本上。
- **混杂期**：部署后，页面在刷新前还跑着旧前端，服务端已经是新的。这段时间测出的问题只算线索，要在刷新后的干净版本上重验才能报 🅰。
- **部署后核对**：等岛上**实际换了包**再开测（可以挂一个轻量监视，看前端包名）。先只读核 HEAD 和工作树是否干净，再把放行时冻结的文件在岛上逐个算 sha256，和快照清单比。
- 文件到底入没入库有争议时：`git hash-object <文件>` 对比 `git rev-parse HEAD:<文件>`，再查首次入库的提交。

## 二、冻结与副本

- 验 builder 的交付前，先把被验文件冻成副本，记下每个文件的 sha256。builder 可能已经在同一棵树上开了下一单。副本的路径要短，LibreOffice 的配置目录路径太深会静默失败。
- **打包整棵树**（`git archive HEAD` 加上改动文件），只打服务端会出几十条假红。
- 副本里全量多出来的红，先归因到环境，补齐后重跑：`CANVAS_ASSET_DIR`、`npm_execpath`、`.eval-runs`、`shared/dist` 不能是 junction、`docs/generated/tool-face-manifest.json`、MinerU 的 `uv.lock`。
- **不在共享工作树里换旧码做对照。** 有过一次：临时换回旧码，恰好被同侪收割，修复本体漏进了库。对照只在副本里做。
- `node_modules` 用 junction 接进副本。删副本先用 `cmd /c rmdir` 拆 junction，⛔ `rm -rf` 穿透。
- Vite 开发服务器读不到根目录外、经 junction 接进来的依赖，KaTeX 字体会加载失败。查字体用生产构建。
- **交来的前端包要证同源**：用「基线 + 回执清单里的文件」自己构建一次，逐文件比哈希。vite 的块文件名带内容哈希，同样的源码两次构建结果相同。比不上，就把 builder 的副本和自己的树逐文件比对。2026-11-07 的编辑器包就是这样查出来混进了 A-19 的 8 个文件，builder 的矩阵数字全是在混合包上跑的。

## 三、真后端、真浏览器

- **只改客户端的修复，接真后端核，不必部署**：本地托管修前、修后两份静态包，`/api` 经隧道转到岛上，只用自己的测试账号，两份同时跑。本地模拟延迟撞不出的问题，真后端常能撞出来（A-18：本地 0，真后端 6/30）。
- 服务端修复才需要本地起服务器，数据放在临时目录里的独立库。
- 探针要写成**人类节奏**：连写短行、用真键打标题、英文句子。builder 的矩阵常漏这些。
- **失败注入**用 CDP 的 `Fetch.enable`，在 Request 阶段按规则处理：扣住、返回 500、延迟、放行、断开。页面一侧每 10ms 记一次字框内容、回车时刻、点击时刻、hash 变化。
- 站内路由用的是 pushState，等「路由事件」等不到，要在页面轮询里记 `location.hash`。
- 走查要同时走**整页刷新**和**站内导航带着状态**（Layout 开着、面板开着）。V1「切不回原页」就是因为探针每次都整页刷新，Layout 状态一刷就复位，这条路根本走不到。
- 窗口宽度矩阵固定包含 ≤760。默认行为一变，就要重审被推上主路径的那些支线。
- 来回切换两个方向都要核，并带命中检测（`elementFromPoint`）。新账号的欢迎弹窗盖住过点击，单向判定把「没切走」记成了 ok。先调 `PUT /settings/onboarding-complete`。
- 每条结果多问一句：**它盖住了什么、换掉了什么。** Overview 的关闭键被悬浮切换盖住，我看过截图却没发现（B-78）。
- 等待用轮询，不用写死的 sleep。岛上偶尔整页「Loading...」5 到 8 秒。固定等 4.5 秒会把慢加载误记成「控件没了」（V2 部署后复走）。

## 四、探针装置的坑

- 无头 Chrome 首次用新配置目录启动可能超过 30 秒，超时就重试一次，不算失败。
- CDP 历史跳回 `Page.navigate` 打开的那条初始记录，会整页重载。测「后退」要在页内的历史记录之间做。
- ok 判据⛔子串匹配：`head` 能匹配上 `[heading_1]`。一律按服务端单元精确比对。
- 判「留住」时只读**这篇笔记**的存档：存档键以笔记编号结尾，不能把所有笔记的存档混在一起查，否则前面场景留下的同一个词会把后面的丢字算成「留住」。回来时屏上看到的框，可能是结构重跑中的活窗口，不是留住的框；要整页重开后再判。
- 被放弃的结构会留下 0 单元的空块。分类时要单列（1e），别算成脚本的毛病，也别算成丢字。
- **闸的阳性对照要配良性镜像**：同一条脚本去掉触发条件，在冻结版上也必须是绿的。只有「目标红、镜像绿」才说明这道闸分得出来，红在目标上；还要看红因，接口对不上导致的红（比如 `null.map`）不算数。
- 等锁不要只靠轮询：同侪放锁后马上又取，20 秒轮询会一直输。要排在它后面，直接发短讯约好顺序。
- 扫页面里的「原始反斜杠」时，KaTeX 渲染后放在 MathML 里的 `<annotation>` 源码也会被扫到。它们 0×0 并被裁剪，屏上看不见。判之前看元素标签。
- 内置浏览器面板被遮挡或在后台时，`requestAnimationFrame` 可能被节流，编辑器的结构提交依赖它。测编辑器时让面板保持可见，报告里注明环境。
- 内置浏览器面板的设备像素比会在 1 和 1.25 之间漂，截图坐标会失准。点击优先用元素引用。编辑态下单行块的拖柄被「Label block」盖住，点拖柄等于一键建标注。
- 内置浏览器没有文件上传工具。用本地小服务（只绑 127.0.0.1、加 CORS）加页面脚本，把自造文件塞进上传控件。材料自造，⛔从网上下载。
- Bash heredoc 会吞反斜杠。含反斜杠的脚本用文件写入工具写；Python 里要反斜杠就用 `chr(92)`。
  - 带引号的 heredoc（`<<'PYEOF'`）也不保险（2026-11-08）：Windows 路径里的 `\\t`、`\\n` 到 Python 成了制表符和换行，把私有卡的一行拆成两行。改 Windows 路径的文字，一律用 Edit 工具。
- Windows 下 Python 打印中文会撞 cp1252，设 `PYTHONIOENCODING=utf-8`。
- **本地临时后端的坑（2026-11-08，A-19 搭环境）**：
  - 停后台任务只停了外层 bash，`exec` 出去的 node 后端常常还活着。停完一律按端口查监听进程（`Get-NetTCPConnection -LocalPort <端口> -State Listen`），确认是自己的再停。
  - Windows 允许两个进程同时监听同一个端口，一个绑 `0.0.0.0`，一个绑 `127.0.0.1`。发到本机的请求会落到后者，测试可能连到旧进程而不自知。查端口要看全部监听地址。
  - 服务端把监听地址写死成 `0.0.0.0`，而这台云机的防火墙是关的。我的临时后端用启动预加载模块把地址改成 `127.0.0.1`，被测源码不动，同源哈希照样成立。
  - 传给 node 的路径用 Windows 形式（`cygpath -m`）。Git Bash 的 `/c/Users/...` 到 node 里会变成「当前盘符:\c\Users\...」，假转换器就是这样崩的。
  - 云机自带的 Wuying 服务（`netrd.exe`）占着 9615 端口，无头 Chrome 的调试端口绑不上，报「chrome did not come up」。换端口之前先 `netstat` 看一眼。
  - `git archive` 只导出 `server/`、`shared/` 不够：后端启动要读生成件 `server/dist/tool-face-manifest.json`。还要导出根目录的 `scripts/` 和 `docs/generated/`，再跑 `npm run check:tool-face-manifest`、`npm run copy:tool-face-manifest`。
- **⛔ 改正在运行的 bash 脚本**：bash 按字节偏移逐段读脚本，每次起子进程都会回到偏移处重读。往运行中的脚本中间插行，它跑完当前命令后会从错位处接着读，可能重复启动探针。要改就写新文件；已经改了，就把文件重写成「当前偏移之后的字节不变」（2026-11-07 run-pair.sh 险些出事）。链式脚本留一个让锁的暂停文件，每步取锁前先查它，不用中途改脚本。
- **停链的顺序**：TaskStop 只停后台任务的外壳，链里排队的 run-pair 还活着。要先按进程停掉 bash（链和 run-pair），确认没有残留，**最后**才删 pause 文件；否则它一取锁就拉起探针，杀它时 trap 删了锁，探针就成了没锁的孤儿（2026-11-07 跑了约 30 秒，那两行作废）。
- **逼出留字框「折叠成提示条」**（编辑器组 r2.3 起的框规则：两侧都不足 200px 才折）：
  - 侧栏开着时，左侧永远超过 200px（侧栏开 270px，收起 60px），所以 1100、950、760、610 四档宽度我都没折出来。
  - 配方：点「Collapse navigator」收起侧栏，关掉导航窗（它占左侧 272px）和暂存栏，页面阅读保持适宽 100%，视口宽度不超过约 1200。1100×1000 时正文栏约在 165–990，左边约 140px、右边约 85–100px，就会折。1440 宽配浏览器缩放 125% 也行。
  - 要逼出「无处可放」，再加一篇长笔记（同一块 40 行、段距 0）滚到中段，加两条无锚存档（注入存档）。
  - 框带着 0.15 秒的 `transition` 时，自检读到的是滑动中途的位置，无锚框在 1440 下也会先折。分辨「该折」和「误折」，要拿编辑器矩形自己算两侧宽度。
- **起本地服务前先查端口有没有人在听**（`netstat -ano | grep :<端口>`）。Windows 允许一个进程绑 `0.0.0.0:P`、另一个再绑 `127.0.0.1:P`，访问 127.0.0.1 会落到后者，不报错。2026-11-07 我早上起的 F3b 本地服务器一直遗留在 13151，晚上 r2.2 的静态服务又绑到同一端口。所幸两个都是我自己的，没碰到别人。用完的本地服务当天停掉，私有卡上的「还开着的东西」照实记。
- 点激活行时别点左端 20px：那里是块工具条的删除按钮，一点就「Block moved to trash」（既有问题）。点击取行左端 +120。
- 计数前想清楚「本来就有多少」：判「字落了一次」要和重开前比增量，S-a1 那条（`My great Intro` → `My great My Intro`）就被我按「多了一个」误标成正常。
- 设置阶段的网络记录别被 `mark()` 清掉。异常偏偏出在设置里时（acc14 那次并单元），没有日志就查不了机理。
- 页面坐标类结论（框压行），要同时记元素的 inline `style.left/top`：`25%` 是没锚上走的回落位，px 是锚上了之后被推走，两种机理不同。

## 五、岛上的特性

- **上传按内容去重**：同一份字节再传一次，返回原来那份源和它的旧投影，不重新解析。部署后核解析器，要用改过字节的副本（比如只加 zip 注释，条目逐字节不变）。这也意味着用户重传同一个文件拿不到新解析，要走 Rebuild。
- 岛库可能整库重建，旧账号和夹具一起失效。每轮开测先确认账号能用。
- 笔记很多的账号上，Group Gallery 逐篇发请求，会被浏览器资源上限打断（TD-53）。测 Gallery 用小账号。
- 判「看不见、没有」之前先整页刷新：客户端列表常是旧缓存。

## 六、判语的纪律

- **验收比的是意思，不是字符**：F1 我用「65 式字符守恒」放行，结果 argmin 被压平成乱码，字符一个没丢。要照源写人工金标准逐条比意思（`docs/audits/2026-11-05-toggle-formula-builder/f3-gold/`）。金标准之外，再写一份 builder 没见过的语料，专测每条修复的相邻情形。
- **阳性对照**：每道检查都要在已知坏的版本上跑一次，证明它真抓得住。阳性对照要红在目标上，不是随便红。部署后核对也一样：部署前先在岛上跑一次，拿到「旧」的结果。
- **对复核的要求**：真缺陷 + 复现 + file:line + 逐条反驳 + 证据对账。
- 疑似引入的红：先看导入闭包，确认改动在运行时到不到；再用干净 HEAD 副本同签名复现。React 时序红，用「把 Scheduler 的 setImmediate 换成延迟 setTimeout」插桩，两臂同签名才判非引入。
- **对照不等于因果**：报告只写观察到的相关；机理留给读代码、读数据的人，推断要标明是推断。
- **说「不能」之前先证明「能」测得出（2026-11-08，A-19 的 J1）**：要坐实原页模式下不能批注、不能建组，先在文本视图把同一探针跑成「能」。我前三版探针在文本视图也报「不能」：点在空白处，合成拖选又没触发应用自己的选区逻辑。直到在只读文字里慢速拖选，块工具条和组把手才出来。阳性对照没成立之前，「不能」不算数。
- **说「丢」之前查完所有恢复入口（2026-11-08，A-20，连错两次）**：401 那条我先报「12/12 丢」，又改口「只在内存里、刷新就丢」，两次都错。其实恢复记录在 sessionStorage，同标签页整页重开后有横幅，点 Apply 就回来了，只有新标签页才丢。
  - 判「丢」要查齐这几处：服务器、留字框、localStorage、sessionStorage、页面上的恢复横幅和它的 Apply。
  - 「回来」的方式要分开写：同标签页整页重开、新标签页（CDP 真开 target，不靠清存储模拟）、应用内改 hash。三者能看到的存储不一样。
  - 模拟「地址栏粘贴本应用的链接」时，只换 `#` 后面那段（同文档导航）。我的 `open()` 带了 `?r=`，再用不带它的地址导航就成了整页导航，那臂测的是另一件事。
- **自造材料要防按内容去重**：应用对同一份字节只认一个 Source。两张「不同」测试图如果字节相同，第二张拿回的是第一张的笔记，那条路根本没测到。造坏文件、改名文件时，内容要和已有的那份不同。
  - **时间巧合先对自己脚本的动作（2026-11-08，连错两次）**：LANDFAIL3 两轮的重试都在「失败后 25.1 到 25.2 秒」，我报成「约 25 秒定时重试」。其实那是我脚本每轮从重开到点外面的固定节奏，应用的重试是失焦触发的。
    - 凡是「每轮间隔都一样」的数，先把脚本自己的动作（点击、失焦、离开、重开）打上同一时钟的时间戳，看是不是正好对上。
    - 再换一种节奏跑一臂（推迟或去掉那个动作），数跟着变的就是脚本造成的。
    - 「从哪一刻算起」要写明，「重开后 26 秒」和「恢复后 26 秒」是两回事。
- 放行前起一个**独立复核**：审读者看代码不看我的结论，批评者挑我的报告。它的结论我亲手复现了才转述，没复现的单列。
- **发判语前核数**：拿报告里每个数字去对原始行和复核记录。头一次就揪出 17 处：计数错、推翻了复核记录却没写明、「全过」和后文自相矛盾。
- 跑到却看不懂的异常、失败的方向，都写进报告，不略过。

## 七、资源与锁

- 云机 CPU 压在 90% 以下。浏览器同时不超过 3 个，工作流不超过 4 路，vitest 加 `--pool=forks --poolOptions.forks.maxForks=3`。⛔ 故意满载。
- **重活锁**：全量测试、矩阵、多路工作流（哪怕只读）都要先取锁。取锁时在锁目录里写持有者文件（会话、时间、用途），取和放写在同一条命令或同一个 try/finally 里。漏放一次锁，曾把同侪挡了 17 小时。汇报前先查锁。
  - **2026-11-08 起允许两个重活并行**（Henry 当日批，`operating-workflow.md` §6 第 7 条）：每个压在 40% 以下，总量仍低于 90%，工作流不超过 4 路、浏览器不超过 3 个。原先的「一次一个」是 11-05 落实 CPU 红线时加的保险丝，红线本身不变。
  - 两个锁位 `<ops>/heavy-job.lock` 与 `<ops>/heavy-job.lock.2`，都用 `mkdir` 抢，哪个建得成占哪个（约定定在 `operating-workflow.md` §6 第 7 条，builder 用同一份）。
  - 各自写 `owner.txt`：角色、单号、活名、预计起止。取放写在同一条命令里。
  - 两个都占着就等，⛔ 开第三个。汇报前两个锁位都查。
  - 单个重活自己压在 40% 以下（限并发线程数、浏览器数），不靠别人让。两个同时跑之前先看一眼 CPU，接近 80% 就等。
- 持锁跑全量、正在验快照时，共享树整体不动，新代码写在副本里。
- 单个浏览器顺序走查不算重活。
