**原始文档库(散沙层)**
- 定义:用户或 Agent 放入的原始文件的全集,零门槛、零整理、零承诺。
- 地位:**备用候选资格**——唯一语义是「它存在且可被找到」。
- 现状:任意字节可入、`content_hash` 非空、入库件可按名发现,四道原拒收闸(后缀白名单 / MIME 不符 / 签名比对 / 文本编码)已改判为「降级收下 + 如实申报」,申报写入 `source_files.intake_declarations_json` 且 code 受 intake 闭集约束;⛔ 但容器(zip / 文件夹)尚未解包(b-2b 未做),所以包内部的件仍不可被发现,对它们而言「它存在且可被找到」尚不成立。
- 它不是:待办清单(躺着不产生任何义务);也不是引用源(存在≠可用)。

**原件(层0)**
- 定义:逐字节保存的原始文件本体,永不修改。
- 地位:证据。它自带的信息(文件日期、文内日期)是**它的自称**,我们转述不背书。

**转写(带锚)**
- 定义:原件的机器可读呈现(文本+结构),**每段文字携带回到原件位置的映射**(页/区域/单元格)。
- 地位:派生物,不是分析。⛔ 丢锚的转写(纯 markdown)不合格——追溯链骑在锚上。
- 现状:live 但原始(平铺文本+页级锚);12.9c 使带锚碎片流第一次有了真生产者——`native-pdf@2.4.5`(页锚)、`native-docx`、`native-text`(元素锚)在征用触发的 materialization 里写出出生证与碎片(`services/sourceMaterialization.ts:421`,经 `routes/sources.ts:17` 可达;c-0 `6ba6152`);MinerU 转写器已注册进解析器表(`services/sourceArtifact.ts:401`;c-1b-1 `d3c8661`),但**只有 `COINCIDES_PDF_PARSER` 精确等于 `mineru` 时才被选中**(`services/sourceFileIntake.ts:179`),本仓 `.env` 与 `.env.experiment` 均未设该键 ⇒ PDF 默认路径仍是 `native-pdf`;`region` 级锚是全有或全无——每个碎片都带同源区域才申报 region,否则降级 page(`sourceMaterialization.ts:363-382`;c-1b-2 `4503768`);⛔ `xlsx` / `csv` / `pptx` / `zip` 在格式表里仍是 `stored_only`,不进转写(`services/sourceFileIntake.ts:133-170`);方向:三层设计(06-28)+ 带版面坐标。时机:属拓印工序,征用时做。

**碎片(可寻址单元)**
- 定义:切分后的转写片段(段落/表格行/题目),有地址、可检索、可被指。
- 地位:**还不是知识**。打散发生在这里,铸造不发生在这里。
- 现状:`source_imprints` / `imprint_fragments` 已不止有插座——除 b-2 的 `source-intake-text-fallback` 外,c-0 起 pdf / docx / txt / md 走 materialization 真实写入碎片(`services/sourceMaterialization.ts:421`);⛔ **但读者仍为零**:`getImprintFragmentsByAnchor` 在生产码中零调用者(仅测试引用),碎片写得进、还没有人按锚取用——「有表且有人写」不等于「有人读」,消费面归 12.9d 与 c-3。

**引用源(拓印件)**
- 定义(Henry 2026-08-27 追认原设计):**原始文档在我们软件里的忠实复刻件**——征用时触发**拓印**(转写+切碎+页码样式保真+碎片组件成型,一次做完),拓印完成=完全可用,拼图碎片现成可直接使用。
- 地位:**完全可用状态**(与散沙层的「备用候选」相对)。
- 晋升条件:**一个使用决定**(人类的,或受命 Agent 的)。⛔ 不需要机器猜想——进引用源靠「被用」,不靠「被理解」。
- 它不是:一个标签或状态位——它是一件被造出来的东西(拓印件本体)。
- 现状:挂在笔记上的源文件+页锚(sourceFileIntake/SourceScope/SourceAnchor 一族),平铺文本,原始但活;出生证 `source_imprints` 自 c-0 起由 pdf / docx / txt / md 的 materialization 真实写入(accepted / rejected 双态落库),转写器身份改以 **lockfile 原始字节 sha256** 承重、版本号退出承重位(c-1b-0 `5792417`),未申报身份的解析器直接拒写出生证而**不回退公共 lockfile**;`native-image` 一族按 `no-imprint` 声明不产出生证(`sourceMaterialization.ts:353`);⛔ 完整拓印工序(转写+切碎+页码样式保真+碎片组件成型一次做完)仍未成形,故拓印件尚不到定义里说的「完全可用」。

**拓印**
- 定义:征用触发的一次性复刻工序——产出带锚转写+可用碎片组件,页码/样式尽量保真。
- 地位:忠实复刻,不是解读(理解归理解轨)。⛔ 时机在征用时,不在入库时(经济账:只拓被征用的)。
- 开放问题(V12.9 现场定):散沙层未拓印文件的内容级可发现性——候选:入库时做极便宜的粗文本层(只供检索,不产碎片不算拓印)。

**征用**
- 定义:把库里的东西真实用于某 purpose 的**决定动作**;晋升的唯一驱动。
- 一份源可被多次征用(多 program)——源仍一份,征用记录累积成**简历**,喂检索排序。

**锚**
- 定义:从任何派生物(转写/碎片/item/熔铸件)回到原件确切位置的指针。
- 地位:**追溯链的地基;指针是数据不是推理**。选品第一考题=「转完还回得去吗」。

**Item(铸件)**
- 定义:被征用的碎片在知识层的身份——带完整出处链的知识单元,进内容组、可复用、可复习。
- 铸造时机:**被用到那一刻**(⛔ 入库即全量铸=architect-all)。

**机器猜想(候选)**
- 定义:模型对内容的语义判断(「这段像定义」「这是道题」),**永远以候选身份存在**。
- 地位:**理解轨的服务,不在晋升线上**——加速征用、预填表单、聚类下拉,但**永不批准征用、永不冒充事实**。机器怀疑 ≠ 真相。

**熔铸件**
- 定义:由多个母本定义综合出的新条目(AI 铸或人写),带全部母本指针,母本零改动。
- 地位:**创作不是删除**;占默认位时可被一次点击换掉。

**折叠的多样性**
- 定义:见 `analysis/2026-08-26-v12-9-infra-integration-node.md` 第六轮 canonical 文本(一处多候选:默认最合身、全集一步之遥、来源随身、选择可逆)。

**强模型 / 弱模型(Henry 语境,2026-08-28 澄清)**
- 强模型:Fable / GPT-5.6 级西方旗舰。
- 弱模型:**中国便宜档的天花板**(DeepSeek / Qwen / GLM 旗舰层)——⛔ 不是小模型或笨模型;相对旗舰「弱」,本身是日常主力,便宜到没有理由不用。
- 用法后果:凡档案中「弱模型压测」读作「未来主力实测」;产品验收基线=弱模型档。
**存在性差异(12.9c 立)**
- 定义:两个转写器的产物比对时,一侧有、另一侧没有的碎片——差异发生在**存在维**(有没有),不在形态维(长什么样)。
- 地位:**先于形态的一道题**。四分类(文本外形 / 归一化 / 切分 / 真实指错)全部预设「两边都有」,故存在性差异落在它们射程之外,须单列。
- 它不是:判谁对谁错——普查只记「仅某一侧有」,归属与对错归判定遍。
- 现状:c-2 实验层普查实测 175 张(仅 Docling 101 / 仅 MinerU 74),逐条索引在 `analysis/2026-08-31-v12-9c-c2-divergence-census-v3.md` §4.1、完整收据在同文件 §6 内嵌 canonical JSON;裁定留痕 `5f103c1`。⛔ 射程只到该文件 §1.1 的 8 个实验层文件,⛔ 不是产品链结论(Docling 在 `server/src` 生产码中零文件)。

**分类学差异(12.9c 立)**
- 定义:两侧都有这块碎片、但**角色**判得不同(一侧 `text`、另一侧 `list` 之类)——差异发生在**是什么维**。
- 地位:存在维与形态维之间的第二道题;与存在性差异合为 12.9c 给分类骨架补上的两个维度。
- 它不是:切分差异——切分问「切在哪」,分类问「这块算什么」。
- 现状:c-2 实测 211 张,构成 9 种有序 canonical signature 对;最大一族是 `[text] × [list]` 194 张,而 v2 停线时正撞上的 `[heading] × [text]` 全程只有 2 张(`census-v3.md` §3.9 / §4.2);裁定留痕 `080c877`。⚠️ v3 的 211 与 v2 参照数 203 **不是同一口径**(v2 身份门含 role,v3 先 role-blind 配对再读 role),⛔ 不可直接相减。

**三道门(配对门 / 角色相容性门 / 四分类)**
- 定义:比对两份转写产物的固定顺序——①**配对门**:这两块是不是同一个东西(存在维)→ ②**角色相容性门**:两侧角色相容吗(是什么维)→ ③**四分类**:形态差在哪(长什么样 + 在哪)。
- 地位:**每道门有自己的分母**,上一道门的通过者才是下一道门的射程;⛔ 绝不拿命中数冒充分母。
- 它不是:一条流水线上的三次过滤——门与门的**计数单位不同**(配对门数 candidate event,角色门数 paired event)。
- 现状:c-2 v3 实跑机械闭合 `856 = 175 + 150 + 211 + 320`(四个 event-ID 集两两不交、并集逐项等于 full),角色门 full `531 = 211 + 320`(`census-v3.md` §3.1);前两道门各抓出一次停线(配对门 `135f782` / 角色门 `c462a2b`)。

**两遍制(普查遍 / 判定遍)**
- 定义:把「点名」与「判刑」拆成两遍——**普查遍**遍历全部事件、只记形态与方向、必须走完;**判定遍**做归属与对错、可以中途停堂。
- 地位:⛔ **两遍不共用一条停线流**。判定一遇未决就停,会把普查一并停死,于是分母永远不出现在任何产物里。
- 它不是:先粗后细的两轮——粗细无关,分的是**「记录」与「裁断」两种权力**。
- 现状:v2 的配对门虽明令不停线,却被塞进一条「一停即全停」的有序流,只跑出 138 个单边事件里的 9 个(**6.5%**),四卷里三卷收据数为 0(`handoffs/2026-08-29-v12-9c-c2-dual-transcription-recon.md:267`);v3 按两遍制重跑,门遍 `status=complete` / `stop_type=null`、856 事件全处理、24 行覆盖率 `remaining=0`(`census-v3.md` §3.1 / §3.3);裁定留痕 `9229796`,收官 `eac1cc8`。

**维度覆盖申报**
- 定义:任何分类骨架须**显式写出自己覆盖哪些维度、不覆盖哪些**,⛔ 不许默认「四类就是全部」。
- 地位:防的是**骨架比宪法少维**这一类错——c-2 的四分类全在问「长什么样」和「在哪」,没有一类问「有没有」和「是什么」,而 v0.7.4 判词早已分出三个维度。
- 它不是:免责声明——⛔ **申报的是射程,不是赦免**;申报了不覆盖,债照挂。
- 现状:通则与反面条款立于 `664efc4`,条文在 `handoffs/README.md` 家法段;c-2 v3 的 24 行覆盖率表(2 域 × 4 卷 × 3 谓词,每行带 `full` / `processed` / `remaining` 与计数单位)是它第一次机械落地(`census-v3.md` §3.3)。
