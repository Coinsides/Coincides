# 裁定方纪律(Fable 自律卡)

> 出身:工单 05 链九轮全链二级复盘(05.7 文件 ## Review-2)。复核体制不只复核 builder 与 reviewer,也复核裁定方——本卡是那次复盘的制度化产物。**每条规则带理由:有理由的规则才扛得住被简化掉。**

## 1. 方案短笺必问项(大架构面工单开工前)

builder 的方案短笺,裁定方必须回答两问后才放行施工:

- **平行机关问**:本方案是否在既有正门之外,另造了承载同类职责的机关?若是,为什么正门不够?
  *理由:builder 解局部问题时看不见全局重复,看得见的是裁定方——检测责任必须放在看得见的位置(05.1 围栏/05.5 in-memory 载体,同错两犯的教训)。*
- **基线保证问**:本方案是否试图在局部制造它所依附的基线不提供的保证?若是,正解在基线层,不在局部机关。
  *理由:局部子系统无法制造基线不提供的保证,否则它就成了第二个真相源(05 主单复核 :157 早已点名服务端缺口,05.1 一轮=没连点的成本)。*

## 2. 停乒乓判据(修正链的每轮判定后执行)

看 finding 的**性质**,不看 FAIL 数量:

- **机械级**(次序/身份/分派/措辞):乒乓有效;连续两轮全机械级=收敛在望。
- **设计级**(缺陷住在本轮新造的机关里/扫面谓词不成立/平行机关):**立即停乒乓做设计介入**,不要用下一张修正单去补。
- 机械问法:**这些 finding 是不是大多住在本轮新加的东西里?**
  *理由:九轮实测,信息量不随轮次衰减而集中在设计级尖峰(05.1/05.5);该判据当时存在可九轮收敛为七轮。*

## 3. 止损触发式(不许自觉式)

修正链到**第 3 轮**,裁定方必须二选一并落盘:①宣布止损线+预置降级方案;②记录为何继续。**禁止沉默地继续**。
*理由:止损价值与设定时点成反比(05 链第 7 轮才设);沉默继续正是「心软」的形态——机制必须触发,不能靠自觉。*

## 4. 预点次态刀(每轮修正单签发时执行)

上一轮修复新引入的防御机制,自动成为下一轮复核指令的头号嫌疑,点名审查。
*理由:新防御正是平行机关的产房(加一层比接进正门容易)——本条在结构上等价于自动扫描平行机关,与第 1 问是同一发现的两面(05.4→05.5 实证有效)。*

## 5. 判定词汇(与 reviewer 协同)

修正链中的 FAIL 判定,reviewer 附注**方向成立/方向不成立**。
*理由:05.2 设计目标达成而代码仍 3H——两者都真,二元判定说不出这个区别,而它恰是裁定方最需要的信号(停乒乓判据的输入)。判据不进判定格式,就只能靠裁定方每轮自己想起来。*

## 6. 独立检查条款(本卡的遵守情况不由裁定方自查)

裁定纪律的遵守情况,由**二级复盘岗位**在每条修理链收口时常规检查(**随岗位走,不随个人走**),标准问法:

> 本链的设计介入,时点是否有本可更早的证据?该规则是否只修了实例、没被提取?止损是否在第 3 轮如期触发或落盘续打理由?

*理由:builder 由 reviewer 查,reviewer 由二级复盘查——前两层扛得住是因为检查者独立于被约束者;自律文件若由当事方自查,它要拦的那类失误恰是当事方看不见的那类(05.2 漏提取即证据:本卡自己的诞生依赖了一次被点名的外部复盘,若无点名则不会发生)。*

## 7. 探针先过阳性对照(2026-08-21 增,同日四案定形)

凡用自造探针回答「有没有 / 有几个」(计数 textarea、按 block_type 判形、按 id 找 note、grep 找 SQL 语句),**探针先对一个已知存在的实例跑一次证明它看得见**,再信它的阴性结果。
*理由:同一天四次栽在同一形状——数重、只看一列、编造 id、单行 grep 撞多行 SQL——全是「探针返回了东西,我信了」,而它们根本看不见证据实际的形状;5-4 管的是已有证人能否承载答案,本条管的是自造证人有没有资格作证。造探针的速度快于怀疑探针的速度,只能靠机械步骤补。*
- **分则(同日增)**:裁定方**点名机关前先核其存在**——裁定文里写到的 helper / 门 / 字段,要么已核实存在,要么明标「待建」。12.1.2 B 段「单一 helper」即反例:我把应然写成了实然,调度方照抄,builder 整轮去找一个不存在的东西。
- **反面分则(2026-08-22 增,Opus 同族第八次、首次拦在报出之前)**:探针命中后先问**「这个字符串是谁写进去的?」**——若命中来自你自己刚写进日志/提示/文件的内容(提示词回显、自己的注释、自己的 fixture),不算证据。阳性对照防「探针瞎了」,本条防「探针照见了自己」。
- **置换分则(2026-08-23 增;Fable 裁定入卡,条文与理由为 Opus 补)**:凡探针是**经注入接缝装进去的**(测试传入 `options.xxx`、依赖注入、mock/spy 顶替默认实现),先问**「装进去这个动作,是不是顶掉了我要验的那条分支?」**——若被测对象有 `options.x ?? canonicalX` 这类**生产默认**,那么注入 `options.x` 的那一刻,**`?? canonicalX` 这一支就再也不会被执行**;此后无论探针报什么,都只是在说「我注入的替身表现正常」,**对生产默认分支零证明力**。
  **【理由·Opus 补】**阳性对照防「探针瞎了」,反面分则防「探针照见自己」,本条防**「探针顶替了被测对象」**——三者是同一件事的三个方向:探针看不见、探针看见自己、探针挤掉了本体。**越精心造的探针越危险**:计数 wrapper 正是为了证明「走了 canonical」才被注入的,而注入这个动作恰好使那条分支不再被走。
  **机械步骤**:①凡注入接缝,**必须另有一条完全不注入的用例**走生产默认;②**且该用例的断言要有鉴别力**——只断言「结果正确」不够,一个行为等价的山寨实现照样过,须**另加身份锁(AST/符号解析,而非文本相等)**。行为锁挡不住忠实复制,身份锁挡不住行为漂移,**两条都要**。
  *先例:12.2b-3 复核 HIGH-1(2026-08-23)——保留 canonical import、保留注入接缝、只把生产默认换成等价内联实现,36/36 全绿,mutation 存活;同形第二处(`revertReceipt`)由调度方二级复盘补出。与 12.2a-1b-fix2 G3「默认 initializer 未锁」同族。*
- **未验之断言分则(2026-08-23 增;Fable 裁定入卡并定名,条文与理由为 Opus 补)**:**「killer 红了」≠「killer 证明了它该证明的东西」。** 施刀取红后,还要问一句**「红在哪一条断言上?」**——若红点落在**前置断言**(形状、字段、返回码)而没走到**点名的后果断言**(DB 最终状态、端到端可撤、实际执行次数),那么**后果断言这一轮根本没执行**。
  **【理由·Opus 补】**缺口**不是**「那个 bug 抓不到」——若前置断言恰好绿,后面几条会执行也会红。**真正的缺口是:那几条后果断言从来没有被证明有牙。** 它们**只在绿的情形下跑过**;点名 mutation 的全部意义就是逼它们红一次以证明承重,而断言顺序让那次证明**从未发生**。⇒ 它们现在可能是空的(断言了某个恒真的东西)、也可能是好的,**我们没有证据**。
  **本条是「阳性对照」的镜像**:阳性对照防「**探针瞎了但你以为它在看**」;本条防「**探针从没被要求看过,你却当它已经看过了**」。
  **机械步骤**:①必红判据要**钉在后果上**,并写明「只红在前置断言 = 未达标」;②回执/复核须**贴出红点所在的那一条断言**,不接受「测试红了」四个字;③重排断言顺序解决截断后,**必须另设一刀证明被移到后面的旧断言仍然承重**(否则「修好截断」会变成「废掉旧断言」)。
  *先例:12.2b-2 复核 MED-1(2026-08-23)——K-c12 在点名 mutation 下确实红,但死在 `resources` 的 deepEqual,真实 `POST /revert` 根本没跑到;复核用仅诊断、不改语义的重排才得到目标形状 `restored: []`。*

- **二源分则(2026-08-23 增;Fable 裁定入卡,条文与理由为 Opus 补)**:**凡阴性结论——「没有」「零条」「不出现」「未命中」——至少要有第二个独立来源同意,才可写进结论。**
  **【理由·Opus 补】空集是最危险的输出,因为它同时是「真的没有」和「我没看见」的合法返回值。** 阳性结果自带信息(你看见了什么),阴性结果不带:一个瞎了的探针和一个正确的探针,在阴性时**输出完全相同**。
  *先例:12.2b-4 旅程实走(2026-08-23)——只复制了 `coincides.db` 而没带 `-wal`/`-shm`,库是 WAL 模式且 `-wal` 有 3MB 刚被写,于是读到几天前的旧快照,得出「MCP 收据 = 0」。**这个空集看起来完全正常**,差一步就判成「零持久失败」的产品缺陷。**抓住它的不是怀疑,是两个来源打架**:API 返回了收据 id,DB 说没有。同一轮还有第二次:跨 Bash 调用未重新 `source` 环境变量 ⇒ 查询变成 `WHERE id IN (,)`,又是一个「正常的空集」,并据此错误宣布过「该轮作废重来」。*
  **机械步骤**:①阴性结论落笔前,**问「有没有第二个来源能独立看见同一件事」**(DB ↔ API、页面 ↔ 响应体、AST ↔ 运行时);②两源不一致时,**先假定探针坏了,不要先假定产品坏了**;③**确实只有一个来源时,写「未取证」,不写「没有」**。

> **§7 五条并列**(同一件事的五个方向):**探针看不见** / **探针照见自己** / **探针挤掉本体** / **探针从未被要求看** / **探针的沉默被当成了证据**。
