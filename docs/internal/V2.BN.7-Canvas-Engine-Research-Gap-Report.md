# V2.BN.7 Canvas Engine Research Gap Report

> 本文回答：已有调研是否足够支撑 V2.BN.8 Canvas Engine Foundation？哪些问题必须补调研或技术 spike？

## 1. 结论

已有调研足够支持方向，不足以直接支持实现。

方向已经比较清楚：

- Coincides Core 继续拥有 truth；
- Canvas Engine 只做 runtime/projection/interaction；
- AFFiNE / BlockSuite 是参考，不是主权层；
- 当前 branch 收口为 experiment/fallback/reference；
- V2.BN.8 进入 clean branch Canvas Engine Foundation。

实现仍需补：

- engine architecture；
- transformed editing；
- measurement service；
- virtualization；
- overlay portal；
- relation endpoint reserve；
- frame export；
- benchmark。

## 2. 已有调研能覆盖的内容

| 主题 | 覆盖程度 | 说明 |
| --- | --- | --- |
| 产品边界 | 高 | NoteBlock / placement / source / relation / template truth 已经能讲清楚。 |
| AFFiNE 体验参考 | 中高 | page/edgeless/frame/connector/toolbar 有参考价值。 |
| BlockSuite 路线风险 | 中高 | full fork 风险高，BlockSuite-first 需 sidecar。 |
| Page / Canvas / Export 边界 | 中高 | 概念已明确，但工程实现未验证。 |
| Performance 原则 | 中 | 有 virtualization / relation on demand / LOD 原则，但缺本地 benchmark。 |
| Relation rendering | 低中 | 知道不能全量显示，但 connector endpoint / route 还未工程化。 |
| Media / formula heavy | 低 | formula seed 有，media 没有真实 runtime。 |

## 3. 必须补调研的问题

### G1: Canvas Architecture

问题：

```text
V2.BN.8 应采用 DOM、SVG、canvas、还是 hybrid rendering？
```

需要回答：

- 文本编辑层是否必须 DOM/contenteditable；
- block shell 是否 DOM；
- relation path 是否 SVG；
- 大量背景/网格/preview 是否 canvas；
- overlay portal 如何和 transform 坐标互转；
- 未来 media 是否独立 layer。

建议：先做小型技术 spike，不要直接重写整页。

### G2: Text Editing Under Transform

问题：

```text
pan / zoom 下，用户如何稳定输入、选中、复制、粘贴、组合输入？
```

需要验证：

- textarea/contenteditable 在 transform scale 下的 caret；
- 中文输入法；
- 复制粘贴长文本；
- slash command anchor；
- selected text toolbar；
- keyboard navigation；
- undo/redo。

这是 V2.BN.8 的高风险点。

### G3: Measurement And AutoHeight

问题：

```text
block 高度由谁测量？何时测量？怎样避免 overlap？
```

需要验证：

- paragraph auto-height；
- definition field editor；
- formula preview + latex input 展开；
- code block；
- future image/video placeholder；
- font size change；
- resize width 后 reflow；
- measurement cache invalidation。

建议：Canvas Engine 第一版就要有 measurement service，不要再靠局部估算。

### G4: Overlay And Portal Layer

问题：

```text
toolbar、preview、slash menu、inspector、context menu 如何不互相打架？
```

需要验证：

- selected block toolbar；
- preview panel；
- slash menu；
- insert palette；
- note info / more actions；
- source picker future；
- relation inspector future；
- z-index policy；
- viewport edge collision。

当前 branch 已多次证明 overlay 不是小问题。

### G5: Large Document And Virtualization

问题：

```text
1000 blocks、formula-heavy、media-heavy、relation-heavy 时还能不能流畅？
```

需要设计 benchmark：

- 首屏加载；
- pan/zoom；
- drag selected block；
- resize selected block；
- open preview overlay；
- toggle type/AI/export overlay；
- future relation layer on/off。

必须明确“未进入视野的 truth 不渲染”的实现方式。

### G6: Frame System And Export Region

问题：

```text
PageFrame 是什么对象？如何导出？如何支持 frame 外 workspace？
```

需要验证：

- one PageFrame；
- custom frame；
- future multi-frame；
- selected frame export；
- frame thumbnail；
- workspace object 不默认导出；
- cross-frame relation future。

### G7: Relation Connector Endpoint Reserve

问题：

```text
relation runtime 还没做，但 Canvas Engine 如何不给未来堵路？
```

需要预留：

- connector endpoint；
- port / anchor；
- relation layer visibility；
- route/path layer；
- edge label；
- relation view budget；
- user-visible CanvasEdge 与 semantic ObjectRelation 的边界。

第一版不做完整 relation runtime，但 layout object 要预留概念。

## 4. 可以边做边验证的问题

这些问题不必在 V2.BN.8 前完整调研完：

- snap/alignment guide 的细节；
- elastic avoidance 是否保留为正式辅助行为；
- bottom toolbar vs side toolbar；
- note-set universe / zoomed-out LOD；
- frame thumbnail 视觉样式；
- media block 的最终编辑体验；
- AI repagination proposal。

它们可以进入 V2.BN.8.x 或更后面。

## 5. 必须技术 spike 的问题

V2.BN.8 开工前或开工早期建议做这些 spike：

| Spike | 验证目标 | 失败信号 |
| --- | --- | --- |
| Transform Text Editing Spike | pan/zoom 下编辑、输入法、selection 是否稳定。 | caret 漂移、输入法异常、复制粘贴不稳定。 |
| Measurement Service Spike | resize/reflow/formula input 是否不 overlap。 | 高度反复错、内容溢出、布局闪烁。 |
| Overlay Portal Spike | slash menu / toolbar / preview 定位是否稳定。 | popover 错位、被 block 遮挡、z-index 混乱。 |
| 1000 Blocks Spike | 大量 block 的加载和拖动是否可接受。 | 首屏慢、拖动卡、内存明显膨胀。 |
| SVG Relation Reserve Spike | connector endpoint/route 预留是否可行。 | path 层与 block 层坐标无法对齐。 |

## 6. AFFiNE / BlockSuite 需要重新看的点

如果使用 browser / Browser Harness 重新观察 AFFiNE，重点不应是“它长什么样”，而是：

- Page mode 和 Edgeless mode 是否共享同一底层 block；
- frame 是否是几何对象还是 semantic object；
- connector 如何 attach 到 block；
- note card 在 edgeless 中如何测量和缩放；
- toolbar 是否使用独立 overlay layer；
- zoomed-out 时是否有 LOD；
- 大量对象时是否虚拟化；
- export frame 如何工作。

## 7. Research Gap 结论

V2.BN.8 可以开始，但不能“凭感觉直接重写”。

建议路径：

```text
V2.BN.7
  -> 明确 gap
  -> 生成 requirement
  -> 生成 route decision

V2.BN.8
  -> clean branch
  -> small engine spike
  -> prove core coordinates / measurement / overlay

V2.BN.8.x
  -> repeated reliability and UX polish
  -> only then move to Template Studio / Source / Relation
```
