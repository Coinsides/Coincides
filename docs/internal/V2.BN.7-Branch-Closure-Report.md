# V2.BN.7 Branch Closure Report

> 本文定义当前 branch 在 V2.BN.7 之后的身份：实验场、经验库、fallback，不再是未来 Canvas Engine 的长期地基。

## 1. 结论

当前 branch 不应被视为失败品。它已经完成了一个非常重要的任务：

```text
把 Better Notebook 的抽象产品想法，压成了可以测试、可以犯错、可以反推图纸的 prototype。
```

但它也不应继续被无限补丁化。V2.BN.7 之后，它的身份应变成：

```text
experiment branch
reference branch
fallback branch
anti-pattern library
```

未来 Canvas Engine 应默认在 clean branch 中启动。

## 2. 当前 branch 的历史价值

当前 branch 证明了：

- Coincides 可以走 self-owned editor surface；
- 用户能接受 NoteBlock + placement 的自由排版逻辑；
- PageFrame 外 workspace 的方向成立；
- structured block field seed 有价值；
- slash command、block control bar、preview overlay、layout mode、snap toggle 等交互有真实产品意义；
- source / link / relation / template / editor state 边界可以被产品化；
- 旧 runtime 的 bug 本身也构成了未来 Canvas Engine 的反向需求。

## 3. 当前 branch 的未来身份

### Experiment branch

当前 branch 是实验场。它允许我们快速验证：

- 交互是否符合用户心智；
- block 操作是否自然；
- preview / overlay / badge 是否干扰写作；
- page/canvas 边界是否讲得通。

### Reference branch

当前 branch 是参考样本。未来 Canvas Engine 做完后，应回头对比：

- V2.BN.1-V2.BN.6 已经磨出的自然写作感是否被保留；
- block resize / reflow 是否比旧 runtime 更稳；
- toolbar / preview / badge 是否更少遮挡；
- page/canvas 切换是否更接近真正统一画布。

### Fallback branch

如果自研 Canvas Engine 在性能或复杂度上不可控，当前 branch 可以成为 fallback 路线：

- 回退到有限大画布；
- 继续强化 page mode；
- 暂缓无限画布；
- 保留用户可用的 Better Notebook 基础体验。

### Anti-pattern library

当前 branch 的 bug 不应被遗忘。尤其是：

- auto-height / measurement；
- overlay z-index；
- slash menu position；
- elastic avoidance；
- page/canvas mode filtering；
- formula input expansion；
- block control bar covering content。

这些都应进入 Canvas Engine 的风险清单。

## 4. 应继承的东西

未来 clean branch 应继承：

- 产品定位；
- truth-layer contracts；
- Block Contract；
- Canvas/Page Surface Contract；
- Source / Link / Relation 边界；
- Template Category Contract；
- V2.BN.7 的三张 runtime autopsy 表；
- 当前 branch 的 UX 截图、patch note 和测试观察；
- 当前 branch 的 fallback 价值。

## 5. 不应继承的东西

未来 clean branch 不应长期继承：

- `NoteDetail.tsx` monolithic runtime；
- 以 DOM 页面流模拟 canvas 的整体结构；
- `better_notebook_layout` 作为正式长期 schema；
- 当前 overlay / toolbar / preview 的局部 z-index 策略；
- 当前 measurement / height estimation 的局部补丁；
- 当前 collision / elastic avoidance 的实现方式；
- 当前 mechanical structured block conversion；
- 为实验数据写沉重 converter 的负担。

## 6. Clean Branch 原则

Canvas Engine clean branch 应遵守：

```text
contracts first
engine first
truth ownership unchanged
adapter/projection second
fallback preserved
no unnecessary migration debt
```

具体规则：

- 可以重写 `NoteDetail.tsx` runtime；
- 可以重建 layout schema；
- 可以 clean reset 当前实验性 layout data；
- 不承诺长期兼容 `better_notebook_layout`；
- 如果未来出现真实用户数据，再单独设计 migration；
- 当前 branch 保留为可回看的 fallback/reference。

## 7. Fallback Trigger

如果未来 Canvas Engine 出现以下情况，应考虑回退或切换路线：

- 1000 blocks 基础场景明显卡顿；
- formula-heavy / media-heavy 页面不可接受；
- pan/zoom 下文本编辑长期不稳定；
- selection / focus / popover under transform 长期无法稳定；
- relation connector path 加入后性能不可控；
- frame export 无法稳定；
- 自研工程成本明显超过可控范围；
- 新 runtime 的写作体验低于 V2.BN.1-V2.BN.6 已有稳定效果。

Fallback 不等于放弃 Canvas。Fallback 可以是：

- 回到有限大画布；
- 先做 PageFrame-first；
- 降低 open canvas 范围；
- 暂缓 relation-heavy view；
- 重新评估 BlockSuite / AFFiNE substrate。

## 8. 收口后的维护规则

V2.BN.7 之后，当前 branch 不再继续做普通体验补丁，除非属于：

- 数据安全；
- 严重崩溃；
- 阻塞 V2.BN.7 文档审计；
- 为 fallback 保留必要稳定性；
- Henry 明确要求的局部修补。

不再做：

- 新的无限画布功能；
- 大规模 UI polish；
- Template Studio 产品化；
- Source Library；
- Relation runtime；
- GraphRAG adapter；
- 复杂 migration。

## 9. 结论

当前 branch 已经尽责。它让我们看到 Better Notebook 的方向，也让我们看到旧 runtime 的边界。

下一步不是继续在旧 runtime 上叠补丁，而是：

```text
用当前 branch 保存经验和 fallback。
用 V2.BN.7 产出图纸和门禁。
用 V2.BN.8 clean branch 建 Canvas Engine。
```
