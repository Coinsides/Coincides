# V2.BN.7 Canvas Engine Requirement Draft

> 本文定义 V2.BN.8 Canvas Engine Foundation 的最低需求。它不是完整产品规格，而是开工门槛。

## 1. 目标

V2.BN.8 的目标不是一次性做完无限画布，而是建立一个可靠的 canvas-native runtime 地基。

最低目标：

```text
用户可以在统一 NoteCanvas 中编辑一个正式 PageFrame。
PageFrame 外可以存在 workspace / scratch area。
block placement、resize、selection、measurement、overlay、viewport 不再依赖旧 NoteDetail DOM-flow 模拟。
```

## 2. 核心对象

### NoteCanvas

NoteCanvas 是一篇 note 的运行画布。

它负责：

- 统一 coordinate system；
- viewport；
- pan / zoom；
- frame membership；
- object placement；
- selection / hit-testing；
- overlay layer anchors；
- relation connector endpoint reserve。

### PageFrame

PageFrame 是 NoteCanvas 中的正式页面区域。

它负责：

- 表示可导出、可阅读、可排版的正式区域；
- 承载默认 page mode 内容；
- 提供 export boundary；
- 提供 AI/context/export 状态边界；
- 可以在未来支持不同 page size / custom frame。

### FrameOutsideWorkspace

FrameOutsideWorkspace 是 PageFrame 外的自由区域。

它负责：

- scratch notes；
- 推导草稿；
- 临时图片、关系、旁注；
- 非默认导出内容；
- 未来 edgeless / infinite canvas 体验。

### SurfaceObject / CanvasObject

Canvas 上可操作对象的统一运行形态。

第一版至少包括：

- NoteBlock projection；
- PageFrame；
- workspace object placeholder；
- connector endpoint reserve。

## 3. Placement 最小字段

V2.BN.8 第一版 placement 至少应考虑：

```text
placement_id
object_id
object_kind
canvas_id
frame_id optional
x
y
width
height
rotation future
z_index
boundary_role
visibility_state
snap_state optional
connector_ports future
```

说明：

- `rotation` 先作为 future 字段或 contract 预留，不一定第一版实现 UI；
- `connector_ports` 先作为 relation endpoint 的预留，不进入完整 relation runtime；
- `frame_id` 允许对象属于某个 PageFrame，也允许对象在 frame 外 workspace；
- placement truth 不等于 NoteBlock content truth。

## 4. 第一版必须能力

| 能力 | 最低要求 | 是否 V2.BN.8 必须 |
| --- | --- | --- |
| Unified coordinate model | PageFrame 和 workspace 使用同一坐标系。 | 是 |
| PageFrame | 至少一个正式页面 frame。 | 是 |
| FrameOutsideWorkspace | PageFrame 外对象不应被强行夹回 page。 | 是 |
| Pan / zoom | 可以移动视野和缩放，viewport 可保存。 | 是 |
| Placement | block 能被移动、resize，并保持稳定坐标。 | 是 |
| Measurement | 文本、formula、field editor 展开后不 overlap。 | 是 |
| Selection / hit-testing | pan/zoom 后仍能准确选中对象。 | 是 |
| Overlay layer | toolbar、preview、slash menu 不和内容层混乱。 | 是 |
| Slash menu anchor | 在 transformed canvas 下出现在正确位置。 | 是 |
| Snap / alignment | 可先做基础版本，但要能关闭。 | V2.BN.8 或 V2.BN.8.1 |
| Operation history seed | 至少能定义移动/resize/input 的 undo 边界。 | V2.BN.8.x |
| Connector endpoint reserve | 不做 relation runtime，但 placement 要预留端点思路。 | 是，作为预留 |

## 5. 第一版不做

V2.BN.8 不做：

- 完整 relation runtime；
- GraphRAG adapter；
- Source Library UI；
- Template Studio 产品化；
- full media pipeline；
- OCR/VLM reconstruction；
- AI repagination proposal；
- multi-frame export engine；
- note-set universe；
- zoomed-out LOD 的完整实现；
- 完整 AFFiNE / BlockSuite integration。

## 6. V2.BN.8.x 打磨要求

Canvas Engine 不应假设一版完成。必须预留小版本空间：

### V2.BN.8.1

Canvas Engine smoke and reliability patch：

- clean branch boot；
- NoteCanvas / PageFrame / workspace object 能跑；
- viewport persistence；
- selection / hit-testing；
- placement save/load；
- basic resize/reflow；
- basic overlay layer。

### V2.BN.8.2

Canvas writing and block interaction polish：

- slash menu；
- block control bar；
- formula field editor；
- definition field editor；
- empty block cleanup；
- keyboard/selection state；
- undo/redo seed。

### V2.BN.8.3

Scale and overlay polish：

- 100 / 500 / 1000 blocks smoke；
- formula-heavy smoke；
- media placeholder smoke；
- preview/debug overlay；
- block type / AI / export overlay；
- z-index / portal stability。

### V2.BN.8.x

根据测试结果继续追加，直到：

- 工程可靠；
- 用户体验接近或超过 V2.BN.1-V2.BN.5 稳定效果；
- 才进入 Template Studio / Source Library / Relation Runtime。

## 7. 性能基线

V2.BN.8 之前或 V2.BN.8.x 中必须建立 benchmark：

```text
100 text blocks
500 text blocks
1000 text blocks
100 formula blocks
mixed definition / formula / code blocks
future media placeholder blocks
relation endpoint reserve smoke
zoomed-out frame smoke
```

第一阶段不一定全部达标，但必须知道瓶颈在哪里。

## 8. Fallback 规则

如果 self-owned Canvas Engine 不稳定：

- 当前 branch 作为 fallback/reference 保留；
- 可退回有限大画布路线；
- 可重新评估 BlockSuite Edgeless；
- 可降低 open canvas 目标，先做 PageFrame-first；
- 不为了面子强推不可维护的 runtime。

## 9. 结论

V2.BN.8 的核心不是“做一个很炫的无限画布”，而是建立：

```text
稳定坐标
稳定测量
稳定选择
稳定 overlay
稳定 truth boundary
稳定 fallback
```

这些成立后，Template Studio、Source Library、Relation Runtime 才能站在可靠地基上。
