# V2.BN.7 Current Runtime Autopsy

> 本文是 V2.BN.7 的核心报告。它审计当前 `NoteDetail.tsx` runtime 已经证明的产品规则、暴露的工程风险，以及未来 Canvas Engine 必须正式重建的能力。

## 1. Runtime 定义

在 V2.BN.7 中：

```text
runtime = 用户正在操作笔记时，连接产品体验、临时交互状态、交互计算和持久 truth layer 的运行层。
```

它不是单个文件，也不是单纯 UI，更不是 canonical truth 本身。

它负责：

- 把 Note、NoteBlock、placement、source、template、relation 等 truth 读入编辑界面；
- 把这些 truth 临时组织成用户可操作的对象；
- 响应用户输入、点击、拖拽、resize、选择、预览、模式切换；
- 在交互过程中计算位置、高度、碰撞、吸附、选中、overlay、popover；
- 把用户确认后的变化写回正确的 truth layer。

它不应该拥有：

- NoteBlock content truth；
- layout / placement truth；
- source provenance truth；
- ObjectRelation truth；
- TemplateDefinition / FieldSchema truth；
- GraphRAG / OCR / VLM / AFFiNE / BlockSuite adapter truth。

## 2. 当前 runtime 的事实基础

当前 runtime 的主要事实来自：

- `client/src/pages/Notes/NoteDetail.tsx`
- `client/src/pages/Notes/noteSlashCommands.ts`
- `server/src/routes/notes.ts`
- `server/src/lib/noteBlockTemplates.ts`
- `server/src/validators/index.ts`
- `shared/types/index.ts`
- `docs/contracts/Block-Contract.md`

当前实现已经具备这些雏形：

- `SurfaceMode = 'page' | 'canvas'`；
- `NOTE_LAYOUT_KEY = 'better_notebook_layout'`；
- block layout 写入 `display_overrides_json`；
- NoteBlock placement route 使用 `note_block_placements`；
- slash command 有 default / math / userDefined 分组；
- runtime template taxonomy 存在，版本为 `v2.1.1`；
- definition / formula / code / source quote 等 block 进入 runtime；
- page / canvas seed、layout mode、snap toggle、preview overlay、block type overlay 已经有真实交互；
- CodeGraph 当前索引可用，说明本次审计可以继续依赖本地代码结构。

## 3. 能力状态分级

| 能力 | 当前状态 | 判断 |
| --- | --- | --- |
| 自然写作表面 | useful prototype | 已经摆脱早期工程卡片感，但仍不是最终 page/canvas editor。 |
| NoteBlock 作为内容单位 | stable product rule | 产品方向成立，未来必须保留。 |
| BlockBox / placement 作为布局单位 | stable product rule | 内容 truth 与布局 truth 分离成立。 |
| slash command | useful prototype | 入口成立，但 menu 定位、create/convert 策略需要 engine 化。 |
| structured field seed | useful prototype | FieldValue 作为 structured block 内容 truth 的方向成立。 |
| mechanical convert heuristic | warning / dead end | 冒号、美元号等弱脚本转换不应继承，未来应转为 deterministic minimal + user confirm / AI proposal。 |
| block control bar | useful prototype | 对象附近控制成立，但 overlay 层级和位置策略需要重建。 |
| preview overlay | useful prototype | 作为 debug/export/visibility panel 成立，但必须与 selected toolbar 分层。 |
| block resize + text reflow | stable product rule / fragile implementation | 体验规则成立，实现方式脆弱。 |
| auto-height measurement | fragile prototype | 多次导致 overlap、空白、公式输入区覆盖，需要 engine service。 |
| layout mode | useful prototype | 批量布局状态有价值，但 selection 与 toolbar 需要 engine 化。 |
| page mode / canvas mode | useful prototype | 概念成立，但当前只是模拟切换，不是统一 NoteCanvas。 |
| elastic avoidance | useful prototype / warning | 手感有价值，但当前 collision 触发条件和约束边界不稳定。 |
| snap alignment | useful prototype | 需要保留为对齐辅助，但应由 layout engine 管理。 |
| undo / redo | useful prototype | 操作边界开始出现，但还不是统一 operation history。 |
| source badge / AI/export badge | stable product rule | 状态按需显现成立；不应常驻污染正文。 |
| relation connector reserve | unknown / future | 目前只是预留，未进入真实 relation runtime。 |
| large document performance | unknown | 未验证 100 / 500 / 1000 blocks。 |
| media-heavy / formula-heavy | unknown | formula 有 seed，image/video/audio 仍未验证。 |

## 4. Table A: Keep As Product Rule

这些规则来自当前 runtime 的成功体验，未来 Canvas Engine 必须继承。

| 体验规则 | 来自哪个当前功能/补丁 | 为什么要保留 | 未来 Canvas Engine 验收方式 | 相关引用 |
| --- | --- | --- | --- | --- |
| NoteBlock 是内容单位，placement 是布局单位。 | NoteBlock + `note_block_placements` + `display_overrides_json` | 用户需要自由排版，但内容不能因为移动/resize 失真。 | 同一个 NoteBlock 能有稳定 content id；placement 改变不改 content truth。 | DATA_MODEL / Block Contract |
| block resize 后文字必须自动重排。 | resize / text reflow patch | 文本框体验必须像成熟笔记/文本框，而不是裁掉内容。 | 缩窄 block 后文字重排，block 高度跟随内容，不 overlap。 | UX Inventory |
| 普通阅读状态不应暴露过多工程标签。 | preview overlay / type badge on demand | 用户写作时不想看工程元信息。 | 默认不显示 AI/export/type badge；preview 或 debug mode 才显示。 | R4 / UX Inventory |
| slash command 是 block type 的自然入口。 | `noteSlashCommands.ts` | 用户心智接近 Notion/AFFiNE；比 toolbar 插入更自然。 | 在光标附近打开，不漂移；支持 default/math/userDefined 分类。 | Block Contract |
| structured block 应保留 FieldValue truth。 | definition / formula block seed | 未来 agent、graph、export 可直接读取字段，不必猜文本结构。 | DefinitionBlock 有 concept_name/description；FormulaBlock 有 latex_input。 | Block Contract |
| 写作与布局应有不同状态。 | layout mode | 用户日常写作不应误触布局；批量排版需要更强控制。 | page writing mode 与 layout mode 行为不同，且可预测。 | UX Inventory |
| Page 是 NoteCanvas 上的正式 frame。 | page/canvas seed | 导出、阅读、正式内容边界需要 PageFrame；Page 外可放 scratch/workspace。 | Canvas Engine 中存在可导出 PageFrame 和 page 外 workspace。 | Canvas/Page Surface Contract |
| source、AI visibility、export status 是 overlay 信息，不是正文内容。 | preview / badge patches | 这些状态重要，但不应污染阅读。 | 可在 preview/debug overlay 中批量显隐。 | Source/Provenance Contract |
| control bar 应靠近被操作对象，但不能遮挡内容。 | selected block toolbar | 用户操作需要就近，阅读需要干净。 | control bar 进入 overlay layer，不改变 block measurement。 | R5 |
| 当前 branch 是 fallback/reference，而不是失败品。 | V2.BN.1-V2.BN.6 patches | 它证明了很多体验规则，也可在 Canvas Engine 失败时回退。 | V2.BN.8 clean branch 可参考，但不背兼容债。 | Roadmap |

## 5. Table B: Keep As Warning

这些问题来自当前 runtime 的真实教训。未来 Canvas Engine 不应照搬这些实现方式。

| 问题/坑 | 触发场景 | 根本原因 | 未来不要怎么做 | 未来需要的 engine 机制 |
| --- | --- | --- | --- | --- |
| DOM flow + 手动高度补丁容易导致 overlap。 | resize、formula input 展开、长文本粘贴。 | block 视觉高度、内容高度、碰撞高度不是同一套 service。 | 不要在组件局部临时猜高度。 | Measurement / AutoHeight Service |
| popover 绑定页面流会漂移。 | slash menu 曾出现在页面顶部或错误位置。 | menu anchor 没有统一转换到 canvas coordinate。 | 不要用当前 DOM rect 直接当最终位置。 | Transform-aware Popover Portal |
| selected toolbar 与 preview panel 图层冲突。 | preview 打开后仍看到 selected toolbar 压在上面。 | overlay 层级没有统一 z-index contract。 | 不要让每个组件自己抢 z-index。 | Overlay Layer System |
| elastic avoidance 在模拟 layout 中容易误触发。 | block 未接触也推走下方 block，或 snap on 时触发。 | collision / snap / drag commit 混在一起。 | 不要把 collision 当成拖拽后处理补丁。 | Interaction Physics / Collision Policy |
| page/canvas mode 当前像视图过滤，不像同一画布下的 frame。 | canvas workspace block 切回 page 后行为容易错位。 | PageFrame 与 workspace 不是统一 coordinate model。 | 不要继续在 page DOM 内模拟 open canvas。 | Unified NoteCanvas |
| mechanical convert 误判字段。 | `CS:GO` 被冒号拆成 concept/description。 | 用脚本猜语义。 | 不要把弱 heuristic 当 structured truth。 | Convert Proposal / User Confirm / AI Assist |
| block control bar 改变或遮挡测量空间。 | block 贴边时 toolbar 挡住下方 block。 | control bar 和 content layout 耦合。 | 不要把 toolbar 放进 block flow。 | Detached Object Overlay |
| undo/redo 与 persistence 边界不清。 | 移动、resize、删除、输入需要不同撤回粒度。 | operation history 没有统一 action model。 | 不要只靠局部 state 回滚。 | Runtime Operation History |
| current layout key 容易变成兼容债。 | `better_notebook_layout` 存在实验性布局。 | prototype data 被写进 display override。 | 不要为实验 layout 写长期 converter。 | Clean Branch / Clean Layout Reset |
| relation connector 没有提前预留会压迫 layout。 | 后续 connector endpoint/port/route/animation 需要空间。 | relation 还没进入 runtime，但 layout 已经在前进。 | 不要等 relation runtime 时才补坐标边界。 | Connector Endpoint Reserve |

## 7. 当前代码中应继承的经验

应该继承的是“经验”，不是“文件结构”：

- `NoteDetail.tsx` 证明了自然写作、block resize、layout mode、preview overlay 有价值；
- `noteSlashCommands.ts` 证明了 slash command 分类入口有价值；
- `noteBlockTemplates.ts` 证明了 template taxonomy 和 field seed 可以作为 structured block 的开端；
- `notes.ts` 证明了 content 与 placement 可以分离写入；
- contracts 证明了 product truth / adapter truth / runtime projection 可以被说清楚。

## 8. 当前代码中不应继承的实现债

不建议在 Canvas Engine 中继续继承：

- monolithic `NoteDetail.tsx` 作为所有 runtime 的中心；
- 以 DOM 页面流模拟 infinite canvas；
- 用局部估算函数长期承担 measurement service；
- 把 overlay / toolbar / popover 混在 block DOM 附近；
- 对结构化 block 做弱 heuristic 自动转换；
- 把 `better_notebook_layout` 当长期稳定 schema；
- 为实验布局写复杂 migration/converter。

## 10. Autopsy 结论

当前 runtime 的价值很高，但它的价值主要在于：

```text
证明产品体验方向
暴露工程风险
提供未来验收样本
提供失败 fallback
```

而不是继续承担未来 Canvas Engine 的主干实现。

V2.BN.8 应从这些表中继承规则、风险和能力清单，在 clean branch 中建立 canvas-native runtime。
